# 行级访问权限控制

在对象级 `GRANT` 之外，OceanBase AI 数据库还提供细粒度访问控制：既支持对指定列授予或限制权限，也支持行级访问权限控制（Row-Level Security，RLS）。本文介绍 RLS。

RLS 可在不改变业务 SQL 的情况下，按当前用户、当前角色或行数据，限制普通查询可返回的行，以及数据修改命令可插入、更新或删除的行。默认情况下，表没有 RLS 策略。用户只要具备 SQL 对象权限，即可平等访问表中所有行。

## 前提条件与注意事项

前提条件如下：

* 创建、修改或删除策略，以及配置表级 RLS 开关，需要目标表的对象级 `ALTER` 权限。

注意事项如下：

* 本权限为附加限制：RLS 是对象权限之上的附加限制：用户必须先拥有目标表所需的 `SELECT`、`INSERT`、`UPDATE` 或 `DELETE` 权限，之后才会应用 RLS；RLS 本身不授予任何对象权限。
* **独立配置**：创建策略（定义）与启用 RLS 是两个独立操作，策略配置不会自动启用表的 RLS；启用 RLS 也不会自动创建策略。
* 分别配置：为实际使用的 DML 分别配置策略；不要假设 `FOR SELECT` 会自动保护 `UPDATE` 或 `DELETE`。
* 角色激活：策略的 `TO` 指定角色时，看当前会话的已激活角色，不只是已授予角色。角色激活参见 [激活角色](../200.user-and-permission/200.permission-of-mysql-mode/340.role-management-of-mysql-mode/500.activating-roles-of-mysql-mode.md)。角色授权变更后，长连接需执行受控的 `SET ROLE` 或重连。
* `SUPER` 限制：`SUPER` 不会绕过 RLS。
* 绕过权限：RLS 支持绕过，如需绕过则授予 `BYPASSRLS` 全局权限，详见 [权限分类](../200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md) 与 [GRANT](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/5500.grant-of-mysql-mode.md)。

这里只列出功能相关的全局注意事项，语法细节注意事项请参见配置操作的 SQL 语法文档，两者需要配合理解。

## 配置模型

完整配置 RLS 需要**同时配置表级开关与策略**。

### 表级开关

表级开关通过 [ALTER TABLE](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1600.alter-table-of-mysql-mode.md) 配置，决定该表是否启用 RLS，以及表所有者是否也受限制：

| **SQL 子句** | **说明** |
| --- | --- |
| `ENABLE ROW LEVEL SECURITY` | 启用 RLS，策略开始对非豁免用户生效。 |
| `DISABLE ROW LEVEL SECURITY` | 禁用 RLS，策略定义保留但不生效。 |
| `FORCE ROW LEVEL SECURITY` | 强制表所有者也受 RLS 限制。 |
| `NO FORCE ROW LEVEL SECURITY` | 默认值。不强制表所有者：在已 `ENABLE` 时，表所有者仍绕过该表的 RLS。也可执行 `FORCE` 强制，再用本子句恢复为默认豁免。 |

新建表或未显式设置时，等价于 `NO FORCE ROW LEVEL SECURITY`。表未启用时单独设置 `FORCE` / `NO FORCE` 无实际效果。SQL 示例见下文 [操作示例](#操作示例)。

### 策略配置

策略使用 [CREATE POLICY](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2320.create-policy-of-mysql-mode.md) 创建，使用 [ALTER POLICY](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1360.alter-policy-of-mysql-mode.md) / [DROP POLICY](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/3690.drop-policy-of-mysql-mode.md) 修改或删除。具体语法说明、限制及示例见 SQL 语法文档。本文完整功能示例见下文 [操作示例](#操作示例)。

## 绕过行级权限

RLS 在不同情况下支持绕过，具体如下：

| **身份** | **行为** |
| --- | --- |
| 表所有者（`ENABLE` + `NO FORCE`） | 绕过该表的 RLS。 |
| 表所有者（已 `FORCE`） | 与普通用户一样受策略限制。 |
| 拥有全局 `BYPASSRLS` 的用户 | 在所有状态下都绕过 RLS（含 `FORCE`），同时绕过读取过滤与写入校验。 |
| 有 `SUPER` 权限的用户（如 `root` 用户） | 不会绕过 RLS。 |

## 操作示例

下面的示例使普通用户只能操作 `owner_account` 等于当前登录账号的行。示例中的 `owner_account` 保存 `CURRENT_USER()` 返回的完整账号，例如 `alice@%`。

1. 创建业务表

    ```sql
    CREATE TABLE orders (
       order_id       BIGINT PRIMARY KEY,
       owner_account  VARCHAR(128) NOT NULL,
       amount         DECIMAL(18, 2),
       order_status   VARCHAR(32)
     );
    ```

2. 创建策略

    ```sql
    CREATE POLICY orders_owner_policy ON orders
       AS PERMISSIVE
       FOR ALL
       TO PUBLIC
       USING (owner_account = CURRENT_USER())
       WITH CHECK (owner_account = CURRENT_USER());
    ```

3. 查看策略配置

    ```sql
    SELECT TABLE_SCHEMA, TABLE_NAME, ROW_SECURITY, ROW_SECURITY_FORCED
    FROM information_schema.TABLES
    WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'orders';

    SELECT POLICY_NAME, POLICY_TYPE, COMMAND_TYPE, ROLES,
          USING_EXPRESSION, WITH_CHECK_EXPRESSION
    FROM oceanbase.DBA_RLS_POLICIES
    WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'orders';
    ```

    <main id="notice" type='explain'>
      <h4>说明</h4>
      <p>建议先创建策略并核对配置，再启用 RLS。启用前用表所有者、普通用户、相关角色用户以及 <code>BYPASSRLS</code> 管理账号分别验证。</p>
    </main>

4. 启用表的 RLS

    ```sql
    ALTER TABLE orders ENABLE ROW LEVEL SECURITY;
    ```

    此时：

    * `SELECT`、`UPDATE` 和 `DELETE` 只能命中当前账号拥有的行。
    * `INSERT` 只能写入 `owner_account = CURRENT_USER()` 的行。
    * `UPDATE` 后的新行仍必须满足 `owner_account = CURRENT_USER()`。

5. 表所有者受限（可选）

    表所有者默认绕过 RLS。若表所有者也必须受限，再执行以下命令

    ```sql
    ALTER TABLE orders FORCE ROW LEVEL SECURITY;
    ```
