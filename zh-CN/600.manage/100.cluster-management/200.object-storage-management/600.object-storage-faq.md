# 对象存储常见问题

本文汇总了对象存储管理过程中常见的操作问题及解决方法。

## 对象存储的 AK/SK 如何轮转？

AK/SK 轮转需要根据凭证持有方的不同，选择对应的管理路径：

* **更新 observer 进程访问对象存储的凭证**：observer 进程持有两类对象存储访问凭证，均通过 `ALTER SYSTEM` 语句更新：
  * **数据存储访问凭证**：通过 `ALTER SYSTEM CHANGE SHARED_STORAGE_DEST` 命令更新。
  * **日志存储访问凭证**：通过修改 `logservice_access_point` 配置项更新。
  * 详细操作步骤参见 [更新对象存储访问凭证](../100.compute-service-management/300.common-cluster-operations/1320.change-shared-storage-dest.md)。
* **更新日志服务访问对象存储的凭证**：通过 `ls_ctrl rotate-ak` 命令轮转，详细操作步骤参见 [轮转日志服务访问凭证](../300.logservice-management/300.logservice-operations/800.rotate-access-key.md)。

## 修改对象存储的 AK/SK 后旧 AK 什么时候失效？

集群替换为新 AK 后，旧 AK 不会立即从集群中移除，删除旧 AK 需等待至少一个小时。

## 对象存储添加失败怎么办？

添加对象存储失败可能有以下原因：

* **对象存储服务不可达**：检查网络连通性，确认 Endpoint 地址正确。
* **AK/SK 权限不足**：确认 AK/SK 具有访问对象存储的权限。
* **对象存储类型不支持**：当前支持接入兼容 S3 协议的对象存储（如阿里云 OSS、华为云 OBS 等）和 Azure Blob 协议。

## 如何监控对象存储的 I/O 带宽使用情况？

可以通过查看 `GV$OB_SHARED_STORAGE_QUOTA` 视图了解对象存储的 I/O 访问资源信息。

## 是否支持修改集群关联的对象存储桶？

不支持。数据存储与日志存储的对象存储桶仅在集群创建时设置，集群运行期间不支持修改。用户需确保所配置的对象存储桶在集群整个生命周期内持续有效，包括桶的存续状态及访问权限。若存储桶被删除、访问权限发生变更或凭证失效，将导致集群无法正常读写数据，直接影响集群的正常运行。
