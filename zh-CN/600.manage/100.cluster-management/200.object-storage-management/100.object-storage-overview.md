# 对象存储概述

OceanBase AI 数据库采用基于存算分离的共享存储架构，增量数据、基线数据以及日志文件均存储于对象存储之上。

对象存储是 OceanBase AI 数据库的数据底座，为计算层和日志服务层提供共享的持久化存储能力，承载全量数据的长期保存与统一访问，是实现低成本、高可靠数据存储的核心基础。该架构下，计算节点（OBServer）共享对象存储上的全量数据，仅在本地缓存热点数据以保障访问性能；日志服务（LogService）通过本地高性能存储实现最新日志的低延迟写入，并将已确认的日志异步归档至对象存储，实现海量持久化保存。

在创建集群前，需通过 OceanBase 云平台（OCP）的外部集成功能预先配置对象存储的连接信息，包括 Bucket 路径、Endpoint 地址、AccessKey 凭证等。具体操作请参见 [创建对象存储配置](https://www.oceanbase.com/docs/common-ocp-1000000006645137)。

## 使用对象存储的组件

共享存储架构下，对象存储同时服务于集群中的多个组件，各组件通过独立的凭证管理方式访问对象存储：

| 组件 | 用途 | 管理方式 |
|------|------|---------|
| **OBServer**（计算节点） | 持久化基线数据和增量数据 | 集群初始化时通过 Bootstrap 命令指定 `SHARED_STORAGE_INFO`；数据存储凭证通过 `ALTER SYSTEM CHANGE SHARED_STORAGE_DEST` 更新，日志存储凭证通过修改 [logservice_access_point](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/12750.logservice_access_point.md) 配置项更新 |
| **LogService**（日志服务节点） | 持久化日志数据 | 通过 `ls_ctrl rotate-ak` 命令行工具轮转访问凭证（AK/SK） |

## 概念介绍

* **对象存储（Object Storage）**：一种将数据作为包含元数据和唯一标识符的独立“对象”，存储在扁平命名空间中，并通过 API 进行访问的海量非结构化数据存储架构。OceanBase AI 数据库当前支持接入 AWS S3、兼容 S3 协议的对象存储以及 Azure Blob 对象存储。

* **Bucket**：对象存储的容器，用于存储对象（文件），每个 Bucket 有唯一的域名和访问地址。

* **Endpoint**：对象存储服务的访问端点地址，不同地域有不同的 Endpoint。

* **AccessKey**：访问对象存储的凭证，包含 AccessKey ID 和 AccessKey Secret，用于身份验证。

## 管理方式

对象存储的配置通过 OCP 的“外部集成”功能统一管理，可以：

* **统一管理**：集中管理集群使用的对象存储配置，避免分散管理导致的配置混乱。
* **生命周期管理**：管理对象存储配置的完整生命周期，包括添加、更新、删除操作。删除操作仅移除 OCP 中的配置记录，不会删除对象存储服务上的实际数据。
* **凭证安全**：安全存储 AccessKey 凭证，在创建集群时自动注入，无需手动填写。

## 注意事项

* **独立 Bucket**：OBServer 和 LogService 使用的对象存储桶建议独立配置，以确保数据隔离和安全性。

* **权限最小化**：为对象存储的 AccessKey 配置最小必要权限，遵循最小权限原则。

* **定期轮换**：建议定期轮换 AccessKey，降低凭证泄露风险。

## 支持的存储类型

当前支持接入 AWS S3、兼容 S3 协议的对象存储（如阿里云 OSS、华为云 OBS 等）和 Azure Blob 对象存储，对应 URL 协议头分别为 `s3://` 和 `azblob://`，仅支持这两种协议头，其它协议不支持。

## 支持的接口与权限要求

OceanBase AI 数据库通过兼容 S3 的协议访问对象存储，支持以下接口：

| 接口名 | 描述 |
| --- | --- |
| `PutObject` | 上传单个对象 |
| `DeleteObject` | 删除单个对象 |
| `DeleteObjects` | 批量删除对象 |
| `GetObject` | 下载单个对象 |
| `ListObjects` | 列举路径下的所有对象 |
| `HeadObject` | 获取某个对象的元数据 |
| `CreateMultipartUpload` | 初始化分片上传 |
| `UploadPart` | 上传单个分片 |
| `CompleteMultipartUpload` | 合并已上传分片为一个对象 |
| `AbortMultipartUpload` | 中止分片上传，删除已上传分片 |
| `ListMultipartUploads` | 列出上传的分片 |
| `ListParts` | 列出上传任务中已完成上传的分片信息 |
| `PutObjectTagging` | 为单个对象设置标签 |
| `GetObjectTagging` | 获取单个对象的标签 |

不同组件访问对象存储所需的最小权限如下：

* **OBServer**（计算节点）：需要以上全部接口的权限，用于持久化基线数据和增量数据。

* **LogService**（日志服务节点）：需要以下接口的权限，用于上传、读取和清理日志数据：

  | 接口名 | 描述 |
  | --- | --- |
  | `PutObject` | 上传日志块 |
  | `GetObject` | 读取日志块 |
  | `HeadObject` | 检查对象是否存在 |
  | `ListObjects` | 列举对象（GC 扫描等） |
  | `DeleteObject` | 删除单个对象（GC 清理） |
  | `DeleteObjects` | 批量删除（S3）；Azure Blob 上等价于多次 `DeleteObject` |

## 对象存储状态

对象存储的生命周期状态定义于视图 [DBA_OB_ZONE_STORAGE](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/24350.o-dba_ob_zone_storage-of-sys-tenant.md) 的 `STATE` 字段，包括：

| 状态 | 说明 |
|------|------|
| `ADDING` | 正在添加对象存储 |
| `ADDED` | 添加成功，对象存储可用 |
| `DROPPING` | 正在删除对象存储 |
| `CHANGING` | 正在轮转 AK/SK |
| `CHANGED` | AK/SK 轮转已完成 |
