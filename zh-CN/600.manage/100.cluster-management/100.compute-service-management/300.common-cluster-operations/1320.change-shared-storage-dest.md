# 更新对象存储访问凭证

共享存储架构下，observer 进程通过对象存储持久化业务数据，日志服务（LogService）通过对象存储持久化日志数据。当需要更新对象存储的访问凭证时（如定期轮转 AK/SK、凭证泄露），可以通过 `ALTER SYSTEM` 语句完成凭证更新。本文介绍如何更新 observer 进程访问对象存储的凭证。

日志服务的 AK/SK 轮转与 observer 进程的凭证更新相互独立，具体操作请参见 [轮转日志服务访问凭证](../../300.logservice-management/300.logservice-operations/800.rotate-access-key.md)。

## 前提条件

更新数据存储和日志存储的访问凭证前，需先在对象存储服务上创建新的 AK/SK，并确保新凭证对目标 Bucket 有读写权限，权限要求参见 [对象存储概述](../../200.object-storage-management/100.object-storage-overview.md)。

## 更新数据存储访问凭证

数据存储访问凭证由计算节点 OBServer 直接持有，指向数据存储所在的对象存储桶，用于读写基线数据和转储数据。该凭证在集群创建时通过 `SHARED_STORAGE_INFO` 参数完成初始配置。

若后续需要更换对象存储桶的访问密钥，可通过以下语句在线更新，无需重启集群：`ALTER SYSTEM CHANGE SHARED_STORAGE_DEST`。

<main id="notice" type='notice'>
<h4>注意</h4>
<p><code>ALTER SYSTEM CHANGE SHARED_STORAGE_DEST</code> 语句仅支持系统租户（即 <code>sys</code> 租户）执行。</p>
</main>

### 操作步骤

1. 使用 `root` 用户登录到集群的 `sys` 租户。

   连接示例如下，连接数据库时请以实际环境为准：

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. 查询 `oceanbase.DBA_OB_ZONE_STORAGE` 视图，查看当前集群配置的对象存储信息。

   ```shell
   obclient [(none)]> SELECT * FROM oceanbase.DBA_OB_ZONE_STORAGE;
   ```

3. 更新对象存储的访问凭证：

   ```sql
   ALTER SYSTEM {ALTER|CHANGE|MODIFY} SHARED_STORAGE_DEST
       PATH [=] 'path'
       SET
       ACCESS_INFO [=] 'access_info';
   ```

   相关参数说明如下：

   * `PATH`：对象存储的路径，兼容 S3 协议的对象存储格式为 `s3://<bucket>/<prefix>?host=<endpoint>`，Azure Blob 格式为 `azblob://<container>/<prefix>?host=<endpoint>`，需与集群当前配置的对象存储路径保持一致。
   * `ACCESS_INFO`：新的访问凭证，格式为 `access_id=<new_access_id>&access_key=<new_access_key>`。

   示例如下：

   ```shell
   obclient [(none)]> ALTER SYSTEM CHANGE SHARED_STORAGE_DEST
       PATH='s3://xxx?host=cn-hangzhou-alipay-b.oss-cdn.aliyun-inc.com'
       SET ACCESS_INFO='access_id=xxx&access_key=xxx';
   ```

4. 更新成功后，重新查询 `oceanbase.DBA_OB_ZONE_STORAGE` 视图，确认更新结果（`STATE` 字段显示为 `CHANGING` 表示正在轮转，显示为 `CHANGED` 表示轮转完成）。

## 更新日志存储访问凭证

日志存储访问凭证由计算节点 OBServer 通过 LibPalf 客户端库持有，指向日志服务所使用的对象存储桶。OBServer 借助该凭证完成服务发现（读取 AccessPoint）以及与日志服务的通信交互。

该凭证通过集群配置项 `logservice_access_point` 进行配置与管理，可通过修改该配置项来更新凭证信息。

<main id="notice" type='notice'>
<h4>注意</h4>
<ul>
<li><code>logservice_access_point</code> 配置项仅允许修改 <code>access_id</code> 和 <code>access_key</code> 字段，其他字段（如 <code>host</code>、<code>s3_region</code> 等）不支持修改，否则语句执行会报错。</li>
<li><code>logservice_access_point</code> 配置项不支持通过启动参数（<code>-o</code>）设置，只能通过 <code>ALTER SYSTEM SET</code> 语句修改，或在集群初始化（bootstrap）时由系统自动设置。</li>
</ul>
</main>

### 操作步骤

1. 使用 `root` 用户登录到集群的 `sys` 租户。

   连接示例如下，连接数据库时请以实际环境为准：

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. 执行以下命令，查看当前 `logservice_access_point` 配置项的值。

   ```shell
   obclient [(none)]> SHOW PARAMETERS LIKE 'logservice_access_point';
   ```

   <main id="notice" type='notice'>
   <h4>说明</h4>
   <p>该配置项的值以加密形式存储，因此 <code>SHOW PARAMETERS</code> 语句显示的是加密后的值。</p>
   </main>

3. 执行以下命令，更新 `logservice_access_point` 配置项中的访问凭证（仅修改 `access_id` 和 `access_key` 字段，其他字段保持不变）。

   语句如下：

   ```sql
   ALTER SYSTEM SET logservice_access_point = 's3://<bucket>/<prefix>?host=<endpoint>&logservice_cluster_id=<cluster_id>&s3_region=<region>&max_iops=<iops>&max_bandwidth=<bandwidth>&access_id=<new_access_id>&access_key=<new_access_key>';
   ```

   示例：

   ```shell
   obclient [(none)]> ALTER SYSTEM SET logservice_access_point = 's3://test/logservice?host=http://10.0.0.1:9000&logservice_cluster_id=20260617&s3_region=cn-north-1&max_iops=10000&max_bandwidth=1GB&access_id=<NEW_AK>&access_key=<NEW_SK>';
   ```

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>修改该配置项时，系统会使用新的 AK/SK 访问对象存储以验证其有效性，若新凭证不存在或无权限，语句执行会被拒绝。</p>
   </main>

4. 更新成功后，确认更新结果。

   * 重新执行 `SHOW PARAMETERS LIKE 'logservice_access_point';` 语句，确认配置已更新。

   * 在 observer 进程日志中确认日志存储凭证已刷新。

     ```shell
     grep "rotate_object_store_ak" observer.log | tail -5
     ```

5. （可选）清理旧的访问凭证。

   新凭证完全生效后，可在对象存储服务上删除旧凭证。删除前请确认以下事项：

   * 所有 OBServer 节点均已完成凭证更新且集群运行正常。
   * 已持续观察至少一个 config reload 周期（约 10 秒），且所有节点日志中出现更新成功日志。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>如果在更新完成前删除旧凭证，正在使用旧凭证的 OBServer 节点将无法访问对象存储，可能导致节点异常甚至集群无法启动（因为 <code>observer.config.bin</code> 中仍保存旧凭证，重启时会加载失败）。</p>
   </main>

### 常见错误与处理

更新 `logservice_access_point` 配置项时，可能出现的错误及处理方法如下：

| 错误信息 | 原因 | 处理方法 |
| --- | --- | --- |
| `logservice_access_point: libpalf env not initialized` | libpalf 环境未初始化（observer 启动中或非共享存储模式） | 等待 observer 完全启动后重试 |
| `only access_id and access_key can be changed` | 修改了 AK/SK 以外的字段（如 `host`、`path`、`region` 等） | 检查新值，确保只修改了 `access_id` 和 `access_key` |
| `new access_id/access_key validation failed` | 新 AK/SK 无法访问对象存储 | 确认新凭证已在对象存储上创建且有读权限 |
| `logservice_access_point cannot be setted by -o` | 尝试通过启动参数 `-o` 设置 | 只能通过 `ALTER SYSTEM SET` 或 bootstrap 设置 |
