# 替换日志服务节点

当日志服务节点（LogServiceNode，LN）出现故障或者需要垂直扩容时，可以对节点进行替换。日志服务（LogService）通过 LS-CTRL 管控命令进行节点替换，替换的基本流程为：先启动新节点并通过 `add ln` 命令将其添加到目标 Zone，再通过 `delete ln` 命令删除待替换节点。

## 操作步骤

1. 启动一个可用的节点。

2. 通过 `ls_ctrl` 工具执行 `add ln` 命令，在待替换节点所属的 Zone 中添加新节点。

   ```shell
   ls_ctrl -H <HOST_ADDRESS> add ln <host:port> <az>
   ```

   其中，`<host:port>` 为待添加节点的地址，`<az>` 为目标 Zone 名称。

   添加节点的详细操作请参见 [添加日志服务节点](400.add-logservice-node.md)。

3. 通过 `ls_ctrl` 工具执行 `delete ln` 命令，删除待替换节点。

   ```shell
   ls_ctrl -H <HOST_ADDRESS> delete ln <ln>
   ```

   其中，`<ln>` 为待删除节点的 ID 或地址（`host:port`）。

4. 通过 `ls_ctrl` 工具执行 `show ln` 命令和 `show meta --table-name t_ln_info_history` 命令，确认待替换节点是否已被安全删除：

   ```shell
   ls_ctrl -H <HOST_ADDRESS> show ln

   ls_ctrl -H <HOST_ADDRESS> show meta --table-name t_ln_info_history
   ```

   如果 `show ln` 命令查询不到待替换节点的信息，且 `show meta --table-name t_ln_info_history` 命令能够查询到待替换节点的信息，说明对应的待替换节点可以被安全删除。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>上述命令中，<code>HOST_ADDRESS</code> 为日志服务任意节点的 HTTP 地址（带端口号），例如 <code>127.0.0.1:8080</code>。关于 ls-ctrl 命令的更多信息，请参考 <a href="../../../../700.reference/950.logservice-reference/100.logservice-commands/100.ls-ctrl-overview.md">LS-CTRL 概述</a>。</p>
</main>

## 删除机制说明

* `delete ln` 命令会标记对应节点为 `DELETING` 状态，并驱动 LogServiceManager（LM）发起迁移任务，将位于 `DELETING` 状态的节点上的 Stream 副本迁移到其他可用的节点上。

* 当所有日志流的成员列表都不包含某个处于 `DELETING` 状态的 LN，且该 LN 也不是任何一个日志流的迁移目的端，同时也没有正在创建的日志流，LM 就认为该 LN 可以被安全地删除。

* 当 LM 探测到某个 LN 长时间处于 `Inactive` 状态，即当前时间与 `t_ln_info` 中的 `offline_time` 相差超过 `node_permanent_offline_time_sec` 配置项的值时，便认为该节点无法恢复，会产生迁移任务，将该 LN 上的日志流副本迁移到同一个 AZ 内的其他可用的 LN 上。

## 观察删除进度

可以通过以下方式观察节点删除的进度：

1. 通过 `show ln` 命令观察对应节点的状态是否为 `DELETING`。

2. 通过 `show meta` 命令查看记录迁移复制任务的内部表 `t_stream_replica_task`。节点被标记为 `DELETING` 状态后，LM 会为对应的节点生成迁移任务，其中迁移源端 `src_ln` 是该节点。

   ```shell
   ls_ctrl -H <HOST_ADDRESS> show meta --table-name t_stream_replica_task
   ```

3. 迁移任务执行完成后，可以通过 `show meta` 命令查看迁移复制任务的历史表 `t_stream_replica_task_history`。其中每一行记录代表一个执行完成的迁移复制任务，`status` 表示迁移任务是否成功执行，`comment` 表示迁移任务失败的原因。

   ```shell
   ls_ctrl -H <HOST_ADDRESS> show meta --table-name t_stream_replica_task_history
   ```

4. 当所有的副本都从对应的 LN 上迁出后，可以通过 `show meta` 命令查看节点的状态表 `t_ln_info` 和历史表 `t_ln_info_history`。如果 `t_ln_info` 中没有对应节点的记录，并且 `t_ln_info_history` 中有对应的记录，说明该 LN 已经从集群中被删除。

   ```shell
   ls_ctrl -H <HOST_ADDRESS> show meta --table-name t_ln_info

   ls_ctrl -H <HOST_ADDRESS> show meta --table-name t_ln_info_history
   ```

## 注意事项

* 如果有日志流一直处于 `CREATING` 状态且 `initial_member_list` 包含待删除的节点，也会导致节点无法被删除。
