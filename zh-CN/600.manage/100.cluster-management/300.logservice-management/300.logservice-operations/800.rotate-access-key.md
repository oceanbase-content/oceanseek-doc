# 轮转日志服务访问凭证

共享存储架构下，observer 进程通过对象存储持久化业务数据，日志服务（LogService）通过对象存储持久化日志数据。日志服务访问对象存储所需的 AK（AccessKey）由集群管理节点（Log Manager，LM）统一管理。本文介绍如何使用 `ls_ctrl` 命令行工具在线更换日志服务访问对象存储的 AK。

observer 侧对象存储访问凭证的更新与日志服务的 AK/SK 轮转相互独立，具体操作请参见 [更新对象存储访问凭证](../../100.compute-service-management/300.common-cluster-operations/1320.change-shared-storage-dest.md)。

## 前提条件

执行轮转前，请确保已在对象存储侧创建新 AK，且具备访问对象存储所需的权限，权限要求参见 [对象存储概述](../../200.object-storage-management/100.object-storage-overview.md)。

## 操作步骤

1. 执行以下命令触发轮转：

   ```bash
   ls_ctrl -H <HOST_ADDRESS> rotate-ak \
       -i <ACCESS_KEY_ID> \
       -k <ACCESS_KEY_SECRET>
   ```

   输出示例：

   ```json
   {"msg":"ok","data":{"new_param_version":43}}
   ```

   输出中的 `data.new_param_version` 表示本次轮转后的参数版本，用于下一步确认全集群已切换到新 AK。

2. 确认全集群已切换到新 AK：

   轮转是异步生效的，反复执行以下命令，确认所有节点均已切换到新 AK：

   ```bash
   ls_ctrl -H <HOST_ADDRESS> param-version-status
   ```

   检查输出中每个节点的参数版本：当所有节点的版本号均达到第 1 步返回的 `new_param_version` 时，表示全集群已切换到新 AK。

   <main id="notice" type='notice'>
   <h4>说明</h4>
   <p>如果不慎丢失了 <code>new_param_version</code>（终端关闭、换机器等），可以用完全相同的 AK 重新执行一次 <code>rotate-ak</code>：服务端识别为幂等重发，返回当前的参数版本，继续后续流程即可。</p>
   </main>

3. （可选）吊销旧 AK：

   确认全集群已切换到新 AK 后，可在对象存储服务的管理控制台或通过其 CLI 工具吊销旧 AK，完成轮转。更多信息，请参考对应对象存储服务商的官方文档。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>上述命令中，<code>HOST_ADDRESS</code> 为日志服务任意节点的 HTTP 地址（带端口号），例如 <code>127.0.0.1:8080</code>。关于 ls-ctrl 命令的更多信息，请参考 <a href="../../../../700.reference/950.logservice-reference/100.logservice-commands/100.ls-ctrl-overview.md">LS-CTRL 概述</a>。</p>
</main>

## 常见错误与处理

| 现象 | 原因 | 处理建议 |
| --- | --- | --- |
| `rotate-ak` 返回 `403` | 新 AK 缺少日志服务所需的对象存储权限（含批量删除） | 响应 body 带有 `failed_step` 标识失败步骤（如 `put` / `head` / `get` / `list` / `delete_batch`）；在对象存储侧补齐权限后重试 |
| 轮转期间 LM 宕机 / 重启 | LM 启动需要从对象存储加载 checkpoint，此时旧 AK 已被禁用或删除 | 在对象存储侧重新启用旧 AK，待 LM 启动并完成参数同步后，再重新确认全集群已切换到新 AK |
| 禁用旧 AK 后出现鉴权错误 | 仍有节点（如新上线节点）未切换到新 AK | 立即重新启用旧 AK，重新确认全集群已切换到新 AK 后再尝试禁用 |

## 注意事项

* 本功能仅支持 `min_oblogservice_version` 不低于 `1.3.1` 的集群，低于该版本的集群会拒绝 `rotate-ak` 与 `param-version-status` 请求。
* 一次 `rotate-ak` 会同时更换 AccessKey ID 和 AccessKey Secret，不支持只更换其中之一。
* 新 AK Secret 通过命令行参数传入，注意避免进入 shell history 或日志采集。建议使用 `read -s` 或环境变量等方式临时持有 Secret，不要把含 Secret 的命令贴在共享聊天工具、wiki 或工单系统。
