# 日志服务负载均衡概述

负载均衡是日志服务（LogService）水平扩缩容能力的基础。当日志服务集群规模较大时，需要通过负载均衡将日志流（Stream）副本均匀分布在集群各节点上，避免单节点负载过高，从而支撑更大的写入负载。

日志流的负载均衡由 **LogServiceManager（LM）** 负责，LM 会持续监控集群中所有日志服务节点（LogServiceNode，LN）的副本分布和负载状态，并自动生成副本迁移任务来维持均衡状态。

## 均衡状态

均衡状态的定义与均衡策略相关，本节描述默认策略 `replica_count_based` 下的均衡状态；`load_based` 策略的调度目标请参见下文“基于负载的均衡（load_based）”章节。

负载均衡以日志流副本为基本单元，只关注处于 `NORMAL` 状态的日志流和 `Active` 状态的节点。均衡状态定义为：集群中存在 N 个日志流、一个可用区（AZ）中存在 M 个节点时，该 AZ 中每个节点上的副本数处于 {⌊N/M⌋, ⌊N/M⌋+1} 的区间内。

可能打破均衡状态的操作包括：

* **日志流创建**：创建日志流时，LM 会优先选择副本分布最少的节点作为初始成员列表。
* **日志流删除**：日志流删除后允许节点副本数低于 ⌊N/M⌋，避免频繁触发均衡任务。
* **节点增加**：新增节点上没有日志流副本，LM 会自动生成均衡任务，将部分副本迁移到新节点上。
* **节点删除/永久下线**：容灾模块负责将删除节点上的日志流副本迁移到活跃节点，迁移时考虑迁移后的均衡性。

## 均衡机制

本节描述 `replica_count_based` 策略下的均衡任务生成机制。

LM 会周期性地生成均衡任务，由容灾模块负责执行具体的副本迁移。均衡任务与容灾任务互斥：当内部表 `t_stream_replica_task` 中有记录时，系统不会生成新的均衡任务。

均衡任务生成时，会根据节点上的日志流副本数将节点划分为：

* Over-Utilized（过载）：节点资源使用率显著高于集群平均水平，处于超负荷运行状态
* Above-Average（偏高）：节点资源使用率高于集群平均水平，但尚在可控范围内
* Below-Average（偏低）：节点资源使用率低于集群平均水平，存在一定资源冗余
* Under-Utilized（空闲）：节点资源使用率显著低于集群平均水平，资源大量闲置

按照以下优先级生成迁移任务：

1. Over-Utilized → Under-Utilized
2. Over-Utilized → Below-Average
3. Above-Average → Under-Utilized

可迁移的日志流副本仅限 `NORMAL` 日志流成员列表中的副本。

## 均衡策略

日志服务支持两种均衡策略，通过集群级配置项 `load_balance_policy` 控制。

### 基于副本数的均衡（replica_count_based）

默认策略。LM 以日志流副本数为均衡指标，尽量使每个 LN 节点承载的副本数量均匀。该策略不依赖节点 IO 容量配置，简单且高效。

### 基于负载的均衡（load_based）

LM 以节点的 IO 资源利用率（IOPS 和带宽）为调度指标，目的是避免节点资源利用率超过 `max_utilization_threshold` 阈值，不要求各节点资源利用率均衡。负载均衡模块基于节点负载以及日志流写入压力进行调度，调度策略如下：

1. 优先将过载节点的上传流量调度到成员列表中的其他成员。
2. 将资源使用率高的 LN 上的日志流副本迁移到能够容纳该副本的节点，即迁移目的端的资源使用率在添加该副本后不会超过阈值。
3. 优先选择占用 IO 资源高的日志流副本迁出。
4. 优先选择资源利用率低的节点迁入。

该策略要求集群中所有节点的 `disk_max_iops` 与 `disk_max_bandwidth` 均已正确配置（非 0）。

**准入校验**：配置为 `load_based` 时，需要满足以下条件，否则拒绝修改：

* 集群中所有节点的 `disk_max_iops` 均大于 0。
* 集群中所有节点的 `disk_max_bandwidth` 均大于 0。

当配置为 `load_based` 但运行期前提不满足时，LM 会按以下规则自动降级：存在节点的 `disk_max_iops` 或 `disk_max_bandwidth` 为 0，降级为 `replica_count_based`（ERROR 日志）。降级期间配置项展示值不变（仍为 `load_based`），待条件满足后自动恢复，无需人工干预。

## 查看均衡状态

通过 LS-CTRL 工具的 `show v-table` 命令可以查看集群的负载信息，支持以下三种虚拟视图。

* `node_load`：显示每个 LN 节点的 IOPS 和带宽使用情况。
* `az_load`：显示每个 AZ 的 IOPS 和带宽使用情况。
* `stream_replica_io`：显示每个日志流副本的 IO 统计信息。

```shell
ls_ctrl -H <HOST_ADDRESS> show v-table node_load
ls_ctrl -H <HOST_ADDRESS> show v-table az_load
ls_ctrl -H <HOST_ADDRESS> show v-table stream_replica_io
```

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>上述命令中，<code>HOST_ADDRESS</code> 为日志服务任意节点的 HTTP 地址（带端口号），例如 <code>127.0.0.1:8080</code>。关于 ls-ctrl 命令的更多信息，请参考 <a href="../../../../700.reference/950.logservice-reference/100.logservice-commands/100.ls-ctrl-overview.md">LS-CTRL 概述</a>。</p>
</main>

## 手动迁移副本

通过 `ls_ctrl migrate replica` 命令可以将指定日志流的副本从源 LN 迁移到目标 LN。详细命令说明请参见 [migrate replica](../../../../700.reference/950.logservice-reference/100.logservice-commands/200.ls-ctrl-commands/1200.logservice-migrate-replica.md)。

建议在执行手动迁移副本前，通过 `enable_rebalance` 配置项关闭自动负载均衡，避免手动迁移与自动均衡任务相互干扰；迁移完成后再重新开启自动负载均衡。配置 `enable_rebalance` 的操作请参见 [配置均衡策略](300.configure-load-balancing-policy.md)。

## 相关配置项

以下配置项与负载均衡直接相关，详细说明请参见 [日志服务配置项总览](../../../../700.reference/950.logservice-reference/200.logservice-parameters/100.logservice-parameters.md)。

| 配置项 | 作用域 | 生效模式 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `enable_rebalance` | cluster | dynamic | true | 是否开启日志流负载均衡 |
| `load_balance_policy` | cluster | dynamic | replica_count_based | 负载均衡策略：`replica_count_based`（基于副本数）或 `load_based`（基于负载） |
| `rebalance_interval_sec` | cluster | dynamic | 60 | 负载均衡触发间隔（秒） |
| `max_utilization_threshold` | cluster | dynamic | 60 | 节点资源利用率上限（百分比），超过时触发副本迁出 |
| `min_utilization_threshold` | cluster | dynamic | 30 | 节点资源利用率下限（百分比），低于时仅记录 UnderUtilized 事件，不触发操作 |

## 注意事项

* 负载均衡任务与容灾任务互斥：当有迁移任务在执行时，系统不会生成新的均衡任务。
* 日志流创建和容灾任务的目的端选择也会参考节点负载，优先选择负载低的节点。
* 基于负载的均衡策略当前仅考虑 IO 负载（IOPS 和带宽），不涉及 CPU 和内存的均衡。
