# OceanSeek V4.6.3

## V4.6.3

### 版本信息

* 发布时间：2026 年 11 月 23 日
* 版本号：V4.6.3
* RPM 版本号：
    * oceanseek-4.6.3.0-482026112114

### 版本概览

OceanSeek V4.6.3 是面向 AI 搜索与湖仓数据管理的功能增强版本。本版本围绕向量与全文搜索、存储引擎与湖仓开放三大方向升级核心能力，重点提升向量与全文搜索的性能、召回率和可观测性，增强冷热数据访问、数据分支及 Catalog 同步能力，并完善 Java / Python UDF 的运行隔离能力和 CDC 数据同步的稳定性。具体能力如下：

* AI 引擎：优化异步搜索索引和异步全文索引的搜索性能，覆盖持续增量写入场景；HNSW 系列和 IVF 系列索引支持 L1（曼哈顿距离），丰富向量距离算法的选择；新增单次向量搜索 Profile，可查看过滤、索引搜索和增量数据处理等阶段的执行情况，辅助定位查询耗时；支持在线修改 HNSW 系列索引参数，构建参数通过后台分区重建生效，无需先删除索引再重新创建。逻辑表场景下，进一步提升 IVF 索引的查询性能稳定性、主备切换后的可用性及读写一致性等。
* 存储引擎：支持通过 `PARTITION TIER` 子句按分区冷热状态裁剪查询范围，减少不必要的数据访问。FORK TABLE / FORK DATABASE 扩展至列存表，并优化包含大量表的数据库的 Fork 性能，经测试包含 1000 张表的数据库单次 fork 耗时可控制在 10 秒以内，大大缩短评测与测试数据集的准备时间。同时完善了 CDC 的稳定性等。
* 计算引擎：Catalog 同步支持更多 DDL 操作、分区表及手动同步，湖仓一体化数据管理链路更加顺畅；Java / Python UDF 支持在独立子进程中运行，降低外部语言异常对 OBServer 主进程的影响等。

### 关键特性说明

#### AI 引擎

* 异步索引性能与稳定性增强（实验特性）

    优化异步搜索索引和异步全文索引的搜索性能，覆盖持续写入增量数据的场景。重点优化单路全文搜索、包含多个词元（Token）且仅需返回少量排名靠前结果（低 TopK）的搜索、短语匹配（`match_phrase`），以及不同取值较多的字段上的范围过滤（高 NDV Range）。减少重复扫描和候选结果处理的开销，同时提升增量写入、合并与故障恢复的稳定性。异步索引仍采用最终一致性，适用于可接受短暂数据可见延迟的业务。具体请参见[搜索索引](../400.ai-search/300.vector-search/210.search-index.md)和[全文搜索](../400.ai-search/500.full-text-search.md)。

* 带搜索索引或全文索引的表支持全量旁路导入

    批量写入带索引的表时，可通过全量旁路导入提升导入效率。带同步或异步搜索索引的堆表支持通过 `INSERT INTO ... SELECT` 或 `LOAD DATA` 执行全量旁路导入，不支持增量旁路导入；带全文索引的表仅支持在 `FULL` 模式下通过 `INSERT INTO ... SELECT` 执行全量旁路导入。具体限制请参见[搜索索引](../400.ai-search/300.vector-search/210.search-index.md)和[全文搜索](../400.ai-search/500.full-text-search.md)。

* 支持查看单次向量搜索的 Profile

    向量搜索 SQL 耗时较高或出现延迟偶尔明显升高时，可使用 `MONITOR` Hint 采集执行信息，再通过 `DBMS_XPROFILE.DISPLAY_PROFILE()` 按层次查看向量搜索内部各阶段的耗时与执行情况，包括标量过滤、向量索引搜索、增量数据处理等，辅助定位主要开销。该能力覆盖现阶段支持的所有稠密和稀疏向量索引；一次 Profile 仅反映指定查询的一次执行，不提供多次执行的平均耗时、P95 等汇总指标或历史趋势。具体请参见[索引监控与维护](../400.ai-search/300.vector-search/200.vector-index/600.vector-index-monitor-and-maintain.md)。

* 支持在线修改 HNSW 系列索引参数

    可通过 `DBMS_VECTOR.ALTER_INDEX_PARAMS` 在线调整 HNSW 系列索引的构建参数和查询参数，以适应数据规模、召回率、查询延迟或资源使用要求的变化，无需先删除索引再重新创建。构建参数变化时，系统在后台按分区异步重建，调用完成不代表所有数据段都已应用新参数；仅修改查询类参数时，不触发重建。可通过 HNSW Segment 信息视图的 `SEGMENT_PARAMS` 列查看各数据段（Segment）实际使用的索引参数。具体请参见 [ALTER_INDEX_PARAMS](../700.reference/600.pl-reference/1000.pl-system-package-mysql/17850.dbms-vector-mysql/900.alter-index-params-mysql.md)。

* 逻辑表场景下 IVF 索引能力增强

    在多个逻辑表共享物理表的场景下，优化带过滤的 IVF 系列索引向量搜索，使查询优化器更准确地根据当前逻辑表分区的数据分布选择执行路径，减少查询性能波动；主备切换后，系统异步恢复 IVF 聚类中心缓存（不包含 IVF_PQ），减少缓存恢复对前台查询的影响；同时完善 IVF 索引（不包含 IVF_PQ）的增量写入处理，提升读写一致性。

* HNSW 和 IVF 系列索引支持 L1 距离

    支持使用 L1（曼哈顿距离）进行向量索引搜索。L1 距离为两个向量各维度差值的绝对值之和，可根据业务需要作为 L2、内积和余弦距离之外的选择。创建索引时指定 `distance=l1`，搜索时使用 `l1_distance()`；仅支持 HNSW 和 IVF 系列索引中的 FP32 普通稠密向量，不支持量化索引或稀疏向量。具体请参见[向量函数](../400.ai-search/300.vector-search/250.vector-function.md)。

#### 存储引擎

* 支持按分区冷热状态查询数据

    同一张表同时保存热数据和冷数据时，可通过 `SELECT ... PARTITION TIER` 子句指定 `HOT`、`COLD`、`NOT_COLD` 或 `NOT_HOT`，仅查询符合冷热状态要求的分区。例如，在线业务可只查询热数据，归档分析可只查询冷数据，以控制查询范围，减少不必要的数据访问与资源开销。不指定该子句时，不按冷热状态限制查询范围。具体请参见 [PARTITION TIER](../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/8100.select-of-mysql-mode/600.partition-tier.md)。

* 支持 `ROWID`

    对于缺少合适主键的表，可先查询 `ROWID`，再通过该行标识定位需要更新或删除的数据，无需修改表结构。支持查询 `ROWID`、使用表别名限定 `ROWID`，以及在单目标表的 `UPDATE`、`DELETE` 中按 `ROWID` 定位行。`ROWID` 用于从查询到更新或删除期间的行定位，不应作为长期保存的业务标识。具体请参见 [ROWID 伪列](../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/50.rowid-pseudo-column.md)。

* 降低海量表场景下的元数据内存开销

    优化表结构元数据的缓存方式，按访问需要加载用户表的元数据，并允许从缓存中淘汰不常访问的表元数据，降低海量表场景下的内存开销。适用于表数量多、实际访问集中在部分表上的场景。

* FORK TABLE / FORK DATABASE 支持列存表

    数据分支能力扩展至列存表，行存表和列存表均可通过 FORK TABLE / FORK DATABASE 创建派生副本，用于数据评测、测试与分析。同时优化包含大量表时的 FORK DATABASE 性能，缩短数据库副本的准备时间。具体请参见 [Fork 概述](../380.data-branching/100.data-branching-overview.md)。

* 支持按维护时间窗口执行合并

    支持为租户级合并配置维护时间窗口，便于在业务低峰期安排合并，减少资源争用。窗口结束后不再调度新的合并任务，已开始的任务继续完成；本轮未完成的合并将在后续窗口沿用原目标继续执行，已达到目标的数据不再重复处理。同时支持自动和手动触发。

#### 计算引擎

* Catalog 同步能力增强

    增强 Catalog Sync，支持将 OceanSeek 中的库、表等元数据同步到 Hive Metastore（HMS），方便 Lakebase 通过 Unified Catalog 统一管理元数据，并供外部计算引擎发现和访问库内数据。本版本支持更多 DDL 操作和分区表，并新增手动同步能力，满足按需同步元数据的需求。具体请参见 [Catalog 数据自动同步](../300.data-pipeline/300.data-sharing/100.auto-synchronize-catalog-data.md)和 [Catalog 数据手动同步](../300.data-pipeline/300.data-sharing/200.manual-synchronize-catalog-data.md)。

* Java / Python UDF 支持独立子进程运行

    支持将 Java 或 Python UDF 运行时放入独立子进程（沙箱）执行，与 OBServer 主进程隔离，降低外部语言运行异常对数据库服务的影响。新增 `[G]V$OB_SANDBOX_PROCESS` 视图，用于查看子进程状态和资源使用情况。

    Java UDF 沙箱默认关闭，需在系统租户下通过集群级配置项 `ob_enable_java_udf_sandbox` 开启，并搭配相应版本的 Java SDK 使用。配置说明请参见 [ob_enable_java_udf_sandbox](../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16655.ob_enable_java_udf_sandbox.md)。

* 外表支持跳过 UTF-8 文件头的 BOM

    部分工具生成的 UTF-8 文件会在文件头添加字节顺序标记（BOM）。外表读取时，BOM 可能被当作首列内容，导致数据异常。本版本支持在 CSV / 文本外表的 `FORMAT` 中显式设置 `byteordermark=check`，检测并跳过文件头的 BOM，提高对这类文件的兼容性。不指定该属性或设置为 `nocheck` 时，不检测 BOM。

#### CDC

* 数据同步性能与稳定性增强

    优化增量数据抽取和同步的处理效率，降低高并发写入、跨机房抽取及大事务场景下的同步延迟。同时降低 CDC 进程的内存占用和 CPU 开销，减少延迟波动，提升单机及集中式 CDC 链路的稳定性。

* 支持过滤 TTL 删除产生的变更日志 

    OBKV 支持通过 `filter_ttl_delete_log` 配置是否过滤 TTL 删除产生的变更日志，减轻此类日志同步给 LogService 带来的 I/O 压力。该功能默认关闭；开启后，TTL 删除变更不再通过 CDC 向下游输出，下游对应数据也不会通过该链路自动删除，但不影响数据库内 TTL 任务的正常执行。该功能需搭配 V4.6.3 及以上版本的 liboblog 使用。具体请参见 [OBKV-Table TTL](../700.reference/960.obkv/100.obkv-table/700.obkv-table-reference/290.obkv-table-ttl.md)。

| **功能** | **说明** |
