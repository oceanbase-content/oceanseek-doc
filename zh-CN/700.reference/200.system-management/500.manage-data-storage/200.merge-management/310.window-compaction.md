# 窗口合并

窗口合并（Window Compaction）用于把租户合并任务集中安排在指定时段，减少对日常业务的影响。每轮合并使用一个固定的目标版本，完成合并和数据一致性校验后结束。

时间窗口只决定何时可以新增合并任务，不决定本轮是否结束。一轮合并可以跨多个窗口完成。

更进一步地，在开启了 cgroup 的 OceanBase AI 数据库集群中，OceanBase AI 数据库允许用户为窗口合并配置专门的资源计划，给合并窗口期的合并任务分配更多的 CPU/IO 资源，充分利用空闲时间进行数据整理工作。

## 使用限制及注意事项

* 窗口合并仅面向主用户租户，系统租户、Meta 租户和备租户不作为独立发起对象。不同用户租户可以分别配置窗口，各自维护目标和合并状态。

* 每轮目标固定。发起新一轮时，系统生成一个目标版本。本轮未完成前，跨窗口、重复请求或新增业务数据都不会替换这个目标。

* 合并状态不随窗口关闭而结束。一轮合并开始后，无论在窗口内还是窗口外，未完成时都保持 COMPACTING，完成后才变为 IDLE。完成判定包含数据一致性校验。

* 窗口结束时不取消已有任务。窗口内按可用资源安排任务；窗口结束后停止新增窗口合并任务，恢复普通资源配置。已经提交的任务继续执行，排队任务也可能在窗口外才开始执行，因此资源消耗不会立即归零。

* 未完成时跨窗口继续。如果一个窗口内没有完成，下一窗口成功触发后会继续原目标，已完成的工作无需从头再做。系统不保证一轮合并一定在一个窗口内完成。

* 提前完成不追加新目标。如果本窗口续跑的旧轮刚开窗就完成，或者新轮在窗口中途完成，系统都会结束本轮并恢复普通资源配置，不会利用剩余窗口时间自动开启第二轮。

    例如，每天 02:00 开始、持续 6 小时：第一天没完成，第二天继续原目标；若第二天 02:05 完成，当天剩余窗口不再追加目标。

* 与普通租户合并互斥。同一租户不能同时进行窗口合并和普通租户合并。任意一种尚未完成时，都不能用另一种替换当前轮次；窗口关闭也不能绕过此限制。

* 业务读写保持原有规则。合并期间业务可以继续读写，新写入的数据不会不断抬高本轮目标。建索引等操作仍遵循数据库原有规则；没有数据变化的表也不要求为了本轮合并而强制重写全部数据。

* 重启后继续原目标。节点以原版本重启后，会重新读取本轮目标并继续处理未完成的工作，不会因此生成新目标。若恢复时已在窗口外，尚未安排的工作仍需等待有效窗口。

* 完成本轮后才允许升级。本轮未完成时不允许升级，窗口外等待也属于尚未完成。窗口关闭、暂停合并或停用功能都不能代替完成本轮；完成后仍需满足升级的其他前置条件。

## 前提条件

* 触发合并前，需要确保全局合并开关已开启，全局合并开关由集群级配置项 [enable_major_freeze](../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/7000.enable_major_freeze.md) 控制，默认值为 `True`，表示开启合并开关。

  如果当前集群未开启全局合并开关，请参考以下操作开启全局合并开关。

  1. 使用 `root` 用户登录集群的 `sys` 租户。

  2. 确认全局合并开关是否已开启。

     ```shell
     obclient(root@sys)[(none)]> SHOW PARAMETERS LIKE 'enable_major_freeze';
     ```

  3. 如果显示未开启，执行以下语句，开启合并开关。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_major_freeze='True';
     ```

* 如果需要触发窗口合并，需要确保租户级配置项 [enable_window_compaction](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3150.enable_window_compaction.md) 为 `True`，即开启窗口合并。

  具体操作如下：

  1. 租户管理员登录集群的用户租户。

  2. 确认租户级配置项 `enable_window_compaction` 的值。

     ```shell
     obclient> SHOW PARAMETERS LIKE 'enable_window_compaction';
     ```

  3. 如果值为 `False`，执行以下语句，开启窗口合并。

     ```shell
     obclient> ALTER SYSTEM SET enable_window_compaction = True;
     ```

     系统租户下，可以通过指定租户名的方式进行设置，例如：`ALTER SYSTEM SET enable_window_compaction = True TENANT = tenant_name;`。

## 配置周期性触发窗口合并

类似于每日统计信息的收集，对于当前版本的每个用户租户，都在定时任务调度器 `DBMS_SCHEDULER` 中注册了 `DAILY_MAINTENANCE_WINDOW` 任务，用户可以根据业务需要，灵活定义窗口合并任务的开启或关闭、触发时间、执行时长等。

### 启用窗口合并任务

触发窗口合并需要用户手动启用窗口合并任务。

1. 租户管理员登录集群的用户租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_SCHEDULER` 系统包的 `ENABLE` 子程序，启用窗口合并。

   执行语句示例如下：

   ```shell
   obclient> CALL DBMS_SCHEDULER.ENABLE('DAILY_MAINTENANCE_WINDOW');
   ```

启用窗口合并任务后，默认窗口合并的开始时间为凌晨 `02:00`，持续时间为 6 小时，周期为每天。

### 修改窗口合并任务下次开始的时间

启用窗口合并任务后，默认下次窗口合并任务的执行开始时间为凌晨 `02:00`，用户可以根据业务需要，配置窗口合并任务下次开始的时间。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>窗口合并默认一天一次，如果修改了下次执行的时间，例如，修改为凌晨 <code>01:00</code>，则之后为每天凌晨 <code> 01:00</code> 执行窗口合并，而不再是凌晨 <code> 02:00</code>。</p>
</main>

1. 租户管理员登录集群的用户租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_SCHEDULER` 系统包的 `SET_ATTRIBUTE` 子程序，设置窗口合并任务下次开始的时间。

   语句如下：

   ```sql
   CALL DBMS_SCHEDULER.SET_ATTRIBUTE('DAILY_MAINTENANCE_WINDOW','NEXT_DATE', 'next_time');
   ```

   语句中，`next_time` 用于指定窗口合并任务下次开始的时间。

   示例如下：

   例如，设置窗口合并下次开始的时间为 `2026-03-10 01:00:00`。

   ```shell
   obclient(root@mysql001)[(none)]> CALL DBMS_SCHEDULER.SET_ATTRIBUTE('DAILY_MAINTENANCE_WINDOW', 'NEXT_DATE', '2026-03-10 01:00:00');
   ```

### 配置窗口合并任务的时长

启用窗口合并任务后，默认窗口合并任务的执行时长为 6 小时，用户可以根据业务需要，适当调整执行时长。

1. 租户管理员登录集群的用户租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_SCHEDULER` 系统包的 `SET_ATTRIBUTE` 子程序，设置窗口合并任务的执行时长。

   语句如下：

   ```sql
   CALL DBMS_SCHEDULER.SET_ATTRIBUTE('DAILY_MAINTENANCE_WINDOW', 'DURATION', duration);
   ```

   语句中，`duration` 用于指定窗口合并任务的执行时长，单位为秒，取值范围为 60 ~ 86400。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <ul><li>修改当前任务的执行时长会影响正在执行的任务本身。例如，调小 <code>duration</code> 的值将会导致当前正在执行的窗口合并任务提前结束。</li>
   <li>由于窗口合并每天调度一次，要求 <code>duration</code> 的值需要设置为小于 24 小时（86400）。</li></ul>
   </main>

   例如，设置窗口合并任务的时长为 10 小时，即 36000 秒。执行语句示例如下：

   ```shell
   obclient> CALL DBMS_SCHEDULER.SET_ATTRIBUTE('DAILY_MAINTENANCE_WINDOW', 'DURATION', 36000);
   ```

## 调整窗口合并的线程数

用户也可以根据业务需要，调整窗口合并的线程数。窗口合并期间，当 `DBMS_DAILY_MAINTENANCE.SET_THREAD_COUNT` 子程序中的 `thread_count` 显示设置为非 0 值的时候，合并线程数使用 `thread_count` 的设置值，当 `thread_count` 为默认值 `0`时，系统会取自适应值与[compaction_low_thread_score](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/1100.compaction_low_thread_score.md) 中的较大值。

1. 租户管理员登录集群的用户租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_DAILY_MAINTENANCE` 系统包的 `SET_THREAD_COUNT` 子程序，设置窗口合并专用的合并线程数。

   语句如下：

   ```sql
   DBMS_DAILY_MAINTENANCE.SET_THREAD_COUNT(thread_count);
   ```

   例如，设置窗口合并的后台合并线程 COMPACTION_LOW 的线程数为 8。执行语句示例如下：

   ```shell
   obclient> CALL DBMS_DAILY_MAINTENANCE.SET_THREAD_COUNT(8);
   ```

## （可选）配置窗口合并的资源管理计划

在开启了 cgroup 的集群上，窗口合并支持在合并期间切换到特定的资源管理计划，从而给合并任务提供更多的合并资源，让合并能够更快地执行，并覆盖充分多的分区，以确保业务高峰期时对分区操作的效率。

1. 租户管理员登录集群的用户租户。

2. 调用 `DBMS_RESOURCE_MANAGER` 系统包中的 `CREATE_CONSUMER_GROUP` 子程序，创建窗口合并专用资源组。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>窗口合并的资源租名称 <code>INNER_DAILY_WINDOW_COMPACTION_LOW_GROUP</code> 为固定名称，不能随意变更。</p>
   </main>

   执行语句示例如下：

   ```shell
   obclient> CALL DBMS_RESOURCE_MANAGER.CREATE_CONSUMER_GROUP(
     CONSUMER_GROUP => 'INNER_DAILY_WINDOW_COMPACTION_LOW_GROUP',
     COMMENT => 'consumer group for daily window maintenance job'
   );
   ```

3. 调用 `DBMS_RESOURCE_MANAGER` 系统包中的 `CREATE_PLAN` 子程序，创建窗口合并专用资源计划。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>窗口合并的资源管理计划名称 <code>INNER_DAILY_WINDOW_PLAN</code> 为固定名称，不能随意变更。</p>
   </main>

   执行语句示例如下：

   ```shell
   obclient> CALL DBMS_RESOURCE_MANAGER.CREATE_PLAN(
     PLAN => 'INNER_DAILY_WINDOW_PLAN',
     COMMENT => 'plan for daily window maintenance job'
   );
   ```

4. 调用 `DBMS_RESOURCE_MANAGER` 系统包中的 `CREATE_PLAN_DIRECTIVE` 子程序，创建资源管理计划对应的资源管理计划内容。

   执行语句示例如下：

   ```shell
   obclient> CALL DBMS_RESOURCE_MANAGER.CREATE_PLAN_DIRECTIVE(
     PLAN => 'INNER_DAILY_WINDOW_PLAN',
     GROUP_OR_SUBPLAN => 'INNER_DAILY_WINDOW_COMPACTION_LOW_GROUP',
     COMMENT => 'directive for window compaction',
     MAX_IOPS => 100,
     MIN_IOPS => 30,
     WEIGHT_IOPS => 50,
     UTILIZATION_LIMIT => 100,
     MGMT_P1 => 70
   );
   ```

配置成功后，当窗口合并任务开始执行时，系统会自动将当前的资源管理计划切换为窗口合并专用的资源计划 `INNER_DAILY_WINDOW_PLAN`，并将当前 COMPACTION_LOW 的 Function 线程（后台合并任务线程）的资源映射到窗口合并专用资源组 `INNER_DAILY_WINDOW_COMPACTION_LOW_GROUP` 上。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>配置窗口合并的资源管理计划后，在窗口合并期间，需要注意以下事项：</p>
<ul><li>不能删除窗口合并专用的资源计划 <code>INNER_DAILY_WINDOW_PLAN</code> 和窗口合并专用资源组 <code>INNER_DAILY_WINDOW_COMPACTION_LOW_GROUP</code>。</li>
<li>不能修改该租户下的所有资源管理计划。</li></ul>
</main>

## 手动触发窗口合并

启用窗口合并任务后，如果还未到窗口合并任务指定的执行时间，用户可以根据业务需要，手动触发窗口合并。

<main id="notice" type='notice'>
<h4>注意</h4>
<ul><li>仅允许用户租户手动触发窗口合并，系统租户（<code>sys</code> 租户）不支持手动触发窗口合并。</li>
<li>如果存在尚未完成的普通租户合并时，手动触发窗口合并会报错，需等待普通租户合并完成后再触发。</li>
<li>手动触发的窗口合并任务的执行时长同样受 <code>DBMS_SCHEDULER.SET_ATTRIBUTE</code> 子程序中窗口合并任务（DAILY_MAINTENANCE_WINDOW）的 <code>duration</code> 参数的控制，具体配置参见本文 <b>配置窗口合并任务的时长</b>。</li></ul>
</main>

1. 租户管理员登录集群对应的用户租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_DAILY_MAINTENANCE` 系统包的 `TRIGGER_WINDOW_COMPACTION_PROC` 子程序，手动触发一次窗口合并。

   执行语句示例如下：

   ```shell
   obclient> CALL DBMS_DAILY_MAINTENANCE.TRIGGER_WINDOW_COMPACTION_PROC();
   ```

## 禁用窗口合并任务

如果不期望再触发窗口合并，可以调用 `DBMS_SCHEDULER` 系统包的 `DISABLE` 子程序禁用窗口合并任务。

1. 租户管理员登录集群的用户租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_SCHEDULER` 系统包的 `DISABLE` 子程序，禁用窗口合并。

   执行语句示例如下：

   ```shell
   obclient> CALL DBMS_SCHEDULER.DISABLE('DAILY_MAINTENANCE_WINDOW');
   ```

禁用窗口合并任务后，系统将无法再触发窗口合并（触发周期性窗口合并、手动触发一次窗口合并等均不可以）。此外，如果租户级配置项 `enable_window_compaction` 的值仍为 `True`，则系统既不会触发窗口合并，也不会触发每日租户合并。如果期望在禁用窗口合并任务后执行每日租户合并，则需要将租户级配置项 `enable_window_compaction` 的值设置为 `False`。开启每日租户合并的详细操作，参见 [定时触发每日租户合并](300.scheduled-trigger-merge.md)。

配置项 [enable_window_compaction](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3150.enable_window_compaction.md) 和窗口合并任务 `DAILY_MAINTENANCE_WINDOW` 的取值与每日合并行为之间的关系如下：

| enable_window_compaction  | DAILY_MAINTENANCE_WINDOW         | 每日合并行为   |
|---------------------------|-----------------|---------------|
| False    | False（`CALL DBMS_SCHEDULER.DISABLE('DAILY_MAINTENANCE_WINDOW');`） |  触发每日租户合并 </br>`enable_window_compaction` 设为 `False` 后会停止新增窗口合并任务，但不会取消本轮窗口合并。如果本轮窗口合并尚未完成，普通租户合并仍然无法发起，因此切换前需要先确认本轮窗口合并已完成。 |
| False    | True（`CALL DBMS_SCHEDULER.ENABLE('DAILY_MAINTENANCE_WINDOW');`）   |  触发每日租户合并 </br>`enable_window_compaction` 设为 `False` 后会停止新增窗口合并任务，但不会取消本轮窗口合并。如果本轮窗口合并尚未完成，普通租户合并仍然无法发起，因此切换前需要先确认本轮窗口合并已完成。     |
| True    | False （`CALL DBMS_SCHEDULER.DISABLE('DAILY_MAINTENANCE_WINDOW');`）|  不触发任何合并，即既不触发窗口合并，也不触发每日租户合并      |
| True   | True（`CALL DBMS_SCHEDULER.ENABLE('DAILY_MAINTENANCE_WINDOW');`）   |  触发窗口合并 |

## 状态查询

执行以下命令查看窗口合并的状态。

```sql
SELECT MODE, STATUS, GLOBAL_BROADCAST_SCN, LAST_SCN,
       START_TIME, IS_SUSPENDED, IS_ERROR
FROM oceanbase.DBA_OB_MAJOR_COMPACTION;
```

* 合并模式：`MODE='WINDOW'` 表示当前或最近一轮是窗口合并。

* 合并版本：`GLOBAL_BROADCAST_SCN` 是本轮目标版本，`LAST_SCN` 是最近完成的版本。

* 窗口与暂停：`START_TIME` 是记录的窗口开始时间，`IS_SUSPENDED='YES'` 表示被显式暂停。

* 完成条件：本轮完成后，`STATUS='IDLE'`、`LAST_SCN=GLOBAL_BROADCAST_SCN`，且 `IS_ERROR='NO'`。刚发起时还需排除查到上一轮旧状态的情况。

## 常见问题

* Q：手工触发和每日任务碰到一起，会发起两轮吗？

    不会。两种入口使用相同的重复请求检查。手工触发会从调用时刻开始一个窗口；如果与随后的每日任务重叠，后者可能被当作重复请求拒绝。

* Q：为什么目标版本没变，`START_TIME` 却变了？

    这是跨窗口续跑的正常表现。`START_TIME` 更新为新窗口的开始时间，目标仍是上一窗口未完成的版本，不能把时间变化当作开始了新一轮。

* Q：修改时长或下一次执行时间，会影响当前合并吗？

    修改 `DURATION` 会影响当前窗口：缩短后可能提前关闭；延长后，若本轮未完成且仍在新的截止时间内，可以继续或恢复安排任务。修改 `NEXT_DATE` 只调整下一次触发时间，不改变当前目标或窗口起点。配置通过后台刷新生效，可能稍有延迟。

* Q：将窗口设为 24 小时，会一直开始新一轮吗？

    不会。`DURATION=86400` 允许已开始的这一轮持续安排任务，直到完成；不会在完成后自动循环生成目标。新一轮仍需要后续有效触发。

* Q：禁用每日任务后，还能手工发起吗？

    不能。手工入口也要求 `DAILY_MAINTENANCE_WINDOW` 处于启用状态。禁用该任务不仅会停止自动触发，也会阻止手工触发和新增窗口合并任务。

* Q：重新打开开关，就会立即继续合并吗？

    不一定。只有本轮尚未完成、当前仍在有效窗口内、每日任务已启用且没有暂停合并时，才可以继续安排任务。如果窗口已结束，还需下一次有效触发。开关本身不会更新窗口起点，也不会生成新目标。

* Q：窗口关闭和暂停合并是一回事吗？

    不是。正常关窗不会把 `IS_SUSPENDED` 设为 YES。显式暂停会阻止新增合并任务，但不会取消本轮；解除暂停后仍受时间窗口限制，不会自动重开窗口。

* Q：显示 COMPACTING，但暂时没有任务，是异常吗？

    不一定。窗口外可能正在等待下一窗口，窗口内也可能在等待资源、共享数据就绪或后台扫描。COMPACTING 表示本轮未完成，不保证始终有任务执行；多个有效窗口都没有进展则不能只当作正常等待。

* Q：开启窗口合并后，普通每日合并还会执行吗？

    `enable_window_compaction=true` 时，不再按 `major_freeze_duty_time` 自动发起普通租户合并，即使每日窗口任务被禁用也一样。上一轮完成且原有条件允许时，仍可以显式发起普通租户合并。

* Q：合并错误也是正常的跨窗口等待吗？

    不是。`IS_ERROR='YES'` 表示存在合并错误，不能当作正常等待，也不能靠重复发起消除。请保留错误信息并联系技术支持。
