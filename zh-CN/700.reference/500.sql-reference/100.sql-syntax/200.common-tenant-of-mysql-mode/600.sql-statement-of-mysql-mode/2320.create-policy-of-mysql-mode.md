# CREATE POLICY

## 描述

该语句用于在表上创建行级权限（Row-Level Security，RLS）策略。策略定义适用的 SQL 命令、角色，以及 `USING` / `WITH CHECK` 条件。

## 权限要求

执行 `CREATE POLICY` 语句，需要当前用户对目标表拥有对象级 `ALTER` 权限。库级或全局 `ALTER` 若已覆盖该表，同样满足要求。更多说明请参见 [权限分类](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)。

## 使用限制及注意事项

* 系统内部表、外部 Catalog 中的表，以及回收站中的对象不支持创建 RLS 策略。
* 创建策略不会自动启用表的 RLS，还需执行 `ALTER TABLE ... ENABLE ROW LEVEL SECURITY`。

## 语法

```sql
CREATE POLICY [IF NOT EXISTS] policy_name ON [schema_name.]table_name
    [AS {PERMISSIVE | RESTRICTIVE}]
    [FOR {ALL | SELECT | INSERT | UPDATE | DELETE}]
    [TO role_name [, role_name ...]]
    [USING (using_expression)]
    [WITH CHECK (check_expression)]
```

## 参数说明

| **参数** | **默认值** | **说明** |
| --- | --- | --- |
| IF NOT EXISTS |  | 同名策略已存在时不报错，静默跳过。 |
| policy_name |  | 策略名。 |
| table_name |  | 目标对象名。可使用 `database_name.table_name` 显式指定数据库。 |
| AS | PERMISSIVE | 策略类型：`PERMISSIVE`（宽松）或 `RESTRICTIVE`（严格）。同表多条策略并存时的合并规则见下文说明。 |
| FOR | ALL | 策略适用的 SQL 命令类型：`ALL`（同时适用于后述四类命令）、`SELECT`、`INSERT`、`UPDATE` 或 `DELETE`。 |
| TO | PUBLIC | 适用角色。省略或 `PUBLIC` 表示所有用户。 |
| USING |  | 行可见性过滤表达式（读、更新旧行、删除）。 |
| WITH CHECK | 若省略且已有 `USING`，则等于 `USING` | 写操作新行校验表达式（插入、更新后的新行）。 |

各 `FOR` 类型允许的表达式如下：

| **FOR 类型** | **USING** | **WITH CHECK** | **作用** |
| --- | --- | --- | --- |
| SELECT | 必需 | 不允许 | 过滤读取行 |
| INSERT | 不允许 | 必需 | 校验新行 |
| UPDATE | 可选 | 可选 | `USING` 过滤旧行，`WITH CHECK` 校验新行 |
| DELETE | 必需 | 不允许 | 过滤待删除行 |
| ALL | 可选 | 可选 | 同时用于四类命令 |

说明及限制如下：

* 同名策略已存在时，`IF NOT EXISTS` 只静默跳过，不会替换或合并原策略。
* 策略名在同一表内必须唯一；不同表可使用相同策略名。
* 同一表上多条策略按类型合并：同类型的宽松策略（`PERMISSIVE`）之间按 `OR` 合并，同类型的严格策略（`RESTRICTIVE`）之间按 `AND` 合并；两类同时存在时，先合并全部宽松策略，再与每条严格策略做 `AND`。即形如 `(PERM1 OR PERM2 OR ...) AND REST1 AND REST2 AND ...`。仅有宽松策略时，满足任一即可；仅有严格策略时，须全部满足。
* 策略必须至少指定一个 `USING` 或 `WITH CHECK` 表达式。
* 对于 `UPDATE` 或 `ALL`，若只有 `USING`，则写入校验默认复用 `USING`。若只有 `WITH CHECK`，读取、更新旧行和删除没有可用的 `USING` 条件，相应命令会拒绝所有行。
* `USING` / `WITH CHECK` 结果须为布尔类型。支持列引用、子查询、内置函数；禁止聚合函数和窗口函数。
* 若新行不满足 `WITH CHECK`，写操作报错 `OB_ERR_POLICY_WITH_CHECK_OPTION_VIOLATION`。

## 示例

以下示例仅供参考，实际使用时请根据实际情况进行调整：

```sql
-- 对所有用户创建宽松策略
CREATE POLICY emp_dept_policy ON hr.employees
    FOR SELECT
    -- SELECT 时只能看到自己部门的行
    USING (dept_id = CURRENT_USER_DEPT());

CREATE POLICY mgr_write_policy ON hr.employees
    -- 对 manager 角色创建限制性策略
    AS RESTRICTIVE
    FOR INSERT, UPDATE
    TO manager
    USING (dept_id = GET_MY_DEPT())
    -- INSERT/UPDATE 时校验新行的 dept_id
    WITH CHECK (dept_id = GET_MY_DEPT());

-- 同名已存在时不报错
CREATE POLICY IF NOT EXISTS emp_dept_policy ON hr.employees
    USING (1 = 1);
```
