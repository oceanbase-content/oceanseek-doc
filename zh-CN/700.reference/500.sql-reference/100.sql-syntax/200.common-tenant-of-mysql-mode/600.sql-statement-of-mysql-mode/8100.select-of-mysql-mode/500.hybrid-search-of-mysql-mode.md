# HYBRID_SEARCH

`HYBRID_SEARCH` 用于在一条 `SELECT` 语句中，通过符合本文档规则的 JSON 字符串描述全文搜索、向量搜索与过滤条件，并返回按融合策略排序后的行。

## 语法

```sql
SELECT select_expr_list
FROM HYBRID_SEARCH(TABLE table_name, dsl_string) [table_alias];

-- select_expr_list 为 SELECT 列表
-- 除表列外，还可引用混搜伪列，具体见下文“伪列”小节
```

## 参数说明

| **参数** | **说明** |
| --- | --- |
| `table_name` | 目标表名。仅支持堆表（`ORGANIZATION = HEAP`），可为分区表或非分区表。 |
| `dsl_string` | JSON 字符串，描述 `query`、`knn`、`rank`、`rerank`、`aggs`、`collapse`、`sort`、`from`、`size`、`min_score` 等。 |

## 全局限制与说明

本节只列出语法限制，功能限制请参见 [混合搜索](#相关文档)，需结合本节内容一并理解。

说明如下：

* 顶层 `query`（全文搜索）和 `knn`（向量搜索）加起来最多允许有三个子查询：`query` 算一个；`knn` 如果是对象算一个，如果是数组则每个元素各算一个。三者总数不得超过三个，并且至少要包含一个全文搜索或向量搜索。
* 对于查询的列名，大小写不敏感。
* 向量查询的 `query_vector`，推荐用字符串输入向量。
* `min_score` 参数只有 SQL 接口支持，PL 接口不支持。
* `query` 和每个 `knn` 都是相互独立的搜索路径，彼此的 `filter` 互不影响。如果某一路查询需要过滤条件，必须在该路径下单独指定对应的 `filter`。所有搜索结果会合并为一个结果集，并基于融合算法进行打分排序，最终返回前 `size` 条结果。
* 任意查询可支持 `boost`，但不一定参与算分，具体规则请参见下文 [boost 参数详细说明](#boost%20参数详细说明)小节。
* `rerank` 须与 `query` 或 `knn` 同时使用，不能单独出现；执行顺序为先粗排、后精排，不支持仅用 `rerank` 替代 `rank` 的融合能力。

限制如下：

* 不支持 `rank_feature`，`es_mode`，`_source` 参数。
* 不支持在与 `HYBRID_SEARCH` 同层直接使用 `WHERE` / `ORDER BY` / `LIMIT`；若需要进一步过滤或排序，请将混搜结果作为子查询再处理。例如：

    ```sql
    -- 不支持：与 HYBRID_SEARCH 同层使用 WHERE
    SELECT id
    FROM HYBRID_SEARCH(TABLE doc_table, '{"knn":{"field":"vector","k":5,"query_vector":"[1,2,3]"}}')
    WHERE id > 3;

    -- 支持：先子查询，再过滤
    SELECT id
    FROM (
      SELECT id
      FROM HYBRID_SEARCH(TABLE doc_table, '{"knn":{"field":"vector","k":5,"query_vector":"[1,2,3]"}}')
    ) t
    WHERE id > 3;
    ```

* 部分嵌套 JSON/ARRAY 元素路径不支持下推，如 `json` 的 `path` 里如果是 `array`，元素是 `json`，不支持再对这个 `json` 元素指定路径。
* 标量查询条件，包括 `term` / `range` / `terms` / `wildcard` / JSON 表达式 / 数组表达式，均支持 `boost`。置于顶层 `query`、`bool.must` / `bool.should` 时参与算分；置于 `bool.filter` / `bool.must_not` / `knn.filter` 时仅作硬过滤。具体规则请参见下文 [boost 参数详细说明](#boost%20参数详细说明)小节。
* 非顶层全文查询的 `boost`、`bool` 查询的 `boost`、全文查询的列权重和词权重，要求大于 `0`，其他情况的 `boost` 要求大于等于 `0`。
* `multi_match` / `query_string` 多查询的多个全文列，必须是使用相同的字符集和 `collation`，全文索引必须使用相同的 `parser`。
* `match` / `multi_match` / `query_string` 用于词项级匹配时，对应全文列应使用 `FTS_INDEX_TYPE = MATCH`（或未指定时与 `MATCH` 等价的默认类型）。`match_phrase` 仅适用于已创建 `FTS_INDEX_TYPE = PHRASE_MATCH` 的全文索引列。
* `sort` 与 `rank` 不支持同时指定；`aggs` 与 `sort` 不支持同时指定；`aggs` 与 `collapse` 不支持同时指定。
* 支持 `SELECT count(*)` 查询，该查询的 SELECT 列表仅支持 `count(*)`，不支持与表列、`__score` 或聚合伪列混写。伪列说明见下文[伪列](#聚合伪列)小节；计数语义见 “计数查询（`count(*)`）” 小节。

## DSL_STRING 参数语法结构

`dsl_string` 是 JSON 格式的字符串，其语法结构将在此节详细介绍，请配合下文参数和示例一起理解。

### 语法说明

本节介绍 BNF（Backus-Naur Form，巴科斯范式）语法符号的含义和使用规则：

1. 可选参数表示

   * `[ ]` 在 BNF 中表示可选多个元素，如 `param_list = param [, param]*` 表示 `param_list` 可以包含 1 个或多个 `param`。
   * `rank_expression` 中 `[ ]` 也表示子参数可选。
   * `[, "boost" : boost_value]` 代表在支持 `boost` 的表达式中该子参数可选。

2. 数组表示
   * `[ ]` 在 JSON 结构中表示数组，如 `[condition_list]`。

3. 选择关系
   * `|` 表示选择关系，如 `param = "query" | "knn"` 表示 param 可以是 "query" 或 "knn"。

4. 重复表示
   * `*` 表示 0 次或多次重复，如 `param_list = param [, param]*` 表示 `param_list` 可以包含 1 个或多个 `param`。

5. JSON 格式要求
   * 所有 JSON 列名和字符串值都需要用双引号包围。
   * 数值不需要用双引号包围。

#### 顶层参数结构

顶层参数结构用于指定混合搜索的参数。

```sql
dsl_string = '{param_list}'
    param_list = param [, param]*
    -- query 和 knn 至少必选一个；混合搜索时可同时使用
    param = "query"     : {query_expression} -- 值为 JSON 对象，须含查询表达式，可附带 search_options
          | "knn"       : {knn_expression}
          | "rank"      : {rank_expression}
          | "rerank"    : {rerank_params}
          | "aggs"      : {aggs_expression}
          | "collapse"  : {collapse_expression}
          | "sort"      : [sort_item_list]
          | "from"      : number
          | "size"      : number
          | "min_score" : number -- 仅 SQL 接口支持
```

##### 查询表达式结构

混合搜索的全文、标量条件都写在 `query` 里。`query` 的值是一个 JSON 对象：内层必须是下面语法中的某一种 `query_expression`（如 `bool`、`match`、`term` 等）。如需配置召回并行等选项，可在同一 JSON 对象中增加可选字段 `search_options`，写法见 [查询选项结构](#查询选项结构)。

```sql
query_expression = bool_query | scalar_term | fulltext_term | nested_query

bool_query = "bool" : {bool_condition_list}
    bool_condition_list = bool_condition [, bool_condition]*
    bool_condition = "must"    : [condition_list]
                  | "should"   : [condition_list]
                  | "must_not" : [condition_list]
                  | "filter"   : [condition_list]
                  | "minimum_should_match" : msm_value -- bool 级 minimum_should_match，从 V4.6.2.1 版本开始支持
                  | "boost"    : boost_value
    condition_list = query_expression [, query_expression]*
```

`bool` 下 `must` / `should` / `must_not` / `filter` 的值均为查询表达式数组：数组中每一项仍是完整的 `query_expression`（可继续嵌套 `bool`、`nested` 或接 `match` / `term` 等）。下面仅展示 `query` 对象的内层片段示例：

:::collapse
```shell
{
  "bool": {
    "must": [
      {
        "match": {
          "content": "oceanbase"
        }
      }
    ],
    "filter": [
      {
        "term": {
          "status": 1
        }
      }
    ]
  }
}
```
:::

###### 标量查询结构

用于定义单个词条中的标量查询表达式，包含 `range_query`、`term_query`、`terms_query`、`wildcard_query`，表示范围查询、精准匹配、多值匹配、通配符匹配。

```sql
scalar_term = range_query | term_query | terms_query | wildcard_query

range_query = "range" : {"field_name" : {range_condition_list}}
    range_condition_list = range_condition [, range_condition]*
    range_condition = "gte" : number
                    | "gt"  : number
                    | "lte" : number
                    | "lt"  : number
                    | "boost" : boost_value

term_query = "term" : {term_condition_list}
    term_condition_list = term_condition [, term_condition]*
    term_condition = "field_name" : scalar_value
                   | "field_name" : term_value_object
    term_value_object = "value" : scalar_value
                      [, "boost" : boost_value]

terms_query = "terms" : {terms_condition_list [, "boost" : boost_value]}
    terms_condition_list = terms_condition [, terms_condition]*
    terms_condition = "field_name" : [scalar_value_list]
    scalar_value_list = scalar_value [, scalar_value]*

wildcard_query = "wildcard" : {wildcard_condition_list}
    wildcard_condition_list = wildcard_condition [, wildcard_condition]*
    wildcard_condition = "field_name" : wildcard_pattern
                       | "field_name" : {wildcard_value_object}
    wildcard_pattern = "string_value" | number | boolean
    wildcard_value_object = wildcard_value_body [, "boost" : boost_value]
    wildcard_value_body = "value" : wildcard_pattern
                       | "wildcard" : wildcard_pattern
```

`term` / `terms` 除支持标量列外，还支持单级数组列及 JSON 文档内的数组路径，具体如下：

| **查询** | **列类型** | **描述** |
| --- | --- | --- |
| `term` | 标量 | 等值匹配 |
| `term` | 单级数组 | 判断数组是否包含标量 |
| `term` | JSON 内数组 | 判断数组是否包含标量 |
| `terms` | 标量 | 字段值在参数列表中 |
| `terms` | 单级数组 | 判断参数数组与数组列有交集 |
| `terms` | JSON 内数组 | 判断参数数组与 JSON 数组有交集 |

限制说明如下：

* `term`/`terms` 当前仅支持单级数组。

###### 嵌套查询结构

###### 全文查询结构

用于定义单个词条中的全文查询表达式，包含 `match_query`、`match_phrase_query`、`query_string`、`multi_match`，表示词项级匹配、短语级匹配、全文查询、多列词项级匹配。

```sql
fulltext_term = match_query | match_phrase_query | query_string | multi_match

match_query = "match" : {"field_name" : match_body}
    match_body = "string_value" | {match_condition}
    match_condition = "query" : "string_value" [, "operator" : ("OR" | "AND")] [, "minimum_should_match" : msm_value] [, "boost" : boost_value]
    -- minimum_should_match 仅在 operator 为 OR（含未指定时的默认 OR）时生效；operator = AND 时要求全部词元命中，与 minimum_should_match 语义冲突，二者不可同时使用

match_phrase_query = "match_phrase" : {"field_name" : phrase_body}
    phrase_body = "string_value" | {phrase_condition}
    phrase_condition = "query" : "string_value" [, "slop" : number] [, "boost" : boost_value]

query_string = "query_string" : {query_string_condition}
    query_string_condition = "fields" : [field_weight_list]
                           | "query"  : "string_value" -- 可含词元级 ^，具体见下文「权重运算符说明」
                           | "boost"  : boost_value
                           | "type"   : ("best_fields" | "most_fields")
                           | "default_operator" : ("AND" | "OR")
                           | "minimum_should_match" : msm_value
    -- minimum_should_match 仅在 default_operator 为 OR（含默认 OR）时生效

multi_match = "multi_match" : {multi_match_condition}
    multi_match_condition = "fields" : [field_weight_list]
                         | "query"  : "string_value" -- 不支持查询串内词元级 ^
                         | "boost"  : boost_value
                         | "type"   : ("best_fields" | "most_fields")
                         | "operator" : ("AND" | "OR")
                         | "minimum_should_match" : msm_value
    -- minimum_should_match 仅在 operator 为 OR（含默认 OR）时生效
    field_weight_list = field_weight [, field_weight]*
    field_weight = "field_name[^number]"

msm_value = number | "string_value" -- 字符串类型从 V4.6.2.1 版本开始支持
```

```sql
search_options = "search_options" : {search_options_body}
    search_options_body = "query_dop" : number
```

##### 向量与排序结构

用于指定向量搜索参数，可配置搜索向量字段、相似度、过滤条件、权重等信息，支持单路及多路向量检索。

```sql
knn_expression = "knn" : {knn_condition_list} | [multi_knn_condition_list]
    knn_condition_list = knn_condition [, knn_condition]*
    knn_condition = "field"           : "field_name"
                 | "k"               : number
                 | "query_vector"    : [vector_values]
                 | "num_candidates"  : number
                 | "search_options"  : {search_option_list}
                 | "filter"          : [condition_list]
                 | "similarity"      : number
                 | "boost"           : boost_value
    search_option_list = search_option [, search_option]*
    search_option = "ef_search"    : number
                 | "refine_k"      : number
                 | "filter_mode"   : ("pre" | "pre-knn" | "pre-brute" | "post" | "post-index-merge")
    multi_knn_condition_list = {knn_condition} [, {knn_condition}]*
    vector_values = float [, float]*

rank_expression = "rank" : {rank_strategy}
    rank_strategy = "rrf" : {rrf_params}
                  | "weighted_sum" : {weighted_sum_params}
    rrf_params = "rank_window_size" : number [, "rank_constant" : number]
    weighted_sum_params = "rank_window_size" : number [, "normalizer" : ("minmax" | "none")]

rerank_params = "model" : "string_value"
              | "field" : "field_name"
              | "query" : "string_value"
              | "rank_window_size" : number
              | "type" : "string_value"

aggs_expression = "aggs" : {aggregation_bucket}
    aggregation_bucket = "agg_name" : {aggregation_body}
    aggregation_body = "terms" : {terms_condition_list}
                     | "cardinality" : {cardinality_condition_list}
    terms_condition_list = terms_condition [, terms_condition]*
    terms_condition = "field" : "field_name"
                    | "size" : number
                    | "min_doc_count" : number
                    | "order" : {"_count" : ("asc" | "desc")}
                    | "order" : {"_key" : ("asc" | "desc")}
    cardinality_condition_list = "field" : "field_name"

collapse_expression = "collapse" : {collapse_condition_list}
    collapse_condition_list = "field" : "field_name"

sort_item_list = sort_item [, sort_item]*
    sort_item = "field_name"
              | "__score"
              | {"field_name" : {sort_condition_list}}
    sort_condition_list = sort_condition [, sort_condition]*
    sort_condition = "order" : ("asc" | "desc")
                   | "missing" : ("_first" | "_last" | number)
```

单路向量搜索时，`knn` 为单个对象；多路时为对象数组，每个元素是一组 `knn_condition`。下面仅展示多路向量搜索时的 `knn` 片段示例：

:::collapse
```shell
{
  "knn": [
    {
      "field": "vector_a",
      "k": 3,
      "query_vector": "[1,0,0]"
    },
    {
      "field": "vector_b",
      "k": 3,
      "query_vector": "[0,1,0]"
    }
  ]
}
```
:::

#### 权重运算符说明

权重运算符 `^` 用于指定**全文查询**语句中**列级别**或者**词元（Token）级别**的权重，语法格式为 `列名^权重` 或 `关键词^权重`，例如 `"title^2.0"`。参数支持如下：

* 仅 `multi_match` 和 `query_string` 支持列级别权重。
* 仅 `query_string` 支持词元级别权重。

词元级别的权重运算符用于指定其左侧关键词（截至空格）的权重，无权重运算符对应的关键词的默认权重为 1.0。一个权重运算符对应的关键词或者连续的无权重运算符对应的关键词为一组。

```shell
{
  "query": {
    "query_string": {
      "fields": ["title^2.0", "content"],
      "query": "红心火龙果 果冻橙^1.5 秋月梨^1.2 蓝莓 山竹"
    }
  }
}
```

如上例所示，查询词元 `"红心火龙果 果冻橙^1.5 秋月梨^1.2 蓝莓 山竹"` 时，词元会分为四组，分别为：默认权重为 1.0 的红心、火龙果，指定权重为 1.5 的果冻、橙，指定权重为 1.2 的秋月、梨，默认权重为 1.0 的蓝莓、山竹。

权重运算符可以和 `boost` 参数同时使用，具体示例见下一小节 [boost 参数详细说明](#boost%20参数详细说明)。

#### boost 参数详细说明

`boost` 参数用于指定查询条件在最终相关性计算中的权重。标量条件满足时计 1 分，再乘以级联的 `boost`。不指定时默认为 `1`。级联指的是 `boost` 参数在参与算分时采用嵌套层级相乘的方式进行计算，例如 `bool.boost × 子查询 boost`。

1. 支持 `boost` 的表达式

    * `bool` 查询。
    * 全文查询（如 `match`、`match_phrase`、`query_string`、`multi_match`）。
    * 向量查询（单路/多路 `knn`）。
    * 标量查询：`term` / `range` / `terms` / `wildcard`。
    * JSON/ARRAY 标量表达式。
    * `nested` 查询。

2. 是否参与算分

    | **查询位置** | **是否计入 `__score`** |
    | --- | --- |
    | 顶层 `query` 子句 | 是 |
    | `bool.must`、`bool.should` | 是（仅当其外层参与算分时才计入，如 `bool.filter.bool.must` 中，内层 `must` 并不计分） |
    | `bool.filter`、`bool.must_not` | 否 |
    | `knn.filter` | 否 |
    | 嵌套在 `filter`/`must_not` 内的 `bool` | 否（该 `bool` 及其子查询均不算分） |

3. 取值约束

    * 非顶层全文查询的 `boost`、`bool` 查询的 `boost`、全文查询的列权重和词权重，要求大于 `0`。
    * 其他情况的 `boost` 要求大于等于 `0`。

4. 语法示例

    a. 标量 `range` 带 `boost`：

    ```shell
    {
      "range": {
        "c1": {
          "gt": 1,
          "boost": 2.1
        }
      }
    }
    ```

    b. 标量 `term` 带 `boost`：

    ```shell
    -- 简写，默认 boost 为 1
    {
      "term": {
        "c1": 1
      }
    }
    ```

    ```shell
    -- 对象形式
    {
      "term": {
        "c1": {
          "value": 1,
          "boost": 2.35
        }
      }
    }
    ```

    c. 标量 `terms` 带 `boost`：

    ```shell
    {
      "terms": {
        "c1": [1, 3, 5],
        "boost": 3.14
      }
    }
    ```

    d. `wildcard` 带 `boost`：

    ```shell
    -- 简写，默认 boost 为 1
    {
      "wildcard": {
        "content": "*ocea*"
      }
    }
    ```

    ```shell
    -- 对象形式
    {
      "wildcard": {
        "content": {
          "value": "*ocea*",
          "boost": 1.8
        }
      }
    }
    ```

    e. JSON/单级数组表达式带 `boost`：

    ```shell
    {
      "json_contains": {
        "meta_json": {
          "candidate": "\"mysql\"",
          "path": "$.tags",
          "boost": 3.14
        }
      }
    }
    ```

    ```shell
    {
      "array_contains": {
        "tag_array1": {
          "arg": "ios",
          "boost": 2.1
        }
      }
    }
    ```

    f. 查询级别 `boost`（`bool`）：

    ```shell
    {
      "bool": {
        "must": [{"range": {"c1": {"gt": 1, "boost": 2.1}}}],
        "boost": 9.131
      }
    }
    ```

    上述示例中，`must` 内 `range` 满足时得分 = 1 × 2.1 × 9.131。

    g. 列级权重（`query_string`）：

    ```shell
    {
      "query_string": {
        "fields": ["product_name^2.0", "description^1.0"],
        "query": "gaming keyboard",
        "boost": 1.5
      }
    }
    ```

    h. 向量查询 `boost`（`knn`）：

    ```shell
    {
      "knn": {
        "field": "vector",
        "k": 5,
        "query_vector": "[1,2,3]",
        "boost": 1.5,
        "filter": [
          {"range": {"c1": {"gt": 1, "boost": 2.1}}}
        ]
      }
    }
    ```

    `knn` 本身参与算分；`knn.filter` 内的标量条件不参与算分。

#### minimum_should_match

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>自 V4.6.2.1 起，<code>match</code>、<code>multi_match</code>、<code>query_string</code> 除了支持整型 <code>minimum_should_match</code> 外，还支持字符串类型（含百分数、组合式等），并支持 <code>bool</code> 级 <code>minimum_should_match</code>。</p>
</main>

`minimum_should_match`（简称 MSM）表示最小匹配数，即指定至少命中多少个可选单元，文档才算匹配。

##### 典型场景

MSM 常见有两类大场景：

* 全文搜索的 `OR` 场景：`match` / `multi_match` 中 `operator` 为 `OR` 或未设置（默认为 `OR`），或 `query_string` 中 `default_operator` 为 `OR` 或未设置时即为此场景。MSM 可写在 `match`、`multi_match` 或 `query_string` 子句中，默认值均为 `1`。`operator` / `default_operator` 为 `AND` 时要求全部可选单元命中，与 MSM 的语义冲突，二者不可同时使用；MSM 仅在上述 `OR` 场景下生效。
* `bool` 的可选子句场景：`bool` 中包含一条或多条 `should` 时即为此场景。`should` 数组中每条均为可选子查询；MSM 写在该 `bool` 对象内（与 `should` 并列），用于规定至少多少条 `should` 成立才算匹配。不同条件下 MSM 默认值不同：
  * 仅有 `should` 子句、且无 `must`/`filter` 子句时，默认值为 `1`；
  * 存在 `must` 或 `filter` 子句时，默认值为 `0`。
  * 无 `should`、仅有 `must`/`filter` 子句时，不会报错但无实际作用。

计算 MSM 时，需先确定 N，即可选单元总数。后续无论 MSM 取正整数、负整数还是百分数，都相对 N 换算为实际最小命中数。各查询子句类型对应的 N 值如下：

| **查询子句类型** | **N 值** |
| --- | --- |
| `match` / `multi_match` | 查询分词后的词元（token）数 |
| `query_string` | 按 `query` 中词元级权重 `^` 分段后的组数（规则见上文[权重运算符说明](#权重运算符说明)；不是分词后的词元个数） |
| `bool` | 对象内 `should` 子句的条数 |

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>下文将 MSM 所统计的单位统称为 <b>可选单元</b>。其中 <code>match</code> / <code>multi_match</code> 为词元，<code>query_string</code> 为按 <code>^</code> 分段后的组，<code>bool</code> 为 <code>should</code> 子句。</p>
</main>

##### 单值匹配逻辑

MSM 支持设置为整型值或字符串。字符串若整串可严格解析为整数，则与直接写整型效果相同；否则按字符串规格解析。本节示例若无特别说明，均设 `N = 10`。

###### 正整数

表示至少需要满足的可选单元数（本节最终计算结果设为 `m`），取值范围为 `[0, N]`，`m=min(MSM, N)`。

| **MSM 值** | **计算（N=10）** | **说明** |
| --- | --- | --- |
| `2` 或 `"2"` | m = min(2, 10) = 2 | 至少命中 2 个 |
| `0` | m = min(0, 10) = 0 | 按查询类型特殊处理：<ul><li><code>match</code> / <code>multi_match</code> / <code>query_string</code> 实际视作 <code>1</code>；</li><li><code>bool</code> 仅含 <code>should</code> 时手动设为 <code>0</code> 无效（系统强制为 <code>1</code>）；</li><li><code>bool</code> 同时含 <code>must</code> 或 <code>filter</code> 时 <code>0</code> 生效，表示文档只要通过 <code>must</code>/<code>filter</code> 即可进入结果集</li></ul> |
| `12`（≥ N） | m = min(12, 10) = 10 | 等价于全部命中（`operator = AND`） |

```shell
"minimum_should_match": 2
```

###### 负整数

表示允许不满足的最大可选单元数（本节最终计算结果设为 `m`），在 N 的基础上减去 `|MSM|`，计算公式为 `m = N - |MSM|`。

| **MSM 值** | **计算** | **说明** |
| --- | --- | --- |
| `-2`（N=10） | m = 10 - |−2| = 8 | 至少命中 8 个 |
| `-4`（N=3） | m = 3 - |−4| = −1 | -1 归 0（逻辑见[正整数](#正整数)说明），系统自动按 1 个可选单元处理 |

```shell
"minimum_should_match": -2
```

###### 正百分数

表示至少命中多少比例的可选单元，按 N 的百分比向零取整，计算公式为 `m = floor(N × MSM / 100)`。

| **MSM 值** | **计算（N=10）** | **说明** |
| --- | --- | --- |
| `"75%"`（小于 100%） | m = floor(10 × 75 / 100) = 7 | 至少命中 7 个 |
| `"100%"`（等于 100%） | m = floor(10 × 100 / 100) = 10 | 全部命中 |
| `"150%"`（大于 100%） | m = floor(10 × 150 / 100) = 15，超过 N 时，系统自动按 N 处理，即 m = 10 | 等价于全部命中，不会报错 |

```shell
"minimum_should_match": "75%"
```

###### 负百分数

表示允许缺失多少比例的可选单元，按 N 的百分比向零取整（如 `trunc(-1.5) = -1`）。本节计算公式中 `MSM` 表示百分数中的带符号数值（如 `"-25%"` 中 `MSM = −25`），计算公式为 `m = N + trunc(N × MSM / 100)`。

| **MSM 值** | **计算（N=10）** | **说明** |
| --- | --- | --- |
| `"-25%"`（数值大于 −100%，即绝对值小于 100%） | m = 10 + trunc(10 × (−25) / 100) = 10 + trunc(−2.5) = 10 + (−2) = 8 | 至少命中 8 个 |
| `≤ −100%`（如 `"-150%"`） | m = 10 + trunc(10 × (−150) / 100) = 10 + (−15) = −5 | 中间值 ≤ 0，系统自动按 1 个可选单元处理，不会报错 |

```shell
"minimum_should_match": "-25%"
```

##### 运算组合逻辑

MSM 还可以写成带运算符的字符串：格式为 `条件阈值<MSM 取值`。例如 `"3<90%"` 表示：当可选单元总数 N 大于条件阈值 3 时，按 `90%` 计算 MSM；对于 N 小于等于 3 的场景，固定按 `100%`（全部命中）计算。多段时用空格连接，系统从左到右依次检查，条件阈值区间**左开右闭（最左侧为闭区间）**，具体见下文示例。

:::tab
tab 单段示例

| **MSM 值** | **计算（N=10）** | **说明** |
| --- | --- | --- |
| `"3<90%"` | N = 10 落在 (3, +∞)，按 `90%` 计算 | m = 10 × 0.9 = 9 |
| `"15<90%"` | N = 10 落在 `[0, 15]`，按 `100%` 计算 | m = 10 |

tab 多段示例

```shell
"minimum_should_match": "2<60%, 5<70%, 9<80%"
```

字符串显式写出三段百分数，系统还会补上一段隐含的默认规则（N 不超过首个阈值时按 100% 处理）。完整区间如下（左开右闭；最左侧为闭区间）：

* 可选单元数在 [0, 2] 区间，应用 100% 阈值。
* 可选单元数在 (2, 5] 区间，应用 60% 阈值。
* 可选单元数在 (5, 9] 区间，应用 70% 阈值。
* 可选单元数在 (9, +∞) 区间，应用 80% 阈值。

因此对于不同 N 值，计算结果如下：

| **N 值** | **扫描过程** | **结果** |
| --- | --- | --- |
| N ≤ 2 | 首段可选单元数阈值为 2，N ≤ 2，直接停止 | m = N × 100 / 100 = N |
| 2 < N ≤ 5（如 N=5） | 5 在 (2, 5] 区间，按 `60%` 计算：m = 5 × 60 / 100 = 3；下一段可选单元数区间为 (5, 9]，5 不属于该区间，停止 | m = 3 |
| 5 < N ≤ 9（如 N=9） | 9 在 (5, 9] 区间，按 `70%` 计算：m = trunc(9 × 70 / 100) = 6；下一段可选单元数区间为 (9, +∞)，9 不属于该区间，停止 | m = 6 |
| N > 9（如 N=10） | 10 在 (9, +∞) 区间，按 `80%` 计算：m = 10 × 80 / 100 = 8 | m = 8 |
:::

##### 嵌套与分层

在掌握前述规则的基础上，须明确：`minimum_should_match` 仅作用于其所在的查询层级；各层级约束相互独立，嵌套查询时逐层分别计算，不互相覆盖。

| **放置位置** | **约束对象（N）** |
| --- | --- |
| `match` / `multi_match` 内部 | 该查询分词后的词元数 |
| `query_string` 内部 | boost 分段后的组数（规则见上文[权重运算符说明](#权重运算符说明)） |
| `bool` 与 `should` 同级 | `should` 子句条数 |

例如外层 `bool` 设 MSM = 2（3 条 `should` 至少中 2 条），其中某条 `should` 里的 `match` 再设 MSM = 2（该 `match` 的 3 个词至少中 2 个），则两层条件需同时满足，示例见“最小匹配数示例”小节。

#### 嵌套查询

本小节补充说明嵌套查询中的路径命名、与 DDL 的差异，以及 `must_not` 语义。

路径命名与 DDL 的差异如下：

| **上下文** | **格式** | **示例** |
| --- | --- | --- |
| DDL `NESTED_PATHS` | `$.路径`，不含列名 | `$.comments` |
| dsl_string `nested.path` | `列名.路径`，不含 `$` | `j1.comments` |
| dsl_string 内层查询的字段路径 | `列名.完整路径` | `j1.comments.author` |

嵌套查询可出现在顶层 `query`，也可出现在 `bool` 的任意子句中。内层 `bool` 的多个条件必须命中同一个数组元素；多层嵌套查询时，查深层字段须继续嵌套 `nested` 子句。DDL 侧路径匹配规则（数组与对象如何对应声明路径）详见 [CREATE INDEX](../2200.create-index-of-mysql-mode.md) 中的“NESTED_PATHS 路径匹配说明”章节。

`must_not` 相对 `nested` 的位置决定否定域：

```shell
父文档（表的一行 / 整份 JSON）
  └── comments[]          ← nested 作用的子元素
        ├── {author: alice}
        └── {author: bob}
```

* 父域否定：外层 `bool.must_not` 直接包裹 `nested`，如：

```shell
# 表示评论里不能出现任何 alice
{
  "bool": {
    "must_not": [{"nested": {"path": "comments", "query": {"bool": {"must": [{"term": {"comments.author": "alice"}}]}}}}]
  }
}
```

父文档会命中，当且仅当没有任何嵌套元素满足否定条件。也就是说，只要有一个嵌套元素满足条件，该文档就不命中；若嵌套数组为空，或文档中缺少该路径字段，同样会命中。

* 子域否定：`must_not` 位于 `nested.query.bool` 下，如：

```shell
# 评论里至少有一条不是 alice
{
  "nested": {
    "path": "comments",
    "query": {"bool": {"must_not": [{"term": {"comments.author": "alice"}}]}}
  }
}
```

父文档会命中，当且仅当至少存在一个嵌套元素不满足被否定的条件。也就是说，只要有一个嵌套元素不符合该否定条件（例如作者不是 alice），该文档就命中；若所有嵌套元素都满足被否定条件，则不命中；若嵌套数组为空，或文档中缺少该路径字段，同样会命中。

#### 聚合伪列

`HYBRID_SEARCH` 在 `SELECT` 列表中提供下列伪列。伪列仅在混搜语法中有效，不属于 MySQL 通用 `SELECT` 表达式。

| **伪列名** | **含义** | **可用场景** |
| --- | --- | --- |
| `__score` | 各路搜索结果融合后的最终评分 | 返回行的混搜查询中均可引用 |
| `agg_name` | 聚合桶计数值（名称与 `aggs` 中自定义的桶键名一致） | 仅在 `dsl_string` 中声明了同名 `aggs` 时可用 |

对 `terms` 聚合，伪列 `agg_name` 返回该分组键对应的文档数（等价于 `COUNT(*)`）；对 `cardinality` 聚合，伪列 `agg_name` 返回该字段的去重计数（等价于 `COUNT(DISTINCT field)`）。也可在 `SELECT` 中写 `COUNT(DISTINCT field)`，但 `field` 必须与 `cardinality.field` 一致。

#### 计数查询（`count(*)`）

`SELECT count(*)` 用于统计各路搜索结果的并集文档总数；单路搜索返回该路径索引命中数，多路搜索对行键并集去重后计数。计数在索引层完成，不算分、不回主表。

`size`、`from`、`sort`、`aggs`、`collapse` 不影响计数结果；`min_score` 会影响。当同时指定 `rank` 且 `min_score > 0` 时，仅融合窗口内且分数达标的文档参与计数。

下列示例设置 `"size": 1`，但 `count(*)` 仍返回全文命中的真实总数，而非 1：

```sql
SELECT count(*)
FROM HYBRID_SEARCH(
  TABLE doc_table,
  '{
    "query": {
      "match": {"content": "oceanbase"}
    },
    "size": 1
  }'
);
```

### 模糊匹配示例（`wildcard`）

本示例展示了 `wildcard` 标量查询的常用场景，包括普通列前缀匹配、JSON 路径匹配、作为 `knn.filter` 中的过滤条件、`bool.must` / `bool.should` 组合过滤。示例表 `doc_table`、`doc_json_array` 的建表与数据请参见 [混合搜索](#相关文档)。

```sql
-- 普通列前缀匹配（doc_table.content）
SELECT c1, content FROM HYBRID_SEARCH(TABLE doc_table, '{
  "query": {"wildcard": {"content": "oceanbase*"}}
}');

-- JSON 路径（doc_json_array.doc_json.name）
SELECT id, title FROM HYBRID_SEARCH(TABLE doc_json_array, '{
  "query": {"wildcard": {"doc_json.name": "doc*"}}
}');

-- 作为 knn.filter（doc_table）
SELECT c1 FROM HYBRID_SEARCH(TABLE doc_table, '{
  "knn": {
    "field": "vector",
    "k": 3,
    "query_vector": "[1,2,3]",
    "filter": [{"wildcard": {"content": "oceanbase*"}}]
  }
}');

-- bool.must / should 组合（doc_table）
SELECT c1, query, content FROM HYBRID_SEARCH(TABLE doc_table, '{
  "query": {
    "bool": {
      "must": [
        {"term": {"c1": 2}},
        {"bool": {
          "should": [
            {"wildcard": {"query": "*world*"}},
            {"wildcard": {"content": "*mysql*"}}
          ],
          "minimum_should_match": 1
        }}
      ]
    }
  }
}');
```

### 最小匹配数示例（`minimum_should_match`）

以下示例对应上文 [minimum_should_match](#minimum_should_match) 各小节。示例表 `doc_table` 的建表与数据请参见文末相关文档 [混合搜索](#相关文档)。

```sql
-- 正百分数（match）：N=10，"75%" → m=floor(10×75/100)=7
SELECT c1, content FROM HYBRID_SEARCH(TABLE doc_table, '{
  "query": {
    "match": {
      "content": {
        "query": "oceanbase mysql oracle postgres redis mongodb tidb starrocks elasticsearch database",
        "operator": "OR",
        "minimum_should_match": "75%"
      }
    }
  }
}');

-- 运算组合（match）：N=10，"2<60%, 5<70%, 9<80%" → N>9 按 80% → m=8
SELECT c1, content FROM HYBRID_SEARCH(TABLE doc_table, '{
  "query": {
    "match": {
      "content": {
        "query": "oceanbase mysql oracle postgres redis mongodb tidb starrocks elasticsearch database",
        "operator": "OR",
        "minimum_should_match": "2<60%, 5<70%, 9<80%"
      }
    }
  }
}');

-- bool.should：N=3（3 条 should），MSM=2 → 至少 2 条成立
SELECT c1, content FROM HYBRID_SEARCH(TABLE doc_table, '{
  "query": {
    "bool": {
      "should": [
        {"match": {"content": "oceanbase"}},
        {"match": {"content": "mysql"}},
        {"match": {"content": "database"}}
      ],
      "minimum_should_match": 2
    }
  }
}');

-- 嵌套：外层 bool（N=3，MSM=2）与内层 match（3 词元，MSM=2）各算各的，需同时满足
SELECT c1, content FROM HYBRID_SEARCH(TABLE doc_table, '{
  "query": {
    "bool": {
      "should": [
        {
          "match": {
            "content": {
              "query": "oceanbase mysql database",
              "operator": "OR",
              "minimum_should_match": 2
            }
          }
        },
        {"match": {"content": "vector"}},
        {"match": {"content": "search"}}
      ],
      "minimum_should_match": 2
    }
  }
}');

-- query_string：query 按 ^ 分为 10 组（N=10），"3<90%" → m=floor(10×90/100)=9
SELECT c1, content FROM HYBRID_SEARCH(TABLE doc_table, '{
  "query": {
    "query_string": {
      "fields": ["content"],
      "query": "oceanbase^1 mysql^1 oracle^1 postgres^1 redis^1 mongodb^1 tidb^1 starrocks^1 elasticsearch^1 database^1",
      "minimum_should_match": "3<90%"
    }
  }
}');
```

### 嵌套查询示例

示例表 `search_idx_nested` 的 DDL 与测试数据如下（后续嵌套查询示例均基于此表；多层嵌套示例依赖 `$.comments.replies` 声明）：

:::collapse
```sql
CREATE TABLE search_idx_nested (
  k INT,
  j1 JSON,
  SEARCH INDEX idx_nested (
    j1 WITH (
      NESTED_PATHS = ('$.comments', '$.comments.replies')
    )
  )
) ORGANIZATION = HEAP;

INSERT INTO search_idx_nested VALUES
-- k=1：alice 评 4 分、bob 评 5 分（不同 comment）；alice 下无 bob 的 reply
(1, '{"title":"doc1","comments":[{"author":"alice","rating":4,"replies":[]},{"author":"bob","rating":5,"replies":[{"author":"bob","text":"good"}]}]}'),
-- k=2：同一条 comment 上 alice 评 5 分，且 replies 中有 bob
(2, '{"title":"doc2","comments":[{"author":"alice","rating":5,"replies":[{"author":"bob","text":"good"},{"author":"carol","text":"well"}]},{"author":"bob","rating":4,"replies":[]}]}'),
-- k=3：无 alice
(3, '{"title":"doc3","comments":[{"author":"bob","rating":4},{"author":"carol","rating":3}]}'),
-- k=4：评论全是 alice
(4, '{"title":"doc4","comments":[{"author":"alice","rating":5}]}'),
-- k=5：comments 为空
(5, '{"title":"doc5","comments":[]}');
```
:::

查找评论作者为 `alice` 且评分大于等于 `5` 的同一条 comment：

```sql
SELECT k, j1 FROM HYBRID_SEARCH(
  TABLE search_idx_nested,
  '{
    "query": {
      "nested": {
        "path": "j1.comments",
        "query": {
          "bool": {
            "must": [
              {"term": {"j1.comments.author": "alice"}},
              {"range": {"j1.comments.rating": {"gte": 5}}}
            ]
          }
        }
      }
    }
  }'
);
```

预期返回 `k=2`、`k=4`。`k=1` 中 alice 与评分 `5` 不在同一条 comment 上，故不命中。

### 多层嵌套查询示例

如果建索引时声明了多层嵌套路径（如 `NESTED_PATHS = ('$.comments', '$.comments.replies')`），查询更深层字段须继续嵌套 `nested` 子句。例如查找 `author=alice` 的 comment，且该 comment 的 replies 中存在 `author=bob`：

```sql
SELECT k, j1 FROM HYBRID_SEARCH(
  TABLE search_idx_nested,
  '{
    "query": {
      "nested": {
        "path": "j1.comments",
        "query": {
          "bool": {
            "must": [
              {"term": {"j1.comments.author": "alice"}},
              {
                -- 继续嵌套 nested 子句
                "nested": {
                  "path": "j1.comments.replies",
                  "query": {
                    "term": {"j1.comments.replies.author": "bob"}
                  }
                }
              }
            ]
          }
        }
      }
    }
  }'
);
```

外层与内层条件须作用于同一条 comment。预期仅返回 `k=2`。

### 嵌套查询 must_not 示例

1. 父域否定

    ```sql
    SELECT k, j1 FROM HYBRID_SEARCH(
      TABLE search_idx_nested,
      '{
        "query": {
          "bool": {
            "must_not": [{
              "nested": {
                "path": "j1.comments",
                "query": {
                  "term": {"j1.comments.author": "alice"}
                }
              }
            }]
          }
        }
      }'
    );
    ```

    预期返回 `k=3`、`k=5`（无 alice 或空数组）。含 alice 的 `k=1`、`k=2`、`k=4` 不命中。

2. 子域否定

    ```sql
    SELECT k, j1 FROM HYBRID_SEARCH(
      TABLE search_idx_nested,
      '{
        "query": {
          "nested": {
            "path": "j1.comments",

              "bool": {
                "must_not": [
                  {"term": {"j1.comments.author": "alice"}}
                ]
              }
            }
          }
        }
      }'
    );
    ```

    预期返回 `k=1`、`k=2`、`k=3`、`k=5`。仅 `k=4`（评论全是 alice）不命中。
