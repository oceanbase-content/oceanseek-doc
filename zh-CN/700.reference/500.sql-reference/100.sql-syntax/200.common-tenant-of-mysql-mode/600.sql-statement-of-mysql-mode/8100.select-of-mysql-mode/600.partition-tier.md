# PARTITION TIER

`PARTITION TIER` 子句用于在 `SELECT` 语句的本地基表引用上，按照叶子分区 Tablet 当前的冷热缓存策略（Storage Cache Policy）状态选择查询范围，实现按冷热域裁剪查询分区，支持只查询热数据、冷数据、非冷数据或非热数据。

共享存储模式下，OceanSeek 支持通过 Storage Cache Policy 管理表或分区数据的冷热状态，实际状态以叶子分区 Tablet 为粒度维护。此前业务如果希望只查询冷数据或热数据，需要梳理并改造 SQL，增加 `WHERE` 过滤条件或显式指定 `PARTITION(...)` 分区列表，成本较高；使用 `PARTITION TIER` 子句后，无需改造 SQL 即可直接按 Tablet 的冷热状态裁剪查询范围。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>OceanSeek 从 V4.6.3 版本开始支持 <code>PARTITION TIER</code> 子句。该子句为 OceanSeek 的扩展语法。</p>
</main>

## 语法

```sql
SELECT select_expr [, select_expr] ...
FROM table_name
     PARTITION [(partition_name [, partition_name] ...)]
     TIER ({HOT | COLD | NOT_COLD | NOT_HOT});

-- PARTITION(...) 与 TIER(...) 同时使用时，先按 PARTITION(...) 展开候选分区，再按 TIER(...) 过滤
```

## 参数说明

| **参数** | **说明** |
| --- | --- |
| table_name | 目标表名，可为分区表或非分区表。 |
| partition_name | 分区名，为可选参数。指定后，先按现有 `PARTITION(...)` 语义展开显式候选分区，再按 `TIER` 指定的冷热属性过滤。一级分区和二级分区名称可以出现在同一个候选分区列表中。 |
| tier_value | 为 `TIER` 子句指定冷热属性过滤条件，为必选参数。取值为 `HOT`、`COLD`、`NOT_COLD` 或 `NOT_HOT`，具体含义见下方取值说明。 |

`TIER` 子句支持以下取值：

* `HOT`：只访问当前属性为 `HOT` 的叶子分区。
* `COLD`：只访问当前属性为 `COLD` 的叶子分区。
* `NOT_COLD`：只访问当前属性不为 `COLD` 的叶子分区，包含 `HOT`、`AUTO`。
* `NOT_HOT`：只访问当前属性不为 `HOT` 的叶子分区，包含 `COLD`、`AUTO`。

## 功能说明

本节介绍 `PARTITION TIER` 子句在候选分区范围、生效时点与一致性、空选择语义及索引行为方面的详细规则。

### 候选分区范围

* `PARTITION TIER(xxx)`：候选范围为表 Schema 中全部正常叶子分区。
* `PARTITION(p0, p1) TIER(xxx)`：先按现有 `PARTITION(...)` 语义展开显式候选，再按 tier 过滤。
* 非分区表：将表的唯一 Tablet 作为候选；匹配时访问整表，不匹配时返回空结果。
* 一级分区表：按每个一级分区对应的 Tablet 判断。
* 二级分区表：按最终叶子 subpartition Tablet 判断，不以一级父分区状态代替叶子状态。
* 隐藏分区（hidden partition）不进入候选范围。

### 生效时点与一致性

冷热状态在 Resolver 生成计划时读取，并展开为固定的分区列表。本次计划生成完成后，执行阶段不再重新读取冷热状态。

带 `TIER` 子句的物理计划不写入 Plan Cache。相同 SQL 再次执行时会重新生成计划并读取最新状态；`Server-side PREPARE/EXECUTE` 也遵守相同规则。

### 空选择语义

如果没有 Tablet 匹配指定的 `TIER` 取值，当前表引用（table reference）将被视为空关系，而不是退化为“没有显式分区限制”的语义。

### 索引行为

Resolver 只对用户引用的主表 Schema 枚举叶子 Tablet，不单独读取索引表的冷热状态。展开后的分区列表复用普通显式分区选择（Partition Selection）的行为。

## 使用限制及注意事项

* `PARTITION TIER` 子句仅支持在 `SELECT` 语句的本地基表引用上使用。
* 该语法新增 `TIER`、`HOT`、`COLD`、`NOT_COLD`、`NOT_HOT` 五个非保留关键字，在普通标识符位置仍可作为表名、列名或别名（alias）使用。

## 示例

本节给出 `PARTITION TIER` 子句的常见使用示例。

### 查询所有热分区

```sql
SELECT *
FROM t PARTITION TIER(HOT);
```

查询表 `t` 中所有当前属性为 `HOT` 的叶子分区。

### 在指定一级分区中查询冷分区

```sql
SELECT *
FROM t PARTITION(p0, p1) TIER(COLD);
```

先按 `PARTITION(p0, p1)` 展开候选分区，再从中筛选当前属性为 `COLD` 的叶子分区。

### 指定二级分区查询非冷分区

```sql
SELECT *
FROM t PARTITION(sp00, sp01) TIER(NOT_COLD);
```

在指定的二级分区（subpartition）中查询当前属性不为 `COLD` 的叶子分区。

### 同时指定一级分区和二级分区

```sql
SELECT *
FROM t PARTITION(p0, sp11) TIER(HOT);
```

一级分区和二级分区名称可以出现在同一个候选分区列表中。

### 与表别名和 Index Hint 组合使用

```sql
SELECT a.*
FROM t PARTITION(p0, sp11) TIER(HOT) AS a
USE INDEX(idx_t);
```

`PARTITION TIER` 子句可以与表别名（`AS a`）和 Index Hint（`USE INDEX`）组合使用。

### 同一个表使用不同的 tier

```sql
SELECT h.id, h.payload, c.payload
FROM t PARTITION TIER(NOT_HOT) AS h
JOIN t PARTITION TIER(COLD) AS c
  ON h.id = c.id;
```

自连接场景下，同一个表的不同表引用可以使用不同的 tier，分别按各自的冷热属性裁剪查询范围。
