# DROP POLICY

## 描述

该语句用于删除指定对象上的行级权限（Row-Level Security，RLS）策略。

## 权限要求

执行 `DROP POLICY` 语句，需要当前用户对目标表拥有对象级 `ALTER` 权限。库级或全局 `ALTER` 若已覆盖该表，同样满足要求。更多说明请参见 [权限分类](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)。

## 使用限制及注意事项

* 删除策略后立即生效。
* 删除策略是永久移除配置。如只需临时禁用表级 RLS，可执行 `ALTER TABLE ... DISABLE ROW LEVEL SECURITY` 而不是 `DROP POLICY`。
* 删除表、普通视图或物化视图时，其关联策略会被级联删除。

## 语法

```sql
DROP POLICY [IF EXISTS] policy_name ON [schema_name.]table_name;
```

## 参数说明

| **参数** | **说明** |
| --- | --- |
| IF EXISTS | 策略不存在时不报错。 |
| policy_name | 待删除的策略名。 |
| table_name | 策略所属对象名。可使用 `database_name.table_name` 显式指定数据库。 |

说明及限制如下：

* 策略名与目标表的匹配规则与 [CREATE POLICY](2320.create-policy-of-mysql-mode.md) 相同（同一表内策略名唯一；可使用 `database_name.table_name` 指定对象）。

## 示例

以下示例仅供参考，实际使用时请根据实际情况进行调整：

```sql
-- 删除策略（不存在时不报错）
DROP POLICY IF EXISTS emp_dept_policy ON hr.employees;

-- 删除 manager 相关写入策略
DROP POLICY IF EXISTS mgr_write_policy ON hr.employees;
```
