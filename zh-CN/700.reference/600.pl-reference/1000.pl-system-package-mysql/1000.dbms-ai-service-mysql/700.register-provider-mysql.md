# REGISTER_PROVIDER

`REGISTER_PROVIDER` 过程用于在租户内创建 AI 服务厂商配置，用于管理厂商连接信息与访问凭证。配置完成后，可通过 `provider/model` 格式调用 AI 函数。支持配置内置厂商和自定义厂商。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>本过程从 V4.6.2.1 开始支持。</p>
</main>

## 语法

```sql
PROCEDURE register_provider(
    IN provider_name VARCHAR(256),
    IN json_params JSON);
```

## 参数说明

| 参数名 | 描述 | 类型 | 取值范围 | 是否可为 NULL |
|--------|------|------|----------|----------|
| provider_name | 厂商名称。 | VARCHAR(256) | 最大 256 字节 | NO |
| json_params | 厂商配置，必须为 JSON 对象。 | JSON | 见下表 | NO |

`json_params` 支持的字段如下：

| 字段 | 类型 | 是否必填 | 说明 |
|------|------|----------|------|
| `protocol` | VARCHAR(256) | 否 | 通信协议。自定义厂商默认 `openai`，也可设为 `vllm` 等；内置厂商首次注册可省略，系统自动填充内置默认值。 |
| `base_url` | VARCHAR(2048) | 是（自定义厂商首次创建时必填） | 模型服务 Base URL。内置厂商可省略，系统自动填充。 |
| `access_key` | VARCHAR(2048) | 是 | 访问凭证，写入时加密存储。 |

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>若同名厂商已存在，请改用 <code>ALTER_PROVIDER</code> 更新配置。</p>
</main>

## 内置厂商

当前版本内置以下厂商的 `protocol`/`base_url` 默认值。内置默认值仅作为预置配置，不会直接写入系统表；执行 `REGISTER_PROVIDER` 时，若厂商为内置类型且未填写 `protocol` 或 `base_url`，系统会自动补全：

| **provider** | **protocol** | **base_url** |
|--------------|--------------|--------------|
| `aliyun` | `openai` | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `aliyun-dashscope` | `dashscope` | `https://dashscope.aliyuncs.com/api/v1` |
| `deepseek` | `openai` | `https://api.deepseek.com` |
| `siliconflow` | `openai` | `https://api.siliconflow.cn/v1` |
| `openai` | `openai` | `https://api.openai.com/v1` |
| `cohere` | `cohere` | `https://api.cohere.com/v2` |
| `tencent` | `openai` | `https://api.hunyuan.cloud.tencent.com/v1` |

## 示例

注册内置厂商，仅需填写 `access_key`：

```sql
CALL DBMS_AI_SERVICE.REGISTER_PROVIDER('aliyun', '{
  "access_key": "sk-xxxx"
}');
```

注册自定义厂商：

```sql
CALL DBMS_AI_SERVICE.REGISTER_PROVIDER('ob-mass', '{
  "protocol": "openai",
  "base_url": "https://example.com/v1",
  "access_key": "sk-xxxx"
}');
```

注册 vLLM 服务（`protocol` 设为 `vllm`，`base_url` 填写 `/v1` 地址；当前仅支持嵌入，不支持文本生成与重排序）：

```sql
CALL DBMS_AI_SERVICE.REGISTER_PROVIDER('vllm', '{
  "protocol": "vllm",
  "base_url": "https://vllm.example.com/v1",
  "access_key": "sk-xxxx"
}');
```
