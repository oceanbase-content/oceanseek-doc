# OBKV-Table 部署简介

本文档介绍了 OBKV-Table 集群的连接模式和部署方式。

## OBKV 连接模式

OBKV-Table 集群可以选择直连和通过 ODP 代理连接两种连接模式：直连模式和 ODP 模式。在不同的连接模式下，需要部署的组件不同。

### 直连模式

直连模式即 OBKV 客户端直接连接 OceanBase AI 数据库集群，OBKV 客户端提供了路由能力，能够将数据请求发到正确的 OBServer 节点，最后将执行结果返回给用户。

在直连模式下，需要依赖 OceanBase Config Server 提供 OceanBase AI 数据库的元数据注册，存储和查询服务。

当 OBServer 集群的 RegionServer List 发生变更的时候，会推送到 Config Server。OBKV-Table 可以实时的从 Config Server 中获取 RegionServer List 的地址。正常情况 OBKV-Table 可以自己感知 RegionServer List 的变更，只有在客户端初始化以及 RegionServer List 同时下线的场景需要访问 Config Server。

![direct](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/kv/V4.2.4/table%E7%9B%B4%E8%BF%9E%E6%A8%A1%E5%BC%8F%EF%BC%88%E7%BC%A9%E5%B0%8F%E7%89%88%EF%BC%89.png)

### ODP 模式

OceanBase Database Proxy（简称 ODP ）是一个代理服务器。OceanBase AI 数据库的用户数据以多副本的形式存放在各个节点上，ODP 接收 OBKV 客户端发出的 RPC 请求，并将 RPC 请求转发至最佳目标节点，最后将执行结果返回给用户。

![odp](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/kv/V4.2.4/table%E5%AE%A2%E6%88%B7%E7%AB%AF%E9%85%8D%E7%BD%AE.png)

### 连接模式选择

直连模式相较于 ODP 模式在数据链路上少了一次跳转，时延会更低一些。直连模式需要暴露 OBServer 节点的 RPC 端口供客户端访问，会增加一些端口管控的复杂性。
ODP 模式下，ODP 可以屏蔽了 OBServer 节点本身分布式的复杂性，提供了连接管理、负载均衡、无限水平扩展等能力，通过 ODP 可以让用户更方便的运维 OceanBase AI 数据库集群。

一般地，私有化部署可以选择直连模式，云上部署可以 ODP 模式：

* 在公有云中，业务集群和数据库集群存在网络隔离，需要依赖 ODP 来路由消息。在私有云中, 如果业务不希望和数据库耦合（比如希望迁移数据库的时候， 业务不感知），也可以使用ODP模式。
* 在私有化部署的部分场景，业务和数据库机房之间存在网络隔离，在这种场景也可以考虑部署 ODP。通过 IP 映射以及负载均衡组件，将业务请求发送到 ODP，ODP 统一转发业务请求到数据库。

## OBKV 集群部署

OBKV 集群部署根据不同的连接模式，需要额外部署的组件也不相同：

* 直连模式需要额外部署 OceanBase Config Server。
* ODP 模式需要额外部署 ODP。因此，在部署过程中需要特别关注勾选部署对应的组件。
