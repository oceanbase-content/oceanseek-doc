# OBKV-Table Java 客户端参数设置

OBKV-Table Java 客户端提供了丰富的 API 接口访问 OceanBase AI 数据库，本文介绍如何设置并使用 OBKV-Table Java 客户端连接集群的参数。

## 参数说明

总览如下：

| **分类** | **配置项**    | **默认值**  | **描述**   |
|----------|---------------|-------------|------------|
| 超时和重试    | RUNTIME_MAX_WAIT                               | 5000ms     | 单次执行超时时间会在超时时间内重试             |
| 超时和重试    | RPC_EXECUTE_TIMEOUT                            | 3000ms     | 执行 RPC 请求的 socket 超时时间             |
| 超时和重试    | RPC_OPERATION_TIMEOUT                          | 2000ms    | OceanBase AI 数据库内部执行 RPC 请求的超时时间        |
| 超时和重试    | RUNTIME.RETRY.TIMES                            | 3        | 运行过程中遇到可重试错误时的重试次数            |
| 超时和重试    | RUNTIME.RETRY.INTERVAL                         | 100ms     | 运行出错时重试的时间间隔                      |
| 连接         | SERVER.CONNECTION.POOL.SIZE                    | 10        | 单个 SERVER 的最大连接数     

### 超时和重试相关参数

执行相关参数是需要关注的最基础参数，尤其需要考虑 `RUNTIME_MAX_WAIT`、`RPC_EXECUTE_TIMEOUT`、`RPC_OPERATION_TIMEOUT` 三个参数。

设置原则：`RUNTIME_MAX_WAIT` ＞ `RPC_EXECUTE_TIMEOUT` > `RPC_OPERATION_TIMEOUT`

具体如下：

| **配置项**    | **默认值**  | **描述**   | **最佳实践** |
|---------------|-------------|------------|------------|
| RUNTIME_MAX_WAIT                               | 5000ms     | 业务 APP 对 OBKV-Table 客户端 的一次接口调用最大的超时时间。在此窗口时间内，会进行失败重试。 | 推荐使用默认值，下列场景可以设置大一些:<ul><li>服务端处理比较慢。</li><li>网络时延比较大。</li></ul>  |
| RPC_EXECUTE_TIMEOUT                            | 3000ms    | 客户端发出 RPC 请求后，等待的最长时间。 | 推荐使用默认值，下列场景可以设置大一些：<ul><li>服务端处理比较慢。</li><li>网络时延比较大。</li><li>建议 `RPC_EXECUTE_TIMEOUT` 是 `RPC_OPERATION_TIMEOUT` 的 1.5 倍。</li></ul>|
| RPC_OPERATION_TIMEOUT                          | 2000ms    | 请求在服务端执行的最长时间，也代表事务的超时时间。 | 推荐使用默认值，下列场景可以设置大一些：<ul><li>单个请求的大小比较大，处理时间比较长。</li><li>服务端压力比较大，处理请求的资源不足。</li></ul>|
| RUNTIME.RETRY.TIMES                            | 3        | 执行出错的时候，OBKV-Table 客户端进行内部重试的次数。 | 推荐使用默认值，业务场景可以根据实际情况进行调整。 |
| RUNTIME.RETRY.INTERVAL                         | 100ms        | 执行出错的时候，OBKV-Table 客户端进行内部重试的间隔时间。 | 推荐设置大一些，避免因为异常，不间断重试造成消息风暴。 |

### SERVER 相关参数

| **配置项**    | **默认值**  | **描述**   | **最佳实践** |
|---------------|-------------|------------|------------|
| SERVER.CONNECTION.POOL.SIZE | 10        | 单个 SERVER 的最大连接数。 | OBKV-Table 客户端和每个 ObServer 节点都会创建一个连接串，该参数代表连接池的最大连接数量。 | <ul><li>连接是长连接，连接池创建的时候统一进行 TCP 连接。</li><li>连接可以被多个请求复用，即持有连接发完消息，就会将连接还回连接池，所以连接池中的连接无需很多。</li></ul> |

### 参数设置

#### 接口

ObTableClient 设置参数的接口如下：

| **接口** | **描述** |
|----------|----------|
| `void addProperty(String key, String value)` | 设置单个参数的值 |

#### 示例

示例通过 addProperty 接口设置了 `RPC_OPERATION_TIMEOUT` 的值为 `1000` 毫秒。

```java
## 假设当前集群如下
## 集群名：obkv
## 租户名：obkv_table
## 数据库名: obkv_table_db
## 用户名：test_user
## 用户密码：admin123
## 系统租户下用户 : test_sys_user
## 系统租户下用户密码 : sys123
## Config URL: http://127.0.0.1:8080/services?Action=ObRootServiceInfo&ObCluster=obkv

String paramURL = "http://127.0.0.1:8080/services?Action=ObRootServiceInfo&ObCluster=obkv&database=obkv_table_db";
ObTableClient obkvHandle = new ObTableClient();
obkvHandle.setParamURL(paramURL);
obkvHandle.setFullUserName("test_user@obkv_table#obkv");
obkvHandle.setPassword("admin123");
obkvHandle.setSysUserName("test_sys_user");
obkvHandle.setSysPassword("sys123");
obkvHandle.addProperty(Property.RPC_OPERATION_TIMEOUT.getKey(), "1000");
obkvHandle.init();
```
