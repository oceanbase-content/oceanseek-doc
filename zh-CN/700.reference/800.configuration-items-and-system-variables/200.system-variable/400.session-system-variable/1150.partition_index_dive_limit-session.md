# partition_index_dive_limit

## 功能描述

`partition_index_dive_limit` 用于指示优化器使用存储层估行时的分区数量限制。

## 权限要求

* 查询变量

  `sys` 租户和所有用户租户均可以使用 `SHOW VARIABLES` 语句或视图 `information_schema.SESSION_VARIABLES` 查看 Session 系统变量的值。

* 修改变量

  `sys` 租户和所有用户租户均可以直接修改本租户的 Session 系统变量的值。

## 属性说明

| **属性**  |    **描述**  |
|-----------|---------------|
| 参数类型    |   Int         |
| 默认值      |  10           |
| 取值范围    |  [0, INT64_MAX]<main id="notice" type='explain'><h4>说明</h4><p><code>0</code> 表示不设限。<code>INT64_MAX</code> 代表的是 64 位有符号整数类型的最大值。该变量允许设置为负数：当本变量与 <code>range_index_dive_limit</code> 同为负数时，存储层估行策略回退到旧版本行为，详见使用说明；其余情况下负数含义与 <code>0</code> 相同。</p></main>   |
| 生效范围    |  Session      |
| 是否可修改  |  是，支持通过 `SET` 语句修改。 |

## 使用说明

修改该变量以控制优化器存储层估行时的分区数量限制：

* 当分区个数小于该变量时，总是选择所有分区做存储层估行。

* 当分区个数大于等于该变量时，随机选择 `partition_index_dive_limit` 个分区进行存储层估行，并将估行结果等比例放大。

* 当该变量为 `0` 时，总是选择所有分区做存储层估行。

* 当 `range_index_dive_limit` 与 `partition_index_dive_limit` 同为负数时，存储层估行策略回退到旧版本行为，仅对单分区 10 个 range 以内做存储层估行，超过时不进行采样。

* 如果需要关闭存储层估行，可以使用系统变量 `enable_storage_cardinality_estimation` 控制。

与 MySQL 的差异如下：

* MySQL 仅通过系统变量 `eq_range_index_dive_limit` 控制等值 range 数量，对分区数量没有限制；OceanSeek 通过本变量对存储层估行的分区数量进行限制。

## 配置示例

在当前 Session 中设置存储层估行的分区数量限制为 1，即随机选择 1 个分区进行存储层估行。

```shell
obclient [test]> SET partition_index_dive_limit = 1;
Query OK, 0 rows affected (0.002 sec)
```

通过执行计划观察估行结果的完整示例，参见 [partition_index_dive_limit](../300.global-system-variable/10650.partition_index_dive_limit-global.md)。
