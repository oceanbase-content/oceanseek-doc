# partition_index_dive_limit

## 功能描述

`partition_index_dive_limit` 用于指示优化器使用存储层估行时的分区数量限制。

## 权限要求

* 查询变量

  * Global 级别

    `sys` 租户和所有用户租户均可以使用 `SHOW VARIABLES` 语句或视图 `information_schema.GLOBAL_VARIABLES` 查看 Global 系统变量的值。

  * Session 级别

    `sys` 租户和所有用户租户均可以使用 `SHOW VARIABLES` 语句或视图 `information_schema.SESSION_VARIABLES` 查看 Session 系统变量的值。

* 修改变量

  * Global 生效

    * `sys` 租户可以直接修改 Global 系统变量的值。

    * 用户租户需要拥有 `SUPER` 或 `ALTER SYSTEM` 权限才能修改 Global 系统变量的值。

  * Session 生效

    `sys` 租户和所有用户租户均可以直接修改本租户的 Session 系统变量的值。

## 属性说明

| **属性**  |    **描述**  |
|-----------|---------------|
| 参数类型    |   Int         |
| 默认值      |  10           |
| 取值范围    |  [0, INT64_MAX]<main id="notice" type='explain'><h4>说明</h4><p><code>0</code> 表示不设限。<code>INT64_MAX</code> 代表的是 64 位有符号整数类型的最大值。该变量允许设置为负数：当本变量与 <code>range_index_dive_limit</code> 同为负数时，存储层估行策略回退到旧版本行为，详见使用说明；其余情况下负数含义与 <code>0</code> 相同。</p></main>   |
| 生效范围    |  <ul><li>Global</li><li>Session</li></ul>  |
| 是否可修改  |  是，支持通过 `SET` 语句修改。 |

## 使用说明

修改该变量以控制优化器存储层估行时的分区数量限制：

* 当分区个数小于该变量时，总是选择所有分区做存储层估行。

* 当分区个数大于等于该变量时，随机选择 `partition_index_dive_limit` 个分区进行存储层估行，并将估行结果等比例放大。

* 当该变量为 `0` 时，总是选择所有分区做存储层估行。

* 当 `range_index_dive_limit` 与 `partition_index_dive_limit` 同为负数时，存储层估行策略回退到旧版本行为，仅对单分区 10 个 range 以内做存储层估行，超过时不进行采样。

* 如果需要关闭存储层估行，可以使用系统变量 `enable_storage_cardinality_estimation` 控制。

与 MySQL 的差异如下：

* MySQL 仅通过系统变量 `eq_range_index_dive_limit` 控制等值 range 数量，对分区数量没有限制；OceanBase AI 数据库通过本变量对存储层估行的分区数量进行限制。

## 配置示例

1. 创建分区表 `t1` 并插入数据。

   ```shell
   obclient [test]> CREATE TABLE t1(c1 int, c2 int, index i1(c2)) PARTITION BY RANGE(c1) (PARTITION p0 VALUES LESS THAN(10), PARTITION p1 VALUES LESS THAN(20), PARTITION p2 VALUES LESS THAN(30));
   Query OK, 0 rows affected (0.457 sec)

   obclient [test]> INSERT INTO t1 SELECT 1,1 FROM table(generator(10));
   Query OK, 10 rows affected (0.130 sec)
   Records: 10  Duplicates: 0  Warnings: 0

   obclient [test]> INSERT INTO t1 SELECT 11,11 FROM table(generator(20));
   Query OK, 20 rows affected (0.008 sec)
   Records: 20  Duplicates: 0  Warnings: 0

   obclient [test]> INSERT INTO t1 SELECT 21,21 FROM table(generator(30));
   Query OK, 30 rows affected (0.009 sec)
   Records: 30  Duplicates: 0  Warnings: 0
   ```
