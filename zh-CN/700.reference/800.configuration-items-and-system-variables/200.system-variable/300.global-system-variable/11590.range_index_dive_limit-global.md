# range_index_dive_limit

## 功能描述

`range_index_dive_limit` 用于指示优化器使用存储层估行时的 range 数量限制。

## 权限要求

* 查询变量

  * Global 级别

    `sys` 租户和所有用户租户均可以使用 `SHOW VARIABLES` 语句或视图 `information_schema.GLOBAL_VARIABLES` 查看 Global 系统变量的值。

  * Session 级别

    `sys` 租户和所有用户租户均可以使用 `SHOW VARIABLES` 语句或视图 `information_schema.SESSION_VARIABLES` 查看 Session 系统变量的值。

* 修改变量

  * Global 生效

    * `sys` 租户可以直接修改 Global 系统变量的值。

    * 用户租户需要拥有 `SUPER` 或 `ALTER SYSTEM` 权限才能修改 Global 系统变量的值。

  * Session 生效

    `sys` 租户和所有用户租户均可以直接修改本租户的 Session 系统变量的值。

## 属性说明

| **属性**  |    **描述**  |
|-----------|---------------|
| 参数类型    |   Int         |
| 默认值      |  10           |
| 取值范围    |  [0, INT64_MAX]<main id="notice" type='explain'><h4>说明</h4><p><code>0</code> 表示不设限。<code>INT64_MAX</code> 代表的是 64 位有符号整数类型的最大值。该变量允许设置为负数：当本变量与 <code>partition_index_dive_limit</code> 同为负数时，存储层估行策略回退到旧版本行为，详见使用说明；其余情况下负数含义与 <code>0</code> 相同。</p></main>   |

| 是否可修改  |  是，支持通过 `SET` 语句修改。 |

## 使用说明

修改该变量以控制优化器存储层估行时的 range 数量限制：

* 当 range 个数小于该变量时，总是选择所有 range 做存储层估行。

* 当 range 个数大于等于该变量时，随机选择 `range_index_dive_limit` 个 range 进行存储层估行，并将估行结果等比例放大。

* 当该变量为 `0` 时，总是选择所有 range 做存储层估行，与 MySQL 系统变量 `eq_range_index_dive_limit` 为 `0` 时的行为相同，不做限制。

* 当 `range_index_dive_limit` 与 `partition_index_dive_limit` 同为负数时，存储层估行策略回退到旧版本行为，仅对单分区 10 个 range 以内做存储层估行，超过时不进行采样。

* 如果需要关闭存储层估行，可以使用系统变量 `enable_storage_cardinality_estimation` 控制。

与 MySQL 的差异如下：

* MySQL 通过系统变量 `eq_range_index_dive_limit` 控制 index dive 的等值 range 数量，默认值为 `200`；OceanSeek 会一并考虑等值 range 与非等值 range 的数量。

* 当 range 数量大于等于该变量的值时，MySQL 不再使用 index dive，而 OceanSeek 会随机选择上限数量的 range 进行采样存储层估行。

## 配置示例

1. 创建表 `t1` 并插入数据。

   ```shell
   obclient [test]> CREATE TABLE t1(c1 int, c2 int, index i1(c1));
   Query OK, 0 rows affected (0.433 sec)

   obclient [test]> INSERT INTO t1 SELECT 1,1 FROM table(generator(10));
   Query OK, 10 rows affected (0.026 sec)
   Records: 10  Duplicates: 0  Warnings: 0

   obclient [test]> INSERT INTO t1 SELECT 2,2 FROM table(generator(20));
   Query OK, 20 rows affected (0.002 sec)
   Records: 20  Duplicates: 0  Warnings: 0

   obclient [test]> INSERT INTO t1 SELECT 3,3 FROM table(generator(30));
   Query OK, 30 rows affected (0.002 sec)
   Records: 30  Duplicates: 0  Warnings: 0
   ```

2. 查看执行计划，默认场景下不超过 10 个 range 均采用存储层估行。

   ```shell
   obclient [test]> EXPLAIN SELECT c1 FROM t1 WHERE c1 IN (1,2,3);
   ```

   查询结果如下：

   ```shell
   +------------------------------------------------------------------------------------------+
   | Query Plan                                                                               |
   +------------------------------------------------------------------------------------------+
   | ===============================================                                          |
   | |ID|OPERATOR       |NAME  |EST.ROWS|EST.TIME(us)|                                          |
   | -----------------------------------------------                                          |
   | |0 |TABLE RANGE SCAN|t1(i1)|60      |11          |                                          |
   | ===============================================                                          |
   | Outputs & filters:                                                                       |
   | -------------------------------------                                                    |
   |   0 - output([t1.c1]), filter(nil), rowset=256                                           |
   |       access([t1.c1]), partitions(p0)                                                    |
   |       is_index_back=false, is_global_index=false,                                        |
   |       range_key([t1.c1], [t1.__pk_increment]), range(1,MIN ; 1,MAX), (2,MIN ; 2,MAX),    |
   |       (3,MIN ; 3,MAX), range_cond([t1.c1 IN (1, 2, 3)])                                  |
   +------------------------------------------------------------------------------------------+
   12 rows in set (0.049 sec)
   ```

3. 修改变量，仅选择 1 个 range 做存储层估行。

   ```shell
   obclient [test]> SET range_index_dive_limit = 1;
   Query OK, 0 rows affected (0.002 sec)
   ```

4. 再次查看执行计划，发现仅选择了一个 range 做存储层估行，估行结果为 10 * 3 = 30。

   ```shell
   obclient [test]> EXPLAIN SELECT c1 FROM t1 WHERE c1 IN (1,2,3);
   ```

   查询结果如下：

   ```shell
   +------------------------------------------------------------------------------------------+
   | Query Plan                                                                               |
   +------------------------------------------------------------------------------------------+
   | ===============================================                                          |
   | |ID|OPERATOR       |NAME  |EST.ROWS|EST.TIME(us)|                                          |

   |       (3,MIN ; 3,MAX), range_cond([t1.c1 IN (1, 2, 3)])                                  |

   12 rows in set (0.006 sec)
   ```
