# dtl_compress_func

<main id="notice" type='explain'>
<h4>说明</h4>
<p>该配置项从 V4.6.3 版本开始引入。</p>
</main>

## 功能描述

`dtl_compress_func` 用于设置 SQL 并行执行中 DTL（Data Transfer Layer，数据传输层）跨节点 RPC 消息使用的压缩算法。默认使用 `lz4_1.0`，设置为 `none` 表示不压缩。当隐藏配置项 `_px_message_compression` 为 `false` 时，本配置项的算法选择不生效。

配置传播后，修改对新初始化的 DFC（DTL 流控上下文）生效，不改变已有 DFC 及其 Channel 的压缩算法。

## 权限要求

* 查询配置项

  `sys` 租户和所有用户租户均可以使用 `SHOW PARAMETERS` 语句或视图 `GV$OB_PARAMETERS` 查询该配置项。

* 修改配置项

  `sys` 租户和用户租户都可以使用 `ALTER SYSTEM SET` 语句修改该配置项。

## 属性说明

| **属性** | **描述** |
| -------- | -------- |
| 参数类型 | String |
| 默认值 | `lz4_1.0` |
| 取值范围 | <ul><li>`none`</li><li>`lz4_1.0`</li><li>`snappy_1.0`</li><li>`zstd_1.3.8`</li><li>`zstd_1.5.7`</li></ul> 算法名称不区分大小写。 |
| 是否可修改 | 是，支持通过 `ALTER SYSTEM SET` 语句修改。 |
| 是否重启 OBServer 节点生效 | 否，设置后立即生效。 |

## 使用说明

### 取值说明

| 取值 | 含义 |
| --- | --- |
| `none` | 不执行压缩，以原始载荷发送。 |
| `lz4_1.0` | 使用现有 LZ4 实现，为默认算法。 |
| `snappy_1.0` | 使用现有 Snappy 实现。 |
| `zstd_1.3.8` | 使用现有 ZSTD 1.3.8 实现，压缩级别固定为 level 1。 |
| `zstd_1.5.7` | 使用现有 ZSTD 1.5.7 实现，压缩级别固定为 level 1。 |

### 生效规则

* 每次初始化 DFC 时，系统会读取租户的 `_px_message_compression` 和 `dtl_compress_func`，确定有效压缩算法，并传递给对应的 Channel 和广播服务。

* 当 `_px_message_compression` 为 `false` 时，后续初始化的 DFC 不启用压缩，不受 `dtl_compress_func` 所选算法的影响。

* 当 `_px_message_compression` 为 `true` 时，使用 `dtl_compress_func` 选择算法；其中 `none` 仍表示不压缩。

* 算法在 DFC 初始化时固定，不会在每个报文发送时重新读取配置。动态修改不会切换已有 DFC 及其 Channel 的算法。

* 生效边界是 DFC，而不是整条 SQL。不同节点或不同初始化时刻的 DFC 可能使用不同算法，不承诺查询级原子切换。

* 仅接受上述白名单中的取值，非法名称会被拒绝。不开放流式压缩、硬件专用压缩以及其他仅适用于存储层的算法。

### 报文处理与兼容性

* 普通发送、批量/聚合发送和广播发送均会将有效算法传递给 RPC 层；本地 Channel 不新增网络压缩流程。

* 报文头沿用现有的压缩算法 ID 和原始长度字段，接收端根据报文头选择解压算法，不依赖接收端当前的租户配置。

* 不新增压缩算法枚举 ID，不修改 DTL 序列化布局及 RPC 协议格式。

* 压缩后体积未减小时，沿用现有 RPC 逻辑，回退为原始载荷发送。

### 使用建议

* 常规场景建议保留默认值 `lz4_1.0`。

* 对于带宽受限且 CPU 有余量的租户，可以测试 ZSTD，并结合网络载荷、CPU 利用率和实际 SQL 耗时决定是否切换。

* Snappy 和不同版本的 ZSTD 用于提供可选方案，不保证在所有数据和负载下都优于默认的 LZ4。

* 需要关闭后续 DTL 压缩时，可以将该配置项设置为 `none`，或将 `_px_message_compression` 设置为 `false`；两者均不会修改已经初始化的 DFC。

* 如果总开关已经关闭，仅将 `dtl_compress_func` 改为其他算法不会重新开启压缩，需要同时将 `_px_message_compression` 设置为 `true`。

* 在 64KiB 分块的合成样本编解码测试中，ZSTD 1.5.7 相比 LZ4 的载荷在 TPC-H 和 TPC-DS 场景下分别减少约 30% 和 38%，但编解码吞吐量较低。该结果不代表完整 SQL 性能提升。

### 适用范围

本配置项仅控制 SQL 并行执行中的 DTL 跨节点 RPC 消息压缩，不控制客户端连接压缩、表存储压缩、共享存储访问或日志传输压缩，也不提供 SQL 级 Hint、会话级配置、压缩级别调整或运行时自适应算法选择。

## 配置示例

以下示例在目标用户租户中执行。修改影响配置传播后新初始化的 DFC，不切换已有 Channel。

```sql
-- 开启压缩总开关，并使用默认 LZ4 算法
ALTER SYSTEM SET _px_message_compression = true;
ALTER SYSTEM SET dtl_compress_func = 'lz4_1.0';

-- 使用 Snappy
ALTER SYSTEM SET dtl_compress_func = 'snappy_1.0';

-- 使用 ZSTD 1.5.7
ALTER SYSTEM SET dtl_compress_func = 'zstd_1.5.7';

-- 通过算法选项关闭后续 DTL 压缩
ALTER SYSTEM SET dtl_compress_func = 'none';

-- 或通过现有总开关关闭；此时算法选择不生效
ALTER SYSTEM SET _px_message_compression = false;

-- 恢复默认压缩行为：同时恢复总开关和默认算法
ALTER SYSTEM SET _px_message_compression = true;
ALTER SYSTEM SET dtl_compress_func = 'lz4_1.0';

-- 查看配置；配置值不一定等于已有 Channel 的有效算法
SHOW PARAMETERS LIKE 'dtl_compress_func';
```
