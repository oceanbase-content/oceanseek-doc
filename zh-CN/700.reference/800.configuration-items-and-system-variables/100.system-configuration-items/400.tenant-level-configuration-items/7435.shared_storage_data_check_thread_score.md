# shared_storage_data_check_thread_score

## 功能描述

`shared_storage_data_check_thread_score` 用于设置共享存储数据存在性巡检 DAG 的工作线程分值。设置为 0 表示使用内置默认线程分值，当前内置默认值为 3；设置为 1～100 表示显式指定巡检任务的调度线程分值。

## 权限要求

* 查询配置项

  `sys` 租户和所有用户租户均可以使用 `SHOW PARAMETERS` 语句或视图 `GV$OB_PARAMETERS` 查询该配置项。

* 修改配置项

  `sys` 租户和用户租户均可修改该配置项。

## 属性说明

| **属性**  |    **描述**  |
|-----------|---------------|
| 参数类型    | Int |
| 默认值      | 0，对应内置默认线程分值 3 |
| 取值范围    | [0, 100] |
| 是否可修改 | 是，支持通过 `ALTER SYSTEM SET` 语句修改。|
| 是否重启 OBServer 节点生效 | 否，设置后立即生效。 |

## 使用说明

* 该配置项用于更新 `DAG_PRIO_SS_DATA_CHECK` 的调度线程分值，并控制该优先级下可以并行运行的 Task 数量。Expected 收集阶段生成的并行 Worker 数量上限取自 `DAG_PRIO_SS_DATA_CHECK` 的有效调度额度，因此该配置项同时影响 Shared Meta 并行读取和解析速度、Expected 宏块集合生成速度、临时文件写入和外排归并的并发资源占用、对象存储 LIST 检查的整体执行效率，以及租户 DAG Scheduler 的工作线程资源分配。
* 默认配置值为 0，此时使用内置默认线程分值，当前内置默认值为 3；设置为 1～100 时，使用配置中显式指定的线程分值，数值越大，可供该优先级使用的并发额度越高。实际并发度仍受租户总线程数、其他 DAG 任务竞争及当前可执行任务数量限制。
* 较小的值可以降低巡检对 CPU、内存、Shared Meta 和对象存储的并发压力；较大的值可以提高大租户的巡检速度，但可能增加临时文件 IO 和对象存储 LIST 压力。
* 该参数是调度线程分值，并不表示为巡检创建固定数量的独立 OS 线程。降低线程分值不会强制终止已经运行的 Task，只影响后续任务生成和调度；设置为 0 不会关闭巡检。

## 配置示例

* 使用内置默认线程分值，当前有效值为 3。

  ```shell
  obclient> ALTER SYSTEM SET shared_storage_data_check_thread_score = 0;
  ```

* 显式设置线程分值为 3。

  ```shell
  obclient> ALTER SYSTEM SET shared_storage_data_check_thread_score = 3;
  ```

* 降低巡检并发度，设置线程分值为 1。

  ```shell
  obclient> ALTER SYSTEM SET shared_storage_data_check_thread_score = 1;
  ```

* 提高大租户的巡检并发度，设置线程分值为 6。

  ```shell
  obclient> ALTER SYSTEM SET shared_storage_data_check_thread_score = 6;
  ```
