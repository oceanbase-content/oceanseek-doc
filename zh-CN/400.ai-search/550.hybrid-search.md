# 混合搜索

本文档介绍 OceanBase AI 数据库的混合搜索 SQL 接口。该接口通过 `HYBRID_SEARCH` 关键字直接在一条 `SELECT` 查询语句中组合全文、向量搜索与过滤条件，并返回按相关性融合后的结果。

混合搜索（Hybrid Search）结合了基于向量的语义搜索和基于全文索引的关键词搜索，通过综合排序提供更准确、全面的搜索结果。向量搜索擅长语义近似匹配，但对精确的关键字、数字和专有名词等匹配能力较弱，而全文搜索能有效弥补这一不足。因此，混合搜索已成为 OceanBase AI 数据库的关键特性之一，广泛应用于各类产品中。

## 功能说明和限制

说明如下：

* 全文索引从 V4.6.2.1 版本开始除常规分词器外，新增支持文本分析器（Analyzer）。
* 标量过滤、JSON/ARRAY 过滤在无索引时也可执行，但建议创建相应索引以获得更好性能。

限制如下：

* 当前版本向量索引类型仅支持 HNSW 系列。
* 仅支持行存表。
* 不支持在生成列上使用。
* 使用异步全文索引或异步搜索索引时，混合搜索查询语法不变，但索引数据由后台增量刷新，查询仅保证最终一致性，不保证强一致与实时可见。
* 当前仅支持在**堆表**上使用 `HYBRID_SEARCH` SQL 子句。
* 向量搜索要求目标向量列已创建向量索引。多路向量搜索当前仅支持稠密向量列。
* 全文搜索要求目标文本列已创建全文索引。如果全文列上是多个列的联合索引，则对于混合搜索无效。

本节只列出功能限制，需结合文末相关文档 `HYBRID_SEARCH` 中的语法限制内容一并理解。

## 语法

```sql
SELECT select_list
FROM HYBRID_SEARCH(TABLE table_name, dsl_string);
```

参数说明如下：

* `table_name`：目标表名，仅支持堆表（`ORGANIZATION = HEAP`）；支持分区表和非分区表。
* `dsl_string`：JSON 字符串，用于描述全文、向量搜索、过滤、排序融合等查询语义。

完整语法、参数和限制说明请参见文末相关文档 `HYBRID_SEARCH`。

## 快速入门示例

这部分提供 6 个简单的核心示例，覆盖混合搜索的常用场景，包含向量搜索、全文搜索、向量搜索 + 全文搜索（RRF 融合）、多路向量搜索、过滤条件合并、分数阈值过滤。

### 向量搜索

本示例搜索 `doc_table` 表中与向量 `[1,2,3]` 最相似的 3 条记录，并返回 `c1` 列。

```sql
SELECT c1 FROM HYBRID_SEARCH(
  TABLE doc_table,
  '{
    "knn": {
      "field": "vector",
      "k": 3,
      "query_vector": "[1,2,3]"
    }
  }'
);
```

预期返回结果如下：

```sql
+------+
|    1 |
|    5 |
|    2 |
+------+
3 rows in set
```

本示例语句同时执行全文搜索（匹配关键词 `"oceanbase mysql"`）和向量搜索（搜索与向量 `[1,2,3]` 最相似的 5 条记录），然后通过 RRF 融合算法将两路结果合并，默认返回与查询最相关的 10 条文档，最终符合条件的共 6 条。

```sql
      "k": 5,

    },
    "rank": {
      "rrf": {
        "rank_constant": 60,
        "rank_window_size": 10

  }'
);
```

### 过滤条件合并

本示例搜索 `doc_table` 表中 `content` 列包含 `oceanbase mysql` 的 6 条记录，过滤条件为 `c1` 大于等于 3 且小于等于 5，并返回 `c1` 列。

### 硬过滤与标量算分

标量条件可以只作硬过滤，也可以参与相关性算分（计入 `__score`）。标量过滤条件（`term` / `range` / `terms` / `wildcard`、JSON/数组表达式）均支持 `boost`，可置于任意查询位置；是否计入得分取决于所在位置。位置规则与各表达式写法见文末相关文档 `HYBRID_SEARCH` 中的 `boost 参数详细说明` 部分。

以下示例对比同一 `range` 条件在 `must` 与 `filter` 中的行为：

```sql
-- must：参与算分
SELECT c1, __score FROM HYBRID_SEARCH(
  TABLE doc_table,
  '{
    "query": {
      "bool": {
        "must": [
          {"range": {"c1": {"gt": 1, "boost": 2.1}}}
        ],
        "boost": 2.0
      }
    }
  }'
);

-- filter：不参与算分
SELECT c1, __score FROM HYBRID_SEARCH(
  TABLE doc_table,
  '{
    "query": {
      "bool": {
        "filter": [
          {"range": {"c1": {"gt": 1, "boost": 2.1}}}
        ]
      }
    }
  }'
);
```

前者 `__score` 含标量贡献；后者仅作过滤，`__score` 为 `0` 或无算分贡献。

## 拓展示例

这部分提供一些更复杂的拓展示例，涵盖混合搜索的复杂场景，包含复杂类型过滤（JSON/ARRAY 等）、`num_candidates` 指定向量候选集数量、`wildcard` 通配符过滤、向量和全文搜索的加权混合、WRRF 混合、归一化、混合搜索分数查询、Rerank 精排、聚合（`aggs`）、计数（`count(*)`）、排序（`sort`）、结果折叠（`collapse`）等。

### 标量+JSON/数组过滤

这部分示例需结合搜索索引使用。对于混合搜索场景，全文分词及关键词搜索由全文索引负责，搜索索引则用于复杂类型内部路径的结构化、半结构化或简单标量条件，二者适用列类型不同，可在同一表中同时存在，并与向量索引配合使用，以提升查询性能。

除此之外，在分析型宽表场景下，搜索索引还可以叠加优化器的多索引联合查询（Index Merge）能力，自动识别并组合可用的全文和标量索引，选择最优扫描路径，以进一步提升查询性能。更多关于搜索索引的用法、语法说明和完整示例，请参考 [搜索索引（Search Index）](300.vector-search/210.search-index.md)。

#### JSON 示例

1. JSON_CONTAINS

    JSON_CONTAINS() 函数用于判断目标 JSON 文档中是否包含指定的 `candidate` 子文档，或在给定路径 `path`（可选）下是否存在该元素。

    ```sql
    SELECT id, doc_json FROM HYBRID_SEARCH(
      TABLE doc_json_array,
      '{
      "query": {
        "bool" : {
          "filter" : [{
            "json_contains":{
              "doc_json": {
                "candidate": "doc2",
                "path": "$.name"
              }
            }
          }]
        }
      }
    }');
    ```

    预期返回结果如下：
    :::collapse
    ```sql
    +------+--------------------------------------------------------------------------------------------------+
    | id   | doc_json                                                                                         |
    +------+--------------------------------------------------------------------------------------------------+
    |    2 | {"name": "doc2", "tags": ["database", "mysql"], "metadata": {"type": "production", "score": 57}} |
    +------+--------------------------------------------------------------------------------------------------+
    1 row in set
    ```
    :::

    预期返回结果如下：

3. JSON_MEMBER_OF

    JSON_MEMBER_OF() 函数用于判断被搜索的元素是否和 JSON 数组中的任意一个元素相同，`path` 为可选参数。

    ```sql
    SELECT id, doc_json FROM HYBRID_SEARCH(
      TABLE doc_json_array,
      '{
      "query": {
        "bool" : {
          "filter" : [{
            "json_member_of":{
              "doc_json": {
                "candidate": "\\"database\\""
              }
            }
          }]
        }
      }
    ```

### 嵌套查询示例

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>嵌套查询从 V4.6.2.1 版本开始支持。</p>
</main>

当 JSON 对象数组需要按同一数组元素关联过滤时，先在搜索索引中声明 `NESTED_PATHS`，再在 `dsl_string` 中使用嵌套查询（Nested Query）。例如查找同一条 comment 上 `author=alice` 且 `rating>=5`：

```sql
CREATE SEARCH INDEX idx_nested ON movie_rating (
  j1 WITH (NESTED_PATHS = ('$.comments'))
);

SELECT k, j1 FROM HYBRID_SEARCH(
  TABLE movie_rating,
  '{
    "query": {
      "nested": {
        "path": "j1.comments",
        "query": {
          "bool": {
            "must": [
              {"term": {"j1.comments.author": "alice"}},
              {"range": {"j1.comments.rating": {"gte": 5}}}
            ]
          }
        }
      }
    }
  }'
);
```

多层嵌套、`must_not` 父域/子域否定、建表与测试数据等完整说明与示例，请参见文末 `HYBRID_SEARCH` 文档中的嵌套查询相关小节；`NESTED_PATHS` 声明说明参见文末 `搜索索引` 相关文档。

### 向量候选集大小（num_candidates）

`num_candidates` 用于指定向量搜索时的候选集规模，执行层映射为 `ef_search`，便于从其他搜索系统迁移。取值范围为 `[k, 10000]` 的整数。与 `search_options.ef_search` 同时设置时，以 `num_candidates` 为准；`search_options` 中的 `refine_k`、`filter_mode` 等子项仍可生效。优先级与 `filter_mode` 取值等完整说明及示例见文末 `HYBRID_SEARCH` 语法文档中相关小节。

### wildcard 通配符过滤

`wildcard` 用于标量列的通配符模糊匹配，语义等同于 SQL `LIKE ... ESCAPE '\\'`：`*` 匹配任意多个字符，`?` 匹配任意单个字符。`wildcard` 可在 `bool.must` / `bool.should` 中参与算分，也可用于 `bool.filter` 或 `knn.filter` 做硬过滤。`VARCHAR` 列上的普通索引可走索引扫描路径加速；前缀索引、全文索引及 JSON 相关索引不支持。

更多说明与示例见文末 `HYBRID_SEARCH` 语法文档中的模糊匹配相关小节。

```sql

}');
```

## 通过分区内并行优化性能

混合搜索默认采用单线程串行执行，因此可能会导致在数据量较大、CPU 资源充足的场景下单条查询语句的响应时间（RT）偏高。为解决此问题，引入了分区内并行执行功能，可在单个分区内用并行执行的策略来降低 RT。本功能默认关闭，需要手动开启。

并行执行的具体策略说明如下：

| **并行策略** | **说明** |
|---------|------|
| 多路并行 | 同一查询语句中的多条召回路径（多条 `knn` 路 + 全文 `query` 路）由不同工作线程并行执行，整体 RT 接近耗时最长的那条路径。支持向量路径和全文路径。 |
| `query` 路径内并行 | 单条 `query` 查询路径内并行，包含全文、标量、JSON 类型过滤等召回路径，按数据范围切分后由多个工作
线程并行扫描不同区间，进一步降低单路 RT。不支持向量路径。 |

具体使用说明及示例如下：

### 开启并行

混合搜索并行默认关闭。使用前需在租户内开启配置项：

```sql
ALTER SYSTEM SET _enable_hybrid_search_parallel_execution = true;
```

开启后效果：

* 自动多路并行：若查询包含 ≥ 2 条召回路径（例如一条 `query` 全文路 + 一条或多条 `knn` 路），多路并行会自动生效，无需在 `dsl_string` 字符串中额外配置。
* `query` 路径内并行：
    * 未指定 `query_dop`（`dsl_string` 字符串中 `query.search_options` 对象下参数）时，系统根据 CPU 负载自动选择查询并行度；
    * 如果指定了 `query_dop` 参数且 `query_dop > 1`，则按指定值切分，覆盖自适应并行度；
    * 如果显式指定 `query_dop = 1`，则不进行路径内并行，但不影响多路并行。
* 不满足并行条件、或并行开关关闭时，执行路径会自动退化为串行。

### 多路并行（开启后自动生效）

以下示例在 `doc_table` 上组合全文与向量搜索。开启并行开关后，`query` 路与 `knn` 路将并行执行：

```sql
SET @q = '{
  "query": {
    "match": {"content": "oceanbase mysql"}
  },
  "knn": [
    {"field": "vector", "k": 10, "query_vector": "[1,2,3]"}
  ],
  "rank": {"weighted_sum": {"normalizer": "minmax"}},
  "size": 10
}';

SELECT c1, __score
FROM HYBRID_SEARCH(TABLE doc_table, @q);
```

### `query` 路径内并行（自动/手动）

开启并行后，`query` 路径内并行度有自动和手动两种控制方式：

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>自适应并行度从 V4.6.2.1 版本开始支持。</p>
</main>

#### 自适应并行度（Auto DOP）

不写 `query_dop` 时，系统根据 CPU 负载自动选择查询并行度，可与上一节多路并行示例使用同一条查询。可通过 [DBMS_XPROFILE.DISPLAY_PROFILE](#相关文档) 观察本次查询的并行决策。

#### 显式指定 `query_dop`

在 `dsl_string` 字符串中 `query.search_options` 对象下通过 `query_dop` 指定路径内并行度。

| **字段** | **类型** | **默认值** | **取值范围** | **说明** |
|------|------|--------|----------|------|
| `query_dop` | int | 未指定时自动选择 | `[1, 128]` | 不指定时使用自适应并行度（Auto DOP）；显式指定 `1` 时不进行路径内并行；指定 `2`～`128` 时请求对应并行度。超出取值范围会在 `dsl_string` 字符串解析阶段报错。 |

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p><code>query_dop</code> 仅在并行开关开启时或通过 Hint 强制并行时生效：租户级开关关闭，或通过 Hint 强制串行时，<code>dsl_string</code> 字符串中的 <code>query_dop</code> 会被忽略，不会报错。</p>
</main>

在 `query` 路上设置 `query_dop = 4`，并与 `knn` 路组合（多路并行 + 路径内并行同时生效），示例如下：

```sql
-- query_dop = 4：全文召回路径按数据范围切成 4 段并行扫描
SET @q = '{
  "query": {
    "search_options": {"query_dop": 4},
    "match": {"content": "oceanbase mysql"}
  },
  "knn": [
    {"field": "vector", "k": 5, "query_vector": "[1,2,3]"}
  ],
  "rank": {"rrf": {"rank_constant": 60}},
  "size": 10
}';

SELECT c1, __score
FROM HYBRID_SEARCH(TABLE doc_table, @q);
```

`query_dop` 参数详细信息请参见 [HYBRID_SEARCH 语法文档](#相关文档)中的查询选项部分。

### 查询级开关

可在单条查询上通过 Hint 临时覆盖租户级配置，便于灰度测试：

| **Hint** | **取值** | **说明** |
|------|------|------|
| `OPT_PARAM('enable_hybrid_search_parallel_execution', 'TRUE'/'FALSE')` | `'TRUE'` / `'FALSE'` | 单条查询级开关，优先级高于租户级配置 `enable_hybrid_search_parallel_execution`。 |

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>Hint 中参数不需要带下划线前缀，直接使用 <code>enable_hybrid_search_parallel_execution</code> 即可。</p>
</main>

强制串行与强制并行对比示例（`dsl_string` 字符串相同，仅 Hint 不同）：

```sql
-- 强制并行（即使系统配置关闭，Hint 也会覆盖）
SELECT /*+ OPT_PARAM('enable_hybrid_search_parallel_execution', 'TRUE') */
       c1, __score
FROM HYBRID_SEARCH(TABLE doc_table, @q);

-- 强制串行（即使系统配置开启，Hint 也会覆盖）
SELECT /*+ OPT_PARAM('enable_hybrid_search_parallel_execution', 'FALSE') */
       c1, __score
FROM HYBRID_SEARCH(TABLE doc_table, @q);
```

Hint 详细信息请参见文末[相关文档](#相关文档)。

### 并行开关与生效条件

混合搜索并行的开关有两种，优先级如下（由高到低）：

1. 查询级 Hint：`OPT_PARAM` Hint 优先级最高，会覆盖系统配置项设置。
2. 租户配置项：`_enable_hybrid_search_parallel_execution`（未写 Hint 时生效）。

开关最终取值为 `TRUE` 只表示允许并行；是否真正走多路并行或 `query` 路径内并行，仍由执行计划按[上文所述策略](#通过分区内并行优化性能)决定。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>Hint 可覆盖系统配置。因此，仅将租户配置项 <code>_enable_hybrid_search_parallel_execution</code> 设置为 <code>FALSE</code> 并不能保证所有并行查询被关闭。如果有 SQL 明确使用 Hint 强制开启并行，仍需移除这些 Hint 后才能完全回退为串行。</p>
</main>

其他并行问题解答请参见文末相关文档中的 `AI 场景常见问题`。
