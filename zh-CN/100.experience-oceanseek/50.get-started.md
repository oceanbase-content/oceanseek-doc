# 开始使用 OceanSeek

本文介绍如何快速搭建一个 OceanSeek 体验和测试环境。OceanSeek 支持 Docker Compose 单机体验和 Helm Kubernetes 部署，两种方式均可完成数据库连接与 SQL 读写验证。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>体验和测试环境不能保证全部功能的可用性和性能，请务必不要用于业务生产。关于部署生产环境的详细介绍，参见 <a href="../150.deploy/100.deploy-overview.md">部署概述</a>。</p>
</main>

## 资源规划

OceanSeek 由 OBServer 和 LogService 两个组件构成，进行资源规划时需要同时考虑两个组件的资源需求。

| 环境 | 节点角色 | 最少节点 | 单节点 CPU/内存 | 单节点本地存储 | 组件配额 |
| --- | --- | --- | --- | --- | --- |
| 最小规格（测试） | ODP + OBServer | 1 | 4C/16G | SSD 50GB | ODP 1C/2G </br> OBServer 3C/10G |
| 最小规格（测试） | LogService | 3 | 2C/4G | 20GB | 每个 LogService 2C/4G |
| 生产环境 | ODP + OBServer | 2 | 8C/32G | SSD 256GB | ODP 2C/4G </br> OBServer 6C/24G |
| 生产环境 | LogService | 3 | 2C/4G | 100GB | 每个 LogService 2C/4G |

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p><ul><li>使用 Compose 部署时，不包含 ODP，通过 SQL 直连 OBServer。部署单机体验环境时，仍需要为 OBServer、3 个 LogService、监控、对象存储和系统预留资源。</li><li>使用 Helm 部署时，默认会部署 1 个 ODP、1 个 OBServer 和 3 个 LogService，且需要符合最小测试组件规格。</li><li>生产环境还需单独规划对象存储、备份恢复、监控和高可用等能力。关于生产环境的部署资源要求和部署方法，参见 <a href="../150.deploy/100.deploy-overview.md">部署概述</a>。</li></ul></p>
</main>

## 使用 Docker Compose 部署

### 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Linux AMD64 |
| 容器环境 | Docker Engine 24+、Docker Compose v2.23.1+ |
| 单机资源 | 12 vCPU、32 GiB 可用内存、250 GiB SSD 可用磁盘 |
| 网络 | 可访问镜像仓库；主机端口 `32881`、`32886` 未占用 |

执行以下命令，查询 Docker Engine 和 Docker Compose 的版本。

```bash
sudo docker version
sudo docker compose version
```

### 部署

在空目录中执行：

```bash
curl -fLO https://mirrors.aliyun.com/oceanbase/docker/oceanseek/compose.yaml
sudo docker compose up -d
sudo docker compose logs -f observer-bootstrap
```

返回 `OceanSeek deployment completed.` 表示部署完成。可以从终端输出获取：

+ obshell 的管理地址：`http://<主机 IP>:32886/`
+ SQL 连接地址：`<主机 IP>:32881`
+ `root@sys` 初始密码

按 `Ctrl+C` 仅退出日志跟踪，不影响服务运行。

### 连接 OceanSeek

使用 MySQL 兼容的客户端进行连接。关于 OceanSeek 连接的详细介绍，参见 [连接概述](../200.connect/100.connection-methods-overview.md)。

```bash
mysql -h<主机或节点 IP> -P<SQL 端口> -uroot@sys -p
```

输入部署输出中的数据库密码，执行以下 SQL：

```sql
CREATE DATABASE IF NOT EXISTS oceanseek_demo;
USE oceanseek_demo;
CREATE TABLE IF NOT EXISTS hello (
  id INT PRIMARY KEY,
  message VARCHAR(64)
);
REPLACE INTO hello VALUES (1, 'Hello, OceanSeek!');
SELECT * FROM hello;
```

查询返回 `Hello, OceanSeek!`，说明部署成功。

### 停止与清理

```bash
# 停止服务并保留数据
sudo docker compose stop -t 120

# 恢复服务
sudo docker compose up -d

# 删除部署及所有数据
sudo docker compose down -v
```

## 使用 Helm 部署

### 环境要求

| 项目 | 要求 |
| --- | --- |
| Kubernetes | 1.33 ~ 1.36 |
| 客户端 | Helm 3、kubectl |
| 权限 | 可创建命名空间、CRD、RBAC 和工作负载 |
| 存储 | 可用的 StorageClass，推荐使用 `local-path` |
| 单机资源 | 16 vCPU、32 GiB 内存、350 GiB 空闲数据盘 |

```bash
kubectl get nodes -o wide
kubectl get storageclass
helm version --short
```

### 部署

```bash
helm repo add ob-operator https://oceanbase.github.io/ob-operator/
helm repo update
helm install oceanseek ob-operator/oceanseek --namespace=oceanseek --create-namespace --create-namespace --wait --wait-for-jobs --timeout 60m
```

返回 `STATUS: deployed` 表示部署完成。

等待安装期间，可在另一个终端查看进度：

```bash
curl -fL --retry 3 -o progress.py 'https://raw.githubusercontent.com/oceanbase/ob-operator/master/scripts/oceanseek/progress/progress.py' 
python3 progress.py -n oceanseek --release oceanseek
```

获取访问地址和初始密码：

```bash
helm get notes oceanseek -n oceanseek
```

按 NOTES 输出访问 OceanSeek Dashboard、SQL 连接地址及对应密码。Dashboard 初始密码与 `root@sys` 数据库密码相互独立。

### 连接 OceanSeek

使用 MySQL 兼容的客户端连接。关于 OceanSeek 连接的详细介绍，参见 [连接概述](../200.connect/100.connection-methods-overview.md)。

```bash
mysql -h<主机或节点 IP> -P<SQL 端口> -uroot@sys -p
```

输入部署输出中的数据库密码，执行以下 SQL：

```sql
CREATE DATABASE IF NOT EXISTS oceanseek_demo;
USE oceanseek_demo;
CREATE TABLE IF NOT EXISTS hello (
  id INT PRIMARY KEY,
  message VARCHAR(64)
);
REPLACE INTO hello VALUES (1, 'Hello, OceanSeek!');
SELECT * FROM hello;
```

查询返回 `Hello, OceanSeek!`，说明部署成功。

### 停止与清理

```bash
helm uninstall oceanseek -n oceanseek

# 如需同时删除命名空间
kubectl delete namespace oceanseek
```

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>如果使用外部对象存储，卸载 Helm 不会自动删除桶内数据，请按对象存储平台规则单独清理。</p>
</main>
