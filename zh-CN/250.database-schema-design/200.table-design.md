# 表设计

在 OceanBase AI 数据库中，表是最基础的数据存储单元，包含了所有用户可以访问的数据。每个表由多行记录组成，每条记录包含多个列。合理的表设计是系统高效性和可扩展性的基础。

## 表类型

OceanBase AI 数据库支持多种表类型，可从**主键**、**存储格式**和**特殊用途**等维度来理解。

### 按主键分类

* **主键表**：表中包含主键，数据按主键排序存储，点查效率高。
* **无主键表**：表中未指定主键，数据按写入顺序存储，适合日志类追加写入场景。

### 按存储格式分类

* **行存表**：数据按行组织存储，适合 OLTP 类点查与事务处理场景。
* **列存表**：数据按列组织存储，能显著提升分析型查询的性能，尤其适用于大数据量下的聚合分析场景。详情请参见 [列存表架构](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000005683265)。
* **行列混存表**：数据同时按行和按列各存储一份，系统会根据查询语句自动选择行存或列存路径，适用于交易类业务和分析类业务兼顾的 HTAP 场景。

### 其他表类型

* **分区表**：将表中数据按一定规则划分到不同区块，同一区块的数据在物理上集中存储，便于分区裁剪和并行处理。基本分区策略包括范围（Range）分区、列表（List）分区、哈希（Hash）分区和 Key 分区。

* **堆表（堆组织表）**：数据不按主键排序存储，主键作为二级唯一索引，数据与索引解耦。当数据按时间顺序写入时，能有效利用 Skip Index 提高分析型查询效率。在 **AP 场景** 下，新建表**默认采用堆组织表**——租户级配置项 [default_table_organization](../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2150.default_table_organization.md) 在 OLAP 参数模板下为 `HEAP`，未显式指定 `ORGANIZATION` 时新建表即为堆表，便于大批量导入与 Skip Index 利用。
* **临时表**：用于存放 ETL 中间结果、旁路导入暂存、复杂查询的中间结果缓存等。数据按会话或事务隔离，会话结束或事务提交/回滚后自动清理。
* **外部表**：数据不在数据库内部，而是存储在外部存储服务中，通过数据库的表定义进行访问，适用于数据导入导出和跨系统数据查询。

## 表更新模式

OceanBase AI 数据库支持在建表时通过 `CREATE TABLE` 语句的 `merge_engine` 参数指定数据更新模式，以适应不同的业务场景。

+ **delete_insert（全列更新模式）**

  以 **查询性能优先**，通过“Merge-On-Write”机制将 `UPDATE` 操作转化为全列的 `DELETE` 和 `INSERT` 记录，确保每行数据包含完整的列值。这种模式显著提升了复杂查询和批处理的效率（如分析型任务），但增量数据需要额外存储空间，适用于 **增量数据频繁且需要快速分析** 的场景。

+ **partial_update（部分更新模式）**  

  仅记录修改的列的值，避免冗余存储。查询时需合并多份数据以获取最新值，性能相对较低，但更适合 **高频更新但查询需求低** 的场景（如 OLTP 类业务），或对存储成本敏感的环境。

| **特性类别** | **delete_insert 更新模式** | **partial_update 更新模式** |
| --- | --- | --- |
| **存储方式** | 每次更新在 SSTable 中写入两行（`DELETE` 和 `INSERT`），包含全列数据。 | 每次更新仅记录修改的列的值，存储空间更节省。 |
| **查询效率** | <ul><li>查询时提前在 Memtable/SSTable 中计算下压过滤算子。</li><li>若增量数据过滤结果不包含对基线数据更新，则可以分别批处理基线与增量数据；如果过滤结果包含对基线数据更新，合并增量/基线的记录获取最新值进行投影。</li></ul>| 查询时需合并多个 Memtable/SSTable 的记录，以获取主键的最新值，可能影响性能。  <br/> 适用于对存储成本敏感且更新操作频繁的场景。 |
| **适用场景** | 增量数据比例较高，需要频繁执行复杂查询或批处理分析的场景。    | 高频更新但查询需求较低的场景。   |
