# 数据写入

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>本功能在当前版本为实验特性。</p>
</main>

本文将介绍 Agent 混合搜索场景中的写入接口。数据模型由 `id`、`document`、`embedding`、`metadata` 四个字段构成，详见 [场景概述](100.overview.md)。

<main id="notice" type='explain'>
    <h4>说明</h4>
    <p>本文示例承接 <a href="300.quick-start.md">快速上手</a>：假定已创建 Collection <code>tech_docs</code> 与 Namespace <code>my_knowledge</code>，并在该 Namespace（变量 <code>ns</code>）上操作。示例数据与快速上手保持一致。</p>
</main>

## 插入（add）

```shell
# 单条
ns.add(
    ids="doc1",
    documents="OceanBase AI 数据库是蚂蚁集团自研的分布式数据库，支持 HTAP 混合负载",
    metadatas={"category": "database", "version": "4.0"},
)

# 批量（建议）
ns.add(
    ids=["doc1", "doc2", "doc3"],
    documents=[
        "OceanBase AI 数据库是蚂蚁集团自研的分布式数据库，支持 HTAP 混合负载",
        "Agent 混合搜索场景是 OceanBase AI 数据库面向 AI Agent 的多租户向量搜索方案",
        "pyseekdb 是 OceanBase AI 数据库的 Python SDK，提供向量存储与混合搜索能力",
    ],
    metadatas=[
        {"category": "database", "version": "4.0"},
        {"category": "ai", "version": "4.6"},
        {"category": "sdk", "version": "1.2"},
    ],
)
```

如果已有向量，传入 `embeddings` 即可跳过自动向量化：

```shell
ns.add(
    ids=["doc1"],
    documents=["OceanBase AI 数据库是蚂蚁集团自研的分布式数据库，支持 HTAP 混合负载"],
    embeddings=[[0.12, 0.34, ...]],  # 384 维
)
```

约束与建议如下：

* `add` 要求 `id` 在 Namespace 内唯一。传入重复 `id` 可能导致插入失败；需要重复执行的场景请使用 `upsert`。
* 写入参数名使用复数形式：`documents` / `embeddings` / `metadatas`。
* 批量写入时，各参数长度必须与 `ids` 一致。例如，`ids` 为 `["doc1", "doc2", "doc3"]`，则 `documents`、`embeddings`、`metadatas` 的长度必须为 3。
* Namespace 模式单次批量最多 100 条；更大数据量请循环分批写入。

嵌入（Embedding）规则如下：

* 显式传入 `embeddings` 稠密向量时，SDK 直接使用该向量，不会调用嵌入函数（EmbeddingFunction）。
* 未传 `embeddings` 但传入 `documents` 时，必须已配置 Collection 的嵌入函数，否则会报错。
* 允许仅传 `metadatas` 占位，此时 `document` 和 `embedding` 为空。
* `add` 至少需要提供 `embeddings`、`documents`、`metadatas` 之一。

## 更新（update）

```shell
# 按 id 更新 metadata 和 document
ns.update(
    ids="doc1",
    documents="OceanBase AI 数据库是蚂蚁集团自研的分布式数据库，支持 HTAP 混合负载（已更新）",
    metadatas={"category": "database", "version": "4.7"},
)
```

`update` 不检查影响行数，传入不存在的 `id` 不会抛错，也不会产生更新。如需确认更新结果，请自行调用 `get` 或 `count` 验证。不需要更新的字段可省略不传。

<main id="notice" type='notice'>
    <h4>注意</h4>
    <p>SDK 不校验传入向量是否与嵌入模型语义一致，需由业务侧保证同一 Collection 内的向量空间一致。</p>
</main>

## 插入或更新（upsert）

`upsert` 按 `id` 执行插入或更新操作：已存在则更新，不存在则插入。比 `add` 更容错，适合需要重复执行的写入场景。

```shell
ns.upsert(
    ids=["doc1", "doc4"],
    documents=[
        "OceanBase AI 数据库是蚂蚁集团自研的分布式数据库，支持 HTAP 混合负载",
        "新增一条 SDK 使用说明",
    ],
    metadatas=[
        {"category": "database", "version": "4.0", "status": "updated"},
        {"category": "sdk", "version": "1.3", "status": "new"},
    ],
)
```

`update` / `upsert` 的向量语义与 `add` 一致：

* 显式传入 `embeddings` 时优先使用该向量，不会调用嵌入函数。
* 仅传 `documents` 时，依赖 Collection 已配置的嵌入函数自动生成向量。
* 仅更新 `metadatas` 时不会触发向量重算。

## 删除（delete）

`delete` 至少需要提供 `ids`、`where`、`where_document` 之一。

```shell
# 按 id 删除
ns.delete(ids=["doc1", "doc2"])

# 按条件删除
ns.delete(where={"status": "obsolete"})

# 按文档内容删除
ns.delete(where_document={"$contains": "过时内容"})
```
