# 限制与约束

接入闪应用场景前，建议先阅读本页，核对版本、规模和 SQL 能力是否满足业务需要。确认可行后再按连接、快速上手等文档动手。

**接入边界（版本、规模、SQL 能力）以本页为准**；单次写入与查询行数、表字段上限等操作限额见 [数据操作](#相关文档)；连接池参数见 [通过 json-table-sdk 连接数据库](#相关文档)。各功能文档中的就近提示仍有效。

## 使用前须知

* 数据库版本须为 OceanSeek **V4.6.2.1** 及以上。
* 创建客户端时须设置 `use_namespace=True`，并先创建或获取 Collection，再执行建表与读写。
* 请通过 json-table-sdk 访问数据，不要直接读写底层物理表或手工修改 SDK 自动维护的映射表。
* Collection 命名与分区数（`partition_count`）规则见 [Collection 与 App 管理](#相关文档)。

## 常见报错情形

| **错误操作** | **结果** |
| --- | --- |
| 未设置 `use_namespace=True` | 不会进入本场景的逻辑表用法。 |
| 已启用 Namespace，但未创建 Collection 就开始读写 | 抛出 `ValueError`。 |
| 数据库版本低于 V4.6.2.1 时创建 Collection | 抛出 `ValueError`。 |
| 同时设置 `use_namespace=True` 与 `index_columns` | 创建客户端时抛出 `ValueError`。 |
| 建表时指定主键或唯一键 | 抛出 `ValueError`。 |

## 规模建议

| **项目** | **说明** |
| --- | --- |
| 单个数据库下的 Collection 数量 | 无硬上限，建议控制在约 20 个以内。 |
| App（`app_prefix`）数量 | 单 Collection 下最多 1000 万个；首次访问某 `app_prefix` 时自动注册 Namespace。 |
| `app_prefix` 长度 | 最长 256 字符。 |
| 每个 App 下的用户表 | 同一 App（Namespace）下可创建多张用户表，最多 10 万张；超出上限会抛出 `ValidationError`。 |

## SQL 能力范围

接入前可据此判断业务 SQL 是否可落地：

| **语句** | **说明** |
| --- | --- |
| `CREATE TABLE` | 可用 `NOT NULL`、`DEFAULT`、`COMMENT`；不可用主键、唯一键、外键、索引、自增等。 |
| `ALTER TABLE` | 仅支持加列，且必须带 `DEFAULT`。 |
| `INSERT` | 必须写明列名；不支持 `INSERT ... SELECT`、`ON DUPLICATE KEY UPDATE`、`REPLACE INTO`。 |
| `SELECT` | 支持常见条件、排序、分页、分组，以及同 App（Namespace）内两表 JOIN（含同表自连接）；不支持跨 App（ Namespace） JOIN、三表及以上 JOIN、子查询、`UNION`、`DISTINCT`、窗口函数、Hint 等。 |
| `UPDATE` / `DELETE` | 建议加 `LIMIT`；操作只会作用在当前 App、当前表。 |

单次 `INSERT` / `SELECT` 行数、`ORDER BY` / `GROUP BY` 列数、单表列数与行大小等，见 [数据操作](#相关文档)。

## 性能与并发

可通过以下说明和限制进行接入评估：

* 批量写入通常建议每批 100～500 行；更高吞吐依赖连接数与并行度，操作请参见 [通过 json-table-sdk 连接数据库](#相关文档)。
* 复杂查询建议分页；新 App 上线前可先 `prewarm`，操作请参见 [Collection 与 App 管理](#相关文档)。
* 尽量避免单个客户端扛过高持续并发、逐行高频 `INSERT`、不带 `LIMIT` 扫大结果集、同一库堆过多 Collection。
