# 闪应用场景概述

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>本功能从 V4.6.2.1 版本开始支持。</p>
</main>

闪应用场景是逻辑表（Logical Table）的一类落地用法，面向动态表结构与多应用 SQL 读写：多个小应用可以共用同一套底层物理表，通过 App（即 Namespace）相互隔离，而不必为每个应用单独建物理表。

本场景通过 `json-table-sdk` 使用逻辑表（创建客户端时设置 `use_namespace=True`）。使用方式与普通表相同：先 `CREATE TABLE` 建表，再用 `INSERT`、`SELECT` 等 SQL 读写数据。行在数据库内以 JSON 形式保存，相关转换由 json-table-sdk 自动完成，一般无需直接处理 JSON 路径或 `JSON_TABLE` 函数。

## 核心能力

| **能力** | **说明** |
| --- | --- |
| 多应用隔离 | 多个 App 共用 Collection 底层存储，按 Namespace 逻辑隔离。 |
| 虚拟表的创建与变更 | 支持创建 / 删除虚拟表、添加列，以及查询表结构与表列表。<main id="notice" type='notice'><h4>注意</h4><p>从 V4.6.2.1 版本开始，同一 App（Namespace）下可创建多张表。</p></main>|
| SQL 读写 | 通过 SDK 执行 INSERT / UPDATE / DELETE / SELECT。 |
| 基于 JSON 的结构化查询 | 利用 `JSON_TABLE` 函数将 JSON 行还原为结构化结果（由 json-table-sdk 完成转换）。 |
| 搜索索引（Search Index）加速 | 逻辑数据表内置搜索索引（如 `idx_json(data_content)`），加速搜索。 |
| 分区裁剪 | 按 `namespace_id` KEY 分区，单 App 查询可裁剪分区。 |
| 预热（Prewarm） | App 长时间未访问或刚上线时，首次查询可能较慢。可调用 `prewarm` 提前把该 App 的数据加载到缓存，减轻首次访问延迟。 |
