# 数据库模式设计概述

数据库模式设计是业务需求与数据库能力之间的桥梁。合理的模式设计能够充分利用 OceanBase AI 数据库的分布式架构，在查询性能、存储效率和扩展性之间取得平衡。本章节将从以下几个方面展开。

## 表设计

介绍 OceanBase AI 数据库支持的表类型和表更新模式。表类型可从数据组织、主键、存储格式和特殊用途等维度理解，包括分区表、复制表、堆表、列存表、行列混存表等；表更新模式包括 delete_insert（全列更新）和 partial_update（部分更新）两种策略。详见[表设计](200.table-design.md)。

## 数据分布

介绍分区策略（Hash/Key、Range、List）及其对数据分布、负载均衡和查询性能的影响。合理的分区设计可以做分区裁剪减少扫描量，并利用多机资源提升查询性能。详见[数据分布](300.data-distribution.md)。

## 索引

介绍 B-tree 索引、全文索引、JSON 多值索引、空间索引、向量索引等类型，以及局部/全局、行存/列存等分类维度。详见[索引](400.index.md)。

## 数据类型

为每个列选择合适的数据类型，以减少存储空间并提高查询速度。常见类型包括基础类型（`INT`、`VARCHAR`、`DATE` 等）和复杂类型（`JSON`、`ARRAY`、`BITMAP` 等）。更多信息，请参见 [数据类型](500.data-type.md)。

## 视图

OceanBase AI 数据库支持普通视图和物化视图。普通视图仅存储查询定义，不存储查询结果；物化视图在物理上保留查询结果，支持异步更新，适用于预聚合、报表和大屏等场景。更多信息，请参见 [物化视图](../700.reference/300.database-object-management/600.manage-views-of-mysql-mode/200.manage-materialized-views-of-mysql-mode/100.materialized-views-overview-of-mysql-mode.md)。

## 逻辑表

逻辑表面向海量隔离域共享底层存储的需求，按 Namespace 做逻辑隔离，避免为每个用户、Agent 或应用单独创建物理表。当前主要落地为 Agent 混合搜索与闪应用两类场景。更多信息，请参见 [逻辑表概述](600.logical-table/50.logical-table-overview.md)。

以上维度相互关联——表类型决定了数据的存储方式，数据分布影响了查询的并行度，索引决定了数据的访问路径，数据类型和视图则影响存储效率与分析能力，逻辑表则用于在海量隔离域下共享底层存储。建议结合实际业务场景（OLTP、OLAP、HTAP 或 AI Agent / 闪应用）综合考虑，而非孤立地做选择。
