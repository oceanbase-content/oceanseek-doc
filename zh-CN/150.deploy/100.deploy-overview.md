# 选择合适的部署方案

OceanBase AI 数据库由 OBServer 和 LogService 两个组件构成，目前支持 OBServer 和 LogService 独立部署和混合部署两种部署方案。

* 独立部署：OBServer 和 LogService 独立机器部署，两个组件独立扩缩容。
* 混合部署：OBServer 和 LogService 部署在同一台机器上，两个组件可以独立扩缩容。

也就是一台物理机上可以同时存在一个 observer 进程和一个 logservice 进程，也可以只有 observer 进程或者只有 logservice 进程。

LogService 需要三副本部署，至少需要三个节点。OBServer 可以单副本或者两副本部署。因此，根据 OBServer 的副本个数，还可以分为单副本部署和两副本部署。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>OceanBase AI 数据库的计算节点（OBServer）仅需部署两副本即可获得与传统三副本架构同等的高可用和容灾能力，同时在存储成本和计算资源消耗上均显著降低。更多副本数（如三副本及以上）不会带来额外的可用性提升，反而会增加不必要的计算和存储开销。因此建议：计算节点（OBServer）副本数推荐设置为单副本或两副本，不推荐配置为三副本或更多</p>
</main>

您可以根据业务需要结合上述两个方面选择合适的部署方案。

| 部署方案 | 方案 | 适用场景 |
| ------- | ------- | ----- |
| 单副本 | OBServer 和 LogService 完全混部 | 适用于集群规模小，且 OBServer 计算资源要求高的场景 |
| 单副本 | OBServer 和 LogService 部分混部 | 适用于业务机器资源有限的场景。 |
| 单副本 | OBServer 和 LogService 独立部署 | 适用于集群规模大，要求资源独占的场景。 |
| 两副本 | OBServer 和 LogService 部分混部 | 可以实现机房级容灾  |

## OBServer 单副本部署方案

### 模式一：OBServer 和 LogService 完全混部

LogService 三副本部署，OBServer 单副本部署。LogService 的所有 Zone 都可以部署 OBServer，将资源最大化利用。适用于集群规模小，且 OBServer 计算资源要求高的场景。具体部署架构如下。

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oceanbase-database-ai/deploy/deploy-overview/1.png)

* observer：zone1@Node1, Node2, Node3
* logservice: zone1@Node1; zone2@Node2; zone3@Node3

### 模式二：OBServer 和 LogService 部分混部

LogService 三副本部署，OBServer 单副本部署。在 LogService 的三个 Zone 中，可以挑选某个 Zone（比如 zone3）仅用于部署 LogService，可以为该 Zone 提供小规格的机器。适用于业务机器资源有限的场景。具体部署架构如下。

![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oceanbase-database-ai/deploy/deploy-overview/2.png)

* observer：zone1@Node1, Node2
* logservice: zone1@Node1; zone2@Node2; zone3@Node3

### 模式三：OBServer 和 LogService 独立部署

LogService 三副本部署，OBServer 单副本部署。如果 OBServer 需要的节点数比较多，也可以将 OBServer 和 LogService 都独占机器部署。适用于集群规模大，要求资源独占的场景。具体部署架构如下。

![3](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oceanbase-database-ai/deploy/deploy-overview/3.png)

* observer: zone1@Node1, Node2, Node3
* logservice: zone1@Node4;
              zone2@Node5;
              zone3@Node6

## OBServer 两副本部署方案

LogService 三副本部署，OBServer 两副本部署。在 LogService 三个 Zone 中，其中两个 Zone 中混合部署 OBServer，第三个 Zone 仅部署 LogService，这样 OBServer 扩节点时，LogService 也可以同步扩资源。该架构下可以实现 OBServer 的机房级容灾。具体部署架构如下。

![4](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oceanbase-database-ai/deploy/deploy-overview/5.png)

* observer：zone1@Node1-1, Node1-2, Node1-3;
            zone2@Node2-1, Node2-2, Node2-3
* logservice: zone1@Node1-1, Node1-2, Node1-3;
              zone2@Node2-1, Node2-2, Node2-3;
              zone3@Node3-1,Node3-2
