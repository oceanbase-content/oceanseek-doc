# Transaction management overview

This topic describes basic information about transactions and related control statements.

## Introduction to transactions

A database transaction consists of a series of operations on the database, which transforms the database from one consistent state to another. Typically, the SQL statements in a transaction include both DML and query statements. If a transaction contains only query statements, it is usually called a read-only transaction.

Before a transaction is committed, you can use the `ROLLBACK` statement to roll it back. 

## Transaction control statements

The basic transaction control statements are as follows:

* [Start a transaction](200.start-a-transaction-of-mysql-mode.md): Explicitly starts a transaction. This statement is optional in the following cases:

  * If the value of the system variable `autocommit` for a tenant session is `0`, the automatic commit feature is disabled. In this case, you do not need to explicitly issue the `BEGIN` statement to combine multiple SQL statements into one transaction.

  * If the value of the system variable `autocommit` for a tenant session is `1`, the automatic commit feature is enabled. In this case, each SQL statement is an independent transaction. If you want a transaction that contains more than one statement, you can explicitly run the `BEGIN` statement to start a transaction. In this case, the automatic commit feature is disabled until the `COMMIT` or `ROLLBACK` statement is executed.

* [Mark a savepoint](300.transaction-savepoints-of-mysql-mode/100.mark-a-savepoint-of-mysql-mode.md): Marks a savepoint in a transaction, so that you can roll back to it later. Savepoints are optional, and a transaction can have multiple savepoints.

* [Commit a transaction](400.submit-transaction-of-mysql-mode.md): Commits and ends the current transaction, permanently applies all changes made in the transaction, clears all savepoints, and releases the locks held by the transaction.

* [Roll back a transaction](500.roll-back-transactions-of-mysql-mode.md): Rolls back all changes made in a transaction or only the changes made after a specific savepoint, clears all savepoints within the rolled-back portion, and releases the locks held by the transaction.

In the `obclient` command-line interface, you can issue transaction control commands after the SQL prompt, or modify the `autocommit` variable at the session level to control whether transactions are automatically committed.

* If you set the `autocommit` variable by using the `SET autocommit` statement, the change takes effect immediately for the current session and becomes invalid after the session is disconnected.

* If you set the tenant-level variable by using the `SET GLOBAL autocommit` statement, the change takes effect only after the session is disconnected.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If the <code>autocommit</code> value of the current session is <code>0</code> and no transaction is explicitly committed, OceanBase AI Database automatically rolls back the last uncommitted transaction if the program terminates abnormally.</p>
