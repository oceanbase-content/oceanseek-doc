# Create a dynamic partitioned table

In OceanSeek, you can use the `DYNAMIC_PARTITION_POLICY` clause to specify the dynamic partition management attributes of a table during creation.

This topic describes how to create a dynamic partitioned table by using SQL statements.

## Limitations and considerations

* You must specify at least one partition definition when creating a dynamic partitioned table in the current version.
* Dynamic partition management is supported only for the following types of partitioned tables:

  * Partitioned tables with RANGE COLUMNS partitioning and a partitioning key of `DATE`, `DATETIME`, `TIMESTAMP`, `YEAR`, or `BIGINT` (with `BIGINT_PRECISION` precision specified).
  * Partitioned tables with RANGE partitioning and a partitioning key of `YEAR` or `BIGINT` (with `BIGINT_PRECISION` precision specified).
  * Partitioned tables with LIST COLUMNS partitioning and a partitioning key that is a string time column. The string partitioning key supports `VARCHAR`/`CHAR`, and the format is determined by the value of `TIME_UNIT`:

    * When `TIME_UNIT = 'year'`: The string partitioning key format is `YYYY`, for example, `2026`.
    * When `TIME_UNIT = 'month'`: The string partitioning key format is `YYYYMM`, for example, `202608`.
    * When `TIME_UNIT = 'day'`: The string partitioning key format is `YYYYMMDD`, for example, `20260819`.
    * When `TIME_UNIT = 'hour'`: The string partitioning key format is `YYYYMMDDHH`, for example, `2026081910`.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>Dynamic partition management is supported for partitioned tables with LIST COLUMNS partitioning and a string time column as of V4.6.2.1.</p>
    </main>

* Dynamic partition management can be enabled only for a partitioned table or a partition of a subpartitioned table.
* Pre-creating partitions and deleting expired partitions after table creation are not executed immediately. You need to wait for the next automatic scheduling of a dynamic partition management task or manually schedule one. For more information about scheduling dynamic partition management tasks, see [Dynamic partition management tasks](500.dynamic-partition-management-task-of-mysql-mode.md).

## Privilege requirements

You must have the `CREATE` privilege to create a dynamic partitioned table. For more information about privileges in OceanSeek, see [Permission classification](../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

The SQL statement for creating a dynamic partitioned table is as follows:

```sql
CREATE TABLE [IF NOT EXISTS] table_name (table_definition_list)
    DYNAMIC_PARTITION_POLICY [=] (dynamic_partition_policy_list)
    partition_option;

dynamic_partition_policy_list:
    dynamic_partition_policy_option [, dynamic_partition_policy_option ...]

dynamic_partition_policy_option:
    ENABLE = {true | false}
    | TIME_UNIT = {'hour' | 'day' | 'week' | 'month' | 'year'}
    | PRECREATE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
    | EXPIRE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
    | TIME_ZONE = {'default' | 'time_zone'}
    | BIGINT_PRECISION = {'none' | 'us' | 'ms' | 's'}
```

## Description of dynamic partition management attributes

| **Attribute name** | **Description** | **Required** | **Modifiable** |
| ------------------ | ---------- | -------------- | ---------------- |
| ENABLE | Indicates whether to enable dynamic partition management. Valid values: <ul><li>`true`: The default value, which indicates that dynamic partition management is enabled.</li><li>`false`: Indicates that dynamic partition management is disabled.</li></ul> | No | Yes |
| TIME_UNIT | The time unit for partitioning, which is the interval at which partition boundaries are automatically created. Valid values: <ul><li>`hour`: Partitions are divided by hour.</li><li>`day`: Partitions are divided by day.</li><li>`week`: Partitions are divided by week.</li><li>`month`: Partitions are divided by month. </li><li>`year`: Partitions are divided by year.</li></ul> | Yes | No |
| PRECREATE_TIME | Represents the pre-create time. When scheduling a dynamic partition management task, partitions are pre-created so that **max_partition_upper_bound > now() + precreate_time**. Valid values: <ul><li>`-1`: The default value, indicating that partitions are not pre-created. </li><li>`0`: Indicates that only the current partition is pre-created.</li><li>`n {hour \| day \| week \| month \| year}`: Indicates to pre-create partitions for the specified time span. For example, `3 hour` means to pre-create partitions for the next 3 hours.</li></ul>  <main id="notice" type='explain'><h4>Note</h4><p><ul><li>When you need to pre-create multiple partitions, the interval between partition boundaries is <code>TIME_UNIT</code>.</li><li>The boundary of the first pre-created partition is the existing maximum partition boundary rounded up by <code>TIME_UNIT</code>.</li></ul></p></main> | No | Yes |
| EXPIRE_TIME | Indicates the partition expiration time. When dynamic partition management is scheduled, all partitions whose **upper_bound < now() - expire_time** are deleted. Valid values: <ul><li>`-1`: The default value, indicating that the partition never expires. </li><li>`0`: Indicates that all partitions except the current partition expire.</li><li>`n {hour \| day \| week \| month \| year}`: The partition expiration time. For example, `1 day` indicates the partition expires in 1 day.</li></ul> | No | Yes |
| TIME_ZONE | The time zone to be used for comparing the current time with the partitioning key values of the `date`, `datetime`, and `year` data types. Valid values: <ul><li>`default`: The default value, which indicates that no time zone is configured and the tenant's time zone is used. For types other than the preceding three types, the `time_zone` field must be set to `default`.</li><li>`time_zone`: The custom time zone offset, such as `+8:00`.</li></ul> | No | No |
| BIGINT_PRECISION | The timestamp precision of the `bigint`-typed partitioning key. Valid values: <ul><li>`none`: The default value, which indicates no precision (that is, the partitioning key is not of the `bigint` type). </li><li>`us`: Microsecond precision.</li><li>`ms`: Millisecond precision.</li><li>`s`: Second precision.</li></ul> | No | No |

For more information about the parameters in the CREATE TABLE statement, see [CREATE TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md).

### Restrictions on dynamic partition parameters

* `TIME_UNIT`: When the partitioning key is of the `date` type, the value of the `TIME_UNIT` parameter cannot be `hour`. When the partitioning key is of the `year` type, the value of the `TIME_UNIT` parameter can only be `year`.
* `PRECREATE_TIME`: You can pre-create at most 2,048 partitions.
* `TIME_ZONE`: The `TIME_ZONE` parameter specifies a custom time zone offset. This parameter takes effect only when the partitioning key is of the `date`, `datetime`, or `year` type. For other types, the value of this parameter must be `default`.
* `BIGINT_PRECISION`: You can set the value of this parameter to `us`, `ms`, or `s` only when the partitioning key is of the `bigint` type. For other types, the value of this parameter must be `none`.
* The values of the `TIME_UNIT`, `TIME_ZONE`, and `BIGINT_PRECISION` parameters cannot be modified after they are specified.

## Examples

### Range Columns partitioning example

Create a dynamic partitioned table named `test_tbl1` with RANGE COLUMNS partitioning. Set the dynamic partitioning attributes as follows:

* Partitions are created every hour.
* Pre-create partitions for the next 3 hours.
* Delete partitions whose upper boundary is earlier than 1 day ago.
* Use Beijing Time (UTC+8) to determine time, so that partition boundaries and expiration logic are based on this time zone.
* The partitioning key `col2` is of the `DATETIME` type, so there is no need to configure the timestamp precision for `bigint`.

```sql
CREATE TABLE test_tbl1 (col1 INT, col2 DATETIME)
    DYNAMIC_PARTITION_POLICY(
        ENABLE = true,
        TIME_UNIT = 'hour',
        PRECREATE_TIME = '3 hour',
        EXPIRE_TIME = '1 day',
        TIME_ZONE = '+8:00',
        BIGINT_PRECISION = 'none'
    )
    PARTITION BY RANGE COLUMNS (col2)(
        PARTITION P0 VALUES LESS THAN ('2025-04-15 13:30:00')
    );
```

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The actions of pre-creating partitions and deleting expired partitions after the table is created are not executed immediately. You need to wait for the next automatic scheduling of a dynamic partition management task or manually schedule one. For more information, see <a href="500.dynamic-partition-management-task-of-mysql-mode.md">Dynamic partition management task</a>.</p>
</main>

### List Columns partitioning example

Create a dynamic partitioned table named `test_tbl2` with LIST COLUMNS partitioning. The partitioning key is a string time column in the format `YYYYMMDD`. Set the dynamic partitioning attributes as follows:

* Partition boundaries are divided by day.
* Pre-create partitions for the next 3 days.
* Delete partitions whose upper boundary is earlier than 30 days ago.
* Use Beijing Time (UTC+8) to determine time, so that partition boundaries and expiration logic are based on this time zone.
* The partitioning key `col2` is of the `VARCHAR` type, so there is no need to configure the timestamp precision for `bigint`.

```shell
obclient> CREATE TABLE test_tbl2 (col1 INT, col2 VARCHAR(20))
    DYNAMIC_PARTITION_POLICY(
        ENABLE = true,
        TIME_UNIT = 'day',
        PRECREATE_TIME = '3 day',
        EXPIRE_TIME = '30 day',
        TIME_ZONE = '+8:00',
        BIGINT_PRECISION = 'none'
    )
    PARTITION BY LIST COLUMNS(col2) (
        PARTITION p_20260801 VALUES IN ('20260801')
    );
```
