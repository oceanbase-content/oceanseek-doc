# Automatic partition splitting

In OceanSeek, automatic partition splitting rules are predefined. When data grows to a certain level, the database automatically splits partitions. This enables database tables to scale out automatically as data increases, thereby avoiding load imbalance and performance issues caused by excessive data volume in a single partition.

## Support for automatic partition splitting

Both rowstore and columnstore tables in OceanSeek support automatic partition splitting. The current version supports automatic partition splitting only for primary key tables that use RANGE or RANGE COLUMNS partitioning.

## Limitations and considerations

* Automatic splitting is not supported for LIST or HASH partitioned tables.
* Automatic splitting is not supported for subpartitioned tables.
* The partitioning key of a table undergoing automatic splitting must have the same prefix as its primary key.
* Automatic partition splitting is not supported for tables without a primary key.
* Automatic partition splitting is not supported for heap-organized tables.
* Automatic partition splitting for columnstore replicas is not supported.
* Automatic partition splitting is not supported for tables containing local columnstore indexes.
* If a table belongs to a `TABLEGROUP` that contains multiple tables, automatic partition splitting is not supported; if the `TABLEGROUP` contains only this one table, automatic partition splitting is supported.
* Automatic partition splitting for materialized views is not supported.
* Automatic splitting of full-text indexes is not supported.
* Automatic splitting of spatial indexes is not supported.
* Automatic splitting of vector indexes is not supported.
* OceanSeek supports the [global_index_auto_split_policy](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3350.global_index_auto_split_policy.md) configuration item, which controls whether automatic partitioning is enabled for newly created global indexes. If automatic partitioning is enabled for a new global index, the partitioning rules are regenerated based on the data volume, that is, pre-splitting occurs.

## Table-level automatic partition splitting

You can configure automatic partitioning at the table level by using the `SIZE` clause when you execute the `CREATE TABLE` statement.

### Syntax for creating a table

```sql
CREATE TABLE table_name (column_definition_list, PRIMARY KEY(column_name_list))
    PARTITION BY RANGE [COLUMNS]([column_name_list]) [SIZE('size_value')]
    [(range_partition_list)]
    [table_column_group_option];

column_definition_list:
    column_definition[, column_definition ...]

column_name_list:
    column_name[, column_name ...]

range_partition_list:
    PARTITION partition_name VALUES LESS THAN (value_list)[, PARTITION partition_name VALUES LESS THAN (value_list) ...]

value_list:
    value[, value ...]

table_column_group_option:
    WITH COLUMN GROUP(all columns)
    | WITH COLUMN GROUP(each column)
    | WITH COLUMN GROUP(all columns, each column)
```

#### Parameters

| **Parameter** | **Description** |
| ---------------------- | ---------- |
| table_name | The name of the table. |
| column_definition_list | The list of column definitions, including column names, data types, and constraints. For more information, see [CREATE TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md). |
| PRIMARY KEY | The primary key of the table. |
| PARTITION BY RANGE \[COLUMNS\]\(\[column_name_list\]\) | The pre-partitioning key. When automatic partition splitting is triggered, the specified pre-partitioning key is used as the actual partitioning key (if `column_name_list` is not specified, the primary key is used as the partitioning key).<main id="notice" type='notice'><h4>Notice</h4><p><ul><li>If you specify multiple columns as the pre-partitioning key, you must use <code>PARTITION BY RANGE COLUMNS()</code>.</li><li>The restrictions on pre-partitioning keys are the same as those on partitioning keys.</li></ul></p></main> |
| SIZE('size_value') | (Optional) The threshold for partition splitting, which ranges from 1 MB to +∞. If the `SIZE()` clause is not specified, the value of the `auto_split_tablet_size` parameter at the tenant level is used as the default value. `size_value` can be set to `unlimited`, which indicates that partition splitting is not triggered and no new automatic partition splitting task is scheduled.<main id="notice" type='notice'><h4>Notice</h4><p>In scenarios with large amounts of table data, do not set <code>SIZE</code> to a small value. Otherwise, a large number of partitions will be generated, which will affect the stability of the system and the performance of subsequent partition operations.</p></main> |
| range_partition_list | (Optional) Predefined partitioning positions (partitioning rules).<main id="notice" type='notice'><h4>Notice</h4><p>If you specify predefined partitioning positions, you must specify the pre-partitioning key. Otherwise, an error is returned.</p></main> |
| table_column_group_option | (Optional) The storage format options of the table. The details are as follows:<ul><li>`WITH COLUMN GROUP(all columns)`: Specifies to create a rowstore table.</li><li>`WITH COLUMN GROUP(each column)`: Specifies to create a columnstore table. </li><li>`WITH COLUMN GROUP(all columns, each column)`: Specifies to create a redundant table that combines rowstore and columnstore storage. </li></ul> |

### Syntax for modifying a table

```sql
ALTER TABLE table_name
    PARTITION BY RANGE [COLUMNS]([column_name_list]) [SIZE('size_value')]
    [(range_partition_list)];

column_name_list:
    column_name[, column_name ...]

range_partition_list:
    PARTITION partition_name VALUES LESS THAN (value_list)[, PARTITION partition_name VALUES LESS THAN (value_list) ...]

value_list:
    value[, value ...]
```

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If no partitioning rule is defined when using the <code>ALTER TABLE ... PARTITION BY ...</code> statement, the table's automatic partition attribute will be modified using Online DDL, without affecting the original partition definition.</p>
</main>

#### Parameters

| **Parameter** | **Description** |
| ---------------------- | ---------- |
| column_name_list | The pre-partitioning key of a non-partitioned table. When you execute the `ALTER TABLE` statement to modify the automatic partition splitting attribute of a non-partitioned table, if the pre-partitioning key is specified in the `RANGE()` clause, the corresponding record in the schema is modified; otherwise, the original setting is retained.<main id="notice" type='notice'><h4>Notice</h4><p>If you specify multiple columns as the pre-partitioning key, you must use <code>PARTITION BY RANGE COLUMNS()</code>.</p></main> |
| SIZE('size_value') | (Optional) The threshold for partition splitting. The value ranges from 1 MB to +∞. When `size_value` is set to `unlimited`, partition splitting is not triggered, and no new automatic partition splitting task is scheduled.<main id="notice" type='notice'><h4>Notice</h4><p>In scenarios where the table contains a large amount of data, we recommend that you do not set <code>SIZE</code> to a small value. Otherwise, too many partitions will be generated, which will affect the performance of subsequent partition operations and the stability of the system.</p></main> |
| range_partition_list | (Optional) The partitioning rules. If you do not specify the `SIZE` clause but specify partitioning definitions, only the partitioning rules are modified, and the existing automatic partition splitting definitions are retained. |

## Tenant-level automatic partition splitting

You can configure the `enable_auto_split` and `auto_split_tablet_size` parameters at the tenant level to control automatic partition splitting for tables that meet the criteria within a tenant. If the `SIZE` clause is omitted when creating a table, the system determines whether the table will use automatic partitioning based on the following tenant-level parameters (by default, the primary key column is used as the partitioning key):

* [enable_auto_split](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2350.enable_auto_split.md): A tenant-level parameter that specifies whether to enable automatic partition splitting for the tenant.
* [auto_split_tablet_size](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/450.auto_split_tablet_size.md): A tenant-level parameter that specifies the threshold for triggering automatic partition splitting after automatic partition splitting is enabled for the tenant.

If you omit the `SIZE` clause and set `enable_auto_split` to `true`, automatic partition splitting is enabled only for tables that meet the partitioning criteria. It does not take effect on tables that do not meet the criteria. For example, when you create a subpartitioned table, a table that is not partitioned by RANGE, a table without a primary key, or a table whose partitioning key does not have the same prefix as the primary key, the table is created as a non-automatic partitioned table (if you manually specify special DDL statements for automatic partition splitting, an error is returned).

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>You can query the automatic partition splitting attributes of a table by using the <code>information_schema.TABLES</code> view or the <code>oceanbase.CDB_TABLES</code> view in the sys tenant.</p>
</main>

## Automatic partition splitting behavior

### DDL operations for automatic partition splitting

* Modify partitioning rules: Only changes to partitioning rules that use RANGE partitioning by primary key are supported. Other partitioning rule modifications are not allowed.
* Modify the primary key: The primary key can be modified only if the automatic partitioning key remains a prefix of the primary key.
* Column operations: The restrictions on pre-partitioning keys are the same as those on partitioning keys.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The restrictions on other DDL operations are the same as those on non-automatic partitioned tables.</p>
</main>

### DML behavior

During partition splitting, the source and destination schemas coexist, and DML operations on both partitions are treated as operating on the same dataset. Specifically, writes and queries on the source partition are redirected to the corresponding destination partition, while writes and queries on the destination partition account for forwarded writes from the source partition. The following table outlines the behavior of DML operations in different scenarios.

| Scenario | DML on the source partition (INSERT INTO t1 PARTITION(p0) ...) | DML involving the source partition (SELECT * FROM t1) | DML on the destination partition | DML involving the destination partition |
| ----- | --------------------------------------------------- | ------------------------------------ | ------------------- | ------------------- |
| Before the partition splitting transaction is committed | Normal | Normal | Error. The behavior is the same as that for operations on non-existent partitions. | Not applicable. |
| During partition splitting | May result in an error. The behavior is the same as that for operations on non-existent partitions. | No error. The system retries write and query statements that fail due to stream switching. | Normal | Normal |
| After the partition splitting transaction is committed | Error. The behavior is the same as that for operations on non-existent partitions. | Not applicable. | Normal | Normal |

## Examples

### Example 1: Create a table-level auto-partitioned table

#### Create an auto-partitioned rowstore table

1. Disable automatic partitioning.

    ```sql
    ALTER SYSTEM SET enable_auto_split = FALSE;
    ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>You can execute <code>SHOW PARAMETERS LIKE 'enable_auto_split';</code> to check whether automatic partitioning is enabled.</p>
    </main>

2. Create an auto-partitioned table named `test1_tbl1`. Do not specify a pre-partitioning key, but set the split threshold to 10 GB.

    ```sql
    CREATE TABLE test1_tbl1 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE() SIZE('10GB');
    ```

3. Create an auto-partitioned table named `test1_tbl2`. Specify `col1` as the pre-partitioning key and set the split threshold to 10 GB.

    ```sql
    CREATE TABLE test1_tbl2 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE(col1) SIZE('10GB');
    ```

4. Create an auto-partitioned table named `test1_tbl3`. Do not specify a pre-partitioning key or a split threshold (the default value of `auto_split_tablet_size` will be used).

    ```sql
    CREATE TABLE test1_tbl3 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE();
    ```

5. When creating an auto-partitioned table named `test1_tbl4`, specify `col1, col2` as the pre-partitioning keys and set the split threshold to 10 GB. Also, pre-create the partitioning points `P0`, `P1`, `P2`, and `P3`.

    ```sql
    CREATE TABLE test1_tbl4 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE COLUMNS(col1, col2) SIZE('10GB')
            (PARTITION P0 VALUES LESS THAN (100, MAXVALUE),
             PARTITION P1 VALUES LESS THAN (500, MAXVALUE),
             PARTITION P2 VALUES LESS THAN (800, MAXVALUE),
             PARTITION P3 VALUES LESS THAN (MAXVALUE, MAXVALUE));
    ```

6. Query the auto-partitioning attributes of the table.

    ```sql
    SELECT TABLE_SCHEMA, TABLE_NAME, AUTO_SPLIT, AUTO_SPLIT_TABLET_SIZE
    FROM information_schema.TABLES
    WHERE TABLE_NAME LIKE "test1%"
    ORDER BY TABLE_NAME;
    ```

    The returned result is as follows:

    ```shell
    +--------------+------------+------------+------------------------+
    | TABLE_SCHEMA | TABLE_NAME | AUTO_SPLIT | AUTO_SPLIT_TABLET_SIZE |
    +--------------+------------+------------+------------------------+
    | db_test      | test1_tbl1 | TRUE       |            10737418240 |
    | db_test      | test1_tbl2 | TRUE       |            10737418240 |
    | db_test      | test1_tbl3 | TRUE       |              134217728 |
    | db_test      | test1_tbl4 | TRUE       |            10737418240 |
    +--------------+------------+------------+------------------------+
    4 rows in set
    ```

#### Create an auto-partitioned columnstore table

1. Create an auto-partitioned columnstore table named `test1_cg1`. Do not specify a pre-partitioning key, but set the split threshold to 10 GB.

    ```shell
    obclient> CREATE TABLE test1_cg1 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1))
        PARTITION BY RANGE() SIZE('10GB')
        WITH COLUMN GROUP (each column);
    ```

2. Create an auto-partitioned hybrid rowstore-columnstore table named `test1_cg2`. Do not specify a pre-partitioning key, but set the split threshold to 10 GB.

    ```shell
    obclient> CREATE TABLE test1_cg2 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1))
        PARTITION BY RANGE() SIZE('10GB')
        WITH COLUMN GROUP (all columns, each column);
    ```

### Example 2: Modify the auto-partitioning attributes of a table

1. Create an auto-partitioned table named `test2_tbl1`, specifying the pre-partitioning key as `col1` and the split threshold as 10 GB.

    ```sql
    CREATE TABLE test2_tbl1 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE(col1) SIZE('10GB');
    ```

2. Modify the auto-partitioning threshold for table `test2_tbl1` to 1 GB.

    ```sql
    ALTER TABLE test2_tbl1 PARTITION BY RANGE() SIZE('1GB');
    ```

    or

    ```sql
    ALTER TABLE test2_tbl1 PARTITION BY RANGE(col1) SIZE('1GB');
    ```

3. Create an auto-partitioned table named `test2_tbl2`, specifying the pre-partitioning key as `col1` and the split threshold as 10 GB. Also, pre-create the partitioning points `p0` (for rows with values less than 100), `p1` (for rows with values greater than or equal to 100 and less than 200), and `p_max` (for rows greater than or equal to 200).

    ```sql
    CREATE TABLE test2_tbl2 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE(col1) SIZE('10GB')
            (PARTITION p0 VALUES LESS THAN(100),
             PARTITION p1 VALUES LESS THAN(200),
             PARTITION p_max VALUES LESS THAN (MAXVALUE));
    ```

4. Modify the auto-partitioning threshold for table `test2_tbl2` to 5 GB, and change the pre-created partitioning points to `p0` (for rows with values less than 300) and `p_max` (for rows greater than or equal to 300).

    ```sql
    ALTER TABLE test2_tbl2
        PARTITION BY RANGE(col1) SIZE('5GB')
            (PARTITION p0 VALUES LESS THAN(300),
             PARTITION p_max VALUES LESS THAN (MAXVALUE));
    ```

5. Create an auto-partitioned table named `test2_tbl3`, specifying the pre-partitioning key as `col1` and the split threshold as 10 GB.

    ```sql
    CREATE TABLE test2_tbl3 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE(col1) SIZE('10GB');
    ```

6. Disable auto-partitioning for table `test2_tbl3`. This modification does not affect existing partitions, and no new auto-partitions will be scheduled for splitting.

    ```sql
    ALTER TABLE test2_tbl3 PARTITION BY RANGE() SIZE('unlimited');
    ```

7. Create an auto-partitioned table named `test2_tbl4`, specifying the pre-partitioning key as `col1` and the split threshold as 10 GB.

    ```sql
    CREATE TABLE test2_tbl4 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE(col1) SIZE('10GB');
    ```

8. Change the pre-partitioning key for table `test2_tbl4` from `col1` to `col1,col2`.

    ```sql
    ALTER TABLE test2_tbl4 PARTITION BY RANGE COLUMNS(col1,col2) SIZE('10GB');
    ```

9. Create a non-partitioned table named `test2_tbl5`.

    ```sql
    CREATE TABLE test2_tbl5 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2));
    ```

10. Change table `test2_tbl5` to an auto-partitioned table without specifying the `SIZE` clause. The split threshold will use the default value of `auto_split_tablet_size`.

    ```sql
    ALTER TABLE test2_tbl5 PARTITION BY RANGE COLUMNS(col1);
    ```

11. Query the auto-partitioning attributes of the table.

    ```sql
    SELECT TABLE_SCHEMA, TABLE_NAME, AUTO_SPLIT, AUTO_SPLIT_TABLET_SIZE
    FROM information_schema.TABLES
    WHERE TABLE_NAME LIKE "test2%"
    ORDER BY TABLE_NAME;
    ```

    The query result is as follows:

    ```shell
    +--------------+------------+------------+------------------------+
    | TABLE_SCHEMA | TABLE_NAME | AUTO_SPLIT | AUTO_SPLIT_TABLET_SIZE |
    +--------------+------------+------------+------------------------+
    | db_test      | test2_tbl1 | TRUE       |             1073741824 |
    | db_test      | test2_tbl2 | TRUE       |             5368709120 |
    | db_test      | test2_tbl3 | FALSE      |                      0 |
    | db_test      | test2_tbl4 | TRUE       |            10737418240 |
    | db_test      | test2_tbl5 | TRUE       |              134217728 |
    +--------------+------------+------------+------------------------+
    5 rows in set
    ```

### Example 3: Create tables with automatic partitioning enabled

1. Enable automatic partitioning.

    ```sql
    ALTER SYSTEM SET enable_auto_split = TRUE;
    ```

2. Create a non-partitioned table named `test3_tbl1`. Because all non-partitioned tables in the tenant are automatically partitioned by using the `SIZE` partitioning method, the following normal table creation statement will automatically partition the table. The tenant-level parameter (128 MB by default) will be used as the split threshold.

    ```sql
    CREATE TABLE test3_tbl1 (col1 INT, col2 INT, PRIMARY KEY(col1));
    ```

3. Create a non-partitioned table named `test3_tbl2` with automatic partitioning. No partitioning key is specified, so the primary key is used by default as the partitioning key.

    ```sql
    CREATE TABLE test3_tbl2 (col1 INT, col2 INT, PRIMARY KEY(col1))
        PARTITION BY RANGE ();
    ```

4. Create a non-partitioned table named `test3_tbl3` with automatic partitioning (split threshold set to 1024 MB using user configuration).

    ```sql
    CREATE TABLE test3_tbl3 (col1 INT, col2 INT, PRIMARY KEY(col1))
        PARTITION BY RANGE () SIZE('1024MB');
    ```

5. Create a non-auto-partitioned table named `test3_tbl4`.

    ```sql
    CREATE TABLE test3_tbl4 (col1 INT, col2 INT, PRIMARY KEY(col1))
        PARTITION BY RANGE () SIZE('unlimited');
    ```

6. A table without a primary key does not meet the requirements for automatic partitioning. Even if `enable_auto_split = true`, automatic partitioning will not be enabled.

    ```sql
    CREATE TABLE test3_tbl5 (col1 INT, col2 INT);
    ```

7. A table without a primary key does not meet the requirements for automatic partitioning. Manually enabling automatic partitioning will result in an error.

    ```sql
    CREATE TABLE test3_tbl6 (col1 INT, col2 INT)
        PARTITION BY RANGE ();
    ```

    The query result is as follows:

    ```shell
    ERROR 1235 (0A000): auto partitioned table without primary key is not supported
    ```

8. View the automatic partitioning attributes of the table.

    ```sql
    SELECT TABLE_SCHEMA, TABLE_NAME, AUTO_SPLIT, AUTO_SPLIT_TABLET_SIZE
    FROM information_schema.TABLES
    WHERE TABLE_NAME LIKE "test3%"
    ORDER BY TABLE_NAME;
    ```

    The query result is as follows:

    ```shell
    +--------------+------------+------------+------------------------+
    | TABLE_SCHEMA | TABLE_NAME | AUTO_SPLIT | AUTO_SPLIT_TABLET_SIZE |
    +--------------+------------+------------+------------------------+
    | db_test      | test3_tbl1 | TRUE       |              134217728 |
    | db_test      | test3_tbl2 | TRUE       |              134217728 |
    | db_test      | test3_tbl3 | TRUE       |             1073741824 |
    | db_test      | test3_tbl4 | FALSE      |                      0 |
    | db_test      | test3_tbl5 | FALSE      |                      0 |
    +--------------+------------+------------+------------------------+
    5 rows in set
    ```

### Example 4: Enable automatic partitioning for global indexes

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For tables with automatic partitioning enabled, even if the parameter <a href="../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3350.global_index_auto_split_policy.md">global_index_auto_split_policy</a> is not enabled, any created global indexes will still use automatic partitioning.</p>
</main>

1. Create an auto-partitioned table named `test4_tbl1` (with a split threshold of 1024 MB, using user configuration).

    ```sql
    CREATE TABLE test4_tbl1 (col1 INT, col2 INT, col3 INT, PRIMARY KEY(col1))
        PARTITION BY RANGE () SIZE('1024MB');
    ```

2. Create a global index named `idx1_test4_tbl1` on the `test4_tbl1` table.

    ```sql
    CREATE INDEX idx1_test4_tbl1 ON test4_tbl1 (col2) GLOBAL;
    ```

3. Create a new global index with the auto-partitioning feature enabled.

    ```sql
    ALTER SYSTEM SET global_index_auto_split_policy = 'ALL';
    ```

4. Create a non-auto-partitioned partitioned table named `test4_tbl2`.

    ```sql
    CREATE TABLE test4_tbl2(col1 INT, col2 INT, col3 INT, PRIMARY KEY(col1)) 
        PARTITION BY RANGE(col1)
        (PARTITION p0 VALUES LESS THAN(100),
        PARTITION p1 VALUES LESS THAN(200),
        PARTITION p2 VALUES LESS THAN(300));
    ```

5. Create a global index named `idx1_test4_tbl2` on the `test4_tbl2` table.

    ```sql
    CREATE INDEX idx1_test4_tbl2 ON test4_tbl2 (col2) GLOBAL;
    ```
