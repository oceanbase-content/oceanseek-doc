# Manually split a partition

OceanSeek allows you to manually split partitions in a partitioned table, that is, splitting an existing partition into multiple partitions. You can specify the partition to be split and the split points for the new partitions when you run the manual partition-splitting command, so that you can adjust partitions based on your requirements and data growth.

## Support for manual partition splitting

Both rowstore and columnstore tables in OceanSeek support manual partition splitting. The current version supports manual partition splitting only for primary partitioned tables that use RANGE or RANGE COLUMNS partitioning, and only allows splitting one partition into multiple partitions.

## Limitations and considerations

* You cannot manually split a LIST or HASH partitioned table.
* You cannot manually split a subpartitioned table.
* The partitioning key of the table being manually split must have the same prefix as its primary key.
* You cannot manually split a table without a primary key.
* You cannot manually split a heap-organized table.
* You cannot manually split a columnstore replica.
* You cannot manually split a table that contains a columnstore local index.
* If the `TABLEGROUP` containing the table has multiple tables, manual partition splitting is not supported; if the `TABLEGROUP` contains only this table, manual partition splitting is supported.
* You cannot manually split a materialized view.
* You cannot manually split a global index.
* You cannot manually split a full-text index.
* You cannot manually split a spatial index.
* You cannot manually split a vector index.
* You cannot separately split the partition of a local index or a LOB table.

## Syntax for manual partition splitting

```sql
ALTER TABLE table_name
    REORGANIZE PARTITION partition_name INTO (
        PARTITION split_partition_name VALUES LESS THAN (value)
        [, PARTITION split_partition_name VALUES LESS THAN (value) ...]
         , PARTITION split_partition_name VALUES LESS THAN (source_value));
```

### Parameters

| **Parameter** | **Description** |
| ---------------------- | ---------- |
| table_name | The name of the table. |
| partition_name | The name of the partition to be split. |
| split_partition_name | The name of the new partition. |
| value | The split point of the partition (the value range).<main id="notice" type='notice'><h4>Notice</h4><p>When manually splitting a RANGE partition, ensure that the <code>value</code> definitions of the partitions are in ascending order and that the ranges are the same as the original partition.</p></main> |
| source_value | The original boundary of the partition to be split (the value range). That is, it defines the split of the last partition, and its <code>value</code> is the same as the <code>value</code> of the original partition. |

## Examples

### Example 1: Manually split a rowstore partition

Create a primary partitioned table `test_tbl1` with RANGE partitions.

```sql
CREATE TABLE test_tbl1(col1 INT, col2 INT, PRIMARY KEY(col1))
    PARTITION BY RANGE(col1)
    (PARTITION p0 VALUES LESS THAN(100),
     PARTITION p1 VALUES LESS THAN(200),
     PARTITION p2 VALUES LESS THAN(300),
     PARTITION p_max VALUES LESS THAN (MAXVALUE));
```

* Split the `p0` partition of the `test_tbl1` table into three new partitions at the rows corresponding to the values `30` and `60`. After splitting, the original `p0` partition is divided into three new partitions: `p0_1`, `p0_2`, and `p0`.

    ```sql
    ALTER TABLE test_tbl1
        REORGANIZE PARTITION p0 INTO (
            PARTITION p0_1 VALUES LESS THAN (30),
            PARTITION p0_2 VALUES LESS THAN (60),
            PARTITION p0 VALUES LESS THAN (100));
    ```

* Split the `p_max` partition of the `test_tbl1` table into three new partitions at the rows corresponding to the values `400` and `500`. After splitting, the original `p_max` partition is divided into three new partitions: `p_max_1`, `p_max_2`, and `p_max_3`.

    ```sql
    ALTER TABLE test_tbl1
        REORGANIZE PARTITION p_max INTO (
            PARTITION p_max_1 VALUES LESS THAN (400),
            PARTITION p_max_2 VALUES LESS THAN (500),
            PARTITION p_max_3 VALUES LESS THAN (MAXVALUE));
    ```

* View the structure and definition of the `test_tbl1` table.

    ```sql
    SHOW CREATE TABLE test_tbl1;
    ```

    The result is as follows:

### Example 2: Manually split a columnstore partition

Create a columnstore table `test2_tbl2` with RANGE partitions.

```shell
obclient> CREATE TABLE test2_tbl2(col1 INT, col2 INT, col3 INT, PRIMARY KEY(col1))
    PARTITION BY RANGE(col1)
    (PARTITION p0 VALUES LESS THAN(50),
     PARTITION p1 VALUES LESS THAN(100),
     PARTITION p_max VALUES LESS THAN (MAXVALUE))
    WITH COLUMN GROUP (each column);
```

* Split the `p0` partition of the `test2_tbl2` table into two new partitions at the row corresponding to the value `30`. After the split, the original partition `p0` is divided into two new partitions `p0_1` and `p0_2`.

    ```shell
    obclient> ALTER TABLE test2_tbl2
        REORGANIZE PARTITION p0 INTO (
            PARTITION p0_1 VALUES LESS THAN (30),
            PARTITION p0_2 VALUES LESS THAN (50));
    ```

* View the structure and definition of the `test2_tbl2` table.

    ```shell
    obclient> SHOW CREATE TABLE test2_tbl2;
    ```

    The result is as follows:

    ```shell
    +-----------+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
    ```
