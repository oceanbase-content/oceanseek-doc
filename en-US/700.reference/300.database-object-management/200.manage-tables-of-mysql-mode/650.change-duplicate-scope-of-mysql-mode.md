# Change the attribute of a replicated table

In OceanSeek, you can use the `DUPLICATE_SCOPE` parameter to specify the attribute of a replicated table. After a table is created, you can change its attribute by modifying the value of the `DUPLICATE_SCOPE` parameter.

## Limitations and considerations

* When converting a replicated table, if the current tenant has triggered a load balancing task due to scaling, zone change, or locality change, the conversion task must wait for the current balancing task to complete.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>The conversion of a replicated table is asynchronous. After manually changing the <code>DUPLICATE_SCOPE</code>, you must wait for the background partition balancing task to complete before the table can be used as a table with the target attribute. For more information about partition balancing, see Intra-tenant balancing.</p>
    </main>

* Replicated tables and table groups are mutually exclusive. When converting a regular table to a replicated table, if the regular table belongs to a table group, it cannot be converted.

* The conversion of a replicated table depends on the tenant's load balancing and transfer capabilities. If any of the tenant-level parameters `enable_rebalance`, `enable_transfer`, or `enable_rereplication` is set to `false`, the conversion operation cannot proceed. If you change the value of `enable_rebalance` or `enable_transfer` to `false` while there is a running replication table conversion task, the corresponding task will be canceled.

## Prerequisites

Before converting a replicated table, ensure the following parameters are set to `True`:

* `enable_rebalance`

  The tenant-level parameter `enable_rebalance` controls whether to perform load balancing between tenants in the sys tenant and within tenants in user tenants. The default value is `True`. For detailed information and settings, see [enable_rebalance](../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2800.enable_rebalance.md).

* `enable_transfer`

  The tenant-level parameter `enable_transfer` controls whether to enable transfers within a tenant. The default value is `True`. For detailed information and settings, see [enable_transfer](../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3000.enable_transfer.md).

* `enable_rereplication`

  The cluster-level parameter `enable_rereplication` is the master switch for automatic migration and replication of log stream replicas. The default value is `True`. For detailed information and settings, see [enable_rereplication](../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/8000.enable_rereplication.md).

## Syntax for changing the attribute of a replicated table

The SQL statement for changing the attribute of a replicated table is as follows:

```sql
ALTER TABLE table_name DUPLICATE_SCOPE= 'none | cluster';
```

In the statement:

* `none`: converts the current table into a regular table.
* `cluster`: converts the current table into a replicated table.

## Example

The following command demonstrates how to convert a replicated table into a regular table.

1. Create a replicated table named `tbl1`.

    ```sql
    obclient [test]> CREATE TABLE tbl1 (c1 int,c2 int) DUPLICATE_SCOPE= 'cluster';
    ```

2. Convert the replicated table to a regular table.

    ```sql
    ALTER TABLE tbl1 DUPLICATE_SCOPE= 'none';
    ```

    <main id="notice" type='notice'>
      <h4>Note</h4>
      <p>The preceding SQL statement immediately returns success after modifying the table attribute, but the actual conversion of the replicated table is performed asynchronously by background threads.</p>
    </main>

3. View the replication attributes of the table.

    You can view the current replication attributes of a table and its log stream ID through the `oceanbase.DBA_OB_TABLE_LOCATIONS` view. A `DUPLICATE_SCOPE` column value of `CLUSTER` indicates it is a replicated table, while `NONE` indicates it is a regular table.

    ```sql
    SELECT database_name, table_name, table_id, tablet_id, ls_id, role, duplicate_scope
    FROM oceanbase.DBA_OB_TABLE_LOCATIONS
    WHERE table_name = 'tbl1';
    ```

    The query result is as follows:

    ```shell
    +---------------+------------+----------+-----------+-------+--------+-----------------+
    | database_name | table_name | table_id | tablet_id | ls_id | role   | duplicate_scope |
    +---------------+------------+----------+-----------+-------+--------+-----------------+
    | test          | tbl1       |   500011 |    200002 |  1002 | LEADER | NONE            |
    +---------------+------------+----------+-----------+-------+--------+-----------------+
    1 row in set
    ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>You can use the following steps to check whether the distribution of partition replicas meets the target attribute after a replicated table is converted.</p>
    </main>

4. Check the conversion progress of the replicated table.

   1. View the properties of the log stream.

       All replicated tables in a tenant are placed on a dedicated log stream (broadcast log stream) that carries replicated tables. You can view the properties of a log stream through the `oceanbase.DBA_OB_LS` view. A `FLAG` column containing `DUPLICATE` indicates it is a broadcast log stream. If `FLAG` is empty or does not contain `DUPLICATE`, it indicates it is a regular log stream.

       ```sql
       SELECT * FROM oceanbase.DBA_OB_LS WHERE LS_ID = 1002;
       ```

       The query result is as follows:

       ```shell
       +-------+--------+--------------+---------------+-------------+---------------------+----------+---------------------+---------------------+-----------+-----------+
       | LS_ID | STATUS | PRIMARY_ZONE | UNIT_GROUP_ID | LS_GROUP_ID | CREATE_SCN          | DROP_SCN | SYNC_SCN            | READABLE_SCN        | FLAG      | UNIT_LIST |
       +-------+--------+--------------+---------------+-------------+---------------------+----------+---------------------+---------------------+-----------+-----------+
       |  1002 | NORMAL | zone1        |             0 |           0 | 1713164377091593001 |     NULL | 1713171198496433000 | 1713171198496433000 | DUPLICATE |           |
       +-------+--------+--------------+---------------+-------------+---------------------+----------+---------------------+---------------------+-----------+-----------+
       1 row in set
       ```

   2. Determine whether a replicated table conversion task needs to be generated.

       Replicated table conversion tasks are generated by the background load balancing and transfer modules. You can use the following statement to quickly determine whether a replicated table conversion task needs to be generated. Here, `DUPLICATE_SCOPE` is an attribute of the table, and `FLAG` is an attribute of the LS to which the current table's `tablet` belongs. If `FLAG` contains `DUPLICATE`, it indicates a broadcast log stream.

       ```sql
       SELECT A.duplicate_scope, B.flag
       FROM oceanbase.DBA_OB_TABLE_LOCATIONS AS A JOIN oceanbase.DBA_OB_LS AS B ON A.ls_id = B.ls_id
       WHERE A.table_name = 'tbl1'
       AND A.role = 'LEADER';
       ```

       The query result is as follows:

       ```shell
       +-----------------+-----------+
       | duplicate_scope | flag      |
       +-----------------+-----------+
       | NONE            | DUPLICATE |
       +-----------------+-----------+
       1 row in set
       ```

       The return information is explained as follows:

       * `DUPLICATE_SCOPE` is `NONE` and `FLAG` contains `DUPLICATE`: The non-replicated table is on the broadcast log stream. You need to generate a task to convert the replicated table to a normal table, which transfers the non-replicated table from the broadcast log stream to a normal log stream.
       * `DUPLICATE_SCOPE` is `NONE` and `FLAG` does not contain `DUPLICATE`: The replicated table is on a normal log stream. You need to generate a task to convert the normal table to a replicated table, which transfers the replicated table from the normal log stream to the broadcast log stream.

   3. Immediately generate a conversion task.

       You can temporarily reduce the parameter `partition_balance_schedule_interval` to immediately generate a conversion task.

       ```sql
       ALTER SYSTEM SET partition_balance_schedule_interval = '30s';
       ```

   4. View the replicated table conversion task.

       The task generated by the replicated table conversion can be viewed through the related views `DBA/CDB_OB_BALANCE_JOB_HISTORY` and `DBA/CDB_OB_BALANCE_JOBS`.

       1. View the execution status of historical conversion tasks.

           If there is no historical record, the task may be in progress or not yet generated.

           ```sql
           SELECT * FROM oceanbase.DBA_OB_BALANCE_JOB_HISTORY;
           ```

           The query result is as follows:

           ```shell
           +--------+----------------------------+----------------------------+-------------------+-------------------+-----------------+-------------------------+-----------+---------+
           | JOB_ID | CREATE_TIME                | FINISH_TIME                | BALANCE_STRATEGY  | JOB_TYPE          | TARGET_UNIT_NUM | TARGET_PRIMARY_ZONE_NUM | STATUS    | COMMENT |
           +--------+----------------------------+----------------------------+-------------------+-------------------+-----------------+-------------------------+-----------+---------+
           | 777854 | 2024-04-15 16:54:29.220400 | 2024-04-15 16:54:39.231516 | partition balance | PARTITION_BALANCE |               1 |                       1 | COMPLETED | NULL    |
           +--------+----------------------------+----------------------------+-------------------+-------------------+-----------------+-------------------------+-----------+---------+
           1 row in set
           ```

       2. View the execution status of the current balancing task.

          ```sql
          SELECT * FROM oceanbase.DBA_OB_BALANCE_JOBS;
          ```

       3. View the subtasks corresponding to the conversion task (including partition lists).

          Insert the `job_id` from the above task into the following SQL statement:

          ```sql
          SELECT * FROM oceanbase.DBA_OB_BALANCE_TASKS WHERE JOB_ID = xxxx;
          ```

          ```sql
          SELECT * FROM oceanbase.DBA_OB_BALANCE_TASK_HISTORY WHERE JOB_ID = xxxx;
          ```

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p><ul><li>If other <code>BALANCE_JOB</code> tasks are running in the <code>DBA_OB_BALANCE_JOBS</code> view, you need to wait for the current task to complete before the partition balancing task is scheduled.</li><li>If no corresponding replication table conversion task appears in the aforementioned <code>BALANCE</code> related views, it may mean the corresponding <code>BALANCE_JOB</code> has not yet been generated. You need to wait or temporarily reduce the parameter <code>partition_balance_schedule_interval</code>.</li><li>If no conversion task is generated for a long time, check load balancing-related parameters such as <code>enable_rebalance</code>, <code>enable_transfer</code>, <code>balancer_idle_time</code>, and <code>enable_rereplication</code>, and verify that Transfer is not disabled.</li></ul></p>
</main>
