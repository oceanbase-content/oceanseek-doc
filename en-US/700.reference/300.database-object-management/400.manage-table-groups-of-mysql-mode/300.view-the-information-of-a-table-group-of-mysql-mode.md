# View table group information

After a table group is created, you can view its information, including the `SHARDING` attribute, the tables within the group, the creation time of the table group, and the location information of the tables in the group.

## View the SHARDING attribute of a table group

### View table group attributes and table partition information by using views

You can query the `CDB_OB_TABLEGROUPS` view in the system tenant and the `DBA_OB_TABLEGROUPS` view in a user tenant for the attributes of a table group and the partition information about tables in the table group. Sample statements are as follows:

* System tenant

  ```sql
  SELECT * FROM oceanbase.CDB_OB_TABLEGROUPS WHERE tablegroup_name = 'tblgroup1';
  ```

  The query result is as follows:

  ```shell
  +-----------+-----------------+-------------------+----------------------+-----------------+------------------------+------------------------+---------------------------+----------+
  | TENANT_ID | TABLEGROUP_NAME | PARTITIONING_TYPE | SUBPARTITIONING_TYPE | PARTITION_COUNT | DEF_SUBPARTITION_COUNT | PARTITIONING_KEY_COUNT | SUBPARTITIONING_KEY_COUNT | SHARDING |
  +-----------+-----------------+-------------------+----------------------+-----------------+------------------------+------------------------+---------------------------+----------+
  |      1002 | tblgroup1       | NONE              | NONE                 |            NULL |                   NULL |                   NULL |                      NULL | ADAPTIVE |
  |      1004 | TBLGROUP1       | NONE              | NONE                 |            NULL |                   NULL |                   NULL |                      NULL | NONE     |
  +-----------+-----------------+-------------------+----------------------+-----------------+------------------------+------------------------+---------------------------+----------+
  2 rows in set
  ```

* User tenant

  ```sql
  SELECT * FROM oceanbase.DBA_OB_TABLEGROUPS WHERE tablegroup_name = 'tblgroup1';
  ```

  The query result is as follows:

  ```shell
  +-----------------+-------------------+----------------------+-----------------+------------------------+------------------------+---------------------------+----------+
  | TABLEGROUP_NAME | PARTITIONING_TYPE | SUBPARTITIONING_TYPE | PARTITION_COUNT | DEF_SUBPARTITION_COUNT | PARTITIONING_KEY_COUNT | SUBPARTITIONING_KEY_COUNT | SHARDING |
  +-----------------+-------------------+----------------------+-----------------+------------------------+------------------------+---------------------------+----------+
  | tblgroup1       | NONE              | NONE                 |            NULL |                   NULL |                   NULL |                      NULL | ADAPTIVE |
  +-----------------+-------------------+----------------------+-----------------+------------------------+------------------------+---------------------------+----------+
  1 row in set 
  ```

Fields in the query result are described as follows:

* `TENANT_ID`: The ID of the tenant to which the table group belongs.

* `TABLEGROUP_NAME`: The name of the table group.

* `PARTITIONING_TYPE`, `SUBPARTITIONING_TYPE`, `PARTITION_COUNT`, `DEF_SUBPARTITION_COUNT`, `PARTITIONING_KEY_COUNT`, `SUBPARTITIONING_KEY_COUNT`: The attributes of a table group in the partition definition. In the current version, the value of these attributes is `NONE` or `NULL`.

* `SHARDING`: The `SHARDING` attribute of the table group.

  * For a table group with the `SHARDING` attribute set to `NONE`, all partitions of all tables in the table group are aggregated on the same server, and no limitations are imposed on tables to be added to the table group.

  * For a table group with the `SHARDING` attribute set to `PARTITION`, the data of each table in the table group is scattered by partition. For a subpartitioned table in the table group, all subpartitions in each partition are aggregated together.

    Partition requirement: A table to be added to the table group must have the same partition definition as existing tables in the table group, including the partitioning type, partition count, and partition value.

  * For a table group with the `SHARDING` attribute set to `ADAPTIVE`, the data of each table in the table group is adaptively scattered. In other words, data in partitioned tables is scattered by partition, and data in subpartitioned tables is scattered by subpartition in each partition.

    Partition requirement: A table to be added to the table group must have the same partition and subpartition definitions as existing tables in the table group, including the partitioning type, partition count, and partition value.

### View table group attributes and the databases of tables by using the SHOW TABLEGROUPS statement

You can also execute the `SHOW TABLEGROUPS` statement in the system tenant or a user tenant to view the `SHARDING` attribute of a table group and the databases to which tables in the table group belong. A sample statement is as follows:

```sql
SHOW TABLEGROUPS WHERE tablegroup_name = 'tblgroup1';
```

The query result is as follows:

```shell
+-----------------+------------+---------------+----------+
| Tablegroup_name | Table_name | Database_name | Sharding |
+-----------------+------------+---------------+----------+
| tblgroup1       | tbl3       | test          | ADAPTIVE |
+-----------------+------------+---------------+----------+
1 row in set
```

Fields in the query result are described as follows:

* `Tablegroup_name`: The name of the table group.

* `Table_name`: The name of the table.

* `Database_name`: The name of the database to which the table belongs.

* `Sharding`: The `SHARDING` attribute of the table group. Valid values of the `SHARDING` attribute are as follows:

  * For a table group with the `SHARDING` attribute set to `NONE`, all partitions of all tables in the table group are aggregated on the same server, and no limitations are imposed on tables to be added to the table group.

  * For a table group with the `SHARDING` attribute set to `PARTITION`, the data of each table in the table group is scattered by partition. For a subpartitioned table in the table group, all subpartitions in each partition are aggregated together.

    Partition requirement: A table to be added to the table group must have the same partition definition as existing tables in the table group, including the partitioning type, partition count, and partition value.

  * For a table group with the `SHARDING` attribute set to `ADAPTIVE`, the data of each table in the table group is adaptively scattered. In other words, data in partitioned tables is scattered by partition, and data in subpartitioned tables is scattered by subpartition in each partition.

    Partition requirement: A table to be added to the table group must have the same partition and subpartition definitions as existing tables in the table group, including the partitioning type, partition count, and partition value.

## View tables in a table group

You can query the `CDB_OB_TABLEGROUP_TABLES` view in the system tenant or the `DBA_OB_TABLEGROUP_TABLES` view in a user tenant for the tables in a table group and the databases to which the tables belong. Sample statements are as follows:

* System tenant

  ```sql
  SELECT * FROM oceanbase.CDB_OB_TABLEGROUP_TABLES WHERE tablegroup_name = 'tblgroup1';
  ```

  The query result is as follows:

  ```shell
  +-----------+-----------------+-------+------------+----------+
  | TENANT_ID | TABLEGROUP_NAME | OWNER | TABLE_NAME | SHARDING |
  +-----------+-----------------+-------+------------+----------+
  |      1002 | tblgroup1       | test  | tbl3       | ADAPTIVE |
  |      1004 | TBLGROUP1       | SYS   | TBL3       | NONE     |
  +-----------+-----------------+-------+------------+----------+
  2 rows in set
  ```

* User tenant

  ```sql
  SELECT * FROM oceanbase.DBA_OB_TABLEGROUP_TABLES WHERE tablegroup_name = 'tblgroup1';
  ```

  The query result is as follows:

  ```shell
  +-----------------+-----------+------------+----------+
  | TABLEGROUP_NAME | OWNER     | TABLE_NAME | SHARDING |
  +-----------------+-----------+------------+----------+
  | tblgroup1       | test      | tbl3       | ADAPTIVE |
  +-----------------+-----------+------------+----------+
  1 row in set
  ```

Fields in the query result are described as follows:

* `TENANT_ID`: The ID of the tenant to which the table group belongs.

* `TABLEGROUP_NAME`: The name of the table group.

* `OWNER`: The name of the database to which the table belongs.

* `TABLE_NAME`: The name of the table.

* `SHARDING`: The `SHARDING` attribute of the table group. Valid values of the `SHARDING` attribute are as follows:

  * For a table group with the `SHARDING` attribute set to `NONE`, all partitions of all tables in the table group are aggregated on the same server, and no limitations are imposed on tables to be added to the table group.

    Partition requirement: A table to be added to the table group must have the same partition and subpartition definitions as existing tables in the table group, including the partitioning type, partition count, and partition value.

## View the creation time of a table group

You can query the `CDB_OBJECTS` view in the system tenant or the `DBA_OBJECTS` view in a user tenant for information such as the creation time and last DDL operation of a table group. Sample statements are as follows:

* System tenant

  ```sql
  SELECT OBJECT_NAME,CREATED, LAST_DDL_TIME FROM oceanbase.CDB_OBJECTS WHERE object_name = 'tblgroup1';
  ```

  The query result is as follows:

  ```shell
  +-------------+---------------------+---------------------+
  | OBJECT_NAME | CREATED             | LAST_DDL_TIME       |
  +-------------+---------------------+---------------------+
  | tblgroup1   | 2023-06-27 14:58:53 | 2023-06-27 15:15:54 |
  | TBLGROUP1   | 2023-06-27 15:25:30 | 2023-06-27 15:25:30 |
  +-------------+---------------------+---------------------+
  2 rows in set
  ```

* User tenant

  ```sql
  SELECT OBJECT_NAME,CREATED, LAST_DDL_TIME FROM oceanbase.DBA_OBJECTS WHERE object_name = 'tblgroup1'; 
  ```

  The query result is as follows:

  ```shell
  +-------------+---------------------+---------------------+
  | OBJECT_NAME | CREATED             | LAST_DDL_TIME       |
  +-------------+---------------------+---------------------+
  | tblgroup1   | 2023-06-27 14:58:53 | 2023-06-27 15:15:54 |
  +-------------+---------------------+---------------------+
  1 row in set
  ```

Fields in the query result are described as follows:

* `OBJECT_NAME`: The object name, which is the name of the queried table group.
* `CREATED`: The time when the table group was created.
* `LAST_DDL_TIME`: The time when the last DDL operation was performed.

Fields in the query result are described as follows:

* `DATABASE_NAME`: The name of the database to which the table belongs.

* `TABLE_NAME`: The name of the table.

* `TABLE_ID`: The ID of the table.

* `TABLE_TYPE`: The type of the table. Valid values:

  * `USER TABLE`: A user table.
  * `SYSTEM TABLE`: A system table, which is created by the system.
  * `INDEX`: An index table.
  * `LOB AUX TABLE`: A LOB auxiliary table, which is created by the system to implement LOB columns.

* `PARTITION_NAME`: The name of the partition. The default value is `NULL` for non-partitioned tables.

* `SUBPARTITION_NAME`: The name of the subpartition. The value `NULL` indicates that no subpartition exists.

* `INDEX_NAME`: The name of the index table. For tables other than index tables, the value is `NULL`.

* `DATA_TABLE_ID`: The ID of the primary table. If the table is not an index table or LOB table, the value is `NULL`.

* `TABLET_ID`: The tablet ID of the partition.
  
* `LS_ID`: The ID of the log stream to which the table belongs.

* `ZONE`: The zone where the replica is located.

* `SVR_IP`: The IP address of the OBServer node where the replica is located.

* `SVR_PORT`: The port of the OBServer node where the replica is located.

* `ROLE`: The role of the log stream replica.

* `REPLICA_TYPE`: The type of the log stream replica. Valid values:

  * `FULL`: A full-featured replica.
  * `READONLY`: A read-only replica.
  * `COLUMNSTORE`: A columnstore replica.

* `OBJECT_ID`: The object ID. If the table is a non-partitioned table, the value is the ID of the table. If the table is a partitioned table, this field shows the ID of each partition in the table.

* `TABLEGROUP_NAME`: The name of the queried table group.

* `TABLEGROUP_ID`: The ID of the queried table group.

* `SHARDING`: The `SHARDING` attribute of the table group. Valid values of the `SHARDING` attribute are as follows:

  * For a table group with the `SHARDING` attribute set to `NONE`, all partitions of all tables in the table group are aggregated on the same server, and no limitations are imposed on tables to be added to the table group.

  * For a table group with the `SHARDING` attribute set to `PARTITION`, the data of each table in the table group is scattered by partition. For a subpartitioned table in the table group, all subpartitions in each partition are aggregated together.

    Partition requirement: A table to be added to the table group must have the same partition definition as existing tables in the table group, including the partitioning type, partition count, and partition value.

  * For a table group with the `SHARDING` attribute set to `ADAPTIVE`, the data of each table in the table group is adaptively scattered. In other words, data in partitioned tables is scattered by partition, and data in subpartitioned tables is scattered by subpartition in each partition.

    Partition requirement: A table to be added to the table group must have the same partition and subpartition definitions as existing tables in the table group, including the partitioning type, partition count, and partition value.
