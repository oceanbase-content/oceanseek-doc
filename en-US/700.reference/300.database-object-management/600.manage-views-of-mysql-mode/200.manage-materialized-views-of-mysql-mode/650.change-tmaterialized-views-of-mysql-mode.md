# Modify materialized view attributes

This topic describes how to modify the attributes of a materialized view using SQL statements.

## Privilege requirements

To modify a materialized view, the current user must have the `ALTER` privilege on the object. For more information about OceanSeek privileges, see [Permission classification](../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

The SQL statement for modifying a materialized view is as follows:

```sql
ALTER MATERIALIZED VIEW [database.]view_name alter_mview_action_list;

alter_mview_action_list:
    alter_mview_action [, alter_mview_action ...]

alter_mview_action:
    parallel_clause
    | REFRESH [nested_refresh_option] [[START WITH expr] [NEXT expr]]

parallel_clause:
    NOPARALLEL
    | PARALLEL integer
    | REFRESH PARALLEL integer

nested_refresh_option:
    INDIVIDUAL
    | INCONSISTENT
    | CONSISTENT
```

## Parameters

* `database.`: Optional. Specifies the database where the materialized view is located. If `database.` is omitted, the materialized view is in the database connected to the current session by default.
* `view_name`: Specifies the name of the materialized view to be modified.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>OceanSeek supports renaming a materialized view using the <code>RENAME TABLE</code> statement.</p>
  </main>

* `alter_mview_action_list`: Indicates the list of modification operations that can be performed on the materialized view. Multiple operations can be specified, separated by commas (`,`).

For detailed parameter descriptions on the syntax for modifying a materialized view, see [ALTER MATERIALIZED VIEW](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1250.alter-materialized-view-of-mysql-mode-in-sql.md).

## Examples

1. Create a table named `test_tbl1`.

    ```sql
    CREATE TABLE test_tbl1 (col1 INT PRIMARY KEY, col2 VARCHAR(20), col3 INT, col4 TEXT);
    ```

2. Create a materialized view named `mv_test_tbl1`.

    ```sql
    CREATE MATERIALIZED VIEW mv_test_tbl1(c1, c2, c3, PRIMARY KEY(c1))
        AS SELECT col1, col2, col3
           FROM test_tbl1;
    ```

3. Modify the query parallelism of the materialized view `mv_test_tbl1` to 5.

    ```sql
    ALTER MATERIALIZED VIEW mv_test_tbl1 PARALLEL 5;
    ```

4. Modify the refresh plan of the materialized view `mv_test_tbl1` to set the initial refresh time to the current date and then refresh it every other day.

    ```sql
    ALTER MATERIALIZED VIEW mv_test_tbl1
        REFRESH START WITH sysdate() NEXT sysdate() + interval 1 DAY;
    ```

5. Create a nested materialized view named `mv_mv_test_tbl1` based on the materialized view `mv_test_tbl1`, with a refresh strategy of `INDIVIDUAL`.

    ```sql
    CREATE MATERIALIZED VIEW mv_mv_test_tbl1
        REFRESH COMPLETE INDIVIDUAL
        AS SELECT c1, c2
           FROM mv_test_tbl1;
    ```

6. Change the refresh strategy of the nested materialized view `mv_mv_test_tbl1` to `INCONSISTENT`.

    ```sql
    ALTER MATERIALIZED VIEW mv_mv_test_tbl1
        REFRESH INCONSISTENT;
    ```

7. Change the refresh parallelism of the nested materialized view `mv_mv_test_tbl1` to 3.

    ```sql
    ALTER MATERIALIZED VIEW mv_mv_test_tbl1
        REFRESH PARALLEL 3;
    ```
