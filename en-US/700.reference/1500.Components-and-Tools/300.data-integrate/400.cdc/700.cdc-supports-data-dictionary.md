# Data dictionary support in obcdc

## Overview

OceanBase AI Database supports the data dictionary feature. The data dictionary is a tenant-level service that persists tenant metadata of an OceanBase AI Database cluster, including log stream information and database/table metadata, into clogs. Its primary purpose is to enable the data link (obcdc) to obtain tenant metadata solely from logs.

The data dictionary serves only user tenants and is persisted in the system log stream (SYS_LS) of a regular tenant through PALF. After a user tenant is created, the data dictionary service is automatically enabled and runs on the LEADER replica of the tenant's SYS_LS.

When the [Log Archiving](../../../../600.manage/600.backup-and-recovery/300.log-archive/100.overview-of-log-archive.md) service is enabled, an asynchronous data dictionary generation task is automatically triggered. OceanBase AI Database supports scheduled data dictionary generation by using the tenant-level parameter [dump_data_dictionary_to_log_interval](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2300.dump_data_dictionary_to_log_interval.md) and the `DBMS_DATA_DICT` system package. We recommend that you use the `DBMS_DATA_DICT` system package to schedule data dictionary generation.

OceanBase AI Database supports recording the data dictionary generation history through DBA/CDB views. You can query the `CDB_OB_DATA_DICTIONARY_IN_LOG` view in the sys tenant or the DBA_OB_DATA_DICTIONARY_IN_LOG view in a user tenant to obtain dictionary location information.

<main id="notice" type='notice'>
   <h4>Notice</h4>
   <ul>
   <li><p>The data dictionary generation time ranges from several seconds to several hours depending on the complexity of tenant metadata. When you set the parameter, take the complexity of tenant metadata into account. An excessively short generation cycle will cause frequent dictionary generation. Because data dictionary generation is a single-threaded task, the thread will be occupied for a long time.</p></li>
   <li><p>During data dictionary generation, the schema services called occupy additional memory. This memory usage is more noticeable when the number of tenant schemas increases or when the tenant's memory specification is small.</p></li>
   </ul>
</main>

## Usage

You can set `meta_data_refresh_mode` in the configuration file to specify whether to parse schema information from the data dictionary in logs. If you set it to `online`, schema information is queried from OBServer nodes through SchemaService, which requires access to OBServer nodes. If you set it to `data_dict`, schema information is parsed from the data dictionary in logs.

<main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>When obcdc synchronizes data from OceanBase AI Database, it ignores user configurations and forcibly uses <code>data_dict</code> mode. To use <code>online</code> mode, you must also set the <code>skip_ob_version_compat_check</code> parameter to <code>1</code>.</p>
</main>

For example, add the following content to the configuration file. For more information about the obcdc configuration file, see [Sample configuration file](200.obcdc-parameters/50.example-configuration-file.md).

```conf
meta_data_refresh_mode=data_dict
```

After configuration, you need to restart the obcdc host process. For example, start it with the following command:

```shell
[admin@test oceanbase]$ ./bin/obcdc_tailf -f libobcdc.conf -D output.txt
```

This example uses the relative path `libobcdc.conf` for the configuration file and saves the output data processed by obcdc to the `output.txt` file. Replace the configuration file name and output file name as needed. For more information about the `obcdc_tailf` command, see [obcdc_tailf](300.obcdc-tailf.md).
