# direct_load_allow_fallback

## Overview

`direct_load_allow_fallback` specifies whether to roll back a direct load operation to an ordinary import operation when the specified direct load scenario is not supported.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Bool |
| Default Value | True |
| Value range | <ul><li>False: If direct load is not supported, you cannot roll back to the normal import method, and an error will be returned for the data import operation. </li><li>True: If direct load is not supported, you can roll back to the normal import method, and no error will be returned for the data import operation. </li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* Whether you manually add a hint to control the data import mode as direct load or globally configure the data import mode as direct load using the parameter [default_load_mode](2050.default_load_mode.md), the behavior when direct load is not supported is determined by the value of the `direct_load_allow_fallback` parameter.

## Configuration example

Configure the system to not report errors when importing data into scenarios that are not supported for direct load, and to allow reverting to the normal import method.

```shell
obclient> ALTER SYSTEM SET direct_load_allow_fallback = True;
```
