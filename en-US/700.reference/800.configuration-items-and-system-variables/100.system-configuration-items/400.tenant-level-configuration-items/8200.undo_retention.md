# undo_retention

## Overview

`undo_retention` specifies the range of multi-version data that the system should retain, controlling the recycling of multi-version data during minor compactions.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Int |
| Default Value | 1,800 seconds |
| Value range | [0, 4294967295] |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

The data compacted by OceanSeek retains multiple versions of historical data rows. You can use the `undo_retention` parameter to control the range of multi-version data retained during a minor compaction.

Where:

* When the value of `undo_retention` is `0`, multi-version minor compaction is not enabled. In this case, only the row data of the current latest version is retained in the minor compaction file.

* When the value of `undo_retention` is greater than `0`, multi-version minor compaction is enabled, and minor compaction files retain row data from multiple versions within this period (in seconds).

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>After multi-version minor compaction is enabled for a tenant, major compactions will retain the corresponding incremental minor compaction files. However, the major SSTable will not store multi-version data. It is recommended not to set this parameter too high to prevent the number of retained SSTables from exceeding the limit.</p>
  </main>

## Configuration example

Set the multi-version data retention period for the system to 1800 seconds.

```shell
obclient> ALTER SYSTEM SET undo_retention=1800;
```
