# enable_ls_leader_balance

## Overview

`enable_ls_leader_balance` specifies whether to enable automatic leader balancing for log streams.

## Privilege requirements

* Query parameters

  The `sys` tenant and all user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.

* Modify parameters

  Both the `sys` tenant and user tenants can use the `ALTER SYSTEM SET` statement to modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ----------- | ---------- |
| Parameter type | Bool |
| Default Value | True |
| Value range | <ul><li>`True`: Enable automatic leader balancing for log streams.</li><li>`False`: Disable automatic leader balancing for log streams.</li></ul> |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* When [enable_rebalance](2800.enable_rebalance.md) is enabled (with a value of `True`), `enable_ls_leader_balance` can be used to independently control the automatic balancing of log stream leaders.

* When this parameter is disabled (value is `False`), automatic leader switchover does not occur at the log stream level. However, leader switchover may still occur at the partition level due to log stream transfers between leaders with different partitions.

## Configuration example

* Users can disable automatic leader balancing for log streams of their own tenants.

  ```shell
  obclient> ALTER SYSTEM SET enable_ls_leader_balance = False;
  ```

* The system tenant specifies to disable automatic leader balancing for the `mysql` tenant's log stream.

  ```shell
  obclient> ALTER SYSTEM SET enable_ls_leader_balance = False TENANT = 'mysql';
  ```
