# connection_control_max_connection_delay

## Overview

`connection_control_max_connection_delay` specifies the maximum duration for which a login attempt will be locked after exceeding the threshold number of failed login attempts.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  This parameter can be modified by both the `sys` tenant and user tenants.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Int |
| Default Value | 2147483647, in milliseconds |
| Value range | [1000,2147483647] |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Configuration example

After the number of failed login attempts exceeds the threshold, the maximum duration for locking an account after failed login attempts is 2,147,483,647 milliseconds.

```shell
obclient> ALTER SYSTEM SET connection_control_max_connection_delay = 2147483647;
```
