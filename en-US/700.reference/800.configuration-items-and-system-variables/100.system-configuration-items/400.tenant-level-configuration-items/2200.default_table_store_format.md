# default_table_store_format

## Overview

`default_table_store_format` specifies the default format for creating tables in a user tenant, including row-store, pure columnar storage, and hybrid row-column storage.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | String |
| Default Value | row |
| Value range | ('row', 'column', 'compound')<main id="notice" type='explain'><h4>Note</h4><ul><li>row: The default format for creating a table in a user tenant is row-based storage.  </li><li>column: If the <code>with column group</code> statement is not added after the table creation statement in a user tenant, the <code>with column group(each column)</code> statement will be automatically added, specifying the default format as a pure columnar table.</li><li>compound: If the <code>with column group</code> statement is not added after the table creation statement in a user tenant, the <code>with column group(all columns, each column)</code> statement will be automatically added, specifying the default format as a hybrid row-columnar table.</li></ul></main> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* This parameter only affects the default format for creating primary tables in user tenants and has no effect on Meta or sys tenants.

* When you create a columnar table for a tenant, you can specify the default storage mode of the table as row-based, columnar, or hybrid row-column storage without modifying the original table creation statement.

* This parameter takes effect only on statements that create tables without the `with column group` clause; it does not apply to index tables.

## Configuration example

* When you create a table in a user tenant, the default format is set to a pure columnar storage table. The `with column group(each column)` clause is automatically added after the table creation statement.

  ```shell
  obclient> ALTER SYSTEM SET default_table_store_format = 'column';
  ```

* When you create a table in a user tenant, the default format is a redundant row-store columnar table. The `with column group(all columns, each column)` clause is automatically added to the table creation statement.

  ```shell
  obclient> ALTER SYSTEM SET default_table_store_format = 'compound';
  ```
