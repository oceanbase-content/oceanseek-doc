# audit_trail

## Overview

`audit_trail` specifies whether to enable database auditing.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | String |
| Default Value | NONE |
| Value range | <ul><li>NONE: Disable auditing.</li><li>OS: Write audit records to local files.</li><li>DB: Write audit records to internal tables.</li><li>DB,EXTENDED: Write audit records to internal tables and include the executed SQL statements in the records.</li><li>DB_EXTENDED: Write audit records to internal tables and include the executed SQL statements in the records.</li></ul> |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Configuration example

Set this parameter to disable database auditing.

```shell
obclient> ALTER SYSTEM SET audit_trail ='NONE';
```
