# ha_high_thread_score

## Overview

`ha_high_thread_score` specifies the number of worker threads for high-priority threads in high-availability mode.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| --- | --- |
| Parameter type | Int |
| Default Value | 0: The default number of worker threads is 8. |
| Value range | [0, 100] |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

Tasks related to high availability, such as migration replication and backup recovery, are scheduled and executed by the tenant-level DagScheduler. Considering the limited thread resources of each tenant, configuration parameters are no longer differentiated by task type. Instead, three high-availability-related parameters are set based on task priority and importance, with each parameter corresponding to different task types:

* ha_high_thread_score: The number of concurrent threads for high-priority, high-reliability task queues such as replication, rebuild, and recovery.
* ha_mid_thread_score: The number of concurrent threads for high-priority and reliable task queues, such as migration.
*   ha_low_thread_score: The number of concurrent threads for low-priority, high-reliability task queues such as backup, backup of backups, and backup cleanup.

## Configuration example

Set the current number of worker threads for high-priority threads in high-availability mode of this tenant to 10.

```shell
obclient> ALTER SYSTEM SET ha_high_thread_score =10;
```
