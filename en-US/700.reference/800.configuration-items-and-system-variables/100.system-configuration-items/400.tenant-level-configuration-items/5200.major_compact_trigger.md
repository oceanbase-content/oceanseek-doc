# major_compact_trigger

<main id="notice" type='explain'>
<h4>Note</h4>
<ul><li><p>OceanSeek supports adaptive compaction, which is controlled by the <code>_enable_adaptive_compaction</code> switch. When adaptive compaction is enabled, the system collects and analyzes user query and write activity in real time, and schedules partition compaction tasks as needed. One scenario for triggering adaptive compaction is when a partition experiences frequent minor compactions and exceeds the specified threshold. In that case, a partition compaction task is scheduled for the partition. For detailed operations and instructions on the adaptive compaction feature, see <a href="../../../200.system-management/500.manage-data-storage/200.merge-management/320.adaptive-compaction.md">Adaptive Compaction</a>.</p>
<p>The <code>major_compact_trigger</code> parameter specifies that a tenant-level major compaction task is scheduled for a tenant when the number of freezes of the tenant reaches the specified threshold. The <code>major_compact_trigger</code> parameter takes effect at the tenant level. Compared with adaptive major compaction, tenant-level major compaction has a larger granularity, involves more partitions, and consumes more system resources. Therefore, we recommend that you disable the adaptive major compaction feature and do not configure the <code>major_compact_trigger</code> parameter.</p></li>
</ul>
</main>

## Overview

`major_compact_trigger` specifies how many minor compactions (the precursor to a major compaction) trigger a major compaction.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ------------------ | -------------- |
| Parameter type | Int |
| Default Value | 0 indicates that a major compaction will not be automatically triggered regardless of the number of freezes. |
| Value range | \[0, 65535\] |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Configuration example

Configure to trigger a tenant-level major compaction after 10 minor compactions.

```shell
obclient> ALTER SYSTEM SET major_compact_trigger=10;
```
