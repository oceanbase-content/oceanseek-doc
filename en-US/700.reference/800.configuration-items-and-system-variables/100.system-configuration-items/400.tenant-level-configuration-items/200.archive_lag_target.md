# archive_lag_target

## Overview

`archive_lag_target` specifies the maximum allowed time lag for log archiving of a tenant.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ------------------ | -------------- |
| Parameter type | Time |
| Default Value | 120s |
| Value range | [0ms, 7200s] |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* For physical standby database scenarios based on log archiving, you can adjust the value of the primary tenant's parameter `archive_lag_target` according to the synchronization requirements of the standby tenants. It can be set to half of the latency requirement of the standby tenants. After adjustment, it will affect all standby tenants under that primary tenant.

* For other scenarios, such as network-based physical standby database scenarios, it is recommended to adjust the value of the primary tenant's parameter `archive_lag_target` based on the tenant's write load and requirements for archiving timeliness. Subject to meeting timeliness requirements, ensure that a single log stream generates at least one log file of 64 MB within the period set by `archive_lag_target`.

  <main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The archive file is homogeneous with the log files of OceanBase AI Database. A single log file can be completely uploaded as a single Normal-type archive file.</p>
  </main>

## Configuration example

Set the tenant log archiving delay to 120 seconds.

```shell
obclient> ALTER SYSTEM SET archive_lag_target ='120s';
```
