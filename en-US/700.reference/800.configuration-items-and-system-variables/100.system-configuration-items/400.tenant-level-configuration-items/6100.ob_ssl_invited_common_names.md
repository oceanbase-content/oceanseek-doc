# ob_ssl_invited_common_names

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter has been deprecated due to feature adjustments. You can query and modify it, but the configuration will not take effect.</p>
</main>

## Overview

`ob_ssl_invited_common_names` is used to record the list of application identities running in the current tenant. These identities are derived from the `cn` (common name) field in the certificate subject of the client during SSL mutual authentication.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Neither the `sys` tenant nor user tenants can modify this parameter.

## Attributes

| Attribute | Description |
| ------------------ | ------- |
| Parameter type | String |
| Default Value | NONE |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

After the password verification for a user's login to the server is completed, login is restricted if all of the following three conditions are met simultaneously:

* SSL is enabled on the client, and mutual authentication is used for the client-side CA, certificate, or private key.
* The server has an application allowlist configured, meaning the allowlist is not empty.
* The `cn` field of the client certificate subject is not in the allowlist.

If none of the above three conditions is met, the allowlist check fails and is ignored.

## Configuration example

Set the CN field value of the client certificate to `ALIPAY`.

```shell
obclient> ALTER SYSTEM SET ob_ssl_invited_common_names = 'ALIPAY';
```
