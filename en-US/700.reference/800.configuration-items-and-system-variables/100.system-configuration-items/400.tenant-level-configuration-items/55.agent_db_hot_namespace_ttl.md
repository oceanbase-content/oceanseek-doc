# agent_db_hot_namespace_ttl

## Overview

`agent_db_hot_namespace_ttl` specifies the lifespan of a hot namespace cache for logical tables. When a namespace has not been accessed for an extended period and exceeds this TTL, the hot namespace cache is evicted. This cache primarily refers to the clustering center cache for vector indexes.

## Privilege requirements

* Query parameters

  The `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view can be used by the `sys` tenant and all user tenants to query this parameter.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Time |
| Default Value | 1h |
| Value range | [1s, 180d] |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* The background task checks every 10 seconds whether there are any namespaces whose caches need to be cleaned.
* To retain Namespace cache for a longer period, set this parameter to a larger value.
* If a Namespace cache is evicted due to its TTL, it must be re-warmed before the cache can be restored.
* Supported time units include seconds (`s`), minutes (`m`), hours (`h`), and days (`d`).

## Configuration example

* Set the hot namespace TTL to 3 days.

  ```shell
  obclient> ALTER SYSTEM SET agent_db_hot_namespace_ttl = '3d';
  ```

* Restore the default value of 1 hour.

  ```shell
  obclient> ALTER SYSTEM SET agent_db_hot_namespace_ttl = '1h';
  ```
