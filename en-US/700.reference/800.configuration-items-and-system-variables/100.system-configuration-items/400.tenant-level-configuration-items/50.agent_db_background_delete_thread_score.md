# agent_db_background_delete_thread_score

## Overview

`agent_db_background_delete_thread_score` specifies the number of threads for background data deletion in logical tables.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Int |
| Default Value | 0: Use the default value 2. |
| Value range | [0, 100] |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* A larger value allows the background deletion task to use more thread resources, resulting in faster deletion but consuming more system resources.
* The background task checks every 10 seconds whether there are logical tables that need cleanup. If so, the system submits multiple partition-level deletion tasks, and this parameter controls the number of threads for concurrent deletion.

## Configuration example

* The system tenant sets the number of threads for deleting data from logical tables in the specified user tenant to 4.

  ```shell
  obclient(root@sys)[(none)]> ALTER SYSTEM SET agent_db_background_delete_thread_score = 4 TENANT = tenant_name;
  ```

* The user tenant sets the number of threads for deleting data from logical tables in the background to 4.

  ```shell
  obclient> ALTER SYSTEM SET agent_db_background_delete_thread_score = 4;
  ```
