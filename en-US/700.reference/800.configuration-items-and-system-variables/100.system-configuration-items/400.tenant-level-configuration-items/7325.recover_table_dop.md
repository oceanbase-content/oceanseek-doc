# recover_table_dop

## Overview

`recover_table_dop` specifies the maximum number of tables that can be restored in parallel during the cross-tenant data import phase of table-level restore.

## Privilege requirements

* Query parameters

  The `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view can be used by the `sys` tenant and all user tenants to query this parameter.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------------------- | -------------- |
| Parameter type | Int |
| Default Value | 0 indicates the default parallelism of 1. |
| Value range | 0, +∞) |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* This parameter is used only to control the degree of parallelism during the **cross-tenant table import stage** of table-level restore. For more information about the table-level restore process, see [Restore process].

## Configuration example

Set the parallelism for single-table restore in the `mysql` tenant to 6.

```shell
obclient> ALTER SYSTEM SET recover_table_dop = 6 TENANT = 'mysql';
```
