# standby_db_fetch_log_rpc_timeout

## Overview

The `standby_db_fetch_log_rpc_timeout` parameter specifies the RPC timeout period for log fetch from a standby database. It controls how long the standby database's log transfer service waits before detecting that a primary server is unavailable and switching logs to another server.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  This parameter can be modified for both the `sys` and user tenants.

## Attributes

| Attribute | Description |
| ------------------ | ------- |
| Parameter type | Time |
| Default Value | 15s |
| Value range | [2s,+∞) |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Configuration example

Set the RPC timeout period for log pulling from the standby database in the `sys` tenant of the cluster where the standby tenant resides.

```shell
obclient> ALTER SYSTEM SET standby_db_fetch_log_rpc_timeout = '30s' tenant = 'standby_tenant';
```

Sets the RPC timeout period for pulling logs from a standby database in a user tenant.

```shell
obclient> ALTER SYSTEM SET standby_db_fetch_log_rpc_timeout = '30s';
```
