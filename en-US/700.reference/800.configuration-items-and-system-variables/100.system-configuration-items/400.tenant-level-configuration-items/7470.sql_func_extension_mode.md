# sql_func_extension_mode

## Overview

The `sql_func_extension_mode` parameter specifies whether to enable functions in mainstream compatibility mode that have naming conventions different from those of MySQL.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ---------- | ---------- |
| Parameter type | Varchar |
| Default Value | empty |
| Value range | <ul><li>NULL: Disable function extensions for any compatibility mode.</li><li>ClickHouse: Enable ClickHouse-compatible functions.</li></ul> |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

OceanSeek maintains a list of functions specific to each compatibility mode. By default, these functions are not exposed. When you set the `sql_func_extension_mode` parameter to the corresponding mode, all functions in that list will be exposed, allowing users to call them in SQL statements.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>The visibility of functions exposed by default is not affected by this parameter.</p>
</main>

### Compatibility mode overlay

Compatibility modes can be used in combination to enable multiple function extensions. When you need to enable multiple function extensions, separate the mode names with commas:

```shell
ALTER SYSTEM SET sql_func_extension_mode = "mode1, mode2";
```

## Configuration example

Enable function extension in ClickHouse compatibility mode.

```shell
obclient> ALTER SYSTEM SET sql_func_extension_mode = "ClickHouse";
```
