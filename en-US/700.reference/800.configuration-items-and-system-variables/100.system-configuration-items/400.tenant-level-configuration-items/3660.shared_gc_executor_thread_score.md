# shared_gc_executor_thread_score

## Overview

`shared_gcexecutor_thread_score` specifies the number of threads that can concurrently execute shared data GC tasks. The default value is 0, which means it is not explicitly specified and the thread score of the priority thread is used by default. In this case, the number of threads for shared data GC tasks is 2 by default.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can use the `ALTER SYSTEM SET` statement to modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Int |
| Default Value | 0: no explicit thread score is specified. The default thread score, which is 2, is used. This thread score is shared among all tasks of the garbage collector that process data. |
| Value range | [0, 100] |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

This parameter is used to dynamically adjust the number of threads for the deletion logic during shared data GC. With this configuration, the system can flexibly adjust the number of execution threads for shared data GC based on specific business requirements.

## Configuration example

In the user tenant, set the number of threads used to execute shared data GC tasks to 8.

```shell
obclient> ALTER SYSTEM SET shared_gc_executor_thread_score = 8;
```
