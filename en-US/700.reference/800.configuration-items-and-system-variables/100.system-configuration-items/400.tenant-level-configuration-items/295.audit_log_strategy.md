# audit_log_strategy

## Overview

The `audit_log_strategy` parameter specifies the strategy for writing audit records to files.

## Privilege requirements

* Query parameters

  The `sys` tenant and all user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.

* Modify parameters

  Both the `sys` tenant and user tenants can use the `ALTER SYSTEM SET` statement to modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | String |
| Default Value | ASYNCHRONOUS |
| Value range | <ul><li>ASYNCHRONOUS: asynchronous log writing. The system waits synchronously when the buffer is full.</li><li>PERFORMANCE: asynchronous log writing. Data is discarded when the buffer is full.</li><li>SYNCHRONOUS: synchronous log writing.</li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

You can set multiple write log strategies using `audit_log_strategy` to balance performance and log integrity. When using asynchronous writes, you can control the buffer size using [audit_log_buffer_size](210.audit_log_buffer_size.md).

## Configuration example

Set the audit record file writing strategy to asynchronous log writing. When the buffer is full, it will wait synchronously.

```shell
obclient> ALTER SYSTEM SET audit_log_strategy='ASYNCHRONOUS';
```
