# ttl_duty_time

## Overview

`ttl_duty_time` specifies the time point at which the background job periodically triggers the execution of the TTL task.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ----------- | --------------- |
| Parameter type | Moment |
| Default Value | 01:00 |
| Value range | [time_zone](../../200.system-variable/300.global-system-variable/13300.time_zone-global.md). |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* This parameter takes effect only when the tenant-level parameter [enable_ttl](3020.enable_ttl.md) is set to `True`. After the specified start time, the system will begin traversing all tables with a TTL attribute under the tenant and execute the TTL task for these tables.

* The `ttl_duty_time` point is in the same time zone as the tenant. It is recommended to set it during the tenant's off-peak business hours, before the daily batch start.

## Configuration example

* After the system tenant specifies a TTL for a user tenant, the background job that periodically triggers the TTL task is scheduled to run at `02:00` a.m.

  ```shell
  obclient(root@sys)[(none)]> ALTER SYSTEM SET ttl_duty_time = '02:00' TENANT = tenant_name;
  ```

* After the user tenant specifies a TTL for itself, the background automatically triggers the execution of the TTL task at `02:00` every morning.

  ```shell
  obclient> ALTER SYSTEM SET ttl_duty_time = '02:00';
  ```
