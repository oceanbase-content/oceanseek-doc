# package_state_sync_max_size

## Overview

The `package_state_sync_max_size` parameter specifies the maximum serializable length for a single package state.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ----------- | --------------- |
| Parameter type | Int |
| Default Value | 8192 |
| Value range | [0, 16777216] |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* This parameter specifies the maximum serialized length for a single package state synchronization packet. In an ODP deployment scenario, if the OBServer determines that the serialized length required to synchronize packet variables exceeds this limit, it will send a special value to instruct ODP to continue routing subsequent statements to the original node for execution.

* In distributed plan scenarios, an error would occur when a remote node constructed the package state if it received a specific value. This error occurred when the SQL statement contained UDFs (user-defined functions) or triggers and explicitly had the `parallel_enable` clause. To resolve this, you can remove the `parallel_enable` clause or increase the value of the `package_state_sync_max_size` parameter.

## Configuration example

Set the serializable length for a single package state to 8193.

```shell
obclient> ALTER SYSTEM SET package_state_sync_max_size=8193;
```
