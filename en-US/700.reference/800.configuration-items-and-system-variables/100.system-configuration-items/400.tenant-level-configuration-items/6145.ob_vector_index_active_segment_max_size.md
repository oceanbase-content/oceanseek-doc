# ob_vector_index_active_segment_max_size

## Overview

`ob_vector_index_active_segment_max_size` controls the maximum memory usage for active incremental segments within a single partition. When the memory occupied by newly written vector data in an active incremental segment exceeds this threshold, the system triggers freezing and persistence operations to flush the incremental data from memory to disk.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Cap |
| Default Value | 0 indicates adaptive. The system automatically sets different thresholds based on the tenant's available vector memory:<ul><li>Below 4 GB: 32 MB</li><li>4 GB to 16 GB (inclusive): 64 MB</li><li>Above 16 GB: 128 MB</li></ul> |
| Value range | [0, +∞), in MB |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* Increase the threshold: This can reduce the frequency of freezes and prevent the generation of excessive active incremental segments when incremental write speeds are too high, which could degrade search performance.
* Lower the threshold: Unless in special test scenarios, it is not recommended to lower the threshold. This is to avoid excessive freeze operations that could impact overall search performance.
* Restart the database: When restarting a database, the system needs to restore data in memory. A large threshold will increase the restart recovery time. Before restarting, it is recommended to lower the threshold to reduce the restart recovery time. Alternatively, perform the restart during off-peak business hours.

## Configuration example

Set the maximum memory usage for the active segment of a vector index in a single partition to 256 MB.

```sql
ALTER SYSTEM SET ob_vector_index_active_segment_max_size = '256MB';
```

View the current configuration.

```sql
SHOW PARAMETERS LIKE 'ob_vector_index_active_segment_max_size';
```
