# audit_log_rotate_on_size

## Overview

`audit_log_rotate_on_size` specifies the maximum size of an audit log file.


## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can use the `ALTER SYSTEM SET` statement to modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Capacity |
| Default Value | 256M |
| Value range | [0M, +∞) |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

Audit records are continuously appended to the `audit.log` file. Automatic log archiving is enabled by setting `audit_log_rotate_on_size`. When the size of `audit.log` reaches the specified value, a new file is automatically generated. Archiving controls the size of individual log files but does not clean up old files.

## Configuration example

Set the maximum size of an audit record file to 256 MB.

```shell
obclient> ALTER SYSTEM SET audit_log_rotate_on_size='256M';
```
