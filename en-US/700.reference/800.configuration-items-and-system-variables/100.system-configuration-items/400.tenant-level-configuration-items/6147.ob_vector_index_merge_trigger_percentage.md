# ob_vector_index_merge_trigger_percentage

## Overview

`ob_vector_index_merge_trigger_percentage` controls the percentage of memory occupied by persistent incremental segments to the total memory of the persistent partitioned index. When the proportion of incremental segments exceeds this value, the system automatically triggers a segment merge to combine the incremental segments with the baseline segments.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Int |
| Default Value | 20 |
| Value range | [0, 100), in percentage |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* Default configuration (20%): The default value is sufficient for most scenarios.
* Configuration improvement: Reduce the frequency of major compactions between the incremental and baseline segments to avoid excessive resource consumption caused by high compaction frequencies when write throughput is too high.
* Lower the configuration: Unless in special test scenarios, it is not recommended to lower the thresholds.
* Set to `0`: the current setting is equivalent to using the default value.

## Configuration example

Set the maximum proportion of an incremental segment to 30% of the entire partition index.

```sql
ALTER SYSTEM SET ob_vector_index_merge_trigger_percentage = 30;
```

View the current configuration.

```sql
SHOW PARAMETERS LIKE 'ob_vector_index_merge_trigger_percentage';
```
