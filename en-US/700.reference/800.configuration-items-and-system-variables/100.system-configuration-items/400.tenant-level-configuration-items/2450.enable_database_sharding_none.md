# enable_database_sharding_none

## Overview

The `enable_database_sharding_none` parameter controls whether to enable automatic aggregation (automatic table group binding) for user tables when creating a database.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ------------------ | -------------------- |
| Parameter type | Bool |
| Default Value | False |
| Value range | <ul><li>True: enabled. </li><li>False: disabled.</li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* The value of the `enable_database_sharding_none` parameter is changed from `False` to `True`:

  * When you create a database, a table group with `SHARDING = 'NONE'` is bound by default. All user tables in this database are bound to the same log stream.
  * Existing databases are not affected.

* The value of the `enable_database_sharding_none` parameter is changed from `True` to `False`:

  * The existing database will not be modified.

## Configuration example

Configure automatic aggregation for user tables when creating a database.

```shell
obclient> ALTER SYSTEM SET enable_database_sharding_none = True;
```
