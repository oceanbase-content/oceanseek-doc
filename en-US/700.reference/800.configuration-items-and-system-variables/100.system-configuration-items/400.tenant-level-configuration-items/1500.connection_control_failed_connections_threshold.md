# connection_control_failed_connections_threshold

## Overview

`connection_control_failed_connections_threshold` specifies the threshold for user incorrect login attempts.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Int |
| Default Value | 0 |
| Value range | [0,2147483647] |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No |

## Usage instructions

When the parameter is set to `0`, this feature is disabled, meaning there is no limit on the number of incorrect login attempts. When a user exceeds the number of incorrect login attempts defined by this parameter, the account will be locked. The lock duration is determined by the [connection_control_min_connection_delay](1700.connection_control_min_connection_delay.md) and [connection_control_max_connection_delay](1600.connection_control_max_connection_delay.md) parameters.

## Configuration example

Set the threshold for user failed login attempts to 3.

```shell
obclient> ALTER SYSTEM SET connection_control_failed_connections_threshold = 3;
```
