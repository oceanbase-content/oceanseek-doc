# global_index_auto_split_policy

## Overview

The `global_index_auto_split_policy` parameter specifies whether to enable automatic partitioning for newly created global indexes.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can use the `ALTER SYSTEM SET` statement to modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ----------- | ---------- |
| Parameter type | STRING |
| Default Value | DISTRIBUTED |
| Value range | <ul><li>`DISTRIBUTED`(Default): When multiple-node resources are available within a tenant (for example, the tenant has more than one primary zone or more than one unit), automatic partition splitting is enabled by default for new global indexes.</li><li>`ALL`: When you create a global index, automatic partition splitting is enabled by default.</li><li>`OFF`: Prohibit automatic splitting of all global indexes, including existing ones. </li></ul> |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`statement to modify the value of this parameter. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

You can execute the `ALTER SYSTEM SET` statement to modify the value of the `global_index_auto_split_policy` parameter. If the primary table is an auto-partitioned table, its global indexes are also automatically partitioned. If the primary table is not an auto-partitioned table, the global indexes are configured according to the policy defined by `global_index_auto_split_policy`.

* If the value of `global_index_auto_split_policy` is set to `ALL`, automatic splitting is enabled by default for newly created global indexes.

* If the value of `global_index_auto_split_policy` is set to `DISTRIBUTED`, automatic splitting is enabled by default for newly created global indexes when it is determined that resources are available across multiple nodes within the tenant (for example, when the tenant has more than one primary zone or more than one unit).

* If the value of `global_index_auto_split_policy` is set to `OFF`, automatic splitting of all global indexes, including existing ones, is disabled.

For more information about automatic partitioning, see [Automatic partition splitting](../../../300.database-object-management/300.manage-partitions-of-mysql-mode/250.partition-splitting-of-mysql-mode/300.automatic-partition-splitting-of-mysql-mode.md).

## Configuration example

Create a global index and enable automatic partitioning.

```sql
obclient> ALTER SYSTEM SET global_index_auto_split_policy = 'ALL';
```
