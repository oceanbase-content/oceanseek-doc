# enable_transfer

## Overview

`enable_transfer` specifies whether to allow transfers within a tenant.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| --- | --- |
| Parameter type | Bool |
| Default Value | True |
| Value range | <ul><li> True: enabled. </li><li>False: disabled. </li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

The load balancing strategy within a tenant is jointly controlled by the tenant-level parameters `enable_rebalance` and `enable_transfer`.

The `enable_rebalance` parameter, when set to the system tenant, controls whether load balancing occurs between tenants. When set to a user tenant, it controls whether load balancing occurs within the tenant. The default value is `true`. After setting, it takes effect immediately without requiring a restart of the OBServer node.

The `enable_transfer` parameter specifies whether to enable the transfer feature for a tenant. The default value is `true`. After setting this parameter, it takes effect immediately without restarting the OBServer node. The meaning of the `enable_transfer` parameter depends on the value of the `enable_rebalance` parameter:

* When the value of the `enable_rebalance` parameter is `false`, the system does not perform automatic load balancing, regardless of whether the value of the `enable_transfer` parameter is `true` or `false`. The command to disable all load balancing is as follows:

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance=false;
  ```

* When the value of the `enable_rebalance` parameter is `true` and the value of the `enable_transfer` parameter is `true`, the system automatically adjusts the partition distribution during tenant scaling to achieve load balancing. The command to dynamically adjust the number of log streams for a tenant and automatically balance leaders and partitions within the tenant based on the load balancing algorithm is as follows:

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance=true;
  obclient> ALTER SYSTEM SET enable_transfer=true;
  ```

* When the value of the `enable_rebalance` parameter is `true` and the value of the `enable_transfer` parameter is `false`, it means that during tenant scaling operations, the system cannot initiate transfer operations; only limited balancing can be achieved through log stream migration. The command that balances log streams based solely on existing log streams without generating transfers or dynamically changing the number of log streams is as follows:

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance=true;
  obclient> ALTER SYSTEM SET enable_transfer=false;
  ```

## Configuration example

* Set the load balancing strategy for a specified tenant in the sys tenant.

  * The system tenant enables intra-tenant load balancing and the transfer feature for a specified tenant.

    ```shell
    obclient> ALTER SYSTEM SET enable_rebalance = true TENANT = 'tenant_name';
    ```

    ```shell
    obclient> ALTER SYSTEM SET enable_transfer = true TENANT = 'tenant_name';
    ```

    The preceding statement specifies that only the values of the parameters `enable_rebalance` and `enable_transfer` under the tenant are set to `true`.

  * The system tenant enables intra-tenant load balancing and the transfer feature for all user tenants (excluding the `sys` tenant and the Meta tenant).

    ```shell
    obclient> ALTER SYSTEM SET enable_rebalance = true TENANT = all_user;
    ```

    ```shell
    obclient> ALTER SYSTEM SET enable_transfer = true TENANT = all_user;
    ```

    or

    ```shell
    obclient> ALTER SYSTEM SET enable_rebalance = true TENANT = all;
    ```

    ```shell
    obclient> ALTER SYSTEM SET enable_transfer = true TENANT = all;
    ```

    The preceding statement sets the values of the `enable_rebalance` and `enable_transfer` parameters to `true` for all user tenants.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p><code>TENANT = all_user</code> has the same semantics as <code>TENANT = all</code>. When you need the change to apply to all user tenants, we recommend that you use <code>TENANT = all_user</code>. The latter <code>TENANT = all</code> will be deprecated in the future.</p>
    </main>

* Users can set the load balancing strategy for their own tenants.

  The statement to enable intra-tenant load balancing and the transfer feature for a user tenant is as follows:

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance = true;
  ```

  ```shell
  obclient> ALTER SYSTEM SET enable_transfer = true;
  ```
