# tde_method

## Overview

`tde_method` specifies the method for transparent tablespace encryption.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can use the `ALTER SYSTEM SET` statement to modify this parameter for a user tenant.

## Attributes

| Attribute | Description |
| ------------------ | ------- |
| Parameter type | String |
| Default Value | none |
| Value range | <ul><li>none: Indicates that transparent tablespace encryption cannot be used.</li><li>internal: Indicates that internal tables are used to manage the master key for transparent encryption.</li><li>bkmi: Indicates that an external BKMI system is used to manage the master key for transparent encryption.</li><li>obcloud: Indicates that the OBCloud unified KMS proxy service is used to manage the master key for transparent encryption, suitable for OBCloud deployments.</li><li>ocp: Indicates that the private cloud OCP KMS proxy service is used to manage the master key for transparent encryption, suitable for private cloud deployments. |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

`tde_method` is a prerequisite configuration for the data encryption feature. Different encryption features have different requirements for the value of `tde_method`:

| Encryption feature | Supported`tde_method`Value | Description |
| --------- | ------------------------ | ------ |
| Transparent Data Encryption (TDE) | No`none`Value; recommended for OBCloud deployment`obcloud`, recommended for private cloud OCP deployment`ocp` | For more information, see [Overview of database transparent encryption](../../../../600.manage/500.security-and-permissions/500.data-encryption/400.data-storage-encryption/100.datastore-encryption-overview.md). |
| Column encryption | No`none`Value; recommended for OBCloud deployment.`obcloud`, recommended for private cloud OCP deployment`ocp` | For more information, see [Column encryption overview](../../../../600.manage/500.security-and-permissions/500.data-encryption/500.column-encryption/100.column-encryption-overview.md). |
| Function Encryption | No`none`Value; recommended for OBCloud deployment`obcloud`, recommended for private cloud OCP deployment`ocp` | For more information, see [ENHANCED_AES_ENCRYPT](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/500.encryption-and-compression-functions-of-mysql-mode/820.enhanced-aes-encrypt-of-mysql-mode.md). |

### Description of `obcloud` mode

The `obcloud` option is used for OBCloud public cloud scenarios: the master key is managed by the OceanBase Cloud KMS service.

The specific usage is as follows:

1. Enable encryption: Use the `obcloud` unified KMS proxy service for master key management.

   ```sql
   ALTER SYSTEM SET tde_method = 'obcloud';
   ```

2. Configure parameters: In the `external_kms_info` parameter, configure the attributes required for the KMS proxy service:

   * `kms_host`: the endpoint of the OceanBase Cloud KMS service.
   * `access_key_id`: The access key used for signature authentication.
   * `access_key_secret`: The SK used for signature authentication.
   * `cmk_id`: The CMK ID.

### Description of `ocp` mode

`ocp`: Used in private cloud scenarios, where the master key is managed by the OCP KMS proxy service.

The specific usage is as follows:

1. Enable encryption: Use the `ocp` private cloud OCP KMS proxy service for master key management.

   ```sql
   ALTER SYSTEM SET tde_method = 'ocp';
   ```

2. Configure parameters: In the `external_kms_info` parameter, configure the attributes required for the KMS proxy service:

   * `kms_host`: The endpoint of the OCP KMS service.
   * `access_key_id`: The access key used for signature authentication.
   * `access_key_secret`: The SK used for signature authentication.
   * `cmk_id`: The CMK ID.

## Configuration example

Set the transparent tablespace encryption method to `internal`.

```shell
obclient> ALTER SYSTEM SET tde_method= 'internal';
```

Set the transparent tablespace encryption method to `obcloud` (applicable to OBCloud deployment. You must also configure `external_kms_info`. The following values are examples; replace them with your actual endpoint and key information).

```shell
obclient> ALTER SYSTEM SET tde_method = 'obcloud';

obclient> ALTER SYSTEM SET external_kms_info = '{
  "kms_host": "https://kms.example.oceanbase.com",
  "access_key_id": "LTAI****************",
  "access_key_secret": "your_access_key_secret",
  "cmk_id": "your_customer_master_key_id"
}';
```

Set the transparent tablespace encryption method to `ocp`.

```shell
obclient> ALTER SYSTEM SET tde_method= 'ocp';
```
