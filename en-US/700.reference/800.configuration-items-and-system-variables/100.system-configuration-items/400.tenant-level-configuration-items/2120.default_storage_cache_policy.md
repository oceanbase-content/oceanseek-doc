# default_storage_cache_policy

## Overview

`default_storage_cache_policy` specifies the default cache policy, which is the default value of the tenant-level `storage_cache_policy` parameter. This parameter takes effect only for newly created tables.

## Privilege requirements

* Query parameters

  The `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

  <main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>The manual hot data caching strategy setting takes effect only in user tenants. When you modify this parameter in non-user tenants (<code>sys</code> tenant and Meta tenant), the parameter value is updated, but the feature does not take effect.</p>
  </main>

## Attributes

| **Attribute** | **Description** |
| ---------- | ---------- |
| Parameter type | String |
| Default Value | AUTO |
| Value range | <ul><li>`HOT`: Specifies to cache all data in the table as hotspot data to the local disk. </li> <li>`AUTO`: Specifies that all data in the table is automatically identified as hot or cold. In other words, shared storage determines the storage method for the data in the table.</li><li>`COLD`: Specifies that the table data is cold data and will not be cached to the local cache disk. For data already persisted to the cache, cache eviction will be actively triggered. Subsequent accesses to the table data can be stored in the macroblock memory cache and will not be persisted to the macroblock cache.</li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* For all newly created tables in the current tenant that do not have a cache policy explicitly specified via the `storage_cache_policy` parameter, the cache policy specified in `default_storage_cache_policy` is used by default.
* Only user tables and indexes are affected by the `default_storage_cache_policy` parameter. System tables are not affected by this parameter and always use the `AUTO` configuration.

## Configuration example

* In the user tenant, set the default cache policy for this tenant to `HOT`.

  ```shell
  obclient> ALTER SYSTEM SET default_storage_cache_policy='HOT';
  ```

* The default cache strategy for the specified tenant `mysqltenant` under the system tenant is set to `HOT`.

  ```shell
  obclient> ALTER SYSTEM SET default_storage_cache_policy='HOT' TENANT = mysqltenant;
  ```
