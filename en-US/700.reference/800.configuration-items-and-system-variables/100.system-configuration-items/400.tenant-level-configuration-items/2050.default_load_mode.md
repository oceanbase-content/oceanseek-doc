# default_load_mode

## Overview

The `default_load_mode` parameter specifies the data import method in data import scenarios.

## Privilege requirements

* Query parameters

  The `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | String |
| Default Value | DISABLED |
| Value range | <ul><li>DISABLED: Do not use direct load. </li><li>FULL_DIRECT_WRITE: Use [full direct load](../../../../300.data-pipeline/100.data-ingestion/300.data-import/200.load-data.md), with SQL semantics taking precedence. </li><li>INC_DIRECT_WRITE: Use the INC mode of incremental direct load. </li><li>INC_REPLACE_DIRECT_WRITE: Use the INC_REPLACE mode of incremental direct load. </li></ul> |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

When importing data using the `LOAD DATA INFILE` statement, `INSERT INTO SELECT` statement, or `CREATE TABLE AS SELECT` statement without specifying any direct load hints, the default import mode is controlled by the `default_load_mode` parameter. If the import operation specifies the `APPEND/DIRECT/NO_DIRECT` hint, the data import mode is controlled by that hint.

## Configuration example

* In data import scenarios, set the data import mode to `FULL_DIRECT_WRITE`.

  ```shell
  obclient [test]> ALTER SYSTEM SET default_load_mode ='FULL_DIRECT_WRITE';
  ```

* In data import scenarios, set the data import mode to `INC_DIRECT_WRITE`.

  ```shell
  obclient [test]> ALTER SYSTEM SET default_load_mode ='INC_DIRECT_WRITE';
  ```
