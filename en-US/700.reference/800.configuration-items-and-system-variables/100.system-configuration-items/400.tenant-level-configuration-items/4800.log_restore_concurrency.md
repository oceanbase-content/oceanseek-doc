# log_restore_concurrency

## Overview

`log_restore_concurrency` specifies the concurrency level for log restore.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Recovery worker threads are created only when a tenant or standby tenant is being restored.</p>
</main>

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| --- | --- |
| Parameter type | Int |
| Default Value | 0 indicates that the adaptive log recovery parallelism of OceanSeek is used. |
| Value range | [0,100] |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

When adaptive log restore parallelism is used in OceanSeek, the number of worker threads for log restore adapts to the value of the tenant's `max_cpu` parameter.

## Configuration example

Set the concurrency for log restore to 5.

```shell
obclient> ALTER SYSTEM SET log_restore_concurrency = 5;
```
