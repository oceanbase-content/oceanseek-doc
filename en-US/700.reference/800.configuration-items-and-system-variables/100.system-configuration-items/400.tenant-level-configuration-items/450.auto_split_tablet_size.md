# auto_split_tablet_size

## Overview

`auto_split_tablet_size` specifies the threshold for triggering automatic partitioning after the auto-partition feature is enabled for a tenant.

## Privilege requirements

* Query parameters

  The `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view can be used by the `sys` tenant and all user tenants to query this parameter.

* Modify parameters

  Both the `sys` tenant and user tenants can use the `ALTER SYSTEM SET` statement to modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ----------- | ---------- |
| Parameter type | CAPACITY |
| Default Value | 2GB |
| Value range | [128M, +∞) |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

You can execute the `ALTER SYSTEM SET` statement to modify the value of a parameter.

When creating or modifying a table, if the auto-partitioning feature is enabled but no auto-partitioning threshold is specified, the value of this parameter will be used as the table's auto-partitioning threshold. When a partition's disk usage exceeds the size set by this parameter, a partition split is triggered.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Modifying this parameter does not affect existing auto-partitioned tables.</p>
</main>

## Configuration example

The split threshold is modified to 256 MB.

```sql
AlTER SYSTEM SET auto_split_tablet_size = '256MB';
```
