# ob_vector_memory_limit_percentage

## Overview

`ob_vector_memory_limit_percentage` specifies the memory usage threshold for the vector index module.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------------------- | -------------- |
| Parameter type | Int |
| Default Value | 0, in percentage.<main id="notice" type='notice'><h4>Note</h4><p>The default value of this parameter indicates adaptive mode, where the system automatically adjusts the memory usage ratio for vector index data within a tenant:<ul><li>If the tenant's actual memory is 8 GB or less, this value adapts to 40.</li><li>If the tenant's actual memory is more than 8 GB, this value adapts to 50.</li></ul></p></main> |
| Value range | [0, 100). The actual maximum value is`85 - Memstore`(That is,`memstore_limit_percentage`(value). When`memstore_limit_percentage`The parameter is set to`0`When this parameter is set to the default value, the system automatically calculates the memory usage of the MemStore. The calculation rules are as follows:<ul><li>If the tenant memory is greater than 8 GB: the MemStore occupies 50% of the tenant memory.</li><li>If the tenant memory is less than or equal to 8 GB: the MemStore occupies 40% of the tenant memory.</li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

### Memory calculation

The specific values for this parameter need to be planned based on the calculation formula and business requirements. Please click [Download memory calculation table](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.3/%E5%86%85%E5%AD%98%E8%AE%A1%E7%AE%97.xlsx) to calculate the parameter values.

Table description:

* When you need to create multiple vector indexes under one tenant, the required memory is the sum of all their memory requirements.

* You need to fill in the values for the number of data records in the first column and the vector dimensionality in the second column based on your business scenario.

* The third column of the table, M, indicates the maximum number of edges in the HNSW graph index. The default value is `16`, which usually does not need to be changed.

* The minimum memory configuration in the fifth column of the table applies only to scenarios where indexes are created later and no new data is added.

### Increase the memory usage of vector indexes

If you need to increase the threshold for vector index memory usage, it is recommended to first reduce the MemStore memory usage of that tenant. This can be achieved by modifying the `_memstore_limit_percentage` parameter under the user tenant.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Reducing the MemStore ratio may impact DML performance. Therefore, in environments with high DML workload, be sure to evaluate the impact before making changes.</p>
</main>

## Configuration example

Set the memory usage threshold for vector indexes to 30%.

```shell
obclient> ALTER SYSTEM SET ob_vector_memory_limit_percentage = 30;
```

Increase the memory usage threshold for vector indexes to 59%.

```shell
obclient> ALTER SYSTEM SET _memstore_limit_percentage = 25;
          ALTER SYSTEM SET ob_vector_memory_limit_percentage = 59;
```

View the current memory configuration for vector indexes.

```shell
obclient> SHOW PARAMETERS LIKE 'ob_vector_memory_limit_percentage';
```
