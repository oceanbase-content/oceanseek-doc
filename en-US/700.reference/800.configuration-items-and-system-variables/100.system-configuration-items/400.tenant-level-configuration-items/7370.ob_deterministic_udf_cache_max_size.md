# ob_deterministic_udf_cache_max_size

## Overview

`ob_deterministic_udf_cache_max_size` specifies the maximum total memory size (in bytes) that can be used by the cache pool for all `deterministic` UDFs during statement execution.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ----------- | --------------- |
| Parameter type | Capacity |
| Default Value | 16M |
| Value range | [0,+∞)<main id="notice" type='explain'><h4>Note</h4><p>If the value is 0, the execution cache feature is disabled.</p></main> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Configuration example

* Run the following command to disable the execution cache feature.

  ```shell
  obclient> ALTER SYSTEM SET ob_deterministic_udf_cache_max_size='0B';
  ```

* Run the following command to set the maximum memory size that the cache pool can use to 16 MB.

  ```shell
  obclient> ALTER SYSTEM SET ob_deterministic_udf_cache_max_size='16M';
  ```
