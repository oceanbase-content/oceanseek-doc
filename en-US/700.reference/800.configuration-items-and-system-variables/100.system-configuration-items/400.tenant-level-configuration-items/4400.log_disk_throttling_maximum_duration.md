# log_disk_throttling_maximum_duration

## Overview

`log_disk_throttling_maximum_duration` specifies the maximum amount of time that the disk can be used for logging after log throttling is triggered.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ------------------ | -------------- |
| Parameter type | Time |
| Default Value | 2h, which indicates 2 hours. |
| Value range | [1s,3d] |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

Both the `log_disk_throttling_maximum_duration` and [log_disk_throttling_percentage](4500.log_disk_throttling_percentage.md) parameters affect log throttling.

* A smaller value for `log_disk_throttling_percentage` sets an earlier threshold for log throttling;
* A larger value for `log_disk_throttling_maximum_duration` indicates a longer expected duration of log throttling support and a stronger throttling effect.

For scenarios with a large gap between write load and minor compaction speed, you can try reducing `log_disk_throttling_percentage` and increasing `log_disk_throttling_maximum_duration`. It is recommended to increase `log_disk_throttling_maximum_duration` first.

## Configuration example

Set the tenant data dictionary persistence cycle to 24h.

```shell
obclient> ALTER SYSTEM SET log_disk_throttling_maximum_duration = '24h';
```
