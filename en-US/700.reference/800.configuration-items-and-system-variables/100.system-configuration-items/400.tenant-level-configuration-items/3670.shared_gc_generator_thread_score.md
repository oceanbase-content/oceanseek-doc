# shared_gc_generator_thread_score

## Overview

`shared_gc_generator_thread_score` specifies the number of threads that can be used to generate shared data GC tasks simultaneously. The default value is 0, which means it is not explicitly specified. In this case, the thread score of the priority thread is used by default, and the number of threads for generating shared data GC tasks is 2 by default.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can use the `ALTER SYSTEM SET` statement to modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Int |
| Default Value | 0: no explicit thread score is specified. The default thread score, which is 2, is used for tasks generated by the garbage collector for shared data. |
| Value range | [0, 100] |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

This parameter is used to dynamically adjust the number of threads for shared data GC tasks. With this configuration, the system can flexibly adjust the thread count for shared data GC tasks based on specific business requirements.

## Configuration example

In the user tenant, set the number of threads for generating shared data GC tasks to 8.

```shell
obclient> ALTER SYSTEM SET shared_gc_generator_thread_score = 8;
```
