# enable_agent_db_background_task

## Overview

`enable_agent_db_background_task` specifies whether to enable background deletion tasks for logical tables.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Bool |
| Default Value | True |
| Value range | <ul><li>`True`: Enable background deletion tasks for logical tables.</li><li>`False`: Disable background deletion tasks for logical tables.</li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* When enabled, the system performs background physical data deletion for `DROP NAMESPACE` and `DROP LTABLE` operations executed by users. When disabled, no new background deletion tasks for logical tables are initiated.
* This parameter helps prevent system jitter caused by a large number of delete tasks.
* This parameter does not control the cleanup of the TTL task for hot namespaces.

## Configuration example

* The system tenant cancels the background deletion task for the logical table of the specified user tenant.

  ```shell
  obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_agent_db_background_task = False TENANT = tenant_name;
  ```

* The user tenant initiates a background deletion task for the logical table in the current tenant.

  ```shell
  obclient> ALTER SYSTEM SET enable_agent_db_background_task = True;
  ```
