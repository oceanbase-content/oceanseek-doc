# zone_deploy_mode

## Overview

`zone_deploy_mode` specifies the deployment mode for tenants across zones.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| Attribute | Description |
| --------------------- | ----------- |
| Parameter type | String |
| Default Value | homo |
| Value range | <ul><li>`homo`: Homogeneous Zone Mode </li><li>`hetero`: Heterogeneous zone mode</li></ul> |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No |

## Usage instructions

By default, a newly created tenant or an upgraded existing tenant operates in homogeneous zone mode. In homogeneous zone mode, the number of units must be the same across all zones. Log streams are symmetrically distributed across zones and are bound to unit groups:

* A unit group consists of one unit from each zone, and each unit belongs to only one unit group.

* A log stream belongs to only one unit group. Replicas of each log stream are distributed across units within that unit group.

* For scaling units, you can only operate at the unit group granularity. The number of units in each zone must be adjusted synchronously to maintain consistency.

To enable the heterogeneous zone mode, you need to change the value of the `zone_deploy_mode` parameter to `hetero`. After modification, the value of the `zone_deploy_mode` parameter cannot be changed back to `homo`.

Heterogeneous zone mode differs from homogeneous zone mode in the following key aspects:

* The concept of unit groups no longer exists for log stream distribution. Log stream replicas in each zone are no longer restricted to symmetric units.

* The `UNIT_NUM` values of resource pools in a tenant can be different, but there can be at most two distinct `UNIT_NUM` values.

* You can individually modify the `UNIT_NUM` of a resource pool under a tenant to achieve scaling at the resource pool level.

* When you use the `ALTER RESOURCE TENANT` statement to scale down by reducing `UNIT_NUM`, specifying `UNIT_GROUP` for deletion is not supported.

* The `UNIT_GROUP` parameter is not supported when using the log stream O&M commands `ALTER SYSTEM CREATE LS` and `ALTER SYSTEM MODIFY LS`.

## Configuration example

Set the zone distribution mode for each tenant to heterogeneous zones.

```shell
obclient> ALTER SYSTEM SET zone_deploy_mode = 'hetero';
```
