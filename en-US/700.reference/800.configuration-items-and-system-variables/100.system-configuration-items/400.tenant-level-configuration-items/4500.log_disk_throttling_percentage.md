# log_disk_throttling_percentage

## Overview

`log_disk_throttling_percentage` specifies the percentage of unreclaimable log disk space that triggers log write throttling.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  This parameter can be modified by both the `sys` tenant and user tenants.

## Attributes

| **Attribute** | **Description** |
| ------------------ | -------------- |
| Parameter type | Int |
| Default Value | 60 |
| Value range | [40,100] |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

Both the [log_disk_throttling_maximum_duration](4400.log_disk_throttling_maximum_duration.md) and log_disk_throttling_percentage parameters affect log throttling.

* A smaller value for `log_disk_throttling_percentage` sets an earlier threshold for log throttling to begin;
* A larger value for `log_disk_throttling_maximum_duration` indicates a longer expected duration of log throttling support and a stronger throttling effect.

For scenarios with a large gap between write load and minor compaction speed, you can try reducing `log_disk_throttling_percentage` and increasing `log_disk_throttling_maximum_duration`. It is recommended to increase `log_disk_throttling_maximum_duration` first.

## Configuration example

Set the percentage of unrecoverable log disk space that triggers log write throttling to 80.

```shell
obclient> ALTER SYSTEM SET log_disk_throttling_percentage=80;
```
