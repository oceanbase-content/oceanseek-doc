# px_node_policy

## Overview

`px_node_policy` is used to support independent scaling of PX compute node resources and indicates the candidate pool for compute nodes.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| Attribute | Description |
| ----- | ---- |
| Parameter type | String |
| Default Value | DATA |
| Value range | <ul><li>`DATA`: The PX compute node can select all data nodes involved in the current SQL statement. </li> <li>`ZONE`: The PX compute nodes can be any nodes belonging to the tenant that are located in the zone involved by the current SQL statement. </li> <li>`CLUSTER`: The PX compute nodes can be any node in the cluster that is involved with the current tenant.</li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Configuration example

The PX compute node for the `mysql` tenant specified by the `sys` tenant can select all data nodes involved in the current SQL statement.

```shell
obclient> ALTER SYSTEM SET px_node_policy = "DATA" tenant = 'mysql';
```
