# standby_fetch_log_bandwidth_limit

## Overview

`standby_fetch_log_bandwidth_limit` specifies the total bandwidth available for log synchronization from the primary tenant or source tenant to all standby tenants in the cluster.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Capacity |
| Default Value | 0 MB: No traffic limit. |
| Value range | [0, 10000G] |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

When setting this parameter, you must specify a unit (B, KB, MB, GB, etc.). The unit is case-insensitive.

## Configuration example

Set the total bandwidth available for log synchronization from the primary tenant or source tenant to the standby tenant in the cluster where the standby tenant resides to 200 MB.

```shell
obclient> ALTER SYSTEM SET standby_fetch_log_bandwidth_limit = '200M';
```
