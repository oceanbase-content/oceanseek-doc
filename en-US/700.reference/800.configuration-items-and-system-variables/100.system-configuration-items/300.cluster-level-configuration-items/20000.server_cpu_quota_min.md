# server_cpu_quota_min

## Overview

`server_cpu_quota_min` specifies the minimum CPU quota that the system can use. The system automatically reserves this quota.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| ------------------ | ----------- |
| Parameter type | Double |
| Default Value | 0, |
| Value range | [0, 16] |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

When the value is 0, adaptive adjustment is performed based on the server's `cpu_count`:

1. If `cpu_count` < 8c, then `server_cpu_quota_min` is adaptively adjusted to 1c;
2. If 8c ≤ `cpu_count` < 16c, then `server_cpu_quota_min` is adaptively adjusted to 2c;
3. If 16c ≤ `cpu_count` < 32c, then `server_cpu_quota_min` is adaptively adjusted to 3c;
4. If 32c ≤ `cpu_count`, then `server_cpu_quota_min` is adaptively adjusted to 4c.

## Configuration example

The system is configured to adaptively adjust the maximum CPU quota.

```shell
obclient> ALTER SYSTEM SET server_cpu_quota_max=0;
```
