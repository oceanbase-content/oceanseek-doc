# server_permanent_offline_time

## Overview

`server_permanent_offline_time` specifies the duration after which a node heartbeat is considered permanently lost. When a node's heartbeat is lost for this period, the Root Service processes the data replicas on that OBServer node, removes it from the Paxos member group, and replenishes the data on other available OBServer nodes to maintain the integrity of the Paxos member group.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| ------------------ | -------------- |
| Parameter type | Time |
| Default Value | 3600s |
| Value range | 20s, +∞) |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

By setting this parameter, unnecessary replica replication can be avoided. Data replica replication on the permanently offline node is initiated only after the replica loss duration exceeds the specified value.

The applicable scenarios and recommended values for this parameter are as follows:

* OceanBase AI Database version upgrade scenarios: It is recommended to set the value of this parameter to `72h`.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>When upgrading OceanBase AI Database to OCP V2.3.5 or later, the system automatically sets the value of this parameter to <code>72h</code>.</p>
  </main>

* Hardware replacement scenario for OBServer nodes: It is recommended to set the value of this parameter to `4h`.

* OBServer node clearance and online scenario: It is recommended to set the value of this parameter to `10m` to enable the cluster to go online quickly.

## Configuration example

Set the node heartbeat interruption time threshold to 3600s.

```shell
obclient> ALTER SYSTEM SET server_permanent_offline_time = '3600s';
```
