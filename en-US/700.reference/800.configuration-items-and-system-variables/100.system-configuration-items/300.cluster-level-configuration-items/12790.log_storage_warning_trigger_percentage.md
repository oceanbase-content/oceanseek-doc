# log_storage_warning_trigger_percentage

## Overview

`log_storage_warning_trigger_percentage` specifies the percentage of write performance that triggers a warning for log disk failure.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| ------------------ | ---------- |
| Parameter type | Int |
| Default Value | 0 |
| Value range | [0, 50]. A value less than 10 is recommended. |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No |

## Usage instructions

* The log disk failure detection algorithm continuously collects baseline data on log disk write performance, monitors the current log disk write performance, and compares it with the baseline. If the current write performance drops significantly compared to the baseline and does not return to normal within a period of time, the log disk is marked as faulty.
* The relationship between the `log_storage_warning_trigger_percentage` parameter and the [log_storage_warning_tolerance_time](12800.log_storage_warning_tolerance_time.md) parameter:

  * When the value of `log_storage_warning_trigger_percentage` is 0, performance data is not monitored. According to the original logic, if the log write-to-disk latency exceeds the value of the parameter `log_storage_warning_tolerance_time`, a log disk failure is detected.
  * When the value of `log_storage_warning_trigger_percentage` is greater than 0, a log disk failure is detected if the write performance of the current log disk drops below the baseline performance multiplied by `log_storage_warning_trigger_percentage` and the performance degradation persists for `log_storage_warning_tolerance_time` seconds.
  * `log_storage_warning_trigger_percentage` controls the percentage of write performance that triggers a warning for log disk failure. A higher value makes the fault detection algorithm more sensitive. `log_storage_warning_tolerance_time` controls the duration of performance degradation. This parameter affects the robustness of the detection algorithm; a higher value makes the algorithm more robust.

## Configuration example

Set the write performance percentage threshold for the log disk fault detection algorithm to 5 and the performance degradation duration threshold to 3 seconds. That is, if the log disk write performance drops below 5% of its baseline performance and persists for 3 seconds, a log disk fault is detected.

```shell
obclient> ALTER SYSTEM SET log_storage_warning_trigger_percentage = 5;
obclient> ALTER SYSTEM SET log_storage_warning_tolerance_time = '3s';
```
