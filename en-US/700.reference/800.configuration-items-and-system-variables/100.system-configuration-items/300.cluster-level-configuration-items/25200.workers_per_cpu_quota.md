# workers_per_cpu_quota

## Overview

`workers_per_cpu_quota` specifies the maximum number of [worker threads](../../../200.system-management/800.management-process/100.overview-of-oceanbase-threads.md) that a tenant can allocate to each CPU.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Int |
| Default Value | 10 |
| Value range | [2, 20] |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to Restart the OBServer Node for the Change to Take Effect | No, the setting takes effect immediately. |

## Usage instructions

The number of threads that can be processed concurrently in a tenant is controlled by the [cpu_quota_concurrency](../400.tenant-level-configuration-items/1800.cpu_quota_concurrency.md) and `workers_per_cpu_quota` parameters. The value of `workers_per_cpu_quota` must be greater than or equal to the value of `cpu_quota_concurrency`.

Where:

* `workers_per_cpu_quota`: The maximum number of worker threads that a tenant can allocate to each CPU.

* `cpu_quota_concurrency`: the maximum number of active threads allowed for each CPU quota of a tenant, that is, the concurrency level.

## Configuration example

Set the maximum number of worker threads that a tenant can allocate per CPU to 10.

```shell
obclient> ALTER SYSTEM SET workers_per_cpu_quota = 10;
```
