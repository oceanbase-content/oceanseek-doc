# syslog_compress_func

## Overview

`syslog_compress_func` is used to set the compression algorithm for system [logs](../../../../600.manage/800.logging/100.logging-overview.md).

When the compression feature is enabled, four timestamped log files—`observer.log`, `rootservice.log`, `election.log`, and `trace.log`—will be compressed. The corresponding files with the `.wf` suffix will not be compressed.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | String |
| Default Value | none: Do not compress system log files. |
| Value range | none, zstd_1.0, zstd_1.3.8 |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* After the log compression algorithm is configured, log compression does not start immediately. Instead, it waits until the number of logs or disk usage reaches the specified limit, then compresses from the oldest log file. This retains more uncompressed logs, facilitating log analysis and troubleshooting.

* After the value of `syslog_compress_func` is modified, subsequent logs will be compressed using the new algorithm. Existing compressed log files do not need to be changed. When deleting log files, only timestamps are compared; file extensions are not distinguished.

* **Relationship between the `syslog_compress_func` parameter and the [syslog_file_uncompressed_count](22060.syslog_file_uncompressed_count.md), [syslog_disk_size](22050.syslog_disk_size.md), and [max_syslog_file_count](13300.max_syslog_file_count.md) parameters:**

  * `syslog_compress_func =none`:

    1. The value of `syslog_file_uncompressed_count` is invalid;
    2. `syslog_disk_size` and `max_syslog_file_count` jointly control the upper limit on log files, enforcing both quantity and size constraints.

  * `syslog_compress_func !=none`:

    1. The value of `max_syslog_file_count` is invalid;
    2. Compress the logs that exceed the value of `syslog_file_uncompressed_count`. Start deleting the oldest logs when the total size approaches the value of `syslog_disk_size`.

## Configuration example

Set the system log compression algorithm to zstd_1.3.8.

```shell
obclient> ALTER SYSTEM SET syslog_compress_func = 'zstd_1.3.8';
```
