# migration_disable_time

## Overview

`migration_disable_time` specifies the cooldown period during which the system prohibits new data migration operations on a node after a data migration fails due to resource exceptions (such as disk space exhaustion).

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Time |
| Default Value | 3600s |
| Value range | [1s, +∞) |
| Modifiable | Yes, you can use the following methods:`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Configuration example

The cooldown period for prohibiting new data migration operations after a node fails to complete data migration due to resource exceptions (such as disk space exhaustion) is set to 3,600 seconds.

```shell
obclient> ALTER SYSTEM SET migration_disable_time = 3600s;
```
