# rpc_client_authentication_method

## Overview

`rpc_client_authentication_method` specifies the authentication method for the RPC client.

For the `sys` tenant, you only need to set the authentication scheme via commands on both the client and server sides.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| ------ | ------ |
| Parameter type | String |
| Default Value | NONE |
| Value range | <ul> <li>NONE: The default authentication method for the client, which means no authentication is performed.</li> <li>SSL_NO_ENCRYPT: Uses a local SSL certificate and private key to complete authentication via the SSL handshake, but subsequent communications are not encrypted.</li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to Restart OBServer for the Change to Take Effect | No, the setting takes effect immediately. |

## Usage instructions

* On the server side, you need to configure the <code>rpc_server_authentication_method</code> parameter. For more information, see [rpc_server_authentication_method](19100.rpc_server_authentication_method.md).
* If the parameter value is set correctly, the latest configuration takes effect. Otherwise, the original authentication method remains unchanged and this configuration does not take effect.
* You can configure only one authentication method at a time. The default value is <code>NONE</code>. This parameter is case-insensitive.

## Configuration example

Set the security authentication method for the RPC client to NONE.

```shell
obclient> ALTER SYSTEM SET rpc_client_authentication_method = 'NONE';
```
