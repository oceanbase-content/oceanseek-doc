# rpc_server_authentication_method

## Overview

`rpc_server_authentication_method` specifies the authentication method for the RPC server.

For the `sys` tenant, you only need to set the authentication scheme via commands on both the client and server sides.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| ------ | ------ |
| Parameter type | String |
| Default Value | ALL |
| Value range | <ul> <li> NONE: No authentication is performed. For scenarios with high security requirements, it is recommended to disable this option on the server side.`NONE`</li> <li>ALL: The default authentication method on the server, which means it supports any authentication method (NONE, SSL_NO_ENCRYPT).</li> <li>SSL_NO_ENCRYPT: Uses a local SSL certificate and private key to complete authentication via an SSL handshake, but subsequent communications are not encrypted.</li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to Restart OBServer for the Change to Take Effect | No, the setting takes effect immediately. |

## Usage instructions

1. On the client, you need to configure the `rpc_client_authentication_method` parameter. For more information, see [rpc_client_authentication_method](18900.rpc_client_authentication_method.md).

2. The server supports configuring multiple authentication methods simultaneously. When setting multiple authentication methods at once, separate them with commas (,). This parameter is case-insensitive.

   ```sql
   ALTER SYSTEM SET rpc_server_authentication_method = 'NONE, SSL_NO_ENCRYPT';
   ```

3. If all parameter values are set correctly, the latest configuration will take effect; otherwise, the original authentication method will remain in effect and this configuration will not take effect.
   For example, if the original authentication method is `NONE` and you try to set it to `alter system set rpc_server_authentication_method = 'SSL_NO_ENCRYPT, ANY';` (but `ANY` is not a valid value), this configuration will not take effect, and the server authentication method will remain `NONE`.

4. The following table describes the client types that are allowed based on the server-side parameter values:

   |Server Parameter Value|Client Types Allowed|
   |-------------|----------------- |
   |NONE         |<ul> <li>Old clients that have not been upgraded (including unauthenticated clients)</li> <li>New clients with the authentication method set to `NONE`</li></ul>|
   |SSL_NO_ENCRYPT|New client with authentication method `SSL_NO_ENCRYPT`|
   |ALL           |The sum of the above two cases|

## Configuration example

Set the security authentication method for the RPC server to ALL.

```shell
obclient> ALTER SYSTEM SET rpc_server_authentication_method = 'ALL';
```
