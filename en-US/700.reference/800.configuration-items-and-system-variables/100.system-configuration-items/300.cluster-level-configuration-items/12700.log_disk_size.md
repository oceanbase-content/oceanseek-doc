# log_disk_size

## Overview

`log_disk_size` specifies the size of the redo log disk, which is the total space of the log disk available to this OBServer node.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| --- | --- |
| Parameter type | Varchar |
| Default Value | 0. The default unit is MB. You must specify the unit when configuring it. |
| Value range | 0M, +∞) |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* When the value of this parameter is 0, log disk space is allocated based on the value set by the <code>log_disk_percentage</code> parameter. For more information about the <code>log_disk_percentage</code> parameter, see <a href="12600.log_disk_percentage.md">log_disk_percentage</a>.
* When an OBServer node starts, it pre-allocates a sufficient number of log files. For example, if you configure <code>log_disk_size = 100 G</code>, the OBServer node will pre-allocate 100 GB of log files as the log file pool upon its first startup.
* When creating a tenant unit on an OBServer node, sufficient log disk space is reserved for the unit. If the local remaining log disk space (total available log disk space - allocated space) does not meet the unit specification requirements, the creation of the tenant unit fails.

## Configuration example

Set the size of the redo log disk to 40 GB.

```shell
obclient> ALTER SYSTEM SET log_disk_size='40G';
```
