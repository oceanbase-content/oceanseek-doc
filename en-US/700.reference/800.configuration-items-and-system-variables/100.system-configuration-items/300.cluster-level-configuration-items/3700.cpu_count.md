# cpu_count

## Overview

`cpu_count` specifies the total number of CPU cores in the system.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter; user tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| ------------------ | ------------------ |
| Parameter type | Int |
| Default Value | 0: The system automatically detects the number of CPUs. |
| Value range | [0, +∞) |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

Other configurations in the cluster may affect how this parameter takes effect. After configuring this parameter, we recommend that you use the `SELECT` statement to view the actual effective value of the `CPU_CAPACITY` field in the internal [GV$OB_SERVERS](../../../../700.reference/700.system-views/300.system-view-of-sys-tenant/300.performance-view-of-sys-tenant/3200.gv-ob_servers-of-sys-tenant.md) table. If it does not take effect dynamically, you need to restart the entire cluster.

## Configuration example

Set the total number of system CPUs to 16.

```shell
obclient> ALTER SYSTEM SET cpu_count=16;
```
