# sql_protocol_min_tls_version

## Overview

`sql_protocol_min_tls_version` specifies the minimum version of the SSL/TLS protocol to be used for SSL connections when executing SQL statements.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| --- | --- |
| Parameter type | String |
| Default Value | none |
| Value range | <ul><li>none: no restrictions on the SSL/TLS version used by the connection.  </li><li>TLSv1 / TLSv1.1 / TLSv1.2 / TLSv1.3: when any of these versions are specified, if the connection chooses to use SSL encryption, it will use the specified version or higher.</li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

This parameter is used only to control the selection of the SSL version. To enable SSL, you must also use [ssl_client_authentication](20800.ssl_client_authentication.md) for configuration.

## Configuration example

Set the minimum SSL/TLS protocol version number to NONE for SQL statements used in SSL connections.

```shell
obclient> ALTER SYSTEM SET sql_protocol_min_tls_version = 'none';
```
