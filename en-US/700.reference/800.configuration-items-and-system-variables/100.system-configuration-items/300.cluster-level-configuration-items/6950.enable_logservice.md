# enable_logservice

## Overview

`enable_logservice` specifies whether to enable the log service mode.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  This parameter must be configured using the `-o` startup parameter on the OBServer node. It is specified when the cluster's RS node is first started and cannot be dynamically modified after taking effect. User tenants do not have permission to modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | ------- |
| Parameter type | Bool |
| Default Value | False |
| Value range | <ul><li>True: enabled. </li><li>False: disabled. </li></ul> |
| Modifiable | No. It is specified during the first startup and cannot be modified. |
| Whether to restart the OBServer node for the change to take effect | No, read-only is the only supported mode. |

## Usage instructions

During cluster expansion, the `enable_logservice` configuration of the new nodes must be consistent with that of the existing nodes in the cluster. Otherwise, it may cause abnormal log service status or failure of root service election. That is, the `enable_logservice` configuration must always be globally consistent across all nodes in the cluster.

## Configuration example

To start an OBServer node in logservice mode, specify the value of the `enable_logservice` parameter as True using the `-o` option on the command line.

```shell
./observer -P 42904 -p 42905
-z zone1
-n ob22.xxxx.qqq.xx.xx.xx.xx
-c 1
-o memory_limit=400G,enable_logservice=True
```
