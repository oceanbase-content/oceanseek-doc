# schema_history_recycle_interval

## Overview

`schema_history_recycle_interval` specifies the interval for executing the internal task to recycle multi-version records of schemas.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| ------------------ | ----------- |
| Parameter type | Time |
| Default Value | 10m indicates 10 minutes. |
| Value range | [0s, +∞)<main id="notice" type='explain'><h4>Note</h4><ul><li>A value of 0 disables the <code>schema</code> multi-version record reclamation task feature.</li> <li>A non-zero value specifies the time interval for executing the <code>schema</code> multi-version record reclamation task.</li></ul></main> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Configuration example

Set the system internal execution time interval for the `schema` multi-version record reclamation task to 10 minutes.

```shell
obclient> ALTER SYSTEM SET schema_history_recycle_interval = '10m';
```
