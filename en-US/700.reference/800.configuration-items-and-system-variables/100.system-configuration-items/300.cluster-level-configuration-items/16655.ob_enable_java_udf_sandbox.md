# ob_enable_java_udf_sandbox

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is available starting with V4.6.3. </p>
</main>

## Overview

`ob_enable_java_udf_sandbox` controls the execution mode of Java UDFs:

* When set to `TRUE`, the Java UDF runs in a separate sandbox process. The JVM runs in isolation from the observer main process, reducing the impact of Java UDF execution on the database main process.
* When set to `FALSE`, the Java UDF is embedded in the observer process for execution via JNI.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| ----------- | --------------- |
| Parameter type | Bool |
| Default Value | FALSE |
| Value range | TRUE/FALSE |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* This parameter must be used together with [ob_enable_java_udf](../400.tenant-level-configuration-items/5860.ob_enable_java_udf.md) and [ob_enable_java_env](16630.ob_enable_java_env.md). After enabling `ob_enable_java_udf` and `ob_enable_java_env`, you can decide whether to enable `ob_enable_java_udf_sandbox` as needed to enable sandbox isolation.

* We recommend that you enable this parameter for public cloud deployment scenarios to enhance the security and stability of Java UDF execution and prevent JVM exceptions from affecting the observer main process.

## Configuration example

* Enable Java UDF sandbox mode

  ```sql
  obclient> ALTER SYSTEM SET ob_enable_java_udf_sandbox = TRUE;
  ```

* Disable Java UDF sandbox mode.

  ```sql
  obclient> ALTER SYSTEM SET ob_enable_java_udf_sandbox = FALSE;
  ```
