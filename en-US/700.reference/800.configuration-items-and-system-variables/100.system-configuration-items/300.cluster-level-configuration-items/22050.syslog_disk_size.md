# syslog_disk_size

## Overview

`syslog_disk_size` specifies the maximum disk space for system [logs](../../../../600.manage/800.logging/100.logging-overview.md). When the total size of system logs approaches this limit, the oldest log files, including compressed ones, are deleted.

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Only the `sys` tenant can modify this parameter. User tenants cannot modify it.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | CAP |
| Default Value | 0M indicates that disk space reclamation is disabled. |
| Value range | [0, +∞) |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* The system log files stored by this parameter include all uncompressed and compressed log files in the `{install_path}/log` directory.

* The `syslog_disk_size` parameter is calculated based on the `du -sh (disk usage)` principle, which only counts the total number of disk blocks occupied by all files in the log directory. This is different from the `df -h (disk free)` method, which displays the usage of the entire disk partition (including metadata and cache) and counts files that have been deleted but are still being used by processes.

* The relationship between the `syslog_disk_size` parameter and the [max_syslog_file_count](13300.max_syslog_file_count.md) parameter:

  1. `max_syslog_file_count=0`, `syslog_disk_size=0`: No log recycling is performed until the disk is full.
  2. `max_syslog_file_count=0`, `syslog_disk_size>0`: When the total log size approaches `syslog_disk_size`, start deleting the oldest log files to reclaim space;
  3. `max_syslog_file_count>0`, `syslog_disk_size=0`: When the number of a certain type of log file exceeds `max_syslog_file_count`, the oldest log files are deleted to reclaim space;
  4. `max_syslog_file_count>0`, `syslog_disk_size>0`: When the number of a certain type of log file exceeds `max_syslog_file_count`, or when the total log size approaches `syslog_disk_size`, the oldest compressed files are deleted.

## Configuration example

Set the disk space for system logs to 50 GB.

```shell
obclient> ALTER SYSTEM SET syslog_disk_size='50GB';
```
