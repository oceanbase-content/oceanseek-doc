# enable_sql_plan_monitor

## Overview

`enable_sql_plan_monitor` specifies whether the SQL statements of the current session are recorded in SQL Plan Monitor.

## Privilege requirements

* Query variables

  Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Attributes

| **Attribute** | **Description** |
| ----------- | --------------- |
| Parameter type | Bool |
| Default Value | False |
| Value range | <ul><li>False: The SQL of the current session is added to the SQL plan monitor only if any of the following conditions is met:<ul><li>A specific hint is used to enable monitoring.</li><li>The SQL execution time exceeds a preset threshold.</li><li>The SQL execution uses parallel processing with a degree of parallelism greater than 1.</li></ul></li><li>True: All SQL statements executed by the current session are automatically recorded in the SQL plan monitor without any additional conditions.</li></ul> |
| Effective Scope | Session |
| Modifiable | Yes, you can use the following methods:`SET`Statement modification. |

## Configuration example

SQL statements executed in the current session are recorded in the SQL plan monitor.

```shell
obclient> SET  enable_sql_plan_monitor =True;
```
