# cursor_sharing

## Overview

`cursor_sharing` determines whether to parameterize SQL statements during processing.

## Privilege requirements

* Query variables

  * Global level

    The `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

  * Session level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

  * Session expiration

    The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Attributes

| Attribute | Description |
| ---------- | ----------------------- |
| Parameter type | enum |
| Default Value | FORCE |
| Value range | <ul><li>FORCE: Indicates that parameterization is required when processing the SQL statement. </li><li>EXACT: Indicates that parameterization is not required when processing the SQL statement. </li></ul> |
| Effective Scope | <ul><li>Global </li><li>Session </li></ul> |
| Modifiable | Yes, you can use the following methods:`SET`Statement modification. |

## Configuration example

Set to parameterize SQL processing.

* Effective globally

  ```shell
  obclient> SET GLOBAL cursor_sharing ='FORCE';
  ```

* Session expiration

  ```shell
  obclient> SET cursor_sharing ='FORCE';
  ```
