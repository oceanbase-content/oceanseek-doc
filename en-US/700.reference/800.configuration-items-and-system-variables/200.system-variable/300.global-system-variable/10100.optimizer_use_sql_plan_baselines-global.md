# optimizer_use_sql_plan_baselines

## Overview

`optimizer_use_sql_plan_baselines` controls whether the optimizer uses plan baselines.

## Privilege requirements

* Query variables

  * Global level

    The `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

  * Session level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

  * Session expiration

    The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Attributes

| **Attribute** | **Description** |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Parameter type | Bool |
| Default Value | 0 |
| Value range | <ul><li> 0: When generating a new plan, the optimizer does not consider the plan in the plan baseline and directly generates and executes a new plan. </li><li>1: When generating a new plan, the optimizer preferentially uses the plan in the plan baseline. A new plan is used only after it passes verification. </li></ul> |
| Effective Scope | <ul><li>Global </li><li>Session </li></ul> |
| Modifiable | Yes, you can use the`SET`Statement modification. |

## Configuration example

Sets the optimizer not to use plan baselines.

* Effective globally

  ```shell
  obclient> SET GLOBAL optimizer_use_sql_plan_baselines = 0;
  ```

* Session expiration

  ```shell
  obclient> SET optimizer_use_sql_plan_baselines = 0;
  ```
