# cardinality_estimation_model

## Overview

The `cardinality_estimation_model` parameter specifies the correlation assumption used by the optimizer for cardinality estimation.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Before introducing this option into the production environment, ensure it has been thoroughly tested.</p>
</main>

## Privilege requirements

* Query variables

  * Global level

    The `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

  * Session level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

  * Session expiration

    The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Attributes

| **Attribute** | **Description** |
| ----------- | --------------- |
| Parameter type | Enum |
| Default Value | PARTIAL |
| Value range | <ul><li>INDEPENDENT: Assumes that predicates are completely independent of each other.</li><li>PARTIAL: Assumes that predicates are partially correlated with each other.</li><li>FULL: Assumes that predicates are fully correlated with each other.</li></ul><main id="notice" type='explain'><h4>Note</h4><p>In most scenarios, the estimated row sizes for the three correlations increase in order: INDEPENDENT < PARTIAL < FULL.</p></main> |
| Effective Scope | <ul><li>Global</li><li>Session</li></ul> |
| Modifiable | Yes, you can use the`SET`Statement modification. |

## Configuration example

Under the three correlation assumptions, the estimated row counts for `t1` after filtering with the base table predicate are `10`, `31`, and `98` respectively.

1. Create table `t1`.

   ```shell
   obclient [test]> create table t1(c1 int, c2 int);
   Query OK, 0 rows affected (0.103 sec)
   ```

2. Insert data into table `t1`.

   ```shell
   obclient [test]> insert into t1 select row_number() over () % 10, row_number() over () % 100 from table(generator(10000));
   Query OK, 10000 rows affected (0.077 sec)
   Records: 10000  Duplicates: 0  Warnings: 0
   ```

3. Analyze table `t1`.

   ```shell
   obclient [test]> analyze table t1;
   Query OK, 0 rows affected (0.073 sec)
   ```

4. Set the correlation assumption to `INDEPENDENT` and perform cardinality estimation.

   ```shell
   obclient [test]> set cardinality_estimation_model = 'independent';
   Query OK, 0 rows affected (0.001 sec)
   ```

5. Query the cardinality estimation result.

   ```shell
   obclient [test]> explain select * from t1 where c1 = 1 and c2 = 1;
   ```
