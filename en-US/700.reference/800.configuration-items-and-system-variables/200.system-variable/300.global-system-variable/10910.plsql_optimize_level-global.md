# plsql_optimize_level

`plsql_optimize_level` specifies the optimization level during PL code compilation.

## Privilege requirements

* Query variables

  Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Overview

| Attribute | Description |
| ------------------ | ------------------------------------ |
| Parameter type | Int |
| Default Value | 0 |
| Value range | [0,3]<ul><li>0: Disable both frontend and backend optimizations. This results in the shortest compilation overhead and time, but may increase execution time.</li><li>1: Disable frontend optimization and enable backend optimization. This significantly reduces compilation overhead and time, but may slightly increase execution time.</li><li>2: Enable both frontend and backend optimizations for balanced compilation and execution performance. This is the default optimization behavior.</li><li>3: Attempt to enable more optimization strategies for potential additional performance improvements. |
| Effective Scope | <ul><li>Global  </li><li>Session </li></ul> |
| Modifiable | Yes, you can use the`SET`or`ALTER SYSTEM SET`Statement modification. |

## Usage instructions

A higher optimization level instructs the compiler to perform more optimization steps. We recommend that you set `plsql_optimize_level = 2`.

## Configuration example

* Set the PL optimization level globally to `1`, which disables frontend optimization and enables backend optimization.

  ```shell
  obclient> SET GLOBAL plsql_optimize_level = 1;
  ```

* Set the PL optimization level globally to `2` to enable both frontend and backend optimizations.

  ```shell
  obclient> SET GLOBAL plsql_optimize_level = 2;
  ```
