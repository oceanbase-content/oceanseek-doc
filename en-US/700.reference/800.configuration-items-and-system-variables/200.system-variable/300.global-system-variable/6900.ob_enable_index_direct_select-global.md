# ob_enable_index_direct_select

## Overview

`ob_enable_index_direct_select` specifies whether users are allowed to directly query index tables.

## Privilege requirements

* Query variables

  * Global level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

  * Session level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

  * Session expiration

    The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Attributes

| **Attribute** | **Description** |
| ---------- | ---------------------------- |
| Parameter type | Bool |
| Default Value | 0 |
| Value range | <ul><li>0: not allowed</li> <li>1: allowed</li></ul> |
| Effective Scope | <ul><li>Global</li> <li>Session </li></ul> |
| Modifiable | Yes, you can use the`SET`Statement modification. |

## Configuration example

Set to prevent users from directly querying index tables.

* Session expiration

  ```shell
  obclient> SET ob_enable_index_direct_select =0;
  ```

* Effective globally

  ```shell
  obclient> SET GLOBAL ob_enable_index_direct_select =0;
  ```
