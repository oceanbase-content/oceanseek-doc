# secure_file_priv

## Overview

`secure_file_priv` controls the paths that can be accessed when importing or exporting to files.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The <code>log/alert</code> directory is in the allowlist of file access privileges for the system tenant. This directory can be skipped when checking the <code>secure_file_priv</code> privilege.</p>
</main>

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>For security reasons, only a client connected via a local Unix socket can execute SQL statements that modify this global variable.</p>
</main>

## Privilege requirements

* Query variables

  Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

## Attributes

| **Attribute** | **Description** |
| ----------- | --------- |
| Parameter type | Varchar |
| Default Value | "" indicates an empty string. |
| Value range | <ul><li>Empty string: Import and export are disabled. </li><li>`NULL`: Import and export are disabled.  </li><li>`"NULL"`: Indicates that import and export are disabled.  </li><li>Path name: Indicates that only files in this path can be imported or exported.  </li><li>`"/"`: No restrictions. Any path is accessible.  </li></ul> |
| Effective Scope | Global |
| Modifiable | Yes, you can use the`SET`Statement modification. |
| Nullable | Yes |

## Usage instructions

**Only local Unix socket connections are supported for connecting to OceanSeek.**

```shell
obclient -S /home/admin/oceanbase/run/sql.sock -u******@obtenant -p******
```

If the current user is different from the user who started the OBServer, the current user does not have permission on `sql.sock`. You need to connect using the following command.

```shell
sudo -u <user of observer> obclient -S /home/admin/oceanbase/run/sql.sock -u******@obtenant -p******
```

**The parameters are described as follows:**

* **-S**: The path to the Unix domain socket file of the local OBServer node, which is located in the run directory under the local OBServer installation directory. The default Unix domain socket file path is `/home/admin/oceanbase/run/sql.sock`.
* **-u**: the connection account for the tenant, in the format `username@tenant_name`.

When connecting via a Unix socket, you can only connect to a local OBServer node. You must also ensure that the tenant's resources are distributed on the local OBServer node. If the tenant's resources are not distributed on the local OBServer node, you cannot connect to the tenant through the local OBServer node.

## Configuration example

Set the accessible path for importing or exporting to a file as `""`.

```shell
obclient> SET GLOBAL secure_file_priv = "";
```
