# transaction_isolation

## Overview

The `transaction_isolation` parameter is used to set the transaction isolation level. It has the same functionality as the system variable `tx_isolation`. You can set either one of them.

## Privilege requirements

* Query variables

  * Global level

    The `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

  * Session level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

  * Session expiration

    The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Attributes

| **Attribute** | **Description** |
| --------- | ------------------------------------------------------------------ |
| Parameter type | Varchar |
| Default Value | READ-COMMITTED |
| Value range | <ul><li>`READ-COMMITTED`: Read Committed </li> <li>`REPEATABLE-READ`: Repeatable read</li> <li>`SERIALIZABLE`: serializable</li></ul> |
| Effective Scope | <ul><li> Global </li><li> Session </li></ul> |
| Modifiable | Yes, you can use the`SET`Statement modification. |

## Configuration example

Set the transaction isolation level to `READ-COMMITTED`.

* Session expiration

  ```shell
  obclient> SET transaction_isolation = 'READ-COMMITTED';
  ```

* Effective globally

  ```shell
  obclient> SET GLOBAL transaction_isolation = 'READ-COMMITTED';
  ```
