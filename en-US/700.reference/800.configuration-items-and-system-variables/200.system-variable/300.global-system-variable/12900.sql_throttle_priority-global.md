# sql_throttle_priority

## Overview

`sql_throttle_priority` specifies the priority for rate limiting. Only requests from sessions with a current priority lower than `sql_throttle_priority` are subject to throttling.

## Privilege requirements

* Query variables

  Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

* Modify variables

  * The `sys` tenant can directly modify the values of global system variables.

  * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

## Attributes

| **Attribute** | **Description** |
| -------- | --------------------------------------------------- |
| Parameter type | Int |
| Default Value | -1 |
| Value range | There is no specific value range. In practice, it is used together with`sql_throttle_current_priority`The value of this parameter is related to the values of the following parameters. |
| Effective Scope | Global |
| Modifiable | Yes, you can use the`SET`Statement modification. |

## Usage instructions

If the query priority is less than this value, the query may not be allowed to execute.

## Configuration example

Set the throttling priority to 1.

```shell
obclient> SET GLOBAL sql_throttle_priority = 1;
```
