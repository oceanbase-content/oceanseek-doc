# ob_compatibility_version

## Overview

`ob_compatibility_version` specifies the version of OceanBase Database to which the product behavior is compatible.

## Privilege requirements

* Query variables

  Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

* Modify variables

  * The `sys` tenant can directly modify the values of global system variables.

  * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

## Attributes

| **Attribute** | **Description** |
| ----------- | --------------- |
| Parameter type | Varchar |
| Default Value | 4.6.2.0 |
| Value range | 4.2.3.0 and later versions |
| Effective Scope | Global |
| Modifiable | Yes, you can use the following methods:`SET`or`ALTER SESSION SET`The statement can be modified later. |

## Usage instructions

* If the value of this variable is not explicitly specified when creating a tenant, its default value is the current `cluster_version`.

## Configuration example

* The feature for changing the product behavior specified during tenant creation is compatible with OceanBase AI Database V4.6.2.0.

  ```shell
  obclient> create tenant tenant_m57 zone_list=('z1'),primary_zone='z1',resource_pool_list=('pool1') set ob_compatibility_mode='MYSQL',ob_compatibility_version='4.6.2.0',ob_tcp_invited_nodes='%';
  ```

* The version of OceanBase AI Database compatible with the specified feature for tracking product behavior changes is V4.6.2.0.

  ```shell
  set global ob_compatibility_version ='4.6.2.0';
  ```
