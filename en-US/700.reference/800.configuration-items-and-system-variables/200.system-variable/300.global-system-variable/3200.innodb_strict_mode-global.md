# innodb_strict_mode

## Overview

`innodb_strict_mode` specifies the SQL check mode for specific syntax.

## Privilege requirements

* Query variables

  * Global level

    The `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

  * Session level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

  * Session expiration

    The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Attributes

| **Attribute** | **Description** |
| ----------- | --------------- |
| Parameter type | Bool |
| Default Value | 1 |
| Value range | <ul><li>1: Strict mode. When executing statements such as `CREATE TABLE`, `ALTER TABLE`, and `CREATE INDEX`, errors may occur in specific scenarios (for example, `ROW_FORMAT` is not supported). No warning is issued, and an error is returned directly. </li><li>0: Indicates that non-strict mode is used. Loose syntax checking is performed, and the default syntax is used to replace erroneous syntax. </li></ul> |
| Effective Scope | <ul><li>Global</li><li>Session</li></ul> |
| Modifiable | Yes, you can use the`SET`Statement modification. |

## Configuration example

Set the SQL check mode for specific syntax to 1.

* Effective globally

  ```shell
  obclient> SET GLOBAL innodb_strict_mode =1;
  ```

* Session expiration

  ```shell
  obclient> SET innodb_strict_mode =1;
  ```
