# sql_select_limit

## Overview

`sql_select_limit` specifies the maximum number of rows that a SELECT query is allowed to return. If a SELECT statement includes a LIMIT clause, the value in the LIMIT clause takes precedence over `sql_select_limit`. By default, the number of rows returned by a SELECT statement is not limited.

## Privilege requirements

* Query variables

  * Global level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement or the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

  * Session level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement or the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

  * Session expiration

    The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Configuration example

Specify that a `SELECT` query is allowed to return at most 100 rows.

* Session expiration

  ```shell
  obclient> SET sql_select_limit= 100;
  ```

* Effective globally

  ```shell
  obclient> SET GLOBAL sql_select_limit= 100;
  ```
