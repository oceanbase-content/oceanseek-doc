# ob_compatibility_mode

## Overview

`ob_compatibility_mode` specifies the compatibility mode for a tenant.

## Privilege requirements

* Query variables

  * Global level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

  * Session level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  After a tenant is created, its ID cannot be modified via SQL statements.

## Attributes

| **Attribute** | **Description** |
| ----------- | -------------------- |
| Parameter type | Enum |
| Default Value | MYSQL |
| Value range | <ul><li>MYSQL: Indicates compatibility with MySQL. </li></ul> |
| Effective Scope | <ul><li>Global </li><li>Session </li></ul> |
| Modifiable | No. This variable can be specified when creating a tenant, but cannot be modified via SQL statements after the tenant is created. |

## Configuration example

The following example shows how to create a tenant by specifying the value of the `ob_compatibility_mode` variable as `MYSQL`:

```shell
obclient> CREATE TENANT IF NOT EXISTS t1 zone_list = ('zone1'), primary_zone = 'zone1', resource_pool_list = ('pool1') SET ob_compatibility_mode = 'MYSQL',lower_case_table_names = 0;
```
