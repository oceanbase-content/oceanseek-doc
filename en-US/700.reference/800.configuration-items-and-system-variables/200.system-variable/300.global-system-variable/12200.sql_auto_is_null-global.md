# sql_auto_is_null

## Overview

`sql_auto_is_null` is used by some special drivers, such as ODBC, to control whether to fetch the auto-increment column value of the last inserted row.

## Privilege requirements

* Query variables

  * Global level

    The `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

  * Session level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

  * Session takes effect

    The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Usage instructions

Assume there is a table named `t1`, and its creation statement is as follows:

```shell
obclient> CREATE TABLE t1 (auto_inc_column auto_increment, j int);
```

When the value of `sql_auto_is_null` is `ON`, the following two statements are equivalent:

```shell
obclient> SELECT * FROM t1 WHERE auto_inc_column is null;
```

```shell
obclient> SELECT * FROM t1 WHERE auto_inc_column = last_insert_id();
```

## Configuration example

Set this parameter to allow direct queries using the `IS NULL` condition to retrieve the auto-increment column value of the last inserted row.

* Session level

  ```shell
  obclient> SET sql_auto_is_null = on;
  ```

* Global level

  ```shell
  obclient> SET GLOBAL sql_auto_is_null = on;
  ```
