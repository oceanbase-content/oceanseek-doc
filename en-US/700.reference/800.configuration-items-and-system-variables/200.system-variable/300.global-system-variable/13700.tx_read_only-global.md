# tx_read_only

## Overview

`tx_read_only` is used to control the read/write mode of a transaction, that is, whether the transaction is a read-only transaction.

## Privilege requirements

* Query variables

  * Global level

    The `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

  * Session level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.SESSION_VARIABLES` view to view the values of session system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

  * Session expiration

    The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Attributes

| **Attribute** | **Description** |
| --------- | ------------------------------------------- |
| Parameter type | Int |
| Default Value | 0 |
| Value range | <ul><li>`1`: read-only transaction</li> <li>`0`: Non-read-only transaction</li></ul> |
| Effective Scope | <ul><li>Global</li> <li>Session </li></ul> |
| Modifiable | Yes, you can use the`SET`Statement modification. |

## Usage instructions

After the system variable `tx_read_only` is successfully set:

* If it takes effect at the session level, it only affects the current user and does not affect other users.

* If it takes effect at the global level, it will affect all users on all subsequent new connections.

## Configuration example

Sets the transaction to read-only.

* Session effective

  ```shell
  obclient> SET tx_read_only = 1;
  ```

* Effective globally

  ```shell
  obclient> SET GLOBAL tx_read_only = 1;
  ```
