# resource_manager_plan

## Overview

The `resource_manager_plan` clause is used to activate a resource management plan. Different plans use different CPU quotas to limit user activity within a resource group.

## Privilege requirements

* Query variables

  Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

* Modify variables

  * The `sys` tenant can directly modify the values of global system variables.

  * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

## Attributes

| Attribute | Description |
| -------- | --------------- |
| Parameter type | Varchar |
| Default Value | "" |
| Effective Scope | Global |
| Modifiable | Yes, you can use the`SET`Statement modification. |
| Whether restart is required for the change to take effect | No, it takes effect within 10 seconds after the setting is configured. |

## Usage instructions

User threads and parallel execution threads within a tenant can preempt each other's CPU resources. By specifying a resource isolation plan for the tenant, you can control the resource preemption strategy and limit resource usage.

## Configuration example

Specify the resource management plan `daytime` for the tenant.

```shell
obclient> SET GLOBAL resource_manager_plan = 'daytime';
```
