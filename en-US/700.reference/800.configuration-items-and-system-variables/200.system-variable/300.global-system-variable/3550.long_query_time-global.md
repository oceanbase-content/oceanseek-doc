# long_query_time

## Overview

`long_query_time` specifies the threshold for identifying a slow query. Queries with an execution time exceeding this value will be recorded in the slow query log.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable is only for compatibility with MySQL. The related feature is not supported. You can query and set it, but the setting will not take effect without an error being returned.</p>
</main>

## Privilege requirements

* Query variables

  * Global level

    The `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement or the `information_schema.GLOBAL_VARIABLES` view (in MySQL-compatible mode) to view the values of global system variables.

  * Session level

    Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement or the `information_schema.SESSION_VARIABLES` view (in MySQL-compatible mode) to view the values of session system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * The user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

  * Session expiration

    The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Attributes

| **Attribute** | **Description** |
| -------- | --------- |
| Parameter type | Numeric |
| Default Value | 10, in seconds |
| Value range | [0, +∞) |
| Effective Scope | <ul><li>Global</li><li>Session</li></ul> |
| Modifiable | Yes, you can use the`SET`Statement modification. |

## Configuration example

Set the slow query threshold to 10s.

* Effective globally

  ```shell
  obclient> SET GLOBAL long_query_time=10;
  ```

* Session expiration

  ```shell
  obclient> SET long_query_time=10;
  ```
