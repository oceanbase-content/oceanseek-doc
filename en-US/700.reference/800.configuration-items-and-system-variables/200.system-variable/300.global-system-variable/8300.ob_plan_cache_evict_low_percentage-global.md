# ob_plan_cache_evict_low_percentage

## Overview

`ob_plan_cache_evict_low_percentage` specifies the percentage of the maximum memory that the cache can occupy before evictions begin.

## Privilege requirements

* Query variables

  Both the `sys` tenant and all user tenants can use the `SHOW VARIABLES` statement and the `information_schema.GLOBAL_VARIABLES` view to view the values of global system variables.

* Modify variables

  * The `sys` tenant can directly modify the values of global system variables.

  * You must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of a global system variable.

## Attributes

| **Attribute** | **Description** |
| ---------- | ---------------------------- |
| Parameter type | Int |
| Default Value | 50 |
| Value range | [0, 100] |
| Effective Scope | Global |
| Modifiable | Yes, you can use the following methods:`SET`Statement modification. |

## Usage instructions

The memory size for stopping the eviction plan cache (the low-watermark of the eviction plan) = Absolute upper memory limit × ob_plan_cache_evict_low_percentage/100. For information about the absolute upper memory limit, see [ob_plan_cache_percentage](../300.global-system-variable/8400.ob_plan_cache_percentage-global.md).

## Configuration example

Set the percentage of the memory upper limit that the cache for stop-mining plans occupies to 50.

```shell
obclient> SET GLOBAL ob_plan_cache_evict_low_percentage =50;
```
