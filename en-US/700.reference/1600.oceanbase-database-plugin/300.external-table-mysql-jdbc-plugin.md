# MySQL external table plugin

This topic describes how to install and use the external table JDBC plugin in OceanSeek. With this plugin, you can access data sources that support JDBC (currently only MySQL data sources).

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p><ul><li>OceanSeek supports the external table JDBC plugin service. It also provides the MySQL external table plugin based on the JDBC plugin service.</li><li>This feature is currently an experimental feature and is not recommended for use in a production environment.</li></ul></p>
</main>

## Limitations

* Data types: The `Array` data type is not supported.
* Query limitations:

  * Concurrent queries are not supported.
  * `JOIN` operations between multiple tables from the same data source are not pushed down to the data source as a single SQL statement.
  * Aggregation functions and `LIMIT` are not pushed down.

* Dependency management: JAR packages cannot be dynamically loaded. They must be placed in the specified directory before the process starts.
* Timeout settings: Query timeout cannot be configured through plugins.
* Parameter modification: The `PARAMETERS` attribute of a table cannot be modified; a new table must be created.

## Prerequisites

* OceanSeek has been deployed, and a MySQL mode user tenant has been created.
* JDK (version 11 or later) has been installed, and the `JAVA_HOME` environment variable has been configured.

## Configure the path of the MySQL external table plugin JAR package

Download the MySQL external table plugin JAR package from [MySQL external table plugin download address](https://github.com/oceanbase/oceanbase-plugins/releases/download/external-v1.0.0/oceanbase-external-plugin-1.0.0-jar-with-dependencies.jar) and place it in the specified directory (the `ob_java_connector_path` directory).

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>The OBServer service, which runs as the <code>admin</code> user, must have read and write permissions on the configured directory.</p>
</main>

**Here is an example:**

1. Create a directory to store the JAR package.

    ```shell
    mkdir -p /jdbc/plugin/jar/package/directory
    ```

2. Navigate to the directory.

    ```shell
    cd /jdbc/plugin/jar/package/directory
    ```

3. Download the MySQL external table plugin JAR package.

    ```shell
    wget https://github.com/oceanbase/oceanbase-plugins/releases/download/external-v1.0.0/oceanbase-external-plugin-1.0.0-jar-with-dependencies.jar
    ```

## Configure OceanSeek parameters (effective after restart)

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If you are using the JAVA SDK for the first time, you do not need to restart the observer process.</p>
</main>

1. Enable Java.

    **Here is an example:**

    ```sql
    ALTER SYSTEM SET ob_enable_java_env = true;
    ```

    For more information about this setting, see [ob_enable_java_env](../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16630.ob_enable_java_env.md).

2. Set the Java home directory for the current OBServer node.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>This path is the HOME directory of the JDK. Set it to <code>$JAVA_HOME</code> in the environment.</p>
    </main>

    **Here is an example:**

    ```sql
    ALTER SYSTEM SET ob_java_home = "/java/home/path";
    ```

    For more information about this setting, see [ob_java_home](../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md).

3. Set the directory for the JDBC plugin JAR package.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>Only the directory of the MySQL external table plugin JAR package needs to be set. The JAR package name does not need to be specified, and the JAR packages in the directory are automatically expanded.</p>
    </main>

    **Here is an example:**

    ```sql
    ALTER SYSTEM SET ob_java_connector_path = "/jdbc/plugin/jar/package/directory";
    ```

    For more information about this setting, see [ob_java_connector_path](../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob_java_connector_path.md).

4. Set the relevant Java environment startup parameters.

    1. Create the corresponding log folder path.

        ```shell
        mkdir -p /home/user/jvmlogs
        mkdir -p /home/user/jvmlogs/heapdumps
        ```

    2. Set the JVM startup parameters for Java execution.

        **Here is an example:**

        ```sql
        ALTER SYSTEM SET ob_java_opts = "-Djdk.lang.processReaperUseDefaultStackSize=true -XX:+HeapDumpOnOutOfMemoryError -Xrs -Xmx2048m -Xms2048m -Xloggc:/home/user/jvmlogs/gc.log -XX:+PrintGCDetails -XX:+PrintGCDateStamps -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/home/user/jvmlogs/heapdumps/ -XX:+UseGCLogFileRotation -XX:NumberOfGCLogFiles=10 -XX:GCLogFileSize=100M -XX:+UseG1GC  -XX:-CriticalJNINatives --add-opens=java.base/java.nio=org.apache.arrow.memory.core,ALL-UNNAMED -Darrow.allocation.manager.type=Netty";
        ```

        For more information about this setting, see [ob_java_opts](../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16650.ob_java_opts.md).

        <main id="notice" type='notice'>
          <h4>Notice</h4>
          <p><ul><li>Changing this parameter requires restarting the observer process. Because the data stream is directly copied to the C++ memory heap, you can appropriately reduce the <code>-Xmx2048m -Xms2048m</code> settings.</li><li>The corresponding GC log files are generated only if the configured log folder path exists. If the path does not exist, the related log files are not generated.</li></ul></p>
        </main>

5. Restart OceanSeek and check whether the plugin is installed successfully.

    **Here is an example:**

    ```sql
    SELECT *
    FROM oceanbase.GV$OB_PLUGINS
    WHERE TYPE = 'EXTERNAL TABLE'
    AND STATUS = 'READY';
    ```

    The returned result is as follows:

    ```shell
    +--------------+----------+-------+--------+----------------+---------+-----------------+------------------+-------------------+-----------------------+---------------+-----------------------------------------------------+
    | SVR_IP       | SVR_PORT | NAME  | STATUS | TYPE           | LIBRARY | LIBRARY_VERSION | LIBRARY_REVISION | INTERFACE_VERSION | AUTHOR                | LICENSE       | DESCRIPTION                                         |

    | 127.0.0.1    |    55803 | mysql | READY  | EXTERNAL TABLE | NULL    | 0.1.0           | NULL             | 0.2.0             | OceanBase Corporation | Mulan PubL v2 | This is a java external data source                 |
    ```

    In the result, `java` is the general implementation of the Java external table plugin, `jdbc` is a Java JDBC data source implemented based on the Java plugin, and `mysql` is a MySQL JDBC data source implemented based on the `jdbc` plugin.

## Data types

MySQL databases support a variety of data types, but the MySQL external table plugin of OceanSeek does not fully support all of them. The following table lists the data types supported by the MySQL external table plugin of OceanSeek in the current version:

* Integer types: `TINYINT`, `SMALLINT`, `MEDIUMINT`, `INT`, and `BIGINT` (including `UNSIGNED`).
* Floating-point types: `FLOAT`, `DOUBLE`, and `DECIMAL`.
* String types: `CHAR` and `VARCHAR`.
* Text types: `TEXT` and `CLOB`.
* Binary types: `BINARY`, `VARBINARY`, and `BLOB`.
* Date and time types: `DATE`, `TIME`, `DATETIME`, `TIMESTAMP`, and `YEAR`.
* Boolean type: `BOOLEAN`.
* Spatial types: related to `GIS`.
* Other types: `JSON`, `ENUM`, and `SET`.

## Predicate pushdown rules

To improve data access efficiency, OceanSeek supports pushing down some predicates to the remote MySQL database.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Here, a predicate refers to the <code>WHERE</code> condition in SQL, which is sometimes also called a filter or predicate.</p>
</main>

The supported predicates are subject to the following conditions:

* Data types: Integer, floating-point (in some scenarios), and string (excluding `CHAR`).
* Operators: `=`, `!=(<>)`, `<=`, `<`, `>=`, `>`, `IS [NOT] NULL`, `[NOT] IN`, `[NOT] LIKE`, and `[NOT] BETWEEN`.
* Combined expressions: `AND`, `OR`, and `NOT`.

## Upgrade the system

For an existing OceanSeek cluster, you can install or upgrade the plugin by restarting each node one by one.

We recommend that you perform the following steps:

1. Place the new version of the plugin JAR package in the specified directory (the directory pointed to by the `ob_java_connector_path` parameter).
2. Restart each node one by one and check whether the node has loaded the plugin.
3. After the OceanSeek cluster is restarted, check whether the plugin is installed.
