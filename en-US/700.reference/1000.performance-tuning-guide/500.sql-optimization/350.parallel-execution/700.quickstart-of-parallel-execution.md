# Quick start of parallel execution

Parallel execution is a deep and complex topic that requires a certain period of study before you can accurately understand the mechanisms of concurrent operations and fully leverage its capabilities. To help beginners quickly grasp the essentials of parallel execution, we provide an introductory practice guide. Although the parameters provided in this article are not optimal choices, they can effectively avoid most adverse situations, enabling beginners to more easily apply parallel execution features.

## Initialize the environment

Set the following parameters under the AP tenant:

```sql
SET GLOBAL parallel_servers_target = MIN_CPU * 20;
```

Here, `MIN_CPU` represents the lower limit of CPU specifications. For detailed information on setting the parallel query queue conditions for each server, see [parallel_servers_target](../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/10600.parallel_servers_target-global.md).

## Collect statistics

After importing data, you can directly call the DBMS statistics package to collect statistics.

For more information about statistics, see [Overview of statistics](../400.sql-optimization/400.optimizer-statistics/100.statistics-overview.md).

## Set hints

The degree of parallelism (DOP) for each SQL statement should not exceed 1.5 times the number of physical CPUs.

Generally, if multiple SQL statements are not executed concurrently, the DOP for a single SQL statement can be set to the number of CPUs. For example, if the system has 32 physical CPUs, set the hint to `/*+ PARALLEL(32) */`.

## Performance tuning

1. Use `top -H` to view the tenant's CPU usage.

## FAQ

1. The performance of a Query does not meet expectations; the CPU is not fully utilized?
   Run `show variables like 'parallel_servers_target'` to confirm that the target value is not less than `MIN_CPU` * 20.

2. PDML performance does not meet expectations?

   Use `explain extended` to explain the PDML statement and confirm whether the plan uses PDML. If PDML is not used, the `Note` field at the bottom of the plan will indicate the reason. This is usually because the modified table contains triggers, foreign keys, `local unique index`, or other reasons.

   If terms such as `DISTRIBUTED INSERT`, `DISTRIBUTED UPDATE`, or `DISTRIBUTED DELETE` appear, it means PDML was not used.

3. The business logic cannot be modified. How can I parallelize business SQL?

   OBProxy allows users to modify connection configurations via the web interface to enable parallelism. For example, on a read-write split connection, you can set the DOP for all SQL statements to 2.
