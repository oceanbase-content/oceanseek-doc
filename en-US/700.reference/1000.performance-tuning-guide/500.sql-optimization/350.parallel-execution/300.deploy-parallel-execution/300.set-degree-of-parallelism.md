# Set the degree of parallelism for parallel execution

The degree of parallelism (DOP) refers to the number of worker threads used by a single data flow operation (DFO) during execution.

Parallel execution is designed to efficiently utilize multi-core resources. The OceanBase parallel execution framework provides various ways to specify the DOP, allowing you to set it manually or let the database automatically choose it.

## Suggestions on DOP values

A simple principle is that the purpose of setting `PARALLEL` is to fully utilize CPU resources, not simply to pursue the maximum value.

### Examples

Assume the tenant has 20 CPUs:

- For simple single-table operations (such as single-table scan filtering, single-table insert, delete, and update), the theoretical value of `PARALLEL` can be set to 20.
- For multi-table `JOIN` queries and PDML with global indexes, the theoretical value of `PARALLEL` can be set to 10.
- For some more complex plans that are right-deep trees (i.e., parts of the operation tree on the right side are deeper), the theoretical value of `PARALLEL` can be set to around 7.

#### Example explanation

Assuming the current tenant has 20 CPUs:

- For single-table operations, there is only one DFO, and all 20 CPUs can be allocated to this DFO.

  For example, if this DFO spends most of its time performing I/O operations, you can set the DOP slightly higher, such as 25, to fully utilize the CPU.

  After tuning, for simple single-table operations (such as single-table scan filtering, single-table insert, delete, and update), the actual `PARALLEL` value is 30.

- For multi-table `JOIN`, two DFOs are started simultaneously to form a data pipeline (one DFO is the producer, and the other is the consumer). Therefore, 10 CPUs can be allocated to each DFO.

  In reality, it cannot be guaranteed that each DFO will use up all the CPUs allocated to it. Therefore, you can appropriately adjust the DOP, for example, to 15, to make more efficient use of the CPU. However, the DOP should not be increased indefinitely. Setting it to 50 does not bring substantial benefits; instead, it increases thread scheduling overhead and framework scheduling overhead.

  After tuning, for multi-table `JOIN` queries and PDML with global indexes, the actual `PARALLEL` value is 15.

- For right-deep tree plans, let's use a simple SQL query as an example to illustrate the situation:

   ```sql
   SELECT /*+ parallel(10) */ column1, column2
   FROM table1
   WHERE condition1;
   ```

   In this query, we use the `parallel(10)` hint, hoping the system will execute the plan with a DOP of 10. Assume the execution plan is as follows:

   ```plaintext
   ======================================================================
   | ID  | OPERATOR                 | NAME    | EST.ROWS  | EST.TIME(us)|
   ----------------------------------------------------------------------
   | 0   | SELECT STATEMENT          |         |         |              |
   | 1   |  PX COORDINATOR           |         |         |              |
   | 2   |   PX SEND QC (RANDOM)     | :EX10000|         |              |
   | 3   |    PX BLOCK ITERATOR      |         | N rows  |              |
   | 4   |     TABLE ACCESS (FULL)   | table1  | N rows  |              |
   ======================================================================
   ```

   In this execution plan, we can see that the right-deep tree part is on the right side of the operation tree, for example, the parts with operation symbols `PX SEND QC` and `PX BLOCK ITERATOR`. At this stage, multiple DFOs may be started, with each DFO responsible for a part of the execution plan.

   Suppose the system decides to start three DFOs simultaneously at a certain local level of this right-deep tree plan, with each DFO allocated 7 CPUs. The purpose of this is to ensure each DFO can fully utilize computing resources and improve overall query performance.

   After tuning, by setting the DOP to 10–15, we provide the system with a larger parallel execution space to accommodate the DOP requirements that different parts of the plan might need. Such adjustments can improve overall performance when processing large datasets or queries requiring high-degree parallel execution.

## Manually specify the DOP

You can manually specify the DOP for a table to ensure parallel execution is always used when scanning that table. The syntax is as follows.

### Specify the DOP by using table attributes

The following statements separately specify the scan DOP for the primary table and an index.

```sql
ALTER TABLE table_name PARALLEL 4;
ALTER TABLE table_name ALTER INDEX index_name PARALLEL 2;
```

If an SQL statement involves only one table, when the primary table is queried, all DFOs except the one where the primary table resides will use a DOP of 4. When an index table is queried, all DFOs except the one where the index table resides will use a DOP of 2.

If an SQL statement involves multiple tables, the maximum value of `PARALLEL` is used as the DOP for the entire plan.

### Specify the DOP by using the PARALLEL hint

You can use the global PARALLEL hint to specify the DOP for the entire SQL statement, or use the table-level PARALLEL hint to specify the DOP for a specific table. If the PARALLEL hint is given for multiple tables in an SQL statement, the DOP for each DFO containing those tables is determined by the respective table's `PARALLEL` value. If a DFO contains multiple tables, the maximum value of their PARALLEL settings is used as the DOP for that DFO.

### Specify the DOP at the session level

Once the DOP is specified for the current session, all query statements in that session will be executed with the specified DOP. Note that even single-row queries will use this DOP, which may result in performance degradation.

```sql
set _force_parallel_query_dop = 3;
```

For DML statements, using the preceding command only enables parallel execution for the query part of the DML statement; the write part remains serial. To enable parallel execution for both the query and write parts, use the following command:

```sql
set _force_parallel_dml_dop = 3;
```

When `_force_parallel_query_dop` is set to a value greater than 1, queries in the current session are executed with a DOP greater than 1. When `_force_parallel_query_dop` is set to 1, parallel execution is disabled for SQL statements in the current session.

Note that these settings apply globally to all queries in the session, including DML statements. Therefore, use them cautiously and understand their impact on the overall session execution.

## DOP priority

TABLE HINT > Global hint > Session-level DOP > Table DOP
