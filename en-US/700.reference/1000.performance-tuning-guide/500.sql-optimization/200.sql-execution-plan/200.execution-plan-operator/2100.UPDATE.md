# UPDATE

The `UPDATE` operator is used to update data rows in a data table that meet specified conditions.

OceanBase AI Database supports the `UPDATE` and `DISTRIBUTED UPDATE` operators.

## UPDATE

The `UPDATE` operator is used to update data in a single partition of a data table.

As shown in the following example, query Q1 updates all rows in table `t1` that satisfy `c2 = '100'` and sets the value of column `c2` to 200.

```sql
obclient> CREATE TABLE t1 (c1 INT PRIMARY KEY, c2 INT);
Query OK, 0 rows affected 

obclient> CREATE TABLE t2 (c1 INT PRIMARY KEY, c2 INT) PARTITION BY 
        HASH(c1) PARTITIONS 10;
Query OK, 0 rows affected 

obclient> CREATE TABLE t3 (c1 INT PRIMARY KEY, c2 INT);
Query OK, 0 rows affected 

obclient> CREATE INDEX IDX_t3_c2 ON t3 (c2) PARTITION BY HASH(c2) PARTITIONS 3;
Query OK, 0 rows affected 

Q1: 
obclient> EXPLAIN UPDATE t1 SET c2 = '200' WHERE c2 = '100';

Query Plan:
======================================
|ID|OPERATOR            |NAME|EST. ROWS|COST  |
-----------------------------------------------
|0 |EXCHANGE IN REMOTE  |    |990      |109687|
|1 | EXCHANGE OUT REMOTE|    |990      |109687|
|2 |  UPDATE            |    |990      |109687|
|3 |   TABLE SCAN       |T1  |990      |108697|
===============================================

Outputs & filters:
-------------------------------------
  0 - output(nil), filter(nil)
  1 - output(nil), filter(nil)
  2 - output(nil), filter(nil), table_columns([{T1: ({T1: (T1.C1, T1.C2)})}]),
      update([T1.C2=?])
  3 - output([T1.C1], [T1.C2], [?]), filter([T1.C2 = '100']),
      access([T1.C2], [T1.C1]), partitions(p0)
```

In the preceding example, the `outputs & filters` section of the execution plan shows the output information of the `UPDATE` operator as follows:

| **Information name** | **Description** |
| --------------- | ------------------------------------------------------------------------------------------------------------------- |
| output | The output columns of this operator. |
| filter | The filter predicate of this operator. In the example, no `filter` is set for the `UPDATE` operator, so the value is `nil`. For UPDATE statements, the predicate in the `WHERE` clause is pushed down to the base table. For example, in query Q1, `c2 = '100'` is pushed down to Operator 3. |
| table_columns | The columns of the data table involved in the update operation. |
| update | The assignment expressions in the update operation. |

## DISTRIBUTED UPDATE

The `DISTRIBUTED UPDATE` operator is used to update data in multiple partitions of a data table. As shown in the following example, query Q5 updates all data rows in table `t3` that satisfy `c2 < '100'` and sets the value of column `c2` to 200. Although `t3` itself is a non-partitioned table, it has a global index `idx_t3_c2`, so each data row exists in multiple partitions.

Q5:

```sql
obclient> EXPLAIN UPDATE t3 SET c2 = '200' WHERE c2 < '100';
```

The result is as follows:

```shell
+--------------------------------------------------------------------------------------------------------+
| Query Plan                                                                                             |
+--------------------------------------------------------------------------------------------------------+
| =======================================================================                                |
| |ID|OPERATOR                      |NAME         |EST.ROWS|EST.TIME(us)|                                |
| -----------------------------------------------------------------------                                |
| |0 |DISTRIBUTED UPDATE            |             |1       |61          |                                |
| |1 |└─DISTRIBUTED TABLE RANGE SCAN|T3(IDX_T3_C2)|1       |6           |                                |
| =======================================================================                                |
| Outputs & filters:                                                                                     |
| -------------------------------------                                                                  |
|   0 - output(nil), filter(nil)                                                                         |
|       table_columns([{T3: ({T3: (T3.C1, T3.C2)}, {IDX_T3_C2: (T3.C2, T3.C1)})}]),                      |
|       update([T3.C2=column_conv(VARCHAR2,utf8mb4_bin,length:10,NULL,cast('200', VARCHAR2(1048576 )))]) |
|   1 - output([T3.C1], [T3.C2]), filter(nil), rowset=256                                                |
|       access([T3.C1], [T3.C2]), partitions(p[0-2])                                                     |
|       is_index_back=false, is_global_index=true,                                                       |
|       range_key([T3.C2], [T3.C1]), range(MIN,MIN ; 100,MIN),                                           |
|       range_cond([T3.C2 < cast('100', VARCHAR2(1048576 ))])                                            |
+--------------------------------------------------------------------------------------------------------+
```

More examples of `DISTRIBUTED UPDATE` are as follows:

* Query Q6 updates data rows in partitioned table `t2` that satisfy `c1 = 100` and sets the value of column `c1` to 101. Since the updated column is the primary key column, the updated data rows may be in different partitions from the original data rows. Therefore, the `DISTRIBUTED UPDATE` operator is required for the update.

    Q6:

