# CPU-related parameters

| **Parameter** | **Description** | **Recommended value/range** |
| ----------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| work_thread_num | The number of OBProxy worker threads, which has a significant impact on CPU utilization. The default value is `128`. You must restart OBProxy after you modify this parameter. | You can adjust the value dynamically based on the environment. The upper limit of CPU usage of OBProxy is the value of `work_thread_num`. |
| task_thread_num | The number of threads for some background tasks, such as pulling rslist information. The default value is `2`. You must restart OBProxy after you modify this parameter. | We recommend that you keep the default value. |
| block_thread_num | The number of block threads. The default value is `1`. You must restart OBProxy after you modify this parameter. | We recommend that you keep the default value. |
| grpc_thread_num | The number of gRPC threads. The default value is `8`. You must restart OBProxy after you modify this parameter. | We recommend that you keep the default value. |
| net_accept_threads | The number of threads that execute the accept operation. The default value is `2`. You must restart OBProxy after you modify this parameter. | We recommend that you keep the default value. |
| automatic_match_work_thread | Specifies whether to ignore the specified `work_thread_num` and automatically adjust the number of threads based on the number of CPUs. If this parameter is set to `true`, the value of `work_thread_num` is used as the upper limit. The default value is `true`. You must restart OBProxy after you modify this parameter. | <ul><li>If <code>automatic_match_work_thread=false</code>, the value of the <code>work_thread_num</code> parameter is used.</li><li>If <code>automatic_match_work_thread=true</code>, the value of <code>MIN(number of CPU cores of the server, work_thread_num)</code> is used.</li></ul>For example, if the value of the <code>work_thread_num</code> parameter is set to a large value:<ul><li>For hybrid deployment, we recommend that you set <code>automatic_match_work_thread=true</code>.</li><li>For standalone deployment, you can set <code>automatic_match_work_thread=false</code> so that ODP occupies the entire server.</li></ul> |
| enable_compression_protocol | Specifies whether to disable compression to reduce the CPU usage of OBProxy. You must restart the OBProxy server for the change to take effect. | We recommend that you set this parameter to `False`. |

You can connect to the OceanBase AI Database cluster through port 2883 of OBProxy in the `sys` tenant, and use the `ALTER PROXYCONFIG SET` and `SHOW PROXYCONFIG LIKE` statements to modify and view the preceding parameters.

Here is an example:

```shell
obclient> ALTER PROXYCONFIG SET automatic_match_work_thread = False;
```

```shell
obclient> SHOW PROXYCONFIG LIKE 'work_thread_num';
```
