# CAST

## Declaration

```sql
CAST(expr AS type)
```

## Description

The `CAST()` function explicitly converts an expression of one data type to another, that is, it converts the value of the `expr` field to the `type` data type.

### Parameters

The parameters are described as follows:

* `expr`: any valid SQL expression.

* `AS`: Separates two parameters. The data before `AS` is the data to be processed, and the data after `AS` is the data type to be converted.

* `type`: The data type supported by the target system. Valid values:

  * `CHAR[(N)] [CHARACTER SET charset_name]`

    Generates a string of the `CHAR` data type. Unless the expression `expr` is empty (length 0), the result type is `CHAR(0)`. If an optional length `N` is specified, `CHAR(N)` will enforce conversion to use no more than `N` characters; values shorter than `N` characters will not be padded. If the optional length `N` is not specified, OceanSeek calculates the maximum length based on the expression. If there is no `CHARACTER SET charset_name` clause, `CHAR` generates a string with the default character set.

  * `DATE`: Generates a `DATE` value.

  * `DATETIME [ (M) ]`: Generates a `DATETIME` value. The `M` value is optional and specifies the precision of seconds in fractional form, with a range of \[0,6\].

  * `DECIMAL [ (M [,D] ) ]`: Generates a `DECIMAL` value. The `M` and `D` values are optional and specify the maximum number of digits (precision) and the number of decimal places, respectively. The maximum value for `M` is 65, and the maximum value for `D` is 30. If `D` is omitted, it defaults to `0`. If `M` is omitted, it defaults to `10`.

  * `SIGNED [INTEGER]`: Generates a signed `BIGINT` value.

  * `JSON`: Generates a `JSON` value. For conversion rules between JSON and other types, see [JSON data type conversion](../../../100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/800.json-formatted-data-type-of-mysql-mode/400.json-formatted-data-type-conversion-of-mysql-mode.md).

  * `TIME [ (M) ]`: Generates a `TIME` value. If the optional M value is provided, it specifies the precision of seconds in the fractional part.

  * `UNSIGNED [INTEGER]`: Generates an unsigned `BIGINT` value.
  * `DECIMAL(m,d)` : a fixed-point number type, where `m` indicates the total number of digits and `d` indicates the number of decimal places.
  * `FLOAT`: single-precision floating-point number, suitable for approximate values.
  * `BIGINT`: Explicitly converts the value of expression `expr` to the `BIGINT` type.
  * `INT` or `INTEGER`: a 32-bit signed integer.
  * `SMALLINT`: a 16-bit signed integer.
  * `TINYINT`: an 8-bit signed integer.
  * `ARRAY`: Converts the elements of a `JSON` array into an array of a specific type. Supports declaring array element types in the `ARRAY<element_type>` format, and also supports nested arrays, such as `ARRAY<ARRAY<INT>>`, which can be used to represent multidimensional array structures.

### Usage instructions

The `CAST` function supports the following data type conversions:

* The data types of the two expressions are exactly the same.

* The two expressions are implicitly convertible.

* Data types must be explicitly converted.
* When the value of expression expr exceeds the numeric range of the target data type, the type conversion returns `null`.
* Converting a high-precision data type to a low-precision data type will result in precision loss.
* Converting fixed-point numbers (`DECIMAL(m,d)`) or floating-point numbers (`DOUBLE`, `FLOAT`) to integers (`INT`/`INTEGER`, `SMALLINT`, or `TINYINT`) will result in precision loss.
* If the expression `expr` is of the `VARCHAR` type and not a numeric value, and is converted to the `INT`/`INTEGER`, `SMALLINT`, or `TINYINT` type, the result is `0`.
* If the expression `expr` is of the JSON type and not a numeric value, converting it to the `INT`/`INTEGER`/`SMALLINT`/`TINYINT` type will return an error.
* If the `VARCHAR` data or `JSON` data does not conform to the `ARRAY` format, an error will be reported during conversion.

When a user attempts an impossible conversion, OceanSeek displays an error message. If the length of a data type is not specified during conversion, the maximum internal length of OceanSeek is used. For example, `VARCHAR` is 262,143 bytes, and `NUMBER` is 65-bit floating-point precision.

The `CAST()` operator supports operations with signed and unsigned 64-bit values. If you use a numeric operator (such as `+`) and one of the operands is an unsigned integer, the result is unsigned. You can explicitly declare the result as a signed or unsigned 64-bit integer by using the `SIGNED` or `UNSIGNED` keyword. If either operand is a floating-point value, the result is a floating-point value.

## Examples

* Convert the numeric value 0 to the `DATE` type.

  ```sql
  obclient> SELECT CAST(0 AS DATE);
  +-----------------+
  | CAST(0 AS DATE) |
  +-----------------+
  | 0000-00-00      |
  +-----------------+
  1 row in set
  ```

* Convert the value 123 to the `TIME` type.

  ```sql
  obclient> SELECT CAST(123 AS TIME);
  +-------------------+
  | CAST(123 AS TIME) |
  +-------------------+
  | 00:01:23          |
  +-------------------+
  1 row in set
  ```

* Convert the value 123 to the `DATETIME` type.

  ```sql
  obclient> SELECT CAST(123 AS DATETIME(4));
  +--------------------------+
  | CAST(123 AS DATETIME(4)) |
  +--------------------------+
  | 2000-01-23 00:00:00.0000 |
  +--------------------------+
  1 row in set
  ```

* Convert the value 123 to the `DECIMAL` type.

  ```sql
  obclient>  SELECT CAST(123 AS DECIMAL(3,2));
  +---------------------------+
  | CAST(123 AS DECIMAL(3,2)) |
  +---------------------------+
  |                      9.99 |
  +---------------------------+
  1 row in set
  ```

* Convert the string "123" to the JSON type.

  ```sql
  obclient> SELECT CAST("123" AS JSON);
  +---------------------+
  | CAST("123" AS JSON) |
  +---------------------+
  | 123                 |
  +---------------------+
  1 row in set
  ```

* The results of "1-2" are represented using unsigned and signed formats, respectively.

  ```sql
  obclient> SELECT CAST(1-2 AS UNSIGNED), CAST(cast(1-2 AS UNSIGNED) AS SIGNED);
  +-----------------------+---------------------------------------+
  | CAST(1-2 AS UNSIGNED) | CAST(cast(1-2 AS UNSIGNED) AS SIGNED) |
  +-----------------------+---------------------------------------+
  |  18446744073709551615 |                                    -1 |
  +-----------------------+---------------------------------------+
  1 row in set
  ```

* Perform numeric operations using `CAST()`.

  ```sql
  obclient> SELECT CAST(1 AS UNSIGNED) - 2.0;
  +---------------------------+
  | CAST(1 AS UNSIGNED) - 2.0 |
  +---------------------------+
  |                      -1.0 |
  +---------------------------+
  1 row in set
  ```

* Convert the value 123 to the `CHAR` type.

  ```sql
  obclient> SELECT CAST(123 AS CHAR(2));
  +----------------------+
  | CAST(123 AS CHAR(2)) |
  +----------------------+
  | 12                   |
  +----------------------+
  1 row in set
  ```

* Convert the value 1 to the `CHAR` type and specify the character set.

  ```sql
  obclient> SELECT CAST(1 AS CHAR CHARACTER SET utf8mb4);
  +---------------------------------------+
  | CAST(1 AS CHAR CHARACTER SET utf8mb4) |
  +---------------------------------------+
  | 1                                     |
  +---------------------------------------+
  1 row in set
  ```

* Converts the character type `123` to an integer type, and converts the integer `1` to an `INT` type.

  ```sql
  obclient> SELECT CAST('123' AS INT),CAST(1 AS CHAR(10));
  +--------------------+---------------------+
  | CAST('123' AS INT) | CAST(1 AS INT) |
  +--------------------+---------------------+
  |                123 | 1                   |
  +--------------------+---------------------+
  1 row in set (0.035 sec
  ```

* Convert the `JSON` data [1,2,3] to `ARRAY` data, where the `ARRAY` data consists of `INT` type values. The statement is as follows:

  ```sql
  obclient> SELECT CAST('[1,2,3]' AS ARRAY<INT>);
  +-------------------------------------+
  | CAST('[1,2,3]' AS ARRAY<INT> |
  +-------------------------------------+
  | [1,2,3]                             |
  +-------------------------------------+
  1 row in set
  ```

* Convert the nested array of type `JSON` `[[1,2],[3,4]]` to nested `ARRAY<ARRAY<INT>>` data. The statement is as follows:

  ```sql
  obclient> SELECT CAST('[[1,2],[3,4]]' AS ARRAY<ARRAY<INT>>);
  +--------------------------------------------+
  | CAST('[[1,2],[3,4]]' AS ARRAY<ARRAY<INT>>) |
  +--------------------------------------------+
  | [[1,2],[3,4]]                              |
  +--------------------------------------------+
  1 row in set
  ```

* Convert the floating-point number `123.456` to the `BIGINT` type.

    ```shell
    obclient> SELECT CAST(123.456 AS BIGINT);
    ```

    The return result is as follows:

    ```shell
    +-------------------------+
    | CAST(123.456 AS BIGINT) |
    +-------------------------+
    |                     123 |
    +-------------------------+
    1 row in set
    ```
