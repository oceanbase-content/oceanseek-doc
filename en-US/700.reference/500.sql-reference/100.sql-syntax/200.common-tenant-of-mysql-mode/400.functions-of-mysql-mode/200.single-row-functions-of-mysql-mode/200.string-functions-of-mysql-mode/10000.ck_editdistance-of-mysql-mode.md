# EDITDISTANCE

The `editDistance(string1, string2)` and `editDistanceUTF8(string1, string2)` functions calculate the Levenshtein edit distance between two strings. The Levenshtein edit distance is the minimum number of operations required to transform one string into another by performing insertions, deletions, or substitutions at most once.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This is a ClickHouse-compatible function. It is disabled by default. To use it, set the tenant-level parameter <code>sql_func_extension_mode</code> to <code>ClickHouse</code>. For more information, see <a href="../../../../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7470.sql_func_extension_mode.md">sql_func_extension_mode</a>.</p>
</main>

## Syntax

```sql
editDistance(string1, string2)
editDistanceUTF8(string1, string2)
```

## Parameters

| **Parameters** | **Note** |
| ---------------------- | ---------------------- |
| `string1`, `string2` | Two strings to be compared. |

## Return type

`BIGINT UNSIGNED` type, which represents the Levenshtein distance between `string1` and `string2`.

## Behavior description

- `editDistance` calculates the distance in **bytes**, making it suitable for ASCII or single-byte character sets. For multibyte character sets (such as UTF-8), a single Chinese character may be counted as multiple bytes of difference.
- `editDistanceUTF8`: Decodes the text to Unicode characters first, then calculates the distance based on the Unicode characters. A multi-byte character counts as one character in the edit distance.
- If any input parameter is `NULL`, the result is `NULL`.
- If any input string is empty, the result is the length of the other string (`editDistance` measures bytes, `editDistanceUTF8` measures characters).
- The maximum length of each input parameter is 65,536 (`editDistance` is in bytes, `editDistanceUTF8` is in characters). Exceeding this limit will result in the error `ERROR 1153 (HY000): Got a packet bigger than 'max_allowed_packet' bytes`, corresponding to the kernel error code `OB_ERR_PARAMETER_TOO_LONG`, with the message `string length is too long for edit distance, should be at most 65536`.

## Examples

1. Enable the ClickHouse extension function mode.

    ```sql
    obclient> ALTER SYSTEM SET sql_func_extension_mode = 'ClickHouse';
    ```

2. Calculate the Levenshtein distance between the strings `Base` and `OceanBase`.

    ```sql
    obclient> SELECT editDistance('Base', 'OceanBase') AS d;
    ```

    The return result is as follows:

    ```shell
    +------+
    | d    |
    +------+
    |    5 |
    +------+
    1 row in set
    ```

3. The difference between byte-level and character-level comparison. `editDistance` counts "middle" as three UTF-8 bytes for the distance, while `editDistanceUTF8` counts it as one character.

    ```sql
    obclient> SELECT editDistance('OB', 'China OB') AS bytes_diff,
                     editDistanceUTF8('OB', 'Chinese OB') AS chars_diff;
    ```

    The return result is as follows:

    ```shell
    +------------+------------+
    | bytes_diff | chars_diff |
    +------------+------------+
    |          3 |          1 |
    +------------+------------+
    1 row in set
    ```

4. Boundary cases involving `NULL` and empty strings.

    ```sql
    obclient> SELECT editDistance(NULL, 'abc') AS null_case,
                     editDistance('', 'abc')   AS empty_case;
    ```

    The return result is as follows:

    ```shell
    +-----------+------------+
    | null_case | empty_case |
    +-----------+------------+
    |      NULL |          3 |
    +-----------+------------+
    1 row in set
    ```
