# JSON_VALUE

## Description

This function extracts values from a JSON document at the specified path and returns the extracted values. You can also choose to convert them into the desired data type.

## Syntax

```sql
JSON_VALUE(json_doc, path [RETURNING type] [on_empty] [on_error])

on_empty:
    {NULL | ERROR | DEFAULT value} ON EMPTY

on_error:
    {NULL | ERROR | DEFAULT value} ON ERROR
```

## Description

### Parameters

The related parameters are described as follows:

* The `json_doc` parameter specifies a valid JSON document.

* The `path` parameter is a JSON path that points to a location in the document and must be a string.

* The `type` parameter supports the following data types:

  * `FLOAT`

  * `DOUBLE`

  * `DECIMAL`

  * `SIGNED`

  * `UNSIGNED`

  * `DATE`

  * `TIME`

  * `DATETIME`

  * `YEAR` (not supported for `YEAR(1)` and `YEAR(2)`))

  * `CHAR`

  * `JSON`

* If the `RETURNING` clause is not used, the return type of the function is `VARCHAR(512)`.
  If no character set is specified for the return type, `JSON_VALUE()` uses the utf8mb4 binary collation and is case-sensitive;
  If utf8mb4 is specified as the character set for the result, the server uses the default collation of this character set, which is case-insensitive.

* The `on_empty` clause specifies the behavior of `JSON_VALUE()` when no data is found in the specified path. Valid values are as follows:

  * `NULL ON EMPTY`: `JSON_VALUE()` returns `NULL`. This is the default behavior of `ON EMPTY`.

  * `DEFAULT value ON EMPTY'`: Returns the provided `value`, which must match the return type.

  * `ERROR ON EMPTY`: The function throws an error.

* When an error occurs, the `on_error` value is as follows:

  * `NULL ON ERROR`: `JSON_VALUE()` returns `NULL`. This is the default behavior if the `ON ERROR` clause is not used.

  * `DEFAULT value ON ERROR`: Returns the provided `value`, which must match the type of the return value.

  * `ERROR ON ERROR`: Throws an error.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>The position of <code>ON EMPTY</code> (if used) must be before all <code>ON ERROR</code> clauses. An incorrect order will result in a syntax error.</p>
  </main>

### Error handling

Normally, JSON_VALUE() checks the validity of all JSON inputs (documents and paths). If any one of them is invalid, it throws an SQL error without triggering the `ON ERROR` clause.

The `ON ERROR` clause is triggered when any of the following events occurs:

* When trying to extract an object or array, the input path is parsed into multiple paths in the JSON document.

* Conversion errors. For example, attempting to convert `'asdf'` to an `UNSIGNED` value.

* Data truncation.

Even if `NULL ON ERROR` or `DEFAULT ... ON ERROR` is specified, conversion errors will always trigger an alert.

The `ON EMPTY` clause is triggered when the source JSON document (`json_doc`) does not contain any data at the specified position (`path`).

## Examples

```sql
obclient> SELECT JSON_VALUE('{"fname": "Smith", "lname": "Will"}', '$.fname');
+--------------------------------------------------------------+
| JSON_VALUE('{"fname": "Smith", "lname": "Will"}', '$.fname') |
+--------------------------------------------------------------+
| Smith                                                        |
+--------------------------------------------------------------+
1 row in set

obclient> SELECT JSON_VALUE('{"item": "shoes", "price": "69.73"}', '$.price'
     RETURNING DECIMAL(4,2)) AS price;
+-------+
| price |
+-------+
| 69.73 |
+-------+
1 row in set
```
