# MATCH AGAINST

## Purpose

This expression is used for text retrieval on a full-text index. `AGAINST` accepts a search string and performs a character-set-based search in the index. For each row of data in the table, the return value of `MATCH` indicates the relevance between the search string and the data in that row, that is, how similar the text in the search string is to the text in the data table.

## Syntax

```sql
MATCH (column_set) AGAINST (query_expr [mode_flag])

column_set:
    column_name [, column_name ...]

mode_flag:
    IN NATURAL LANGUAGE MODE
    | IN BOOLEAN MODE
    | IN MATCH PHRASE MODE
```

## Parameters

| **Field** | **Note** |
| ------------ | ---------- |
| column_set | Specify the columns for the full-text search. To list multiple columns, separate them with commas. The query order does not matter; however, there must be at least one indexed column that matches the search criteria. `column_set` Only a full-text index that matches exactly can execute the corresponding `MATCH AGAINST` Expression. |
| query_expr | Specify the keyword or phrase to search for, which is the parameter to match. OceanSeek will use the tokenizer of the matched full-text index to process it. `query_expr` After tokenization, the search is performed on the full-text index. |
| mode_flag | Optional. Specifies the full-text search mode. Default value: `IN NATURAL LANGUAGE MODE`. For more information, see [mode_flag](#mode_flag). |

### mode_flag

* `IN NATURAL LANGUAGE MODE`: The default value, which specifies to use the natural language search mode. In this mode, full-text search works by tokenizing the query expression (`query_expr`) into a set of tokens (`token`) and matching them against the tokens in the index. A match is considered successful if any token matches a token in the query expression. Relevance ranking (sorting) of the matched rows is performed using a frequency-based method (Okapi BM25).

  By default or when the `IN NATURAL LANGUAGE MODE` identifier is specified, `MATCH AGAINST` uses the `NATURAL LANGUAGE` mode for full-text search. In `NATURAL LANGUAGE` mode, `AGAINST` accepts a search string and performs a character-set-based search in the index. For each row of data in the table, the return value of `MATCH` indicates the relevance between the search string and the data in that row, that is, how similar the text in the search string is to the text in the data table.

* `IN BOOLEAN MODE`: Specifies to use the boolean mode for search. The current version supports three common boolean operators and nested operations, as follows:

  * `+`: Represents `AND`, the intersection.

  * `-`: Represents negation, the difference.

  * The absence of an operator: When used alone, it represents `OR`, the union. For example, `A B` means `A OR B`. Mixing the operators with the `+` sign will increase the relevance of existing sentences but lose the semantics of `OR`. For example, `+A B` means A must be present, and then calculates the relevance of A and B in the sentence.

  * `()`: Represents nested operations. When no outer operator is present, it has the semantics of `OR`. For example, `+A (nested clause)` means A must be present or the nested clause must be true.

    **Examples:**

    1. The output sentence must contain "computer".

       ```sql
       SELECT * FROM my_table WHERE MATCH (doc) AGAINST ("+computer" IN BOOLEAN MODE);
       ```

    2. The output sentence must contain "computer" and must not contain "weather".

       ```sql
       SELECT * FROM my_table WHERE MATCH (doc) AGAINST ("+computer -weather" IN BOOLEAN MODE);
       ```

    3. The output sentence must contain "computer", and "oceanbase" makes the match more relevant.

       ```sql
       SELECT * FROM my_table WHERE MATCH (doc) AGAINST ("+computer oceanbase" IN BOOLEAN MODE);
       ```

* `IN MATCH PHRASE MODE`: Supports exact phrase matching.

  **Example:**

  1. Create a table named `test` and add a full-text index to the specified column.

     ```sql
     CREATE TABLE test(c1 int, c2 VARCHAR(200), c3 TEXT, FULLTEXT INDEX fts_idx (c2, c3));
     ```

  2. Query for records in columns c2 and c3 that exactly match `some words`.

     ```sql
     SELECT c2 FROM test WHERE MATCH(c2,c3) AGAINST('some words' IN MATCH PHRASE MODE);
     ```

## Usage instructions

In addition to representing text matching, the `MATCH AGAINST` expression also carries different semantics when used in various clauses of an SQL statement:

* Projection correlation:

  * Full-text search supports word-frequency-based ranking, which can be represented by a MATCH AGAINST expression to project relevance.
  * The correlation indicates the degree of relevance between the matched data rows and the query specified by MATCH AGAINST.
  * Correlation is a `DOUBLE` type data greater than or equal to 0. A value of 0 indicates that the data row has no correlation with the query. Larger values indicate stronger correlation.

* Filter semantics:

  * For a `MATCH AGAINST` expression that appears in the `WHERE` clause and is connected to all other filter conditions by `AND`, it contains filtering semantics, meaning it filters out data rows that do not match.

    **Example:**

    ```sql
    SELECT id, digest, detail
    FROM t1
    WHERE MATCH (detail) AGAINST ('oceanbase');
    ```

    is equivalent to

    ```sql
    SELECT id, digest, detail
    FROM t1
    WHERE MATCH (detail) AGAINST ('oceanbase') > 0;
    ```

* Sorting semantics:

  * For `MATCH AGAINST` expressions concatenated with other filter conditions using `AND` in the `WHERE` clause, sorting semantics are involved.
  * indicates that the results of the full-text search will be sorted in descending order according to the `MATCH AGAINST` ranking.
  * When multiple `MATCH AGAINST` expressions exist, they are sorted by the relevance of the first `MATCH AGAINST` expression.

  **Example:**

  ```sql
  SELECT id, digest, MATCH (detail) AGAINST ('oceanbase') AS relevance
  FROM t1
  WHERE MATCH (detail) against ('oceanbase');
  ```

  is equivalent to

  ```sql
  SELECT id, digest, MATCH (detail) AGAINST ('oceanbase') AS relevance
  FROM t1
  WHERE MATCH (detail) AGAINST ('oceanbase')
  ORDER BY relevance DESC;
  ```

### How text retrieval works

* When the `MATCH AGAINST` clause in an SQL statement contains filtering semantics, OceanSeek can execute the query by scanning the full-text index to evaluate the `MATCH AGAINST` expression and then returning to the table for further processing.

* When the `MATCH AGAINST` clause in an SQL statement does not contain filtering semantics, OceanSeek supports scanning and filtering using other secondary indexes, and calculates the `MATCH AGAINST` expression by randomly accessing the full-text index based on the primary key to execute the query.

* When the `WHERE` clause of an SQL statement contains both `MATCH AGAINST` and multiple filter conditions connected by `AND`, and other secondary indexes can be matched, OceanSeek attempts to select an appropriate index for scanning based on cost.

* When calculating `MATCH AGAINST` by scanning a full-text index, if the query contains a `LIMIT` clause, OceanSeek attempts to push down the top-k computation to the full-text index scan for better performance.

* When querying a `MATCH AGAINST` clause with `OR` connections, the system automatically attempts to generate an index merge plan. Whether to use this plan ultimately depends on the cost comparison results.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>An index merge plan supports multiple predicates connected by <code>AND</code>. An index merge plan is automatically generated when a query contains multiple predicates, including <code>MATCH AGAINST</code>.</p>
    </main>

## Examples

1. Create the sample table `test_tbl1`, along with the full-text indexes `ft_idx1_test_tbl1` and `ft_idx1_test_tbl1`, and the index `idx_test_tbl1`.

   ```sql
   CREATE TABLE test_tbl1(id INT, ref_no INT, digest VARCHAR(512), detail VARCHAR(4096),
       FULLTEXT INDEX ft_idx1_test_tbl1(detail),
       FULLTEXT INDEX ft_idx2_test_tbl1(digest, detail),
       INDEX idx_test_tbl1 (id));
   ```

2. Insert test data into the `test_tbl1` table.

   ```sql
   INSERT INTO test_tbl1 VALUES
       (1, 1234, 'fulltext', 'Try text retrieval with OceanBase fulltext index'),
       (2, 2345, 'log', 'OceanBase can halp with log analysis'),
       (3, 3456, 'order', 'Simple text retrieval scan will return result set in order of descending ranking in OceanBase'),
       (4, 4567, 'ranking', 'OceanBase will ranking relevance to query for matched result set'),
       (5, 5678, 'filter', 'Using text retrieval as a filter condition would be probably more efficient');
   ```

3. Project correlations using the `MATCH AGAINST` expression.

   ```sql
   SELECT id, digest, detail, MATCH (detail) AGAINST ('oceanbase') AS relevance
   FROM test_tbl1;
   ```

   The return result is as follows:

   ```shell
   +------+----------+-----------------------------------------------------------------------------------------------+--------------------+
   | id   | digest   | detail                                                                                        | relevance          |
   +------+----------+-----------------------------------------------------------------------------------------------+--------------------+
   |    1 | fulltext | Try text retrieval with OceanBase fulltext index                                              | 0.2989130434782609 |
   |    2 | log      | OceanBase can halp with log analysis                                                          | 0.3142857142857143 |
   |    3 | order    | Simple text retrieval scan will return result set in order of descending ranking in OceanBase |  0.240174672489083 |
   |    4 | ranking  | OceanBase will ranking relevance to query for matched result set                              | 0.2849740932642488 |
   |    5 | filter   | Using text retrieval as a filter condition would be probably more efficient                   |                  0 |
   +------+----------+-----------------------------------------------------------------------------------------------+--------------------+
   5 rows in set
   ```

4. Filter data using the `MATCH AGAINST` expression.

   ```sql
   SELECT id, digest, detail
   FROM test_tbl1
   WHERE MATCH (detail) AGAINST ('oceanbase');
   ```

   The return result is as follows:

   ```shell
   +------+----------+-----------------------------------------------------------------------------------------------+
   | id   | digest   | detail                                                                                        |
   +------+----------+-----------------------------------------------------------------------------------------------+
   |    2 | log      | OceanBase can halp with log analysis                                                          |
   |    1 | fulltext | Try text retrieval with OceanBase fulltext index                                              |
   |    4 | ranking  | OceanBase will ranking relevance to query for matched result set                              |
   |    3 | order    | Simple text retrieval scan will return result set in order of descending ranking in OceanBase |
   +------+----------+-----------------------------------------------------------------------------------------------+
   4 rows in set
   ```

5. Retrieve and sort data using the `MATCH AGAINST` expression.

   ```sql
   SELECT id, digest, MATCH (detail) AGAINST ('oceanbase') AS relevance
   FROM test_tbl1
   WHERE MATCH (detail) AGAINST ('oceanbase');
   ```

   or

   ```sql
   SELECT id, digest, MATCH (detail) AGAINST ('oceanbase') AS relevance
   FROM test_tbl1
   WHERE MATCH (detail) AGAINST ('oceanbase')
   ORDER BY relevance DESC;
   ```

   The return result is as follows:

   ```shell
   +------+----------+--------------------+
   | id   | digest   | relevance          |
   +------+----------+--------------------+
   |    2 | log      | 0.3142857142857143 |
   |    1 | fulltext | 0.2989130434782609 |
   |    4 | ranking  | 0.2849740932642488 |
   |    3 | order    |  0.240174672489083 |
   +------+----------+--------------------+
   4 rows in set
   ```
