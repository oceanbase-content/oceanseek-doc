# AUDIT_LOG_FILTER_SET_USER

## Purpose

This function (expression) is used to set filters on a user.

## Syntax

```sql
AUDIT_LOG_FILTER_SET_USER('user_name', 'filter_name');
```

## Description

### Parameters

* `user_name`: the username.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>The <code>user@host</code> specified in <code>AUDIT_LOG_FILTER_SET_USER</code> does not need to be an existing user. You can use a wildcard or a non-existent user. The <code>user_name</code> has the following limitations:<ul><li>The <code>host</code> field cannot be specified.</li><li><code>user</code> only supports wildcarding the entire field, that is, <code>%</code>. Partial wildcarding, such as <code>test_%</code>, is not supported.</li></ul></p>
    </main>

* `filter_name`: the name of the filter.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><code>AUDIT_LOG_FILTER_SET_USER</code> has <code>CREATE OR REPLACE</code> semantics. Executing DDL on an existing object will overwrite it. If the specified <code>filter_name</code> does not exist, the DDL will not take effect but no error will be reported either.</p>
    </main>

### Return value

The expression input must be a string constant, and the output is of the string type.

* When the DDL statement is executed successfully, the expression returns `OK`.
* When DDL execution fails, the `SELECT` statement is still executed successfully, and the output of the expression is an error message.

## Examples

Set the `log_all` filter for user `user001`.

```sql
SELECT AUDIT_LOG_FILTER_SET_USER('user001', 'log_all');
```

The return result is as follows:

```shell
+-------------------------------------------------+
| AUDIT_LOG_FILTER_SET_USER('user001', 'log_all') |
+-------------------------------------------------+
| OK                                              |
+-------------------------------------------------+
1 row in set
```
