# Spatial analysis functions

Spatial analysis functions are used to perform complex spatial processing and analysis tasks, such as buffer analysis, merging, and clipping.

The spatial analysis functions currently supported by OceanBase AI Database include `ST_Length()`, `ST_Centroid()`, and `_ST_PointOnSurface()`.

## ST_Length

The `ST_Length(ls[,unit])` function calculates the length of a linear geometric object, such as a line segment, polyline, or curve. This function is typically applicable to geometric objects of the `LINESTRING` and `MULTILINESTRING` types.

For unit conversions to take effect, the geometry object ls must have an associated Spatial Reference System Identifier (SRID), and that SRID must not be 0 (an SRID of 0 typically indicates no spatial reference).

The unit used must be a valid unit supported by the database, and the database must be able to recognize the conversion factor corresponding to that unit.

## ST_Centroid

`ST_Centroid(geometry A)` is a spatial function that calculates the centroid (geometric center) of a given geometry `A`. The centroid is the balance point of all parts of the geometry and can be considered its central location. For two-dimensional geometries, such as polygons, the centroid is the average position of all points.

- If `A` is an empty geometry (contains no points), the function may return `NULL` or an invalid result.
- If `A` is a complex geometry, calculating its centroid can become complex and computationally intensive, especially when the geometry has many vertices or internal holes.
- The calculated centroid may not lie on the original geometry, especially when the geometry itself has an irregular shape or concave parts. For example, for a "U"-shaped polygon, the centroid might be located in the external space of the depression.
- For linear geometric shapes (such as line segments or polygons), the centroid is the average position of all points on the shape. However, for complex line shapes (such as self-intersecting or curved polygons), the position of the centroid may be difficult to interpret intuitively.

The syntax is as follows:

```sql
ST_Centroid(geometry A)
```

An example is as follows:

```sql
obclient> SELECT ST_AsText(_ST_PointOnSurface(geom)) AS pt_on_surf, ST_AsText(ST_Centroid(geom)) AS centroid FROM (SELECT ST_GeomFromText('POLYGON ((0 0, 0 10, 10 10, 10 8, 2 8, 2 2, 10 2, 10 0, 0 0))') AS geom) AS t;
```

In this example, a polygon geometry with a complex shape is defined, and two spatial analysis operations are performed on it:

The `_ST_PointOnSurface` function is used to obtain a point located on the surface of a polygon. This point typically represents the location of the entire geometry and is guaranteed to be inside the polygon.
The `ST_Centroid` function calculates the centroid of a polygon. It is the balance point of all parts of the polygon but does not necessarily lie inside the polygon.
The results are displayed in two columns. The first column, `pt_onsurf`, contains the coordinates of points on the polygon's surface, and the second column, `centroid`, contains the coordinates of the calculated centroid of the polygon. As shown in the query result, a point on the polygon's surface is located at (1, 5), and the centroid is located at (4.076923076923077, 5).

The return result is as follows:

```shell
+------------+----------------------------+
| pt_on_surf | centroid                   |
+------------+----------------------------+
| POINT(1 5) | POINT(4.076923076923077 5) |
+------------+----------------------------+
1 row in set
```

## _ST_PointOnSurface

The `_ST_PointOnSurface(geometry a)` function returns a point from the input geometry `a` that is guaranteed to lie on its surface. It can return a point that is precisely inside the geometry (for polygons and other planar geometries), rather than just the geometric or arithmetic center of the geometry.

The `_ST_PointOnSurface` function is generally meaningful only for polygonal geometries, as the concept of interior points may not be well-defined or applicable for linear or point geometries.

This function may not return any of the multiple interior points, but instead returns a specific point that represents the entire geometry (for example, a vertex of a polygon or a point on an edge).

The syntax is as follows:

```sql
_ST_PointOnSurface(geometry g1)
```

For example:

```sql
obclient> SELECT ST_AsText(_ST_PointOnSurface(geom)) AS pt_on_surf, ST_AsText(ST_Centroid(geom)) AS centroid FROM (SELECT ST_GeomFromText('POLYGON ((0 0, 0 10, 10 10, 10 8, 2 8, 2 2, 10 2, 10 0, 0 0))') AS geom) AS t;
```

In this example, a polygon geometry with a specific shape is first created from a Well-Known Text (WKT) string. Then, two functions are applied to this polygon: `_ST_PointOnSurface` and `ST_Centroid`.

The `_ST_PointOnSurface` function returns a point that is guaranteed to lie on the surface of the polygon, meaning it is either on the boundary or inside the polygon. In contrast, the `ST_Centroid` function calculates and returns the geometric center of the polygon.

Finally, the query result uses two columns to display the coordinates of these two points: `pt_onsurf` represents the point on the surface, and `centroid` represents the centroid's coordinates. In the provided example, `pt_onsurf` returns a point with coordinates (1 5), while `centroid` returns a point with coordinates (4.076923076923077 5).

The return result is as follows:

```shell
+------------+----------------------------+
| pt_on_surf | centroid                   |
+------------+----------------------------+
| POINT(1 5) | POINT(4.076923076923077 5) |
+------------+----------------------------+
1 row in set
```
