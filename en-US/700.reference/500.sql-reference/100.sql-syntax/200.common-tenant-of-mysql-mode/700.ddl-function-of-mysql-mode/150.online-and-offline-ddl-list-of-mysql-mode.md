# Online DDL and Offline DDL Operations

## Online DDL (Online DDL)

- **Definition**: During DDL operations, users can still access the database, including read and write operations.
- **Advantages**: It has minimal impact on business operations and allows DDL operations to be executed at runtime. It is typically used in scenarios requiring high availability.
- **Features**: Typically support concurrent access and require fewer locks, which can reduce downtime.

## Offline DDL

- **Definition**: When performing DDL operations, the relevant tables are locked, preventing users from accessing the corresponding data in the database.
- **Advantages**: Simple and easy to implement, suitable for scenarios where the impact on business is minimal.
- **Characteristics**: DDL operations result in a certain degree of downtime, impacting normal queries and transaction processing.

## Transaction affinity

- **Transaction**: A sequence of operations that either all succeed or all fail, ensuring data consistency throughout the transaction.
- Online DDL and offline DDL operations are typically separate, and DDL operations themselves may not be supported for transaction control in some database management systems (especially offline DDL).

## Transaction waiting strategies

- **Online DDL**: Typically does not require waiting for the current transaction to end and can be executed concurrently.
- **Offline DDL**: Typically requires waiting for the current transaction to complete, as it locks the relevant tables during execution.

## How to determine if a DDL operation is online (Online DDL)

In OceanSeek, the online or offline status of DDL operations has a significant impact on business operations. This topic describes how to determine whether a DDL operation is an Online DDL, and provides specific steps and considerations. For some operations, such as column type changes or hybrid DDL operations, it is uncertain whether they are Online DDLs before execution. It is recommended to verify and determine this first using the following methods.

### How to determine if a DDL operation is online

For some operations with a wide scope, it is not possible to categorize all DDL operations as either online or offline. Therefore, we recommend that users, when performing mixed DDL operations, explicitly determine whether the operation is online.

**Offline DDL principle**:

Offline DDL operations in OceanSeek are performed by "rebuilding a table". Specifically, offline DDL creates a temporary hidden table (invisible to users) and migrates the data from the original table to the new table. After the data migration is complete, the temporary table is renamed to the name of the original table, and the old table is deleted. Therefore, after an offline DDL operation is completed, the `table_id` changes. Note that DML operations are not allowed during DDL execution.

Using this principle, you can determine whether a DDL operation is an online DDL.

**Detection method**:

Execute the following SQL statements before and after the DDL operation to check if the `table_id` changes. If it does not change, the operation is an Online DDL; if it changes, the operation is an Offline DDL.

```sql
select distinct(table_id) from oceanbase.DBA_OB_TABLE_LOCATIONS where table_name='xxx';
```

**Procedure**:

Use the following procedure to determine whether a DDL operation is an Online DDL.

1. Create an empty table for verification:

   ```sql
   CREATE TABLE t10(a INT, b INT);
   ```

2. Check the current `table_id`:

   ```sql
   SELECT distinct(table_id)
   FROM oceanbase.DBA_OB_TABLE_LOCATIONS
   WHERE table_name='t10';
   ```

3. Perform the expected DDL operation:

   ```sql
   ALTER TABLE t10 ADD c INT, ADD CONSTRAINT c_idx UNIQUE(c);
   ```

4. Check the `table_id` again:

   ```sql
   SELECT distinct(table_id)
   FROM oceanbase.DBA_OB_TABLE_LOCATIONS
   WHERE table_name='t10';
   ```

5. If the `table_id` returned in step 2 and step 4 is the same, the DDL operation is online; if the `table_id` has changed, the corresponding DDL operation is offline.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This detection method is invalid for table operations and partition operations.</p>
</main>
