# Column type change rules

When changing a column type, you must first consider the table-level rules for column type changes, particularly the scenarios where certain data types are prohibited. Next, consider the conversion rules between the source and target data types during the change.

## Rules for changing column types at the table level

### Disabled rules

* Foreign key constraints

  For both online and offline DDL, the type of a foreign key column cannot be modified in any scenario except for the following special case (note that the type modification only changes the display precision, not the storage structure).

  * If the column's data type is `FLOAT(m,n)`, you can change the precision, but conversion between `SIGNED` and `UNSIGNED` is not supported.

  * If the data type of a column is `DOUBLE(m,n)`, you can change its precision, but you cannot convert it between `SIGNED` and `UNSIGNED`.

  * If the column's data type is `VARCHAR(m)`, increasing the precision is supported, decreasing the precision is not supported, and changing it to the `CHAR` type is not supported.

* `CHECK` constraint

  For both online and offline DDL operations, columns with a `CHECK` constraint cannot have their data type modified, except for those of the integer type (`INTEGER`).

* Trigger constraints

  This restriction applies only to offline DDL operations. If a column has triggers other than `DISABLE`, the column type cannot be modified. If all triggers are `DISABLE`, the DDL operation is allowed, but the new table must include these `DISABLE` triggers.

### Change rules

* When the length of a data type increases for the same data type, for example, changing the data type of a column from `VARCHAR(8)` to `VARCHAR(11)`, this operation can be performed as an online DDL without rewriting the data.

  * If you modify the length of a column using online DDL and the column is part of an index table (for example, changing the length of a `VARCHAR` type column), you must also modify the schemas of related dependent objects, such as the index table, during the online DDL operation. In other words, **"the data expected by users remains unchanged, but the schemas in dependent objects must be updated accordingly"**.
  * For columns of the `INTEGER` or `DecimalInt` type, if they are index columns or primary key columns, operations that increase the column type can be performed using online DDL.

* In OceanBase AI Database, for the growth of `LOB` data, Online DDL operations support the following scenarios:

  * Modification of regular columns.
  * Modifications as generated columns (Store/Virtual)
  * Modifications that depend on generated columns (Store/Virtual)
  * Added `NOT NULL` and `CHECK` constraints.
  * Modified the original `NOT NULL` constraint.

* For numeric data types, if a `SIGNED` to `UNSIGNED` conversion occurs and type change is allowed, an offline operation is required. For character data types, if a change in the character set or collation occurs and column type change is allowed, an offline operation is required.

* When a column is referenced by a generated column, changes to its data type are allowed.

## Column-level conversion rules

In OceanBase AI Database, all column data types are divided into three main categories: numeric data types, character data types, and time data types. The conversion rules within these three categories are similar, as are the change rules between each category, although there are some special cases.

### DECIMAL/DECIMALINT

`DECIMAL(precision, scale)` indicates a decimal number type, where `precision` represents the total length of the number, and `scale` represents the number of digits in the fractional part. The precision range for `precision` during online DDL operations is [1, 9], [10, 18], [19, 38], and [39, 65].

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p><ul><li>The maximum value of <code>precision</code> is 65.</li></ul></p>
</main>

When the `precision` length is within the same range and `scala` remains unchanged, the underlying physical storage does not change and can be modified using online DDL. For example, changing from `DECIMAL(10, 2)` to `DECIMAL(12, 2)` can be done via online DDL.

* For changes to the first parameter `precision`, if increasing it (i.e., extending the length of `precision`), modifications can be made using Online DDL. For example, changing from `DECIMAL(10, 2)` to `DECIMAL(12, 2)` can be done via Online DDL. However, if decreasing it (i.e., shortening the length of `precision`), Online DDL cannot be used; instead, Offline DDL must be employed. Modifications that cross precision intervals also require Offline DDL.

* For the second parameter `scala`, any change in its length, whether increasing or decreasing, requires the use of offline DDL for modification; online DDL cannot be used. For example, changing from `DECIMAL(10, 2)` to `DECIMAL(10, 4)` or from `DECIMAL(10, 2)` to `DECIMAL(10, 1)` requires the use of offline DDL for modification.

### VARCHAR variable length

To convert `VARCHAR(x)` to `VARCHAR(y)`, you only need to ensure that `y` is greater than or equal to `x`. You can then use online DDL to upgrade the column type. For example, to convert `VARCHAR(10)` to `VARCHAR(20)`, you can use online DDL to modify the column type.

### VARBINARY variable length

To convert `VARBINARY(x)` to `VARBINARY(y)`, you only need to ensure that the length of `y` is greater than or equal to the length of `x`. You can then use online DDL to modify the column type. For example, to convert `VARBINARY(10)` to `VARBINARY(20)`, you can use online DDL to modify the column type.
