# Overview of data types

This chapter describes the MySQL data types supported by the current version of OceanSeek, including their attributes and storage requirements.

The current version of OceanSeek supports the following MySQL data types:

* [Overview of numeric types](200.numeric-of-mysql-mode/100.numeric-type-of-mysql-mode.md)

* [Overview of date and time types](300.date-and-time-types-of-mysql-mode/100.date-and-time-types-of-mysql-mode.md)

* [Character type overview](400.string-of-mysql-mode/100.string-type-overview-of-mysql-mode.md)

* [Overview of LOB and text types](500.large-object-of-mysql-mode/100.large-object-and-text-type-overview-of-mysql-mode.md)

* [Overview of LOB and text types](500.large-object-of-mysql-mode/100.large-object-and-text-type-overview-of-mysql-mode.md)

* [Overview of Efficient Compression for Bitmap Data Types](1000.roaring-bitmap-data-type-of-mysql-mode/100.roaring-bitmap-data-type-overview-of-mysql-mode.md)

* [Overview of Array Element Types](1200.array-data-type-of-mysql-mode/100.array-data-type-overview-of-mysql-mode.md)

* [Overview of mapped data types](1300.map-data-type-of-mysql-mode/100.map-data-type-overview-of-mysql-mode.md)

OceanSeek allows you to compare any two or more data items of arbitrary types. The comparison results can be as follows:

* Non-zero / `TRUE`

* 0 / `FALSE`

* `NULL`

If the data types of the elements to be compared are inconsistent, OceanSeek determines a common data type for the comparison based on relevant rules. Logically, all data to be compared must first be converted to this common type before the comparison can proceed. If the comparison involves text data, an appropriate collation for the comparison must also be determined.

For conversion rules of comparison operators, see [Data type conversion rules](../200.expression-of-mysql-mode/300.type-conversion-of-expression-evaluation-of-mysql-mode.md).
