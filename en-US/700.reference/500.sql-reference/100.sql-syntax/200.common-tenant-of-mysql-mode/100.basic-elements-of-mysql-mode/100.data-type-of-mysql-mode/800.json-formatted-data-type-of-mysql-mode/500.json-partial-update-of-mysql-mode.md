# Update partial data in a JSON document

OceanSeek supports updating only a partial portion of a JSON document. When you need to modify only specific fields within a JSON document, this feature allows you to update only the changed parts without having to fully refresh the entire JSON document.

## Limitations

* The current version does not support partial update of JSON data. Even if the `partial_json` option is enabled in the `log_row_value_options` variable, a full update is performed instead of a partial update when updating a JSON document.

## Json Partial Update Switch

The JSON partial update feature of OceanSeek is disabled by default. The switch is controlled by the system variable `log_row_value_options`. For more information, see [log_row_value_options](../../../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/3500.log_row_value_options-global.md).

**Example:**

* Enable the JSON partial update feature.

  * Session level:

  ```sql
  SET log_row_value_options="partial_json";
  ```

  * Global level:

  ```sql
  SET GLOBAL log_row_value_options="partial_json";
  ```

* Disable the JSON partial update feature.

  * Session level:

  ```sql
  SET log_row_value_options="";
  ```

  * Global level:

  ```sql
  SET GLOBAL log_row_value_options="";
  ```

* Query the value of `log_row_value_options`.

  ```sql
  SHOW VARIABLES LIKE 'log_row_value_options';
  ```

  The return result is as follows:

  ```sql
  +-----------------------+-------+
  | Variable_name         | Value |
  +-----------------------+-------+
  | log_row_value_options |       |
  +-----------------------+-------+
  1 row in set
  ```

## JSON expressions that can be used for partial update

In addition to the `log_row_value_options` parameter for enabling JSON partial update, you must also use specific expressions to update the JSON document for this feature to take effect.

The following table describes the JSON expressions that support partial update in OceanSeek:

* json_set or json_replace: Updates the value of a JSON field.
* json_remove: Deletes a JSON field.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p><ol><li>Ensure that the left operand of the <code>SET</code> assignment clause and the first parameter of the JSON expression are the same and both refer to a JSON column in the table. For example, in <code>j = json_replace(j, '$.name', 'ab')</code>, both the parameter on the left side of the equal sign and the first parameter of the JSON expression <code>json_replace</code> on the right side are <code>j</code>.</li><li>JSON partial update is triggered only when the data of the current JSON column is stored as <code>outrow</code>. Whether to store as <code>outrow</code> or <code>inrow</code> is controlled by the <code>lob_inrow_threshold</code> parameter during table creation. <code>lob_inrow_threshold</code> configures the <code>INROW</code> threshold. When the LOB data size exceeds this threshold, it will be converted to <code>OUTROW</code> storage in the LOB Meta table. The default value is 4 KB.</li></ol></p>
</main>

**Example:**

1. Create the `json_test` table.

   ```sql
   CREATE TABLE json_test(pk INT PRIMARY KEY, j JSON);
   ```

2. Insert data.

   ```sql
   INSERT INTO json_test VALUES(1, CONCAT('{"name": "John", "content": "', repeat('x',8), '"}'));
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   ```

3. Query the data in column `j` of the JSON type.

   ```sql
   SELECT j FROM json_test;
   ```

   The return result is as follows:

   ```shell
   +-----------------------------------------+
   | j                                       |
   +-----------------------------------------+
   | {"name": "John", "content": "xxxxxxxx"} |
   +-----------------------------------------+
   1 row in set
   ```

4. Use `json_replace` to update the value of the `name` field in the JSON column.

   ```sql
   UPDATE json_test SET j = json_replace(j, '$.name', 'ab') WHERE pk = 1;
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

5. Query the modified data in the `j` column as a JSON string.

   ```sql
   SELECT j FROM json_test;
   ```

   The return result is as follows:

   ```shell
   +---------------------------------------+
   | j                                     |
   +---------------------------------------+
   | {"name": "ab", "content": "xxxxxxxx"} |
   +---------------------------------------+
   1 row in set
   ```

6. Use `json_set` to update the value of the `name` field in the JSON column.

   ```sql
   UPDATE json_test SET j = json_set(j, '$.name', 'cd') WHERE pk = 1;
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

7. Query the data in column `j` after modification.

   ```sql
   SELECT j FROM json_test;
   ```

   The return result is as follows:

   ```shell
   +---------------------------------------+
   | j                                     |
   +---------------------------------------+
   | {"name": "cd", "content": "xxxxxxxx"} |
   +---------------------------------------+
   1 row in set
   ```

8. Use `json_remove` to remove the value of the `name` field from the JSON column.

   ```sql
   UPDATE json_test SET j = json_remove(j, '$.name') WHERE pk = 1;
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

9. Query the data in column `j` after modification.

   ```sql
   SELECT j FROM json_test;
   ```

   The return result is as follows:

   ```shell
   +-------------------------+
   | j                       |
   +-------------------------+
   | {"content": "xxxxxxxx"} |
   +-------------------------+
   1 row in set
   ```

## Update granularity

The JSON data in OceanSeek is stored as LOB data, and the underlying storage of LOB data in OceanSeek is block-based storage. Therefore, the minimum amount of data updated in each partial update is one LOB block. The smaller the LOB block size, the less data is written. For this reason, a DDL statement for setting the LOB block size is also provided, which can be specified when creating a column.

**Example:**

```sql
CREATE TABLE json_test(pk INT PRIMARY KEY, j JSON CHUNK '4k');
```

The chunk size cannot be set too small, as this will impact the performance of `SELECT`, `INSERT`, and `DELETE` operations. It is generally recommended to set it based on the average field size in the JSON document. If most fields are small, you can set it to 1 KB. To optimize read performance for LOB-type data, OceanSeek stores data smaller than 4 KB directly in `INROW` format, which prevents partial updates from being performed in such cases. Partial updates are primarily intended to improve the performance of updating large documents; for smaller documents, a full update actually yields better performance.

## Rebuild

JSON partial update does not impose any restrictions on the length of data before and after an update for a JSON column. If the length of the new value is less than or equal to the length of the old value, the original data at that position is directly replaced with the new data. When the length of the new value is greater than the length of the old value, the new data is appended at the end. OceanSeek sets a threshold. When the length of the appended data exceeds 30% of the original data length, a rebuild is performed. In this case, a partial update is not performed; instead, the data is overwritten in its entirety.

You can use the `JSON_STORAGE_SIZE` expression to obtain the actual storage length of JSON data and the `JSON_STORAGE_FREE` expression to obtain the additional storage overhead.

**Example:**

1. Enable JSON partial update.

   ```sql
   SET log_row_value_options = "partial_json";
   ```

2. Create a test table named `json_test`.

   ```sql
   CREATE TABLE json_test(pk INT PRIMARY KEY, j JSON CHUNK '1K');
   ```

3. Insert a row of data into the `json_test` table.

   ```sql
   INSERT INTO json_test VALUES(10 , json_object('name', 'zero', 'age', 100, 'position', 'software engineer', 'profile', repeat('x', 4096), 'like', json_array('a', 'b', 'c'), 'tags', json_array('sql boy', 'football', 'summer', 1), 'money' , json_object('RMB', 10000, 'Dollers', 20000, 'BTC', 100), 'nickname', 'noone'));
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   ```

4. Query the storage size of a JSON column (the actual occupied storage space) using `JSON_STORAGE_SIZE`, and estimate the storage space that can be released for the JSON column using `JSON_STORAGE_FREE`.

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   The return result is as follows:

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4335 |                    0 |
   +----------------------+----------------------+
   1 row in set
   ```

   Since no partial update has been performed, the value of `JSON_STORAGE_FREE` is 0.

5. Use `json_replace` to update the value of the `position` field in the JSON column, where the length of the new value is less than the length of the old value.

   ```sql
   UPDATE json_test SET j = json_replace(j, '$.position', 'software enginee') WHERE pk = 10;
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

6. Query the JSON column storage size again using `JSON_STORAGE_SIZE`, and estimate the storage space that can be released for the JSON column using `JSON_STORAGE_FREE`.

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   The return result is as follows:

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4335 |                    1 |
   +----------------------+----------------------+
   1 row in set
   ```

   After the JSON column data is updated, since the new data is one byte shorter than the old data, the result of `JSON_STORAGE_FREE` is 1.

7. Use `json_replace` to update the value of the `position` field in a JSON column, where the new value is longer than the old value.

   ```sql
   UPDATE json_test SET j = json_replace(j, '$.position', 'software engineera') WHERE pk = 10;
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

8. Query the storage size of the JSON column again using `JSON_STORAGE_SIZE`, and estimate the amount of storage space that can be released for the JSON column using `JSON_STORAGE_FREE`.

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   The return result is as follows:

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4355 |                   19 |
   +----------------------+----------------------+
   1 row in set
   ```

   After appending data to the JSON column, the `JSON_STORAGE_FREE` length is 19, indicating that 19 bytes can be released after rebuilding.
