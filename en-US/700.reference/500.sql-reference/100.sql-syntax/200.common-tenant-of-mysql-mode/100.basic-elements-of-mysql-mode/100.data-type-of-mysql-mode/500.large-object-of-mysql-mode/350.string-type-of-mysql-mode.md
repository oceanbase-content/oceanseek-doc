# STRING type

As a text type, `STRING` can better support and migrate AP business, and also supports variable-length strings as primary keys.

## Basic features

* When creating a table, you do not need to specify the data length for the `STRING` type. The maximum storable data length is 16 MB (16,777,216 bytes).

* Columns of the `STRING` type (hereinafter referred to as string columns) can be used as primary key columns and index columns, and can also serve as the partitioning keys for the Key/Range columns/List columns partitioning types.

* The `STRING` type is a special case of the `LOB` type:

  * For the `STRING` type, which is not a primary key column, data exceeding the length of `LOB_INROW_THRESHOLD` (the threshold for `LOB` columns) will be stored out-of-row.
  * The `STRING` type is the primary key column. All data is stored in-row, and the data length is limited by the primary key length.

## Limitations

* The default value for the `STRING` type is only `NULL`.

* When the `STRING` type is used for a non-primary key column, whether overflow data is stored externally is determined by the value of `LOB_INROW_THRESHOLD`.

  For more information about `LOB_INROW_THRESHOLD`, see [LOB types](400.lob-type-of-mysql-mode.md) and [ob_default_lob_inrow_threshold](../../../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/6300.ob_default_lob_inrow_threshold-global.md).

* When a String column is used as the primary key or index key, its length is checked during write (or update) operations. If the length exceeds 16 KB, an error is returned.

* When creating an index on a String column, if the String data on the primary table has already overflowed and requires external storage, an error will be returned indicating that the index cannot be created.

* After an index is created on a String column, if the data written (or updated) to that column exceeds the row length (i.e., the data length is greater than `LOB_INROW_THRESHOLD`), an error will be returned, indicating that the data cannot be written or updated.

* When a String column is used as the partitioning key, an error will be returned if the data to be written (or updated) is an overflowed LOB. (For example, in `INSERT INTO ... SELECT ...`, where the data for the `SELECT` statement is an overflowed LOB.)

* In a direct load scenario, if an index exists on the String column of the target table and the data length exceeds the maximum allowed for in-row storage (`LOB_INROW_THRESHOLD`) after import, an error will be returned and the data cannot be imported.

* In an incremental direct load scenario, if an index exists on the String column of the target table and the corresponding String column in the source table has exceeded its row length and requires out-of-row storage, an error will be reported and data import will fail.

## Usage examples

1. Create a table named `test_tbl1`, where `col1`, `col2`, and `col3` are string columns, and `col1` is the primary key. The table is partitioned by KEY on the value of `col1` into four partitions.

   ```sql
   CREATE TABLE test_tbl1 (col1 STRING PRIMARY KEY,
       col2 STRING,
       col3 STRING,
       col4 VARCHAR(10))
       PARTITION BY KEY(col1) PARTITIONS 4;
   ```

2. Create an index named `idx_test_tbl1` on the `col2` column of the string type.

   ```sql
   CREATE INDEX idx_test_tbl1 ON test_tbl1(col2);
   ```

3. View the definition of table `test_tbl1`.

   ```sql
   SHOW CREATE TABLE test_tbl1;
   ```

   The return result is as follows:

   ```shell
   +-----------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   | Table     | Create Table                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
   +-----------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   | test_tbl1 | CREATE TABLE `test_tbl1` (
   `col1` string NOT NULL,
   `col2` string DEFAULT NULL,
   `col3` string DEFAULT NULL,
   `col4` varchar(10) DEFAULT NULL,
   PRIMARY KEY (`col1`),
   KEY `idx_test_tbl1` (`col2`) BLOCK_SIZE 16384 LOCAL
   ) ORGANIZATION INDEX DEFAULT CHARSET = utf8mb4 ROW_FORMAT = DYNAMIC COMPRESSION = 'zstd_1.3.8' REPLICA_NUM = 1 BLOCK_SIZE = 16384 USE_BLOOM_FILTER = FALSE ENABLE_MACRO_BLOCK_BLOOM_FILTER = FALSE TABLET_SIZE = 134217728 PCTFREE = 0
   partition by key(col1)
   (partition `p0`,
   partition `p1`,
   partition `p2`,
   partition `p3`) |
   +-----------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   1 row in set
   ```

4. Insert test data into the `test_tbl1` table.

   ```sql
   INSERT INTO test_tbl1 VALUES("A1", "B1", "C1", "D1"),("A2", "B2", "C2", "D2");
   ```

5. View the data in the `test_tbl1` table.

   ```sql
   SELECT * FROM test_tbl1;
   ```

   The return result is as follows:

   ```shell
   +------+------+------+------+
   | col1 | col2 | col3 | col4 |
   +------+------+------+------+
   | A2   | B2   | C2   | D2   |
   | A1   | B1   | C1   | D1   |
   +------+------+------+------+
   2 rows in set
   ```
