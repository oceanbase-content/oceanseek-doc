# Set hint under Optimized hint type

A hint that controls the behavior of set operations.

Since there is no direct location to add hints for set operation clauses, the hints described in this topic must use the qb name to specify the set operation object they affect. For detailed usage, see the examples of each hint.

| Hint type | Description |
| ---------------------------------- | ------------------------------------------------------- |
| `PQ_SET` | Controls the distributed execution mode for set operations. |
| `USE_HASH_SET` | Enables the optimizer to use the HASH method in set operations. Its inverse operation is `NO_USE_HASH_SET`. |
| `NO_USE_HASH_SET` | Prohibits the optimizer from using the HASH method in set operations. Its inverse operation is `USE_HASH_SET`. |

## `PQ_SET` Hint

The `PQ_SET` hint specifies the data distribution method for set operations during distributed execution.

### Syntax

```sql
PQ_SET ( [ @qb_name ] [left_branch_qb_name] method_list )
```

#### Parameters

- `left_branch_qb_name`: Identifies the left branch for the `UNION` or `INTERSECT` set operation.

- `method_list` specifies the specific distributed execution method.

The specific method description and examples are as follows:

| Data Distribution Method | outline data hint description | Description |
| ---------------------- | ------------------------------ | ----------- |
| DIST_BASIC_METHOD | PQ_SET ( @SET$1 ) , no hint is added to the outline |  |
| DIST_PARTITION_WISE | PQ_SET ( @SET$1 NONE NONE) |  |
| DIST_PULL_TO_LOCAL | PQ_SET ( @SET$1 LOCAL LOCAL) |  |
| DIST_SET_RANDOM | PQ_SET ( @SET$1 RANDOM NONE) | Limited to `UNION ALL` |
| DIST_SET_RANDOM | PQ_SET ( @SET$1 NONE RANDOM) | Limited to `UNION ALL` |
| DIST_SET_RANDOM | PQ_SET ( @SET$1 RANDOM NONE RANDOM) | Limited to `UNION ALL` |
| DIST_HASH_HASH | PQ_SET ( @SET$1 SEL$1 HASH HASH) | Limited to union/intersect of two branches, with SEL$1 as the left branch |
| DIST_NONE_PARTITION | PQ_SET ( @SET$1 SEL$2 NONE PARTITION ) | Limited to union/intersect of two branches, with SEL$2 as the left branch |
| DIST_PARTITION_NONE | PQ_SET ( @SET$1 SEL$1 PARTITION NONE ) | Limited to union/intersect of two branches, with SEL$1 as the left branch |

### Examples

In the query example below, `pq_set(@set$1 local local)` specifies to pull data directly back to the local node for distributed execution. `pq_set(@set$1 sel$2 hash hash)` instructs to redistribute data using the `HASH` method for set operations, with `sel$2` serving as the left branch of the set operation.

```sql
-- Specify a specific distributed execution method for set operations using the PQ_SET hint.
CREATE TABLE tp1(c1 INT, c2 INT, c3 INT) PARTITION BY HASH(c1) PARTITIONS 10;
EXPLAIN BASIC SELECT /*+ PQ_SET(@set$1 local local) */ c2, c3 FROM tp1 a UNION SELECT c2, c3 FROM tp1 b;
```

## `USE_HASH_SET` Hint

The `USE_HASH_SET` hint controls the specific algorithm used for set operations. Its reverse operation is `NO_USE_HASH_SET`.

### Syntax

```sql
/*+ USE_HASH_SET [ ( [ @ qb_name ] ) ] */
```

### Examples

In the query example below, `USE_HASH_SET` is used to enable the `HASH` algorithm.

```sql
-- Use the USE_HASH_SET hint to force set operations to use the HASH method.
EXPLAIN BASIC
SELECT /*+ USE_HASH_SET(@set$1) */ c1, c2, c3 FROM t1
UNION
SELECT c1, c2, c3 FROM t1;
```

## `NO_USE_HASH_SET` Hint

The `NO_USE_HASH_SET` hint controls the specific algorithm used for set operations. Its inverse operation is `USE_HASH_SET`.

### Syntax

```sql
/*+ NO_USE_HASH_SET [ ( [ @ qb_name ] ) ] */
```

### Example

In the query example below, `NO_USE_HASH_SET` is used to disable the HASH algorithm. Since OceanSeek supports both HASH and MERGE set operation algorithms, using the `NO_USE_HASH_SET` hint effectively instructs the set operation to use the `MERGE` algorithm. The `UNION ALL` set operation does not have a deduplication semantics and is not controlled by this hint.

```sql
-- Use the NO_USE_HASH_SET hint to instruct the optimizer to avoid using hash methods in set operations.
EXPLAIN BASIC
SELECT /*+ NO_USE_HASH_SET(@set$1) */ c1, c2, c3 FROM t1
UNION
SELECT c1, c2, c3 FROM t1;
```
