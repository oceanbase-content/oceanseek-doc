# Full-text query

Full-text query refers to the operation of performing a full-text search or retrieval in text data. It is used to find text content that contains specific keywords, phrases, or text expressions. Full-text queries can search the entire text more comprehensively and return results that match the search criteria.

## Syntax

You can use the following syntax to perform a [Full-text search](../../../../../400.ai-search/500.full-text-search.md) by specifying columns and keywords or phrases. You can also use specific search modifiers to adjust the search pattern (i.e., search conditions or rules).

```sql
MATCH (column_name [, column_name ...]) AGAINST (expr [search_modifier])

search_modifier:
    IN NATURAL LANGUAGE MODE
    | IN BOOLEAN MODE
    | IN MATCH PHRASE MODE
```

**The related parameters are described as follows:**

* `column_name`: The column for which to perform the full-text search. If you need to list multiple columns, separate them with commas.

* `expr`: the keyword or phrase to search for.

* `search_modifier`: Optional. Specifies the search pattern. For details about the valid values and applicable scenarios, see the following table:

  |         Search Mode          | Parameter Description | Application Scenarios |
  |--------------------------|----------|---------|
  | IN NATURAL LANGUAGE MODE | The default value. Specifies to use the natural language search mode for the search. | Natural language, top-k scenarios, performs fuzzy matching, and outputs relevance scores. Words are automatically segmented by default using the tokenizer configured for the table. |
  | IN BOOLEAN MODE | Specifies to perform a search in boolean mode. The current version supports the following boolean operators and nested operations:<ul><li>`+`: represents `AND`, the intersection.</li><li>`-`: represents negation, the difference set.</li><li>No operator: when used alone, it represents `OR`, the union. For example, `A B` means `A OR B`. Mixing the operators with the `+` operator increases the relevance of existing sentences but loses the semantics of `OR`. For example, `+A B` means A must be present, and then calculates the relevance of A and B in the sentence.</li><li>`()`: represents nested operations. When no outer operator is present, it has the semantics of `OR`. For example, `+A (nested clause)` means A must be present or the nested clause must be true.</li></ul>| Filters semantics for exact match, filtering based on user output syntax. You can choose to output relevance, where each word is segmented only by spaces and `+`, `-`, `()`.|
  | IN MATCH PHRASE MODE | Specifies to use phrase query. | Exact phrase match without stemming. The query result must exactly match the phrase. |

  **Example:**

  1. The output sentence must contain the word "computer".

      ```sql
      obclient> SELECT * FROM my_table WHERE MATCH (doc) AGAINST ("+computer" IN BOOLEAN MODE);
      ```

  2. The output sentence must contain the word "computer" and must not contain the word "weather".

      ```sql
      obclient> SELECT * FROM my_table WHERE MATCH (doc) AGAINST ("+computer -weather" IN BOOLEAN MODE);
      ```

  3. The output sentence must contain the word "computer", and the sentence is more likely to match if it also contains "oceanbase".

      ```sql
      obclient> SELECT * FROM my_table WHERE MATCH (doc) AGAINST ("+computer oceanbase" IN BOOLEAN MODE);
      ```

  4. Perform queries using phrase matching patterns.

     * `MATCH AGAINST` is used as the `SELECT` field for querying.

       ```sql
       obclient> SELECT id, MATCH (title, body) AGAINST ('some words' IN MATCH PHRASE MODE) AS score
           FROM test;
       ```

     * `MATCH AGAINST` is used as the `WHERE` field for querying.

       ```sql
       obclient> SELECT * FROM test WHERE MATCH (title, body) AGAINST ('some words' IN MATCH PHRASE MODE);
       ```

For more information about the `MATCH AGAINST` expression, see [MATCH AGAINST](../400.functions-of-mysql-mode/1000.other-functions-of-mysql-mode/2250.match-against-of-mysql-mode.md).

### Vectorized queries

For queries containing full-text indexes, you can choose between vectorized and non-vectorized execution. You can use the `/*+ opt_param('rowsets_enabled', '[true | false]')*/` hint to enable or disable vectorization.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If no hint is specified, whether vectorization is enabled is determined by the configuration of the vectorization engine system parameter. By default, it is enabled.</p>
</main>

**Example:**

* Enable vectorized queries.

  ```sql
  obclient> SELECT /*+ opt_param('rowsets_enabled', 'true') */ title, body
      FROM articles
      WHERE MATCH(title, body) AGAINST('tutorial');
  ```

* Disable vectorized queries.

  ```sql
  obclient> SELECT /*+ opt_param('rowsets_enabled', 'false') */ title, body
      FROM articles
      WHERE MATCH(title, body) AGAINST('tutorial');
  ```

## ES Full-text Query

OceanBase AI Database supports the SQL syntax for ES full-text queries, including the `MATCH()` and `SCORE()` statements:

* The `MATCH()` statement is used as a field after `WHERE` to indicate filtering semantics and must be used together with the `SCORE()` statement.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>Currently, there can be at most one <code>MATCH()</code> statement in the <code>WHERE</code> clause, and it cannot be used together with <code>MATCH() AGAINST()</code>.</p>
  </main>

* The `SCORE()` statement indicates the correlation of the corresponding `MATCH()` statement. The `SCORE()` statement is used in conjunction with the `MATCH()` syntax and has no meaning when used alone.

The SQL syntax for full-text queries in ES is as follows:

```sql
SELECT [select_expr_list ,] SCORE()
FROM table_name
WHERE
    MATCH(
        A_COLUNM^x, B_COLUNM^y ...,
        'expr',
        '[parameters]'
        )
... ;

parameters:
    operator=or;
    minimum_should_match=int_value;
    boost=number_value;
    score_norm=min-max;
    type={most_fields | best_fields}
```

**The related parameters are described as follows:**

* `A_COLUNM^x, B_COLUNM^y ...`: Indicates column names and their corresponding weights, where the weights are positive numbers.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>For each column in the <code>MATCH()</code> expression, you must create a full-text index, not a composite index on the columns. For information about creating full-text indexes, see <a href="../../../../300.database-object-management/500.manage-indexes-of-mysql-mode/200.create-an-index-of-mysql-mode.md">Create an index</a>.</p>
  </main>

* `expr`: The query statement, which is divided into tokens. Each token can contain a weight. The weight must be a positive number, with a default value of 1.
* `parameters`: Optional. Specifies a key-value pair list. If no additional parameters are specified, include an empty pair of quotation marks `''`. The following parameters are currently supported:

  * `operator`: the aggregation algorithm for the `expr` parameter. Valid values:

    * `or`: Indicates that the output is generated as long as one token exists. If the `minimum_should_match` parameter is specified, refer to its description below for the return result information.

  * `minimum_should_match`: A positive integer. When the `operator` parameter is `or`, this parameter specifies the minimum number of keywords in a token group that must match.
  * `boost`: A positive value indicating the `MATCH` level weight, which is multiplied by the relevance. The default value is 1.
  * `score_norm`: Specifies the normalization algorithm for a `MATCH` score during scoring. Valid value: `min-max`. By default, normalization is not performed.
  * `type`: the correlation calculation method when multiple columns are involved in a `MATCH` operation. Valid values:

    * `most_fields`: Indicates to sum the correlations of all columns.
    * `best_fields`: Indicates to take the maximum correlation value for each column.

**Example:**

1. Create a full-text index on column `col2` of table `tbl1`.

    ```shell
    obclient> CREATE FULLTEXT INDEX ft_idx_tbl1_col2 ON tbl1(col2);
    ```

2. Create a full-text index on column `col3` of table `tbl1`.

    ```shell
    obclient> CREATE FULLTEXT INDEX ft_idx_tbl1_col3 ON tbl1(col3);
    ```

3. Filter rows from table `tbl1` that contain both "OceanBase" and "Database" (at least 2 keywords, `minimum_should_match=2`), perform a full-text search on fields `col2` (weight 2) and `col3` (weight 1), and return the matching score (normalized to the range 0-1).

    ```shell
    obclient> SELECT *, SCORE() AS relevance_score
        FROM tbl1
        WHERE
            MATCH(col2^2, col3^1,
                  'OceanBase Database',
                  'operator=or;
                  minimum_should_match=2;
                  boost=1;
                  score_norm=min-max;
                  type=most_fields'
                );
    ```

    The return result is as follows:

    ```shell
    +------+-----------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    | col1 | col2      | col3                                                                                                                | relevance_score    |
    +------+-----------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    |    2 | OceanBase | OceanBase Database is a native, enterprise-level distributed database developed independently by the OceanBase team | 0.6079027355623101 |
    +------+-----------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    1 row in set
    ```

4. Filter rows containing "OceanBase" or "Database" from table `tbl1` (match at least one keyword, `minimum_should_match=1`), perform a full-text search on fields `col2` (weight 2) and `col3` (weight 1), and return the matching score (normalized to the range 0-1).

    ```shell
    obclient> SELECT *, SCORE() AS relevance_score
        FROM tbl1
        WHERE
            MATCH(col2^2, col3^1,
                  'OceanBase Database',
                  'operator=or;
                  minimum_should_match=1;
                  boost=1;
                  score_norm=min-max;
                  type=most_fields'
                );
    ```

    The return result is as follows:

    ```shell
    +------+---------------------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    | col1 | col2                | col3                                                                                                                | relevance_score    |
    +------+---------------------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    |    2 | OceanBase           | OceanBase Database is a native, enterprise-level distributed database developed independently by the OceanBase team | 0.4208104883442219 |
    |    3 | Database Management | Learn about SQL and database administration                                                                         | 0.2876526910145043 |
    +------+---------------------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    2 rows in set
    ```
