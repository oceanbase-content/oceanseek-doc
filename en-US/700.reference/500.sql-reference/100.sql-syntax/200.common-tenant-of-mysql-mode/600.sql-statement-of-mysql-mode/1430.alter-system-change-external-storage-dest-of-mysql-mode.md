# ALTER/CHANGE/MODIFY EXTERNAL_STORAGE_DEST

## Purpose

This statement is used to modify the source configuration (such as `zone`, `idc`, or `region`) of the backup or archive path, I/O throttling parameters (`max_iops` and `max_bandwidth`), and key information such as `access_id` and `access_key` for the current tenant. After modification, the new configuration will overwrite the original one.

## Limitations and considerations

* Only user tenants can execute this statement; the system tenant (sys tenant) cannot execute it.

* Before modifying the `zone`, `idc`, or `region` configuration of a path, if you need to set the region level or IDC level, you must first use the `ALTER SYSTEM MODIFY ZONE zone_name SET REGION=region_name;` or `ALTER SYSTEM MODIFY ZONE zone_name SET IDC=idc_name;` statement to set the region information or IDC information respectively. It is recommended to set the source-side configuration at the IDC level. This way, backup tasks can use an IDC with more network bandwidth resources, have a wider range of available nodes, and users do not need to worry about changes in zones within the IDCs of the cluster.

* When you modify the source-side configuration of a backup path, if any backup tasks are in progress, the change may not be detected by those tasks for up to several minutes. During this period, nodes outside the configured scope may still access the backup path, potentially generating cross-IDC or cross-region traffic.

* Only the object storage path supports changing the I/O throttling parameters (`max_iops` and `max_bandwidth`) and the `access_id` and `access_key` information. If you set I/O throttling parameters (`max_iops` and `max_bandwidth`) or `access_id`/`access_key` for a backup medium that is an NFS path, the system returns an error code `1235`, indicating that the operation is not supported.

* When setting the `ACCESS_INFO` attribute (`access_id` and `access_key`) for an object storage path, if the parameter format is incorrect (for example, contains extra `=`, or is missing `access_id` or `access_key`), the system returns the error `OB_OBJECT_STORAGE_PERMISSION_DENIED` (error code `-9116`).

* When using the Assume Role method to access object paths for backup or archive locations:

  * If you set `ACCESS_INFO = 'access_id=new_access_id&access_key=new_access_key'`, the system will report an error.

  * If you set only the I/O throttling parameters in `ATTRIBUTE` (without setting the `ACCESS_INFO` attribute), the system may indicate that the setting is not supported or will not take effect.

* Multiple settings of the same `ATTRIBUTE` + `ACCESS_INFO` pair are allowed for the same path.

## Privilege requirements

The user executing this statement must have the `ALTER SYSTEM` privilege. For more information about OceanBase AI database privileges, see [Permission classification](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

```sql
ALTER SYSTEM {ALTER|CHANGE|MODIFY} EXTERNAL_STORAGE_DEST 
  PATH [=] 'path' 
  SET [ATTRIBUTE = '[{zone=zone_name | idc=idc_name | region=region_name}][&max_iops=iops_num][&max_bandwidth=bandwidth_num]']
  [ACCESS_INFO = 'access_id=new_access_id&access_key=new_access_key'];
```

## Parameters

| Parameter | Description |
| --------------------------------------------------- | -------------------------------------------------- |
| path | Specify the backup or archive path for the key information to be changed. The path must be a backup or archive path already set for the current tenant, and it must be an object storage path. The path must also contain `host` Information. Taking S3 as an example, the path format is as follows: `s3://oceanbase-test-bucket/backup/databackup?host=***`. |
| zone=zone_name \ \| idc=idc_name \ \| region=region_name | Specifies the source for the current backup or archive path. Valid values: `zone`, `idc`, or `region`. Only one configuration level from the three levels can be selected at a time, or none can be set. If not explicitly specified, the default is no setting.<p>When modifying the source-side configuration of the log archive path:<ul><li>Since all traffic for log archiving is written by the leader replica, there is no difference in access priority for the log archive path; only the range of nodes that can access the archive path is limited. If you need to set multiple zones, IDCs, or regions, separate the values with commas (,) or semicolons (;). For example, `zone=z1,z2;z3` indicates that `z1`, `z2`, and `z3` are the sources of the archive path. </li> <li>When you modify `zone`, `idc`, or `region`, the leader replica is required to be within the specified `zone`, `idc`, or `region`. Otherwise, log archiving will not proceed.</li></ul></p> <p>When modifying the source configuration of the backup path:<ul><li>If you need to set multiple zones, IDCs, or regions, separate them with commas (,) and semicolons (;). Specifically:<ul><li>A comma (,) indicates that nodes within the zones, IDCs, or regions on either side have the same priority when selecting nodes to execute the backup task.</li> <li>A semicolon (;) indicates that nodes within the zone, IDC, or region on the left have a higher priority than those on the right. That is, nodes within the zone, IDC, or region on the left are preferentially selected to execute the backup task.</li></ul>For example, `zone=z1,z2;z3` specifies `z1`, `z2`, and `z3` as the backup sources. `z1` and `z2` have the same priority, and both have a higher priority than `z3`.</li> <li>When modifying `zone`, `idc`, or `region` for the backup path, the leader node of the Root Service must be within the specified `zone`, `idc`, or `region`; otherwise, the backup task will fail to write backup metadata to the target backup path, ultimately causing the backup task to fail. It is recommended that the source backup path setting include the Primary Zone scope.</li></ul></p> |
| max_iops | Specifies the maximum IOPS allowed for the current backup or archive path. The value must be a positive integer, indicating approximately how many I/O requests per second are allowed. If not explicitly set, this path has no IOPS limit, which is determined by the underlying object storage and network capabilities.<p>Example: `max_iops=1000`</p> |
| max_bandwidth | Specifies the maximum bandwidth allowed for the current backup or archive path. The value must be a positive integer with a unit. Supported units are kb, mb, and gb, representing KB/s, MB/s, and GB/s respectively. If not explicitly set, it indicates that the path has no bandwidth limit.<p>Example: `max_bandwidth=1000mb`</p> |
| access_id=new_access_id&access_key=new_access_key | Specify the new value after the change. `access_id` and `access_key` Information. `access_id` and `access_key` Both fields are required. |

## Examples

### Modify the source configuration of the archive path

  Assume the original source configuration for the archive path is `zone=z1,z2,z3`, and now you need to change it to `region=region1`. After the modification, only nodes in `region1` will be able to access this path.

  * NFS

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='file:///data/nfs/backup/archive' SET ATTRIBUTE = 'region=region1';
    ```

  * S3

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'region=region1';
    ```

  * Object storage services compatible with the S3 protocol (OBS, GCS, and COS)

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=obs.****.myhuaweicloud.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=https://storage.googleapis.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=cos.ap-xxxx.myqcloud.com' SET ATTRIBUTE = 'region=region1';
    ```

### Set I/O throttling parameters (`max_iops` and `max_bandwidth`) for the archive path

You can set both the `max_iops` and `max_bandwidth` parameters, or set either one of them separately. These parameters are only supported for object storage paths; NFS paths do not support I/O throttling.

* S3

  Set both the `max_iops` and `max_bandwidth` parameters. Example:

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'max_iops=1000&max_bandwidth=1000mb';
  ```

* Object storage services compatible with the S3 protocol (OBS, GCS, and COS)

  Set both the `max_iops` and `max_bandwidth` parameters at the same time. Example:

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=obs.****.myhuaweicloud.com' SET ATTRIBUTE = 'max_iops=1000&max_bandwidth=1000mb';
  ```

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=https://storage.googleapis.com' SET ATTRIBUTE = 'max_iops=1000&max_bandwidth=1000mb';
  ```

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=cos.ap-xxxx.myqcloud.com' SET ATTRIBUTE = 'max_iops=1000&max_bandwidth=1000mb';
  ```

### Set I/O throttling parameters (`max_iops` and `max_bandwidth`) for the backup path

<main id="notice" type='explain'>
<h4>Note</h4>
<p>Suggestions for setting I/O throttling parameters:</p>
<ul><li>For high-concurrency, bandwidth-sensitive multi-tenant environments, you can set different <code>max_iops</code> or <code>max_bandwidth</code> values for different backup paths to isolate the impact of backups on online business bandwidth and IOPS.</li>
<li>We recommend that you start with a lower value and gradually adjust it based on your actual network bandwidth and the object storage service's rate-limiting policies. For example, begin by setting it to <code>max_iops=500&max_bandwidth=100mb</code> to observe the performance, then fine-tune the values based on backup duration and business peak loads.</li></ul>
</main>

You can set both the `max_iops` and `max_bandwidth` parameters, or set either one of them separately. These parameters are supported only for object storage paths; NFS paths do not support setting I/O throttling parameters.

* S3

  Set both the `max_iops` and `max_bandwidth` parameters. Example:

  ```shell

  ```

* Object storage compatible with the S3 protocol (OBS, GCS, and COS)

  You can also set both the `max_iops` and `max_bandwidth` parameters. Example:

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=obs.****.myhuaweicloud.com' SET ATTRIBUTE = 'max_iops=1000&max_bandwidth=1000mb';
  ```
