# CREATE CONCURRENT_LIMITING_RULE

## Description

This statement is used to create a rate-limiting rule and specify the throttling scope to limit the concurrency of specific SQL statements.

## Privilege requirements

To execute the `CREATE CONCURRENT_LIMITING_RULE` statement, the current user must have the CREATE privilege. For more information about OceanBase AI database privileges, see [Permission classification](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

```sql
CREATE CONCURRENT_LIMITING_RULE [ IF NOT EXISTS ] `ccl_rule_name`
ON `database`.`table`
TO '<usename>'@'ip'
FOR { ALL | UPDATE | SELECT | INSERT | DELETE }
filter_options:
    [ FILTER BY KEYWORD('KEYWORD1', 'KEYWORD2',…) ]
 with_options:
    WITH MAX_CONCURRENCY = value1 [per sql]
```

## Parameters

| Parameter | Description |
| ---------------------------- | ---------- |
| `ccl_rule_name` | Required. The name of the throttling rule.<main id="notice" type='explain'><h4>Note</h4><p>To avoid conflicts with SQL keywords, we recommend that you add a backtick (`` ` ``) before and after the rule name.</p></main> |
| `database`.`table` | Required. The name of the database or table. You can use an asterisk (*) to match any characters. <main id="notice" type='explain'><h4>Note</h4><p>To avoid conflicts with SQL keywords, we recommend that you add a backtick (`` ` ``) before and after the rule name.</p></main> |
| `<usename>@<host>` | Optional. The username, which can contain an asterisk (*) to represent all users. In the host field, a percent sign (%) can be used to indicate any match. |
| `ALL`\ \| `UPDATE \ \| SELECT \ \| INSERT\ \| DELETE` | Required. Indicates the type of SQL statement. Currently supported: `ALL`, `UPDATE`, `SELECT`, `INSERT` and `DELETE`. Type.<main id="notice" type='explain'><h4>Note</h4><p>Each rate-limiting rule supports only one type of SQL statement.</p></main> |
| `[ filter_options ]` | Optional. Specifies the throttling keywords.<main id="notice" type='explain'><h4>Note</h4><p><ul><li>Keywords are concatenated with the wildcard character <code>%</code>. For example, given three keywords <code>'asdasd', 'c2 = 123', 'xxyyzz'</code>, they are concatenated into <code>'%asdasd%c2 = 123%xxyyzz%'</code>, which is then used for wildcard matching in the SQL text.</li><li>If a keyword contains <code>'_'</code>, it is escaped. For example, <code>'table_t1'</code> is recorded as <code>'%table\_t1%'</code>.</li><li>The number of throttling keywords is not limited, but the length of the concatenated string must not exceed <code>OB_MAX_VARCHAR_LENGTH=1048576</code>.</li></ul></p></main> |
| `with_options` | Required. Specifies the concurrency level for rate limiting and whether the throttling statistics are counted at the rule level or the format SQL ID statement level. Currently, only `MAX_CONCURRENCY` parameter, which indicates the maximum concurrency of SQL statements that match this throttling rule. |

## Examples

Run the following command to enable throttling by keyword:

```shell
obclient> CREATE CONCURRENT_LIMITING_RULE IF NOT EXISTS  `sql1_keywords_ccl_rule`
ON *.* TO '%'@'%' FOR SELECT
FILTER BY KEYWORD('table1', 'table2', 'c1') WITH MAX_CONCURRENCY 100;
```
