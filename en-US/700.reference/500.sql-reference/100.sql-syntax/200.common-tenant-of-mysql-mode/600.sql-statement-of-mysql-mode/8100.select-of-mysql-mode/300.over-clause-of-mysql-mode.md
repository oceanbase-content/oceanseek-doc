# WINDOW clause

## Purpose

In a `SELECT` query, the `WINDOW` clause is used to define named windows with specific window specifications. A "window", also known as a frame, can be either `ROWS`-based or `RANGE`-based in OceanSeek. The former is based on physical row offsets, while the latter is based on logical value offsets.

Use an analytic function and add `OVER window_name` after it to reference the window specification. Functions that can be used in the `OVER` clause are called analytic functions. For more information about analytic functions, see the **Analytic functions** section in [Function overview](../../400.functions-of-mysql-mode/100.function-overview-of-mysql-mode.md).

## Syntax

```sql
window_clause:
    WINDOW window_definition_list

window_definition_list:
    window_definition [, window_definition ...]

window_definition:
    window_name AS ([PARTITION BY expression_list] [ORDER BY order_by_condition_list] [win_window])

expression_list:
    expression [, expression ...]

order_by_condition_list:
    order_by_condition [, order_by_condition ...]

order_by_condition:
    expression [ASC | DESC]

win_window:
    {ROWS | RANGE} BETWEEN win_bounding AND win_bounding
    | {ROWS | RANGE} win_bounding

win_bounding:
    CURRENT ROW
    | win_interval {PRECEDING | FOLLOWING}

win_interval:
    expression
    | INTERVAL expression date_unit

date_unit:
    DAY
    | DAY_HOUR
    | DAY_MICROSECOND
    | DAY_MINUTE
    | DAY_SECOND
    | HOUR
    | HOUR_MICROSECOND
    | HOUR_MINUTE
    | HOUR_SECOND
    | MICROSECOND
    | MINUTE
    | MINUTE_MICROSECOND
    | MINUTE_SECOND
    | MONTH
    | QUARTER
    | SECOND
    | SECOND_MICROSECOND
    | WEEK
    | YEAR
    | YEAR_MONTH
```

## Parameters

| Parameter | Description |
| ------------------------------- | ----------------------------------------------------------- |
| WINDOW window_definition_list | Specifies the window definition for the analytic function. `window_definition_list` Defines a list for the window. |
| window_definition | Represents the window definition, including the window name, grouping method, sorting method, and window range. For more information, see [window_definition](#window_definition). |

### window_definition

* `window_name`: The name of the window, used to identify the defined window.

* `PARTITION BY expression_list`: Optional. Specifies the list of grouping keys for the analytic function. It groups the input data based on the specified list of expressions and applies the analytic function to each group. This allows independent calculations to be performed on each group within the analytic function, rather than calculating the entire dataset.

  * `expression`: a column or expression.

* `ORDER BY order_by_condition_list`: Optional. Specifies the list of sorting rules for the grouped result set, defining how data within the window is ordered.

  * `expression [ASC | DESC]`: the sorting expression defined for the window. `ASC | DESC` is an optional parameter that specifies the sorting order. `ASC` indicates ascending order (default), and `DESC` indicates descending order.

* `win_window`: Optional. Specifies the definition of the window range, including the boundary conditions for `ROWS` or `RANGE`. For more information, see [win_window](#win_window).

#### win_window

* `{ROWS | RANGE} BETWEEN win_bounding AND win_bounding`: Indicates that the window boundaries are determined by two boundary values. Specifically:

  * `ROWS | RANGE`: specifies the frame semantics.

    * `ROWS`: Indicates a physical window. The calculation is based on the first `N` and last `N` rows after sorting according to the `ORDER BY` clause.
    * `RANGE`: specifies the range of values for the corresponding column in the current row.

  * `win_bounding`: specifies the boundary condition for the window range. It can be the current row or an interval relative to the current row. For more information, see [win_bounding](#win_bounding).

* `{ROWS | RANGE} win_bounding`: Indicates that the window boundary is determined by a single boundary value.

#### win_bounding

* `CURRENT ROW`: Indicates that the current row is used as the window boundary.

* `win_interval {PRECEDING | FOLLOWING}`: Specifies whether the relative position is before or after the current row when calculating the current row. It specifies the start and end positions of the window. The details are as follows:

  * `win_interval`: Defines the interval size of the window. It can be a fixed value, an unspecified value, a decimal number, unlimited, or a date unit.

    * `expression`: Indicates the starting position of the window. The value can be an integer representing the number of rows to offset, or a specific keyword, as follows:

      * `UNBOUNDED PRECEDING`: The window starts from the beginning of the dataset.
      * `UNBOUNDED FOLLOWING`: indicates that the end of the window is unbounded, meaning the calculation extends to the end of the last row.
      * `CURRENT ROW`: The starting position of the window is the current row.

    * `INTERVAL expression date_unit`: defines the time interval, consisting of an expression and a time unit.

      <main id="notice" type='notice'>
        <h4>Notice</h4>
        <p><ul><li>In the current version of OceanSeek, the <code>INTERVAL</code> clause can only be used together with <code>RANGE</code>.</li><li>When using the <code>ORDER BY</code> clause to define the sorting order of data within a window, ensure that the sorting expression in the window definition is in date format.</li></ul></p>
      </main>

      * `expression`: the interval expression. The value can be any integer, indicating the number of intervals.
      * `date_unit`: the unit of the interval. Valid values: `YEAR`, `MONTH`, `DAY`, and `HOUR`.

  * `PRECEDING`: the first `N` rows.

  * `FOLLOWING`: the next `N` rows.

## Examples

Query the data in specified columns of the `test_tbl1` table and calculate the sum of `col5` across different window conditions for each row.

1. Create the table `test_tbl1`.

   ```sql
   CREATE TABLE test_tbl1 (col1 INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
     col2 INT,
     col3 VARCHAR(50),
     col4 DATE,
     col5 INT);
   ```

2. Insert test data.

   ```sql
   INSERT INTO test_tbl1(col2, col3, col4, col5)
     VALUES(100, 'A1', '2017-01-01', 120),
           (100, 'A1', '2018-01-01', 20),
           (100, 'A1', '2019-01-01', 100),
           (100, 'A1', '2020-01-01', 40),
           (100, 'B1', '2021-01-01', 80),
           (100, 'B1', '2022-01-01', 60),
           (200, 'B1', '2017-01-01', 70),
           (200, 'B1', '2018-01-01', 50),
           (200, 'C1', '2019-01-01', 90),
           (200, 'C1', '2020-01-01', 30),
           (200, 'C1', '2021-01-01', 110),
           (200, 'C1', '2022-01-01', 10);
   ```

3. Select columns `col1`, `col3`, and `col5` from the `test_tbl1` table, then use aggregate functions to calculate the sum of `col5` under different window conditions. Finally, output the results in ascending order by the value of `col1`. The window conditions include different `PARTITION BY` and `ORDER BY` clauses, as well as `ROWS` and `RANGE` clauses, as follows:

   1. `my_window_1` has no specific condition, so the entire table is considered a window. `sum1` calculates the sum of `col5` across the entire table.
   2. `my_window_2` is partitioned by `col3`. `sum2` calculates the sum of `col5` for each `col3` partition.
   3. `my_window_3` is sorted by the value of `col5`. `sum3` calculates the sum of `col5` values up to (including) the current row.
   4. In `my_window_4`, the `col5` column is set to unspecified in the `col3` partition. `sum4` calculates the sum of `col5` values sorted by `col5` within each `col3` partition.
   5. In `my_window_5`, the rows within the `col3` partition are set to undefined in the order of `col5`. `sum5` calculates the sum of `col5` values in each `col3` partition.
   6. `my_window_6` sets the current row as the current row in the `col3` partition, ordered by `col5`. `sum6` calculates the sum of `col5` for the current row in each `col3` partition.
   7. `my_window_7` sets the window for each row in the `col3` partition to the rows that precede it by one row in the order of `col5`. `sum7` calculates the sum of `col5` values for the current row and the preceding row in each `col3` partition.
   8. `my_window_8` in the `col3` partition sets the first and last rows in order of `col5`. `sum9` calculates the sum of `col5` for the first to last row in each `col3` partition.
   9. `my_window_9` sets the rows within the `col3` partition in order of `col4` to the first and last year. `sum10` calculates the sum of `col5` from the first year to the last year within each `col3` partition.

   ```sql
   SELECT col1, col3, col4, col5,
         SUM(col5) OVER my_window_1 AS sum1,
         SUM(col5) OVER my_window_2 AS sum2,
         SUM(col5) OVER my_window_3 AS sum3,
         SUM(col5) OVER my_window_4 AS sum4,
         SUM(col5) OVER my_window_5 AS sum5,
         SUM(col5) OVER my_window_6 AS sum6,
         SUM(col5) OVER my_window_7 AS sum7,
         SUM(col5) OVER my_window_8 AS sum8,
         SUM(col5) OVER my_window_9 AS sum9
     FROM test_tbl1
     WINDOW
       my_window_1 AS (),
       my_window_2 AS (PARTITION BY col3),
       my_window_3 AS (ORDER BY col5),
       my_window_4 AS (PARTITION BY col3 ORDER BY col5),
       my_window_5 AS (PARTITION BY col3 ORDER BY col5 ROWS UNBOUNDED PRECEDING),
       my_window_6 AS (PARTITION BY col3 ORDER BY col5 ROWS CURRENT ROW),
       my_window_7 AS (PARTITION BY col3 ORDER BY col5 ROWS 1 PRECEDING),
       my_window_8 AS (PARTITION BY col3 ORDER BY col5 ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING),
       my_window_9 AS (PARTITION BY col3 ORDER BY col4 RANGE BETWEEN INTERVAL 1 YEAR PRECEDING AND INTERVAL 1 YEAR FOLLOWING)
     ORDER BY col1;
   ```

   The return result is as follows:

   |    1 | A1   | 2017-01-01 |   10 |  780 |  100 |   10 |   10 |   10 |   10 |   10 |   30 |   30 |
