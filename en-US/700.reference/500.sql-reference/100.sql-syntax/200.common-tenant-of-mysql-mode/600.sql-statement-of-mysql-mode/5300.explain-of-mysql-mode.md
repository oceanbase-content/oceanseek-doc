# EXPLAIN

## Purpose

This statement is used to explain the [execution plan](../../../../1000.performance-tuning-guide/500.sql-optimization/200.sql-execution-plan/100.introduction-to-sql-execution-plans.md) of an SQL statement, which can be a `SELECT`, `DELETE`, `INSERT`, `REPLACE`, or `UPDATE` statement.

`EXPLAIN` is synonymous with `DESCRIBE` and `DESC`.

## Syntax

```sql
{EXPLAIN [INTO table_name ] [SET statement_id = string]
 | DESCRIBE
 | DESC}
[explain_type] [PRETTY | PRETTY_COLOR] dml_statement

explain_type:
    BASIC
  | OUTLINE 
  | EXTENDED
  | EXTENDED_NOADDR
  | PARTITIONS
  | FORMAT = {TRADITIONAL| JSON}

dml_statement:
    SELECT statement
  | DELETE statement
  | INSERT statement
  | REPLACE statement
  | UPDATE statement
```

## Parameters

| **Parameters** | **Description** |
| ------------------------------- | ------------------------------------------- |
| INTO table_name | Indicates that the plan information of `EXPLAIN` is stored in the specified table. If `INTO table_name` is not specified, the result is queried from the `PLAN_TABLE` table by default. |
| SET statement_id | Indicates that the current query uses a string tag to facilitate subsequent querying of the SQL plan information. If not specified, `SET statement_id` By default, an empty string is used as the information marker. |
| PRETTY \ \| PRETTY_COLOR | Parent nodes and child nodes in the plan tree are connected by tree lines or colored tree lines to make the execution plan easier to read. |
| BASIC | Specifies the basic information of the output plan, such as operator ID, operator name, and referenced table name. |
| OUTLINE | Specify the output plan information to include `OUTLINE` Information. |
| EXTENDED | `EXPLAIN` Additional information is generated, including: the input and output columns of each operator, partition information of the accessed table, currently used filter information. If an index is used by the current operator, the index columns and the extracted query range are displayed. |
| EXTENDED_NOADDR | Display additional information in a concise manner. |
| PARTITIONS | Displays partition information. |
| FORMAT = {TRADITIONAL\ \| JSON} | Specifies the output format of `EXPLAIN` as follows: <ul><li>`TRADITIONAL`: table output format    </li> <li>`JSON`: `KEY:VALUE` Output format. JSON is displayed as a JSON string, including `EXTENDED` and `PARTITIONS` information. </li></ul> |
| dml_statement | DML statements. |

* Explain the execution plan of an `UPDATE` statement.

  ```shell
  obclient> CREATE TABLE employees (emp_id INT PRIMARY KEY, emp_name VARCHAR(50), salary INT);
  obclient> INSERT INTO employees VALUES (1, 'Alice', 5000), (2, 'Bob', 6000);
  obclient> EXPLAIN UPDATE employees SET salary = salary * 1.1 WHERE emp_id > 1;
  ```
