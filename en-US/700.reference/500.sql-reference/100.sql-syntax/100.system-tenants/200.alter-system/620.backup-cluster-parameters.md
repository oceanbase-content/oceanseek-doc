# BACKUP CLUSTER PARAMETERS

The `ALTER SYSTEM BACKUP CLUSTER PARAMETERS` statement is used to back up cluster-level parameters.

## Limitations and considerations

* This statement can only be executed by the `root` user in the `sys` tenant.

* This statement only backs up cluster-level parameters that have non-default settings.

  <main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Parameters such as <code>all_server_list</code>, <code>rootservice_list</code>, and <code>debug_sync_timeout</code> are not backed up, regardless of whether their values are default or not. </p>
  </main>

## Syntax

```sql
ALTER SYSTEM BACKUP CLUSTER PARAMETERS TO 'parameters_backup_path';
```

## Parameters

| Parameter | Description |
| ------------------------ | --------------------------------------------------------------------------- |
| parameters_backup_path | You must specify the target path for the backup files of cluster-level parameters. The requirements for this path are the same as those for the backup destination path used in data backup. For more information, see [Prepare for backup](../../../../../600.manage/600.backup-and-recovery/400.data-backup/100.preparation-before-data-backup.md). |

## Examples

Back up the cluster-level parameters to the `s3://oceanbase-test-bucket/backup/cluster_parameters?host=***&access_id=***&access_key=***` directory.

```shell
obclient> ALTER SYSTEM BACKUP CLUSTER PARAMETERS TO 's3://oceanbase-test-bucket/backup/cluster_parameters?host=***&access_id=***&access_key=***';
```
