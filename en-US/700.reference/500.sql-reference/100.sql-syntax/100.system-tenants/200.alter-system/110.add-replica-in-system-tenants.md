# ADD REPLICA

## Description

This statement is used to manually add a log stream replica.

## Limitations and considerations

* Before adding a replica, ensure that the target server has available resources and that no replicas of this log stream exist on those resources.

* The sys tenant can add replicas to log streams of all tenants, while a user tenant can only add replicas to its own log streams.

* This statement can add only one replica at a time. To add multiple replicas, you need to execute the statement multiple times.

* For the same log stream of a tenant, except that multiple replica migration tasks can be executed in parallel, only one disaster recovery task (including adding replicas, deleting replicas, changing replica types, and modifying the quorum size of the log stream) can be executed at a time.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>You can query the <code>CDB_OB_LS_REPLICA_TASKS</code> view in the sys tenant to check whether any disaster recovery tasks are running. You can also query the <code>DBA_OB_LS_REPLICA_TASKS</code> view in a user tenant to check whether any disaster recovery tasks are running.</p>
    </main>

## Privilege requirements

The user executing this statement must have the `ALTER SYSTEM` privilege. For more information about OceanBase AI database privileges, see [Permission classification](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

```sql
ALTER SYSTEM ADD REPLICA
    LS [=] ls_id
    SERVER [=] 'svr_ip:svr_port'
    REPLICA_TYPE [=] 'replica_type'
    [DATA_SOURCE [=] 'data_source']
    [PAXOS_REPLICA_NUM [=] $paxos_replica_num]
    [TENANT [=] '$tenant_name'];
```

## Parameters

| **Parameters** | **Description** |
| ------------------- | ------------------------------------ |
| ls_id | Specifies the log stream ID to which a replica is to be added. |
| svr_ip:svr_port | Specify the IP address and port of the target server to which you want to add the replica. For example, `xxx.xx.xxx.001:2882`. |
| replica_type | Specifies the type of replica to add. Currently, only the following two types are supported (case-insensitive):<ul><li>Full-featured replica: represented by <code>FULL</code> or <code>F</code>.</li><li>Read-only replica: represented by <code>READONLY</code> or <code>R</code>.</li></ul>  <main id="notice" type='explain'><h4>Note</h4><p><code>F</code> replicas can be elected as Leaders (primary replicas), while <code>R</code> replicas cannot be elected as Leaders.</p></main> |
| data_source | Optional. The data source address of the replica to be added. Format: `svr_ip:svr_port`, for example, `xxx.xx.xxx.002:2882`. If this value is not explicitly specified, the system automatically selects an available data source.<main id="notice" type='notice'><h4>Note</h4><p>If the specified data source is unavailable, the system returns an error.</p></main> |
| paxos_replica_num | Optional. Specifies the required number of quorum members for the log stream leader. If this value is not explicitly specified, the system will use the current default value of `paxos_replica_num`. Also, the number of F replicas for a log stream cannot exceed 7.<main id="notice" type='notice'><h4>Notice</h4><p>To specify a value for this parameter, the following conditions must be met:<ol><li>After modification, <code>paxos_replica_num</code> must form a majority.</li><li>The value of <code>paxos_replica_num</code> must be greater than or equal to the number of members in <code>MEMBER_LIST</code> of the current leader replica. You can confirm this by querying the <code>CDB_OB_LS_LOCATIONS</code> view for the sys tenant, or the <code>DBA_OB_LS_LOCATIONS</code> view for user tenants.</li><li>The absolute change in the value of <code>paxos_replica_num</code> cannot exceed 1. For example, if the current <code>paxos_replica_num</code> is 2, you can only set it to 3.</li></ul>If any of the above conditions are not met for the specified value, the system will report an error.</p></main> |
| tenant_name | Optional. Specifies the tenant to operate on. If you do not explicitly specify the tenant, the default tenant is the current tenant. <main id="notice" type='notice'><h4>Notice</h4><p>The system tenant can specify other tenants, while a user tenant can only specify itself. This statement does not support using <code>ALL</code>, <code>ALL_USER</code>, or <code>ALL_META</code> to specify all tenants, user tenants, or all Meta tenants.</p></main> |

## Examples

Execute the following command in the sys tenant to add a log stream replica for the `mysql001` tenant.

```sql
ALTER SYSTEM ADD REPLICA
    LS = 1001
    SERVER = 'xxx.xxx.xxx.001:2882'
    REPLICA_TYPE = 'F'
    DATA_SOURCE = 'xxx.xxx.xxx.002:2882'
    PAXOS_REPLICA_NUM = 3
    TENANT = 'mysql001';
```

For more examples of adding log stream replicas, see [Add a replica](../../../../../600.manage/300.replica-management/200.replica-distribution/200.locality-common-operations/300.add-replica.md).
