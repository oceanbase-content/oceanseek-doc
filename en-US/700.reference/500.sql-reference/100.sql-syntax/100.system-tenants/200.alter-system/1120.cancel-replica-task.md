# CANCEL REPLICA TASK

## Purpose

This statement is used to manually cancel a running replica task.

## Limitations and considerations

* The current version only supports canceling two types of replica tasks: adding replicas and migrating replicas. You can view which disaster recovery tasks are currently in progress through the `DBA_OB_LS_REPLICA_TASKS` view.
* This statement can only cancel one disaster recovery task for a tenant at a time.
* The cancel command is idempotent. Executing it multiple times has the same effect as executing it once.
* You must ensure that the task to be canceled is still running. If the task has already completed, it cannot be canceled.
* A successful return from the cancel command only indicates that the RS has sent the cancellation RPC to the underlying layer. The underlying layer may not guarantee a successful cancellation, as replica task execution is divided into multiple stages. If a task has reached its final stage, it cannot be canceled. The result of a task cancellation can be checked through the `TASK_STATUS` field in the `DBA_OB_LS_REPLICA_TASK_HISTORY` view. If it is `CANCELED`, the cancellation was successful.

## Privilege requirements

The user executing this statement must have the `ALTER SYSTEM` privilege. For more information about OceanBase AI database privileges, see [Permission classification](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

```sql
ALTER SYSTEM CANCEL REPLICA TASK
    TASK_ID [=] task_id
    [TENANT [=] '$tenant_name'];
```

## Parameters

| **Parameters** | **Description** |
| ------------------- | ------------------------------------ |
| task_id | Specify the task ID of the replica task to be canceled. `TASK_ID`. |
| tenant_name | Optional. Specifies the tenant to operate on. If you do not explicitly specify the tenant, the default tenant is the current tenant. <main id="notice" type='notice'><h4>Notice</h4><p>The system tenant can specify other tenants, while a user tenant can only specify itself. This statement does not support using <code>ALL</code>, <code>ALL_USER</code>, or <code>ALL_META</code> to specify all tenants, user tenants, or all Meta tenants.</p></main> |

## Examples

Execute the following command in the sys tenant to cancel the ongoing replica task in tenant `mysql001`.

```sql
ALTER SYSTEM CANCEL REPLICA TASK
    TASK_ID = 'Y13CE64586BD4-000610C5F3EDBBCB-0-0'
    TENANT = 'mysql001';
```

For more examples of canceling a running replica task, see [Cancel a replica task](../../../../../600.manage/300.replica-management/200.replica-distribution/200.locality-common-operations/900.cancel-a-replica-task.md).
