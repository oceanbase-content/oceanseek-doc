# RECOVER STANDBY CANCEL

## Description

During segmented or continuous log replay for a standby tenant, you can use the `ALTER SYSTEM RECOVER... CANCEL` statement to cancel log replay for the standby tenant.

## Privilege requirements

It must be executed by the `root` user of the `sys` tenant (`root@sys`) or the administrator user of a user tenant (`root` user).

## Syntax

```sql
ALTER SYSTEM RECOVER STANDBY [TENANT [=] tenant_name] CANCEL;
```

## Parameters

| Parameter | Description |
| ------------ | ------------------------------------------------------------------------------------------------------------ |
| tenant_name | Specifies the standby tenant for which log replay is to be canceled. Only one standby tenant can be specified at a time. To specify multiple tenants, you need to run this command multiple times.<main id="notice" type='notice'> <h4>Notice</h4> <p>Only the system tenant needs to specify the tenant to operate on using the <code>TENANT = tenant_name</code> clause. User tenants can only execute this command for themselves and cannot specify the <code>TENANT = tenant_name</code> clause.</p></main> |

## Examples

* The system tenant of the cluster where the standby tenant `restore_mysql_tenant` resides cancels the log replay for the standby tenant.

  ```sql
  obclient [oceanbase]> ALTER SYSTEM RECOVER STANDBY TENANT restore_mysql_tenant CANCEL;
  ```

* The standby tenant `restore_mysql_tenant` cancels the log replay for the current tenant.

  ```shell
  obclient [SYS]> ALTER SYSTEM RECOVER STANDBY CANCEL;
  ```
