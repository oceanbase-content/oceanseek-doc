# REFRESH

## Purpose

This statement series is used to trigger refresh operations, including refreshing schemas, time zone information, and various caches.

This statement can only be executed in the sys tenant.

## Syntax

```sql
alter_system_refresh_stmt:
  ALTER SYSTEM refresh_action;

refresh_action:
  REFRESH SCHEMA
  | REFRESH TIME_ZONE_INFO
  | FLUSH KVCACHE [TENANT [=] tenant_name] [CACHE [=] cache_name]
```

## Parameters

| **Parameters** | **Description** |
| ------------------------ | ---------------------------- |
| REFRESH SCHEMA | Refresh the schema. <br>**Note** Normally, when the system performs a DDL operation, the Root Service proactively notifies all OBServer nodes to refresh their schemas. If an OBServer node fails or the network connection to the Root Service is interrupted, manual schema refresh is required. |
| REFRESH TIME_ZONE_INFO | Notifies all servers in the cluster to update their local time zone information.  <main id="notice" type='explain'><h4>Note</h4><p>This parameter is not supported in the current version.</p></main> |
| FLUSH KVCACHE | Clear the dynamically scalable memory of the KVCache.  <ul><li> If specified `tenant_name` and `cache_name`, then the specified KVCache for the specified tenant is cleared. </li>   <li> If only `tenant_name`, then all KVCache of the specified tenant will be cleared. </li>   <li> If not specified `tenant_name` and `cache_name`, all tenant KVCache will be cleared. </li></ul> |

## Examples

* Refresh the schema.

  ```shell
  obclient> ALTER SYSTEM REFRESH SCHEMA;
  Query OK, 0 rows affected
  ```

* Refresh all KV caches.

  ```shell
  obclient> ALTER SYSTEM FLUSH KVCACHE;
  Query OK, 0 rows affected
  ```

* Refresh the user tenant's KVCache.

  ```shell
  obclient> ALTER SYSTEM FLUSH KVCACHE TENANT 'MySQL';
  Query OK, 0 rows affected
  ```
