# PARAMETER

## Purpose

- The `ALTER SYSTEM [SET] parameter_name = expression` statement is used to modify the value of a parameter.

- The `ALTER SYSTEM RESET parameter_name` statement is used to reset the value of a parameter.

Configuration parameters in OceanSeek are divided into cluster-level parameters and tenant-level parameters. Cluster-level parameters apply to all nodes in the cluster, while tenant-level parameters apply to all nodes where the current tenant resides. For more information about parameters, see [Overview of parameters and system variables](../../../../800.configuration-items-and-system-variables/000.configuration-items-and-system-variables-overview.md).

## Limitations and considerations

* Only the `sys` tenant can modify or reset cluster-level parameters. User tenants cannot modify or reset cluster-level parameters.

* Parameter effectiveness generally falls into two categories: dynamic and restart. Most parameters are dynamic, meaning they take effect without restarting the OBServer node. Before modifying a parameter, you can use the `SHOW PARAMETERS LIKE` statement to confirm its effectiveness mode. For detailed operations on checking the effectiveness mode of parameters, see [Cluster parameters](../../../../../600.manage/100.cluster-management/100.compute-service-management/200.cluster-configuration-items.md).

## Privilege requirements

To execute the `ALTER SYSTEM [SET] parameter_name = expression` statement and the `ALTER SYSTEM RESET parameter_name` statement, the current user must have the `ALTER SYSTEM` privilege. For more information about OceanBase AI database privileges, see [Permission classification](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

### Modify the value of a parameter

```sql
ALTER SYSTEM [SET] alter_system_set_parameter_action [, alter_system_set_parameter_action...]

alter_system_set_parameter_action:
parameter_name = expression [COMMENT [=] 'text'] [SCOPE = {MEMORY | SPFILE | BOTH}] [SERVER [=] 'ip:port' | ZONE [=] 'zone_name' | TENANT [=] {sys | all_user | all | all_meta | tenant_name}]
```

#### Parameters

| **Parameters** | **Description** |
| ----------------- | ----------------------- |
| parameter_name | Specifies the name of the parameter to be modified. |
| expression | Specifies the value of the modified parameter. |
| COMMENT | Add comments about this modification. This parameter is optional, but it is recommended that you do not omit it. |
| SCOPE | Specifies the scope of effect for this parameter modification. The main scopes are as follows: <ul><li>`MEMORY`: Indicates that only the value of the parameter in memory is modified. The modification takes effect immediately but will be lost after the OBServer node restarts. (Currently, no parameters support this method.)</li>   <li>`SPFILE`: Indicates that only the parameter values in the configuration file are modified. The changes take effect after the OBServer node is restarted.</li>   <li>`BOTH`: Indicates that both the configuration table and the memory value are modified. The changes take effect immediately and remain valid after the OBServer node restarts.</li> </ul>  </br>The default value of `SCOPE` is `BOTH`. |
| SERVER | Specify the OBServer node in the cluster whose parameter value needs to be modified. Only one OBServer node can be specified. |
| ZONE | Specify the zone in the cluster whose parameter value needs to be modified. Only one zone can be specified. After a zone is specified, the modification takes effect on all OBServer nodes within that zone. You cannot specify both a zone and a server. |
| TENANT | The system tenant specifies the tenant whose parameter values are to be modified. If not specified, the current tenant is used by default. Valid values: <ul><li><code>sys</code>: specifies to modify the parameter values of the system tenant.</li> <li><code>all_user</code>, <code>all</code>: specifies to modify the parameter values of all user tenants.<main id="notice" type='explain'><h4>Note</h4><p><code>TENANT = all_user</code> and <code>TENANT = all</code> have the same semantics. When you need to modify the parameter values for all user tenants, it is recommended to use <code>TENANT = all_user</code>. The latter <code>TENANT = all</code> will be deprecated in the future.</p></main></li> <li><code>all_meta</code>: specifies to modify the parameter values of all Meta tenants.</li> <li><code>tenant_name</code>: specifies a particular tenant. Only one tenant can be specified at a time.</li></ul></br>Specify only by `sys` This clause is required when modifying tenant-level parameters for a specified tenant. For a list of tenant-level parameters, see [Parameter overview](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/200.system-configuration-items-overview-list.md). |

### Reset the value of a parameter

```sql
ALTER SYSTEM RESET parameter_name [SCOPE = {MEMORY | SPFILE | BOTH}] [TENANT [=] tenant_name];
```

#### Parameters

| **Parameters** | **Description** |
| ----------------- | ----------------------- |
| parameter_name | Specifies the name of the parameter to be reset. |
| SCOPE | Specifies the scope of effect for this parameter reset. The main scopes are as follows: <ul><li>`MEMORY`: Resets only the parameter values in memory. The changes take effect immediately but will be lost after the OBServer node restarts. (Currently, no parameters support this method.)</li>   <li>`SPFILE`: Indicates that only the parameter values in the configuration table are reset. The change takes effect after the OBServer node restarts.</li>   <li>`BOTH`: Resets both the configuration table and memory values. The reset takes effect immediately, and the parameter values remain in effect after the OBServer node restarts.</li> </ul>  </br>The default value of `SCOPE` is `BOTH`. |
| TENANT | Specifies the tenant whose parameter values need to be reset. If not specified, the current tenant is used by default. Only available when the system tenant has the `sys` This clause is required when modifying tenant-level parameters for a specified tenant. For a list of tenant-level parameters, see [Parameter overview](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/200.system-configuration-items-overview-list.md). |

## Examples

### Modify parameters

* The system tenant modifies the value of the cluster-level parameter `enable_sql_audit`.

  ```sql
  obclient [oceanbase]> ALTER SYSTEM SET ENABLE_SQL_AUDIT = False SCOPE = BOTH;
  ```

* The system tenant modifies the value of the tenant-level parameter `connection_control_max_connection_delay` for the `tenant` tenant.

  ```sql
  obclient [oceanbase]> ALTER SYSTEM SET connection_control_max_connection_delay = 2147483646 TENANT = tenant;
  ```

* The system tenant modifies the value of the tenant-level parameter `major_freeze_duty_time` for all tenants in the cluster, including the sys tenant, user tenants, and Meta tenant.

  You must execute the following commands in sequence under the sys tenant:

  ```sql
  obclient [oceanbase]> ALTER SYSTEM SET major_freeze_duty_time='01:00' TENANT = sys;
  ```

  ```sql
  obclient [oceanbase]> ALTER SYSTEM SET major_freeze_duty_time='01:00' TENANT = all_user;
  ```

  ```sql
  obclient [oceanbase]> ALTER SYSTEM SET major_freeze_duty_time='01:00' TENANT = all_meta;
  ```

* A user tenant modifies the value of the tenant-level parameter `major_freeze_duty_time` for itself.

  ```sql
  obclient [oceanbase]> ALTER SYSTEM SET major_freeze_duty_time='01:00';
  ```

* The system tenant resets the value of the cluster-level parameter `enable_sql_audit` to its default value. The change takes effect immediately and is also updated to the `SPFILE`.

  ```sql
  obclient [oceanbase]> ALTER SYSTEM RESET ENABLE_SQL_AUDIT SCOPE = BOTH;
  ```

### Reset parameters

* The following example shows how to modify the `log_disk_utilization_threshold` parameter:

  ```sql
  obclient> ALTER SYSTEM RESET log_disk_utilization_threshold;
  ```

* Modify tenant-level parameters for all or specified tenants under the sys tenant. Example:

  ```sql
  obclient> ALTER SYSTEM RESET log_disk_utilization_threshold TENANT='ALL';
  obclient> ALTER SYSTEM RESET log_disk_utilization_threshold TENANT='mysql';
  ```
