# MIGRATE REPLICA

## Purpose

This statement is used to migrate a replica of the log stream, that is, to migrate the corresponding [replica migration](../../../../../600.manage/300.replica-management/200.replica-distribution/200.locality-common-operations/700.unit-migration.md) to a specified location.

## Limitations and considerations

* Replica migration can only be performed between zones.

* Before you perform a replica migration, ensure that the target server has available resources in the form of units and that no replica of this log stream exists on those units.

* If the current log stream already has seven follower replicas, you cannot execute the migration command.

* This statement can only migrate one log stream replica at a time. To migrate multiple replicas, you need to execute the statement multiple times.

* For the same log stream of a tenant, except that multiple replica migration tasks can be executed in parallel, only one disaster recovery task (including adding replicas, deleting replicas, converting replica types, and modifying the quorum size of the log stream) can be executed at a time.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>You can query the <code>CDB_OB_LS_REPLICA_TASKS</code> view in the sys tenant to check whether any disaster recovery tasks are running. You can also query the <code>DBA_OB_LS_REPLICA_TASKS</code> view in a user tenant to check whether any disaster recovery tasks are running.</p>
    </main>

## Privilege requirements

The user executing this statement must have the `ALTER SYSTEM` privilege. For more information about OceanBase AI database privileges, see [Permission classification](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

```sql
ALTER SYSTEM MIGRATE REPLICA
    LS [=] ls_id
    SOURCE [=] 'svr_ip:svr_port'
    DESTINATION [=] 'destination_addr'
    [DATA_SOURCE [=] 'data_source']
    [TENANT [=] 'tenant_name'];
```

## Parameters

| **Parameters** | **Description** |
| ------------------- | ------------------------------------ |
| ls_id | Specifies the log stream ID of the replica to be migrated. |
| svr_ip:svr_port | Specify the IP address and port number of the server where the replica to be migrated resides. For example, `xxx.xx.xxx.001:2882`. |
| destination_addr | Specify the IP address and port number of the target server for the replica to be migrated. The format is `svr_ip:svr_port`, for example, `xxx.xx.xxx.002:2882`. |
| data_source | Optional. Specifies the data source address of the replica. You can select any other replica in the log stream as the data source address. Choose according to your actual business needs. The format is `svr_ip:svr_port`, for example, `xxx.xx.xxx.001:2882`. If this value is not explicitly specified, the system automatically selects an available data source.<main id="notice" type='notice'><h4>Note</h4><p>If the specified data source is unavailable, the system reports an error.</p></main> |
| tenant_name | Optional. Specifies the tenant to operate on. If you do not explicitly specify the tenant, the default tenant is the current tenant. <main id="notice" type='notice'><h4>Notice</h4><p>The system tenant can specify other tenants, while a user tenant can only specify itself. This statement does not support using <code>ALL</code>, <code>ALL_USER</code>, or <code>ALL_META</code> to specify all tenants, user tenants, or all Meta tenants.</p></main> |

## Examples

Execute the following command in the sys tenant to migrate the log stream (1002) replica from `xxx.xxx.xxx.001:2882` to `xxx.xxx.xxx.002:2882` in tenant `mysql001`.

```sql
ALTER SYSTEM MIGRATE REPLICA
    LS = 1002
    SOURCE = 'xxx.xxx.xxx.001:2882'
    DESTINATION = 'xxx.xxx.xxx.002:2882'
    TENANT = 'mysql001';
```

For more examples of migrating log stream replicas, see Replica migration.
