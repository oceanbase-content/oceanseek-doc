# SERVICE_NAME

## Description

The `ALTER SYSTEM {CREATE | DELETE | START | STOP} SERVICE ...` statement is used to maintain a `SERVICE_NAME` by controlling its creation, deletion, start, and stop operations.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Manage service names and perform primary/standby switchover operations through OCP. For more information, see <a href="https://docs.oceanbase.com/ocp/switchover">Perform routine switchover between primary and standby tenants</a>.</p>
</main>

## Limitations and considerations

* The `META` and `SYS` tenants do not support the `SERVICE_NAME` feature.
* OceanBase Cloud Platform (OCP) ensures that within the clusters it manages, there can be only one primary tenant under a `SERVICE_NAME`. You must ensure this setting for `SERVICE_NAME` manually via the command line.
* The `FAILOVER` operation automatically drops all `SERVICE_NAME` under the tenant.
* A tenant can have at most one `SERVICE_NAME`.
* For a connection established by using `SERVICE_NAME`, you are not allowed to execute O&M commands related to the primary/standby role switchover of `SERVICE_NAME` and its tenants. Otherwise, the `OB_OP_NOT_ALLOW` error is returned.

## Privilege requirements

The user executing this statement must have the `ALTER SYSTEM` privilege. For more information about OceanBase AI database privileges, see [Permission classification](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

```sql
ALTER SYSTEM {CREATE | DELETE | START | STOP} SERVICE service_name [tenant = 'tenant_name'];
```

## Parameters

| **Parameters** | **Description** |
| --------------- | -------------------- |
| CREATE | After the service is created, it starts automatically. |
| DELETE | Delete a service. Before deleting a service, you must stop it first. |
| START | Start the service. After starting the service, you can use this `SERVICE_NAME` Establish a session or allow the request. |
| STOP | Stops the service. After the service is stopped, no sessions started through this `SERVICE_NAME` exist, and no new sessions can be established through this `SERVICE_NAME`. |
| service_name | Specify the service name. |
| tenant_name | Optional. Specifies the tenant to operate on. If not explicitly specified, the default tenant name is the current tenant.<main id="notice" type='notice'><h4>Notice</h4><p>The <code>SERVICE_NAME</code> feature is not supported in the sys tenant. When executing this statement under the sys tenant, you must specify the <code>TENANT = tenant_name</code> clause.</p></main> |

## Examples

Create a service named `service_mysql001` for the tenant `mysql001`.

```sql
ALTER SYSTEM CREATE SERVICE service_mysql001 TENANT = 'mysql001';
```
