# ALTER RESOURCE POOL

## Purpose

The `ALTER RESOURCE POOL` statement is used to modify the attributes of a resource pool, including `UNIT`, `UNIT_NUM`, and `ZONE_LIST`.

## Limitations and considerations

* When using the `ALTER RESOURCE POOL` statement to [modify resource pool attributes](../../../../600.manage/200.tenant-management/600.common-tenant-operations/900.modify-resource-pool-properties.md), each statement only supports modifying one attribute at a time. If you need to modify two or more attributes among `UNIT`, `UNIT_NUM`, and `ZONE_LIST` simultaneously, you must execute multiple statements.

* The current version of OceanSeek supports both homogeneous zone mode and heterogeneous zone mode for tenants. In homogeneous zone mode, the number of units in each zone of a tenant must be the same. In heterogeneous zone mode, the number of units in each zone of a tenant can be different, but a tenant is limited to at most two `unit_num` values. When increasing or decreasing `UNIT_NUM`:

  * In heterogeneous zone mode, you can use the `ALTER RESOURCE POOL` statement to increase or decrease `UNIT_NUM`, regardless of whether the resource pool is allocated to a tenant.

    <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>Typically, for existing tenants or tenants upgraded from earlier versions, the default deployment mode is Homogeneous Zone Mode. To enable Heterogeneous Zone Mode, you must set the value of the <code>zone_deploy_mode</code> parameter to <code>hetero</code>. After modification, it is not possible to change it back to <code>homo</code>.</p>
    </main>

  * In homogeneous zone mode, if a resource pool has already been allocated to a tenant, you cannot use the `ALTER RESOURCE POOL` statement. Instead, you must use the `ALTER RESOURCE TENANT` statement for modification. For more information about the `ALTER RESOURCE TENANT` statement, see [ALTER RESOURCE TENANT](300.alter-resource-tenant.md).

## Privilege requirements

Only the `root` user of the `sys` tenant (`root@sys`) can modify resource pools. Other tenants do not support this operation.

## Syntax

### ALTER RESOURCE POOL

```sql
ALTER RESOURCE POOL pool_name
      UNIT [=] unit_name
    | UNIT_NUM [=] unit_num [DELETE UNIT = (unit_id_list)]
    | ZONE_LIST [=] ('zone_name' [, 'zone_name' ...]);
```

## Parameters

| **Parameters** | **Description** |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| unit_name | Specifies the name of the unit config to be used for modifying the resource pool. |
| unit_num | Specifies the number of units in a single zone after modification. Increase `unit_num` must be less than or equal to the number of nodes in the target zone. <main id="notice" type=notice'><h4>Notice</h4><p>In heterogeneous zone mode, when you increase or decrease <code>unit_num</code>, the number of <code>unit_num</code> in each zone of a tenant can be different, but all zones of a tenant can have at most two different <code>unit_num</code>.</p><p>For example, if a tenant has three resource pools <code>pool1</code>, <code>pool2</code>, and <code>pool3</code> with <code>unit_num</code> values of 2, 4, and 4 respectively, changing <code>unit_num</code> for <code>pool3</code> to 1 will result in the system returning the error <code>More than two distinct unit_num in a single tenant not allowed</code>.</p></main> |
| DELETE UNIT | When you decrease `unit_num`, you can use `DELETE UNIT` to delete a specified unit. If `DELETE UNIT` is not specified, the system randomly deletes the specified number of units. <main id="notice" type=notice'><h4>Notice</h4><p>When using <code>DELETE UNIT</code> to delete a specified <code>unit_id</code>, if there are multiple zones, the following conditions must also be met:<ul><li>The number of units deleted in each zone in the <code>unit_id</code> list must be equal.</li>   <li>After deletion, the number of units remaining in each zone in the specified <code>unit_id</code> list must match the specified <code>unit_num</code>.</li></ul> </p></main> |
| ZONE_LIST | Specifies the list of zones for the modified resource pool. |

## Examples

* You cannot modify multiple attributes of the resource pool `pool1` at the same time. For example, the following statement attempts to modify the `UNIT`, `UNIT_NUM`, and `ZONE` attributes simultaneously, which will result in an error.

  ```sql
  obclient [oceanbase]> ALTER RESOURCE POOL pool1 UNIT='unit2', UNIT_NUM=1, ZONE_LIST=('zone1');
  ERROR 1235 (0A000): alter unit_num, resource_unit, zone_list in one cmd not supported
  ```

  Specifically, when reducing `UNIT_NUM`, you can delete specified units.

  ```sql
  obclient [oceanbase]> ALTER RESOURCE POOL pool1 UNIT_NUM=1 DELETE UNIT = (1002);
  ```

* Change the unit of resource pool `pool1` to `unit2`.

  ```sql
  obclient [oceanbase]> ALTER RESOURCE POOL pool1 UNIT='unit2';
  ```
