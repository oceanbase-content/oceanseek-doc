# CREATE RESOURCE UNIT

## Purpose

OceanSeek manages physical resources through resource units. The `sys` tenant can use the `CREATE RESOURCE UNIT` statement to create a resource unit and specify its resource specifications. A resource unit's specifications define common physical resources, including CPU, memory, log disk storage space, and IOPS.

The resource specification of a unit defines the total amount of resources that can be allocated to a single OBServer node within a single zone. A tenant can use the resources on a node to store data only if the tenant has a unit on that node.

The total amount of resources allocated to a tenant is calculated as follows: Unit specification × Number of units.

## Limitations and considerations

The unit's resource specification cannot exceed the total allocatable resources of a single node.

## Privilege requirements

Only the `root` user of the `sys` tenant (`root@sys`) can create units. Other tenants do not support creating units.

## Syntax

```sql
CREATE RESOURCE UNIT [IF NOT EXISTS] unit_name
MEMORY_SIZE [=] 'size_value',
MAX_CPU [=] cpu_num,
[MAX_IOPS [=] iops_num,]
[MIN_CPU [=] cpu_num,]
[MIN_IOPS [=] iops_num,]
[IOPS_WEIGHT [=]iopsweight,]
[MAX_NET_BANDWIDTH [=] bandwidth_num,]
[NET_BANDWIDTH_WEIGHT [=] bandwidth_weight_num,]
[DATA_DISK_SIZE [=] 'size_value',]
[LOG_DISK_SIZE [=] 'size_value'];
```

## Parameters

| Parameter | Description |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| IF NOT EXISTS | Optional. If the unit to be created already exists and no specific value is specified for this parameter, `IF NOT EXISTS`, an error will be returned. |
| unit_name | Specifies the name of the unit. |
| MEMORY_SIZE | Specifies the memory specification. Its minimum value is determined by the hidden parameter `__min_full_resource_pool_memory`, whose default value is 5 GB. To ensure system stability, we recommend that you set the minimum memory to 4 GB.  <main id="notice" type='notice'><h4>Notice</h4><p>OceanSeek no longer supports memory overprovisioning.</p></main> |
| MAX_CPU | Specifies the upper limit of CPU specifications. The minimum value is 1, which indicates 1 core. |
| MIN_CPU | Specifies the minimum CPU specification. The minimum value is 1, which indicates 1 core. This parameter is required.</br>If this parameter is not specified, its default value is equal to `MAX_CPU`.<main id="notice" type='notice'><h4>Notice</h4><p>The sum of <code>MIN_CPU</code> values for all tenants must not exceed the node's total CPU capacity <code>CPU_CAPACITY</code>.</p></main> |
| MAX_IOPS | Specify the upper limit of IOPS. The minimum value is 1024. The specified value must meet the following requirements: `MAX_IOPS >= MIN_IOPS`, which is optional. </br>If not specified, the system automatically calculates the value of `MAX_IOPS` based on the following rules:<ul><li> If the value of <code>MIN_IOPS</code> is specified, the value of <code>MAX_IOPS</code> is set to the same value as <code>MIN_IOPS</code>.</li> <li>If neither <code>MIN_IOPS</code> nor <code>MAX_IOPS</code> is specified, both <code>MAX_IOPS</code> and <code>MIN_IOPS</code> are set to <code>INT64_MAX</code>.</li></ul> |
| MIN_IOPS | Specifies the lower limit of IOPS. The minimum value is 1024, which is optional. </br>If not specified, the system automatically calculates the value of `MIN_IOPS` based on the following rules:<ul><li> If the value of <code>MAX_IOPS</code> is specified, the value of <code>MIN_IOPS</code> is set to <code>MAX_IOPS</code>.</li> <li>If the value of <code>MAX_IOPS</code> is not specified, both <code>MIN_IOPS</code> and <code>MAX_IOPS</code> are set to <code>INT64_MAX</code>.</li></ul> |
| IOPS_WEIGHT | Optional. Specifies the weight value for IOPS. </br>If not specified, the system automatically calculates the value of `IOPS_WEIGHT` based on the following rules:<ul><li>If both <code>MAX_IOPS</code> and <code>MIN_IOPS</code> are specified, or only one of them is specified, the value of <code>IOPS_WEIGHT</code> is <code>0</code>.</li> <li>If neither <code>MAX_IOPS</code> nor <code>MIN_IOPS</code> is specified, <code>IOPS_WEIGHT = MIN_CPU</code>.</li></ul> |
| MAX_NET_BANDWIDTH | Specifies the maximum network bandwidth allowed for each unit of the tenant. The minimum value is 1 MB. If not specified, the default value is `INT64_MAX`. |
| NET_BANDWIDTH_WEIGHT | Specifies the network bandwidth weight of a tenant unit, which is used to calculate the proportion of bandwidth allocated to each tenant by each OBServer node. The minimum value is 0. If not specified, the system automatically calculates the value of `NET_BANDWIDTH_WEIGHT` according to the following rules:<ul><li>If `MAX_NET_BANDWIDTH` is specified, `NET_BANDWIDTH_WEIGHT` is set to 0. </li> <li>If `MAX_NET_BANDWIDTH` is not specified, `NET_BANDWIDTH_WEIGHT = MIN_CPU`.</li></ul> |
| DATA_DISK_SIZE | Specifies the size of local disk space available for each unit of the tenant. When this parameter is specified:<ul><li>If it is set to `0`: Indicates that the local disk space available for each unit of the tenant is not limited. Each OBServer node can automatically adjust the size of the local cache disk allocated to a tenant's units.</li> <li>When set to a value other than `0`, the value must be greater than or equal to 2 GB. </li><li>Once specified, `0` Value and Not `0` Values cannot be switched with each other. That is, if this parameter is specified as `0` After that, it cannot be changed to a non-`0` the value; similarly, specify this specification as non-`0` After the value is set, it cannot be modified to `0`</li> <li>If not specified, the default value is twice the memory specification.</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>[Create a tenant](../../../../600.manage/200.tenant-management/600.common-tenant-operations/200.manage-create-tenant.md), migration, or scale-out, the system considers the <code>DATA_DISK_SIZE</code> specification of the unit. If the local disk free space on the OBServer is insufficient, tenant creation may fail or the unit cannot be migrated.</p></main> |
| LOG_DISK_SIZE | Specifies the size of the log disk space for the tenant. Optional.</br>If not specified, the default value is three times the memory specification, with a minimum value of 2 GB. |

## Examples

* Create a unit named `unit1`, specifying the following parameters: 4 CPU cores, `5G` of memory, `10G` of log disk capacity, an IOPS upper limit of `1280`, an IOPS lower limit of `1024`, and an IOPS weight of `1`. The unit also has a maximum network bandwidth of `5M` and a network bandwidth weight of `10`.

  ```shell
  obclient(root@sys)[(none)]> CREATE RESOURCE UNIT unit1 MAX_CPU 4, MEMORY_SIZE '5G', MAX_IOPS 1280, MIN_IOPS=1024, IOPS_WEIGHT=1, MAX_NET_BANDWIDTH '5M',NET_BANDWIDTH_WEIGHT 10, LOG_DISK_SIZE '10G';
  ```

  After the unit is successfully created, you can confirm the creation result through a view. The statement is as follows:

  ```shell
  obclient(root@sys)[oceanbase]> SELECT * FROM oceanbase.DBA_OB_UNIT_CONFIGS WHERE NAME='unit1';
  ```

  The query result is as follows:

  ```shell
  +----------------+-------+----------------------------+----------------------------+---------+---------+-------------+---------------+----------------+----------+----------+-------------+-------------------+----------------------+
  | UNIT_CONFIG_ID | NAME  | CREATE_TIME                | MODIFY_TIME                | MAX_CPU | MIN_CPU | MEMORY_SIZE | LOG_DISK_SIZE | DATA_DISK_SIZE | MAX_IOPS | MIN_IOPS | IOPS_WEIGHT | MAX_NET_BANDWIDTH | NET_BANDWIDTH_WEIGHT |
  +----------------+-------+----------------------------+----------------------------+---------+---------+-------------+---------------+----------------+----------+----------+-------------+-------------------+----------------------+
  |           1001 | unit1 | 2025-05-28 11:19:39.116490 | 2025-05-28 11:19:39.116490 |       4 |       4 |  5368709120 |   10737418240 |           NULL |     1280 |     1024 |           1 |           5242880 |                   10 |
  +----------------+-------+----------------------------+----------------------------+---------+---------+-------------+---------------+----------------+----------+----------+-------------+-------------------+----------------------+
  1 row in set
  ```

* Create a unit named `unit1`, specifying 4 CPU cores, `5G` of memory, and `100G` of local disk space per unit.

  ```shell
  obclient(root@sys)[(none)]> CREATE RESOURCE UNIT unit1 MAX_CPU 4, MEMORY_SIZE '5G', DATA_DISK_SIZE '100G';
  ```
