# ALTER TENANT

## Purpose

The `ALTER TENANT` statement is used to modify the attributes of a user tenant, including the locality, primary zone, resource pool list, and system variable values.

To rename a user tenant, you can use the `ALTER TENANT ... RENAME` statement.

To lock or unlock a user tenant, you can use the `ALTER TENANT ... LOCK / UNLOCK` statement. After executing the `ALTER TENANT ... LOCK` statement to lock a tenant, the system will prevent users from creating new connections to the locked tenant. Existing connections are not affected.

## Privilege requirements

Only the `root` user of the `sys` tenant (`root@sys`) can modify a tenant. Modifying tenants is not supported for other tenants.

## Syntax

### ALTER TENANT

```sql
ALTER TENANT tenant_name
    [SET] [tenant_option_list] [set_sys_var];

tenant_option_list:
    tenant_option [, tenant_option ...]

tenant_option:
      LOCALITY [=] 'locality_description'
    | PRIMARY_ZONE [=] zone
    | RESOURCE_POOL_LIST [=](pool_name [, pool_name...])
    | ENABLE_ARBITRATION_SERVICE [=] {True | False}
    | [DEFAULT] TABLEGROUP [=] {NULL | tablegroup_name}
    | ENABLE_EXTENDED_ROWID [=] {true | false}
    | COMMENT [=]'string'

set_sys_var:
    VARIABLES var_name {TO | =} var_value [,var_name {TO | =} var_value...]
```

### ALTER TENANT ... RENAME

```sql
ALTER TENANT tenant_name RENAME GLOBAL_NAME TO new_tenant_name;
```

### ALTER TENANT ... LOCK / UNLOCK

```sql
ALTER TENANT tenant_name LOCK | UNLOCK;
```

## Parameters

| **Parameters** | **Description** |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| tenant_name | Specifies the name of the tenant to be modified. |
| LOCALITY | Modify the locality of a tenant. Locality describes how replicas are distributed across zones. The current version supports the following replica types: Full-featured replica: The name is FULL, abbreviated as F. For more information about full-featured replicas, see Full-featured replicas.</br>Example: `LOCALITY = 'F@z1,F@z2,F@z3'`</br>When modifying this parameter, if you need to add zones, the tenant resource pool must have sufficient resources. `ZONE_LIST` contains this zone. |
| PRIMARY_ZONE | Modify the primary zone of a tenant. Valid values: <ul><li>`RANDOM`: Specifies that the tenant's primary zone is all zones where the tenant resides, indicating that all zones have the same priority.</li> <li>zone_name: Specifies a particular zone as the tenant's primary zone.</li></ul> </br>If no primary zone is specified when creating the tenant, the default value is `RANDOM`. |
| RESOURCE_POOL_LIST | Modify the tenant's resource pool list. </br>If there are multiple resource pools, ensure that the number of `UNIT_NUM` is the same for all resource pools.<main id="notice" type='notice'><h4>Note</h4><ul><li>The <code>ZONE_LIST</code> of multiple resource pools belonging to the same tenant must not intersect.</li> <li>When modifying the resource pool list, you can add or remove only one resource pool at a time.</li></ul></main> |
| ENABLE_ARBITRATION_SERVICE | No action is required at this time. |
| [DEFAULT] TABLEGROUP | Modifies the default table group information of a tenant. `NULL` indicates to cancel the default table group. |
| ENABLE_EXTENDED_ROWID | Specifies whether to enable Extended ROWID mode for all tables in the tenant. Once enabled, this parameter cannot be disabled. However, you can use the tenant-level parameter `default_enable_extended_rowid` to specify whether to enable Extended ROWID mode for newly created tables. For more information about this tenant-level parameter, see [default_enable_extended_rowid](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2000.default_enable_extended_rowid.md). |
| system_var_name | Modify the system variable value of a tenant. |
| RENAME GLOBAL_NAME TO | Modify the tenant name. |
| COMMENT | Modify the comment. |

## Examples

* Change the primary zone of tenant `tenant1` to `zone2`.

  ```shell
  obclient [oceanbase]> ALTER TENANT tenant1 primary_zone='zone2';
  ```

* Change the primary zone of tenant `tenant1` to `RANDOM`.

  ```shell
  obclient [oceanbase]> ALTER TENANT tenant1 primary_zone = RANDOM;
  ```

  Assuming the tenant has three zones: `zone1`, `zone2`, and `zone3`, this statement is equivalent to

  ```shell
  obclient [oceanbase]> ALTER TENANT tenant1 primary_zone = 'zon1,zone2,zone3';
  ```

* Modifying a resource pool is typically used in scenarios where the number of tenant replicas needs to be upgraded or downgraded. When modifying a resource pool, you can only add or remove one resource pool at a time. You cannot execute the following statement to directly replace the tenant's resource pool `pool1` with `pool2`, otherwise the following error will occur.

  ```shell
  obclient [oceanbase]> ALTER TENANT tenant1 resource_pool_list=('pool2');
  ```

  The error message is as follows:

  ```shell
  ERROR 1210 (HY000): Incorrect arguments to resource pool list
  ```

  If you want to adjust the resources available to a tenant, for example, to scale out the tenant, you can increase the specification of its resource units.

  ```shell
  obclient [oceanbase]> ALTER RESOURCE UNIT unit1 MAX_CPU 15, MEMORY_SIZE '20G', MAX_IOPS 1280, MIN_CPU=10, MIN_IOPS=1024;
  ```

* Modify the locality of tenant `tenant1` and increase the number of replicas. Here, `F` indicates that the replica type is a full-featured replica, and `B_4` is the name of the new zone.

  Assume the current tenant `tenant1` has a locality of `F@B_1,F@B_2,F@B_3`, a resource pool of `pool1`, and its `ZONE_LIST` scope is `'B_1','B_2','B_3'`.

  1. Create the resource unit `unit2`.

     ```shell
     obclient [oceanbase]> CREATE RESOURCE UNIT unit2, MAX_CPU=5, MIN_CPU=2.5, MEMORY_SIZE= '32G', MAX_IOPS=10000, MIN_IOPS=5000, LOG_DISK_SIZE=5301023539200;
     ```

  2. Create a resource pool named `pool2`.

     ```shell
     obclient [oceanbase]> CREATE RESOURCE POOL pool2 unit='unit2',unit_num=1,zone_list=('B_4');
     ```

  3. Add the resource pool `pool2` to the tenant.

     ```shell
     obclient [oceanbase]> ALTER TENANT tenant1 resource_pool_list=('pool1','pool2');
     ```

  4. Modify the tenant's locality.

     ```shell
     obclient [oceanbase]> ALTER TENANT tenant1 LOCALITY='F@B_1,F@B_2,F@B_3,F@B_4';
     ```
