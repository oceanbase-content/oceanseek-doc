# Core features of OBKV-HBase

## HBase model features

### Basic features

| **Feature** | **Description** |
| --- | --- |
| HBase compatibility | <ul><li>Compatible with most features of HBase 0.94 and 1.1.13 through API implementation.</li><li>Supports [HBase-compatible interfaces](700.obkv-hbase-reference/150.obkv-hbase-interface-compatibility.md), such as put, get, exists, delete, append, increment, and scan.</li></ul> |
| Row lock support | Supports HBase row locks. |
| [Data operation examples](200.obkv-hbase-develop/300.obkv-hbase-demo.md) | The put, delete, get, and scan APIs support multiple column families. |
| Subpartition | Supports subpartitions. |
| Table model | Supports both standard table models and time series table models. |
| Filter | <ul><li>Supports various filters, including CompareFilter, SingleColumnValueFilter, PageFilter, ColumnCountGetFilter, PrefixFilter, SkipFilter, WhileMatchFilter, ColumnPrefixFilter, ColumnPaginationFilter, FirstKeyOnlyFilter, KeyOnlyFilter, RandomRowFilter, and TimestampsFilter.</li><li>Supports multiple filters by using FilterList.</li></ul> |
| Ecosystem | <ul><li>Supports Flink integration with OBKV-HBase.</li></ul> |
| Development tools | <ul><li>HBase shell is not supported.</li><li>Supports accessing HBase table data by using a MySQL client.</li></ul> |

### Performance optimization features

| **Feature** | **Description** |
| --- | --- |
| [Delete expired data in OBKV-HBase](700.obkv-hbase-reference/500.obkv-hbase-ttl.md) | <ul><li>Table-level TTL (the TTL policy is set on the table, and all rows expire according to the table-level policy).</li><li>Supports real-time invisibility of expired data.</li></ul><main id="notice" type='notice'><h4>Notice</h4><p>The expired data deletion (TTL) feature is only available for OceanBase KV scenarios. It is disabled for SQL scenarios to prevent unexpected data loss.</p></main> |
| MaxVersion | <ul><li>Supports configuring the maximum number of versions to keep. Excess versions are deleted asynchronously in the background when combined with TTL.</li></ul> |
| [OBKV-HBase weak-consistency reads and near reads](700.obkv-hbase-reference/600.obkv-hbase-weak-read.md) | <ul><li>Weak-consistency read: The client reads data from non-leader replicas (such as followers). Reading data in this mode introduces a slight delay but improves read performance and system availability.</li><li>Near read: The client preferentially reads from the replica in the IDC nearest to its geographical location or network distance, reducing network latency and improving access speed and user experience.</li></ul> |
| [Automatic partition splitting in OBKV-HBase](700.obkv-hbase-reference/400.obkv-hbase-auto-partition.md) | <ul><li>Supports automatic partition splitting. When the table data volume reaches a certain threshold, partitions are automatically split to improve query performance and system availability.</li></ul> |

## Advanced features

| **Feature** | **Description** |
| --- | --- |
| Transactions | <ul><li>Single operations support row-level transactions.</li><li>Batch operations support single-node transactions.</li><li>Distributed transactions across nodes are not supported yet.</li></ul> |
| Disaster recovery | Leverages all disaster recovery capabilities of OceanSeek, such as multi-replica architecture, primary/standby databases, and deployments with three IDCs across two regions or five IDCs across three regions. |
| Multi-tenancy | Leverages the multi-tenancy capabilities of OceanSeek. |
| Scalability | Leverages the data partitioning and elastic scaling capabilities of OceanSeek. |
| Backup and restore | Leverages the backup and restore capabilities of OceanSeek. |
| Monitoring metrics | Provides monitoring metrics for both the server and the client, including QPS, RT, and ROWS-related metrics and histogram performance metrics. For more information, see [OBKV-HBase monitoring metrics](300.obkv-hbase-manage/200.obkv-hbase-monitor-items.md). |
| Data compression | Supports data compression. |
| Data encryption | Supports transparent data encryption (TDE). |

## Client compatibility of OBKV-HBase

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>OBKV-HBase supports only the Java client.</p>
</main>

The version roadmap of `obkv-hbase-client-java` is as follows:

* 1.x client versions are compatible with HBase 1.x business scenarios.
* 2.x client versions are compatible with HBase 2.x business scenarios.

Details are as follows:

| **obkv-hbase-client-java 1.x client version** | **Release notes** |
| --- | --- |
| 1.1.0 | Supports partition splitting and batch get operations. |

| **obkv-hbase-client-java 2.x client version** | **Release notes** |
| --- | --- |
| 2.1.0 | Supports partition splitting and batch get operations. |
