# HBase-compatible interfaces

The OBKV-HBase client implements the [HTableInterface](https://svn.apache.org/repos/asf/hbase/hbase.apache.org/trunk/0.94/apidocs/org/apache/hadoop/hbase/client/HTableInterface.html) interface of HBase. This topic describes the compatibility of OBKV-HBase with the open-source HBase interfaces.

## Differences in API usage

Due to architectural differences, some configuration code needs to be adjusted when migrating code from open-source HBase to OBKV-HBase.

### Description of differences

The data access code for open-source HBase and OBKV-HBase remains unchanged, ensuring compatibility in the data access part. The main differences lie in:

* Configuration: The architecture and configuration settings differ between open-source HBase and OBKV-HBase.
* OHTableClient: Data access requires a handle based on OBKV-HBase.

### Code example

Open-source HBase code:

```java
public class HBaseInsertDemo {
    public static void main(String[] args) throws Exception {
        // Configure HBase
        Configuration conf = HBaseConfiguration.create();
        conf.set("hbase.zookeeper.quorum", "your_zookeeper_quorum"); // Set the ZooKeeper address.
        conf.set("hbase.zookeeper.property.clientPort", "2181"); // Set the ZooKeeper port.
        // Obtain a Table handle
        TableName tableName = TableName.valueOf("your_table_name");
        HTable table = new HTable(tableName, conf);
        // Prepare data for insertion
        Put put = new Put(Bytes.toBytes("row_key"));
        put.addColumn(Bytes.toBytes("cf"), Bytes.toBytes("qualifier"), Bytes.toBytes("value")); // Column family, column qualifier, value.
        table.put(put);
        // Close resources
        table.close();
        System.out.println("Data inserted successfully!");
    }
}
```

OBKV-HBase code:

```java
public class OBHBaseInsertDemo {
    public static void main(String[] args) throws Exception {
        // Configure HBase
        Configuration conf = new Configuration();
        conf.set(HBASE_OCEANBASE_FULL_USER_NAME, "");
        conf.set(HBASE_OCEANBASE_PASSWORD, "");
        conf.set(HBASE_OCEANBASE_PARAM_URL, "");
        conf.set(HBASE_OCEANBASE_SYS_USER_NAME, "");
        conf.set(HBASE_OCEANBASE_SYS_PASSWORD, "");
        // Obtain a Table handle
        TableName tableName = TableName.valueOf("your_table_name");
        OHTableClient table = new OHTableClient(tableName, conf); // Create an HTable object.

        // Prepare data for insertion.
        Put put = new Put(Bytes.toBytes("row_key"));
        put.addColumn(Bytes.toBytes("cf"), Bytes.toBytes("qualifier"), Bytes.toBytes("value")); // Column family, column qualifier, value.
        table.put(put);
        // Close resources.
        table.close();
        System.out.println("Data inserted successfully!");
    }
}
```

## API details and examples

### API description and examples for the Scan class

Some APIs of the Scan class are supported, including `setBatch`, `setCaching`, `setMaxResultSize`, `setAllowPartialResults`, and `setCacheBlocks`.

#### setBatch

Sets the maximum number of cells returned by each `next()` call. This is used to implement pagination queries on the client side.

```java
public Scan setBatch(int batch);
```

#### setCaching

Limits the number of rows returned by the server in a single RPC. By default, there is no limit. You can set a large caching value to retrieve more data per RPC and speed up queries, or set a small caching value to reduce client-side memory consumption and avoid Out-of-Memory (OOM).

```java
public Scan setCaching(int caching);
```

#### setMaxResultSize

Limits the maximum number of bytes of data that can be returned by the server in a single RPC. By default, there is no limit.

```java
public Scan setMaxResultSize(long maxResultSize);
```

#### setAllowPartialResults

Determines whether partial rows can be returned to the user to avoid client-side OOM caused by excessively long single-row data. The default value is `false`. In this case, even if you set `setMaxResultSize` to limit the amount of returned data, the server returns at least one complete row of data to the client each time.

```java
public Scan setAllowPartialResults(final boolean allowPartialResults);
```

#### setCacheBlocks

Determines whether the query result set is cached in OceanBase AI Database's row cache or BlockCache. The default value is `true`. For example, you can set it to `false` when you perform a full table scan to avoid contaminating the cache.

```java
public Scan setCacheBlocks(boolean cacheBlocks);
```

#### renew

Sets the expiration time of the query result set. The default value is `0`, which indicates that no expiration time is set.

The `ResultScanner.renewLease()` method extends the validity period (lease) of a ResultScanner. In HBase, a ResultScanner has a default validity period of 60,000 ms. If no data is read within this period, the scanner closes automatically. By calling `renewLease()`, you can refresh the status of the ResultScanner so that the validity period is reset and the scanner remains open longer.

In OBKV-HBase, the validity period of a ResultScanner is adjusted by using [kv_hbase_client_scanner_timeout_period](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/4170.kv_hbase_client_scanner_timeout_period.md).

Here is an example:

```java
ResultScanner scanner = hTable.getScanner(scan);

Thread.sleep(5 * 1000);
scanner.next();
Thread.sleep(20 * 1000);
scanner.renewLease();

Thread.sleep(41 * 1000);
scanner.next();
```

#### withStartRow/withStopRow

The `Scan.withStartRow` and `Scan.withStopRow` methods specify the start row and the stop row of the scan, and whether the row keys are inclusive. These methods help you define the scan range so that only data in the specified row key range is scanned.

Example:

```java
// Create a Scan object
Scan scan = new Scan();

// Set the start row and the stop row
byte[] startRow = Bytes.toBytes("row1");
```

#### Set connection timeout

The `rpcConnectTimeout` parameter in tableClient and the `obTableConnectTimeout` parameter in ObTable control the connection timeout when the Table client initializes and establishes a connection with the OBServer node of the current tenant. The minimum connection timeout for tableClient is 1 second.

Design of the OBKV-HBase client:

Both parameters for the Table client in OBKV-HBase can be set by using the configuration interface in ObTableClient. Therefore, they must be set before the TableClient object in the HBase client is initialized.

```java
/*
 * Set rpc connect timeout.
 */
public void setRpcConnectTimeout(int rpcConnectTimeout) {
    this.properties.put(RPC_CONNECT_TIMEOUT.getKey(), String.valueOf(rpcConnectTimeout));
    this.rpcConnectTimeout = rpcConnectTimeout;
}
```

For compatibility with the earlier `ipc.socket.timeout` parameter, you can still set the connection timeout by using this parameter. However, the new `hbase.ipc.client.socket.timeout.connect` parameter takes precedence over the old one. The Table client uses the setting of the old parameter only if you set only that parameter and do not set the new one. In all other cases, it uses the default or specified value of the new parameter.

```java
// SOCKET_TIMEOUT_CONNECT = "hbase.ipc.client.socket.timeout.connect", default value: 10s
// SOCKET_TIMEOUT = "ipc.socket.timeout", default value: 20s
int rpcConnectTimeout = -1;
// If a new parameter is set, use it directly.
if (conf.get(SOCKET_TIMEOUT_CONNECT) != null) {
    rpcConnectTimeout = conf
            .getInt(SOCKET_TIMEOUT_CONNECT, DEFAULT_SOCKET_TIMEOUT_CONNECT);
} else {
    // If no new parameter is set but an old one is, the old parameter is used.
    if (conf.get(SOCKET_TIMEOUT) != null) {
        rpcConnectTimeout = conf.getInt(SOCKET_TIMEOUT, DEFAULT_SOCKET_TIMEOUT);
    } else { // Neither parameter is set, use the default value of the new parameter.
        rpcConnectTimeout = conf
                .getInt(SOCKET_TIMEOUT_CONNECT, DEFAULT_SOCKET_TIMEOUT_CONNECT);
    }
}
this.rpcConnectTimeout = rpcConnectTimeout;
```

Pass `rpcConnectTimeout` to the function that creates ObTableClient so that the timeout is set before initialization.

```java
public static ObTableClient getOrCreateObTableClient(ObTableClientKey obTableClientKey,
                                                         int rpcConnectTimeout) throws IOException {
    // other code...
                obTableClient.setFullUserName(obTableClientKey.getFullUserName());
                obTableClient.setPassword(obTableClientKey.getPassword());
                obTableClient.setRpcConnectTimeout(rpcConnectTimeout);
                obTableClient.init();
                OB_TABLE_CLIENT_INSTANCE.put(obTableClientKey, obTableClient);
            }
        } catch (Exception e) {
            throw new IOException(e);
        } finally {
            lock.unlock();
        }
    }
    return OB_TABLE_CLIENT_INSTANCE.get(obTableClientKey);
}
```

The OBKV-HBase client caches created ObTableClient objects and does not reinitialize them. Therefore, if you later want to set the connection timeout for an ObTableClient, you cannot use the `Configuration.set` method. Instead, you must directly use the `setRpcConnectTimeout` interface of the corresponding ObTableClient object.

### BufferedMutator API description and examples

Similar to the BufferedMutator of HBase, it is used to accumulate mutation operations for batch execution. You can choose to manually commit batch operations or have the OBKV BufferedMutator automatically commit them when the accumulation threshold is reached. `ohBufferedMutatorImpl` is the BufferedMutator implementation class in OBKV-HBase.

Currently, the BufferedMutator of OBKV-HBase supports only delete and add operations, and a created OBKV-HBase BufferedMutator object can perform batch operations on only one type of mutation. Operations within a BufferedMutator cannot guarantee concurrent order, execution order, or atomicity when an operation fails.

#### 1.x compatibility

The BufferedMutator of OBKV-HBase is compatible with HBase BufferedMutator 1.x. OHBufferedMutatorImpl 1.x depends on the batch interface in OHTable 1.x.

The features are described as follows:

* The same BufferedMutator object can perform mixed put and delete operations.
* Both put and delete operations in a BufferedMutator support multiple column families.
* When the number of mutation operations in a BufferedMutator reaches the threshold, it executes batch operations. Automatic batch processing has an upper limit, which is consistent with native HBase and equals twice the batch processing threshold.
* For failed mutation operations, the system recycles them.

#### 2.x compatibility

The BufferedMutator of OBKV-HBase is compatible with HBase BufferedMutator 2.x. OHBufferedMutatorImpl 2.x depends on the batch interface in OHTable 2.x.

The features are described as follows:

* The same BufferedMutator object can perform mixed put and delete operations.
* Both put and delete operations in a BufferedMutator support multiple column families.
* A BufferedMutator has an internal timer that periodically executes batch processing operations. Each batch processing operation commits all accumulated operations.
* For failed mutation operations, the system recycles them.

New interfaces in 2.x:

* Added the `setWriteBufferPeriodicFlush` interface to configure the auto-committer. `timeoutMs` controls the interval between two executions, and `timerTickMs` controls the interval of the committer trigger. Example:

    ```java
    public synchronized void setWriteBufferPeriodicFlush(long timeoutMs, long timerTickMs);
    ```

* Added the `disableWriteBufferPeriodicFlush` interface to disable the auto-committer. Example:

    ```java
    public void disableWriteBufferPeriodicFlush();
    ```

#### How to obtain a BufferedMutator

There are two ways to obtain a BufferedMutator:

1. Pass in `TableName` to specify the table name and use default parameters for the others.

```java
public BufferedMutator getBufferedMutator(TableName tableName) throws IOException {
    return getBufferedMutator(new BufferedMutatorParams(tableName));
}
```

2. Pass in `BufferedMutatorParams` to use custom parameters.

```java
public BufferedMutator getBufferedMutator(BufferedMutatorParams params) throws IOException {
        if (params.getTableName() == null) {
            throw new IllegalArgumentException("TableName cannot be null.");
        }
        if (params.getPool() == null) {
            params.pool(HTable.getDefaultExecutor(getConfiguration()));
        }
        if (params.getWriteBufferSize() == BUFFERED_PARAM_UNSET) {
            params.writeBufferSize(connectionConfig.getWriteBufferSize());
        }
        if (params.getMaxKeyValueSize() == BUFFERED_PARAM_UNSET) {
            params.maxKeyValueSize(connectionConfig.getMaxKeyValueSize());
        }
        return new OHBufferedMutatorImpl(this, params);
    }
```

Add a mutation operation:

1. Single mutation operation

```java

    mutate(Collections.singletonList(mutation));
}
```

2. Multiple mutation operations interface

```java

    // ...
}
```

After you call `close`, you can also manually flush to commit existing operations, but you cannot add new mutation operations.

```java

}
```

### CheckAndMutateBuilder interface description and example

CheckAndMutateBuilder is a new structure in HBase 2.x HTable for performing CheckAndxxx operations. You can set parameters such as the row, column family, column qualifier, value, time range, and comparison operator (CompareOp) to perform put, delete, and mutate operations. CheckAndMutateBuilder compares your settings with the data in the database based on parameters such as CompareOp and family. If a match is found, the corresponding operation is executed.

The interface is described as follows:

| Method | Purpose |
| --- | --- |
| `CheckAndMutateBuilder qualifier(byte[] qualifier)` | Sets the qualifier. |
| `CheckAndMutateBuilder timeRange(TimeRange timeRange)` | Sets the TimeRange. |
| `CheckAndMutateBuilder ifNotExists()` | Checks whether the qualifier does not exist. |
| `CheckAndMutateBuilder ifEquals(byte[] value)` | Checks whether a value exists. |
| `CheckAndMutateBuilder ifMatches(CompareOperator compareOp, byte[] value)` | Sets the comparator and value. |
| `boolean thenPut(Put put)` | Performs a put operation. |
| `boolean thenDelete(Delete delete)` | Performs a delete operation. |
| `boolean thenMutate(RowMutations mutation)` | Performs mixed put and delete operations. |

An example is as follows:

Perform a put operation on data whose key is `putKey`, family is `family_group`, qualifier is `column1`, and value is `value1`:

```java
OHTable hTable;
Put put = new Put(toBytes("putKey"));
put.addColumn(toBytes("family_group"), toBytes("column1"), toBytes("value2"));
boolean ret = hTable.checkAndMutate(toBytes("putKey"), toBytes("family_group"))
                    .qualifier(toBytes("column1"))
                    .ifEqual("value1")
                    .thenPut(put);
```

### batch interface description and example

The `batch(List<Row> actions, Object[] results)` method is used to batch execute multiple operations (such as put, get, and delete) and store the results in a specified array. This method allows you to execute multiple operations at once, improving efficiency.

Currently, only put and delete operations are supported. Mixed put and delete operations, as well as multi-column family operations, are also supported.

#### Interface description

```java
// This API is available in both 1.x and 2.x.
public void batch(final List<? extends Row> actions, final Object[] results)
// This API is removed in 2.x.
public void batch(final List<? extends Row> actions)   
```

#### Usage example

```java
List<Row> batchList = new LinkedList<>();
for (int i = 0; i < rows; ++i) {
    Put put = new Put(toBytes("Key" + i));
    Delete delete = new Delete(toBytes("Key" + i));
    batchList.add(delete);
    put.addColumn(family1, family1_column1, family1_value);
    put.addColumn(family1, family1_column2, family1_value);
    put.addColumn(family1, family1_column3, family1_value);
    put.addColumn(family2, family2_column1, family2_value);
    put.addColumn(family2, family2_column2, family2_value);
    put.addColumn(family3, family3_column1, family3_value);
    batchList.add(put);
}

// f1c1 f1c2 f1c3 f2c1 f2c2 f3c1
Delete delete = new Delete(toBytes("Key1"));
delete.addColumns(family1, family1_column1);
delete.addColumns(family2, family2_column1);
batchList.add(delete);
Object[] results = new Object[batchList.size()];
multiCfHTable.batch(batchList, results);
```

### Admin API details and examples

The Admin API of OBKV-HBase is compatible with some APIs of the HBase Admin module.

#### Prerequisites

To use the Admin API of OBKV-HBase, you must enable the `_enable_kv_hbase_admin_ddl` tenant-level hidden parameter. The default value of this parameter is `false`, which disables this feature. The enabling command is as follows:

```sql
ALTER SYSTEM SET _enable_kv_hbase_admin_ddl = true;
```

#### createTable

`createTable` creates an HBase table.

**In the underlying implementation of OBKV-HBase, a table group with the specified name is created. Then, the column families specified by the `TableDescriptor` parameter are created under this table group, along with the corresponding TTL and MaxVersion parameters for each column family. Each column family also corresponds to an entity table. The entity table name is in the `table name$column family name` format. Creating a table group and an entity table are two necessary steps. The system ensures that both steps succeed or fail simultaneously.**

The interface definition is as follows:

```java
void createTable(TableDescriptor desc) throws IOException
```

The following example creates a `test` table with two column families (`cf1` and `cf2`). The MaxVersion of `cf1` is `2`, and the data retention time is `86400` seconds (1 day). The MaxVersion of `cf2` is `1`, and the data retention time is `86400` seconds (1 day). The details are as follows:

```java
Connection connection = ConnectionFactory.createConnection(conf);
Admin admin = connection.getAdmin();

// 1. Construct the HTable description and column family description
HColumnDescriptor hcd1 = new HColumnDescriptor(Bytes.toBytes("cf1"));
hcd1.setMaxVersions(2);
hcd1.setTimeToLive(86400);

HColumnDescriptor hcd2 = new HColumnDescriptor(Bytes.toBytes("cf2"));
hcd2.setMaxVersions(1);
hcd2.setTimeToLive(86400);

// 2. Perform the table creation operation
HTableDescriptor htd = new HTableDescriptor(TableName.valueOf("test"));
htd.addFamily(hcd1);
htd.addFamily(hcd2);
admin.createTable(htd);
```

Consider the following points:

* Currently, only the `void createTable(TableDescriptor desc)` interface is supported.
* Currently, only setting TTL and MaxVersion are supported for a column family.
* Cell-level TTL is not supported.
