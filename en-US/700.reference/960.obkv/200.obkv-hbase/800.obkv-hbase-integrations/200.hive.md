# Access OBKV-HBase by using Hive

Apache Hive is data warehouse software built on Apache Hadoop. It uses SQL to enable users to read, write, and manage large-scale datasets. Its main features include distributed storage, fault tolerance, and large-scale data analysis, which simplify the query and analysis of data stored in distributed systems.

This topic describes how to access OBKV-HBase directly by using Hive without modifying code.

## Prerequisites

Before you use Hive to access OBKV-HBase, make sure that the following conditions are met:

* The OBKV-HBase Java client is version 2.0.0-alpha4 or later, which supports native Hive capabilities.
* Ensure that the Hive version is 3.0.0 to 3.1.3.

## Create a table

When using Hive to access an OBKV-HBase wide table, you can create the table in one of the following ways:

* Use the [HBase-compatible interfaces](../700.obkv-hbase-reference/150.obkv-hbase-interface-compatibility.md) to create the table.
* Create the table by using SQL. If you create the table by using SQL, follow the OBKV-HBase table creation rules. For more information, see [Data operation examples](../200.obkv-hbase-develop/300.obkv-hbase-demo.md).

## Set OBKV-HBase client connection parameters

The method for setting client connection parameters differs between public cloud and on-premises deployments of OBKV-HBase. For an on-premises OceanSeek cluster, configure the parameters as described in **Direct connection mode configuration**. For a public cloud OBKV service, configure them as described in **Cloud mode configuration**.

Regardless of the deployment mode, you can set all parameters in either of the following ways:

* In the `hive-site.xml` configuration file of the Hive client.
* In your code, by using the `set` method of Hive `Configuration` before initializing the `Connection` object.

### Direct connection mode configuration

Direct connection mode applies to on-premises OceanSeek clusters. It connects directly to the OceanSeek cluster by using `Configurl`, which is used to obtain the real address of the underlying OceanSeek servers. The following describes how to configure connection parameters in Hive for direct connection mode:

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>The <code>paramURL</code> contains the XML special character <code>&amp;</code>, which must be converted to <code>&amp;amp;</code>; otherwise, parsing will fail.</p>
</main>

* Method 1: Configure the following parameters in the Hive configuration file `hive-site.xml`:

    ```xml
    <!--
    Assume the current cluster is as follows:
    * ClusterName: obkvcluster
    TenantName: obkv
    DatabaseName: test
    UserName: root
    User password:
    SYS_USER_NAME: sysroot
    SYS user password:
    -->

    <configuration>
    <!-- Replace the HBase implementation class with that of OceanSeek -->
    <property>
        <name>hbase.client.connection.impl</name>
        <value>com.alipay.oceanbase.hbase.util.OHConnectionImpl</value>
    </property>
    
    <!-- OceanSeek connection configuration -->
    <property>
        <!-- The URL for obtaining the RSlist from the OBConfig server. For details, see Obtaining the config URL. -->
        <name>hbase.oceanbase.paramURL</name>
        <value>PARAM_URL</value>
    </property>
    <property>
        <!-- Format: userName@tenantName#clusterName -->
        <name>hbase.oceanbase.fullUserName</name>
        <value>root@obkv#obkvcluster</value>
    </property>
    <property>
        <!-- The password for userName to access OceanSeek -->
        <name>hbase.oceanbase.password</name>
        <value></value>
    </property>
    <property>
        <!-- The username under the sys tenant. Only users in the sys tenant have the permission to access the routing table. -->
        <name>hbase.oceanbase.sysUserName</name>
        <value>sysroot</value>
    </property>
    <property>
        <!-- The password for the user under the sys tenant. -->
        <name>hbase.oceanbase.sysPassword</name>
        <value></value>
    </property>
    </configuration>
    ```

* Method 2: Configure parameters by using `HiveConf` in your code.

    ```java
    /*
    * Assume the current cluster is as follows:
    * ClusterName: obkvcluster
    * TenantName: obkv
    * DatabaseName: test
    * UserName: root
    * User password:
    * SYS_USER_NAME: sysroot
    * SYS user password:
    */
    HiveConf conf = new HiveConf();
    conf.set("hbase.client.connection.impl", "com.alipay.oceanbase.hbase.util.OHConnectionImpl");
    conf.set("hbase.oceanbase.fullUserName", "root@obkv#obkvcluster");
    conf.set("hbase.oceanbase.password", "");
    // Obtain the RSlist URL from the OBConfig server. For details, see Obtain the Config URL.
    conf.set("hbase.oceanbase.paramURL", "");
    conf.set("hbase.oceanbase.sysUserName", "sysroot");
    conf.set("hbase.oceanbase.sysPassword", "");
    ```

Obtain the Config URL:

You can obtain the Config URL by using one of the following methods:

* Obtain the Config URL from OCP

  If you use OCP, you can obtain the Config URL from OCP as follows:

  a. Log on to the OceanSeek console.
  b. In the left navigation pane, choose **Clusters**, scroll down to **Cluster List**, and click the name of the cluster that you want to access.
  c. On the cluster details page, find the **ConfigURL** parameter. You need to specify this parameter during client initialization.
      ![](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/OBKV/hive.png)

* Deploy a Config Server by using OBD and obtain `ObRootServiceInfoUrl`

  If you do not use OCP, you must [deploy a Config Server by using OBD](https://docs.oceanbase.com/obd/deploy-obconfigserver) and obtain `ObRootServiceInfoUrl`.

### Cloud mode configuration

Cloud mode applies to OceanSeek clusters deployed on public clouds. It connects to the OceanSeek cluster through ODP. The following describes how to configure connection parameters for Hive in cloud mode:

* Method 1: Configure the following parameters in the Hive configuration file `hive-site.xml`:

    ```xml
    <!--
    Assume the current cluster is as follows:
    DatabaseName: test
    UserName: root
    -->
    <configuration>
    <!-- Replace the HBase implementation class with that of OceanSeek -->
    <property>
        <name>hbase.client.connection.impl</name>
        <value>com.alipay.oceanbase.hbase.util.OHConnectionImpl</value>
    </property>

    <!-- Configure the OceanSeek connection -->
    <property>
        <name>hbase.oceanbase.fullUserName</name>
        <value>root</value>
    </property>
    <property>
        <name>hbase.oceanbase.password</name>
        <value></value>
    </property>
    <property>
        <!-- For details, see Obtain the ODP address. -->
        <name>hbase.oceanbase.odpAddr</name>
        <value></value>
    </property>
    <property>
        <name>hbase.oceanbase.odpPort</name>
        <value>3307</value>
    </property>
    <property>
        <name>hbase.oceanbase.odpMode</name>
        <value>true</value>
    </property>
    <property>
        <name>hbase.oceanbase.database</name>
        <value>test</value>
    </property>
    </configuration>
    ```

* Method 2: Configure parameters by using `HiveConf` in your code:

    ```java
    /*
    * Assume the current cluster is as follows:
    * DatabaseName: test
    * UserName: root
    */
    HiveConf conf = new HiveConf();
    conf.set("hbase.client.connection.impl", "com.alipay.oceanbase.hbase.util.OHConnectionImpl");
    conf.set(HBASE_OCEANBASE_FULL_USER_NAME, "root");
    // User password.
    conf.set(HBASE_OCEANBASE_PASSWORD, "");
    // For details, see Obtain the ODP address.
    conf.set(HBASE_OCEANBASE_ODP_ADDR, "");

    // The port for OBKV is 3307 (fixed).
    conf.setInt(HBASE_OCEANBASE_ODP_PORT, 3307);

    // Use ODP mode on the cloud (fixed).
    conf.setBoolean(HBASE_OCEANBASE_ODP_MODE, true);

    // The name of the database.
    conf.set(HBASE_OCEANBASE_DATABASE, "test");
    ```

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p><code>paramURL</code> contains the XML special character <code>&amp;</code>, which must be converted to <code>&amp;amp;</code>; otherwise, parsing will fail.</p>
</main>

Obtain the ODP address:

You can obtain the ODP address as follows: Go to the OB Cloud console, open the tenant workspace, and view the deployment diagram.
![](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/OBKV/hive-2.png)

## Usage examples

### Add dependencies

Add the following OBKV-HBase dependency to the `pom.xml` file of your project:

```xml
<dependency>
  <groupId>com.oceanbase</groupId>
  <artifactId>obkv-hbase-client</artifactId>
  <version>2.2.1</version>
</dependency>
```

Add the Hive dependencies. When you add `Hive-HbaseHandler`, you must exclude the `hbase-common` and `hadoop-common` dependencies that come with Hive to avoid conflicts with the OBKV-HBase dependencies:

```xml
<!-- Hive JDBC Driver -->
<dependency>
    <groupId>org.apache.hive</groupId>
    <artifactId>hive-jdbc</artifactId>
    <version>${hive.version}</version>
    <exclusions>
        <exclusion>
            <groupId>org.apache.hadoop</groupId>
            <artifactId>hadoop-common</artifactId>
        </exclusion>
        <exclusion>
            <groupId>org.apache.hbase</groupId>
            <artifactId>hbase-common</artifactId>
        </exclusion>
    </exclusions>
</dependency>

<!-- Hive HBase Handler -->
<dependency>
    <groupId>org.apache.hive</groupId>
    <artifactId>hive-hbase-handler</artifactId>
    <version>${hive.version}</version>
    <exclusions>
        <exclusion>
            <groupId>org.apache.hbase</groupId>
            <artifactId>hbase-common</artifactId>
        </exclusion>
    </exclusions>
</dependency>
```

### Hive read/write examples

The following examples show how Hive reads data from and writes data to OBKV-HBase by creating and querying external tables and by inserting data.

#### Hive create external table

The syntax for creating an external table is as follows:

```sql
CREATE EXTERNAL TABLE IF NOT EXISTS {HiveTableName}(key string, value string)
STORED BY 'org.apache.hadoop.hive.hbase.HBaseStorageHandler'
WITH SERDEPROPERTIES ("hbase.columns.mapping" = ":key,{HbaseFamilyName}:{HbaseQualifierName}")
TBLPROPERTIES ("hbase.table.name" = "{HbaseTableName}", "hbase.mapred.output.outputtable" = "{HbaseTableName}");
```

The parameters are described as follows:

* `HiveTableName` specifies the name of the external table in Hive.
* `HbaseFamilyName` specifies the column family name in HBase.
* `HbaseQualifierName` specifies the qualifier name in HBase.
* `hbase.table.name` specifies the name of the corresponding HBase table.
* `hbase.mapred.output.outputtable` specifies the name of the target HBase table for writing.

#### Read/write examples

Create a Hive external table for the OBKV-HBase table:

```sql
hive> CREATE EXTERNAL TABLE IF NOT EXISTS user_behavior_analysis(
    >   user_id string,           -- Maps to the K field in OBKV.
    >   user_name string,         -- Maps to the V value where Q='user_name'.
    >   user_age string,          -- Maps to the V value where Q='user_age'.
    >   user_city string,         -- Maps to the V value where Q='user_city'.
    >   total_orders string,      -- Maps to the V value where Q='total_orders'.
    >   total_amount string,      -- Maps to the V value where Q='total_amount'.
    >   last_login string         -- Maps to the V value where Q='last_login'.
    > )
    > STORED BY 'org.apache.hadoop.hive.hbase.HBaseStorageHandler'
    > WITH SERDEPROPERTIES (
    >   "hbase.columns.mapping" = ":key,user_behavior:user_name,
    >                               user_behavior:user_age,
    >                               user_behavior:user_city,
    >                               user_behavior:total_orders,
    >                               user_behavior:total_amount,
    >                               user_behavior:last_login"
    > )
    > TBLPROPERTIES (
    >   "hbase.table.name" = "ecommerce_data",
    >   "hbase.mapred.output.outputtable" = "ecommerce_data"
    > );
```
