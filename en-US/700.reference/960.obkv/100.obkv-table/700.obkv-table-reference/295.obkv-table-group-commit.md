# Group commit in OBKV-Table

Group commit is a performance optimization feature provided by OBKV-Table for single-operation requests. When the database server aggregates single-operation requests from clients, it processes these requests in batches for combined computation, write, or read operations, thereby reducing the overhead of multiple transaction and storage calls.

## Supported operations

Currently, group commit supports the following single operations in Table mode:

* `get`
* `put`
* `insert`
* `delete`
* `replace`
* `update`
* `insert_or_update`
* `increment`
* `append`

For more information about the single operations supported in Table mode, see [OBKV-Table operations](220.obkv-table-operations-supported.md).

## Usage instructions

To use group commit, you only need to enable the corresponding parameter on the server side. After group commit is enabled, the API behavior and usage remain unchanged, and only performance is expected to improve.

Group commit provides the following two parameters, `kv_group_commit_batch_size` and `kv_group_commit_rw_mode`, to control whether it is enabled. They are described as follows:

* Parameter `kv_group_commit_batch_size`

    This parameter specifies the batch size of group commit. When it is set to 1, group commit is disabled, which is the default value. A value greater than 1 enables group commit. When you enable group commit, you must set a batch size, which affects the performance of single operations. For more information about the `kv_group_commit_batch_size` parameter, see [kv_group_commit_batch_size](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/4150.kv_group_commit_batch_size.md).

    The configuration method is as follows:

    ```sql
    -- Default value, which disables group commit.
    ALTER SYSTEM SET kv_group_commit_batch_size = 1 TENANT = <tenant_name>;
    -- Set the group commit batch size to 10.
    ALTER SYSTEM SET kv_group_commit_batch_size = 10 TENANT = <tenant_name>;
    ```

* Parameter `kv_group_commit_rw_mode`

    In some scenarios, you may want to enable group commit only for certain types of operations. For example, in scenarios with uneven read and write traffic, such as read-heavy workloads, batching read operations can take a long time and increase the response latency of read requests. In such cases, you can enable group commit only for write operations. `kv_group_commit_rw_mode` takes effect only when group commit is enabled. Its default value is `ALL`, which means that all operations support group commit. `READ` means that only read operations support group commit, and `WRITE` means that only write operations support group commit. For more information about the `kv_group_commit_rw_mode` parameter, see [kv_group_commit_rw_mode](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/4160.kv_group_commit_rw_mode.md).

    The configuration method is as follows:

    ```sql
    -- Default value, which enables group commit for all operation types.
    ALTER SYSTEM SET kv_group_commit_rw_mode = 'ALL' TENANT = <tenant_name>;
    -- Enable group commit only for read operations.
    ALTER SYSTEM SET kv_group_commit_rw_mode = 'READ' TENANT = <tenant_name>;
    ```

    The operations supported by each value of `kv_group_commit_rw_mode` are described as follows:

* `ALL`: All single operations in Table mode.
* `WRITE`: All operations except `GET`.
* `READ`: `GET`.

## Monitoring

Group commit provides the monitoring view `(G)V$OB_KV_GROUP_COMMIT_STATUS`. After group commit is enabled, you can query the group commit views to observe the status of requests processed by group commit. In group commit, different types of operations are divided into different groups. Each group has a request queue to hold KV operation requests. Worker threads take out requests in batches of `batch_size` from the request queue to form a batch for batch execution and then return a response.

* In the sys tenant, `GV$OB_KV_GROUP_COMMIT_STATUS` provides access to the group commit status information of all OBKV tenants. For more information about the `GV$OB_KV_GROUP_COMMIT_STATUS` view, see [GV$OB_KV_GROUP_COMMIT_STATUS](../../../700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/1260.gv-ob-kv-group-commit-status-of-mysql-mode.md). `V$OB_KV_GROUP_COMMIT_STATUS` records the group commit status information of all tenants on the current observer node. For more information about the `V$OB_KV_GROUP_COMMIT_STATUS` view, see [V$OB_KV_GROUP_COMMIT_STATUS](../../../700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/31460.v-ob-kv-group-commit-status-of-mysql-mode.md).
* In a user tenant, `GV$OB_KV_GROUP_COMMIT_STATUS` provides access only to the group commit status information of the current tenant. For more information about the `GV$OB_KV_GROUP_COMMIT_STATUS` view, see [GV$OB_KV_GROUP_COMMIT_STATUS](../../../700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/1260.gv-ob-kv-group-commit-status-of-mysql-mode.md). `V$OB_KV_GROUP_COMMIT_STATUS` provides access only to the group commit status information of the current tenant on the current observer node. For more information about the `V$OB_KV_GROUP_COMMIT_STATUS` view, see [V$OB_KV_GROUP_COMMIT_STATUS](../../../700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/31460.v-ob-kv-group-commit-status-of-mysql-mode.md).

## Limitations

* In a minor compaction scenario, the performance of group commit is affected by the disk I/O performance bottleneck. When the I/O performance bottleneck is reached, the performance of group commit degrades.

* In scenarios with low load pressure, we do not recommend that you enable group commit. Take a tenant specification of 16C32G as an example. When the CPU load is below 60%, for write operations, setting the batch size to less than 5 provides some optimization, whereas setting it to greater than 10 results in performance regression. For read operations, enabling group commit does not significantly improve overall performance.
