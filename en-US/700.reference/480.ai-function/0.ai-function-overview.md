# Overview of AI Function Service

This topic describes the basic concepts, features, use cases, and limitations of AI Function Service.

## Basic concepts

AI Function Service is an innovative feature provided by OceanBase AI Database. It seamlessly integrates AI model capabilities and document processing capabilities into the internal data processing workflow of the database. Users can directly call these capabilities using SQL expressions, significantly simplifying the RAG process.

## Function overview

| **Requires a large language model** | **Function** | **Description** | **Use case** |
| --- | --- | --- | --- |
| No, pure local processing | `AI_SPLIT_DOCUMENT` | Splits text into multiple segments for subsequent processing.<main id="notice" type='notice'><h4>Notice</h4><p>Using this function does not require registering a model and endpoint, nor does it require granting AI model permissions.</p></main> | Document splitting |

## Use cases

AI Function Service is suitable for the following scenarios:

* Text splitting: The `AI_SPLIT_DOCUMENT` function splits text into multiple segments for subsequent processing.
* Text/image embedding: The `AI_EMBED` function converts the retrieved or split text or images into vectors, laying the foundation for vector search and matching, such as image search by image.
* Result reranking: The `AI_RERANK` function further sorts search results based on similarity or relevance to improve result accuracy.
* Model inference: The `AI_COMPLETE` and `AI_PROMPT` functions call a large model to perform advanced reasoning tasks such as generation, summarization, and Q&A on text or images, and output the final results.

## Usage notes and limitations

* When using functions with pure local processing (e.g., `AI_SPLIT_DOCUMENT`), you do not need to register a model and endpoint, nor do you need to grant AI model permissions.
* You can view AI model configuration information through views. For more information, see [Syntax and examples of AI functions](300.ai-function.md).
* External text reading is implemented through the SQL function [LOAD_FILE](../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/5920.load-file-of-mysql-mode-in-sql.md). You do not need to grant AI model permissions or register an AI model and endpoint. The `LOAD_FILE` function reads external storage files into the database using the external table interface created by [CREATE LOCATION](../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2230.create-location-of-mysql-mode-in-sql.md) and returns the file content in `BLOB` format.
* The following notes and limitations apply to image embedding and processing:
    * Only the `AI_EMBED`, `AI_COMPLETE`, and `AI_PROMPT` functions support it.
    * Supported image sources: HTTP/HTTPS image URLs (image size typically limited to within 5 MB) and binary image data (`BLOB` columns or passed via `FROM_BASE64(...)`; the system automatically identifies the format).
    * Supported image formats: common formats such as JPEG, PNG, WebP, BMP, and TIFF.
