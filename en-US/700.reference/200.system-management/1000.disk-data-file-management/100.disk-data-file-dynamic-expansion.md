# Configure dynamic expansion of disk data files

OceanBase AI Database supports automatic expansion based on the actual usage of disk data files.

## Background information

In OceanBase AI Database, the file that stores data is named `block_file`. The `block_file` is located in the `/store/sstable` directory under the installation directory of the OBServer node. This file is created after each OBServer node starts up. The size of the `block_file` is controlled by the `datafile_size` or `datafile_disk_percentage` parameter. 

OceanBase AI Database introduces a user-configurable option for progressive disk space usage by data files. That is, the system first pre-allocates a reasonable disk size for data files and then automatically expands the capacity based on the actual disk usage and user configuration.

## Related parameters

OceanBase AI Database primarily uses the following parameters in combination to achieve automatic expansion of disk data files:

* `datafile_size`: Sets the amount of available disk space that data files can occupy. The default value is `0M`. For detailed information about the cluster-level parameter `datafile_size`, see [datafile_size](../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/4700.datafile_size.md).

* `datafile_disk_percentage`: The percentage of total disk space occupied by data files. The default value is `0`. For detailed information about the cluster-level parameter `datafile_disk_percentage`, see [datafile_disk_percentage](../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/4400.datafile_disk_percentage.md).

* `datafile_next`: Sets the step size for automatic expansion of disk data files. The default value is `0`, which means growth is not enabled. To enable automatic growth, set this parameter to a value other than `0`. For detailed information about the cluster-level parameter `datafile_next`, see [datafile_next](../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/4600.datafile_next.md).

* `datafile_maxsize`: Sets the maximum size for automatic expansion of disk data files. The default value is `0`, which means automatic expansion is not enabled. For detailed information about the cluster-level parameter `datafile_maxsize`, see [datafile_maxsize](../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/4500.datafile_maxsize.md).

When configuring the above parameters, note the following:

* Both `datafile_size` and `datafile_disk_percentage` can be used to set the disk space occupied by data files. You can choose either one to configure. In other cases:

  * If both parameters are configured, that is, both `datafile_size` and `datafile_disk_percentage` are set to non-zero values, the value set by `datafile_size` prevails.

  * If neither parameter is configured, that is, `datafile_size` is `0M` and `datafile_disk_percentage` is `0`, the system automatically calculates the percentage of total disk space occupied by data files based on whether logs and data share the same disk, as follows:

    * If logs and data share the same disk, data files occupy 60% of the total disk space.

    * If logs and data are stored on separate disks, data files occupy 90% of the disk space on which they reside.

* When configuring `datafile_maxsize`, its value must be greater than the current disk space occupied by the data file, which is `datafile_size` (or `datafile_disk_percentage`). If the set value is less than the current disk space occupied by the data file, automatic expansion will not be triggered.

* The maximum size of a data file is the smaller value of `datafile_maxsize` and the maximum available disk space.

* For `datafile_next`:

  * When `datafile_next` is set to a value less than or equal to `1G`, its value is `min (1G, datafile_maxsize * 10%)`.

  * When `datafile_next` is set to a value greater than `1G`, its value is `min (datafile_next, remaining disk space)`.

## Considerations and limitations

* When configuring the automatic expansion feature for disk data files, it is recommended to initially set the step size `datafile_next` to about 20% of `datafile_maxsize` to avoid frequent expansions.

* After enabling automatic data file expansion, plan the capacity for other applications deployed on the same server to prevent the actual maximum expandable space from being smaller than the configured `datafile_maxsize`.

* Dynamic shrinking of disk data files is not supported.

* If you do not want to enable the automatic expansion feature, you can directly set the value of `datafile_next` or `datafile_maxsize` to `0M` or keep them at their default value `0`. The system will then reserve a portion of disk space for data files using the original pre-allocation method.

## How to enable automatic data file expansion

### Step 1: View the values of current parameters

Before configuring dynamic expansion for disk data files, you need to view the values of each parameter to understand their current configurations.

1. Log in to the `sys` tenant of the cluster as the `root` user.

2. Run the following command to view the values of each parameter.

   ```shell
   obclient> SHOW PARAMETERS LIKE '%datafile_%';
   ```

### Step 2: Configure dynamic expansion for disk data files

After obtaining the values of each parameter, you can modify their values according to your actual usage scenario to enable automatic expansion for disk data files.

#### `datafile_size` (or `datafile_disk_percentage`), `datafile_next`, and `datafile_maxsize` are configured during cluster startup

If you have configured `datafile_size` (or `datafile_disk_percentage`), `datafile_next`, and `datafile_maxsize` to non-zero values when deploying and starting the OceanBase AI Database cluster, then:

* If the value of `datafile_maxsize` is greater than the value of `datafile_size`, or if `datafile_maxsize` is greater than the disk space calculated based on the `datafile_disk_percentage` ratio, automatic expansion will take effect after the cluster starts.

* If the value of `datafile_maxsize` is less than the value of `datafile_size`, or if `datafile_maxsize` is less than the disk space calculated based on the `datafile_disk_percentage` ratio, you need to modify the value of `datafile_maxsize` to be greater than `datafile_size` before enabling automatic data file expansion.

#### Only `datafile_size` (or `datafile_disk_percentage`) is configured during cluster startup

If you have set only the value of `datafile_size` or `datafile_disk_percentage` when deploying and starting the OceanBase AI Database cluster, you only need to manually set the values for `datafile_maxsize` and `datafile_next`, ensuring that the value of `datafile_maxsize` is greater than `datafile_size` or greater than the disk space calculated based on the `datafile_disk_percentage` ratio.

#### No `datafile_size` (or `datafile_disk_percentage`), `datafile_next`, or `datafile_maxsize` is configured during cluster startup

If you did not set `datafile_size` (or `datafile_disk_percentage`), `datafile_next`, or `datafile_maxsize` when deploying and starting the OceanBase AI Database cluster, you can follow these steps to enable automatic expansion for disk data files.

<main id="notice" type='notice'>
<h4>Note</h4>
<p>Whether to set <code>datafile_size</code> or <code>datafile_disk_percentage</code> during the initial cluster startup primarily affects the initial size of the disk data file.</p>
</main>

The specific procedure is as follows:

1. Log in to the `sys` tenant of the cluster as the `root` user.

2. Execute the following statement to confirm the pre-allocated space on the current disk.

   ```shell
   obclient> SELECT data_disk_allocated/1024/1024/1024 AS datafile_G FROM oceanbase.GV$OB_SERVERS;
   ```

   An example of the query result is shown below.

   ```shell
   +-------------------+
   | datafile_G        |
   +-------------------+
   | 1770.000000000000 |
   +-------------------+
   1 row in set
   ```

   According to the query result, the pre-allocated space for the current disk data file, `data_disk_allocated`, is 1770 GB, which is approximately 1.7 TB.

   For more information about the fields in the `GV$OB_SERVERS` view, see [GV$OB_SERVERS](../../700.system-views/300.system-view-of-sys-tenant/300.performance-view-of-sys-tenant/3200.gv-ob_servers-of-sys-tenant.md).

3. Based on the result from the previous step, set the value of `datafile_maxsize` to a value greater than `data_disk_allocated`, and also set `datafile_next` to a non-zero value.

   A sample configuration is as follows:

   ```sql
   ALTER SYSTEM SET datafile_maxsize='4TB';
   ```

   ```sql
   ALTER SYSTEM SET datafile_next='1TB';
   ```

4. After the settings are successfully applied, execute the following statement to confirm whether the automatic expansion setting takes effect.

   ```sql
   SELECT data_disk_allocated/1024/1024/1024 AS datafile_G, data_disk_capacity/1024/1024/1024 AS datafile_max_G FROM oceanbase.GV$OB_SERVERS;
   ```

   A sample query result is shown below.

   ```shell
   +-------------------+-------------------+
   | datafile_G        | datafile_max_G    |
   +-------------------+-------------------+
   | 1770.000000000000 | 4096.000000000000 |
   +-------------------+-------------------+
   1 row in set
   ```

   According to the query result, if the maximum auto-expansion space for the current disk data file, `data_disk_capacity`, is set to the value of `datafile_maxsize`, and `data_disk_capacity` is greater than `data_disk_allocated`, it indicates that the automatic expansion setting was successful.

### What to do next

After successful configuration, the system will automatically expand the data file based on its actual usage, taking into account the values of `datafile_next` and `datafile_maxsize`, thereby minimizing disk allocation.
