# O&M guide for custom hot/cold storage policies

This topic describes how to control the execution of background tasks for custom hot/cold storage policies by using SQL statements, including suspending, resuming, and manually triggering tasks.

## Suspend or resume background cache tasks

OceanBase AI Database provides the `suspend_storage_cache_task` parameter to specify whether to suspend background cache tasks. Valid values are as follows:

* `True`: Suspends all ongoing and newly initiated cache tasks.
* `False`: Does not suspend background cache tasks, which means suspended cache tasks are resumed.

For more information about this parameter, see [suspend_storage_cache_task](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7740.suspend_storage_cache_task.md).

### Examples

* Execute the following statement to suspend all hot cache tasks in a tenant.

    ```shell
    obclient> ALTER SYSTEM SET suspend_storage_cache_task = true;
    ```

* Execute the following statement to reactivate all suspended hot cache tasks in a tenant.

    ```shell
    obclient> ALTER SYSTEM SET suspend_storage_cache_task = false;
    ```

## Manually trigger a hot data caching task

After a custom hot/cold storage policy takes effect, you can execute the following SQL statement to manually trigger a hot data caching task immediately:

```sql
ALTER SYSTEM TRIGGER STORAGE_CACHE_POLICY_EXECUTOR;
```

### Example

Execute the following statement to immediately trigger a hot cache task.

```shell
obclient> ALTER SYSTEM TRIGGER STORAGE_CACHE_POLICY_EXECUTOR;
```
