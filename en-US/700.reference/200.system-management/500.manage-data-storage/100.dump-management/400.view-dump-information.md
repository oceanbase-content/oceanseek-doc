# View minor compaction information

After triggering a minor compaction, you can view the minor compaction progress and history through views.

## View minor compaction progress

1. Log in to the `sys` tenant or user tenant of the cluster as a tenant administrator.

2. To view the minor compaction progress, you can check information such as the amount of data that has not been compacted and the estimated completion time.

   The `GV$OB_TABLET_COMPACTION_PROGRESS` view displays progress information of only ongoing tablet-level compaction tasks but not completed tasks. The query statements are as follows:

   * View minor compaction progress in the system tenant

      ```sql
      obclient> SELECT * FROM oceanbase.GV$OB_TABLET_COMPACTION_PROGRESS WHERE TYPE='MINI_MERGE'\G
      ```

   * View minor compaction progress in a user tenant

      ```sql
      obclient> SELECT * FROM oceanbase.GV$OB_TABLET_COMPACTION_PROGRESS WHERE TYPE='MINI_MERGE'\G
      ```

   An example of the query result is as follows:

   ```shell
   *************************** 1. row ***************************
                         SVR_IP: xx.xx.xx.xx
                       SVR_PORT: 2401
                      TENANT_ID: 1002
                           TYPE: MINI_MERGE
                          LS_ID: 1001
                      TABLET_ID: 1152921504606847235
                 COMPACTION_SCN: 1680514780195130031
                        TASK_ID: Y9610BA2DA3E-0005F7FD6E1FE0FF-0-0
                         STATUS: NODE_RUNNING
                      DATA_SIZE: 31890729
           UNFINISHED_DATA_SIZE: 3351030
   PROGRESSIVE_COMPACTION_ROUND: 1
                    CREATE_TIME: 2023-04-03 17:49:17.278506
                     START_TIME: 2023-04-03 17:51:57.953999
          ESTIMATED_FINISH_TIME: 2023-04-03 23:32:25.969930
                    START_CG_ID: 0
                      END_CG_ID: 0
   1 row in set
   ```

   The following table describes some fields in the query result:

   * `TYPE`: Indicates the type of the compaction task. Valid values include the following ones:

      * `MDS_TABLE_MERGE`: Persists system metadata to disk in SSTable format.
      * `MAJOR_MERGE`: Tenant-level major compaction.
      * `MEDIUM_MERGE`: Partition-level major compaction.
      * `MINI_MERGE`: Mini compaction, which converts a MemTable into a Mini SSTable.
      * `MINOR_MERGE`: Minor compaction, which combines multiple Mini SSTables into a new Mini SSTable, or combines multiple Mini SSTables with one Minor SSTable to form a new Minor SSTable.
      * `META_MAJOR_MERGE`: A special type of major compaction that combines data from before a specified point in time into a Meta Major SSTable. Its data format is the same as that of a Major SSTable, excluding multi-version data and uncommitted transaction data.

   * `STATUS`: Indicates the task status. When the task is running, this field's value is `NODE_RUNNING`.

   * `DATA_SIZE`: Indicates the total amount of data that needs to be compacted.

   * `UNFINISHED_DATA_SIZE`: Indicates the amount of data that has not completed compaction.

   * `ESTIMATED_FINISH_TIME`: Indicates the estimated completion time.

   For detailed descriptions of the fields in the `GV$OB_TABLET_COMPACTION_PROGRESS` view, see [GV$OB_TABLET_COMPACTION_PROGRESS](../../../700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/4300.gv-ob_tablet_compaction_progress-of-mysql-mode.md).

   Based on the query result, if a tablet does not appear in this view or its minor compaction remains unfinished for a long time, you can query the `GV$OB_COMPACTION_DIAGNOSE_INFO` view to verify whether an exception has occurred.

   For detailed descriptions of the fields in the `GV$OB_COMPACTION_DIAGNOSE_INFO` view, see [GV$OB_COMPACTION_DIAGNOSE_INFO](../../../700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/500.gv-ob_compaction_diagnose_info-of-mysql-mode.md).

## View minor compaction history

1. Log in to the `sys` tenant or a user tenant of the cluster as a tenant administrator.

2. View the minor compaction history.

   The `GV$OB_TABLET_COMPACTION_HISTORY` view displays historical information about tablet-level compactions. The specific query statements are as follows:

   * View minor compaction history in the system tenant

      ```sql
      obclient> SELECT * FROM oceanbase.GV$OB_TABLET_COMPACTION_HISTORY WHERE TYPE='MINI_MERGE'\G
      ```

   * View minor compaction history in a user tenant

      ```sql
      obclient> SELECT * FROM oceanbase.GV$OB_TABLET_COMPACTION_HISTORY WHERE TYPE='MINI_MERGE'\G
      ```
