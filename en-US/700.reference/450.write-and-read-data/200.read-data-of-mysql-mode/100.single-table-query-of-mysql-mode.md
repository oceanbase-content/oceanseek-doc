# Single-table query

This topic describes how to perform a single-table query in OceanBase AI Database using SQL statements.

## Prerequisites

* You are connected to an OceanBase AI Database tenant.
* You have the `SELECT` privilege. For more information about checking user privileges, see [View user privileges](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/400.view-user-permissions-of-mysql-mode.md). If you do not have this privilege, contact your administrator to grant it. For more information about granting privileges to users, see [Grant privileges directly](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/200.authority-of-mysql-mode.md).

## Syntax

Use the [SELECT](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/8100.select-of-mysql-mode/100.select-of-mysql-mode.md) statement to query data.

The general structure of a single-table query using the `SELECT` statement is as follows:

```sql
SELECT [ALL | DISTINCT | UNIQUE | SQL_CALC_FOUND_ROWS] select_list
FROM table_name
[ WHERE query_condition ]
[ GROUP BY group_by_condition ]
[ HAVING group_condition ]
[ ORDER BY column_list ][ASC | DESC]
[ LIMIT limit_clause ]

column_list:
 column_name[,column_name...]
```

**The parameters are described as follows:**

| Parameter | Description |
| ----------------------------- | ----------------------------------------------------- |
| select_list | The list of columns to retrieve, which can be column names, expressions, aggregate functions, etc. Multiple columns can be separated with commas. |
| table_name | The name of the table from which data is to be retrieved. |
| WHERE query_condition | Optional. Specifies the search conditions. Only rows that meet the conditions are returned. |
| GROUP BY group_by_condition | Optional. Specifies the column by which to group the results. This clause is often used together with aggregate functions. |
| HAVING group_condition | Optional. Filters the grouped result set and returns only the groups that meet the specified conditions. |
| ORDER BY column_list | Optional. Specifies the columns to use for sorting the result set. |
| ASC | DESC | Optional. Specifies the sorting order. ASC indicates ascending order (default), and DESC indicates descending order. |
| LIMIT limit_clause | Optional. Specifies the number of rows to return in the result set. |
| column_list | The parameter used to specify the columns to retrieve. You can specify one or more columns, separated by commas. |
| column_name | The name of the column to retrieve. |

### Overview of the execution order of SELECT keywords

When keywords such as `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY`, and `LIMIT` are used together, their sequence is strictly defined. The execution order is as follows:

1. Execute `FROM` to find the table.

2. Execute `WHERE` to specify the constraints.

3. Execute `GROUP BY` to group (aggregate) each record fetched. If there is no `GROUP BY`, the entire result set acts as one group.

4. Execute `HAVING` to filter the results of the groups.

5. Execute `SELECT`.

6. Execute `DISTINCT` to remove duplicates.

7. Execute `ORDER BY` to sort the results in ascending or descending order based on the conditions.

8. Execute `LIMIT` to limit the number of results.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>The difference between <code>WHERE</code> and <code>HAVING</code> is that <code>WHERE</code> filters data before grouping, while <code>HAVING</code> filters the results after grouping to finally return the query result of the entire SQL statement.</p>
</main>

## Data filtering

When you want to query data that meets specific conditions, you can add a `WHERE` clause to the `SELECT` statement for data filtering. The `WHERE` clause can contain one or more conditions that filter the data. Only data that meets the `WHERE` conditions is returned. You can flexibly use query conditions to filter and retrieve target data according to your specific needs.

When using the `WHERE` clause, ensure the conditions are correct and appropriate operators are used.

The following table lists common query conditions used in the `WHERE` clause.

| Query condition type | Operator |
| ------------ | --------------------------------------------- |
| Comparison query | `=`,`>`,`<`,`>=`,`<=`,`!=`,`<>` |
| Logical query (multiple conditions) | `AND`,`OR`,`NOT` |
| Fuzzy query (character matching) | `LIKE`,`NOT LIKE` |
| Range query (specified range) | `BETWEEN AND`,`NOT BETWEEN AND` |
| Specified set query | `IN`,`NOT IN` |
| NULL value query | `IS NULL`,`IS NOT NULL` |

For more information about query condition operators, see [Comparison operators](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/200.operator-of-mysql-mode/500.comparison-operators-of-mysql-mode.md).

### Comparative condition queries

#### Equal to

Equal to (`=`): Queries data in the specified column that equals the target value. If the value is of string type, it must be enclosed in single or double quotes.

Example 4: Use the following SQL statement to query all rows in the `student` table where the `gender` column equals `1`, and return the data in the `id`, `name`, and `gender` columns for these rows.

```sql
SELECT id, name, gender
FROM student
WHERE gender = 1;    
```

The query result is as follows:

```shell
+----+-----------+--------+
| id | name      | gender |
+----+-----------+--------+
|  2 | William   |      1 |
|  4 | James     |      1 |
|  6 | Benjamin  |      1 |
|  8 | Michael   |      1 |
|  9 | Charlotte |      1 |
| 10 | Ethan     |      1 |
+----+-----------+--------+
6 rows in set
```

#### Not equal to

"Not equal to" includes two notations: `<>` and `!=`.

Example 5: Use the following SQL statement to query all rows in the `student` table where the `gender` column does not equal `1`, and return the data in the `id`, `name`, and `gender` columns for these rows.


#### Greater than and less than

Greater than (`>`) and less than (`<`) compare numerical values in size. When comparing characters, they are compared based on their ASCII code values, comparing each corresponding character position in sequence.

<main id="notice" type='explain'>

### Logical condition query

The logical operators `AND` and `OR` support queries with multiple conditions.

#### AND

The `AND` keyword is used to combine multiple conditions. Data is returned only if all conditions are met simultaneously.

Example 7: Use the following SQL statement to query all rows in the `student` table where `gender` equals `1` and `score` is less than or equal to `90`, and return the data in the `id`, `name`, `gender`, and `score` columns for these rows.

```sql
SELECT id, name, gender, score
FROM student
WHERE gender = 1 AND score <= 90;
```

The query result is as follows:

```shell
+----+-----------+--------+-------+
| id | name      | gender | score |
+----+-----------+--------+-------+
|  4 | James     |      1 |  87.5 |
|  9 | Charlotte |      1 |    88 |
+----+-----------+--------+-------+
2 rows in set
```

#### OR

The `OR` keyword is used to connect multiple conditions. Data is returned if any one of the conditions is met.

Example 8: Use the following SQL statement to query all rows in the `student` table where `gender` equals `1` or `score` is less than `90`, and return the data in the `id`, `name`, `gender`, and `score` columns for these rows.

```sql

FROM student
WHERE gender = 1 OR score < 90;
```

The query result is as follows:

```shell

+----+-----------+--------+-------+
|  1 | Emma      |      0 |    85 |
```

### Fuzzy query

The `LIKE` predicate can be used for fuzzy string matching.

This syntax matches the value in the corresponding column against `pattern`. `pattern` can be a complete string or contain the wildcard characters `%` and `_`. Specifically:

* The underscore (`_`) matches any single character.

* The percent sign (`%`) matches zero or more characters in the value. `%` cannot match `NULL`.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When the database character set is ASCII, two <code>_</code> characters are required for one Chinese character; when the character set is GBK, only one <code>_</code> character is needed.</p>
</main>

Example 9: Use the following SQL statement to query all rows in the `student` table where `name` contains `am`, and return the data in the `id` and `name` columns for these rows.

```sql
SELECT id, name
FROM student
WHERE name LIKE '%am%';
```

The query result is as follows:

```shell
+----+----------+
| id | name     |
+----+----------+
|  2 | William  |
|  4 | James    |
|  6 | Benjamin |
+----+----------+
3 rows in set
```

### Range query

The `BETWEEN ... AND` operator retrieves data that falls between two values. These values can be numeric, text, or date.

<main id="notice" type='notice'>
  <h4>Note</h4>
  <p>The two boundary values in a range query must not be swapped. The value must be greater than or equal to the left value and less than or equal to the right value.</p>
</main>

Example 10: Use the following SQL statement to query all rows in the `student` table where the `score` value is between `85` and `90`, and return the data in the `id`, `name`, and `score` columns for these rows.

```sql
SELECT id, name, score
```

The query result is as follows:


### Specified set query

The `IN` operator specifies multiple values in the `WHERE` clause, which form a set. `IN` returns any data in the specified column that matches any value in the set. `NOT IN` returns only data that does not match any value in the set.

  <main id="notice" type='notice'>
    <h4>Note</h4>
    <ul>
    <li>The value types in the <code>[NOT] IN</code> set must be consistent or compatible with each other.</li>
    <li>Values in the <code>[NOT] IN</code> set do not support wildcards.</li>
    </ul>
  </main>

Example 11: Use the following SQL statement to query all rows in the `student` table where the `id` value is in the set `(1, 3, 5, 7)`, and return the data in the `id` and `name` columns for these rows.

The `IS NULL` condition is used to query for data where the value in the specified column is `NULL`.

The `IS NOT NULL` condition is used to query data where the value of a specified column is not `NULL`.

## Data grouping

In SQL queries, you can use the `GROUP BY` clause to group the query results. `GROUP BY` supports grouping by a single field or multiple fields. Before grouping, you can use the `WHERE` clause to filter data. After grouping, you can use the `HAVING` clause to filter data and the `ORDER BY` clause to sort data.

**Considerations for data grouping:**

* When using the `GROUP BY` clause, the columns in the `SELECT` statement must be either columns in the `GROUP BY` clause or aggregate functions.
* When using the `HAVING` clause, the `HAVING` condition filters the grouped results, not the original data.

### Grouping by a single field

Example 14: Query the number of orders per customer in the `fruit_order` table and output `user_id` and `COUNT(order_id)`.

```sql
SELECT user_id, COUNT(order_id)
FROM fruit_order
GROUP BY user_id;
```

The query result is as follows:

```shell
+---------+-----------------+
| user_id | COUNT(order_id) |
+---------+-----------------+
|    1011 |               3 |
|    1022 |               4 |
|    1033 |               2 |
|    1034 |               1 |
+---------+-----------------+
4 rows in set
```

### Grouping by multiple fields

Example 15: Query the number of orders per customer per year in `fruit_order` and output `user_id`, `order_year`, and `COUNT(order_id)`.

```sql
SELECT user_id, order_year, COUNT(order_id)
FROM fruit_order
GROUP BY user_id,order_year;
```

The query result is as follows:

```shell
+---------+------------+-----------------+
| user_id | order_year | COUNT(order_id) |
+---------+------------+-----------------+
|    1011 |       2019 |               1 |
|    1011 |       2020 |               2 |
|    1022 |       2019 |               2 |
|    1022 |       2021 |               2 |
|    1033 |       2020 |               1 |
|    1033 |       2021 |               1 |
|    1034 |       2021 |               1 |
+---------+------------+-----------------+
7 rows in set
```

### Filtering before grouping

Example 16: Query the number of orders per customer for the year 2020 and output `user_id` and `COUNT(order_id)`.

```sql
SELECT user_id, COUNT(order_id)
FROM fruit_order t
WHERE t.order_year = 2020
GROUP BY user_id;
```

The query result is as follows:

```shell
+---------+-----------------+
| user_id | COUNT(order_id) |
+---------+-----------------+
|    1011 |               2 |
|    1033 |               1 |
+---------+-----------------+
2 rows in set
```

### Filtering after grouping

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>When a query contains <code>HAVING</code>, it first obtains the SQL query result without the <code>HAVING</code> clause, then filters out the matching data based on the <code>HAVING</code> condition on this result, and finally returns these data. Therefore, aggregate functions can be used after <code>HAVING</code>, and these aggregate functions do not have to be the same as those after <code>SELECT</code>. </p>
</main>

Example 17: Query customers with more than 1 order in 2019 and output `user_id` and `COUNT(order_id)`.

```sql
SELECT user_id, COUNT(order_id)
FROM fruit_order t
WHERE t.order_year = 2019
GROUP BY user_id
HAVING COUNT(order_id) >= 2;
```

The query result is as follows:

```shell
+---------+-----------------+
| user_id | COUNT(order_id) |
+---------+-----------------+
|    1022 |               2 |
+---------+-----------------+
1 row in set
```

### Aggregate queries

An aggregate query is a type of query that performs aggregate operations on data and returns a summary of the results. It can perform aggregate operations such as statistics, counting, summing, averaging, finding the maximum value, and finding the minimum value on a set of data. Aggregate queries are typically used with the `GROUP BY` clause to group the data and apply aggregate operations to each group. The `GROUP BY` clause groups the data by specified columns, and then aggregate functions are applied to each group to generate a result set.

Common aggregate functions used in grouping are shown in the following table.

| Aggregate function | Description |
| --------- | -------------- |
| MAX() | Returns the maximum value in the specified column. |
| MIN() | Returns the minimum value in the specified column. |
| COUNT() | Returns the number of rows in the query result. |
| SUM() | Returns the sum of the values in the specified column. |
| AVG() | Returns the average value of the data in the specified column. |

For more information about using aggregate functions in queries, see [Use aggregate functions in queries](300.use-operators-and-functions-in-query-of-mysql-mode/700.use-aggregate-functions-in-queries-of-mysql-mode.md).

## Data sorting

Data sorting is an operation that sorts the query results according to specified columns or expressions, and it can rearrange data in ascending order (`ASC`) or descending order (`DESC`). In SQL queries, you can use the `ORDER BY` clause to specify the sorting method. The `ORDER BY` clause supports sorting by a single field, multiple fields, by alias, and by function. Multiple fields are separated by commas. When performing a sorting query, if the `ASC` or `DESC` keyword is not added, the query result is sorted in ascending order by default.

Using the `ORDER BY` clause to sort a result set is a resource-consuming operation, especially for large datasets. When necessary, it is recommended to use indexes to optimize the sorting operation. Ensure the correct columns and sorting order are specified.

### Sorting by a single field

Example 19: Display student information in ascending order of `score` in the `student` table.

```sql
SELECT id, name, score
```

## LIMIT clause

### Limit the number of rows in a result set

In an SQL query, you can use the `LIMIT` clause to limit the number of rows returned in the result set.

The syntax of format 1 of the `LIMIT` clause for limiting the number of rows is as follows:

```sql
LIMIT [offset,] row_count
```

The syntax of format 2 of the `LIMIT` clause for limiting the number of rows is as follows:

```sql
LIMIT row_count OFFSET offset
```

**The parameters are described as follows:**

* `offset`: The offset, which is the number of rows to skip. In format 1, `offset` is optional and defaults to 0, meaning 0 rows are skipped. The value range for `offset` is [0,+∞).

* `row_count`: The number of rows to return. In format 1, if `offset` is not specified, the first row is used by default. The value range for `row_count` is [0,+∞).

<main id="notice" type='notice'>
  <h4>Note</h4>
  <p>The values for <code>offset</code> and <code>row_count</code> are subject to the following restrictions:<ul><li>Expressions cannot be used.</li><li>They must be exact numbers and cannot be negative.</li></ul></p>
</main>

#### Get the first m rows

Example 24: Query the first 5 records of columns `id` and `name` from the `student` table.

```sql
SELECT id, name
FROM student
LIMIT 5;
```

The query result is as follows:

```shell
+----+---------+
| id | name    |
+----+---------+
|  1 | Emma    |
|  2 | William |
|  3 | Olivia  |
|  4 | James   |
|  5 | Sophia  |
+----+---------+
5 rows in set
```

Example 25: To get the record with the highest `score` from the `student` table, you can first sort by `score` in descending order and then select the first record.

#### Get the m rows after skipping n rows

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>When skipping n rows of records, if the number of remaining data rows is less than m, the query result will include all the remaining data.</p>
</main>

### Paginated query

In SQL queries, you can use the `LIMIT` clause to implement paginated queries.

The usage format for the `LIMIT` clause in paginated queries is as follows:

```sql
LIMIT (page_no - 1) * page_size, page_size;
```

**The parameters are described as follows:**

* `page_no`: Indicates which page to retrieve, starting from 1. The range is [1,+∞).

* `page_size`: Indicates how many records to display per page. The range is [1,+∞). For example, page_no = 5, page_size = 10 means to retrieve 10 data records on the 5th page.

Example 27: In the `student` table, display 2 data records per page, and retrieve the data on the 1st, 2nd, and 3rd pages in sequence.

Page 1:

```sql
SELECT id, name
FROM student
ORDER BY id
LIMIT 0,2;
```

```shell
+----+---------+
|  1 | Emma    |
|  2 | William |
+----+---------+
2 rows in set
```

Page 2:

```sql
SELECT id, name
FROM student

LIMIT 2,2;
```

The query result is as follows:

```shell
+----+--------+
| id | name   |
+----+--------+
|  3 | Olivia |
|  4 | James  |
+----+--------+
2 rows in set
```

Page 3:


```shell
2 rows in set
```
