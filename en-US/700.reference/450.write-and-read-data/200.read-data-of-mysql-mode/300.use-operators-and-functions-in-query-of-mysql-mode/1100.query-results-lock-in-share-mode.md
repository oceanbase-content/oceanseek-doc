# Lock in share mode

`SELECT ... LOCK IN SHARE MODE` is used to acquire a shared lock while querying data, preventing other transactions from writing to the data but allowing other transactions to read it. When this statement is used, a shared-mode lock is placed on the rows being read. Other sessions can read these rows, but they cannot modify them until the current transaction is committed.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>OceanSeek emulates the functionality of the <code>LOCK IN SHARE MODE</code> shared lock syntax by using write locks. This meets compatibility requirements for some software while ensuring syntactic correctness. However, since write locks cause read operations with the <code>LOCK IN SHARE MODE</code> command to block each other, this syntax is generally not recommended, especially in performance-sensitive scenarios.</p>
</main>

This topic demonstrates how to use `SELECT ... LOCK IN SHARE MODE` to lock query results through examples.

## Example

1. In **Session 1**, execute the following SQL statement to start a transaction.

    ```sql
    START TRANSACTION;
    ```

2. In **Session 1**, use the `LOCK IN SHARE MODE` syntax to query the record with `id` equal to `1` in the `test_tbl1` table and acquire a shared lock.

    ```sql
    SELECT * FROM test_tbl1 WHERE id = 1 LOCK IN SHARE MODE;
    ```

    The query result is as follows:

    ```shell
    +------+------+
    | id   | name |
    +------+------+
    |    1 | A1   |
    +------+------+
    1 row in set
    ```

3. In **Session 2**, execute the following SQL statement to start a transaction.

    ```sql
    START TRANSACTION;
    ```

4. In **Session 2**, execute the following SQL statement to query the record with `id` equal to `1` in the `test_tbl1` table.

    ```sql
    SELECT * FROM test_tbl1 WHERE id = 1;
    ```

    The query result is as follows:

    ```shell
    +------+------+
    | id   | name |
    +------+------+
    |    1 | A1   |
    +------+------+
    1 row in set
    ```

5. In **Session 2**, execute the following SQL statement to change the `name` value to 'A1A1A1' for the row with `id` equal to `1` in the `test_tbl1` table. This SQL statement waits until the transaction in **Session 1** is rolled back or committed before it can be executed.

    ```sql
    UPDATE test_tbl1 SET name = 'A1A1A1' WHERE id = 1;
    ```

    The query result is as follows:

    ```shell
    ERROR 1205 (HY000): Lock wait timeout exceeded; try restarting transaction
    ```

6. In **Session 1**, execute the following SQL statement to commit the transaction.

    ```sql
    COMMIT;
    ```

7. In **Session 2**, execute the update statement from **Step 5** again.

    ```sql
    UPDATE test_tbl1 SET name = 'A1A1A1' WHERE id = 1;
    ```

    The query result is as follows:

    ```shell
    Query OK, 1 row affected
    Rows matched: 1  Changed: 1  Warnings: 0
    ```
