# MANAGE_DYNAMIC_PARTITION

The `MANAGE_DYNAMIC_PARTITION` statement is used to perform a one-time dynamic partition management task, which includes pre-creating future partitions and dropping expired partitions for dynamic partitioned tables under the current tenant.

## Syntax

```sql
DBMS_PARTITION.MANAGE_DYNAMIC_PARTITION (
    precreate_time VARCHAR(64) DEFAULT NULL,
    time_unit VARCHAR(64) DEFAULT NULL);
```

## Parameters

| Parameter | Description |
| ---------------- | ----------- |
| precreate_time | Optional value. `n {hour \| day \| week \| month \| year}`.<ul><li>The default value is `null`, indicating that no pre-create time is specified.</li><li>When explicitly specified, the larger of the specified `precreate_time` and the table's `precreate_time` is used as the pre-create time when pre-creating partitions for a dynamic partitioned table.</li></ul> |
| time_unit | Optional value. `null \| hour \| day \| week \| month \| year`. <ul><li>The default value is `null`, which means dynamic partition management tasks are performed on all dynamically partitioned tables.</li><li>When the value is `hour`, dynamic partition management tasks are performed only on tables whose `time_unit` is `hour`.</li><li>When the value is `day`, dynamic partition management tasks are performed only on tables whose `time_unit` is `day`.</li><li>When the value is `week`, dynamic partition management tasks are performed only on tables whose `time_unit` is `week`.</li><li>When the value is `month`, dynamic partition management tasks are performed only on tables whose `time_unit` is `month`.</li><li>When the value is `year`, dynamic partition management tasks are performed only on tables whose `time_unit` is `year`.</li></ul> |

## Examples

```sql
CALL DBMS_PARTITION.MANAGE_DYNAMIC_PARTITION();
```

```sql
CALL DBMS_PARTITION.MANAGE_DYNAMIC_PARTITION('3DAY');
```

```sql
CALL DBMS_PARTITION.MANAGE_DYNAMIC_PARTITION('3DAY', 'HOUR');
```
