# GRANT_PERMISSION

The `DBMS_JAVA.GRANT_PERMISSION` procedure is used to grant Java privileges to a specified user or role.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This subprogram is available starting with OceanBase AI Database V4.6.3.</p>
</main>

## Syntax

The `GRANT_PERMISSION` statement provides two overloaded forms. The second form returns the primary key of the granted permission record through the `key` output parameter.

```sql
DBMS_JAVA.GRANT_PERMISSION(IN grantee VARCHAR(65535), IN permission_type VARCHAR(65535), IN permission_name VARCHAR(65535), IN permission_action VARCHAR(65535));

DBMS_JAVA.GRANT_PERMISSION(IN grantee VARCHAR(65535), IN permission_type VARCHAR(65535), IN permission_name VARCHAR(65535), IN permission_action VARCHAR(65535), OUT key BIGINT);
```

## Parameters

| **Parameter** | **Note** |
| ------------------- | ----------- |
| grantee | The name of the user or role to which the privilege is granted. |
| permission_type | The Java permission type, which is the class name of the Java permission. For example: `java.io.FilePermission`. |
| permission_name | The target name corresponding to the permission, for example, `/dev/random`. |
| permission_action | The operation corresponding to the permission, for example, `read`. |
| key | Output parameter. The primary key of the granted permission record is returned. |

## Usage instructions

- Before calling `DBMS_JAVA.GRANT_PERMISSION`, ensure that the tenant parameter `ob_enable_java_udf` is enabled. Otherwise, an unsupported error will be returned.
- Only the root user can operate Java permissions. Other users will receive an error indicating insufficient permissions when they attempt to call it.
- Only system privilege types are supported. Non-system privilege types specified in the `SCHEMA:TYPE` format are not supported.
- For privileges not in the allowlist, only the root user of the sys tenant (`root@sys`) can grant them.
- This operation is idempotent: if the target permission record already exists and is enabled, it will not be created again; if it exists but is disabled, it will be re-enabled.
