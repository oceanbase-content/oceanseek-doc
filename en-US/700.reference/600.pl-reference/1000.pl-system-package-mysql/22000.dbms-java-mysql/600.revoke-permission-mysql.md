# REVOKE_PERMISSION

The `DBMS_JAVA.REVOKE_PERMISSION` subprogram is used to revoke Java privileges from a specified user or role. It disables all privilege records under the object that match the input parameters and are in the enabled state.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This subprogram is available starting with OceanSeek V4.6.3.</p>
</main>

## Syntax

```sql
DBMS_JAVA.REVOKE_PERMISSION(IN permission_schema VARCHAR(65535), IN permission_type VARCHAR(65535), IN permission_name VARCHAR(65535), IN permission_action VARCHAR(65535));
```

## Parameters

| **Parameter** | **Note** |
| ------------------- | ------- |
| permission_schema | The name of the user or role whose privileges need to be revoked. |
| permission_type | Java permission type, which is the class name of the Java permission. For example: `java.io.FilePermission`. |
| permission_name | The target name corresponding to the permission, for example, `/dev/random`. |
| permission_action | The operation corresponding to the permission, for example, `read`. |

## Usage instructions

- Before calling `DBMS_JAVA.REVOKE_PERMISSION`, ensure that the tenant parameter `ob_enable_java_udf` is enabled. Otherwise, an unsupported error will be returned.
- Only the root user can operate Java permissions. Other users will receive an insufficient permission error when calling it.
- This subprogram matches permission records under the specified object that have consistent `permission_type`, `permission_name`, and `permission_action` and are enabled, and disables them.
- To permanently delete a permission record, use `DBMS_JAVA_DELETE_PERMISSION`.
