# DISPLAY_CURSOR

The `DISPLAY_CURSOR` function is used to display the details of executed query plans.

## Syntax

```sql
DBMS_XPLAN.DISPLAY_CURSOR(plan_id      DECIMAL          DEFAULT    0,         -- default value: last plan
                          format       VARCHAR(32)      DEFAULT    'TYPICAL',
                          svr_ip       VARCHAR(64)      DEFAULT    null,   -- default value: server connected by client
                          svr_port     DECIMAL          DEFAULT    0,     -- default value: server connected by client
                          tenant_id    DECIMAL          DEFAULT    0,     -- default value: current tenant
                          sql_handle   VARCHAR(32)      DEFAULT    NULL,
                          plan_name    VARCHAR(32)      DEFAULT    NULL
                        )
RETURN DBMS_XPLAN_TYPE_TABLE;
```

## Parameters

| Parameter | Description |
| ---- | ---- |
| plan_id | The ID of the execution plan. If not specified, the last executed plan is used. |
| format | Specifies the plan format information. The following parameters are available:<ul><li>`'BASIC'`: Displays a small amount of information, such as the operator ID, operator name, operator remarks, and expression information.</li><li>`'TYPICAL'`: Displays basic information, such as operator ID, operator name, operator remarks, optimizer-estimated output rows, optimizer-estimated execution time, and expression information. If the plan has been executed, it also displays the actual feedback from the first execution, such as the actual number of rows and cost.</li><li>`'ALL'`: Displays comprehensive plan information, such as operator ID, operator name, operator remarks, optimizer-estimated output rows, optimizer-estimated execution time, expression information, effective hints, Query Block Name Trace information, outline information, base table optimization information, constant parameterization information, constraint information, and Plan Note.</li><li>`'ADVANCED'`: Displays comprehensive plan information, which is consistent with the 'ALL' parameter. Additionally, it shows a hierarchical structure for complex plans.</li></ul> |
| svr_ip | The IP address of the node where the plan resides. By default, it is the IP address of the node to which the session is connected. |
| svr_port | Port number of the node where the plan resides. By default, it is the port number of the node to which the session is connected. |
| tenant_id | Tenant ID of the plan. By default, it is the tenant to which the current session is connected. |
| sql_handle | An execution plan is a handle for an SQL statement. When querying a specific execution plan of an SQL statement, if multiple similar SQL statements exist, you can use the sql_handle to precisely identify the target statement. |
| plan_name | The name of the execution plan. |

## Examples

In user tenants, since the Function Table feature is not available, you can directly use the `DISPLAY_CURSOR` function in a `SELECT` statement to output plan information.

1. Create a table.

   ```shell
   obclient [test]> CREATE TABLE t1(c1 INT);
   ```

2. Execute the query.

   ```shell
   obclient [test]> SELECT * FROM t1;
   ```

3. Use the `DBMS_XPLAN` package to view historical execution plans.

   * Query without specifying parameters.

     ```shell
     obclient [test]> SELECT DBMS_XPLAN.DISPLAY_CURSOR() ;
     ```

     The query result is as follows:

     ```shell

     |0 |TABLE FULL SCAN|t1  |1       |4           |0        |0            |0          |155         |
     ================================================================================================

     Outputs & filters:
     ```
