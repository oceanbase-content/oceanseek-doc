# GATHER_SCHEMA_STATS

The `GATHER_SCHEMA_STATS` procedure is used to collect statistics for all objects in a specified schema.

## Syntax

```sql
DBMS_STATS.GATHER_SCHEMA_STATS (
  ownname            VARCHAR2,
  estimate_percent   NUMBER DEFAULT AUTO_SAMPLE_SIZE,
  block_sample       BOOLEAN DEFAULT FALSE,
  method_opt         VARCHAR2 DEFAULT DEFAULT_METHOD_OPT,
  degree             NUMBER DEFAULT NULL,
  granularity        VARCHAR2 DEFAULT DEFAULT_GRANULARITY,
  cascade            BOOLEAN DEFAULT NULL,
  no_invalidate      BOOLEAN DEFAULT FALSE,
  stattype           VARCHAR2 DEFAULT 'DATA',
  force              BOOLEAN DEFAULT FALSE);
```

## Parameters

| Parameter | Explanation |
| ------------------ | -------------- |
| ownname | The schema to which the table belongs. |
| estimate_percent | Estimated percentage of rows. The valid range is \[0.000001,100\]. |
| block_sample | Determine whether the database uses random block sampling (`TRUE`) or random row sampling (`FALSE`). The default value is `FALSE`. Random block sampling is more efficient, but if the data is not randomly distributed on disk, the sample values may be correlated. |
| method_opt | When setting preferences at the global, schema, database, or dictionary level, only the following operations are allowed: `FOR ALL` Syntax. In addition, `method_opt` Only one of the following options or a combination of both is allowed: <ul><li> `FOR ALL [INDEXED \| HIDDEN] COLUMNS [size_clause]`   </li>   <li> `FOR COLUMNS [column_clause]`    where `size_clause` is defined as `size_clause := SIZE {integer \| REPEAT \| AUTO \| SKEWONLY}`. The `column_clause` is defined as `column_clause := column_name \| extension name \| extension`. </li>   <li> `integer`: The number of histogram buckets. The valid range is \[1,2048\].   </li>   <li> `REPEAT`: Collect histograms only on columns that already have histograms.   </li>   <li> `AUTO`: Determines which columns to collect histograms for based on data distribution and column workload.   </li>   <li> `SKEWONLY`: Determines which columns to collect histograms for based on column data distribution.   </li>   <li>`column_name`: The column name.   </li>   <li> `extension`: Can be a group of columns or an expression in the format `(column_name, colume_name [, ...])`. </li>   </ul>   The default value is `FOR ALL COLUMNS SIZE AUTO`. |
| degree | Degree of parallelism. Default value is `NULL`. `NULL` Indicates the use of a `CREATE TABLE` or `ALTER TABLE` In the statement, `DEGREE` The default value of the table specified by the  clause. When `DEGREE=>NULL` or `DEGREE=>n` is used, if the object size does not guarantee parallel execution, `DBMS_STATS` may use serial execution. |
| granularity | The granularity of the statistics to be collected (only applicable when the table is partitioned). <ul><li>`ALL`: Collects all statistics (subpartition, partition, and global).    </li>   <li>`APPROX_GLOBAL AND PARTITION`: similar to `GLOBAL AND PARTITION` However, in this case, global statistics are the aggregation of partition-level statistics. This option summarizes all statistics except for the number of distinct values and the number of distinct keys in the index. But it only aggregates partitions with statistics. If `partname` is `NULL` or when summarization cannot be performed (for example, due to missing statistics for one of the partitions), global statistics are collected.    </li>   <li>`AUTO`: The granularity is determined by the partition type. This is the default value.    </li>   <li>`DEFAULT`: Collects global and partition-level statistics. This option is deprecated. It is recommended to use `GLOBAL AND PARTITION`.    </li>   <li> `GLOBAL`: Collects global statistics.    </li>   <li>`GLOBAL AND PARTITION`: Collects global and partition-level statistics. Subpartition-level statistics are not collected, even for composite partition objects.    </li>   <li>`PARTITION`: Collects partition-level statistics.    </li>   <li>`SUBPARTITION`: Collects statistics at the subpartition level.</li></ul> |
| cascade | In addition to collecting statistics on tables and columns, statistics on indexes are also collected. This is equivalent to running the `GATHER_INDEX_STATS` The process. |
| no_invalidate | Whether to flush the plan cache during statistics collection. Valid values: `TRUE` Indicates that the plan cache is not flushed during statistics collection. |
| stattype | The location where the current statistics are stored. |
| force | Whether to forcibly collect and ignore the lock status. Default is `FALSE`. If set to `TRUE` Statistics collection will continue even if statistics locks are acquired. |

## Exceptions

| Error Code | Description |
| ----------- | -------------------- |
| HY000 | <ul><li>The schema does not exist, or you do not have sufficient permissions.</li><li>The input value is incorrect.</li></ul> |

## Usage instructions

To call this procedure, you must be the owner of the table. For objects owned by `SYS`, you must be the table owner or have the `SYSDBA` privilege to call this procedure.

## Examples

Gathers statistics for all tables in the `hr` schema.

```sql
obclient> CALL DBMS_STATS.GATHER_SCHEMA_STATS ('hr', degree=>64,no_invalidate=>TRUE);
Query OK, 0 rows affected
```
