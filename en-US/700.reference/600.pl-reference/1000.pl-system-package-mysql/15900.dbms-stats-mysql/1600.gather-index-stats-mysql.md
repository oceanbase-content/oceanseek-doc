# GATHER_INDEX_STATS

The `GATHER_INDEX_STATS` procedure is used to collect index statistics.

## Syntax

```sql
DBMS_STATS.GATHER_INDEX_STATS (
  ownname            VARCHAR2,
  indname            VARCHAR2,
  partname           VARCHAR2 DEFAULT NULL,
  estimate_percent   NUMBER DEFAULT AUTO_SAMPLE_SIZE,
  stattab            VARCHAR2 DEFAULT NULL,
  statown            VARCHAR2 DEFAULT NULL,
  degree             NUMBER DEFAULT NULL,
  granularity        VARCHAR2 DEFAULT DEFAULT_GRANULARITY,
  no_invalidate      BOOLEAN DEFAULT FALSE,
  force              BOOLEAN DEFAULT FALSE,
  tabname            VARCHAR2 DEFAULT NULL
);
```

## Parameters

| Parameter | Explanation |
| ------------------ | ---------------------- |
| ownname | The schema to which the table belongs. |
| indname | Index name. |
| partname | Partition name. |
| estimate_percent | Estimated percentage of rows. The valid range is \[0.000001,100\]. |
| stattab | Specifies the table name of the user table for storing statistics. |
| statown | Specifies the username of the user table for storing statistics. |
| degree | Degree of parallelism. Default value is `NULL`. `NULL` Indicates the use of a `CREATE TABLE` or `ALTER TABLE` In the statement, `DEGREE` The default value of the table specified by the clause. When `DEGREE=>NULL` or `DEGREE=>n` is used, if the object size does not guarantee parallel execution, `DBMS_STATS` may use serial execution. |
| granularity | The granularity of index statistics to be collected (only applicable when the table is partitioned). <ul><li>`ALL`: Collects statistics for all indexes, including subpartitions, partitions, and global indexes. </li>   <li>`APPROX_GLOBAL AND PARTITION`: Similar to `GLOBAL AND PARTITION` However, in this case, global index statistics are a summary of partition-level statistics. This option summarizes all index statistics except for the number of distinct values and the number of distinct keys in the index. But only partitions with index statistics are summarized. If `partname` is `NULL` or when aggregation cannot be performed (for example, because index statistics are missing for one of the partitions), global index statistics will be collected.   </li>   <li>`AUTO`: The granularity is determined by the partition type. This is the default value. </li>   <li>`DEFAULT`: Collects index statistics at the global and partition levels. This option is deprecated. It is recommended to use `GLOBAL AND PARTITION`.  </li>   <li>`GLOBAL`: Collects global index statistics.  </li>   <li>`GLOBAL AND PARTITION`: Collects index statistics at the global and partition levels. Even for composite partition objects, index statistics at the subpartition level are not collected.   </li>   <li>`PARTITION`: Collects partition-level index statistics.   </li>   <li>`SUBPARTITION`: Collects index statistics at the subpartition level.</li>   </ul> |
| no_invalidate | Whether to flush the plan cache during statistics collection. Valid values: `TRUE` Indicates that the plan cache is not flushed during statistics collection. |
| force | Whether to forcibly collect and ignore the lock status. Default is `FALSE`. If set to `TRUE`, index statistics are collected even if the statistics themselves are locked. |
| tabname | Table name. |

## Exceptions

| Error Code | Description |
| ----------- | -------------- |
| HY000 | <ul><li>The index does not exist or you do not have sufficient permissions.</li><li>The input value is incorrect.</li></ul> |

## Usage instructions

To call this procedure, you must be the owner of the table. For objects owned by `SYS`, you must be the table owner or have the `SYSDBA` privilege to call this procedure.

## Examples

Gather statistics on index `idx` of table `tbl1` for user `testUser01`.

```sql
obclient> CALL DBMS_STATS.GATHER_INDEX_STATS('testUser01', 'idx1', degree=>4, tabname=>'tbl1');
Query OK, 0 rows affected
```
