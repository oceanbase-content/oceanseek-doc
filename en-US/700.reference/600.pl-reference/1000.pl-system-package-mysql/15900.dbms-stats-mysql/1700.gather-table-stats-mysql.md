# GATHER_TABLE_STATS

The `GATHER_TABLE_STATS` procedure is used to collect statistics for tables and columns.

## Syntax

```sql
DBMS_STATS.GATHER_TABLE_STATS (
  ownname             VARCHAR2,
  tabname             VARCHAR2,
  partname            VARCHAR2 DEFAULT NULL,
  estimate_percent    NUMBER DEFAULT AUTO_SAMPLE_SIZE,
  block_sample        BOOLEAN  DEFAULT FALSE,
  method_opt          VARCHAR2 DEFAULT DEFAULT_METHOD_OPT,
  degree              NUMBER   DEFAULT to_degree_type(get_param('DEGREE')),
  granularity         VARCHAR2 DEFAULT DEFAULT_GRANULARITY,
  cascade             BOOLEAN DEFAULT NULL,
  no_invalidate       BOOLEAN DEFAULT FALSE,
  stattype            VARCHAR2 DEFAULT 'DATA',
  force               BOOLEAN DEFAULT FALSE,
  hist_est_percent    NUMBER DEFAULT AUTO_SAMPLE_SIZE,
  hist_block_sample   BOOLEAN DEFAULT NULL
  );
```

## Parameters

| Parameter | Explanation |
| ------------------ | ------------------- |
| ownname | The schema of the table to be analyzed. |
| tabname | Table name. |
| partname | Partition name. |
| estimate_percent | Estimated percentage of rows. The valid range is \[0.000001,100\]. |
| block_sample | Determine whether the database uses random block sampling (`TRUE`) or random row sampling (`FALSE`). The default value is `FALSE`. Random block sampling is more efficient, but if the data is not randomly distributed on disk, the sample values may be correlated. |
| method_opt | When setting preferences at the global, schema, database, or dictionary level, only the following operations are allowed: `FOR ALL` syntax. In addition, `method_opt` Only one of the following options, or a combination of both, is allowed: <ul><li> `FOR ALL [INDEXED \| HIDDEN] COLUMNS [size_clause]`   </li>   <li> `FOR COLUMNS [column_clause]`    where `size_clause` is defined as `size_clause := SIZE {integer \| REPEAT \| AUTO \| SKEWONLY}`. The `column_clause` is defined as `column_clause := column_name \| extension name \| extension`. </li>   <li> `integer`: The number of histogram buckets. The valid range is \[1,2048\].   </li>   <li> `REPEAT`: Collect histograms only on columns that already have histograms.   </li>   <li> `AUTO`: Determines which columns to collect histograms for based on the data distribution and column workload.   </li>   <li> `SKEWONLY`: Determines which columns to collect histograms for based on the column's data skew.   </li>   <li> `column_name`: The column name.   </li>   <li> `extension`: Can be a group of columns or an expression in the format `(column_name, colume_name [, ...])`. The default value is `FOR ALL COLUMNS SIZE AUTO`. </li>   </ul> |
| degree | Degree of parallelism. Default value is `NULL`. `NULL` indicates that the function is used by `CREATE TABLE` or `ALTER TABLE` In the statement, `DEGREE` The default value of the table specified by the  clause. When `DEGREE=>NULL` or `DEGREE=>n` is used, if the object size does not guarantee parallel execution, `DBMS_STATS` may use serial execution. |
| granularity | The granularity of the statistics to be collected (only applicable when the table is partitioned). <ul><li>`ALL`: Collects all statistics (subpartition, partition, and global).</li> <li>`APPROX_GLOBAL AND PARTITION`: Similar to `GLOBAL AND PARTITION` However, in this case, global statistics are the aggregation of partition-level statistics. This option summarizes all statistics except for the number of distinct values and the number of distinct keys indexed. But only partitions with statistics are aggregated. If `partname` is `NULL` or when aggregation cannot be performed (for example, statistics for one of the partitions are missing), global statistics are collected.   </li> <li>`AUTO`: The granularity is determined by the partition type. This is the default value.   </li> <li>`DEFAULT`: Collects global and partition-level statistics. This option is deprecated. It is recommended to use `GLOBAL AND PARTITION`.   </li> <li> `GLOBAL`: Collects global statistics.   </li> <li>`GLOBAL AND PARTITION`: Collects global and partition-level statistics. Subpartition-level statistics are not collected, even for composite partition objects.   </li> <li>`PARTITION`: Collects partition-level statistics.   </li> <li>`SUBPARTITION`: Collects statistics at the subpartition level.</li>  </ul> |
| cascade | In addition to collecting statistics on tables and columns, statistics on indexes are also collected. This is equivalent to running the `GATHER_INDEX_STATS` The process. |
| no_invalidate | Whether to flush the plan cache when statistics are collected. Valid values: `TRUE` Indicates that the plan cache is not flushed during statistics collection. |
| stattype | The location where the current statistics are stored. |
| force | Whether to forcibly collect the data, ignoring the lock status. Default value: `FALSE`. If set to `TRUE`, statistics collection will continue even if the statistics are locked. |
| hist_est_percent | Specifies the sampling ratio for the histogram. |
| hist_block_sample | Specifies the sampling method for the histogram. |

## Usage instructions

To call this procedure, you must be the owner of the table. For objects owned by `SYS`, you must be the table owner or have the `SYSDBA` privilege to call this procedure.

## Examples

Collect statistics for the `tbl1` table of user `testUser01`.

```sql
obclient> CALL DBMS_STATS.GATHER_TABLE_STATS ('testUser01', 'tbl1', method_opt=>'FOR ALL COLUMNS SIZE
   5', granularity=>'ALL', degree=>4, no_invalidate=>FALSE);
Query OK, 0 rows affected
```
