# DBMS_DATA_DICT

The `DBMS_DATA_DICT` package is used to control the scheduling of data dictionaries.

## Syntax

### Prohibit Scheduling Data Dictionaries

```sql
CALL DBMS_DATA_DICT.DISABLE_DUMP();
```

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If the runtime dictionary parameter <a href="../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2300.dump_data_dictionary_to_log_interval.md">dump_data_dictionary_to_log_interval</a> is not set to <code>0</code>, the operation fails and a message prompting you to set this parameter to <code>0</code> is displayed.</p>
</main>

### Allow Scheduling Data Dictionary

```sql
CALL DBMS_DATA_DICT.ENABLE_DUMP();
```

### Manually trigger dictionary generation

```sql
CALL DBMS_DATA_DICT.TRIGGER_DUMP(DICT_ITEM_RETENTION_BY_DAY);
```

### Adjust the scheduled DUMP cycle of a dictionary

```sql
CALL DBMS_DATA_DICT.MODIFY_DUMP_INTERVAL(INTERVAL_EXPR);
```

Scenarios that trigger dictionary generation scheduling:

* A data dictionary is automatically generated immediately after a tenant is created.

* Data dictionary generation is automatically triggered immediately after archiving is enabled.

<main id="notice" >
  <h4>Notice</h4>
  <p>The dictionary DUMP service must be enabled during execution (that is, execute <code>ALL DBMS_DATA_DICT.ENABLE_DUMP()</code> first). Otherwise, the execution will fail.</p>
</main>

### Adjust the recycling interval for dictionary history records

```sql
CALL DBMS_DATA_DICT.MODIFY_DICT_ITEM_RETENTION(DICT_ITEM_RETENTION_BY_DAY)
```

## Parameters

| **Parameter** | **Note** | **Data types** |
| ------------------ | --------------------------------- | ------- |
| DICT_ITEM_RETENTION_BY_DAY | <ul>After triggering the execution to generate a dictionary, the system recovers historical DUMP records of the dictionary:<li>When parameters are involved, the value range is greater than or equal to `0`.</li><li>No parameters are carried, or the parameter is `0` indicates that the dictionary is not reclaimed in this DUMP operation. </li></ul> | INT |
| INTERVAL_EXPR | Indicates the desired scheduling cycle. This parameter must follow the `DBMS_SCHEDULER` of `REPEAT_INTERVAL` The writing format is as follows, and it must be enclosed in single quotes. For example: `'FREQ=MINUTELY; INTERVAL=120'`. Where: <ul><li>`FREQ` Optional `SECONDLY`/`DAILY`/`HOURLY`/`WEEKLY`/`YEARLY`.</li><li>`INTERVAL` is the execution cycle. Enter the corresponding number for the desired execution cycle.</li></ul>Together, they form `INTERVAL_EXPR`. | TEXT |
| DICT_ITEM_RETENTION_BY_DAY | Represents the expected recycling time of dictionary history records, in days.<br/>and `DBMS_DATA_DICT.TRIGGER_DUMP` Compared with a call without parameters, after this stored procedure is executed, subsequent dictionary DUMPs will by default recycle the dictionary history records based on the time specified this time (unless you manually execute a parameterized `DBMS_DATA_DICT.TRIGGER_DUMP`(stored procedures). | INT |

## Examples

### Prohibit Scheduling Data Dictionaries

```sql
CALL DBMS_DATA_DICT.DISABLE_DUMP();
Query OK, 0 rows affected
```

### Allow Scheduling Data Dictionary

```sql
CALL DBMS_DATA_DICT.ENABLE_DUMP();
Query OK, 0 rows affected
```

### Manually trigger dictionary generation

```sql
CALL DBMS_DATA_DICT.TRIGGER_DUMP(7);
Query OK, 0 rows affected
```

### Adjust the scheduled DUMP cycle for the dictionary

```sql
CALL DBMS_DATA_DICT.MODIFY_DUMP_INTERVAL('FREQ=MINUTELY; INTERVAL=120');
Query OK, 0 rows affected
```

### Adjust the recycling interval of dictionary history records

```sql
CALL DBMS_DATA_DICT.MODIFY_DICT_ITEM_RETENTION(7);
Query OK, 0 rows affected
```
