# KILL_REFRESH

`KILL_REFRESH` is used to actively terminate a materialized view refresh batch that is currently in progress and managed by the new scheduling framework.

## Overview

After you call `DBMS_MVIEW.KILL_REFRESH(refresh_id)`, the system performs the following operations on the refresh batch corresponding to the specified `refresh_id`:

* Mark tasks in the `PENDING` state as `CANCELLED`: All tasks that have not been scheduled for execution will be immediately cancelled and will no longer enter the scheduling queue.
* Terminate tasks in the `RUNNING` state: For a task that is currently running, the system locates its executing session and initiates a `kill` operation to forcibly interrupt its execution.
* Status convergence processing: Tasks that are killed are eventually marked with the status `CANCELLED`.
* Terminal tasks are not affected: Tasks that have already been successfully completed (`SUCCESS`), failed (`FAILED`), or cancelled (`CANCELLED`) will not be affected by this termination operation.

## Syntax

```sql
DBMS_MVIEW.KILL_REFRESH(refresh_id)
```

## Parameters

| **Parameter** | **Note** |
| ------------ | ---------- |
| refresh_id | Specifies the unique identifier for the materialized view refresh batch, which is assigned by the new scheduling framework. <main id="notice" type='explain'><h4>Note</h4><p>You can view the <code>refresh_id</code> information through the <a href="../../../700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/5200.o-dba_mvref_run_stats-of-mysql-mode.md">DBA_MVREF_RUN_STATS</a> view.</p></main> |

## Examples

Terminate the refresh of the materialized view with `refresh_id` 100023.

```shell
obclient> CALL DBMS_MVIEW.KILL_REFRESH(100023);
```
