# List of LogService views

LogService provides two types of views: virtual views and internal tables, which are used to query the operational status and metadata of a cluster.

## Virtual views

Virtual views are queried using the `show v-table` command and display real-time performance statistics for the cluster.

| **View name** | **Query method** | **Description** |
| --- | --- | --- |
| [node_load](300.virtual-views/100.node-load.md) | `show v-table node_load` | Displays the IOPS and bandwidth usage of each LN node. |
| [az_load](300.virtual-views/200.az-load.md) | `show v-table az_load` | Displays the IOPS and bandwidth usage of each AZ. |
| [stream_replica_io](300.virtual-views/300.stream-replica-io.md) | `show v-table stream_replica_io` | Displays the I/O statistics for each log stream replica, including I/O type, replica type, bandwidth, and IOPS. |

## Internal tables

Internal tables are queried using the `show meta --table-name` command and store persistent metadata for the LogService cluster.

### Node information

| **Table name** | **Query method** | **Description** |
| --- | --- | --- |
| `t_ln_info` | `show meta --table-name t_ln_info` | Records the status information of an LN, including the node ID, address, AZ, status (Active/Inactive/Deleting), start time (`start_time`), and offline time (`offline_time`). |
| `t_ln_info_history` | `show meta --table-name t_ln_info_history` | Records the historical status information of an LN to track its online and offline history. |

### Log stream replicas

| **Table name** | **Query method** | **Description** |
| --- | --- | --- |
| `t_stream` | `show meta --table-name t_stream` | Records the basic information of a log stream, including the log stream ID, status (CREATING, NORMAL, or DELETING), and initial member list (`initial_member_list`). |
| `t_stream_replica` | `show meta --table-name t_stream_replica` | Records the member list of log stream replicas, reflecting the current distribution of log stream replicas in the cluster. |

### Migration and replication tasks

| **Table name** | **Query method** | **Description** |
| --- | --- | --- |
| `t_stream_replica_task` | `show meta --table-name t_stream_replica_task` | Records the information about the migration or replication task being executed, including the migration source (`src_ln`), migration destination (`dest_ln`), and task status. |
| `t_stream_replica_task_history` | `show meta --table-name t_stream_replica_task_history` | Records the history of completed migration and replication tasks, including `status` (whether the task succeeded) and `comment` (the failure reason). |

### Upload scheduling

| **Table name** | **Query method** | **Description** |
| --- | --- | --- |
| [t_stream_upload_mapping](400.internal-tables/100.t-stream-upload-mapping.md) | `show meta --table-name t_stream_upload_mapping` | Records the mapping between log streams and upload nodes, including the log stream ID, upload node ID, and generation module (UploadService/LoadBalancer/DisasterRecovery). |

### Resource events

| **Table name** | **Query method** | **Description** |
| --- | --- | --- |
| [t_resource_event](400.internal-tables/200.t-resource-event.md) | `show meta --table-name t_resource_event` | Records resource event alerts for a cluster, including the resource type (IOPS/bandwidth), event type (OverUtilized/UnderUtilized), resource utilization, associated AZ, and node. |
