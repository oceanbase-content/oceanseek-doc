# Overview of Log Service parameters

This topic describes the cluster-level and node-level parameters of Log Service (LogService) by scope.

## Cluster-level parameters

| **Parameter name** | **Description** |
| --- | --- |
| [min_oblogservice_version](./200.cluster-level-parameters/100.min_oblogservice_version.md) | The minimum oblogservice version allowed for the cluster. It should be increased only during an upgrade and must not be manually rolled back. |
| [node_permanent_offline_time_sec](./200.cluster-level-parameters/200.node_permanent_offline_time_sec.md) | The node is marked as permanently offline after it remains offline continuously for longer than the configured duration. |
| [stream_replica_task_history_retention_sec](./200.cluster-level-parameters/300.stream_replica_task_history_retention_sec.md) | The retention period (in seconds) of the history of log stream replica migration or replication tasks. |
| [object_store_url](./200.cluster-level-parameters/400.object_store_url.md) | The access address of the object storage service. |
| [log_local_target_retention_sec](./200.cluster-level-parameters/500.log_local_target_retention_sec.md) | The target retention period (in seconds) of local logs of each stream. This period is guaranteed as much as possible, but may be shortened under disk pressure. |
| [retained_remote_log_blocks](./200.cluster-level-parameters/600.retained_remote_log_blocks.md) | The number of log blocks retained on the remote object storage. |
| [log_local_disk_utilization_threshold](./200.cluster-level-parameters/700.log_local_disk_utilization_threshold.md) | The local disk usage threshold (in percentage). When this threshold is exceeded, the disk pressure handling logic is triggered. |
| [max_syslog_file_count](./200.cluster-level-parameters/800.logservice-max_syslog_file_count.md) | The maximum number of log files (`oblogservice.log`) retained after rolling. A value of 0 indicates no limit. |
| [enable_rebalance](./200.cluster-level-parameters/900.logservice-enable_rebalance.md) | Whether to enable log stream load balancing. |
| [load_balance_policy](./200.cluster-level-parameters/1000.load_balance_policy.md) | The load balancing policy. `load_based` indicates balancing based on node load (such as disk usage), and `replica_count_based` indicates balancing based on the number of replicas. |
| [rebalance_interval_sec](./200.cluster-level-parameters/1100.rebalance_interval_sec.md) | The interval (in seconds) at which load balancing is triggered. |
| [metric_sample_save_interval_sec](./200.cluster-level-parameters/1200.metric_sample_save_interval_sec.md) | The interval (in seconds) for sampling and saving monitoring metrics. |
| [max_utilization_threshold](./200.cluster-level-parameters/1300.max_utilization_threshold.md) | The upper limit (in percentage) of disk or resource utilization of a node in log stream load balancing. Migration is triggered when the limit is exceeded. |
| [min_utilization_threshold](./200.cluster-level-parameters/1400.min_utilization_threshold.md) | The lower limit (in percentage) of disk or resource utilization of a node in log stream load balancing. When the utilization falls below this limit, only `UnderUtilized` resource events are recorded for observation, and migration is not triggered. |
| [log_disk_throttling_percentage](./200.cluster-level-parameters/1500.logservice-log_disk_throttling_percentage.md) | The threshold at which progressive throttling of the log disk starts, expressed as a percentage of the total log disk capacity. Throttling starts when the space occupied by unreclaimable logs exceeds this threshold. |
| [log_disk_throttling_maximum_duration](./200.cluster-level-parameters/1600.logservice-log_disk_throttling_maximum_duration.md) | The maximum latency duration (in milliseconds) for progressive throttling of the log disk. If this parameter is set to 0, progressive throttling is disabled. |
| [rebuild_log_lag_threshold](./200.cluster-level-parameters/1700.rebuild_log_lag_threshold.md) | The replica log lag threshold that triggers automatic Rebuild in Log Service. |

## Node-level parameters

| **Parameter name** | **Description** |
| --- | --- |
| [cluster_id](./300.server-level-parameters/100.logservice-cluster_id.md) | The unique identifier of the cluster. |
| [region](./300.server-level-parameters/200.region.md) | The identifier of the region where the node is located. |
| [az](./300.server-level-parameters/300.az.md) | The identifier of the availability zone (AZ) where the node is located. |
| [local_ip](./300.server-level-parameters/400.logservice-local_ip.md) | The IP address on which the node listens for external requests. |
| [rpc_port](./300.server-level-parameters/500.logservice-rpc_port.md) | The port on which the node's gRPC service listens. It forms the listening address together with `local_ip`. |
| [log_disk_size](./300.server-level-parameters/600.logservice-log_disk_size.md) | The upper limit of the disk space occupied by log data. If this parameter is set to 0, the quota is determined by `log_disk_percentage`. |
| [io_worker_count](./300.server-level-parameters/700.io_worker_count.md) | The number of I/O worker threads. |
| [http_port](./300.server-level-parameters/800.http_port.md) | The listening port of the HTTP status/management service. It forms the listening address together with `local_ip`. **The port must be valid. Otherwise, an error is reported when the node starts, and the node fails to start.** |
| [status_thread_pool_size](./300.server-level-parameters/900.status_thread_pool_size.md) | The size of the thread pool of the HTTP status service. |
| [stack_size](./300.server-level-parameters/1000.logservice-stack_size.md) | The stack size of worker threads. |
| [net_thread_count](./300.server-level-parameters/1100.logservice-net_thread_count.md) | The number of network I/O threads. If this parameter is set to 0, the runtime automatically determines the number. |
| [enable_heap_profile](./300.server-level-parameters/1200.enable_heap_profile.md) | Whether to enable heap memory profiling. |
| [log_disk_percentage](./300.server-level-parameters/1300.logservice-log_disk_percentage.md) | The percentage of the total file system space allocated to logs. This parameter takes effect only when `log_disk_size` is set to 0. The value must be in the range [1, 99]. A value of 0 or greater than or equal to 100 causes disk quota parsing to fail. |
| [memory_limit](./300.server-level-parameters/1400.logservice-memory_limit.md) | The upper limit of the memory that the process can use. If this parameter is set to 0, the process uses 70% of the physical memory of the system by default. The total memory used by the process must not exceed the total physical memory of the system. |
| [log_level](./300.server-level-parameters/1500.log_level.md) | The log output level. |
| [max_syslog_file_size](./300.server-level-parameters/1600.max_syslog_file_size.md) | The size threshold for rolling over a single log file (`oblogservice.log`). When this threshold is exceeded, the system switches to a new file. |
| [disk_max_iops](./300.server-level-parameters/1700.disk_max_iops.md) | The estimated maximum disk IOPS, used for I/O rate limiting. The value must be greater than 0. |
| [disk_max_bandwidth](./300.server-level-parameters/1800.disk_max_bandwidth.md) | The estimated maximum disk bandwidth, used for I/O rate limiting. The value must be greater than 0. |
| [upload_block_concurrency](./300.server-level-parameters/1900.upload_block_concurrency.md) | The concurrency of uploading log blocks to object storage. |
| [log_cache_memory_percentage](./300.server-level-parameters/2000.log_cache_memory_percentage.md) | The percentage of `memory_limit` that LogCache capacity can use (if `memory_limit` is set to 0, 70% of the total system memory is used). The actual capacity has a lower limit of 256 MB. If this parameter is set to 0, the cache is completely disabled. |
| [log_cache_evict_scan_budget](./300.server-level-parameters/2100.log_cache_evict_scan_budget.md) | The upper limit of the budget for scanning reusable space in the cache during a single log publish. |
| [log_cache_enable_write](./300.server-level-parameters/2200.log_cache_enable_write.md) | The LogCache write switch. It is enabled by default. |
| [log_cache_enable_read](./300.server-level-parameters/2300.log_cache_enable_read.md) | The LogCache read switch. It is enabled by default. |
| [log_cache_metrics_dump_interval_sec](./300.server-level-parameters/2400.log_cache_metrics_dump_interval_sec.md) | The interval (in seconds) at which each node outputs `log_cache_metrics` monitoring logs. A value of 0 disables this feature (the default, which causes no behavior change during an upgrade). If you set it to a value such as 10, time series data such as `hit_rate`, `hit_bytes`, and `miss_bytes` can be obtained during the verification period. |
| [ln_id](./300.server-level-parameters/2500.ln_id.md) | The numeric ID of the current node (LN) in the cluster, which is written by the deployment system. |
| [local_storage_dir](./300.server-level-parameters/2600.local_storage_dir.md) | The path of the local data directory of the node. |
