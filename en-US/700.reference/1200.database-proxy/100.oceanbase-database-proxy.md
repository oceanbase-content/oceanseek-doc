# OceanBase Database Proxy (ODP)

OceanBase Database Proxy (ODP) is a dedicated proxy server for OceanBase AI Database. Data of OceanBase AI Database users is stored in multiple replicas on OBServer nodes. ODP receives SQL requests from users, forwards them to the optimal target OBServer node, and returns the execution results to users.

## Features

As a key component of OceanBase AI Database, ODP has the following features:

* Connection management

  For the physical connection of a client, ODP maintains its own connections to multiple OBServer nodes at the backend. It uses an incremental synchronization scheme based on version numbers to maintain the session state of the connection to each OBServer node, ensuring that the client can efficiently access each OBServer node.

* Optimal routing

  ODP fully considers the replica locations involved in user requests, the read/write separation routing strategies configured by users, the optimal links for multi-region OceanBase deployment, and the status and load of each OceanBase node. It routes user requests to the optimal OBServer node, ensuring the high-performance operation of OceanBase Database as a whole.

* High-performance forwarding

  ODP is fully compatible with the MySQL protocol and supports OceanBase's proprietary protocol. With a multi-threaded asynchronous framework and transparent stream forwarding, ODP ensures high-performance data forwarding while minimizing its own consumption of machine resources.
  
* Easy maintenance

  ODP is stateless and supports unlimited horizontal scaling. It also supports access to multiple OceanBase AI Database clusters at the same time. You can use a rich set of internal commands to monitor ODP status in real time, making maintenance simple and convenient.

* High availability

  ODP provides high availability in two aspects. First, ODP itself is highly available and continuously provides proxy services. Second, ODP is a key component of the OceanBase high availability system, shielding users from outages, upgrades, and other situations and ensuring the stability and fast recovery of OceanBase AI Database services.

* Proprietary protocol

  By default, ODP uses OceanBase's proprietary protocol with OBServer nodes. For example, it performs cyclic redundancy check (CRC) on messages to ensure the correctness of the link with OBServer nodes, and enhances the transport protocol to support Oracle-compatible data types and interaction models.
