# ODP management overview

OceanBase Database Proxy (ODP) is a proxy server dedicated to OceanBase AI Database. OceanBase AI Database stores replicas of user data on multiple OBServer nodes. When ODP receives an SQL statement from a user, ODP forwards the statement to the optimal OBServer node and returns the execution result to the user.

## ODP overview

OceanBase AI Database differs from traditional standalone databases in that it is a distributed database, where each table, or even different partitions of a table, may be stored on different machines. To read from or write to a table, you must first locate the primary replica of the table or partition that contains the data, and then execute the corresponding SQL statement. This is almost impossible to achieve at the application layer. As a dedicated reverse proxy for OceanBase AI Database, ODP has routing as its core function: it forwards data access requests initiated by clients to the correct OBServer node and forwards the response from the OBServer node back to the client.

The following figure shows how a client accesses data in OceanBase AI Database by using ODP.

![obproxy](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.1/700.reference/1200.database-proxy/obproxy.png)

The user sends a request from a client to a load balancing component, which forwards the request to a stateless ODP. Then, ODP forwards the request to the optimal OBServer node in the OceanBase AI Database cluster.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>
    <p>The load balancing component can be a common product on the market, such as SLB or F5.</p>
    </li>
    <li>
    <p>ODP is not responsible for database or table sharding, nor does it participate in the generation or scheduling of execution plans as an SQL engine does. It performs only reverse proxy forwarding.</p>
    </li>
    </ul>
  </main>

Each OBServer node contains a complete SQL engine and a storage engine, which parse user SQL statements to generate and execute physical execution plans. Distributed OBServer nodes use the Paxos protocol to ensure high availability. In this architecture, ODP undertakes only basic routing and disaster recovery, whereas all database capabilities are implemented by OBServer nodes. This clear division of labor allows each component to perform to its full potential, enabling OceanBase AI Database to achieve performance close to that of a standalone database.

ODP can correctly send requests to the primary replica. With specific configurations, ODP also supports scenarios such as read/write splitting and read preference for standby replicas. In addition, when an OBServer node is down, being upgraded, or undergoing a major compaction, the [Blocklist mechanism](../700.route-management/400.odp-routing-policy/300.blacklist-mechanism.md) ensures that user requests are routed to a normally available OBServer node.
