# Physical connections

This topic describes how to query the number of sessions in the current tenant and view the internal attributes of all network connections on ODP.

## Query the number of sessions and session IDs for the current tenant

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This document uses ODP V4.2.3 as an example to describe the query method and output information.</p>
</main>

1. Connect to OceanSeek through ODP. The following example uses the `root@sys` user.

   ```shell
   obclient -h10.10.10.1 -P2883 -uroot@sys -p -Doceanbase -A
   ```

2. Use the `SHOW PROCESSLIST` statement to query the number of sessions and session IDs for the current tenant.

   ```shell
   obclient> SHOW PROCESSLIST;
   ```

   The output varies depending on the value of the ODP parameter `client_session_id_version`.

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>The <code>client_session_id_version</code> parameter specifies the computing logic for generating client session IDs. We recommend that you set the parameter to <code>2</code> to use the new computing logic, which ensures that the generated client session IDs are globally unique.</p>
   </main>

   * When the ODP parameter `client_session_id_version` is set to `2`, ODP uses the new computing logic to generate globally unique client session IDs. In this case, the output displays session information on the OBServer node corresponding to the tenant. The query result is as follows:

     ```shell
     +------------+---------+---------------------+-----------+---------+------+--------+------------------+
     | Id         | User    | Host                | db        | Command | Time | State  | Info             |
     +------------+---------+---------------------+-----------+---------+------+--------+------------------+
     |          1 | root    | 10.10.10.1:39512    | oceanbase | Query   |    0 | ACTIVE | SHOW PROCESSLIST |
     | 3221501386 | proxyro | 10.10.10.1:37728    | oceanbase | Sleep   |   13 | SLEEP  | NULL             |
     +------------+---------+---------------------+-----------+---------+------+--------+------------------+
     ```

     The meaning of each field is described in the following table:

     | Field | Description |
     |-------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
     | Id                | The ID of the session, which is the `cs id`.     |
     | User              | The user to which the session belongs.   |
     | Host              | The client IP address and port number that initiated the session.           |
     | db                | The name of the database to which the session is currently connected.|
     | Command           | The type of command the session is currently executing. |
     | Time              | The time taken to execute the current command, in seconds. If a command is retried, the system resets and recalculates. |
     | State             | The current state of the session.   |
     | Info              | The statement being executed by the session.  |

   * When the ODP parameter `client_session_id_version` is set to `1`, ODP uses the original computing logic to generate client session IDs. In this case, the output displays session information on the ODP node. The query result is as follows:

     ```shell
     +------+--------+------+---------------------+-----------+-------------+-------------------+-------------------+-------+-------+
     | Id   | Tenant | User | Host                | db        | trans_count | svr_session_count | state             | tid   | pid   |
     +------+--------+------+---------------------+-----------+-------------+-------------------+-------------------+-------+-------+
     |    9 | sys    | root | 10.10.10.1:17890    | oceanbase |           0 |                 1 | MCS_ACTIVE_READER | 48243 | 48243 |
     +------+--------+------+---------------------+-----------+-------------+-------------------+-------------------+-------+-------+
     ```

     The meaning of each field is described in the following table:

     | Field | Description |
     |-------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
     | Id                | The `id` number assigned to each client session by ODP, that is, the `cs id`.     |
     | Tenant            | Indicates the tenant to which the session belongs.   |
     | User              | Indicates the user to whom the session belongs.   |
     | Host              | Indicates the client IP address and port number that initiated the session.            |
     | db                | Indicates the name of the database currently connected by the session.|
     | trans_count       | Indicates the number of transactions transmitted by ODP in the session.       |
     | svr_session_count | The number of sessions.                  |
     | state             | The status of the client session. Valid values: <ul><li>MCS_INIT (initializing)</li> <li>MCS_ACTIVE_READER (active)</li><li>MCS_KEEP_ALIVE (keep-alive)</li><li>MCS_HALF_CLOSE (half-closed)</li><li>MCS_CLOSED (closed)</li></ul>    |
     | tid               | The thread ID.                 |
     | pid               | The process ID.                 |

## View the internal attribute status of all network connections on ODP

Use the `SHOW PROXYNET CONNECTION` statement to view the internal attribute status of all network connections on ODP.

```sql
SHOW PROXYNET CONNECTION [thread_id [LIMIT xx]]
```

The parameters are described as follows:

* If `thread_id` is not specified, the internal attribute status of all network connections on ODP is displayed.

* If `thread_id` is specified, the connection status on the specified thread is displayed. You can specify the `LIMIT [offset,] rows` and `LIMIT rows OFFSET offset` parameters, which are fully compatible with MySQL format. When `rows == -1`, all rows are displayed.

The meaning of each field is described in the following table:

| Field | Description |
| ---------------------------- | ------------ |
| thread_id | The thread ID. |
| connect_id | The network connection ID. |
| socket_fd | The socket descriptor. |
| type | The connection status. |
| src_ip | The source IP address. |
| src_port | The source port number. |
| dst_ip | The destination IP address. |
| dst_port | The destination port number. |
| virtual_ip | The virtual IP address. |
| virtual_port | The virtual port number. |
| bind_style | The binding type. |
| read_enabled | Indicates whether the connection supports read operations. |
| read_nbytes | The number of bytes to be read. |
| read_ndone | The number of bytes that have been read. |
| write_enabled | Indicates whether the connection supports write operations. |
| write_nbyte | The number of bytes to be sent. |
| write_ndone | The number of bytes that have been sent. |
| alive_time(sec) | The duration for which the connection has been alive. |
| activity_timeout_in(sec) | The timeout period of the active state. |
| inactivity_timeout_in(sec) | The timeout period of the inactive state. |
| timeout_close_in(sec) | The timeout period after which the connection is closed. |
| last_error_no | The last returned error code. |
| shutdown | The number of closed network connections. |
| comments | The comments. |
