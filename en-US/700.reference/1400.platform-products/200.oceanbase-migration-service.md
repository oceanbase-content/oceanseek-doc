# OceanBase Migration Service (OMS)

OceanBase Migration Service (OMS) is a service provided by OceanBase AI Database that supports data interaction between homogeneous or heterogeneous data sources and OceanBase AI Database. It supports online migration of existing data and real-time synchronization of incremental data.

OMS provides a visualized and centralized management platform. You can migrate data in real time with simple configurations. OMS aims to help you achieve real-time data migration and data synchronization from homogeneous or heterogeneous databases to OceanBase with low risk, low cost, and high efficiency.

## Features and benefits

* Supports multiple data sources

  OMS supports data transfer between OceanBase AI Database and multiple types of data sources such as MySQL and Kafka. The features provided may vary depending on the type of the source database and the type of the destination.

* Online migration without service interruption, imperceptible to applications

  You can use OMS to seamlessly migrate data to OceanBase without service interruption. After the application is switched to OceanBase AI Database, all changed data in OceanBase AI Database is synchronized in real time to the source database used before the switch.

  OMS reduces the risks of business migration and helps enterprises build data architectures with high availability and reliability.

* High-performance, secure, and reliable data migration

  OMS replicates large amounts of data between heterogeneous IT infrastructures in near real time with a second-level latency. Therefore, OMS can be applied to multiple scenarios such as data migration, inter-city and cross-region data disaster recovery, emergency systems, real-time data synchronization, disaster recovery, and database upgrade and migration.

  OMS allows you to migrate and synchronize data without affecting or interrupting your business applications while ensuring data integrity and transaction consistency. Full migration performance can reach 100 MB/s and 200,000 TPS, and data synchronization performance can reach 50,000 RPS. OMS also provides a high-availability deployment architecture to deliver stable and reliable transmission for data migration and real-time synchronization.

* All-in-one interaction

  OMS supports full-lifecycle management of data migration. You can create, configure, and monitor data migration tasks on the management console, with simple and convenient interaction.

* Real-time data synchronization to facilitate business decoupling

  OMS supports real-time data synchronization between the two tenant types of OceanBase and self-managed Kafka or RocketMQ instances. It can be applied to business scenarios such as real-time data warehouse construction, data query, and report distribution.

* Multiple data consistency checks

  OMS provides multiple data consistency check methods to ensure data quality in a more comprehensive, time-saving, and efficient manner. It also displays inconsistent data and provides a quick correction path.

* Convenient migration to OceanBase

  The service is fully adapted to the features of various OceanBase AI Database versions, intelligently processes the collection and conversion of database objects, and supports migration without service interruption at the source.

## Application scenarios

This topic describes the enterprise-level database migration and data synchronization scenarios of OceanBase Migration Service (OMS).

### In-service data migration

![image.png](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.1/700.reference/1400.oceanbase-tools/continuous-service-migration.jpg)

In traditional database migration solutions, data is usually migrated during downtime to ensure migration stability and data consistency. During the downtime, data writes to the source database must be temporarily stopped. The business database can be switched only after the migration is completed and data consistency is verified.

The downtime duration varies according to the business data volume and network conditions. In case of a massive volume of business data, the downtime may last several days, greatly affecting the business.

OMS supports in-service data migration, ensuring service continuity of the source database during the migration and minimizing the impact of data migration on the business. After schema migration, full data migration, and incremental data migration are completed, all full and incremental data in the source database has been synchronized to the target database in real time. After data verification succeeds, the business can be switched from the source to the target.

### Real-time data synchronization

OMS can synchronize incremental data from databases such as OceanBase to self-managed message queues such as Kafka or RocketMQ in real time. This improves message processing capabilities and extends business applications in big data fields such as monitoring data aggregation, stream data processing, and online and offline analytics.

OMS enables real-time data synchronization between physical tables of OceanBase Database and self-managed data sources such as Kafka. You can use OMS in various business scenarios such as cloud BI, real-time data warehouse construction, data querying, and report distribution.

### High availability and flexible deployment

* The Store and Incr-Sync components support high availability on individual nodes. When the Store or Incr-Sync component fails, the corresponding abnormal process is restarted.

  ![HA1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.1/700.reference/1400.oceanbase-tools/HA1.png)

* IDC-level disaster recovery is supported.

  ![HA2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.1/700.reference/1400.oceanbase-tools/HA2.png)

  * When a server fails, all components on the server are migrated to an appropriate server.

  * When the resource metrics of a server are abnormal, some components are load-balanced.

  * When a Store fails, OMS tries to restart it if server resources are sufficient. If resources are insufficient, OMS performs load balancing or deletes redundant Stores.

  * When Incr-Sync fails, the abnormal process is restarted.

* Regional IDC-level disaster recovery is supported.

  OMS supports separate deployment of incremental log reading and incremental synchronous writing. By using optimization methods such as parallel transmission over multiple Transmission Control Protocol (TCP) connections, data compression, and data encryption, OMS overcomes challenges such as long distances, poor network conditions, and data security. Cross-region scheduling is not supported.

  ![HA3](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.1/700.reference/1400.oceanbase-tools/HA3.png)

## Product features

OMS supports data migration and data synchronization features:

* Data migration: Data migration is a one-time task. After migration is completed, project resources can be released. You can use data migration to migrate data between homogeneous or heterogeneous data sources, which is suitable for business scenarios such as database upgrades, cross-instance data migration, database splitting, and scaling.

  A data migration project is the basic unit of the data migration feature of OMS. When you create a migration project, you can specify a maximum migration scope of database level and a minimum migration scope of table level. For more information about supported project types and migration types, see the documentation in the Data Migration module.

* Data synchronization: Data synchronization is a continuous operation. After a project is created, data is continuously synchronized to ensure consistency between the source and target databases and enable real-time data flow for critical business systems. You can use data synchronization to synchronize data between data sources in real time, which is suitable for business scenarios such as multi-active data distribution, remote disaster recovery, data aggregation, and real-time data warehouses.
