# 9000 ~ 9499

This range indicates backup and restore error codes and STORAGE 3.0 error codes.

## ERROR 9001 (HY000) : URI error

* OceanBase error code: 9001

* Cause: The destination link specified in the backup and restore settings may be incorrect.

* Solution: Check the backup and restore configurations and modify them as needed.

## ERROR 9004 (HY000) : Init MD5 fail

* OceanBase error code: 9004

* Cause: An OpenSSL initialization MD5 error occurred.

* Solution: Contact OceanBase Technical Support for assistance.

## ERROR 9005 (HY000) : Out of element

* OceanBase error code: 9005

* Cause: The limit on shards has been exceeded.

* Solution: Contact OceanBase Technical Support for assistance.

## ERROR 9006 (HY000) : Update MD5 fail

* OceanBase error code: 9006

* Cause: MD5 update failed.

* Solution: Contact OceanBase Technical Support for assistance.

## ERROR 9011 (HY000) : cannot find backup file

* OceanBase error code: 9011

* Cause: The backup file could not be found. The specified backup and restore configuration may be incorrect.

* Solution: Check the backup and restore configurations and modify them as needed.

## ERROR 9012 (HY000) : Can not get data version from timestamp

* OceanBase error code: 9012

* Cause: The `data version` parameter was not passed in the logical restore parameters.

* Solution: Contact OceanBase Technical Support for assistance.

## ERROR 9014 (HY000) : Another restore is in progress

* OceanBase error code: 9014

* Cause: A tenant with the same name already exists for the tenant to be restored.

* Solution: Check whether the username of the tenant to be restored is duplicated. If so, use a unique tenant name.

## ERROR 9016 (HY000) : ob cluster name not equal

* OceanBase error code: 9144

* Cause: An unexpected file appeared in the macroblock cache directory, possibly a file created by the user.

* Solution: Contact OceanBase Technical Support for assistance.

## ERROR 9147 (HY000) : can not access backup set file

* OceanBase error code: 9147

* Cause: During physical restore execution, the OBServer node cannot access the backup set file in the specified backup medium.

* Solution: Check the connectivity of object storage. After confirming no connectivity issues, contact Technical Support for assistance.

## ERROR 9148 (HY000) : disk quota is exceeded

* OceanBase error code: 9148

* Cause: The disk quota has been exceeded.

* Solution: Clean up files or adjust the disk quota.

## ERROR 9149 (HY000) : backup dest is not allowed to set when log_only policy exists

* OceanBase error code: 9149

* Cause: The `log_only` cleanup policy applies only to scenarios where only log archiving is enabled and no data backup is performed. When a `log_only` cleanup policy exists, configuring a data backup path is not allowed.

* Solution: First, delete the `log_only` cleanup policy, then configure the data backup path.

## ERROR 9150 (HY000) : log_only policy is not allowed to set when backup dest exists

* OceanBase error code: 9150

* Cause: The `log_only` cleanup policy applies only to scenarios where only log archiving is enabled and no data backup is performed. In scenarios where a data backup path is already configured, the cleanup policy cannot be set to `log_only`.

* Solution: To use the `log_only` cleanup policy, you must first delete the configured data backup path.

## ERROR 9151 (HY000) : backup clean can not start, because %s

* OceanBase error code: 9151

* Cause: Data backup and archiving cleanup cannot proceed. Possible reasons include the tenant's status being non-`NORMAL` (for example, `CREATING`, `RESTORE`, etc.) or the tenant not having a cleanup policy configured (for expiration cleanup scenarios).

* Solution: Check the tenant status. For expiration cleanup scenarios, confirm whether the relevant tenant has a cleanup policy correctly configured.

## ERROR 9152 (HY000) : backup device may be not mounted, %s did not read any data written by %s

* OceanBase error code: 9152

* Cause: The backup medium is not properly mounted.

* Solution: Mount the backup medium correctly to ensure all OBServer nodes of the tenant initiating the archiving/backup/restoration operation can access the same backup medium. 

## ERROR 9153 (HY000) : backup device is not read and write strongly consistent. %s did not read the latest data written by %s.

* OceanBase error code: 9153

* Cause: The read and write operations on the backup medium are not strongly consistent.

* Solution: If the backup medium is NFS, refer to the deployment instructions for mounting it in the specified manner; if the backup medium is object storage, contact the corresponding service provider.

## ERROR 9155 (HY000) : micro block is too large and rejected from micro cache

* OceanBase error code: 9155

* Cause: The size of the microblock to be cached exceeds the upper limit allowed by the microblock cache (default: 128 KB), and the system refuses to write this microblock to the microblock cache.

* Solution: This error is a normal internal stream control behavior of the system, which does not affect data correctness or business availability. Generally, no action is required. If it occurs frequently and significantly impacts read performance, contact technical support for assistance.

## ERROR 9156 (HY000) : ss ls is in gc status

* OceanBase error code: 9156

* Cause: The log stream is in GC status and no longer accepts new write or operation requests.

* Solution: Retry may succeed. If failures persist, contact OceanBase technical support for assistance.

## ERROR 9158 (HY000) : the object type is invalid

## ERROR 9159 (HY000) : available data backup set is not found

* OceanBase error code: 9159

* Cause: No backup set is available to restore to the specified time.

## ERROR 9200 (HY000) : Extend ssblock file to smaller is not allowed

## ERROR 9201 (HY000) : Mark blocks timeout(5s) in auto extend process when alloc block fail

* OceanBase error code: 9201

## ERROR 9202 (HY000) : Auto extend param is not ready to start extending file

* OceanBase error code: 9202

* Cause: Automatic extension may not have started due to configuration issues, or the preset disk usage of `datafile` has reached its limit.

* Solution: Check if the `free_size` field in the `__all_virtual_disk_stat` table is 0. If it is, disk space is exhausted. You need to increase the `datafile` threshold or perform disk expansion.
