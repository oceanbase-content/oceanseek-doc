# Common wait events

## Introduction to Waiting Events

Information about wait events is displayed in the following three dynamic performance views:

* `V$SESSION_WAIT`: Displays the events that a session has just finished waiting for or is currently waiting for.
* `V$SYSTEM_EVENT`: Displays the total number of all pending events in the current tenant.
* `V$SESSION_EVENT`: Similar to `V$SYSTEM_EVENT`, but displays all wait events for each session.

Many wait events are related to internal implementations and may be subject to changes or removals. Please refer to the actual situation.

## Event types

Every wait event belongs to a category. Wait events are mainly classified into the following types:

| Type of the event to be waited for | Wait Category Number ID | Description |
| ------------------- | -------------- | --------------------------------------------- |
| OTHER | 100 | Waiting Events Not Belonging to Other Types |
| APPLICATION | 101 | Wait Events Caused by Client Code |
| CONFIGURATION | 102 | Waiting Events Caused by Insufficient Database or Instance Resource Configuration |
| ADMINISTRATIVE | 103 | Wait Events Caused by Database Administrators' Command Input |
| CONCURRENCY | 104 | Wait events for internal database resources |
| COMMIT | 105 | Waiting Events Related to Log Commit |
| IDLE | 106 | A wait event that the session is in an inactive state and waiting for a task. |
| NETWORK | 107 | Network Communication-Related Waiting Events |
| USER_IO | 108 | I/O Wait Events |
| SYSTEM_IO | 109 | Waiting for I/O of Background Process Event |
| CLUSTER | 111 | Cluster-related wait events |

## View Waiting Events

You can execute an SQL statement in the sys tenant to display all wait events in alphabetical order along with their corresponding wait event types. Example:

```sql
obclient> SELECT name, wait_class FROM V$EVENT_NAME ORDER BY name;
```
