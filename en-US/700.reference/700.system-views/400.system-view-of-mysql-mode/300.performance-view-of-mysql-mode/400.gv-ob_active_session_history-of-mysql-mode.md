# GV$OB_ACTIVE_SESSION_HISTORY

## Overview

The `GV$OB_ACTIVE_SESSION_HISTORY` view displays the history of active sessions on all OBServer nodes in the current tenant.

## Columns

| **Column** | **Type** | **Is NULL** | **Description** |
| --- | --- | --- | --- |
| SVR_IP | varchar(46) | NO | IP address of the server to which the sample belongs. |
| SVR_PORT | bigint(20) | NO | Port number of the server to which the sample belongs. |
| SAMPLE_ID | bigint(20) | NO | Unique ID of the sample host. |
| SAMPLE_TIME | timestamp(6) | NO | Sampling time. |
| CON_ID | bigint(20) | NO | Tenant ID. |
| USER_ID | bigint(20) | NO | The user ID of the sampled session. |
| SESSION_ID | bigint(20) | NO | The ID of the sampled session. <ul><li>In direct connection mode:<br>This field indicates the server session ID.</li> <li>In ODP mode:</li><ul><li>When the ODP parameter <code>client_session_id_version = 2</code> is set, this field indicates the client session ID. </li> <li>When <code>client_session_id_version = 1</code> is set, this field indicates the server session ID.</li></ul></ul> |
| SESSION_TYPE | varchar(10) | NO | Session type. Valid values: <ul><li>FOREGROUND: foreground session, that is, a user session.  </li><li>BACKGROUND: background session. </li></ul> |
| SESSION_STATE | varchar(7) | NO | Session status: <ul><li>ON CPU: The session is currently not waiting and is executing SQL logic.  </li><li>WAITING: The session is currently waiting. For details, see the EVENT field. </li></ul> |
| SQL_ID | varchar(32) | NO | SQL ID. |
| PLAN_ID | bigint(20) | NO | The plan ID of the sampled SQL statement in the PLAN CACHE, used to associate the sampling point with the plan. |
| TRACE_ID | varchar(64) | NO | The trace ID of the operator. |
| EVENT | varchar(64) | NO | The description of the event being waited for. |
| EVENT_NO | bigint(20) | NO | Internal event ID, used to associate queries with other tables. |
| EVENT_ID | bigint(20) | YES | The ID of the event currently being waited for. |
| P1TEXT | varchar(64) | NO | The name of parameter 1 for the WAIT EVENT statement. This name varies depending on the event. |
| P1 | bigint(20) | NO | Value of parameter 1 for the wait event. |
| P2TEXT | varchar(64) | NO | The name of parameter 2 for the WAIT EVENT. This name varies depending on the event. |
| P2 | bigint(20) | NO | The value of parameter 2 for the WAIT FOR EVENT. |
| P3TEXT | varchar(64) | NO | The name of parameter 3 for the wait event. This name varies depending on the event. |
| P3 | bigint(20) | NO | The value of parameter 3 for the wait event. |
| WAIT_CLASS | varchar(64) | NO | Type of the event being waited for. |
| WAIT_CLASS_ID | bigint(20) | NO | The ID of the event type to wait for, used to associate queries with other tables. |
| TIME_WAITED | bigint(20) | NO | The total wait time for this event, in microseconds (us). |
| SQL_PLAN_LINE_ID | bigint(20) | YES | The number of the SQL operator in the SQL plan during sampling. |
| GROUP_ID | bigint(20) | YES | The ID of the resource group to which the instance belongs. |
| PLAN_HASH | bigint(20) unsigned | YES | The current execution SQL command's plan hash. |
| THREAD_ID | bigint(20) | YES | Thread ID of the current active session. |
| STMT_TYPE | bigint(20) | YES | SQL type of the current active session. |
| TIME_MODEL | bigint(20) | NO | Time model information is a collection of data from all IN_XXX fields, such as IN_PARSE and IN_PL_PARSE. |
| IN_PARSE | varchar(1) | NO | Whether the session is performing SQL parse during sampling. |
| IN_PL_PARSE | varchar(1) | NO | Whether SQL PL parsing is in progress for the session during sampling. |
| IN_PLAN_CACHE | varchar(1) | NO | Whether the session is performing plan cache matching during sampling. |
| IN_SQL_OPTIMIZE | varchar(1) | NO | Whether the session is performing SQL parsing optimization during sampling. |
| IN_SQL_EXECUTION | varchar(1) | NO | Whether the session is performing SQL execution during sampling. |
| IN_PX_EXECUTION | varchar(1) | NO | Whether the session is performing SQL parallel execution during sampling. When a session is in this state, it must also be in the IN_SQL_EXECUTION state. |
| IN_SEQUENCE_LOAD | varchar(1) | NO | Whether the session is fetching values from an auto-increment column or a sequence during sampling. |
| IN_COMMITTING | varchar(1) | NO | Whether the current sampling point is in the transaction commit phase. |
| IN_STORAGE_READ | varchar(1) | NO | Whether the current sampling point is in the read phase. |
| IN_STORAGE_WRITE | varchar(1) | NO | Whether the current sampling point is in the storage write phase. |
| IN_REMOTE_DAS_EXECUTION | varchar(1) | NO | Whether the current sampling point is in the DAS remote execution phase. |
| IN_FILTER_ROWS | varchar(1) | NO | Indicates whether the current sampling point is in the store pushdown execution phase. |
| IN_RPC_ENCODE | varchar(1) | NO | The serialization operation currently in progress for the SQL statement. |
| IN_RPC_DECODE | varchar(1) | NO | The deserialization operation currently being performed by the SQL statement. |
| IN_CONNECTION_MGR | varchar(1) | NO | The current SQL statement is performing a link creation operation. |
| PROGRAM | varchar(64) | YES | Program name being executed at the current sampling point: <ul><li>Background thread: refers to the thread name, for example, `observer`, `WrTimer`</li><li>Frontend threads: <ul><li>For regular requests, it is `user@client_ip (thread_name)`  </li><li>`inner_sql` Remote execution is `INNER SQL REMOTE EXEC (thread_name)`</li><li>For DAS remote execution, it is `DAS REMOTE EXEC (thread_name)` </li></ul> </li></ul> |
| MODULE | varchar(64) | YES | The MODULE value recorded during session sampling. It is obtained through `DBMS_APPLICATION_INFO.SET_MODULE` Package settings. |
| ACTION | varchar(64) | YES | The ACTION value recorded during sampling for a session, through `DBMS_APPLICATION_INFO.SET_ACTION` Package settings. |
| CLIENT_ID | varchar(64) | YES | The CLIENT_ID value recorded during session sampling. `DBMS_SESSION.set_identifier` Package settings. |
| BACKTRACE | varchar(512) | YES | Auxiliary debugging field, used to record the code call stack at the time the event occurred. The value of this field is always NULL. |
| TM_DELTA_TIME | bigint(20) | YES | Calculate the time interval of the time model, in microseconds. |
| TM_DELTA_CPU_TIME | bigint(20) | YES | Past `TM_DELTA_TIME` The amount of time spent on the CPU during the period. |
| TM_DELTA_DB_TIME | bigint(20) | YES | Past `TM_DELTA_TIME` The amount of time spent on database calls within the time period. |
| TOP_LEVEL_SQL_ID | varchar(32) | YES | Top-level SQL ID. |
| IN_PLSQL_COMPILATION | varchar(1) | NO | Current PL Compilation Status: Y/N |
| IN_PLSQL_EXECUTION | varchar(1) | NO | Current PL Execution Status: Y/N |
| PLSQL_ENTRY_OBJECT_ID | bigint(20) | YES | OBJECT ID of the top-level PL. |
| PLSQL_ENTRY_SUBPROGRAM_ID | bigint(20) | YES | Sub-project ID of the top-level PL. |
| PLSQL_ENTRY_SUBPROGRAM_NAME | varchar(32) | YES | Sub-project name of the top-level PL. |
| PLSQL_OBJECT_ID | bigint(20) | YES | The ID of the PL object currently being executed. |
| PLSQL_SUBPROGRAM_ID | bigint(20) | YES | The ID of the PL subprogram currently being executed. |
| PLSQL_SUBPROGRAM_NAME | varchar(32) | YES | The name of the currently executing PL subprogram. |
| TX_ID | bigint(20) | YES | Current Transaction ID |
| BLOCKING_SESSION_ID | bigint(20) | YES | If the current session is blocked, displays the session ID that blocked it. This feature currently takes effect only in lock conflict scenarios, showing the session IDs of the holding locks. |
| TABLET_ID | bigint(20) | YES | ID of the tablet being processed by the current SQL statement |
| PROXY_SID | bigint(20) | YES | Proxy Session ID |
| DELTA_READ_IO_REQUESTS | bigint(20) | NO | The number of reads performed between two samples. |
| DELTA_READ_IO_BYTES | bigint(20) | NO | The cumulative size of files read between the two samples. |
| DELTA_WRITE_IO_REQUESTS | bigint(20) | NO | The number of writes between two samples. |
| DELTA_WRITE_IO_BYTES | bigint(20) | NO | The cumulative size of files written between the two samples. |

## Sample query

View the active session history of all OBServer nodes in the current tenant.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.GV$OB_ACTIVE_SESSION_HISTORY LIMIT 1\G
```
