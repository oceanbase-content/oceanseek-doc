# V$OB_LS_LOG_RESTORE_STATUS

## Overview

Displays the log restoration status of log streams in the current tenant.

## Columns

| **Column** | **Type** | **Is NULL** | **Description** |
| --- | --- | --- | --- |
| TENANT_ID | bigint(20) | NO | Tenant ID |
| LS_ID | bigint(20) | NO | Log Stream ID |
| SYNC_LSN | bigint(20) unsigned | NO | Maximum Consecutive Majority LSN/Maximum Consumable LSN of Standby Database |
| SYNC_SCN | bigint(20) unsigned | NO | Maximum Consecutive Majority LSN/Maximum Consumable SCN of Standby Database |
| SYNC_STATUS | varchar(128) | NO | Log stream restore status. <ul><li>NORMAL: Normal synchronization.  </li><li>SOURCE HAS A GAP: There is a log gap at the log source. </li><li>STANDBY LOG NOT MATCH: The restored logs conflict with those in the standby database. Logs at the same LSN in the standby database are different from those at the log source.  </li><li>CHECK USER OR PASSWORD: The username or password of the replication account is incorrect, and the log source cannot be accessed. </li><li>CHECK NETWORK: The log source is unreachable, including incorrect tenant access entry IP or PORT settings. </li><li>FETCH LOG TIMEOUT: Log fetch timed out.  </li><li>RESTORE SUSPEND: Log restore has reached the set maximum synchronization point. </li><li>STANDBY NEED UPGRADE: The standby database version lags behind the primary database version; the standby database version needs to be updated. </li><li>CHECK PRIMARY ALIVE: The primary database cannot be accessed. Check if the primary database has been deleted. </li><li> NOT AVAILABLE: Log synchronization is unavailable due to other exceptions. </li></ul> |
| ERR_CODE | bigint(20) | NO | Error code. During normal synchronization, this error code is 0. |
| COMMENT | varchar(2048) | NO | Error details. This column is empty during normal synchronization. |

## Sample query

You can query the recovery status of log streams in the current tenant.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$OB_LS_LOG_RESTORE_STATUS;
```
