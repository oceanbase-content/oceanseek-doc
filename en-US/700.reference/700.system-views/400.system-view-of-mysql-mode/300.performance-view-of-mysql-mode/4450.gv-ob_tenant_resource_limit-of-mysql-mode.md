# GV$OB_TENANT_RESOURCE_LIMIT

## Overview

The `GV$OB_TENANT_RESOURCE_LIMIT` view displays the logical resource usage, upper limit, effective constraints, and maximum usage after a crash restart for the current tenant across all OBServer nodes.

## Columns

| Field Name | Type | Whether can be NULL | Description |
| ---------- | -------- | ----------------- | ------------- |
| SVR_IP | varchar(46) | NO | IP Address of OBServer |
| SVR_PORT | bigint(20) | NO | RPC Port of OBServer |
| TENANT_ID | bigint(20) | NO | Tenant ID |
| ZONE | varchar(128) | NO | Name of the zone |
| RESOURCE_NAME | varchar(128) | NO | Resource Name |
| CURRENT_UTILIZATION | bigint(20) | NO | Current Resource Usage |
| MAX_UTILIZATION | bigint(20) | NO | Maximum resource usage after the server starts |
| RESERVED_VALUE | bigint(20) | NO | The amount of memory pre-allocated, which is the most fundamental guarantee for stable operation. |
| LIMIT_VALUE | bigint(20) | NO | Maximum Allowable Usage |
| EFFECTIVE_LIMIT_TYPE | varchar(128) | NO | Effective limit type, such as parameter, memory, CPU, disk, and so on. |

## Sample query

Query the logical resource usage, upper limit, effective constraints, and maximum usage after a crash restart for the current tenant across all OBServer nodes.

```shell
obclient[oceanbase]> SELECT * FROM oceanbase.GV$OB_TENANT_RESOURCE_LIMIT;
```
