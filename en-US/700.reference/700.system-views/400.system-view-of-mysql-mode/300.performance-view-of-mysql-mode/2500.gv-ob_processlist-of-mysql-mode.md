# GV$OB_PROCESSLIST

## Overview

The `GV$OB_PROCESSLIST` view displays session information on all OBServer nodes of a tenant.

## Columns

| Field Name | Type | Whether can be NULL | Description |
| ---------------- | --------------------- | ------------ | -------------------------------------------------------------- |
| SVR_IP | varchar(46) | NO | Server IP Address |
| SVR_PORT | bigint(20) | NO | Server Port Number |
| SQL_PORT | bigint(20) | NO | SQL Port Number |
| ID | bigint(20) unsigned | NO | Session ID<ul><li>In direct connection mode:<br>This field indicates the server session ID.</li> <li>In ODP mode:</li><ul><li>When the ODP parameter <code>client_session_id_version = 2</code> is set, this field indicates the client session ID. </li> <li>When <code>client_session_id_version = 1</code> is set, this field indicates the server session ID.</li></ul></ul> |
| USER | varchar(32) | NO | Username |
| HOST | varchar(128) | NO | Client IP:PORT |
| DB | varchar(128) | YES | Name of the accessed database |
| TENANT | varchar(128) | NO | Tenant Name |
| COMMAND | varchar(4096) | NO | Type of the command being executed |
| TIME | bigint(20) | NO | The current command execution time, in seconds. If the command is retried, it will be reset and recalculated. |
| TOTAL_TIME | bigint(20) | NO | Total execution time of the current command, in seconds. This value is not cleared if the command is retried. |
| STATE | varchar(128) | YES | Current Session Status |
| INFO | varchar(262143) | YES | Displays the currently executing command |
| PROXY_SESSID | bigint(20) unsigned | YES | If the client is OBProxy, this column displays the proxy session ID. |
| MASTER_SESSID | bigint(20) unsigned | YES | Primary session ID, used to concatenate multiple sub-sessions of the same SQL statement |
| USER_CLIENT_IP | varchar(46) | YES | User Client IP |
| USER_HOST | varchar(128) | YES | User Client Host Name |
| RETRY_CNT | bigint(20) | NO | Number of Retries for the Current Command |
| RETRY_INFO | bigint(20) | NO | Retry information for the current command, typically the error code from the last retry. |
| SQL_ID | varchar(32) | NO | SQL ID Information |
| TRANS_ID | bigint(20) unsigned | NO | Transaction ID |
| THREAD_ID | bigint(20) unsigned | NO | Thread ID |
| SSL_CIPHER | varchar(4096) | YES | Encrypted Password Name |
| TRACE_ID | varchar(64) | YES | Trace ID |
| TRANS_STATE | varchar(32) | YES | Transaction status. If no transaction exists in the session, this field is empty. <ul><li>`IDLE`: Idle, indicating that the transaction has not started. </li> <li>`ACTIVE`: The transaction is explicitly started. Use `START TRANSACTION`, `BEGIN` and other statements are explicitly enabled. </li> <li>`IMPLICIT_ACTIVE`: The transaction is implicitly started. `autocommit = on` In this mode, a transaction is started after executing data-modifying statements such as DML. </li> <li>`ROLLBACK_SAVEPOINT`: The transaction is rolling back to a savepoint. </li> <li>`IN_TERMINATE`: The transaction is being terminated, including termination due to internal reasons and user-initiated transaction termination (for example, executing the `COMMIT`, `ROLLBACK` statements). </li> <li>`ABORTED`: The transaction is internally terminated or rolled back due to an exception. </li> <li>`ROLLED_BACK`: The transaction has been rolled back. </li> <li>`COMMIT_TIMEOUT`: Transaction commit timeout.</li> <li>`COMMIT_UNKNOWN`: The transaction commit result is unknown.</li> <li>`COMMITTED`: The transaction has been successfully committed. </li></ul> |
| ACTION | varchar(4096) | YES | The name of the current operation, set by calling the DBMS_APPLICATION_INFO.SET_ACTION procedure. |
| MODULE | varchar(4096) | YES | The name of the current operation, set by calling the DBMS_APPLICATION_INFO.SET_MODULE procedure. |
| CLIENT_INFO | varchar(4096) | YES | Information set by the DBMS_APPLICATION_INFO.SET_CLIENT_INFO procedure |
| LEVEL | bigint(20) | NO | Indicates the end-to-end tracing monitoring level for the session. For example, 1 indicates diagnostic information at level 1. |
| SAMPLE_PERCENTAGE | bigint(20) | NO | Indicates the sampling frequency for end-to-end tracing of the session. For example, 50 means diagnostic information is sampled at a frequency of 50%. |
| RECORD_POLICY | varchar(32) | NO | Specifies the tracing record strategy for the entire session. The following three strategies are supported:<ul><li>ALL: All trace information collected by sampling is printed to the log file. This happens at the end of each span. </li><li>ONLY_SLOW_QUERY: Only trace information belonging to slow queries is printed to the log file. For other traces, the trace information is discarded. In this printing strategy, trace logs are printed after the request is identified as a slow query. For root spans (that is, transaction-level spans) in the proxy, the root span is printed only when a slow query is detected. </li><li>SAMPLE_AND_SLOW_QUERY: In all trace information collected by sampling, traces that meet the following conditions are printed to the log file:<ol><li>Probability sampling is performed at a rate of one in ten thousand using the hidden parameter <code>_print_sample_ppm</code>. A trace is printed to the log only if it is selected in the sampling.</li><li>The trace meets the printing conditions in ONLY_SLOW_QUERY mode.</li></ol>In this mode, trace logs are not printed at the end of a span. If condition 1 is met, the trace log is marked as mandatory to be printed on the client side, and this information is passed to subsequent link components. If condition 2 is met, the printing timing is the same as that in ONLY_SLOW_QUERY mode.</li></ul> |
| LB_VID | bigint(20) | YES | If the database is directly connected through a load balancer in a public cloud environment, this column displays the VPC ID of the load balancing service. Otherwise, it displays NULL. |
| LB_VIP | varchar(46) | YES | If you are directly connecting to the database through a load balancer in a public cloud environment, this column displays the IP address of the client that connects to the load balancing service. Otherwise, it displays NULL. |
| LB_VPORT | bigint(20) | YES | For connections to databases through load balancing in a public cloud environment, this column displays the port used by the client to connect to the load balancing service. Otherwise, it displays NULL. |
| IN_BYTES | bigint(20) | NO | Indicates the inbound traffic of the session, in bytes. |
| OUT_BYTES | bigint(20) | NO | Indicates the outbound traffic of the session, in bytes. |
| USER_CLIENT_PORT | bigint(20) | NO | Client Address Information |
| PROXY_USER | varchar(128) | YES | <ul><li>For proxy user login scenarios, returns the name of the proxy user.</li><li>For non-proxy user login scenarios, displays as empty.</li></ul> |
| SERVICE_NAME | varchar(64) | YES | The service name that created the session. Value: `NULL` Indicates that the session was not created by a service name. |
| TOTAL_CPU_TIME | bigint(21) | NO | The CPU time consumed by the current command, in seconds. |
| TOP_INFO | varchar(262143) | YES | Displays the top-level PL statement information where the SQL statement being executed resides. |
| MEMORY_USAGE | bigint(20) | YES | The memory size currently occupied by a single SQL statement, in bytes. |
