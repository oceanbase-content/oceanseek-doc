# information_schema.role_table_grants

## Overview

The `role_table_grants` view displays the table-level privileges granted to the user in the current session by the activated roles, as well as the table-level privileges granted to these roles by other roles.

## Columns

| **Field** | **Type** | **Nullable** | **Description** |
| ---------------- | -------------- | ---------------------- | ----------------- |
| GRANTOR | varchar(97) | YES | The username part of the account authorized with this role. |
| GRANTOR_HOST | varchar(256) | YES | The host part of the account being granted the role. |
| GRANTEE | varchar(32) | NO | The username part of the account corresponding to this role. |
| GRANTEE_HOST | varchar(255) | NO | The hostname part of the account corresponding to this role. |
| TABLE_CATALOG | varchar(3) | NO | The name of the directory authorized to this role. This value is always 'def'. |
| TABLE_SCHEMA | varchar(64) | NO | The name of the database to which the table authorized for this role belongs. |
| TABLE_NAME | varchar(64) | NO | The name of the table to which this role has been granted access. |
| PRIVILEGE_TYPE | varchar(90) | NO | The privilege granted. This can be any privilege that can be granted at the table level. |
| IS_GRANTABLE | varchar(3) | NO | Whether the privileges of this role can be granted to other users. |

## Sample query

1. Create a role and a table.

   ```shell
   obclient [test]> CREATE ROLE employee;
   ```

   ```shell
   obclient [test]> CREATE TABLE tbl1(c1 int, c2 int, c3 int);
   ```

2. Grant table-level privileges on the table to the role.

   ```shell
   obclient [test]> GRANT DROP,UPDATE,SELECT ON test.tbl1 TO employee WITH GRANT OPTION;
   ```

3. Grant the role to the user.

   ```shell
   obclient [test]> GRANT employee TO user1;
   ```

4. Connect to the database as user `user1`.

5. Activate the `employee` role in the current session.

   ```shell
   obclient [test]> SET ROLE employee;
   ```

6. View the table-level privileges of activated roles granted to the user in the current session.

   ```shell
   obclient [test]> USE information_schema;
   ```

   ```shell
   obclient [test]> SELECT * FROM information_schema.role_table_grants;
   ```

   The query result is as follows:

   ```shell
   +---------+--------------+-----------+--------------+---------------+--------------+------------+--------------------+--------------+
   | GRANTOR | GRANTOR_HOST | GRANTEE   | GRANTEE_HOST | TABLE_CATALOG | TABLE_SCHEMA | TABLE_NAME | PRIVILEGE_TYPE     | IS_GRANTABLE |
   +---------+--------------+-----------+--------------+---------------+--------------+------------+--------------------+--------------+
   | root    | %            | employee  | %            | def           | test         | tbl1       | Drop,Update,Select | YES          |
   +---------+--------------+-----------+--------------+---------------+--------------+------------+--------------------+--------------+
   1 row in set
   ```
