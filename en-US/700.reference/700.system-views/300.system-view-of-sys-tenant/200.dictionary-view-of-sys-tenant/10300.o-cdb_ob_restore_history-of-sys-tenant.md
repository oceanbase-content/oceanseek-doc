# oceanbase.CDB_OB_RESTORE_HISTORY

## Overview

Displays the status of a physical restore task when it is completed. It is a snapshot of the corresponding record in the `oceanbase.CDB_OB_RESTORE_PROGRESS` table at the end of the restore task.

## Columns

| **Field** | **Type** | **Nullable** | **Description** |
| --------------------------- | --------------- | ---------------- | ------------------------------------------------------------------- |
| TENANT_ID | bigint(20) | NO | Tenant ID for the restore task |
| JOB_ID | bigint(20) | NO | Recovery Job ID, corresponding to a single recovery task |
| RESTORE_TENANT_NAME | varchar(128) | NO | Name of the restored tenant |
| RESTORE_TENANT_ID | bigint(20) | NO | Recovered Tenant ID |
| BACKUP_TENANT_NAME | varchar(128) | NO | Name of the source tenant for backup |
| BACKUP_TENANT_ID | bigint(20) | NO | Source Tenant ID for Backup |
| BACKUP_CLUSTER_NAME | varchar(128) | NO | Source cluster name for backup |
| BACKUP_DEST | longtext | NO | Backup set path, which refers to the data backup path and log archive path entered by the user. |
| RESTORE_SCN | bigint(20) unsigned | NO | User-specified restore point |
| RESTORE_SCN_DISPLAY | varchar(26) | NO | The timestamp of the user-specified restore point is represented as |
| RESTORE_OPTION | varchar(4096) | NO | The restore options specified by the user when initiating the restore. `restore_option` |
| RESTORE_TYPE | varchar(4096) | NO | The recovery type. <ul> <li>`FULL`: indicates full restore.</li> <li>`QUICK`: indicates quick recovery.</li></ul> |
| START_TIMESTAMP | timestamp(6) | YES | Restored Task Start Timestamp |
| FINISH_TIMESTAMP | timestamp(6) | YES | Restored Task End Timestamp |
| STATUS | varchar(64) | NO | Recovery result: <ul> <li>`SUCCESS`: indicates a successful restore. </li> <li>`FAILED`: indicates the restore failed. </li></ul> |
| BACKUP_PIECE_LIST | longtext | NO | List of log archive shard paths for recovery. Separate shards with commas. `,` Separate them with commas. For example: `file:///data/nfs/backup/archive/2_1_2,file:///data/nfs/backup/archive/2_1_3` |
| BACKUP_SET_LIST | longtext | NO | List of restore-dependent data backup sets, separated by `,` Separate them with commas, for example: `file:///data/nfs/backup/data/backup_set_1_full,file:///data/nfs/backup/data/backup_set_2_inc` |
| BACKUP_CLUSTER_VERSION | bigint(20) | NO | Version of the source cluster to be backed up |
| LS_COUNT | bigint(20) | NO | Total restored log streams |
| FINISH_LS_COUNT | bigint(20) | NO | Number of Log Streams Restored |
| TABLET_COUNT | bigint(20) | NO | Total Number of Restored Shards |
| FINISH_TABLET_COUNT | bigint(20) | NO | Number of Restored Shards |
| TOTAL_BYTES | bigint(20) | NO | Total Bytes Restored |
| TOTAL_BYTES_DISPLAY | varchar(27) | NO | Total bytes restored, displayed in storage capacity units |
| FINISH_BYTES | bigint(20) | NO | Number of bytes restored |
| FINISH_BYTES_DISPLAY | varchar(27) | NO | Number of bytes restored, in storage capacity units |
| DESCRIPTION | varchar(1024) | YES | Specified in the restore command `DESCRIPTION` Information |
| COMMENT | varchar(1024) | YES | Record failure information when recovery fails |

## Sample query

The system tenant is used to view the status of a restore task when it is completed.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.CDB_OB_RESTORE_HISTORY\G
```
