# V$OB_SQL_WORKAREA_MEMORY_INFO

## Overview

This view displays general information about the SQL workarea on the current OBServer node, including the maximum available memory, current memory usage, and currently held memory. It helps you understand the workarea usage of the current tenant, such as memory utilization.

## Columns

| **Field** | **Type** | **Nullable** | **Description** |
| ------------------------ | ------------ | ---------------- | ----------------------------------------------------- |
| MAX_WORKAREA_SIZE | bigint(20) | NO | Maximum workarea memory. The amount of memory available is determined by the parameter, in bytes. |
| WORKAREA_HOLD_SIZE | bigint(20) | NO | The current memory size held by the workarea, in bytes.  <main id="notice" type='explain'><h4>Note</h4><p>The specific usage amount cannot be obtained from the memory management module, so only the hold value can be retrieved.</p></main> |
| MAX_AUTO_WORKAREA_SIZE | bigint(20) | NO | When set to `auto`, the expected maximum available memory size, in bytes. You can simply consider that the maximum available memory is calculated using the formula: `max_work_area_size - hold + total_mem_used` Calculated based on the current workarea conditions, indicating the maximum memory size that can be automatically managed. |
| MEM_TARGET | bigint(20) | NO | The target size of memory available for the current work area, in bytes. The difference between this value and `max_auto_work_area` is that this value is a certain percentage of `max_auto_work_area`. |
| TOTAL_MEM_USED | bigint(20) | NO | The current automatic memory usage, in bytes. This value is reported by the SQL automatic memory management module and does not represent the actual memory usage. |
| GLOBAL_MEM_BOUND | bigint(20) | NO | The maximum size of available memory in auto mode, in bytes. |
| DRIFT_SIZE | bigint(20) | NO | The change in memory required for the current demand, in bytes. It is primarily used to track fluctuations. When the fluctuation reaches a certain range, it automatically triggers a recalculation of the global bound size. |
| WORKAREA_COUNT | bigint(20) | NO | Number of Registered Operator Profiles |
| MANUAL_CALC_COUNT | bigint(20) | NO | Number of Times Calculating Global Bound Size Without Scheduled Trigger |
| TENANT_ID | bigint(20) | NO | Tenant ID |
| SVR_IP | varchar(46) | NO | Server IP Address |
| SVR_PORT | bigint(20) | NO | Server Port Number |

## Sample query

Query the SQL workarea information of all tenants on the current OBServer node in the sys tenant.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$OB_SQL_WORKAREA_MEMORY_INFO;
```
