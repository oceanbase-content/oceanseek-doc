# V$OB_FUNCTION_IO_STAT

## Overview

This view displays the I/O statistics at the function level for all tenants on the current OBServer node. If the resource group corresponding to a background task at the function level does not have a resource management plan enabled, the displayed I/O information is for statistical reference only, and the corresponding resources cannot be limited.

## Columns

| Field Name | Type | Whether can be NULL | Description |
| ------------------------------ | -------------- | ---------------- | ------------------------------------------------------------ |
| SVR_IP | varchar(46) | NO | Server IP Address |
| SVR_PORT | bigint(20) | NO | Server Port Number |
| TENANT_ID | bigint(20) | NO | Tenant ID |
| FUNCTION_NAME | varchar(32) | NO | The backend task name corresponding to the function: <ul><li>`COMPACTION_HIGH`: Mini merge and DDL/KV merge tasks</li> <li>`HA_HIGH`: high-priority and highly reliable tasks such as replication, rebuild, and recovery.</li> <li>`COMPACTION_MID`: Minor merge task</li> <li>`HA_MID`: medium-priority, highly reliable tasks, such as migration tasks</li> <li>`COMPACTION_LOW`: Major compaction task</li> <li>`HA_LOW`: low-priority but high-reliability tasks such as backup and backup cleanup</li> <li>`DDL`: Tasks in scenarios such as unique index verification and data replenishment after column deletion.</li> <li>`DDL_HIGH`: DDL MemTable Minor Compaction Task</li> <li>`CLOG_LOW`: Physical standby database and CDC read tasks</li> <li>`CLOG_MID`<: Tasks such as read from shared storage for follower replicas and read from local disks for log archiving</li> <li>`CLOG_HIGH`: tasks such as writing clogs to the local disk, uploading clog files to shared storage, and reading from the local disk by follower replicas.</li> <li>`GC_MACRO_BLOCK`: Macroblock recycling and reuse tasks</li> <li>`OPT_STATS`: statistics collection task</li> <li>`IMPORT`: Import Task</li> <li>`SQL_AUDIT`: SQL audit log persistence task</li> <li>`DEFAULT_FUNCTION`: all background tasks except for the defined ones.</li></ul> |
| MODE | varchar(32) | NO | The read/write modes corresponding to I/O operations (requests for shared storage are remote requests, while requests for other types are local requests): <ul><li>`LOCAL READ`: Local read</li> <li>`LOCAL WRITE`: Local write</li> <li>`REMOTE READ`: remote read</li> <li>`REMOTE WRITE`: Remote write</li></ul> |
| SIZE | bigint(20) | NO | Average I/O Size |
| REAL_IOPS | bigint(20) | NO | Actual IOPS |
| REAL_MBPS | bigint(20) | NO | Actual bandwidth, in MB/s |
| SCHEDULE_US | bigint(20) | NO | Average I/O Scheduling Time, in μs |
| IO_DELAY_US | bigint(20) | NO | Average execution time of disk I/O, in μs |
| TOTAL_US | bigint(20) | NO | The overall average I/O execution time, in microseconds. |

## Sample query

In the sys tenant, query the IO statistics at the function level for all tenants on the current OBServer node.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$OB_FUNCTION_IO_STAT LIMIT 5;
```
