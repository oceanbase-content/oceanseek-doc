# Deploy a LogService cluster by using OCP

LogService is OceanBase’s distributed log service, used to receive, store, and manage log data for AI clusters. Through OCP, you can conveniently manage LogService clusters, including cluster creation, monitoring, parameter configuration, and more.

This topic describes how to create a new LogService cluster in OCP.

## Prerequisites

* * You have deployed OCP Community Edition V4.5.1 BP3 or later. For the deployment procedure of OCP Community Edition, see [Deploy OCP](https://docs.oceanbase.com/obd/deploy-ocp-ui).
* The user currently logged in to OCP has the **ADMIN** or **ORG_ADMIN** role. For more information, see [Role overview](https://docs.oceanbase.com/ocp/user-management-overview) and [Default OCP roles](https://docs.oceanbase.com/ocp/default-ocp-roles).
* You have obtained the RPM package of LogService. For more information, see [Prepare installation packages](../300.preparations-before-deploy/300.prepare-installation-packages.md).
* Object storage has been configured. For details, see [Create an object storage configuration](200.create-an-object-storage.md). A bucket has already been created and is accessible.
* Memory planning: If the LogService cluster and the OBServer cluster are deployed on the same machine (mixed deployment scenario), you must plan memory usage in advance to avoid insufficient memory. It is recommended to set the `memory_limit` parameter when creating the LogService cluster to limit memory usage. For details, refer to the recommended LogService resource settings in [Configure Servers](../300.preparations-before-deploy/200.configure-servers.md).

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If the OBServer cluster and the LogService cluster are mixed deployed and their memory usage is not limited separately, memory contention may occur, potentially causing OOM (out-of-memory) issues and affecting cluster stability. Therefore, during planning, allocate memory properly and set appropriate values for the <code>memory_limit</code> parameter of both clusters based on the available host memory resources.</p>
   </main>

## Step 1: Add hosts to the resource pool of OCP

Before you deploy a LogService cluster, you must add the required hosts to the resource pool of OCP by referring to the content of this section.

1. Log on to OCP.

2. In the left-side navigation pane, click **Hosts** to go to the **Hosts** page.

3. In the upper-right corner of the **Hosts** page, click **Add Host**.

4. In the dialog box that appears, enter the host information.

   The following table describes the parameters that you need to configure.

   |   **Parameter** |         **Description**     |
   |------------|----------------------|
   | **IP Address**  | The IP address of the host to be added. Enter the IPv4 address of the new host. You can add multiple IP addresses at the same time, separated by commas.  |
   | **SSH Port** | The SSH port number. The default value is `22`.               |
   | **Host Type**   | The label that you specify for hosts with the same configurations to facilitate host management. If the required host type is unavailable, click **Create Host Type** in the drop-down list to add a new type.|
   | **IDC**   | Select the IDC where the host is deployed. If the target IDC is unavailable, click **Create IDC** in the drop-down list to add IDC information to OCP. IDC information includes **IDC** and **Region**.<ul><li>An IDC is one of the host attributes that you must record for an OceanBase cluster. The IDC is referenced in OceanBase load balancing and SQL statement routing strategies. Specify the actual IDC.</li><li>Region specifies the geographical area where the host is located. It is one of the host attributes that you must record for an OceanBase cluster. The region affects the OceanBase load balancing and SQL statement routing strategies. Specify the actual region.</li></ul><main id="notice" type='explain'><h4>Note</h4><p>OCP V3.1.1 and later support multi-zone mode. When you add an IDC, it is created in the zone where the current OCP is deployed.</p></main>|
   | **Type**     | Valid values: **Physical Machine**, **Container**, and **ECS**. If you select **Container**, you must specify **Port Mapping**, which specifies two mapping relationships between ocp-agent and the host, and between ocp-exporter and the host. The format is `<host port>:<ocp-agent port in Docker>,<host port>:<ocp-exporter port 1 in Docker>`.   |
   | **Credentials**   | Select the credentials used to remotely log in to the physical server. You can click **Create Credential** in the drop-down list to create credentials. </br>When you add a credential, take note of the following:<ul><li>**Credential Name**: The credential name must start with a letter and end with a letter or a digit. It can contain letters, digits, and underscores (_). It must be 2 to 64 characters in length.</li><li>**Authorization Type**: Valid values: **Password authentication**, **Public key authentication**, and **Configured password-free login**.</li> <li>**User Type**: SSH users with root permissions are supported. A regular user with root permissions must first be granted the permission to run sudo commands without a password. OCP currently supports only granting the permission to run all sudo commands without a password by adding `username ALL=(ALL) NOPASSWD:ALL` to the `/etc/sudoers` file.</li></ul>|
   | **Host Alias** (optional)   | Optional. Specifies another name for the host.   |
   | **Description** (optional)     | The comments of the host to facilitate host management.      |

5. After you complete the configuration, click **OK**.

## Deploy LogService Cluster

1. Log in to OCP.

2. In the left navigation bar, click **Logservice** under **Component**.

3. On the **LogService** page, click **Create LogService Cluster**.

4. On the **Create LogService Cluster** page, configure the basic information for the cluster.

   The **Basic Information** is shown in the following table.

   |    **Parameter**       |     **Description**    |
   |-------------------|-----------------|
   | **LogService Cluster Name**     | Customize a name for the cluster to be managed. Naming rules: must start with a letter; must end with a letter or number; 2–32 characters long; special characters are limited to underscores.|
   | **LogService Version** | You can select an existing oblogservice version from the list, or click **Upload Software Package** below the list to upload an oblogservice RPM package.     |

5. On the **Create LogService Cluster** page, configure the deployment mode information for the cluster.

   The LogService cluster must be configured with 3 zones.

   |       **Parameter**     |            **Description**               |
   |--------------------|-----------------------------------|
   | **Zone Name**      | Usually a default name is provided. You can customize it as needed. The zone name must start with an English letter, can contain uppercase and lowercase letters, numbers, and underscores, and must be 2 to 48 characters long.|
   | **Region**           | Select the region to which the zone belongs. |
   | **Instance Type (Optional)**   | Select the instance type. If a machine type is selected, the host list will be filtered accordingly.|
   | **CPU Architecture**   | Automatically identified after you select the **Logservice Version** in the **Basic Information** section.        |
   | **Host**           | The IP address of the machine. Multiple IP addresses can be selected.|
   | **Software Package Type** | Automatically identified after you select the  **Logservice Version** in the **Basic Information** section.       |

6. On the **Create Logservice Cluster** page, configure the data storage information for the cluster.

   The **Storage Information** is shown in the following table.

    |    **Parameter**     |     **Description**    |
    |--------------------|-----------------|
    | **Object Storage Configuration**      | The storage medium type. Supported options include AWS S3, S3-compatible object storage (such as Alibaba Cloud OSS, Huawei Cloud OBS, Tencent Cloud COS, etc.), and Azure Blob. The object storage URL only supports the `s3://` and `azblob://` protocol headers; other protocols are not supported.|
    | **Storage Directory**      | The path for storing data. The path used to store data. For S3-compatible object storage, the format is `s3://bucket/data/1`. For Azure Blob, the format is `azblob://container/data/1`.|

7. (Optional) Configure cluster parameters. You can customize startup and runtime parameters for the cluster.

   You can use the default parameter settings, or open the **Parameter Configuration** module to configure cluster parameters.

   * You can add startup parameters one by one and assign values to them.
  
     <main id="notice" type='explain'>
      <h4>Note</h4>
      <ul><li>If the LogService cluster and the OBServer cluster are deployed on the same machine (mixed deployment scenario), it is recommended to set the <code>memory_limit</code> parameter in the parameter configuration to limit Logservice's memory usage. Based on the log volume and business requirements, set LogService memory within a reasonable range to avoid memory contention with the OBServer cluster.</li>
      <li>The <code>memory_limit</code> parameter for a Logservice cluster must be configured when the cluster is created, and cannot be modified after the cluster has been created. Please set this parameter appropriately during planning based on the available host memory resources.</li></ul>
     </main>

   * You can also click **Select Template to Auto-Fill**, then select a parameter template, and the system will automatically fill in the parameters and configurations from the template here. If no cluster parameter template has been created, you can click **Create Logservice Parameter Template** to create one for the cluster.

8. (Optional) Configure paths and ports through custom settings.

   You can use the default path and port configurations, or open the **Custom Settings** section to customize the **Path Settings** and **Port Settings**.

   * Configure paths:

      In the **Path Configuration** section, customize the **Software Installation Path** and **Local Storage Path** as needed.

   * Configure ports:

      In the **Port Configuration** section, customize the **SQL Port** and **Web Port**.

   After configuration, click **Test** to check whether the ports are already in use. If a port is in use, you must reconfigure an available one.

9. After completing the configuration, click **Create** in the lower-right corner.

   After clicking Create, you will be redirected to the task center and must wait for the LogService cluster to be created successfully.

## What to do next

After the LogService cluster is successfully created, you can create an OceanSeek cluster.

For more information about creating an OceanSeek cluster using OCP, see [Deploy an OceanSeek cluster using OCP](400.deploy-oceanbase-ai-cluster-using-ocp.md).
