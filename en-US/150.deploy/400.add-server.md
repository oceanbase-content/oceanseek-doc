# Add a server

When adding servers, you need to add all the servers involved in the deployment.

This topic describes how to add a server to an OAT resource pool.

<main id="notice" type='explain'>
   <h4>Note</h4>
   <p>This section uses OAT V4.5.1 as an example. The operation interface may vary by OAT version. Please refer to the actual interface.</p>
</main>

## Prerequisites

You have installed OAT. For more information, see [Deploy OAT](300.preparations-before-deploy/400.deploy-oat.md).

## Procedure

1. Log in to OAT.

2. In the left navigation bar, click **Server** to go to the **Server Management** page. In the upper-right corner of the page, click **Add Server**.

3. On the **Add Server** page, enter the basic information.

   **The specific fields are described as follows:**

   |   Field    |          Description          |
   |-----------|----------------------|
   | Server IP | The public IP address of the server to be added.    |
   | SSH Port  | The SSH access port of the server to be added.   |
   | IDC| The IDC where the server to be added is located.       |
   | Credentials      | The access credentials for the server to be added. Two credential types are supported: usernames and passwords, and SSH keys.|
   | Description (Optional) | A note for the server that helps you manage hosts more effectively.|

4. On the **Add Server** page, configure the initialization settings.

   **The specific fields are described as follows:**

   |   Field    |          Description          |
   |----------|----------------------|
   | Server Usage | The purpose of the server to be added. For servers used for OBServer and LogService, select OB Server.|
   | OceanBase OS User | The operating system user who installs and runs OBServer and OceanBase product services. This can be customized. |
   | User Password | The password for the above OS owner user. |
   | User UID:GID | The UID and GID corresponding to the OS owner user. |
   | Docker Root Directory | The Docker data directory. |

   * Clock Synchronization (Optional): Disabled by default. To enable clock synchronization, specify the following parameters:

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>The servers used to deploy OceanBase AI Database and LogService clusters, as well as the server used to deploy OCP, must be synchronized with the time source.</p>
      </main>

      | Parameter | Description |
      |-----------|-------------|
      | Clock Source IP | The IP address of the clock source. |
      | minpoll: | The minimum interval, in seconds, at which the chrony client sends time synchronization requests to the time source. |
      | maxpoll: | The maximum interval, in seconds, at which the chrony client sends time synchronization requests to the time source. |
      | maxslewrate: | The maximum adjustment rate of the chrony client clock, in PPM (parts per million). |
      | Use this server as a secondary clock source (Optional) | If enabled, and if requests from clients in the whitelist are allowed while requests from clients in the blacklist are denied, the server can provide time synchronization services as a time source. |

   * Automatically Synchronize to OCP (Optional): Disabled by default. If enabled, you need to select an installed OCP instance. If no OCP instances are available, the option is disabled. After initializing the server in OAT, the system automatically calls the OCP API to add the server to the specified OCP for later use.

      <main id="notice" type='notice'>
        <h4>Notice</h4>
        <p>Before deploying OceanBase AI Database and LogService clusters using OCP, add the deployment machine to an OCP resource pool.</p>
      </main>

   * Disk Initialization (Optional): To ensure the stability of OceanBase AI Database and related products and services, it is usually recommended to configure service directories on independent disks. After selecting disk initialization, the program automatically creates the corresponding `vg` using `lvm` and mounts a logical volume (`lv`) of the appropriate size to the specified directory.

      * Select a disk or partition: The system automatically identifies unmounted disks. You can select one or more disks to be mounted.
      * Specify the file system type: Specify the file system type. Valid values: xfs, ext4, and auto. Default value: auto.
      * Mounting Purpose: Select a mounting purpose. Valid values: Software Installation Path, Data Disk Path, and Log Disk Path.
      * Mounting Point: Select the mounting path based on the actual situation.
      * Space (GB): Specify the space size based on the actual situation, in GB.

5. Click **Confirm**.

   * If disk initialization is enabled, a pop-up window will show the validation items when you submit. If no errors are found, click OK to add the server.
   * If disk initialization is not enabled, the submission proceeds directly and initialization begins.

After the server is successfully submitted, you can view it in the server list. Its status will be **Initializing**. On the **Server Management** page, locate the added server and click **View Tasks** in its corresponding **Actions** column to view the task progress. If there are too many servers, you can search by IP at the top of the page.

If a subtask encounters an error and does not affect business operations, you can view the log information and manually set the subtask status to successful.

After OCP is deployed and the servers are added, you can proceed to deploy the LogService and OceanBase AI Database clusters:
