# (Optional) Deploy OBProxy

OceanBase Database Proxy, abbreviated as ODP and also known as OBProxy, is a database proxy middleware provided by OceanBase. It can be used for connection pool management, load balancing, failover, and other features. OBProxy is an optional component, and whether to deploy it depends on your application requirements and scenarios.

This topic mainly describes how to create an OBProxy cluster using OCP.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p><ul>
  <li>This section uses OCP V4.5.0 as an example. The operation interface may vary by OCP version. Please refer to the actual interface.</li>
  <li>After OBProxy is deployed on any machine, it provides OceanBase proxy services by exposing an IP address and port. Users can access OceanSeek through this IP address and port just like accessing a MySQL database. It is generally recommended to deploy it on OBServer nodes.</li>
  <li>It is recommended to deploy only one OBProxy service on a single machine and use the standard 2883 port. If multiple OBProxy services are deployed on the same machine, different ports must be specified to distinguish them.</li>
  </ul></p>
</main>

## Prerequisites

* You have deployed OCP. For more information, see [Deploy OCP](500.deploy-ocp-use-oat/400.deploy-ocp.md).
* The currently logged-in user has the `OBPROXY_MANAGER` role or has the permissions to manage OBProxy. For more information, see [Role overview](https://docs.oceanbase.com/ocp/user-management-overview) and [Default OCP roles](https://docs.oceanbase.com/ocp/default-ocp-roles).
* You have obtained the OBProxy RPM package. For more information, see [Prepare installation packages](300.preparations-before-deploy/300.prepare-installation-packages.md).

## Procedure

1. Log in to OCP.

2. In the left navigation bar, click **OBProxy** under **Component**.

3. On the **OBProxy** page, click **Create OBProxy Cluster** in the upper-right corner.

4. On the **Create OBProxy Cluster** page, configure the **Basic Settings**.

   | Parameter | Description |
   |------------------|-------------|
   | **Cluster Name** | Customize the cluster name according to your business requirements. It must start with an English letter and can contain English letters, numbers, and underscores.|
   | **Software Version** | Select the OBProxy version to install. You need to choose an OBProxy software package of V4.0.0 or later. |
   | **root@proxysys Password** | The root@proxysys account is used to log in to OBProxy for managing parameters of the proxy itself. Set a password for this account here. A custom password or a randomly generated one is supported. The password must meet the following complexity requirements:<ul><li>It must be 8 to 32 characters long.</li><li>It must contain at least three of the four types: digits (0-9), uppercase letters (A-Z), lowercase letters (a-z), and special characters. Supported special characters are <code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>.</li></ul> |
   | **Load Balancing Management** |Disabled by default.</br> <ul><li>When Load Balancing Management is disabled, the following information must be configured:<ul><li>Access Address: The access address of the OBProxy cluster, used only to generate tenant connection strings and does not affect actual usage. If a VIP address is used, you must request and bind it to the OBProxy server yourself.</li><li>Defaults to 2883 and can be customized.</li></ul> </li><li>When load balancing management is enabled, the following information must be configured:<ul><li>Load Balancer: Defaults to OBLB. Alibaba Cloud SLB is only applicable to private cloud environments. It is recommended to contact technical support for assistance.</li><li>OBLB Service: You can select an existing OBLB service configured when OCP was deployed, or click Add OBLB Service to create one in the right-side panel.</li><li>VIP: Select the specific VIP address of the OBLB.</li><li>Access Port: Defaults to 2883 and can be customized.</li><li>Domain Configuration (Optional): Used to map the VIP and port. The platform does not provide a mapping between VIPs and domain names, so you must prepare DNS resolution yourself.</li></ul></li></ul>|
   | **Startup Method** | The startup method for this OBProxy cluster. Possible values are:<ul><li>ConfigUrl: Multi-cluster startup mode. The OBProxy cluster can access multiple OceanSeek clusters.</li><li>RsList: Single-cluster startup mode. The OBProxy cluster can access only the OceanSeek cluster specified when the OBProxy cluster is created. After the OBProxy cluster is created, additional connectable OceanSeek clusters cannot be added.</li></ul>|
   | **Select Connectable OceanBase Cluster** | Select the OceanSeek cluster that this OBProxy cluster can access. Only OceanSeek clusters on the same network as this OBProxy cluster can be selected.<ul><li>This parameter is optional when Startup Method is configured as ConfigUrl.</li><li>This parameter is required when Startup Method is configured as RsList. Select the corresponding cluster from the drop-down list.</li><li>If the password vault already contains the connection credentials of the cluster’s proxyro user, that user is selected by default.</li><li>If the password vault does not contain the connection credentials of the cluster’s proxyro user, click Create Connection to create connection credentials for that cluster’s proxyro user.</li></ul>|

5. (Optional) On the **Create OBProxy Cluster** page, configure **Deploy OBProxy**.

   If you want to deploy OBProxy while creating the OBProxy cluster, configure it in this step. Otherwise, you can skip this step and add OBProxy to the cluster later through **Take Over OBProxy** or **Add OBProxy** after the cluster is created.

   Turn on **Deploy OBProxy** and fill in the deployment information according to the following table:

   |    **Parameter**       |     **Description**    |
   |-------------------|-----------------|
   | **Data Center** | The data center where the OBProxy resides. An OBProxy can exist only in one data center.|
   | **Host Type (Optional)** | Optional. If you select a host type, the subsequent host list will be filtered accordingly.|
   | **Select OBProxy Host** | Select the host for deploying the OBProxy. </br>By default, two host slots are shown, which is sufficient to deploy two OBProxy instances. If you need to deploy more, click **Add OBProxy** to add more hosts. If you want to deploy only one OBProxy, click the delete icon next to a host as shown above to remove it.|

6. (Optional) On the **Create OBProxy Cluster** page, configure the **Parameter Settings**.

   Open **Parameter Settings** to add or modify startup parameters and other parameters.

7. Open **Custom Configuration** to configure the cluster port, the primary user of the operating system, and paths.

   |    **Parameter**       |     **Description**    |
   |-------------------|-----------------|
   | **SQL Port** | Default is 2883, supports custom ports.|
   | **RPC Port** | Default is 2885, supports custom ports.|
   | **Exporter Port** | Default is 2884, supports custom ports.|
   | **Primary User of Operating System** | The operating system user used to install and run OBServer. This field cannot be edited. You can adjust the default configuration using the system parameter `ocp.operation.default.os.user`. For details, see [Modify system parameters](https://docs.oceanbase.com/ocp/modify-system-parameters).|
   | **Software Installation Path** | <ul><li>When **Primary User of Operating System** is admin, **Software Installation Path** defaults to <code>/home/admin/obproxy</code>, supports custom paths.</li><li>When **Primary User of Operating System** is non-admin, **Software Installation Path** defaults to <code>/opt/oceanbase/obproxy</code>, supports custom paths.</li></ul> After configuration, click **Test** to verify if the path is available. If not, you can troubleshoot based on the test results or change the path to another available one.|


   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>After modifying the <code>ocp.operation.default.os.user</code> parameter, the change takes effect only for creating distributed clusters, creating OBProxy clusters, and creating arbitration services. It does not affect other configurations of existing clusters.</p>
   </main>

8. After completing the configuration, click **Submit** in the lower-right corner.
