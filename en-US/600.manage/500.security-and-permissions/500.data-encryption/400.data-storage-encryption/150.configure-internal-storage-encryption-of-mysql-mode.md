# Set up transparent data encryption for a newly created table

This topic describes how to enable transparent data encryption for a newly created table by creating an encrypted tablespace.

In OceanBase AI Database, the unit of data encryption is the tablespace. OceanBase AI Database is not a multi-data-file database system; the concept of tablespaces is designed for compatibility and can be simply understood as a collection of tables.

This topic uses creating a table named `t1` in the encrypted tablespace `sectest_ts1` as an example to provide step-by-step guidance for enabling transparent data encryption:

1. Configure the encryption method. This topic provides configuration examples for the `internal` method and the `obcloud` method in OBCloud deployment.
2. Create a tablespace and specify the encryption algorithm. This topic uses `aes-256` as an example.

## Limitations

* The system tenant cannot enable encryption.
* Once a tenant has TDE configured, it cannot switch to other encryption methods unless the tenant is rebuilt.

## Configure encryption

This topic provides configuration examples for the `internal` method and the `obcloud` method in OBCloud deployment.

### Configure transparent data encryption for the internal method

The tenant master key for the internal method has its encryption information primarily managed in internal tables. To avoid circular dependencies during log replay, clogs are not encrypted in this encryption method.

1. Log in to the user tenant of the cluster as the administrator.

2. Execute the following statement to enable transparent data encryption for the internal method.

   The `tde_method` configuration item sets the method for transparent tablespace encryption. The default value is `none`, which means transparent tablespace encryption is disabled.

   For more information about the `tde_method` configuration item, see [tde_method](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7800.tde_method.md).

      <main id="notice" type='notice'>
       <h4>Notice</h4>
       <p>Once the <code>tde_method</code> configuration item is set, it cannot be modified.</p>
      </main>

      ```shell
      obclient> ALTER SYSTEM SET tde_method='internal';
      ```

3. Execute the following statement to confirm that the value of the `tde_method` configuration item is `internal` on all OBServer nodes of the tenant.

   ```shell
   obclient> SHOW PARAMETERS LIKE 'tde_method';
   ```

4. After confirmation, execute the following statement to generate the master key.

      <main id="notice" type='explain'>
       <h4>Note</h4>
       <p>This statement can be executed only if the value of the <code>tde_method</code> configuration item is <code>internal</code> on all OBServer nodes of the tenant.</p>
      </main>

      ```shell
      obclient> ALTER INSTANCE ROTATE INNODB MASTER KEY;
      ```

5. Create a tablespace and specify the encryption algorithm.

   You can specify the encryption algorithms `aes-256`, `aes-128`, `aes-192`, `sm4-cbc`, `aes-128-gcm`, `aes-192-gcm`, `aes-256-gcm`, and `sm4-gcm`. If you use `'y'`, aes-256 is used by default.

   Example:

   ```shell
   obclient> CREATE TABLESPACE sectest_ts1 encryption = 'y'; 
   ```

### Configure transparent data encryption using obcloud

The `obcloud` method is suitable for OBCloud deployments, where the tenant master key is managed by the OceanBase Cloud KMS proxy service. For private cloud OCP deployments, use `ocp`. For specific configurations, see [tde_method](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7800.tde_method.md).

1. Log in to the user tenant of the cluster as the administrator.

<main id="notice" type='explain'>
   <h4>Note</h4>
   <p>Steps 2 through 5 are used to configure the <code>obcloud</code> encryption method, set up the KMS proxy service, and generate the tenant master key.<strong>If this tenant has already completed the same configuration by referring to <a href="../300.tenant-master-key/200.configure-tenant-master-key-mysql.md">Generate tenant master key</a>, skip these steps</strong>. For ease of reading and operation, the entire process is listed in detail below.</p>
</main>

2. Execute the following statement to enable transparent data encryption using the `obcloud` method.

   The `tde_method` configuration item specifies the method for transparent tablespace encryption. The default value is `none`, which disables transparent tablespace encryption.

   For more information about the `tde_method` configuration item, see [tde_method](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7800.tde_method.md).

   ```shell
   obclient> ALTER SYSTEM SET tde_method = 'obcloud';
   ```

3. Execute the following statement to confirm that the value of the `tde_method` configuration item is `obcloud` on all OBServer nodes of the tenant.

   ```shell
   obclient> SHOW PARAMETERS LIKE 'tde_method';
   ```

4. Execute the following statement to configure the KMS proxy service configuration items.

   ```shell
   obclient> ALTER SYSTEM SET external_kms_info = '{
     "kms_host": "https://kms.example.oceanbase.com",
     "access_key_id": "LTAI****************",
     "access_key_secret": "your_access_key_secret",
     "cmk_id": "your_customer_master_key_id"
   }';
   ```

5. After confirmation, execute the following statement to generate the master key.

   ```shell
   obclient> ALTER INSTANCE ROTATE INNODB MASTER KEY;
   ```

6. Create a tablespace and specify the encryption algorithm.

   You can specify the encryption algorithms `aes-256`, `aes-128`, `aes-192`, `sm4-cbc`, `aes-128-gcm`, `aes-192-gcm`, `aes-256-gcm`, and `sm4-gcm`. If you use `'y'`, aes-256 is used by default.

   ```shell
   obclient> CREATE TABLESPACE sectest_ts1 encryption = 'y';
   ```

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>The preceding values are examples. Replace them with your actual KMS endpoint and key information. For more information, see <a href="../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7800.tde_method.md">tde_method</a> and <a href="../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3200.external_kms_info.md">external_kms_info</a>.</p>
</main>

## Create a new table in an encrypted tablespace

After configuring the encryption method, you can create a new table in the encrypted tablespace. The steps are as follows:

1. Log in to the database as a regular user.

2. After entering the corresponding database, create a table and specify its tablespace.

   ```shell
   obclient> CREATE TABLE t1 (id1 int, id2 int) TABLESPACE sectest_ts1;
   ```

   After creation, any transaction related to this table must be encrypted.

3. Confirm whether the table in the tablespace is marked as encrypted.

   Execute the following statement to check if `encryptionalg` is the previously set `aes-256`.

   ```shell
   obclient> SELECT table_name,encryptionalg,encrypted FROM oceanbase.V$OB_ENCRYPTED_TABLES;
   +------------+---------------+-----------+
   | table_name | encryptionalg | encrypted |
   +------------+---------------+-----------+
   | t1         | aes-256       | YES       |
   +------------+---------------+-----------+
   1 row in set
   ```

   If `encryptionalg` is `aes-256` and `encrypted` is `YES`, the table encryption configuration is successful.

   For more information about the fields in the `V$OB_ENCRYPTED_TABLES` view, see [V$OB_ENCRYPTED_TABLES](../../../../700.reference/700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/31000.v-ob_encrypted_tables-of-mysql-mode.md).
