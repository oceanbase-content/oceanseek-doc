# View the physical restore progress

During data restore, you can view the physical restore progress in views.

## Procedure

1. Log in as the `root` user to the `sys` tenant of the cluster where the tenant to be restored resides.

2. Execute the following statement to view the restore progress:

   ```sql
   obclient [oceanbase]> SELECT * FROM oceanbase.CDB_OB_RESTORE_PROGRESS\G
   ```

   This view records information such as the parameters entered during restore and the restore progress.

   One tenant restore corresponds to two task records: the task record of the `sys` tenant and the task record of the restored tenant. The task record of the `sys` tenant mainly records information about the restore of the restored tenant, and the task record of the restored tenant mainly records its own restore progress.

   During restore, pay attention to the `STATUS` column in the restore progress view:

   * For the `sys` tenant:

      * `CREATE_TENANT`: The `sys` tenant is creating the tenant to be restored. After the tenant is created, the status changes to `WAIT_TENANT_RESTORE_FINISH`. If the creation fails, the status changes to `RESTORE_FAIL`.

      * `WAIT_TENANT_RESTORE_FINISH`: The system is waiting for the restore of the tenant to be restored to complete. After the tenant is restored, the status changes to `RESTORE_SUCCESS`. If the restore fails, the status changes to `RESTORE_FAIL`.

      * `RESTORE_SUCCESS`: The tenant is restored successfully.

      * `RESTORE_FAIL`: The restore of the tenant failed.

   * For the restored tenant:

      * `RESTORING`: Data of the tenant is being restored. After the tenant is restored, the status changes to `POST_CHECK`. If the restore fails, the status changes to `RESTORE_FAIL`.

      * `POST_CHECK`: The system is checking the role of the tenant and restoring the tenant as a standby database. After the operation is completed, the status changes to `UPGRADE`. If the operation fails, the status changes to `RESTORE_FAIL`.

      * `UPGRADE`: The tenant is being upgraded. For restore across versions, an upgrade is performed for the tenant. After the operation is completed, the status changes to `RESTORE_SUCCESS`. If the operation fails, the status changes to `RESTORE_FAIL`.

      * `RESTORE_SUCCESS`: The restore succeeded.

      * `RESTORE_FAIL`: The restore failed.

   For more information about the `CDB_OB_RESTORE_PROGRESS` view, see [Introduction to views related to physical restore](../600.restore-data/900.views-of-the-restore.md).

   After restore is complete, you can view the restore result. For more information, see [View the result of physical restore](../600.restore-data/500.view-the-restore-history.md).
