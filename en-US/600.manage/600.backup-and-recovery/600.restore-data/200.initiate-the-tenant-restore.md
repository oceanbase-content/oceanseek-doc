# Perform physical restore

This topic describes how to perform tenant-level physical restore by using commands. Currently, OceanSeek supports tenant-level full restore to a point in time. For more information about full restore, see [Overview of physical backup and restore](../100.overview-of-physical-backup-and-recovery.md).

You can restore a tenant in the same cluster or in a different cluster in OceanSeek.

The restore process first restores the required macroblocks from the corresponding full backup to the target tenant based on the commands you enter. It then synchronously pulls and replays the transaction logs.

## Prerequisites

Before you perform a physical restore, make sure that all preparations are complete. For more information, see [Preparations before restore](../600.restore-data/100.preparation-before-recovery.md).

## Precautions

* In addition to data, tenant-level configuration items are backed up during data backup. However, the backed-up tenant-level configuration items are provided only as configuration references and are not directly restored to the tenant during physical restore. For more information about backing up parameters, see [Back up parameters](../400.data-backup/320.backup-parameters.md).

## Procedure

1. Log in to the `sys` tenant of the cluster as the `root` user.

2. (Optional) Execute the following statement to set the restore password for the backup.

   The restore password is required only if a password was added during data backup.

   ```sql
   SET DECRYPTION IDENTIFIED BY 'password';
   ```

   Replace `password` with the password added during backup.

   Here is an example:

   ```sql
   SET DECRYPTION IDENTIFIED BY '******';
   ```

3. Execute the following statement to set the encryption information.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>If the data is not encrypted or the original Key Management Service can be accessed during restore, skip this step.</p>
   </main>

   ```shell
   obclient [(none)]> SET @kms_encrypt_info = '<encryption_string>';
   ```

   Here, `<encryption_string>` is the value of `EXTERNAL_KMS_INFO`, which is a tenant-level configuration item.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p><code>external_kms_info</code> is used to store key management information. For more information about this configuration item, see <a href="../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3200.external_kms_info.md">external_kms_info</a>.</p>
   </main>

4. Execute the following statement to start a restore task.

   * Restore to a specified timestamp

      ```sql
      ALTER SYSTEM RESTORE dest_tenant_name FROM uri UNTIL TIME='timestamp' WITH 'pool_list=pool_list[&locality=locality][&primary_zone=zone_name][&concurrency=int_num][&kms_encrypt={true | false}][&method=full]' [WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password'] [DESCRIPTION description];
      ```

   * Restore to a specified SCN

      ```sql
      ALTER SYSTEM RESTORE dest_tenant_name FROM uri UNTIL SCN=scn WITH 'pool_list=pool_list[&locality=locality][&primary_zone=zone_name][&concurrency=int_num][&kms_encrypt={true | false}][&method=full]' [WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password'] [DESCRIPTION description];
      ```

   * Restore to the latest timestamp

      ```sql
      ALTER SYSTEM RESTORE dest_tenant_name FROM uri WITH 'pool_list=pool_list[&locality=locality][&primary_zone=zone_name][&concurrency=int_num][&kms_encrypt={true | false}][&method=full]' [WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password'] [DESCRIPTION description];
      ```

   The parameters in the statements are described as follows:

   * `TIME='timestamp'` and `SCN=scn`: Specifies the end point for restore. Data is restored to this point, including the point. For more information about how to specify `TIME` or `SCN`, see [Introduction to physical restore parameters](800.parameters-of-the-restore.md).

   * `uri`: Specifies the data backup path `backup_data_dest` and the log archive path `log_archive_dest` specified during backup. At least one data backup path and one log archive path must be specified, and they are separated by commas (,).

   * `pool_list`: Specifies the resource pools for the user. Multiple resource pools are separated by commas (,).

   * `locality` and `primary_zone`: Optional. Specifies the locality information for the new tenant replica distribution and the preferred location for the leader replica. For more information about these parameters, see [RESTORE](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3300.restore.md).

   * `concurrency`: Optional. Specifies the concurrency for data restore. The default value is the `MAX_CPU` value of the units allocated to the tenant.

   * `kms_encrypt`: Optional. Specifies whether to use the `kms_encrypt_info` specified before restore.

   * `method`: Optional. Specifies the restore method. The value is case-insensitive. Valid values:

     * `full`: Full restore. If this parameter is not specified, the default value is `full`.

   * `WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password'`: Specifies the key backup information for the encrypted tenant. Specify the key backup information only if transparent encryption is configured for the source tenant.

      * `backup_key_path`: The backup path of the key.

      * `password`: The encryption password set when backing up the key.

      For more information about key backup, see **Back up the key** in [Prepare for backup](../400.data-backup/100.preparation-before-data-backup.md).

   For more information about the parameters of physical restore, see [RESTORE](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3300.restore.md).

   Here are some restore examples:

   :::tab
   tab AWS S3

      Restore the `mysql` tenant from the S3 backup path and S3 log archive path to the specified timestamp `2024-01-15 00:00:00`. Specify the resource pool as `restore_pool` and perform a full restore.

      ```sql
      ALTER SYSTEM RESTORE mysql FROM 's3://oceanbase-test-bucket/backup/data?host=s3.<region>.amazonaws.com&access_id=***&access_key=***&s3_region=***, s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com&access_id=***&access_key=***&s3_region=***' UNTIL TIME='2024-01-15 00:00:00' WITH 'pool_list=restore_pool';
      ```

   tab Object storage compatible with the S3 protocol

   * Restore the `mysql` tenant from the OBS backup path and log archive path to the specified timestamp `2023-06-01 00:00:00`. Specify the resource pool as `restore_pool` and perform a full restore.

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 's3://oceanbase-test-bucket/backup/data/?host=obs.***.myhuaweicloud.com&access_id=***&access_key=***,s3://oceanbase-test-bucket/backup/archive/?host=obs.***.myhuaweicloud.com&access_id=***&access_key=***' UNTIL TIME='2023-06-01 00:00:00' WITH 'pool_list=restore_pool';
      ```

   * Restore the `mysql` tenant from the GCS backup path and log archive path to the specified timestamp `2023-06-01 00:00:00`. Specify the resource pool as `restore_pool` and perform a full restore.

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 's3://oceanbase-test-bucket/backup/data/?host=https://storage.googleapis.com&access_id=***&access_key=***,s3://oceanbase-test-bucket/backup/archive/?host=https://storage.googleapis.com&access_id=***&access_key=***' UNTIL TIME='2023-06-01 00:00:00' WITH 'pool_list=restore_pool';
      ```

   * Restore the `mysql` tenant from the COS backup path and log archive path to the specified timestamp `2023-06-01 00:00:00`. Specify the resource pool as `restore_pool` and perform a full restore.

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 's3://oceanbase-test/backup/data?host=cos.ap-xxxx.myqcloud.com&access_id=***&access_key=***,s3://oceanbase-test/backup/archive?host=cos.ap-xxxx.myqcloud.com&access_id=***&access_key=***' UNTIL TIME='2023-06-01 00:00:00' WITH 'pool_list=restore_pool';
      ```

   :::

5. (Optional) After the Meta tenant corresponding to the tenant to be restored is created, if you need to accelerate the restore, you can configure the number of concurrent threads for the restore task by using the `ha_high_thread_score` configuration item.

   1. Query the `oceanbase.DBA_OB_TENANTS` view to check whether the Meta tenant corresponding to the tenant to be restored has been created.

      A sample query is as follows:

      ```shell
      obclient> SELECT * FROM oceanbase.DBA_OB_TENANTS;
      ```

      In the query result, the tenant whose `TENANT_NAME` column starts with `META$` is the Meta tenant. When the status of the Meta tenant is `NORMAL`, it indicates that the Meta tenant has been created successfully.

      For more information about the columns in the `DBA_OB_TENANTS` view, see [DBA_OB_TENANTS](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/23100.o-dba_ob_tenants-of-sys-tenant.md).

   2. Set the `ha_high_thread_score` configuration item.

      The tenant-level configuration item `ha_high_thread_score` specifies the current number of worker threads for high availability high-priority threads. The default value is 0, and the value range is [0, 100]. We recommend that you set it to 10. For more information about `ha_high_thread_score`, see [ha_high_thread_score](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3400.ha_high_thread_score.md).

      The statement is as follows:

      ```shell
      obclient> ALTER SYSTEM SET ha_high_thread_score =10 TENANT = mysql;
      ```

## What to do next

* After initiating a restore task, you can view the progress and results of the restore in views. For more information, see [View the physical restore progress](../600.restore-data/400.view-the-restore-progress.md).

* After the restore task is completed, if you are restoring from backup data of a lower version to a cluster of a higher version, you also need to upgrade the restored tenant. For more information, see [Upgrade a tenant after restore is complete](610.update-the-tenant-after-the-restore.md).

* A tenant after physical restore is a standby tenant. Subsequently, this tenant can provide services as a standby tenant or be converted to a primary tenant to provide services. For more information about how to continue log archiving and replay logs from the source tenant as a standby tenant, see [Segment-based log replay for a standby tenant](510.recover-the-standby-tenant.md); for more information about how to convert a standby tenant into a primary tenant, see [Convert a standby tenant into a primary tenant](600.active-standby-tenant.md).
