# Restore from a specified path

After you move the backup sets and archivelog pieces of a tenant to other paths due to business needs, you can load them and then execute the `RESTORE` statement to restore the tenant.

## Prerequisites

* You have obtained the storage paths of the backup sets and archivelog pieces to be restored.

* The backup sets and archivelog pieces to be restored belong to the same tenant. Currently, you can restore a new tenant only from the backup sets and archivelog pieces of the same tenant.

* You have completed the preparations. For more information, see [Preparations before restore](../600.restore-data/100.preparation-before-recovery.md).

## Procedure

1. Log in to the `sys` tenant of the cluster where the tenant to be restored resides as the `root` user.

2. (Optional) Execute the `ALTER SYSTEM RESTORE...PREVIEW` statement to specify the original data backup path and log archive path, as well as the time point to restore to.

   The syntax is as follows:

   ```sql
   ALTER SYSTEM RESTORE FROM 'uri' UNTIL { TIME='timestamp' | SCN=scn } PREVIEW;
   ```

   The parameters are described as follows:

   * `uri`: Specifies the original data backup path and log archive path, which must be separated with a comma (,).

   * `TIME='timestamp' | SCN=scn`: Specifies the timestamp or SCN to restore to. You must explicitly specify this parameter in the statement.

   For more information about the parameters, see [RESTORE PREVIEW](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3350.restore-preview.md).

   Here are some examples:

   * Specify the original data backup path and log archive path, and specify the SCN to restore to as `1712650554000909004`.

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 's3://ob_backup/data?host=obs.***.myhuaweicloud.com&access_id=***&access_key=***, s3://oceanbase-test-bucket/backup/archive?host=obs.***.myhuaweicloud.com&access_id=***&access_key=***' UNTIL SCN = 1712650554000909004 PREVIEW;
      ```

   * Specify the original data backup path and log archive path, and specify the timestamp to restore to as `2024-04-09 16:15:54`.

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 's3://ob_backup/data?host=obs.***.myhuaweicloud.com&access_id=***&access_key=***, s3://oceanbase-test-bucket/backup/archive?host=obs.***.myhuaweicloud.com&access_id=***&access_key=***' UNTIL TIME = '2024-04-09 16:15:54' PREVIEW;
      ```

3. (Optional) Execute the `SHOW RESTORE PREVIEW` statement to query the backup sets and archivelog pieces required to restore to the specified time point.

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>You must wait until the execution of the <code>ALTER SYSTEM RESTORE...PREVIEW</code> statement succeeds before you execute the <code>SHOW RESTORE PREVIEW</code> statement. Otherwise, the query result is not as expected.</p>
   </main>

   ```shell
   obclient [oceanbase]> SHOW RESTORE PREVIEW;
   ```

   The query result shows all the backup sets and archivelog pieces required to restore to the specified time point, as well as their storage paths in the original data backup and log archive destinations. If you have moved some or all of these files to other paths or storage media due to business needs, you must maintain the mapping from the original path to the current path for each backup set and archivelog piece.

   For example, in the preceding query result, if you need to use the archivelog piece whose `BACKUP_PIECE` is `1` for restore but the file has been moved to `S3://test_bucket/archive/piece_1`, you must specify the new path `S3://test_bucket/archive/piece_1` when you execute the `ADD RESTORE SOURCE` statement to load the backup path.

4. Execute the `ADD RESTORE SOURCE` statement to load the backup sets and archivelog pieces to be restored.

   The syntax is as follows:

   ```sql
   ALTER SYSTEM ADD RESTORE SOURCE 'restore_path';
   ```

   The parameters in the syntax are described as follows:

   * `restore_path`: Specifies the path of the backup set or archivelog piece to load. You can specify one or more paths.

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>If the backup sets or archivelog pieces to load are stored on object storage, the paths of all backup sets or archivelog pieces must have the same <code>host</code>, <code>access_id</code>, and <code>access_key</code> settings.</p>
      </main>

   * You can execute this statement multiple consecutive times in the same session. The system incrementally adds the execution results to the restore source list.

   Here is an example:

   1. Load the backup set to be restored.

      ```shell
      obclient [oceanbase]> ALTER SYSTEM ADD RESTORE SOURCE 's3://ob_backup/data/backup_set_1_full?host=obs.***.myhuaweicloud.com&access_id=***&access_key=***';
      ```

   2. Load the archivelog piece to be restored.

      ```shell
      obclient [oceanbase]> ALTER SYSTEM ADD RESTORE SOURCE 's3://ob_backup/archive/piece_d1002r1p1,s3://ob_backup/archive/piece_d1002r1p2?host=obs.***.myhuaweicloud.com&access_id=***&access_key=***';
      ```

      ```shell
      obclient [oceanbase]> ALTER SYSTEM ADD RESTORE SOURCE 'S3://test_bucket/archive/piece_1?host=***&access_id=x****&access_key=****';
      ```

5. (Optional) If you find that the specified path of the backup set or archivelog piece is incorrect during loading, execute the following statement to clear the previous input, and then reload the backup set or archivelog piece from the correct path.

    ```shell
    obclient [oceanbase]> ALTER SYSTEM CLEAR RESTORE SOURCE;
    ```

6. Call the `RESTORE` statement after the loading from all the specified paths is completed.

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <ul>
   <li>You must execute the <code>RESTORE</code> statement in the same session as the <code>ADD RESTORE SOURCE</code> statement. If the original session is interrupted or you use a new session, the previously loaded restore source list is cleared.</li>
   <li>After you execute the <code>ADD RESTORE SOURCE</code> statement, you cannot restore a tenant by executing the <code>RESTORE</code> statement with a specified backup destination in the same session.</li>
   <li>After you execute the <code>RESTORE</code> statement, the previously loaded restore source list is cleared regardless of whether the restore succeeds. If you want to call the <code>RESTORE</code> statement again, you must reload the backup sets and archivelog pieces to be restored.</li>
   </ul>
   </main>

   The syntax is as follows:

   ```sql
   ALTER SYSTEM RESTORE restore_tenant_name [UNTIL {TIME='timestamp' | SCN=scn} ] WITH 'restore_option';
   ```

   For more information about the statement, see [RESTORE](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3300.restore.md).

   For more information about the parameters, see [Introduction to physical restore parameters](800.parameters-of-the-restore.md).

   Here are some examples:

   * Restore the `mysql` tenant from the specified paths to the SCN `1658285759724047000`, and set the resource pool to `restore_pool`.

      ```shell
      // Full restore
      obclient [oceanbase]> ALTER SYSTEM RESTORE mysql UNTIL SCN = 1712650554000909004 WITH 'pool_list=restore_pool';
      ```

   * Restore the `mysql` tenant from the specified paths to the timestamp `2024-04-09 16:15:54`, and set the resource pool to `restore_pool`.

      ```shell
      // Full restore
      obclient [oceanbase]> ALTER SYSTEM RESTORE mysql UNTIL TIME = '2024-04-09 16:15:54' WITH 'pool_list=restore_pool';
      ```

## What to do next

* After you initiate a restore task, you can view the restore progress and results in views. For more information, see [View the physical restore progress](../600.restore-data/400.view-the-restore-progress.md).

* After the restore task is completed, if you restore backup data from a lower version to a cluster of a higher version, you must also upgrade the restored tenant. For more information, see [Upgrade a tenant after restore is complete](610.update-the-tenant-after-the-restore.md).

* A tenant after physical restore is a standby tenant. It can subsequently provide services as a standby tenant or be converted to a primary tenant to provide services. For more information about how to continue log archiving and replay logs from the source tenant as a standby tenant, see [Segment-based log replay for a standby tenant](510.recover-the-standby-tenant.md); for more information about how to convert a standby tenant into a primary tenant, see [Convert a standby tenant into a primary tenant](600.active-standby-tenant.md).
