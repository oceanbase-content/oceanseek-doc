# View backup cleanup progress

After a cleanup policy is successfully configured and automatic cleanup is triggered, you can view the execution progress of cleanup tasks.

## View cleanup task progress in the sys tenant

1. Log in to the `sys` tenant of the cluster as the `root` user.

   Here is an example of how to connect to the database. Use the actual environment settings when you connect to the database.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. View the cleanup task progress.

   1. View the job progress.

      ```shell
      obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_DELETE_JOBS\G
      ```

      The query result is as follows:

      ```shell
      *************************** 1. row ***************************
                     TENANT_ID: 1002
                        JOB_ID: 7
                   INCARNATION: 1
           INITIATOR_TENANT_ID: 1002
              INITIATOR_JOB_ID: 7
            EXECUTOR_TENANT_ID: 1002
                          TYPE: DELETE OBSOLETE BACKUP
                     PARAMETER: expired_time:2025-09-10 12:09:40.060284
                     JOB_LEVEL: USER_TENANT
               START_TIMESTAMP: 2025-09-11 12:09:53.389512
                 END_TIMESTAMP: 
                        STATUS: DOING
                    TASK_COUNT: 2
            SUCCESS_TASK_COUNT: 1
                        RESULT: 0
                       COMMENT: 
      1 row in set
      ```

      According to the query result, the user tenant with the tenant ID `1002` initiated an expired backup cleanup task at `2025-09-11 12:09:53.389512`. The expiration time point for the cleanup check is `2022-05-31 12:09:40.060284`, which indicates that the value of the `recovery_window` parameter in the cleanup policy of the tenant is `1d`. `TASK_COUNT` is `2`, indicating that two `backup_set/backup_piece` subtasks are being executed under the JOB task. Meanwhile, `SUCCESS_TASK_COUNT` is `1`, meaning one task has been completed, so the current task completion rate is 50% (`SUCCESS_TASK_COUNT/TASK_COUNT`).

   2. Based on the query result, view the progress of the `backup_set/backup_piece` cleanup.

      ```shell
      obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_DELETE_TASKS\G
      ```

      The query result is as follows:

      ```shell
      *************************** 1. row ***************************
               TENANT_ID: 1002
                 TASK_ID: 4
             INCARNATION: 1
                  JOB_ID: 7
               TASK_TYPE: BACKUP SET
                      ID: 1
                ROUND_ID: 0
                 DEST_ID: 1002
         START_TIMESTAMP: 2025-09-11 12:09:50.800772
           END_TIMESTAMP: 2025-09-11 12:09:54.954691
                  STATUS: COMPLETED
        TOTAL_TASK_COUNT: 2
       FINISH_TASK_COUNT: 2
                  RESULT: 0
                 COMMENT: 
                    PATH: s3://oceanbase-test-bucket/backup/data?host=obs.****.myhuaweicloud.com
      *************************** 2. row ***************************
               TENANT_ID: 1002
                 TASK_ID: 5
             INCARNATION: 1
                  JOB_ID: 7
               TASK_TYPE: BACKUP PIECE
                      ID: 1
                ROUND_ID: 1
                 DEST_ID: 1001
         START_TIMESTAMP: 2025-09-11 12:09:50.968413
           END_TIMESTAMP: 
                  STATUS: DOING
          TOTAL_TASK_COUNT: 2
         FINISH_TASK_COUNT: 1
                  RESULT: 0
                 COMMENT: 
                    PATH: s3://oceanbase-test-bucket/backup/archive?host=obs.****.myhuaweicloud.com
      2 rows in set
      ```

      According to the query result, the user tenant with the tenant ID `1002` has completed cleaning up the backup file with `backup_set_id=1` in the destination `s3://oceanbase-test-bucket/backup/data?host=obs.****.myhuaweicloud.com`, with a task completion rate of 100% (`FINISH_TASK_COUNT/TOTAL_TASK_COUNT`). The backup file for log archiving with `round_id=1/backup_piece_id=1` in the destination `s3://oceanbase-test-bucket/backup/archive?host=obs.****.myhuaweicloud.com` is being cleaned up, with a task completion rate of 50% (`FINISH_TASK_COUNT/TOTAL_TASK_COUNT`). You can view the relevant information about the cleanup task initiation in the job-level task view using `JOB_ID`.

## View cleanup task progress in a user tenant

1. Log in to the database as a tenant administrator.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>The administrator user of a user tenant is the <code>root</code> user.</p>
   </main>

   Here is an example of how to connect to the database. Use the actual environment settings when you connect to the database.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql001#obdemo -p***** -A
   ```

2. View the cleanup task progress.

   1. View the job progress.

      A sample query is as follows:

      ```shell
      obclient(root@mysql001)[oceanbase]> SELECT * FROM oceanbase.DBA_OB_BACKUP_DELETE_JOBS\G
      ```

      Except for the absence of the `TENANT_ID` column, all columns in the `DBA_OB_BACKUP_DELETE_JOBS` view correspond to those in the `CDB_OB_BACKUP_DELETE_JOBS` view. For more information about the query result, see **View cleanup task progress in the sys tenant**.

   2. Based on the query result, view the progress of the `backup_set/backup_piece` cleanup.

      A sample query is as follows:

      ```shell
      obclient(root@mysql001)[oceanbase]> SELECT * FROM oceanbase.DBA_OB_BACKUP_DELETE_TASKS\G
      ```

      Except for the absence of the `TENANT_ID` column, all columns in the `DBA_OB_BACKUP_DELETE_TASKS` view correspond to those in the `CDB_OB_BACKUP_DELETE_TASKS` view. For more information about the query result, see **View cleanup task progress in the sys tenant**.
