# Cancel a cleanup task

Backup cleanup can be performed automatically or manually. When you cancel a cleanup task:

* In automatic cleanup scenarios, to prevent the canceled task from being rescheduled, you must first delete the cleanup policy and then stop the ongoing cleanup task. If you only want to cancel the current cleanup task, you do not need to delete the cleanup policy.
* In manual cleanup scenarios, you can directly cancel the cleanup task.

## Cancel an ongoing cleanup task in the sys tenant

1. Log in to the `sys` tenant of the cluster as the `root` user.

   Here is an example of how to connect to the database. Use the actual environment settings when you connect to the database.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. Execute the following statement to stop the ongoing cleanup task of the specified tenant.

   ```shell
   obclient [(none)]> ALTER SYSTEM CANCEL DELETE BACKUP TENANT tenant_name_list;
   ```

   Here, `TENANT` specifies the name of the user tenant whose cleanup task you want to cancel. You can specify multiple user tenant names. Only the cleanup tasks running in the specified tenants are canceled.

   Here is an example of canceling the ongoing cleanup task in the `tenant1` tenant from the sys tenant:

   ```shell
   obclient [(none)]> ALTER SYSTEM CANCEL DELETE BACKUP TENANT tenant1;
   ```

   If you do not specify the `TENANT` parameter, the ongoing cleanup tasks in all user tenants are canceled.

   ```shell
   obclient [(none)]> ALTER SYSTEM CANCEL DELETE BACKUP;
   ```

3. Check whether the cleanup task has stopped.

   1. Check whether the cleanup task is running.

      ```shell
      obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_DELETE_JOBS WHERE tenant_id = 1002\G
      ```

      The query result is as follows:

      ```shell
      *************************** 1. row ***************************
                         TENANT_ID: 1002
                            JOB_ID: 1
                       INCARNATION: 1
               INITIATOR_TENANT_ID: 1002
                  INITIATOR_JOB_ID: 7
                EXECUTOR_TENANT_ID: 1002
                              TYPE: DELETE OBSOLETE BACKUP
                         PARAMETER: expired_time:2025-09-12 12:09:40.060284
                         JOB_LEVEL: USER_TENANT
                   START_TIMESTAMP: 2025-09-13 12:09:53.389512
                     END_TIMESTAMP: 
                            STATUS: CANCELING
                        TASK_COUNT: 2
                SUCCESS_TASK_COUNT: 1
                            RESULT: 0
                           COMMENT:  
      1 row in set
      ```

      According to the query result, if the value of `STATUS` is `INIT`, `DOING`, or `CANCELING`, the cleanup task has not finished.

      If the query result is empty, no cleanup task is running in the specified tenant. You can proceed to the next step to view the cleanup task history to confirm the execution result.

   2. View the cleanup task history.

      ```shell
      obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_DELETE_JOB_HISTORY WHERE tenant_id = 1002\G
      ```

      The query result is as follows:

      ```shell
      *************************** 1. row ***************************
                        TENANT_ID: 1002
                           JOB_ID: 1
                      INCARNATION: 1
              INITIATOR_TENANT_ID: 1002
                 INITIATOR_JOB_ID: 7
               EXECUTOR_TENANT_ID: 1002
                             TYPE: DELETE OBSOLETE BACKUP
                        PARAMETER: expired_time:2025-09-12 12:09:40.060284
                        JOB_LEVEL: USER_TENANT
                  START_TIMESTAMP: 2025-09-13 12:09:53.389512
                    END_TIMESTAMP: 2025-09-13 12:10:36.829576 
                           STATUS: CANCELED
                       TASK_COUNT: 2
               SUCCESS_TASK_COUNT: 2
                           RESULT: 0
                          COMMENT: 
      1 row in set
      ```

      If the value of `STATUS` is `COMPLETED`, `FAILED`, or `CANCELED`, the cleanup task has stopped.

## Cancel an ongoing cleanup task in a user tenant

1. Log in to the database as a tenant administrator.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>The administrator user of a user tenant is the <code>root</code> user.</p>
   </main>

   Here is an example of how to connect to the database. Use the actual environment settings when you connect to the database.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql001#obdemo -p***** -A
   ```

2. Execute the following statement to stop the ongoing cleanup task of the current tenant.

   ```shell
   obclient> ALTER SYSTEM CANCEL DELETE BACKUP;
   ```

3. Check whether the cleanup task has stopped.

   1. Check whether the cleanup task is running.

      A sample query is as follows:

      ```shell
      obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_BACKUP_DELETE_JOBS\G
      ```

      According to the query result, if the value of `STATUS` is `INIT`, `DOING`, or `CANCELING`, the cleanup task has not finished.

      If the query result is empty, no cleanup task is running in the current tenant. You can proceed to the next step to view the cleanup task history to confirm the execution result.

   2. View the cleanup task history.

      A sample query is as follows:

      ```shell
      obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_BACKUP_DELETE_JOB_HISTORY\G
      ```

      According to the query result, if the value of `STATUS` is `COMPLETED`, `FAILED`, or `CANCELED`, the cleanup task has stopped.
