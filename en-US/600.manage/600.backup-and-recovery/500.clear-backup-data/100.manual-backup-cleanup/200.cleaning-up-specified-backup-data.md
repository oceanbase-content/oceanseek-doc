# Manually clean up specified backup or archive data

If you need to manually clean up specific backup or archive data due to business requirements, you can refer to this topic to manually clean up specified data backup sets or log archive pieces.

## Limitations

* When manually cleaning up specified backup or archive data, the user tenant being operated on must not have an automatic cleanup policy configured. If an automatic cleanup policy is configured, manual cleanup cannot be performed.

* For scenarios where only log archiving is enabled and no data backup path is configured, you cannot manually clean up specified log archive pieces. Users can only achieve the cleanup of log archive pieces by configuring the automatic cleanup policy to `log_only`.

  For more information about how to configure an automatic cleanup policy, see [Automatically clean up expired backups](../50.automatic-backup-cleanup/100.cleaning-up-backed-up-data-automatically.md).

## Clean up a specified data backup set

### Precautions

When you clean up a specified data backup set, note the following:


* If you need to specify multiple `BACKUP_SET_ID` for cleanup, all `BACKUP_SET_ID` must be under the same backup path. Cleaning up data backups from multiple paths in a single command is not supported.

* For the currently in-use backup path, you must retain at least one latest full data backup that can be used for recovery. That is, you can delete other backup sets before the one to be cleaned up only after retaining a full backup available for recovery.

* If the data backup set to be deleted is not in the currently used backup path, make sure that OceanSeek has access permissions on the corresponding backup path.

### Clean up a specified data backup set for a specified user tenant in the sys tenant

1. Log in to the `sys` tenant of the cluster as the `root` user.

   Here is an example of how to connect to the database. Use the actual environment settings when you connect to the database.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. View tenant information to obtain the tenant's `TENANT_ID`.

   This document uses the tenant `mysql001` as an example. The query example is as follows:

   ```shell
   obclient(root@sys)[(none)]> SELECT TENANT_ID, TENANT_NAME, TENANT_TYPE FROM oceanbase.DBA_OB_TENANTS WHERE TENANT_NAME = 'mysql001';
   ```

   The query result is as follows:

   ```shell
   +-----------+-------------+-------------+
   | TENANT_ID | TENANT_NAME | TENANT_TYPE |
   +-----------+-------------+-------------+
   |      1002 | mysql001    | USER        |
   +-----------+-------------+-------------+
   1 row in set
   ```

   According to the query result, the `TENANT_ID` of this tenant is 1002.

3. Obtain the `backup_set_id` of the backup set to be cleaned up.

   ```shell
   obclient(root@sys)[(none)]> SELECT TENANT_ID, BACKUP_SET_ID, BACKUP_TYPE, PREV_FULL_BACKUP_SET_ID, PREV_INC_BACKUP_SET_ID, STATUS, FILE_STATUS, START_REPLAY_SCN, START_REPLAY_SCN_DISPLAY, MIN_RESTORE_SCN, MIN_RESTORE_SCN_DISPLAY, PATH FROM oceanbase.CDB_OB_BACKUP_SET_FILES WHERE TENANT_ID = 1002;
   ```

   According to the query result, for the tenant with the tenant ID `1002`, five full backups are all located in the same backup path. Specifically:

   * The backups with `BACKUP_SET_ID` 1, 3, 4, 5, and 6 are full backups.

   According to the cleanup requirements:

   * If the backup path where the backup set to be deleted is located is the backup path currently used by the tenant, you must retain the latest full backup that can be used for restore, and earlier backups can be deleted.

     Whether a backup can be used for restore depends on whether the required log archive data is complete. For example, in this scenario, you can determine whether the full backup `BACKUP_SET_ID` 6 can be used for restore as follows:

In this case, you must check whether the previous full backup `BACKUP_SET_ID` 5 can be used for restore in the same way, and so on.

4. Execute the following statement to delete the specified data backup:

   ```sql
   ALTER SYSTEM DELETE BACKUPSET backup_set_id[,backup_set_id,...] TENANT [=] tenant_name;
   ```

   The parameters in the statement are described as follows:

   * `backup_set_id`: the ID of the backup set to be deleted. You can specify multiple data backup sets in a single statement. If you specify multiple `backup_set_id` values for cleanup, all of them must be in the same backup path. You cannot clean up data backups in multiple paths in a single statement.

   * `tenant_name`: the tenant for which the backup set is to be deleted.

   Here are some examples:

   * Delete the data backup set with `backup_set_id` 3 of the `mysql001` tenant.

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM DELETE BACKUPSET 3 TENANT = mysql001;
     ```

   * Delete the three data backup sets with `backup_set_id` 1, 2, and 4 of the `mysql001` tenant at the same time.

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM DELETE BACKUPSET 1,2,4 TENANT = mysql001;
     ```

   <p>The administrator user of a user tenant is the <code>root</code> user.</p>
   </main>

   Here is an example of how to connect to the database. Use the actual environment settings when you connect to the database.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql001#obdemo -p***** -A
   ```

2. Obtain the `backup_set_id` of the backup set to be cleaned up.

   A sample query is as follows:

   ```shell
   obclient(root@mysql001)[(none)]> SELECT BACKUP_SET_ID, BACKUP_TYPE, PREV_FULL_BACKUP_SET_ID, PREV_INC_BACKUP_SET_ID, STATUS, FILE_STATUS, START_REPLAY_SCN, START_REPLAY_SCN_DISPLAY, MIN_RESTORE_SCN, MIN_RESTORE_SCN_DISPLAY, PATH FROM oceanbase.DBA_OB_BACKUP_SET_FILES;
   ```

3. Execute the following statement to delete the specified data backup:

   ```sql
   ALTER SYSTEM DELETE BACKUPSET backup_set_id[,backup_set_id,...];
   ```

   The parameters in the statement are described as follows:

   * `backup_set_id`: the ID of the backup set to be deleted. You can specify multiple data backup sets in a single statement, separated by commas. If you specify multiple `backup_set_id` values for cleanup, all of them must be in the same backup path. You cannot clean up data backups in multiple paths in a single statement.

   * `tenant_name`: the tenant for which the backup set is to be deleted.

   Here are some examples:

   * Delete the data backup set with `backup_set_id` 3 of the current tenant.

     ```shell
     obclient> ALTER SYSTEM DELETE BACKUPSET 3;
     ```

   * Delete the three data backup sets with `backup_set_id` 1, 2, and 4 of the current tenant at the same time.

     ```shell
     obclient> ALTER SYSTEM DELETE BACKUPSET 1,2,4;
     ```

## Clean up a specified log archive piece

### Precautions

When you clean up a specified log archive piece, note the following:

* You must clean up log archive pieces in order.

* When you clean up pieces in the current archive path, make sure that the piece to be cleaned up is not depended on by any data backup in the current data backup path.

  To determine whether a piece to be cleaned up is depended on by a data backup set, perform the following steps:

  1. In the current backup path of the tenant, find a data backup set that was created earlier.

  2. Check the `START_REPLAY_SCN` of this data backup set.

     * System tenant

        ```shell
        obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_SET_FILES WHERE TENANT_ID = tenant_id AND BACKUP_SET_ID = set_id;
        ```

     * User tenant

        ```shell
        obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_BACKUP_SET_FILES WHERE BACKUP_SET_ID = set_id;
        ```

        ```shell
        obclient(SYSt@oracl001)[SYS]> SELECT * FROM SYS.DBA_OB_BACKUP_SET_FILES WHERE BACKUP_SET_ID = set_id;
        ```

     For more information, see [View data backup results](../../400.data-backup/600.view-data-backup-history.md).

  3. Check the `END_SCN` of the piece to be cleaned up.

     * System tenant

       ```shell
       obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_ARCHIVELOG_PIECE_FILES WHERE TENANT_ID = tenant_id AND PIECE_ID = piece_id;
       ```

     * User tenant

       ```shell
       obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_ARCHIVELOG_PIECE_FILES WHERE PIECE_ID = piece_id;
       ```

       ```shell
       obclient(SYSt@oracl001)[SYS]> SELECT * FROM SYS.DBA_OB_ARCHIVELOG_PIECE_FILES WHERE PIECE_ID = piece_id;
       ```

     For more information, see [View piece information](../../300.log-archive/500.view-log-archive-piece.md).

  4. Compare the obtained information. If the `END_SCN` of the piece to be cleaned up is greater than or equal to the `START_REPLAY_SCN` of any data backup in the current backup path, it means this piece is depended on by that data backup set.

* If you specify multiple `PIECE_ID` values for cleanup, all of them must be in the same archive path. You cannot clean up log archive pieces in multiple paths in a single statement.

   * When specifying multiple `PIECE_ID` values, all `PIECE_ID` must refer to pieces in the same archive path. For example, you cannot clean up pieces with `PIECE_ID` 1, 2, and 5, or 5, 6, and 7 at the same time.

   ```sql
   ALTER SYSTEM DELETE ARCHIVELOG_PIECE piece_id[,piece_id,...] TENANT [=] tenant_name;
   ```

   The parameters in the statement are described as follows:

   * `piece_id`: the ID of the log archive piece to be deleted. You can specify multiple pieces in a single statement. If you specify multiple `piece_id` values for cleanup, all pieces must be in the same archive path. You cannot clean up log archive pieces in multiple paths in a single statement.

   * `tenant_name`: the tenant for which the log archive piece is to be deleted.

   Here is an example:

   * Delete the log archive piece with `piece_id` 5 of the `mysql001` tenant.

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM DELETE ARCHIVELOG_PIECE 5 TENANT = mysql001;
     ```

   * Delete the four log archive pieces with `piece_id` 6, 7, 8, and 9 of the `mysql001` tenant at the same time.

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM DELETE ARCHIVELOG_PIECE 6,7,8,9 TENANT = mysql001;
     ```
