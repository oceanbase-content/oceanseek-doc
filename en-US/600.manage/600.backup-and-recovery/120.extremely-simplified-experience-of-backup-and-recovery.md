# Physical backup and restore with a minimal experience

This topic provides a minimal tenant-level backup and restore example as a complete minimal usage guide for first-time users of the physical backup and restore feature of OceanBase AI Database. It mainly involves the following three steps:

1. Initiate log archiving.
2. Initiate data backup.
3. Initiate physical restore.

## Considerations

* This topic uses the backup of a single tenant as an example. To back up multiple tenants, you must configure an independent empty directory for the backup path and archive path of each tenant. Different tenants cannot use the same path.
* OceanBase AI Database supports restore both within a cluster and across clusters.

## Background information

This topic uses the non-encrypted tenant `user_test` as an example to describe how to back up the tenant by using the physical backup feature and then restore a new tenant named `user_backup` from the backup data.

The key information in this example is as follows:

1. The log archive path of the source tenant is `/data/backup/archive`.
2. The archive mode is set to the default business priority mode (Optional), and a log piece is switched every other day.
3. The data backup path of the source tenant is `/data/backup/data`.
4. For the target tenant `user_backup` to be restored, the resource pool is `restore_pool`, the `Locality` replica is `F@z1`, and the tenant is restored to the latest timestamp.

   If the cluster where the tenant resides is a multi-replica cluster, see [Preparations before restore](600.restore-data/100.preparation-before-recovery.md) to perform the restore step by step.

## Procedure

### Step 1: Initiate log archiving

1. Log in to the database as the administrator of the `user_test` tenant.

2. Run the following command to configure the archive destination.

   ```sql
   obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=s3:///data/backup/archive?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****';
   ```

3. Enable the log archiving mode.

   ```sql
   obclient> ALTER SYSTEM ARCHIVELOG;
   ```

4. Check whether the log archiving status is `DOING`. You can initiate data backup only when the log archiving status is `DOING`.

   ```sql
   obclient> SELECT * FROM DBA_OB_ARCHIVELOG\G
   ```

### Step 2: Initiate data backup

Make sure that the log archiving status is `DOING` before you initiate data backup.

1. Log in to the database as the administrator of the `user_test` tenant.

2. Run the following command to configure the backup destination.

   ```sql
   obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3:///data/backup/data?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****';
   ```

3. Initiate a full data backup.

   ```sql
   obclient> ALTER SYSTEM BACKUP DATABASE;
   ```

4. Wait for the data backup to complete.

   You can query the `DBA_OB_BACKUP_TASKS` view. If the returned task list is empty, the data backup is complete.

   ```sql
   obclient> SELECT * FROM DBA_OB_BACKUP_TASKS;
   ```

5. View the data backup result.

   ```sql
   obclient> SELECT * FROM DBA_OB_BACKUP_JOB_HISTORY;
   ```

   The query result is as follows:


### Step 3: Perform physical restore

1. Log in as the `root` user to the `sys` tenant of the cluster where the target tenant resides.

2. Create the resources required for the target tenant.

   1. Create a resource unit named `unit_backup`.

      ```sql
      obclient> CREATE RESOURCE UNIT unit_backup MAX_CPU 8, MEMORY_SIZE = '16G', MAX_IOPS 10240, MIN_IOPS=10240;
      ```

   2. Create a resource pool for the target tenant. We recommend that you create a resource pool with the same specifications as the source tenant, that is, the number of `UNIT_NUM` in the resource pool is the same as that in the source tenant.

      ```sql
      obclient> CREATE RESOURCE POOL restore_pool UNIT = 'unit_backup', UNIT_NUM = 1, ZONE_LIST = ('z1');
      ```

3. Initiate a physical restore task to restore data to the `user_backup` tenant.

   ```sql
   obclient> ALTER SYSTEM RESTORE user_backup FROM 's3://data/backup/data?host=obs.****.myhuaweicloud.com,s3:///data/backup/archive?host=obs.****.myhuaweicloud.com' WITH 'pool_list=restore_pool&locality=F@z1';
   ```

For more information about the operations and instructions on physical restore, see [Preparations before restore](600.restore-data/100.preparation-before-recovery.md).
