# Initiate a full data backup

This topic describes how to initiate a full data backup after log archiving is enabled.

## Prerequisites

Before you initiate a full data backup, make sure that archiving mode is enabled. You can initiate a data backup only when the `STATUS` of the log archiving task is `DOING`.

For more information about how to view the status of a log archiving task, see [View archiving progress](../300.log-archive/600.view-log-archive-progress.md).

For more information about how to enable archiving mode, see [Enable archiving mode](../300.log-archive/300.open-the-log-archive-mode.md).
  
## (Optional) Preparations

Before you initiate a data backup, you can set a password for the backup set.

1. Log in to the `sys` tenant of the cluster as the `root` user.

2. (Optional) Execute the following statement to set a backup password:

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>This password is for the backup set after backup. If this option is set, you must enter this password when restoring from this backup set, and this password cannot be deleted.</p>
   </main>

   ```shell
   obclient [(none)]> SET ENCRYPTION ON IDENTIFIED BY 'password' ONLY;
   ```

   Here is an example:

   ```shell
   obclient [(none)]> SET ENCRYPTION ON IDENTIFIED BY '******' ONLY;
   ```

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>After setting the backup password, before initiating the data backup, you can cancel this setting by disconnecting the session and then reconnecting to the database.</p>
   </main>

## Initiate a full data backup

After you complete the preparations, you can perform the following steps to initiate a full data backup.

Assume the current cluster has three tenants: `sys`, `mysql_tenant`, and `mysql_tenant1`, and both tenants `mysql_tenant` and `mysql_tenant1` have completed the preparation before initiating a data backup.

### Initiate a full data backup from the sys tenant

The `sys` tenant can initiate a full data backup for all or specified tenants in the cluster.

1. Log in to the `sys` tenant of the cluster as the `root` user.

2. (Optional) Set the backup concurrency for the tenant.

   The backup concurrency is specified by the tenant-level configuration item `ha_low_thread_score`, which specifies the number of threads used for medium- and low-priority task queues, such as backup and backup cleanup. The value range is \[0, 100\]. The default value is `0`. Before you initiate a backup, you can increase the value of the `ha_low_thread_score` configuration item. We recommend that you double the value each time. For more information about the operations related to the `ha_low_thread_score` configuration item, see [View data backup parameters](700.parameters-of-data-backup.md).

   For more information about the `ha_low_thread_score` configuration item, see [ha_low_thread_score](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3500.ha_low_thread_score.md).

   * Execute the following statement to set the backup concurrency for all tenants in the cluster:

      ```sql
      obclient [(none)]>  ALTER SYSTEM SET ha_low_thread_score = 10 TENANT = all_user;
      ```

      Alternatively, execute the following statement:

      ```sql
      obclient [(none)]>  ALTER SYSTEM SET ha_low_thread_score = 10 TENANT = all;
      ```
  
      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><code>TENANT = all_user</code> and <code>TENANT = all</code> have the same semantics. If you want the setting to take effect for all user tenants, we recommend that you use <code>TENANT = all_user</code>. <code>TENANT = all</code> will be deprecated.</p>
      </main>

   * Execute the following statement to set the backup concurrency for a specified tenant in the cluster:

      ```sql
      obclient [(none)]>  ALTER SYSTEM SET ha_low_thread_score = 10 TENANT = mysql_tenant;
      ```

3. Execute the following statement to initiate a full data backup.

   * Initiate a full data backup for all tenants in the cluster

      You can initiate a full data backup for all tenants in the cluster.

      ```sql
      ALTER SYSTEM BACKUP DATABASE
      ```

      To initiate a full data backup for all tenants in the cluster, execute the following statement:

      ```sql
      obclient [(none)]> ALTER SYSTEM BACKUP DATABASE;
      ```

      After the statement is executed, the system initiates a full data backup for the `mysql_tenant` and `mysql_tenant1` tenants in the cluster in this example.

   * Initiate a full data backup for a specified tenant in the cluster

      You can initiate a full data backup for a specified tenant without affecting other tenants in the cluster. Here is a sample statement:

      ```sql
      ALTER SYSTEM BACKUP TENANT = mysql_tenant;
      ```

      To initiate a full data backup for the `mysql_tenant` tenant, execute the following statement:

      ```shell
      obclient [(none)]> ALTER SYSTEM BACKUP TENANT = mysql_tenant;
      ```

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>If you specify multiple tenants, separate the tenant names with commas (,).</p>
      </main>

      After the statement is executed, the system initiates a full data backup for the `mysql_tenant` tenant.

   You can view the backup progress in real time. For more information, see [View the data backup progress](../400.data-backup/500.view-data-backup-progress.md).

### Initiate a full data backup from a user tenant

You can initiate a full data backup for a user tenant without affecting other tenants.

1. Log in to the database as a tenant administrator.

    In this example, you can log in to the `mysql_tenant` or `mysql_tenant1` tenant as the `root` user.

2. (Optional) Set the backup concurrency.

   The backup concurrency is specified by the tenant-level configuration item `ha_low_thread_score`, which specifies the number of threads used for medium- and low-priority task queues, such as backup and backup cleanup. The value range is \[0, 100\]. The default value is `0`. Before you initiate a backup, you can increase the value of the `ha_low_thread_score` configuration item. We recommend that you double the value each time. For more information about the operations related to the `ha_low_thread_score` configuration item, see [View data backup parameters](700.parameters-of-data-backup.md).

   For more information about the `ha_low_thread_score` configuration item, see [ha_low_thread_score](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3500.ha_low_thread_score.md).

   ```sql
   obclient [(none)]>  ALTER SYSTEM SET ha_low_thread_score = 10;
   ```

3. Execute the following statement to initiate a full data backup:

   ```sql
   ALTER SYSTEM BACKUP DATABASE;
   ```

   To initiate a full data backup for the current tenant, execute the following statement:

   ```sql
   obclient [(none)]> ALTER SYSTEM BACKUP DATABASE;
   ```

   After the statement is executed, the system initiates a full data backup for the current tenant.

   You can view the backup progress in real time. For more information, see [View the data backup progress](../400.data-backup/500.view-data-backup-progress.md).
