# Data link introduction

As a distributed database, OceanSeek naturally distributes data across multiple nodes. In order to shield the complexity of distributed databases from applications (APPs) and make accessing OceanSeek as simple as accessing a standalone database, the OceanBase Database Proxy (ODP), also known as OBProxy, is introduced in the architecture. ODP is a dedicated reverse proxy service that addresses the SQL statement routing and disaster recovery issues of OceanSeek.

![Data link diagram 1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oceanbase-database-ai/manage/high-availability/multi-replica-disaster-recovery/odp-data-link1.jpg)

As a core component on the data link, ODP has multiple deployment forms:

* OBServer-side deployment: ODP and OBServer are deployed on the same server, which may result in resource competition and difficulty in troubleshooting under heavy load. This deployment form is commonly used in private cloud scenarios.

* ODP standalone deployment: ODP is deployed as an independent cluster, which reduces the mutual impact between ODP and OBServer. This deployment form is commonly used in public cloud scenarios.

* Client-side deployment: Another container running ODP is deployed next to the APPServer container. ODP and APPServer are located in the same pod but support independent upgrade, release, and maintenance. This deployment form has high requirements for the control plane and is less commonly used.

For the first two deployment forms, APPServer accessing ODP needs to go through a load balancer, which is responsible for the high availability and load balancing of ODP. For example, F5 distributes requests to multiple ODP instances.

In terms of product form, in addition to the proxy form, ODP also has the SDK form. The SDK form is integrated into the business code as a library. Compared with the proxy form, the SDK form has one less hop on the access link, achieving better performance and a shorter troubleshooting process. However, the SDK form also has some disadvantages, for example, there is mutual impact between the SDK and business code due to the integration, and the business needs to be restarted when the ODP SDK is upgraded.

After ODP is introduced, the data link of OceanSeek is as follows: APPServer <-> ODP <-> OBServer. APPServer sends user requests to ODP through the database driver. Due to the distributed architecture of OceanSeek, user data is distributed across multiple OBServer nodes in the form of multiple log streams and replicas. ODP forwards the requests to the most suitable OBServer node for execution and returns the execution result to the user. Since each OBServer node is capable of route forwarding, it forwards the request to the correct OBServer node upon detecting that it cannot execute the request, which requires remote execution and affects the response time (RT) of the request.

![Data link diagram 2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oceanbase-database-ai/manage/high-availability/multi-replica-disaster-recovery/odp-data-link2.jpg)

As the reverse proxy service for OceanSeek, ODP provides route selection and disaster recovery from the user side to the database side, shielding applications from the perception of the distributed database. Each OBServer node has a complete set of SQL engine, storage engine, and distributed transaction engine. It is responsible for parsing SQL statements, generating and executing physical execution plans, and committing transactions based on the Paxos protocol. OBServer provides high-performance, high-availability, and high-scalability database services. ODP and OBServer are loosely coupled, which allows for incorrect route selection due to delayed routing information updates on ODP. OBServer forwards the request internally and notifies ODP to update the routing information when returning the result.

As described above, the application layer sends user requests to the proxy service ODP, and ODP forwards the requests to the actual OBServer nodes that provide the data service. The execution result is returned to the application layer through the reverse path. Components on the entire data link achieve high availability in different ways.
