# Replace a LogService node

When a LogService node (LN) fails or requires vertical scaling, you can replace it. LogService performs node replacement by using `LS-CTRL` management commands. The basic procedure is as follows: start a new node and add it to the target Zone by using the `add ln` command, and then delete the node to be replaced by using the `delete ln` command.

## Procedure

1. Start an available node.

2. Use the `ls_ctrl` tool to execute the `add ln` command to add the new node to the Zone where the node to be replaced is located.

   ```shell
   ls_ctrl -H <HOST_ADDRESS> add ln <host:port> <az>
   ```

   Here, `<host:port>` is the address of the node to be added, and `<az>` is the name of the target Zone.

   For more information about how to add a node, see [Add a LogService node](400.add-logservice-node.md).

3. Use the `ls_ctrl` tool to execute the `delete ln` command to delete the node to be replaced.

   ```shell
   ls_ctrl -H <HOST_ADDRESS> delete ln <ln>
   ```

   Here, `<ln>` is the ID or address (`host:port`) of the node to be deleted.

4. Use the `ls_ctrl` tool to execute the `show ln` command and the `show meta --table-name t_ln_info_history` command to check whether the node to be replaced can be safely deleted:

   ```shell
   ls_ctrl -H <HOST_ADDRESS> show ln

   ls_ctrl -H <HOST_ADDRESS> show meta --table-name t_ln_info_history
   ```

   If the information about the node to be replaced cannot be found by using the `show ln` command but can be found by using the `show meta --table-name t_ln_info_history` command, the node can be safely deleted.

  <h4>Note</h4>
  <p>In the preceding commands, <code>HOST_ADDRESS</code> is the HTTP address (including the port number) of any LogService node, for example, <code>127.0.0.1:8080</code>. For more information about LS-CTRL commands, see <a href="../../../../700.reference/950.logservice-reference/100.logservice-commands/100.ls-ctrl-overview.md">Overview of LS-CTRL</a>.</p>

## Deletion mechanism

* The `delete ln` command marks the node as `DELETING` and drives LogServiceManager (LM) to initiate a migration task to move the stream replicas on the node to other available nodes.

* If a log stream's member list no longer contains an LN in the `DELETING` state, the LN is not the destination of migration for any log stream, and no log streams are being created, LM considers that the LN can be deleted safely.

* If LM detects that an LN has been in the `Inactive` state for a long time, that is, the current time is later than the time obtained by adding the `offline_time` in `t_ln_info` and the value of the `node_permanent_offline_time_sec` parameter, the system considers that the node cannot recover and generates a migration task to move the log stream replicas from this LN to another available LN in the same Zone.

## Monitor deletion progress

You can monitor the deletion progress of a node by using the following methods:

1. Use the `show ln` command to check whether the node is in the `DELETING` state.

2. Use the `show meta` command to view the internal table `t_stream_replica_task`, which records migration tasks. After a node is marked as `DELETING`, LM generates a migration task for the node, and the source `src_ln` is the node itself.

   ```shell
   ls_ctrl -H <HOST_ADDRESS> show meta --table-name t_stream_replica_task
   ```

3. After the migration task is completed, you can use the `show meta` command to view the `t_stream_replica_task_history` table of migration and replication tasks. Each row in this table records a completed migration and replication task. The `status` column indicates whether the migration task is successfully executed, and the `comment` column records the reason for a task failure.

   ```shell
   ls_ctrl -H <HOST_ADDRESS> show meta --table-name t_stream_replica_task_history
   ```

4. After all replicas on the LN are migrated out, you can use the `show meta` command to view the `t_ln_info` table and its history table `t_ln_info_history`. If the record of the node does not exist in `t_ln_info` but exists in `t_ln_info_history`, the LN is deleted from the cluster.

   ```shell
   ls_ctrl -H <HOST_ADDRESS> show meta --table-name t_ln_info

   ls_ctrl -H <HOST_ADDRESS> show meta --table-name t_ln_info_history
   ```

## Considerations

* If a log stream remains in the `CREATING` state and the `initial_member_list` contains the node to be deleted, the node cannot be removed.
