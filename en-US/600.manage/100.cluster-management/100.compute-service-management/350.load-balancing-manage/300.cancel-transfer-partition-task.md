# Cancel a partition transfer task

After manually initiating a partition transfer, you can cancel the task based on your business needs.

## Limitations

* You cannot cancel a partition transfer task in the `DOING` state, but you can cancel tasks in other states.

## Cancel a partition transfer task in the sys tenant

1. Log in to the `sys` tenant of the cluster as the `root` user.

   Note that you must specify the corresponding options in the following sample code based on your actual database configurations.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. Query the `CDB_OB_TRANSFER_PARTITION_TASKS` view for the status of the current task.

   ```shell
   obclient [oceanbase]> SELECT TENANT_ID, TABLE_ID, OBJECT_ID, STATUS FROM oceanbase.CDB_OB_TRANSFER_PARTITION_TASKS WHERE TENANT_ID = 1002;
   ```

   The query result is as follows:

   ```shell
   +-----------+----------+-----------+---------+
   | TENANT_ID | TABLE_ID | OBJECT_ID | STATUS  |
   +-----------+----------+-----------+---------+
   |      1002 |   500006 |    500008 | WAITING |
   +-----------+----------+-----------+---------+
   1 row in set
   ```

   Only tasks with a `STATUS` other than `DOING` (such as `WAITING` or `INIT`) can be canceled in the query result.

   If the `STATUS` of the task you want to cancel is `DOING`, you can disable the transfer feature by setting the tenant-level parameter `enable_transfer` to `false`. After disabling the transfer feature, all partition transfer tasks in the `DOING` state will roll back to the `WAITING` state, and then you can cancel the partition transfer task.

   For more information about the `enable_transfer` parameter, see [enable_transfer](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3000.enable_transfer.md).

3. Perform the appropriate operation based on the query result:

   * Cancel a partition transfer task for a specified partition in a specified tenant

      ```sql
      ALTER SYSTEM CANCEL TRANSFER PARTITION TABLE_ID [=] table_id OBJECT_ID [=] object_id TENANT = 'tenant_name';
      ```

      where

      * `table_id`: The ID of the table containing the partition to be canceled.

      * `object_id`: The ID of the partition to be canceled.

      * `tenant_name`: The name of the tenant containing the partition to be canceled.

      Here is an example:

      ```shell
      obclient [oceanbase]> ALTER SYSTEM CANCEL TRANSFER PARTITION TABLE_ID = 500006, OBJECT_ID = 500008 TENANT = 'mysql_tenant';
      ```

   * Cancel all partition transfer tasks for a specified tenant.

      ```sql
      ALTER SYSTEM CANCEL TRANSFER PARTITION ALL TENANT = 'tenant_name';
      ```

      Here is an example:

      ```shell
      obclient [oceanbase]> ALTER SYSTEM CANCEL TRANSFER PARTITION ALL TENANT = 'mysql_tenant';
      ```

## Cancel a partition transfer task in a user tenant

1. Connect to the database as the tenant administrator of the user tenant.

   Note that you must specify the corresponding options in the following sample code based on your actual database configurations.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. Query the `DBA_OB_TRANSFER_PARTITION_TASKS` view for the status of the current task.

   The query statement is as follows:

   ```shell
   obclient [oceanbase]> SELECT TABLE_ID, OBJECT_ID, STATUS FROM oceanbase.DBA_OB_TRANSFER_PARTITION_TASKS;
   ```

   A sample query result is shown below:

   ```shell
   +----------+-----------++--------+
   | TABLE_ID | OBJECT_ID | STATUS |
   +----------+-----------+--------+
   |   500046 |    500052 | INIT   |
   +----------+-----------+--------+
   1 row in set
   ```

   Only tasks with a `STATUS` other than `DOING` (such as `WAITING` or `INIT`) can be canceled in the query result.

   If the `STATUS` of the task you want to cancel is `DOING`, you can disable the transfer feature by setting the tenant-level parameter `enable_transfer` to `false`. After the transfer feature is disabled, all partition transfer tasks in the `DOING` state will roll back to the `WAITING` state, and then you can cancel the partition transfer task.

   For more information about the `enable_transfer` parameter, see [enable_transfer](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3000.enable_transfer.md).

3. Perform the appropriate operation based on the query result:

   * Cancel the partition transfer task for a specified partition in the current tenant.

      ```sql
      ALTER SYSTEM CANCEL TRANSFER PARTITION TABLE_ID [=] table_id OBJECT_ID [=] object_id;
      ```

      where

      * `table_id`: The ID of the table containing the partition to be canceled.

      * `object_id`: The ID of the partition to be canceled.

      Here is an example:

      ```shell
      obclient [oceanbase]> ALTER SYSTEM CANCEL TRANSFER PARTITION TABLE_ID = 500046, OBJECT_ID = 500052;
      ```

   * Cancel all partition transfer tasks in the current tenant.

      ```shell
      obclient> ALTER SYSTEM CANCEL TRANSFER PARTITION ALL;
      ```
