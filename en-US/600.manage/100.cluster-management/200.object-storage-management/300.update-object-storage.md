# Update object storage information

This topic describes how to update the access credentials (AK/SK) for object storage and adjust its bandwidth and IOPS limits.

## Update access credentials

AK/SK rotation is a common operation in object storage management, used to periodically update access credentials to enhance security. In a shared storage architecture, object storage serves multiple components such as OBServer and LogService. Each component accesses object storage using independent credentials. When updating credentials, you must select the corresponding operation entry based on the component to which the credential belongs:

| Component | Credential update method | Operation guide |
| ------ | ------------ | --------- |
| **OBServer** (compute node) | <ul><li>`ALTER SYSTEM CHANGE SHARED_STORAGE_DEST` (business data credentials)</li><li>`ALTER SYSTEM SET logservice_access_point` (log storage credentials)</li></ul> | [Update object storage access credentials](../100.compute-service-management/300.common-cluster-operations/1320.change-shared-storage-dest.md) |
| **LogService** (log service node) | `ls_ctrl rotate-ak` | [Rotate LogService access credentials](../300.logservice-management/300.logservice-operations/800.rotate-access-key.md) |

### Considerations

* The `ALTER SYSTEM CHANGE SHARED_STORAGE_DEST` statement can be executed only in the `sys` tenant.

* The log storage of OBServer and LogService access the same object storage bucket. When rotating the AK/SK for this bucket, you must update the credentials on both the OBServer side (`logservice_access_point`) and the LogService side (`ls_ctrl rotate-ak`) to avoid access failures caused by unilateral updates.

* After the cluster is switched to the new AK, the old AK is not immediately removed from the cluster. You must wait at least one hour before deleting the old AK.

## Update bandwidth and IOPS limits

During object storage usage, if business traffic changes require you to adjust the bandwidth and IOPS limits of object storage, you can modify the limits by using the `ATTRIBUTE` parameter of the `ALTER SYSTEM CHANGE SHARED_STORAGE_DEST` statement. This statement can be executed only in the `sys` tenant.

The syntax of the statement is as follows:

```sql
ALTER SYSTEM CHANGE SHARED_STORAGE_DEST
    PATH [=] 'path'
    SET ATTRIBUTE [=] 'attribute';
```

where:

* `PATH`: the path of the object storage, in the format `s3://<bucket>/<prefix>?host=<endpoint>`. It must be consistent with the currently configured object storage path of the cluster.
* `ATTRIBUTE`: the new IOPS and bandwidth limits, in the format `max_iops=<iops>&max_bandwidth=<bandwidth>`.

Here is an example:

```shell
obclient [(none)]> ALTER SYSTEM CHANGE SHARED_STORAGE_DEST
    PATH='s3://xxx?host=cn-hangzhou-alipay-b.oss-cdn.aliyun-inc.com'
    SET ATTRIBUTE='max_iops=10000&max_bandwidth=100MB';
```
