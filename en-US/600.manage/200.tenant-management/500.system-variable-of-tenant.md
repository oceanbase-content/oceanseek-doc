# Tenant system variables

Tenant system variables in OceanSeek are divided into global variables and session variables. By setting system variables, you can configure the behavior of OceanSeek to meet business requirements.

* Global variables: Modifications at the global level apply to all users in the same tenant. Global variable changes do not become invalid when a session exits. However, changes to global variables do not take effect for currently open sessions. You must establish a new session for the changes to take effect.
* Session variables: Modifications at the session level apply only to the current session. When a client connects to the database, the database automatically generates session variables based on global variables. Changes to session variables take effect only for the current session.

Comparison between system variables and system parameters:

| Comparison item | System parameters | System variables |
| --------- | ----------- | --------- |
| Effective scope | It is divided into clusters, zones, servers, and tenants. | It can be set to the global or session level for a tenant. |
| Effective mode | <ul><li> Dynamic effective: <code>edit_level</code> is <code>dynamic_effective</code></li><li> Effective after restart: <code>edit_level</code> is <code>static_effective</code></li></ul> | <ul><li>Setting a variable at the session level takes effect only for the current session and does not apply to other sessions.</li><li>Setting a variable at the global level does not take effect for the current session. You must log in again and establish a new session for the change to take effect.</li></ul> |
| Modification method | <ul><li>You can modify the value by using an SQL statement. Example:</br><code>Alter SYSTEM SET schema_history_expire_time='1h';</code></li><li>You can also modify the value by using a startup parameter. Example:</br><code>cd /home/admin/oceanbase && ./bin/observer -o "schema_history_expire_time=1h";</code> </li></ul> | It can be modified only by using SQL statements. Example:</br><code>SET ob_query_timeout = 20000000;</code></br><code>SET GLOBAL ob_query_timeout = 20000000;</code> |
| Query method | You can use the `SHOW PARAMETERS` statement to query parameters. Example: `SHOW PARAMETERS LIKE 'schema_history_expire_time';` | You can use the `SHOW [GLOBAL] VARIABLES` statement to query variables. Example:</br>`SHOW VARIABLES LIKE 'ob_query_timeout';`</br>`SHOW GLOBAL VARIABLES LIKE 'ob_query_timeout';` |
| Persistence | The configuration is persisted to internal tables and the configuration file. You can query this parameter in the <code>/home/admin/oceanbase/etc/observer.config.bin</code> and <code>/home/admin/oceanbase/etc/observer.config.bin.history</code> files. | Only global-level variables are persisted. Session-level variables are not persisted. |
| Lifecycle | Long, from process startup to exit. | Short. It takes effect only after the tenant's schema is created successfully. |
