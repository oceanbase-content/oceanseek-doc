# Modify tenant system variables

System variables in OceanSeek can be configured to meet business requirements. This topic describes how to modify the system variables of a tenant.

You can use the `SET` statement to modify system variables of a tenant.

* Setting a session-level system variable takes effect only for the current session and does not affect other sessions.
* Setting a global-level system variable does not take effect for the current session. You must log in again and establish a new session for the change to take effect.

  <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>To set a global-level variable, the current user must have the <code>SUPER</code> or <code>ALTER SYSTEM</code> privilege. Make sure that you have the required privilege before you set the variable. For more information about user privileges, see <a href="../../500.security-and-permissions/300.access-control/200.user-and-permission/100.user-and-permission-overview.md">Overview of users and privileges</a>.</p>
  </main>

The following sections use `ob_query_timeout` to describe how to modify a system variable. `ob_query_timeout` specifies the timeout period for SQL queries, in microseconds. By increasing the value of `ob_query_timeout`, you can avoid SQL query failures caused by query timeouts during large-scale data queries.

## Modify session-level system variables

1. Log in to a user tenant of the cluster as the `root` user.

   For example, to log in to the `mq_t1` tenant, run the following command:

    ```shell
    obclient -h172.30.xx.xx -P2883 -uroot@mq_t1#cluster -p**** -A
    ```

2. Query the session-level system variables of the tenant.

    ```shell
    obclient [(none)]> SHOW VARIABLES LIKE 'ob_query_timeout';
    ```

    The query result is as follows:

    ```shell
    +------------------+----------+
    | Variable_name    | Value    |
    +------------------+----------+
    | ob_query_timeout | 10000000 |
    +------------------+----------+
    1 row in set
    ```

3. Modify the value of the session-level system variable by using the `SET` statement.

    ```shell
    obclient [oceanbase]> SET ob_query_timeout = 20000000;
    ```

4. Query the modification result.

    ```shell
    obclient [(none)]> SHOW VARIABLES WHERE variable_name LIKE 'ob_query_timeout';
    ```

    The query result is as follows:

    ```shell
    +------------------+----------+
    | Variable_name    | Value    |
    +------------------+----------+
    | ob_query_timeout | 20000000 |
    +------------------+----------+
    1 row in set
    ```

## Modify global-level system variables

1. Log in to a user tenant of the cluster as the `root` user.

   For example, for the `mq_t1` tenant:

    ```shell
    obclient -h172.30.xx.xx -P2883 -uroot@mq_t1#cluster -p**** -A
    ```

2. Query the global-level system variables of the tenant.

    ```shell
    obclient [(none)]> SHOW GLOBAL VARIABLES WHERE variable_name LIKE  'ob_query_timeout';
    ```

    The query result is as follows:

    ```shell
    +------------------+----------+
    | Variable_name    | Value    |
    +------------------+----------+
    | ob_query_timeout | 10000000 |
    +------------------+----------+
    1 row in set
    ```

3. Modify the value of the global-level system variable by using the `SET` statement.

    ```shell
    obclient [oceanbase]> SET GLOBAL ob_query_timeout = 20000000;
    ```

4. Query the modification result.

    ```shell
    obclient [(none)]> SHOW GLOBAL VARIABLES WHERE variable_name LIKE 'ob_query_timeout';
    ```

    The query result is as follows:

    ```shell
    +------------------+----------+
    | Variable_name    | Value    |
    +------------------+----------+
    | ob_query_timeout | 20000000 |
    +------------------+----------+
    1 row in set
    ```

    After the modification, you can execute the following statement to query the `DBA_OB_SYS_VARIABLES` view for the modification status and default value of the `ob_query_timeout` variable:

    ```shell
    obclient [oceanbase]> SELECT * FROM oceanbase.DBA_OB_SYS_VARIABLES WHERE NAME='ob_query_timeout';
    ```

    The query result is as follows:

    ```shell
    +----------------------------+----------------------------+------------------+----------+-----------+-----------+------------------+----------------------------------+---------------+-----------+
    | CREATE_TIME                | MODIFY_TIME                | NAME             | VALUE    | MIN_VALUE | MAX_VALUE | SCOPE            | INFO                             | DEFAULT_VALUE | ISDEFAULT |
    +----------------------------+----------------------------+------------------+----------+-----------+-----------+------------------+----------------------------------+---------------+-----------+
    | 2024-05-08 14:20:28.885780 | 2024-05-09 15:11:11.654128 | ob_query_timeout | 20000000 |           |           | GLOBAL | SESSION | Query timeout in microsecond(us) | 10000000      | NO        |
    +----------------------------+----------------------------+------------------+----------+-----------+-----------+------------------+----------------------------------+---------------+-----------+
    1 row in set
    ```

## Modify a Boolean variable

For variables displayed as ON/OFF in the `SHOW VARIABLES` command, you can modify the variable value by using any of the following methods:

```sql
SET foreign_key_checks = ON;
SET foreign_key_checks = TRUE;
SET foreign_key_checks = 1;

SET GLOBAL foreign_key_checks = OFF;
SET GLOBAL foreign_key_checks = FALSE;
SET GLOBAL foreign_key_checks = 0;
```

<main id="notice" type='explain'>
 <h4>Note</h4>
 <p>Setting Boolean variables by using ON/OFF, TRUE/FALSE, or 1/0 is equivalent.</p>
</main>
