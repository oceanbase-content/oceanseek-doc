# Log interpretation

This topic describes how to interpret logs in OceanSeek, including log features and log location, log structure, and log interpretation for key scenarios.

## observer.log

The main service process runtime log, which records the operations of all modules except for election and RootService, including SQL parsing, transaction execution, and storage engine behavior.

### OBServer startup logs

OBServer startup logs record key events during process initialization and service readiness, which are used to diagnose issues during the startup phase.

* **Log location method**

  Locate by searching for the keyword `[NOTICE]`.

* **Log location command**

  ```log
  [admin@OB /home/admin/oceanbase/log] $grep "NOTICE" observer.log
  ```

* **Typical output example**

  ```log
  [2023-05-11 14:19:09.703272] INFO  [SERVER] ob_server.cpp:533 [95303][0][Y0-0000000000000000-0-0] [lt=9] [dc=0] [NOTICE] server instance start succeed

  [2023-05-11 14:19:25.555836] INFO  [SERVER] ob_server.cpp:609 [95303][0][Y0-0000000000000000-0-0] [lt=16] [dc=0] [NOTICE] observer start service(start_service_time=1683785965555827)
  ```

* **Key field description**

  | Log information                        | Description                                                                                     |
  | ----------------------------- | ---------------------------------------------------------------------------------------- |
  | server instance start succeed | The OBServer process started successfully.                                                                  |
  | observer start service        | OBServer has completed startup and is now providing services. `start_service_time` is the timestamp when OBServer started providing services. |

### Statistical logs


#### Tenant disk statistics

The disk usage of the tenant is printed every 10 seconds.

* **Log location method**

  Locate by searching for the keywords `ob_tenant_disk_usage_mgr.cpp` or `dump tenant disk usage update info`.

* **Log location command**

  ```log
  [admin@OB /home/admin/oceanbase/log] $grep "ob_tenant_disk_usage_mgr.cpp" observer.log
  ```

  or

  ```log
  [admin@OB /home/admin/oceanbase/log] $grep "dump tenant disk usage update info" observer.log
  ```

* **Typical output example**

  ```log
  [2023-05-15 17:30:59.055858] INFO  [STORAGE] ob_tenant_disk_usage_mgr.cpp:69 [87424][0][Y0-0000000000000000-0-0] [lt=11] [dc=0] dump tenant disk usage update info(disk_usage={tenant_id:1, max_disk_size:0, used_data_size:935329792, used_meta_size:56623104})  
  ```

* **Key fields**

  | Log information | Description |
  | -------------- | --------------------------------------------------------- |
  | tenant_id      | The tenant ID.                                                 |
  | max_disk_size  | The maximum disk size of the tenant. |
  | used_data_size | The disk space used by user data in the tenant.                            |
  | used_meta_size | The disk space used by management data in the tenant.                            |
