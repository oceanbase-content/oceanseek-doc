# HNSW series indexes

This topic describes how to create, search for, and drop HNSW series indexes in OceanBase AI Database, including syntax and examples.

## Index syntax and description

### Create

The HNSW series includes three types of indexes: HNSW, HNSW_SQ, and HNSW_BQ. They can be created **during table creation** or **after table creation**. Consider the following when creating:

* The `VECTOR` keyword is required to create a vector index.
* Parameters and descriptions for indexes created afterward are the same as those for creating indexes during table creation.
* If the amount of data is large, we recommend that you write the data and then create the index to achieve the best search performance.
* We recommend that you create an HNSW_SQ index after you write the data and rebuild the index after you write a large amount of incremental data. For more information about how to create an HNSW series index, see the following examples.
* When creating an HNSW index, the index name length must not exceed 25 characters; otherwise, an exception may occur due to the index auxiliary table name exceeding the `index_name` limit. Longer index names will be supported in future versions.
* We recommend that you create an HNSW series index on a heap table to achieve the best search performance.

### Create during table creation

Syntax:

```sql
CREATE TABLE table_name (
    column_name1 data_type1,
    column_name2 VECTOR(dim),
    ...,
    VECTOR INDEX index_name (column_name2) WITH (param1=value1, param2=value2, ...)
);
```

### Create after table creation

Syntax:

```sql
-- You can specify the parallelism to improve the index construction performance. The maximum value of the parallelism is twice the number of CPU cores.
CREATE [/*+ paralell $value*/] VECTOR INDEX index_name ON table_name(column_name2) WITH (param1=value1, param2=value2, ...);
```

The following table describes the `param` parameters.

| ------ | -------- | ---------- | ---------- | ------ | ------ |
| distance |  | l1/l2/inner_product/cosine | Yes | Specifies the vector distance algorithm type. | l1 indicates Manhattan distance; l2 indicates Euclidean distance, inner_product indicates inner product distance, and cosine indicates cosine distance. |
| type |  | `hnsw` / `hnsw_sq` / `hnsw_bq` | Yes | Specifies the index type. |  |
| lib | vsag | vsag | No | Specifies the type of the vector index database. | Currently, only the VSAG vector database is supported. |
| m | 16 | [5,128] | No | The maximum number of neighbors for each node. | A larger value indicates slower index construction but better search performance. |
| ef_construction | 200 | [5,1000] | No | The size of the candidate set during index construction. | A larger value indicates a slower index build but better index quality. `ef_construction` must be greater than `m`. |
| ef_search | 64 | [1,1000] | No | The size of the candidate set during search. | A larger value indicates a slower search but a higher recall rate. |
| duplicate_group | false | true/false | No | Specifies whether to enable identical-vector grouping. `TRUE` enables it and `FALSE` disables it. | Improves the recall rate in scenarios with many duplicate vectors, but increases the memory overhead for recording grouping relationships. Only exactly identical vectors can be merged. For an existing index, you can enable or disable `duplicate_group` through a full rebuild. | bq_bits_query | 32 | 0/4/32 | No | This parameter can only be specified when creating the HNSW_BQ index.<br/> It specifies the search precision for quantized vector indexes, in bits. | This value improves efficiency by reducing memory usage and index construction time during index creation, but it may affect recall. |
| bq_use_fht | true | true/false | No | This parameter can only be specified when creating the HNSW_BQ index.<br/> It specifies whether to use FHT for search. FHT (Fast Hadamard Transform) is an algorithm used to accelerate vector inner product calculations. |  |

* [Overview of date and time types](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/300.date-and-time-types-of-mysql-mode/100.date-and-time-types-of-mysql-mode.md)
* [Character type overview](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/400.string-of-mysql-mode/100.string-type-overview-of-mysql-mode.md): VARCHAR type.

Calculation method for primary key information size:

```sql
SET @table_name = 'test'; -- Replace with the table name to query
SELECT 
    CASE 
        WHEN COUNT(*) <> COUNT(result_value) THEN 'not support' 
        ELSE COALESCE(SUM(result_value), 'not support') 
    END AS extra_info_size
FROM (
    SELECT
        CASE 
            WHEN vdt.data_type_class IN (1, 2, 3, 4, 6, 8, 9, 14, 27, 28) THEN 8 -- For numeric types. extra_info_size += 8
            WHEN oc.data_type = 22 THEN oc.data_length -- For the varchar type, extra_info_size += data_length
            ELSE NULL -- Other types are not supported
        END AS result_value
    FROM 
        oceanbase.__all_column oc
    JOIN 
        oceanbase.__all_virtual_data_type vdt 
    ON 
        oc.data_type = vdt.data_type
    WHERE 
        oc.rowkey_position != 0 
        AND oc.table_id = (SELECT table_id FROM oceanbase.__all_table WHERE table_name = @table_name)
) AS result_table;
-- The calculation result is 8 bytes.
```

### Online modify index parameters

Starting from V4.6.3, you can use `DBMS_VECTOR.ALTER_INDEX_PARAMS` to online modify the construction and query parameters of HNSW series vector indexes after they are created. You only need to pass the parameters to be modified; unspecified parameters retain their current values.

When the construction parameters change, asynchronous partition-level rebuilding is triggered; modifying only query parameters does not trigger index rebuilding. For specific operation methods, see [Index monitoring and maintenance](#References).

### Search

The search in the HNSW index series is an approximate nearest neighbor (ANN) search, and does not guarantee 100% accuracy in the search results. The recall rate is used to measure the accuracy of the search. For example, if 9 of the 10 nearest neighbors are returned stably, the recall rate is 90%.

```sql
SELECT ... FROM table_name 
ORDER BY distance_function(column_name, vector_expr) [APPROXIMATE|APPROX] 
LIMIT num [OFFSET num]
[PARAMETERS(param1=value1, param2=value2, ...)];
```

**Search syntax requirements:**
* The `APPROXIMATE`/`APPROX` keyword must be specified for the search to use the vector index instead of a full table scan.
* The `ORDER BY` and `LIMIT` clauses must be included.
* `ORDER BY` supports only a single vector condition.
* The value range for `LIMIT + OFFSET` is `(0, 16384]`. A single approximate search returns at most 16384 results; for larger-scale similar recalls, you can use the search iterator to continue fetching data in batches via `last_distance` in `PARAMETERS` (supported starting from V4.6.2.1).
* Omitting the `LIMIT` clause will cause an error.
* `PARAMETERS` is an optional query-level parameter where you can set `ef_search`, `refine_k`, and `last_distance`.

**Distance function usage rules:**
* The `l1_distance()` distance function is supported only by HNSW indexes and applies only to regular dense vectors of FP32 (32-bit floating-point). It does not support quantized indexes like HNSW_SQ or HNSW_BQ, nor other vector types such as sparse vectors.
* If you specify the `APPROXIMATE`/`APPROX` keyword, the search will use the vector index. In this case, the distance function must be supported by the current version and must match the vector index algorithm.
* If you specify the `APPROXIMATE`/`APPROX` keyword, the search will not use the vector index, but no error is returned if the distance function does not match the vector index algorithm.
* If you specify the `APPROXIMATE`/`APPROX` keyword, the search will not use the vector index and an error is returned if the distance function is not supported by the current version.
* If you do not specify the `APPROXIMATE`/`APPROX` keyword, the search will not use the vector index, but no error is returned if the distance function is supported by the current version.

**Other notes:**
* `WHERE` conditions serve as filter criteria for vector index searches.
* Recall is affected by construction parameters and search parameters.
* Index search parameters can be set when creating the index or modified online after creation. For details, see [Online modification of index parameters](#Online%20modify%20index%20parameters); query-level parameters can be specified per query via `PARAMETERS`.
* When the `SELECT` list contains a distance function (such as `l2_distance()`) and the query accesses the vector index path, the system can reuse previously computed distance values from the index, reducing overhead in large `LIMIT` scenarios.

**Search parameters:**

| **Parameters** | **Default value** | **Value range** | **Required** | **Note** | **Remarks** |
| --- | --- | --- | --- | --- | --- |
| ef_search | 64 | [1,1000] | No | The size of the candidate set during search. | A larger value results in slower search but a higher recall rate. It can be set when creating the index or specified during the search by using the `PARAMETERS` clause. If specified during the search, the specified value is used; otherwise, the value used when the index was created is used. |
| refine_k | 4.0 | [1.0,1000.0] | No | <main id="notice" type='notice'><h4>Notice</h4><p>This parameter applies only to the HNSW_BQ index.</p></main> It is used to adjust the rearrangement ratio of quantized vector indexes. | It can be set when creating the index or specified during a search by using the `PARAMETERS` clause. If specified during the search, the specified value is used; otherwise, the value used when the index was created is used. |
| last_distance |  |  | No | <main id="notice" type='notice'><h4>Notice</h4><p>This parameter is supported starting from V4.6.2.1.</p></main> It is used for iterative pagination queries (Search Iterator). When the single TopK limit is exceeded, it fetches similar results in batches. | This parameter is not set for the first batch of queries. For each subsequent batch, pass the distance value of the last row from the previous batch's results to continue fetching the next batch. It is not recommended to pass `0` for the initial request. When the number of rows returned in a batch is less than `LIMIT` or no results are returned, it indicates that all data has been fetched. This parameter is valid only for `APPROXIMATE`/`APPROX` queries and is not supported for the HNSW_BQ index. |

### Delete

The syntax for deleting a vector index is as follows:

```sql
DROP INDEX index_name ON table_name;
```

## Examples of creation, search, and deletion

### Create during table creation

#### HNSW example

Create a test table.

```sql
CREATE TABLE t1(c1 INT, c0 INT, c2 VECTOR(10), c3 VECTOR(10), PRIMARY KEY(c1), VECTOR INDEX idx1(c2) WITH (distance=l2, type=hnsw, lib=vsag),  VECTOR INDEX idx2(c3) WITH (distance=l2, type=hnsw, lib=vsag));
```

Write test data.

```sql
INSERT INTO t1 VALUES(1, 1,'[0.203846,0.205289,0.880265,0.824340,0.615737,0.496899,0.983632,0.865571,0.248373,0.542833]', '[0.203846,0.205289,0.880265,0.824340,0.615737,0.496899,0.983632,0.865571,0.248373,0.542833]');
INSERT INTO t1 VALUES(2, 2, '[0.735541,0.670776,0.903237,0.447223,0.232028,0.659316,0.765661,0.226980,0.579658,0.933939]', '[0.213846,0.205289,0.880265,0.824340,0.615737,0.496899,0.983632,0.865571,0.248373,0.542833]');
INSERT INTO t1 VALUES(3, 3, '[0.327936,0.048756,0.084670,0.389642,0.970982,0.370915,0.181664,0.940780,0.013905,0.628127]', '[0.223846,0.205289,0.880265,0.824340,0.615737,0.496899,0.983632,0.865571,0.248373,0.542833]');
```

##### HNSW_SQ example

```sql
CREATE TABLE t2 (c1 INT AUTO_INCREMENT, c2 VECTOR(3), PRIMARY KEY(c1), VECTOR INDEX idx1(c2) WITH (distance=l2, type=hnsw_sq, lib=vsag));
```

##### HNSW_BQ example

```sql
CREATE TABLE t3 (c1 INT AUTO_INCREMENT, c2 VECTOR(3), PRIMARY KEY(c1), VECTOR INDEX idx3(c2) WITH (distance=l2, type=hnsw_bq, lib=vsag));
```

For HNSW_BQ, the `distance` parameter supports `l2` and `cosine`.

### Search

An example of a search iterator is as follows:

```sql
-- First batch: do not pass last_distance
SELECT pk, l2_distance(vec, '[1,1,2]') AS dist
FROM image_embeddings
ORDER BY l2_distance(vec, '[1,1,2]') APPROXIMATE LIMIT 1000
PARAMETERS(ef_search=200);
-- Assume the last row is dist = 0.35

-- Batch 2: Use the maximum distance from the previous batch and continue to select results where dist > 0.35.
SELECT pk, l2_distance(vec, '[1,1,2]') AS dist
FROM image_embeddings
ORDER BY l2_distance(vec, '[1,1,2]') APPROXIMATE LIMIT 1000
PARAMETERS(ef_search=200, last_distance=0.35);
```

### Delete

```sql
DROP INDEX vec_idx1 ON vec_table;
```

View the deleted index.

```sql
SHOW INDEX FROM vec_table;
```

The return result is as follows:

```shell
Empty set
```
