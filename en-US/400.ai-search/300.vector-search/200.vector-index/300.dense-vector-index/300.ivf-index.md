# IVF series indexes

This topic describes the syntax and examples for creating, searching, and dropping IVF series indexes in OceanSeek.

## Index syntax and description

### Create

The IVF series indexes include two types: IVF and IVF_PQ. The cluster centers of an IVF index are built based on the data in the primary table. To ensure normal use of the IVF index, you must create the primary table and import data before you create the IVF index. You can create an IVF index only after the primary table is created. When you create an IVF index, note the following:

* If the data volume is large, we recommend that you write data to the primary table and then create the index to achieve the best search performance.
* We recommend that you create IVF/IVF_PQ indexes after writing data to the primary table, and rebuild them after writing a large amount of incremental data. For more information about how to create an index, see the examples in the following sections.
* When creating an IVF index, the index name length must not exceed 33 characters; otherwise, an exception may occur due to the index auxiliary table name exceeding the `index_name` limit. Longer index names will be supported in future versions.
* When processing large-scale vector data, appropriately increasing the `nlist` parameter helps improve the recall rate of IVF indexes. When `nlist` ≥ 5000, the storage structure for caching IVF coarse clustering centers switches from an array to an HGraph (graph structure), further optimizing index performance and space utilization.

Syntax for post-create indexes:

```sql
-- You can specify the parallelism to improve the index construction performance. The maximum value of the parallelism is twice the number of CPU cores.
CREATE [/*+ paralell $value*/] VECTOR INDEX index_name ON table_name(column_name2) WITH (param1=value1, param2=value2, ...);
```

Explanation of `param` parameters:

### Search

IVF series indexes support approximate nearest neighbor (ANN) search. The search results are not guaranteed to be 100% accurate. The recall rate is used to measure the search accuracy. For example, if 9 out of 10 nearest neighbors can be returned, the recall rate is 90%.

```sql
SELECT ... FROM table_name 
ORDER BY distance_function(column_name, vector_expr) [APPROXIMATE|APPROX] 
LIMIT num (OFFSET num);
```

**Search syntax requirements:**
* The `APPROXIMATE`/`APPROX` keyword must be specified for the search to use the vector index instead of a full table scan.
* The `ORDER BY` and `LIMIT` clauses must be included.
* `ORDER BY` supports only a single vector condition.
* The value range for `LIMIT + OFFSET` is `(0, 16384]`.
* Omitting the `LIMIT` clause will result in an error.

**Distance function usage rules:**
* The `l1_distance()` distance function is supported only for IVF indexes and applies only to regular dense vectors with FP32 (32-bit floating-point) precision. It does not support IVF_PQ quantized indexes or other vector types such as sparse vectors.
* If `APPROXIMATE`/`APPROX` is specified, and a supported distance function is called that matches the vector index algorithm, the search will use the vector index.
* If `APPROXIMATE`/`APPROX` is specified, and the distance function does not match the vector index algorithm, the search will not use the vector index but no error will be reported.
* If `APPROXIMATE`/`APPROX` is specified, and the distance function is not supported, the search will not use the vector index and an error will be reported.
* If `APPROXIMATE`/`APPROX` is not specified, and a supported distance function is called, the search will not use the vector index but no error will be reported.

**Other notes:**
* `WHERE` conditions serve as filtering criteria for vector index searches.
* Recall is affected by construction parameters and search parameters.
* Index search parameters are specified during index creation and cannot be modified afterward. However, you can set the number of cluster centers used during search by using the session variable `ob_ivf_nprobes`. If this session variable is set, its value is used for the search. For more information about how to set this session variable, see [ob_ivf_nprobes](../../../../700.reference/800.configuration-items-and-system-variables/200.system-variable/400.session-system-variable/560.ob_ivf_nprobes.md).

### Delete

The syntax for dropping a vector index is as follows:

```sql
DROP INDEX index_name ON table_name;
```

## Create, search, and delete examples

### Post-creation

#### IVF example

Create a test table.

```sql
CREATE TABLE vec_table_ivf (c1 INT, c2 VECTOR(3), PRIMARY KEY(c1));
```

Create an IVF index.

```sql
CREATE VECTOR INDEX vec_idx3 ON vec_table_ivf(c2) WITH (distance=l2, type=ivf_flat);
```

### Delete

```sql
DROP INDEX vec_idx1 ON vec_table;
```

Query the index after dropping it.

```sql
SHOW INDEX FROM vec_table;
```

The return result is as follows:

```shell
Empty set
```
