# Get started with OceanSeek

This topic describes how to quickly set up an OceanSeek environment for experience and testing. OceanSeek supports single-machine experience with Docker Compose and deployment on Kubernetes with Helm. Both methods allow you to verify database connections and SQL read and write operations.

<main id="notice" type='notice'>
  <h4>Note</h4>
  <p>The experience and test environment does not guarantee the availability and performance of all features. Do not use it in a production scenario. For details about deploying a production environment, see <a href="../150.deploy/100.deploy-overview.md">Deployment overview</a>.</p>
</main>

## Resource planning

OceanSeek consists of two components, OBServer and LogService. Resource planning must take the resource requirements of both components into account.

| Environment | Node role | Minimum nodes | CPU/Memory per node | Local storage per node | Component quota |
| --- | --- | --- | --- | --- | --- |
| Minimum specification (testing) | ODP + OBServer | 1 | 4C/16G | SSD 50 GB | ODP 1C/2G </br> OBServer 3C/10G |
| Minimum specification (testing) | LogService | 3 | 2C/4G | 20 GB | 2C/4G for each LogService |
| Production environment | ODP + OBServer | 2 | 8C/32G | SSD 256 GB | ODP 2C/4G </br> OBServer 6C/24G |
| Production environment | LogService | 3 | 2C/4G | 100 GB | 2C/4G for each LogService |

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p><ul><li>Compose deployment does not include ODP and connects directly to OBServer through SQL. When you deploy a single-machine experience environment, you still need to reserve resources for OBServer, three LogService instances, monitoring, object storage, and the system.</li><li>Helm deployment deploys one ODP, one OBServer, and three LogService instances by default, and must meet the minimum component specifications for testing.</li><li>A production environment also requires separate planning for object storage, backup and recovery, monitoring, and high availability. For the deployment resource requirements and deployment methods of a production environment, see <a href="../150.deploy/100.deploy-overview.md">Deployment overview</a>.</li></ul></p>
</main>

## Deploy by using Docker Compose

### Requirements

| Item | Requirement |
| --- | --- |
| Operating system | Linux AMD64 |
| Container environment | Docker Engine 24+, Docker Compose v2.23.1+ |
| Single-machine resources | 12 vCPU, 32 GiB available memory, 250 GiB available SSD disk |
| Network | Access to the image repository; host ports `32881` and `32886` are not in use |

Run the following commands to query the versions of Docker Engine and Docker Compose.

```bash
sudo docker version
sudo docker compose version
```

### Deploy

Run the following commands in an empty directory:

```bash
curl -fLO https://mirrors.aliyun.com/oceanbase/docker/oceanseek/compose.yaml
sudo docker compose up -d
sudo docker compose logs -f observer-bootstrap
```

The message `OceanSeek deployment completed.` indicates that the deployment is complete. You can obtain the following information from the terminal output:

+ The management address of obshell: `http://<host IP>:32886/`
+ The SQL connection address: `<host IP>:32881`
+ The initial password of `root@sys`

Press `Ctrl+C` to stop following the logs only. This does not affect the running service.

### Connect to OceanSeek

Use a MySQL-compatible client to connect to OceanSeek. For details about connections to OceanSeek, see [Overview of connection methods](../200.connect/100.connection-methods-overview.md).

```bash
mysql -h<host or node IP> -P<SQL port> -uroot@sys -p
```

Enter the database password from the deployment output and execute the following SQL statements:

```sql
CREATE DATABASE IF NOT EXISTS oceanseek_demo;
USE oceanseek_demo;
CREATE TABLE IF NOT EXISTS hello (
  id INT PRIMARY KEY,
  message VARCHAR(64)
);
REPLACE INTO hello VALUES (1, 'Hello, OceanSeek!');
SELECT * FROM hello;
```

If the query returns `Hello, OceanSeek!`, the deployment is successful.

### Stop and clean up

```bash
# Stop the service and retain the data
sudo docker compose stop -t 120

# Resume the service
sudo docker compose up -d

# Delete the deployment and all data
sudo docker compose down -v
```

## Deploy by using Helm

### Requirements

| Item | Requirement |
| --- | --- |
| Kubernetes | 1.33 to 1.36 |
| Client | Helm 3, kubectl |
| Permissions | Can create namespaces, CRDs, RBAC, and workloads |
| Storage | An available StorageClass. `local-path` is recommended. |
| Single-machine resources | 16 vCPU, 32 GiB memory, 350 GiB free data disk |

```bash
kubectl get nodes -o wide
kubectl get storageclass
helm version --short
```

### Deploy

```bash
helm upgrade --install oceanseek \
  http://x.xx.xxx.xxx:xxxxx/experience/20261116-selinux-matrix-dev-r32/oceanbase-lakehouse-0.6.0-dev.20261116.4.tgz \
  -n oceanseek --create-namespace \
  --wait --wait-for-jobs --timeout 35m
```

The message `STATUS: deployed` indicates that the deployment is complete.

While waiting for the installation, you can view the progress in another terminal:

```bash
curl -fLO http://x.xx.xxx.xxx:xxxxx/experience/20261116-selinux-matrix-dev-r32/progress.py
python3 progress.py -n oceanseek --release oceanseek
```

Obtain the access addresses and initial passwords:

```bash
helm get notes oceanseek -n oceanseek
```

Access the OceanSeek Dashboard, the SQL connection address, and the corresponding passwords as described in the NOTES output. The initial password of the Dashboard is independent of the `root@sys` database password.

### Connect to OceanSeek

Use a MySQL-compatible client to connect to OceanSeek. For details about connections to OceanSeek, see [Overview of connection methods](../200.connect/100.connection-methods-overview.md).

```bash
mysql -h<host or node IP> -P<SQL port> -uroot@sys -p
```

Enter the database password from the deployment output and execute the following SQL statements:

```sql
CREATE DATABASE IF NOT EXISTS oceanseek_demo;
USE oceanseek_demo;
CREATE TABLE IF NOT EXISTS hello (
  id INT PRIMARY KEY,
  message VARCHAR(64)
);
REPLACE INTO hello VALUES (1, 'Hello, OceanSeek!');
SELECT * FROM hello;
```

If the query returns `Hello, OceanSeek!`, the deployment is successful.

### Stop and clean up

```bash
helm uninstall oceanseek -n oceanseek

# To also delete the namespace
kubectl delete namespace oceanseek
```

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If you use external object storage, uninstalling Helm does not automatically delete the data in the bucket. Clean up the data separately according to the rules of your object storage platform.</p>
</main>
