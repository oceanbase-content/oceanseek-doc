# Import data by using the LOAD DATA statement

## Overview

This topic describes how to use the **`LOAD DATA`** statement in OceanBase AI Database to write external data into internal tables, and to enable **direct load** when conditions are met (for example, by using hints such as `APPEND` or `direct(...)`) or by configuring the tenant-level parameter [default_load_mode](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2050.default_load_mode.md), to improve throughput for large-scale data loading.

### Syntax

```sql
-- FROM FILES()
LOAD DATA /*+ [APPEND | DIRECT(need_sort,max_error,{'full'|'inc'|'inc_replace'})] parallel(N) */ FROM FILES(...) INTO TABLE table_name ...;

-- Local client file (direct load is not supported)
LOAD DATA LOCAL INFILE 'file_name' INTO TABLE table_name ...;
```

## Classification and syntax relationship of `LOAD DATA` based on data read location

| Path / syntax | Data location | Typical application scenarios | Syntax and description | Limitations / configuration / additional information |
| --- | --- | --- | --- | --- |
| `LOAD DATA FROM FILES(...)` | Server-accessible paths described in the `FILES` clause (local directory, object storage URL, HDFS, etc., subject to the manual). | Single statement describes `LOCATION / FORMAT / PATTERN`, suitable for batch scanning and error diagnosis of CSV, ORC, and Parquet files. | Declare the set of files to be scanned via `FROM FILES(LOCATION = ..., FORMAT = (...), [PATTERN = ...])`. The server parses the declaration according to the format and writes it to the target table. This clause can be used together with `LOG ERRORS` for error diagnosis during import. | In a direct load scenario, you can add `/*+ direct(...) parallel(N) */` and other hints after the `LOAD DATA` keyword. |
| `LOAD DATA ... INFILE 'path'` (no `LOCAL`) | Server file system path readable by the OBServer process. | The file has been distributed to the database node or shared storage. This is often used together with `secure_file_priv`. | When `LOCAL` is not specified and `INFILE` is a path on the OBServer, the server directly reads this file (or a set of files matched by the wildcard). | Configure the path in the [`secure_file_priv`](../../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/12000.secure_file_priv-global.md) within the allowed range. Modifying this variable typically requires execution through a local Unix Socket connection. |
| `LOAD DATA ... LOCAL INFILE 'path'` | Path on the client where the connection is initiated. | The file exists only on the client. The connection must be enabled with `--local-infile`. | The keyword `LOCAL` indicates that the file is located on the client. The client reads the file and then uploads it to the server for parsing and writing. | Use `obclient --local-infile` (or its equivalent option) when connecting to enable local loading. **`LOCAL INFILE` does not support direct load.** |

## Examples

**Full direct load** (`direct(..., 'full')`) is typically used for the initial loading of an empty table or a complete baseline import.

**Incremental direct load** (`direct(..., 'inc')` or `'inc_replace'`) is typically used for append loading based on the **existing data** in the target table.

The two differ in the third parameter of `DIRECT()`, the target table status, and applicable limitations. For details about the differences, application scenarios, and limitations between full direct load and incremental direct load, see [Data import overview](100.data-import-overview.md).

The following examples focus on **full direct load**. The syntax for the incremental direct load hint is the same; only the third parameter is changed to `'inc'` or `'inc_replace'`.

### LOAD DATA FROM FILES

1. Log in to the server where the OBServer node to be connected resides. Prepare the data files to be scanned in the `/home/admin` directory (`LOCATION` points to a **server-accessible path**), which can be CSV, ORC, or Parquet files in this directory. This example uses CSV files.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The <code>LOCATION</code> in <code>FROM FILES</code> must be a path accessible to the OBServer. It is recommended that the directory and files be within the scope permitted by <code>secure_file_priv</code> (the same as for <code>LOAD DATA INFILE</code>).</p>
    </main>

   1. Access the server where the OBServer node resides.

      ```shell
      [xxx@xxx /home/admin]# ssh admin@10.10.10.1
      ```

   2. Create the test data file `tbl1.csv` (with content identical to the file in the preceding <code>LOAD DATA INFILE</code> example for easy comparison).

      ```shell
      [admin@xxx /home/admin]# vi tbl1.csv
      1,11
      2,22
      3,33
      ```

2. Set the import file path.

    Set the system variable `secure_file_priv` to configure the accessible paths for import or export files.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>For security reasons, when setting the system variable <code>secure_file_priv</code>, you must connect to the database via a local Unix Socket to execute the SQL statement that modifies this global variable. For more information, see <a href="../../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/12000.secure_file_priv-global.md">secure_file_priv</a>.</p>
    </main>

    1. Log in to the server where the OBServer node to be connected resides.

        ```shell
        [xxx@xxx /home/admin]# ssh admin@10.10.10.1
        ```

    2. Execute the following command to connect to the tenant `mysql001` via a local Unix Socket connection.

        ```shell
        obclient -S /home/admin/oceanbase/run/sql.sock -uroot@mysql001 -p******
        ```

    3. Set the import path to `/home/admin`.

        ```shell
        obclient [(none)]> SET GLOBAL secure_file_priv = "/home/admin";
        Query OK, 0 rows affected
        ```

3. After reconnecting to the database, use `LOAD DATA FROM FILES` with the direct load hint to import the data.

    1. Create table `tbl2` (with the same structure as the full example in the preceding <code>LOAD DATA INFILE</code>).

       ```shell
       obclient [test]> CREATE TABLE tbl2 (
                           col1 INT PRIMARY KEY,
                           col2 INT
                        )
                        PARTITION BY RANGE (col1)
                           SUBPARTITION BY RANGE (col1) (
                              PARTITION p0 VALUES LESS THAN (100) (
                                    SUBPARTITION p0_1 VALUES LESS THAN (50),
                                    SUBPARTITION p0_2 VALUES LESS THAN (100)
                              ),
                              PARTITION p1 VALUES LESS THAN (200) (
                                    SUBPARTITION p1_1 VALUES LESS THAN (150),
                                    SUBPARTITION p1_2 VALUES LESS THAN (200)
                              )
                        );
       Query OK, 0 rows affected
       ```

    2. Query whether there is data in table `tbl2`. The result shows the table is empty.

       ```shell
       obclient [test]> SELECT * FROM tbl2;
       Empty set
       ```

    3. Use direct load to scan and import `tbl1.csv` into table `tbl2`.

       If you need to import data using incremental direct load, you can refer to the following syntax examples:

        ```shell
        obclient [test]> LOAD DATA /*+ direct(true,1024,'inc') parallel(16) */ FROM FILES(
            LOCATION = '/home/admin',
            FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ','),
            PATTERN = 'tbl1.csv'
        ) INTO TABLE tbl2;
        ```

        or:

        ```shell
        obclient [test]> LOAD DATA /*+ direct(true,1024,'inc_replace') parallel(16) */ FROM FILES(
            LOCATION = '/home/admin',
            FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ','),
            PATTERN = 'tbl1.csv'
        ) INTO TABLE tbl2;
        ```

       The subsequent steps will continue with an example of full direct load.

       * Specify all columns of table `tbl2` to import data.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ FROM FILES(
             LOCATION = '/home/admin',
             FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ','),
             PATTERN = 'tbl1.csv'
         ) INTO TABLE tbl2;
         Query OK, 3 rows affected
         Records: 3  Deleted: 0  Skipped: 0  Warnings: 0
         ```

       * Specify columns of table `tbl2` to import data. For example, specify columns `col1` and `col2`.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ FROM FILES(
             LOCATION = '/home/admin',
             FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ','),
             PATTERN = 'tbl1.csv'
         ) INTO TABLE tbl2 (col1,col2);
         Query OK, 3 rows affected
         Records: 3  Deleted: 0  Skipped: 0  Warnings: 0
         ```

       * Specify a partition of table `tbl2` to import data.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ FROM FILES(
             LOCATION = '/home/admin',
             FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ','),
             PATTERN = 'tbl1.csv'
         ) INTO TABLE tbl2 partition(p0, p1);
         ```

       * Specify a subpartition of table `tbl2` to import data.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ FROM FILES(
             LOCATION = '/home/admin',
             FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ','),
             PATTERN = 'tbl1.csv'
         ) INTO TABLE tbl2 partition(p0sp0_1, p1sp1_1);
         ```

       * (Optional) Combine with `LOG ERRORS` for error diagnostics during import (only available when the current version supports this clause).

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ FROM FILES(
             LOCATION = '/home/admin',
             FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ','),
             PATTERN = 'tbl1.csv'
         ) INTO TABLE tbl2
         LOG ERRORS REJECT LIMIT UNLIMITED;
         ```

       * Use the parameter `default_load_mode` to import data.

         1. Set the value of `default_load_mode` to `FULL_DIRECT_WRITE`.

            ```shell
            obclient [test]> ALTER SYSTEM SET default_load_mode ='FULL_DIRECT_WRITE';
            ```

         2. Do not specify hints for the `LOAD DATA` statement.

            ```shell
            obclient [test]> LOAD DATA FROM FILES(
                LOCATION = '/home/admin',
                FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ','),
                PATTERN = 'tbl1.csv'
            ) INTO TABLE tbl2;
            ```

    4. Verify whether data has been imported into table `tbl2`.

       ```shell
       obclient [test]> SELECT * FROM tbl2;
       ```

       The query result is as follows:

       ```shell
        +------+------+
        | col1 | col2 |
        +------+------+
        |    1 |   11 |
        |    2 |   22 |
        |    3 |   33 |
        +------+------+
        3 rows in set
       ```

       The result shows that data has been imported into table `tbl2`.

#### LOAD DATA INFILE

1. Log in to the server where the OBServer node to be connected resides, and create test data in the `/home/admin` directory.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The <code>LOAD DATA</code> statement in OceanBase AI Database only supports loading input files local to the OBServer node. Therefore, you must copy the file to an OBServer node before importing it.</p>
    </main>

   1. Access the server where the OBServer node is located.

      ```shell
      [xxx@xxx /home/admin]# ssh admin@10.10.10.1
      ```

   2. Create the test data file `tbl1.csv`.

      ```shell
      [admin@xxx /home/admin]# vi tbl1.csv
      1,11
      2,22
      3,33
      ```

2. Set the import file path.

    Set the system variable `secure_file_priv` to configure the accessible paths for import or export files.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>For security reasons, when setting the system variable <code>secure_file_priv</code>, you must connect to the database via a local Unix Socket to execute the SQL statement that modifies this global variable. For more information, see <a href="../../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/12000.secure_file_priv-global.md">secure_file_priv</a>.</p>
    </main>

    1. Log in to the server where the OBServer node to be connected resides.

        ```shell
        [xxx@xxx /home/admin]# ssh admin@10.10.10.1
        ```

    2. Execute the following command to connect to the tenant `mysql001` via a local Unix Socket.

        ```shell
        obclient -S /home/admin/oceanbase/run/sql.sock -uroot@mysql001 -p******
        ```

    3. Set the import path to `/home/admin`.

        ```shell
        obclient [(none)]> SET GLOBAL secure_file_priv = "/home/admin";
        Query OK, 0 rows affected
        ```

3. After reconnecting to the database, use the `LOAD /*+ DIRECT */ DATA` statement to import the data.

    1. Create table `tbl2`.

       ```shell
       obclient [test]> CREATE TABLE tbl2 (
                           col1 INT PRIMARY KEY,
                           col2 INT
                        )
                        PARTITION BY RANGE (col1)
                           SUBPARTITION BY RANGE (col1) (
                              PARTITION p0 VALUES LESS THAN (100) (
                                    SUBPARTITION p0_1 VALUES LESS THAN (50),
                                    SUBPARTITION p0_2 VALUES LESS THAN (100)
                              ),                           
                              PARTITION p1 VALUES LESS THAN (200) (
                                    SUBPARTITION p1_1 VALUES LESS THAN (150),
                                    SUBPARTITION p1_2 VALUES LESS THAN (200)
                              )
                        );
       Query OK, 0 rows affected
       ```

    2. Query whether table `tbl2` contains data. The result shows the table is empty.

       ```shell
       obclient [test]> SELECT * FROM tbl2;
       Empty set
       ```

    3. Use direct load to import the data from the `tbl1.csv` file into table `tbl2`.

        If you need to import data using incremental direct load, you can refer to the following syntax examples:

        ```shell
        obclient [test]> LOAD DATA /*+ direct(true,1024,'inc') parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 FIELDS TERMINATED BY ',';
        ```

         or:

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'inc_replace') parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 FIELDS TERMINATED BY ',';
         ```

        In the subsequent steps, we will continue with an example of full direct load.

       * Specify all columns of table `tbl2` to import data.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 FIELDS TERMINATED BY ',';
         Query OK, 3 rows affected
         Records: 3  Deleted: 0  Skipped: 0  Warnings: 0
         ```

       * Specify any columns of table `tbl2` to import data. For example, specify columns `col1` and `col2`.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 FIELDS TERMINATED BY ','(col1,col2);
         Query OK, 3 rows affected
         Records: 3  Deleted: 0  Skipped: 0  Warnings: 0
         ```

       * Specify a partition of table `tbl2` to import.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 partition(p0, p1)  FIELDS TERMINATED BY ',';
         ```

       * Specify a subpartition of table `tbl2` to import.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 partition(p0sp0_1, p1sp1_1)  FIELDS TERMINATED BY ',';
         ```

       * Use the parameter `default_load_mode` to import data.

         1. Set the value of `default_load_mode` to `FULL_DIRECT_WRITE`.

            ```shell
            obclient [test]> ALTER SYSTEM SET default_load_mode ='FULL_DIRECT_WRITE';
            ```

         2. Do not specify hints for the `LOAD DATA` statement.

            ```shell
            obclient [test]> LOAD DATA INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 FIELDS TERMINATED BY ',';
            ```

    4. Verify whether data has been imported into table `tbl2`.

       ```shell
       obclient [test]>  SELECT * FROM tbl2;
       ```

       The query result is as follows:

       ```shell
        +------+------+
        | col1 | col2 |
        +------+------+
        |    1 |   11 |
        |    2 |   22 |
        |    3 |   33 |
        +------+------+
        3 rows in set
       ```

       The result shows that data has been imported into table `tbl2`.

#### LOAD DATA LOCAL INFILE

1. Prepare the data file on the client where obclient is running. This path is a **client-side local path**, which is different from the path on the OBServer. The file content is the same as in the previous example, and the file is still named `tbl1.csv`.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p><code>LOCAL INFILE</code> specifies that the client reads a local file and uploads it to the server. The connection command must include the <code>--local-infile</code> option (or its equivalent). <strong><code>LOAD DATA LOCAL INFILE</code> does not support direct load</strong>, so do not add the <code>APPEND</code> or <code>DIRECT(...)</code> hint.</p>
    </main>

   1. Create a data file on the client. In this example, the path is `/home/admin/client_csv/tbl1.csv`; adjust the directory based on your actual client environment.

      ```shell
      mkdir -p /home/admin/client_csv
      vi /home/admin/client_csv/tbl1.csv
      ```

      The file content is as follows:

      ```shell
      1,11
      2,22
      3,33
      ```

2. Connect to the database with the local infile capability enabled and access the target database (in this example, the `test` database under the `mysql001` tenant).

    ```shell
    obclient --local-infile -h10.10.10.1 -P2881 -uroot@mysql001 -p****** -Dtest
    ```

3. Use `LOAD DATA LOCAL INFILE` to import data (without direct load).

    1. Create table `tbl2` (the table structure is the same as the full example in the previous <code>LOAD DATA INFILE</code> section).

       ```shell
       obclient [test]> CREATE TABLE tbl2 (
                           col1 INT PRIMARY KEY,
                           col2 INT
                        )
                        PARTITION BY RANGE (col1)
                           SUBPARTITION BY RANGE (col1) (
                              PARTITION p0 VALUES LESS THAN (100) (
                                    SUBPARTITION p0_1 VALUES LESS THAN (50),
                                    SUBPARTITION p0_2 VALUES LESS THAN (100)
                              ),
                              PARTITION p1 VALUES LESS THAN (200) (
                                    SUBPARTITION p1_1 VALUES LESS THAN (150),
                                    SUBPARTITION p1_2 VALUES LESS THAN (200)
                              )
                        );
       Query OK, 0 rows affected
       ```

    2. Query whether there is data in table `tbl2`. The result shows the table is empty.

       ```shell
       obclient [test]> SELECT * FROM tbl2;
       Empty set
       ```

    3. Use `LOAD DATA LOCAL INFILE` to import the client file `tbl1.csv` into table `tbl2`.

       * Specify all columns of table `tbl2` to import data.

         ```shell
         obclient [test]> LOAD DATA LOCAL INFILE '/home/admin/client_csv/tbl1.csv' INTO TABLE tbl2 FIELDS TERMINATED BY ',';
         Query OK, 3 rows affected
         Records: 3  Deleted: 0  Skipped: 0  Warnings: 0
         ```

       * Specify columns of table `tbl2` to import data. For example, specify columns `col1` and `col2`.

         ```shell
         obclient [test]> LOAD DATA LOCAL INFILE '/home/admin/client_csv/tbl1.csv' INTO TABLE tbl2 FIELDS TERMINATED BY ','(col1,col2);
         Query OK, 3 rows affected
         Records: 3  Deleted: 0  Skipped: 0  Warnings: 0
         ```

       * Specify a partition of table `tbl2` to import data.

         ```shell
         obclient [test]> LOAD DATA LOCAL INFILE '/home/admin/client_csv/tbl1.csv' INTO TABLE tbl2 partition(p0, p1)  FIELDS TERMINATED BY ',';
         ```

       * Specify a subpartition of table `tbl2` to import data.

         ```shell
         obclient [test]> LOAD DATA LOCAL INFILE '/home/admin/client_csv/tbl1.csv' INTO TABLE tbl2 partition(p0sp0_1, p1sp1_1)  FIELDS TERMINATED BY ',';
         ```

       * The `LOCAL INFILE` format does not use the direct load mode specified by `default_load_mode`. You can directly execute the following statement:

         ```shell
         obclient [test]> LOAD DATA LOCAL INFILE '/home/admin/client_csv/tbl1.csv' INTO TABLE tbl2 FIELDS TERMINATED BY ',';
         ```

    4. Verify whether data has been imported into table `tbl2`.

       ```shell
       obclient [test]> SELECT * FROM tbl2;
       ```

       The query result is as follows:

       ```shell
        +------+------+
        | col1 | col2 |
        +------+------+
        |    1 |   11 |
        |    2 |   22 |
        |    3 |   33 |
        +------+------+
        3 rows in set
       ```

       The result shows that data has been imported into table `tbl2`.
