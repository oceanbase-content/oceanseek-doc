# Use the INSERT INTO SELECT FROM FILES statement for direct load

When prerequisites such as parallel DML are met, you can enable direct load for `INSERT INTO SELECT` using hints like `APPEND`, `DIRECT(...)`, and `enable_parallel_dml`. If hints are not explicitly specified, you can also control the import behavior by configuring the [default_load_mode](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2050.default_load_mode.md) parameter.

Based on the write target and processing method, direct load of `INSERT INTO SELECT` can be divided into **full direct load** and **incremental direct load**. Full direct load is suitable for initial loading or full overwriting scenarios, while incremental direct load is suitable for batch appending scenarios based on existing data. The following sections describe the limitations, syntax, and usage examples for each method.

## Full direct load

### Limitations

* Only Parallel Data Manipulation Language (PDML) is supported. Non-PDML operations cannot use direct load. For more information about parallel DML, see [Parallel DML](../../../../700.reference/1000.performance-tuning-guide/500.sql-optimization/300.distributed-execution-plan/1000.parallel-dml.md).
* Two write statements cannot be executed simultaneously during the import process (that is, one table cannot be written to at a time), because a table lock is acquired at the beginning of the import and only read operations are allowed throughout the import.
* Direct load is a DDL statement and cannot be executed within a multi-row transaction (a transaction containing multiple operations).
  * It cannot be executed within a BEGIN block.
  * Autocommit must be set to 1.
* It is not supported for use with triggers.
* Tables with generated columns are not supported (some indexes create hidden generated columns, for example, KEY `idx_c2` (`c2`(16)) GLOBAL).
* Liboblog and flashback queries are not supported.

### Syntax

```sql
INSERT /*+ [APPEND |DIRECT(need_sort,max_error,'full')] enable_parallel_dml parallel(N) */ INTO  table_name [PARTITION(PARTITION_OPTION)] select_sentence
```

For more information about the `INSERT INTO` syntax, see [INSERT](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/5700.insert-sql-of-mysql-mode.md).

**Parameter description:**

| Parameter | Description |
| ------ | ------ |
| APPEND \| DIRECT() | Use hints to enable the direct load feature. <ul><li>The <code>APPEND</code> hint is equivalent to using <code>DIRECT(true, 0)</code> by default and also enables online statistics collection (<code>GATHER_OPTIMIZER_STATISTICS</code> hint).</li><li>The parameters of <code>DIRECT()</code> are described as follows:<ul><li><code>need_sort</code>: Indicates whether the data to be written needs sorting. The value is of type <code>bool</code>:<ul><li><code>true</code>: Sorting is required.</li><li><code>false</code>: Sorting is not required.</li></ul></li><li><code>max_error</code>: Indicates the maximum number of erroneous rows tolerated. The value is of type <code>INT</code>. If this number is exceeded, the import task fails.</li><li><code>full</code>: Indicates full direct load. This is an optional parameter, and its value must be enclosed in English single quotes.</li></ul></li></ul> |
| enable_parallel_dml | The degree of parallelism for loading data.<main id="notice" type='explain'><h4>Note</h4><p>In general, the <code>enable_parallel_dml</code> hint and the <code>parallel</code> hint must be used together to enable parallel DML. However, if a table-level degree of parallelism is specified for the target table's schema, only the <code>enable_parallel_dml</code> hint is required.</p></main> |
| parallel(N) | The degree of parallelism for loading data. This parameter is required and must be an integer greater than 1. |
| table_name | The name of the table into which data is imported. You can specify any number of columns. |
| PARTITION_OPTION | The partition name for partition-level direct load:<ul><li>partition_option_list: the list of partitions. Separate multiple partitions with commas (,). </li> <li>subpartition_option_list: the list of subpartitions. Separate multiple subpartitions with commas (,).</li></ul> |

### Examples

**Example 1: A complete example of using INSERT INTO SELECT for full direct load.**

Use direct load to import some data from table `tbl2` into table `tbl1`.

1. Check if table `tbl1` contains any data. The result shows the table is empty.

   ```shell
   obclient [test]> SELECT * FROM tbl1;
   Empty set
   ```

2. Check if table `tbl2` contains any data.

   ```shell
   obclient [test]> SELECT * FROM tbl2;
   ```

   The query finds that table `tbl2` contains data.

   ```shell
   +------+------+------+
   | col1 | col2 | col3 |
   +------+------+------+
   |    1 | a1   |   11 |
   |    2 | a2   |   22 |
   |    3 | a3   |   33 |
   +------+------+------+
   3 rows in set
   ```

3. Use direct load to import the data from table `tbl2` into table `tbl1`.

   * Specify hints for the `INSERT INTO SELECT` statement.

     * Do not specify a partition for import.

         ```shell
         obclient [test]> INSERT /*+ DIRECT(true, 0, 'full') enable_parallel_dml parallel(16) */ INTO tbl1 SELECT t2.col1,t2.col3 FROM tbl2 t2;
         Query OK, 3 rows affected
         Records: 3  Duplicates: 0  Warnings: 0
         ```

     * (Optional) Specify a partition for import.

         ```shell
         obclient [test]> INSERT /*+ DIRECT(true, 0, 'full') enable_parallel_dml parallel(16) */ INTO tbl1 partition(p0, p1) SELECT t2.col1,1 FROM tbl2 partition(p0, p1) t2;
         Query OK, 3 rows affected
         Records: 3  Duplicates: 0  Warnings: 0
         ```

         ```shell
         obclient [test]> INSERT /*+ DIRECT(true, 0, 'full') enable_parallel_dml parallel(16) */ INTO tbl1 partition(p0, p1) SELECT t2.col1,1 FROM tbl2 partition(p0sp0_1, p1sp1_1) t2;
         Query OK, 3 rows affected
         Records: 3  Duplicates: 0  Warnings: 0
         ```

   * Do not specify a hint for the `INSERT INTO SELECT` statement.

      Set the value of the `default_load_mode` parameter to `FULL_DIRECT_WRITE`.

      ```shell
      obclient [test]> ALTER SYSTEM SET default_load_mode ='FULL_DIRECT_WRITE';
      ```

      ```shell
      obclient [test]> INSERT INTO tbl1 SELECT t2.col1,t2.col3 FROM tbl1 t2;
      ```

**Example 2: For a RANGE-HASH subpartitioned table, specify a primary partition for full direct load.**

The target table is a subpartitioned table with RANGE partitions as primary partitions and HASH partitions as subpartitions.

1. Create a table `tbl1` with two partitions: one RANGE partition and one HASH subpartition.

   ```shell
   obclient [test]> CREATE TABLE tbl1(col1 INT,col2 INT)
                     PARTITION BY RANGE COLUMNS(col1)
                        SUBPARTITION BY HASH(col2) SUBPARTITIONS 3 (
                           PARTITION p0 VALUES LESS THAN(10),                                               
                           PARTITION p1 VALUES LESS THAN(20));
   ```

2. Use direct load to import data from table `tbl2` into partitions `p0` and `p1` of table `tbl1`.

   ```shell
   obclient [test]> insert /*+ direct(true, 0, 'full') enable_parallel_dml parallel(3) append */ into tbl1 partition(p0,p1) select * from tbl2 where col1 <20;
   ```

## Incremental direct load

### Limitations

* Only Parallel Data Manipulation Language (PDML) is supported; non-PDML operations cannot use direct load. For more information about parallel DML, see [Parallel DML](../../../../700.reference/1000.performance-tuning-guide/500.sql-optimization/300.distributed-execution-plan/1000.parallel-dml.md).
* During the import process, two write statements cannot be executed simultaneously (that is, one table cannot be written to at a time), because a table lock is acquired at the beginning of the import and only read operations are allowed throughout the import.
* Direct load is not supported for tables with triggers.
* Tables with generated columns are not supported (some indexes create hidden generated columns, for example, KEY `idx_c2` (`c2`(16)) GLOBAL).
* Liboblog and flashback queries are not supported.
* Tables with indexes (excluding primary keys) do not support incremental direct load.
* Tables with foreign keys do not support incremental direct load.
* Tables with `GLOBAL` indexes do not support incremental direct load.
* Tables with constraints do not support incremental direct load.
* Tables without a primary key that have more than one unique `LOCAL` index do not support incremental direct load.
* Tables with a primary key and a unique index do not support incremental direct load.

### Syntax

```sql
INSERT /*+ [DIRECT(need_sort,max_error,{'inc'|'inc_replace'})] enable_parallel_dml parallel(N) */ INTO  table_name [PARTITION(PARTITION_OPTION)] select_sentence
```

For more information about the `INSERT INTO` syntax, see [INSERT](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/5700.insert-sql-of-mysql-mode.md).

**Parameter description:**

| Parameter | Description |
| ------ | ------ |
| DIRECT() | Use the hint to enable direct load. The parameters of <code>DIRECT()</code> are described as follows:<ul><li><code>need_sort</code>: Indicates whether the data to be written needs to be sorted. The value is of type <code>bool</code>.<ul><li><code>true</code>: Indicates that sorting is required.</li><li><code>false</code>: Indicates that sorting is not required.</li></ul></li><li><code>max_error</code>: Indicates the maximum number of erroneous rows that can be tolerated. The value is of type <code>INT</code>. If the number of erroneous rows exceeds this value, the import task fails.</li><li><code>inc \| inc_replace</code>: Indicates the two modes of incremental direct load. The value must be enclosed in English single quotes.<ul><li><code>inc</code>: Indicates incremental import. It checks for duplicate primary keys and supports the <code>INSERT</code> and <code>IGNORE</code> semantics.</li><li><code>inc_replace</code>: Indicates incremental import without checking for duplicate primary keys, equivalent to an incremental import with the <code>REPLACE</code> semantics.</li></ul></li></ul> |
| enable_parallel_dml | The degree of parallelism for loading data.<main id="notice" type='explain'><h4>Note</h4><p>In general, the <code>enable_parallel_dml</code> hint and the <code>parallel</code> hint must be used together to enable parallel DML. However, if a table-level degree of parallelism is specified for the target table's schema, only the <code>enable_parallel_dml</code> hint is required.</p></main> |
| parallel(N) | The degree of parallelism for loading data. This parameter is required and must be an integer greater than 1. |
| table_name | The name of the table into which data is imported. You can specify any number of columns. |
| PARTITION_OPTION | The partition name for partition-level direct load:<ul><li>partition_option_list: the list of partitions. Separate multiple partitions with commas (,). </li> <li>subpartition_option_list: the list of subpartitions. Separate multiple subpartitions with commas (,).</li></ul> |

**Example 2: For a RANGE-HASH subpartitioned table, specify a primary partition for incremental direct load.**

The target table is a subpartitioned table with RANGE partitions as primary partitions and HASH partitions as subpartitions.

1. Create a table `tbl1` with two partitions: one RANGE partition and one HASH subpartition.

   ```shell
   obclient [test]> CREATE TABLE tbl1(col1 INT,col2 INT)
                     PARTITION BY RANGE COLUMNS(col1)
                        SUBPARTITION BY HASH(col2) SUBPARTITIONS 3 (
                           PARTITION p0 VALUES LESS THAN(10),                                               
                           PARTITION p1 VALUES LESS THAN(20));
   ```

2. Use direct load to import data from table `tbl2` into partitions `p0` and `p1` of table `tbl1`.

   ```shell
   obclient [test]> insert /*+ direct(true, 0, 'inc_replace') enable_parallel_dml parallel(3) append */ into tbl1 partition(p0,p1) select * from tbl2 where col1 <20;
   ```
